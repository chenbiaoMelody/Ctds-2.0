# 第一部分 总体实施计划说明

## 1.1 编制依据与范围界定

1. **范围**：本计划覆盖 PRD V2.0 全部三个版本阶段的实施安排。V1.0（T+3）按 PRD"**P0 不膨胀原则**"执行 V1.0 全部 P0 功能 + AI-0 底座预留；V1.5（T+3~T+6）与 V2.0（T+6~T+12）纳入基线但采用**滚动式规划**（见 1.6）。
2. **约束**：全员无编程经验；人工评审与测试仅覆盖业务功能维度；质量保障依赖三道防线（CI 门禁 + AI 评审会审 + 业务验收）；会话纪律强制（单会话单任务、50% 停机、日志续点、冷启动）。
3. **团队配置（2026-09-05 启动确认）**：**全部人工角色由 1 人兼任**（项目经理/产品负责人/AI 编排师/业务验收员/安全与合规专员/发布与运维专员）；外部技术顾问不聘请（D-2，已登记为"已接受的最高优先级风险"，补偿控制见《项目启动确认记录》D-2/D-4）。

## 1.2 实施策略（六条）

| # | 策略 | 内容 |
| --- | --- | --- |
| S1 | 规格驱动 | 每个功能包先产出业务规格与验收剧本并评审通过，才进入实现；规格由 PO 主导、规格澄清智能体辅助 |
| S2 | **会话即工作包** | 工作包是最小计划单元，也是最小会话单元：1 个工作包 = 1 张任务卡 = 1–2 个 AI 会话；预估超过 2 会话的工作包必须再拆（见 1.6 粒度标准） |
| S3 | P0 不膨胀 | V1.0 只做 PRD P0 + AI-0 预留；AI 全量能力放 V1.5/V2.0；任何插入需求走 A/S 级变更 |
| S4 | 质量前置 | 公共组件（common）与标准适配层（std-adapter）在 W1–W2 优先建成，后续功能"用组件拼装"而非"各写各的"，从源头抑制 AI 代码不一致与重复 |

## 1.5 资源与产能测算

**产能模型（1 人兼任，2026-09-05 启动确认）**：1 个会话 = 1 个任务卡（2–4 小时人机协作，受 50% 停机规则约束）；单人兼任全部角色，按"每周有效执行 10 个会话 + 约 5 个会话当量用于规格编写、验收、演示与管理"测算。

| 项目 | 数值 |
| --- | --- |
| V1.0 执行会话需求（136 工作包 ≈ 140 会话 × 1.15 返工系数） | ≈161 |
| 每周有效执行会话 | 10 |
| 纯执行周数 | ≈16 |
| **基线总周数（含里程碑演示、节假日与缓冲）** | **22** |
| 有效负载率（执行+治理开销 / 总产能） | ≈73% |

> 结论：22 周基线下 1 人兼任**可行但缓冲有限**——任何范围插入必须置换等量工作包，"连续 2 周偏差 >15% 触发熔断"的法则照常生效（1.8）。若后续立项增员，可按原多人力模型压缩回 12 周（136 工作包清单不变，直接重排周表即可）。

## 1.6 WBS 编制规则

**层级定义**：

```
L1 阶段群（如：工程基建）
L2 模块/工作流（如：合约与使用控制）
L3 功能包（对应 PRD 需求编号，如 C-4.3 使用控制策略引擎）
L4 工作包（最小执行单元 = 1 张任务卡 = 1–2 个 AI 会话）
```

**工作包粒度标准（会话可完成性判定）**——同时满足才允许立项为一个工作包：

1. **单一交付物**：产出一个可验收的交付物（一份规格、一个服务类、一组页面、一份测试集、一份剧本）；
2. **单会话可完成**：预估 1 个会话（复杂者至多 2 个，且须在任务卡中预拆为"前半/后半"两个续点）；预估 >2 会话的必须继续拆分；
3. **独立可验证**：完成标准不依赖"其他工作包顺便完成"（依赖的集成验证归入专门的联调工作包）；
4. **边界明确**：任务卡能写清"改哪些目录、不改哪些"（防 AI 越界）。

**编号规则**：`<L1>.<L2>.<L3>.<L4>`（如 `3.4.2.3` = 平台功能开发/合约与使用控制/C-4.2 合约协商签署/协商工作台服务）。

**估算单位**：会话数（1 或 2）。全局统一出口（所有工作包相同，表中不再重复）：任务卡关闭 = 本地验证全绿 + 三道防线通过 + 开发日志落盘 + 追溯矩阵与文档更新。

**任务卡映射**：每个工作包对应一张任务卡（卡号 = WBS 编号），任务卡内容 = 工作包产出 + 依赖的规格/剧本链接 + 边界声明；由编排师按章程 9.1 SOP 执行。

**滚动式规划**：V1.5/V2.0 的 L4 分解在各阶段启动时（KT 会）按 1.6 规则展开并经变更评审会确认基线；本文件先给出其 L3 功能包清单与**标准工作包分解模板**（见 2.6/2.7），保证后续展开的一致性。

## 1.8 计划治理

1. **基线管理**：本文档为项目基线；里程碑日期、范围、工作包增删一律走变更评审会（章程第 7 章），变更后更新本文件并留版本记录；
2. **周节奏**：每周质量看板评审（进度燃尽、门禁通过率、缺陷趋势、缓冲余量）+ 演示性检查（本周完成工作包抽样演示）；
3. **燃尽与预警**：按周跟踪"已完成工作包 / 计划工作包"燃尽曲线；连续 2 周偏差 >15% 触发范围熔断评估；
4. **熔断联动**：里程碑前 2 周按章程 8.2 执行"可降级清单"决策（保接口合规与验收标准，砍实现深度）；
5. **跨阶段衔接**：每阶段末 KT 会完成下一阶段 L4 展开、经验教训入库（开发日志归档 + 模板库更新）。
