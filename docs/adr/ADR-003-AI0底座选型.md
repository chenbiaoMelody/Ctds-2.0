# ADR-003 AI-0 底座选型（模型网关、国产模型与向量库）

| 字段 | 内容 |
| --- | --- |
| 编号 | ADR-003 |
| 状态 | **提案（待 PM+PO 批准）** |
| 日期 | 2026-09-06 |
| 关联工作包 | WBS 2.1.3 → 3.10.1~3.10.4（AI-0 底座预留，V1.0 仅抽象不承载业务功能）；外部顾问意见按 D-2 暂缓，以内部自查代偿 |

## 1. 背景

PRD V2.0 的 C-11 智能中枢/C-12 智能体生态需要统一的模型接入与语义检索底座；V1.0 阶段只做**抽象与配置预留**（AI-0），不实现业务功能。约束：零预算、数据不出境、模型可替换（章程 3.1.4 双轨备案）。

## 2. 备选方案与业务影响对比

### 2.1 模型接入

| 维度 | 方案 A：模型网关抽象 + 多 Provider（推荐） | 方案 B：直连单一模型 API |
| --- | --- | --- |
| 换模型成本 | 改配置 | 改代码 |
| 供应商锁定 | 无 | 高 |
| 实现工作量 | 需先建抽象层（V1.0 本就要求预留） | 少但日后加倍偿还 |

**推荐 A**：网关按 OpenAI 兼容协议统一（业界事实标准），Provider 适配器配置化路由。

**国产模型清单**（均为 OpenAI 兼容 API，国内直连）：默认 智谱 GLM（当前在用）；备选 DeepSeek、通义千问 Qwen、Kimi。模型密钥只进配置中心/KMS，禁止入库（红线）。

### 2.2 向量库（目录语义检索 C-3.4 依赖）

| 维度 | 方案 A：PostgreSQL + pgvector（推荐起步） | 方案 B：Milvus | 方案 C：Elasticsearch |
| --- | --- | --- | --- |
| 运维复杂度 | 最低（随主库，无新组件） | 需独立集群 | 需独立集群 |
| 规模上限 | 千万级向量内够用 | 十亿级 | 亿级 |
| 国产/信通院生态贴合 | 一般 | 好（国产开源主流） | 一般 |
| 演示环境资源 | 0（复用主库） | 2G+ 内存 | 2G+ 内存 |

**推荐 A 起步**：检索能力收敛在统一的 `VectorStore` 检索抽象接口之后（切换接口），数据量或性能触顶时以 Milvus 适配器平滑替换，业务代码不动。

## 3. 决策（推荐）

1. 模型网关：OpenAI 兼容协议 + Provider 适配器 + 配置化路由 + 预算/开关控制位（对接 3.10.4 配置管理）；
2. 向量库：`VectorStore` 抽象接口 + PostgreSQL/pgvector 首版实现；
3. 全部 AI 调用走网关统一记录审计日志（预留，V1.5 填充）。

## 4. 理由与业务影响说明

**理由**：模型网关抽象把"换模型"从改代码降为改配置，直接兑现章程 3.1.4 双轨备案与 D-3 可替换性要求；pgvector 复用主库使向量检索在演示阶段零新增运维组件，而 `VectorStore` 抽象保住数据规模触顶后切换 Milvus 的路径——即"演示优先、接口预留"。

- **成本**：全部组件开源免费；模型调用按量付费部分在 V1.0 仅预留不产生消耗，V1.5 前须做调用预算评估（列入待办）；
- **工期**：抽象层为 V1.0 既有工作项（3.10.1），不新增；
- **风险**：模型服务商 API 变更风险由适配器隔离；pgvector 性能上限风险由抽象接口隔离；
- **影响范围**：C-11/C-12 及目录语义检索（C-3.4），不触及 V1.0 其他 P0 模块。

## 5. 可替换性评估（D-3）

模型层与向量层均为"抽象接口 + 可插拔适配器"结构，替换=新增适配器+改配置。风险等级：低。
