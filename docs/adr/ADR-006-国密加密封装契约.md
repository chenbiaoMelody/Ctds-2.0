## 1. 背景

章程红线：加解密/密钥一律调用 `common` 国密组件，禁止自行实现密码学。WBS 2.4.6 交付"全平台唯一加解密入口"，为 2.6.3/3.1.8/3.5.3/4.3.3 的依赖底座。全体下游需要一个**不可绕过、行为可预期**的统一契约。

## 2. 备选方案与取舍

| 决策点 | 方案 A（采用） | 方案 B（弃） | 取舍理由 |
| --- | --- | --- | --- |
| SM4 工作模式 | **GCM（AEAD，密文自带完整性标记）** | CBC+HMAC 双步、或裸 ECB/CBC | GCM 一步完成加密+防篡改，主流程天然拒绝"篡改不报错"红线；CBC 需额外拼 HMAC 且易配错 |
| SM2 密文排列 | **C1C3C2** | C1C2C3（旧版国标） | GB/T 32918.4 新版默认，与主流互联互通实现一致 |
| 密钥供给 | **KeyProvider 抽象 + V1.0 本地文件实现**（模式 A，Q3 裁决） | 组件内直接读配置、或等真实 KMS 落地再交付 | 抽象先行使 2.6.3 接 KMS 业务零改动，演示不依赖外部采购（lofi Q3 业务裁决留痕） |
| SM3 是否纳入 | **纳入**（Q2 裁决） | 只交付 SM2/SM4 | 存证（ADR-004）与文件完整性（3.5.3）已明确需要国密摘要，不纳入则下游各自封装、破坏唯一入口 |
| 空输入语义（SM3） | **放行空输入**（空消息摘要有标准定义） | 一律拒绝 | 摘要与加解密语义不同；评审③P1 统一两重载并留痕 |
| enabled=false 语义 | **全禁用 fail-fast**（Bean 全不注册） | 部分禁用（沿 auth 型） | 加密组件"静默跳过=以为加密其实没加密"是红线旁路面，沿 2.4.5 评审教训取 fail-fast（评审③P2-2 登记两种语义） |

## 3. 决策（契约正文，实现 = `common-crypto`，设计定稿 `docs/designs/WBS-2.4.6-hifi.md`）

1. **唯一入口**：平台内 SM2/SM3/SM4 运算一律经 `com.ctds.common.crypto` 的 `Sm2Service`/`Sm3Service`/`Sm4Service`；组件只做 BouncyCastle 封装调用，**不实现任何密码学算法**；不注册全局 JCE Provider（零全局副作用）；
2. **SM4 密文信封格式 v1**（跨服务可互认）：`CTSE`(4B 魔数) + `0x01`(1B 格式版本) + IV(12B 随机) + 密文 + GCM 标签(16B)，即 SM4/GCM/AEAD——密文篡改/截断/错密钥一律拒绝（`1001C0002`），非本格式数据报"输入不合法"（`1001C0001`，与"被篡改"语义区分）；**版本字段为密钥轮换与算法升级预留**（2.6.3 依赖此位）；
3. **SM2 契约**：曲线 sm2p256v1；公钥 = 非压缩点 hex（`04`+X+Y，130 字符）、私钥 = D 值 hex（64 字符）；加密 C1C3C2（GB/T 32918.4 新版默认）；签名 = GB/T 32918.2 DER（默认用户标识）；SM2 密钥为**参数传入**（主体身份类密钥归 3.1.8/DID 体系，不进本组件密钥库）；
4. **密钥供给边界（Q3 模式 A）**：`KeyProvider` 接口统一 SM4 取密钥；V1.0 默认 `LocalFileKeyProvider`（properties 文件 `编号=Base64(16字节)`，启动一次性只读加载、永不回写；配置了路径但文件缺失/坏行 = 启动失败 fail-fast）；**真实 KMS（2.6.3）以覆盖 KeyProvider Bean 接入，业务代码零改动**；未配置密钥源时组件正常启动、SM4 操作报 `1001S0001`（密钥服务暂不可用）；
5. **错误码模块位规划**（全平台通用制度，后续组件顺延）：9 位码 `平台域(2)+模块位(2)+类型(1)+序号(4)` 中，`00` = 平台公共（`ErrorCodes`，1000 段已用）；`01` = 国密组件（`CryptoErrorCodes`：`1001C0001` 输入不合法 / `1001C0002` 数据校验未通过 / `1001S0001` 密钥服务暂不可用 / `1001S0002` 加解密操作失败）；**后续公共组件从 1002 顺延申请，禁止跨段占用**（评审③P3-3：位宽表述已由"8 位"更正为 9 位）；
6. **红线兑现**：密钥材料/明文/密文禁止入代码、日志与异常消息（组件对外文案为服务端常量）；密钥文件禁止入库（`.gitignore` + gitleaks 门禁兜底）；组件总开关 `ctds.crypto.enabled=false` 时 Bean 全不注册（使用方注入失败 = 启动失败，杜绝"以为加密其实没加密"的静默旁路）；
7. **合规证据与遗留义务**（Q4 口径的执行记录）：SM3/SM4 算法正确性测试向量（GB/T 32905/32907 公开示例）经 **OpenSSL 3.5.5、Python gmssl、BouncyCastle 1.85.2 三重独立实现交叉计算一致**后锁定为测试断言（编码会话 2026-09-08，过程留痕开发日志）；因本机网络不可达标准原文站点：①向量与 PDF 原文的逐字核对、②SM2 固定 k 附录示例向量（不凭记忆写入）——**登记为 4.3.3"国密合规验证"的前置补齐义务**；SM2 现阶段以 C1C3C2/DER 结构断言 + 加解密与验签双向用例覆盖。

## 4. 理由与业务影响说明

- **理由**：GCM 是唯一同时满足"完整性内置（防篡改可判定）+ 主流实现无坑"的 SM4 模式；信封带版本位使密钥轮换（2.6.3）与大文件分块（3.5.3）不破坏既有密文可读性；KeyProvider 抽象把"接 KMS"从算法组件解耦出去，演示期零外部依赖；三重实现交叉计算是网络受限条件下对"测试值不可能是 AI 编造"的最强自证；
- **成本**：无新增采购；bcprov 1.85.2 已登记 `docs/dependencies.md`；
- **风险**：① SM2 附录向量未逐字核对（已限 4.3.3 补齐，S0 级外部测评天然覆盖）；② 本地密钥文件仅演示级保护（OS 文件权限），生产必须先落 2.6.3——部署基线应禁止以默认配置上生产；③ 大文件超 64MiB 直接拒绝（防内存打爆），3.5.3 落地流式分块方案前不得加密超限文件；
- **影响范围**：全部业务服务（引入即合规）、std-adapter（测评项"国密调用路径全覆盖"以本组件为单一审计面）、2.6.3/3.1.8/3.5.3/4.3.3。

## 5. 可替换性（组件级替换路径，防锁定）

1. **密钥源可替换**：`KeyProvider` 为唯一密钥供给抽象，2.6.3 真实 KMS 以定义 Bean 整体替换本地文件实现，业务与组件本体零改动（评审①④已用 Bean 覆盖测试钉死）；
2. **算法库可替换**：算法调用全部收敛在本组件 6 个门面类内（Sm4Service/Sm2Service/Sm3Service 及内部），BouncyCastle 若因安全公告需更换为国产库（如 GmSSL 的 Java 版），只改本组件内部调用点，对外契约（信封格式/错误码/配置）不变；本组件不注册全局 JCE Provider，替换无系统级副作用；
3. **格式版本可演进**：密文信封版本位（0x01）预留，算法升级或密钥轮换（2.6.3）通过新增版本号向后兼容，旧密文不失效；
4. **不可替换边界（红线）**：全平台任何 SM2/SM3/SM4 运算不得绕过本组件自行实现——这是"唯一入口"制度的反面约束，4.3.3 将按"国密调用路径全覆盖审查"校验。
