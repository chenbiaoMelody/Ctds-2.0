## 1. 背景

章程 4.3 / AGENTS §3：幂等与分布式锁是点名要求收敛 `common` 的横切能力——重复投递不重复处理、并发资源不互相踩踏，是数据流通平台的刚需（消息消费、回调、库存/额度扣减）。WBS 2.4.7 交付"幂等组件、锁组件 + 用例"，为后续业务包提供统一、不可绕过的执行入口。

## 2. 备选方案与取舍

| 决策点 | 方案 A（采用） | 方案 B（弃） | 取舍理由 |
| --- | --- | --- | --- |
| 基础设施 | **Redis 实现（ADR-001 冻结栈内）为主 + 内存实现兜底** | 纯 Redis / 纯数据库（MySQL 唯一键/悲观锁） | 幂等与锁都需要跨实例共享状态，Redis 已在栈内且性能/语义最优；内存实现作无 Redis 演示/单测/单机兜底（接口抽象 + 配置切换），避免 2.4.11 Testcontainers 未建的测试阻塞；数据库实现避免双中间件依赖（lofi Q1"认可"） |
| 分布式锁实现 | **Redisson RLock**（看门狗自动续期/可重入/释放校验持有者） | spring-data-redis 自封装 Lua 锁脚本 | 锁协议正确性（崩溃自动释放、误删他人锁防护）由成熟库保证，**锁协议不自研**——与"不自研算法"红线同逻辑；Redisson 3.52.0 已核验官方注册表且与 Spring Boot 3.5 同主次兼容（4.x 面向 Boot 4 弃用）；AI 语料/外部顾问接手成本最低（lofi Q2"选 Redisson"） |
| 幂等语义 | **模式 B 结果复用**：重复请求不重复执行、返回首次结果 | 模式 A 防重复提交（重复直接拒绝） | 数据流通"重复投递不重复处理 + 可取回首次结果"是刚需（消息/回调消费）；A 可视为 B 的简化子集（lofi Q3"选 B"） |
| 幂等/锁键 | **SpEL 表达式（方法参数上下文）+ 全局前缀** | 请求头/固定前缀 | 业务代码一行声明键来源，显式可审计；前缀防跨业务键冲突 |
| 基础设施不可用语义 | **fail-closed**（存储/锁不可用 → 报错拒绝执行/放行） | fail-open（降级执行） | 幂等不可用仍执行 = 可能重复处理；锁不可用仍放行 = 可能超卖/踩踏——安全默认（沿红线 7 精神） |
| 模式配置缺失语义 | **默认 redis + 安全失败**（mode=redis 但无 Redis 依赖/连接 → 启动失败显式报错） | 默认 memory 静默降级 | 内存实现是单机语义，多实例部署静默降级 = 悄悄失效（防单机语义误用） |

## 3. 决策（契约正文，实现 = `common-idempotency`，设计定稿 `docs/designs/WBS-2.4.7-hifi.md`）

1. **组件边界**：`@Idempotent`（幂等，模式 B 结果复用）与 `@Locked`（互斥锁）注解 + 切面（Spring AOP）；幂等键/锁键 = 配置前缀 + SpEL 表达式求值（方法参数上下文，如 `#orderNo` / `#productId`）；表达式为 null/空/求值失败 → `1000C0001`（快速失败，不执行业务）；
2. **幂等语义**：同一幂等键首次执行并缓存成功结果（结果 TTL = 注解 `expireSeconds` 或配置默认 600s）；重复请求不执行业务、返回首次结果（反序列化按方法泛型返回类型还原，null 为合法结果）；业务异常释放执行权、不缓存、可重试；幂等键被占用且无结果（业务执行中）→ `1002C0001`"请求处理中，请稍后重试"；执行中标记 TTL 与结果 TTL 分离（`processing-ttl-seconds` 默认 60s，complete 时延长到结果 TTL——结果有效期内同键保持"已占用"）；**使用方责任：processing TTL 须 ≥ 业务最长执行时间，超长业务可能被重复执行**；
3. **锁语义**：同一互斥键并发调用只有一个进入，其余等待 `waitSeconds`（默认 3s，配置 `default-wait-seconds`）；超时 → `1002C0002`"操作繁忙，请稍后重试"；持锁时间 `leaseSeconds` 默认 -1 = Redisson 看门狗自动续期（持锁线程存活期间锁不过期、崩溃自动释放——防死锁）；释放校验持有者（Redisson 原生语义，误删他人锁不可能）；业务异常 finally 释放（不泄漏）；解锁失败不覆盖业务结果（看门狗/leaseTime 兜底过期）；
4. **双实现与部署边界**：`IdempotencyStore` / `LockService` 接口抽象 + Redis（默认，production 语义）/ 内存（单机语义，演示/单测/单机部署）双实现，`ctds.idempotency.mode` / `ctds.lock.mode` 切换，`@ConditionalOnMissingBean` 支持业务整体替换；**多实例部署必须 mode=redis**（内存实现不跨实例，配置注释与文档明示）；mode=redis 但引入方无 spring-data-redis/Redisson 依赖 → 内嵌配置类字符串条件守卫不加载 → 缺 Bean 启动失败（安全失败，不静默降级）；
5. **错误码模块位规划（沿 ADR-006 §3-5 顺延）**：`02` = 幂等与锁组件（`IdempotencyErrorCodes`：`1002C0001` 请求处理中 / `1002C0002` 操作繁忙 / `1002S0001` 幂等存储不可用 / `1002S0002` 锁服务不可用）；S 码出站统一"系统繁忙，请稍后重试"（沿 ADR-006 评审①P2-3 已确认口径）；errorcode 组件既有码与行为零改动；
6. **审计联动**（沿 2.4.5 已确认口径）：幂等命中/处理中、锁超时默认记审计（复用 2.4.4 AuditRecorder，`audit-enabled` 默认 true 可配置关闭）；
7. **依赖与红线**：分布式锁唯一实现来源 = `redisson-spring-boot-starter:3.52.0`（optional 引入——防无 Redis 环境被 Redisson 自动配置牵连；Redis 模式由引入方显式加依赖触发；锁协议不自研）；注解切面 = 官方 `spring-boot-starter-aop`；返回值序列化 = `jackson-databind` + `jackson-datatype-jsr310`（Boot BOM 管理，支持 java.time 返回值）；组件开关 `enabled=false` → Bean 全不注册（fail-fast，沿 2.4.5 教训）；密钥/敏感信息不入日志与对外文案。

## 4. 理由与业务影响说明

- **理由**：幂等与锁是横切能力，收敛 `common` 后业务一行注解获得正确性由库/组件保证的语义（不自研锁协议、fail-closed 防重复与超卖）；接口抽象 + 双实现使演示/单测零中间件、生产走 Redis 不改变业务代码；
- **成本**：无新增采购；redisson 3.52.0 / aop / jackson 三件已登记 `docs/dependencies.md`（PO 预授权，2026-09-09）；
- **风险**：① 内存实现仅单机语义，误用于多实例会静默失效——配置注释与文档明示，部署基线（2.5.x）应强制 redis；② Redis 哨兵/集群高可用属 2.5.x，V1.0 组件连接单节点、配置预留；③ processing TTL 与业务执行时长失配可能重复执行——使用方责任（契约第 2 条）；
- **影响范围**：全部业务服务（消息/回调消费幂等、库存/额度互斥）；2.4.11 集成测试基建（Redis 契约测试策略观察项）；2.5.x（Redis 部署基线）。

## 5. 可替换性（组件级替换路径，防锁定）

1. **实现可替换**：`IdempotencyStore` / `LockService` 为唯一抽象，业务定义 Bean 即整体替换（@ConditionalOnMissingBean 钉死）；Redis ↔ 内存按配置切换零代码改动；
2. **锁库可替换**：Redisson 调用收敛在 `RedissonLockService` 单类内，若需更换锁实现只改该实现类与依赖登记，对外契约（注解/错误码/配置/看门狗语义）不变；
3. **不可替换边界（红线）**：全平台分布式锁不得绕过本组件自行实现（与"唯一入口"制度同逻辑）；幂等不得各自散落实现（章程 4.3 横切能力收敛义务）。
