## 1. 背景

平台每个业务服务都会有数据库表结构，且随业务迭代持续变化。人工改表不可追溯、不可复现、环境间必然漂移；"谁改了表、改到哪一版、新环境如何从零建到最新"必须由工具统一管理。ADR-001 已冻结 MySQL 8 与 Spring Boot 3 技术栈，本 ADR 固化迁移工具链的平台级规范（WBS 2.4.10 产出定义："迁移脚本规范、版本化管理、示例迁移"）。

## 2. 备选方案与取舍

| 备选 | 取舍结论 |
| --- | --- |
| **Flyway（选定）** | Spring Boot 官方 auto-config 原生集成、脚本即纯 SQL（全员无编程团队可直读评审）、Java 生态事实标准、资料密度最高。取舍：社区版无 undo 命令（以"只前进"纪律承接） |
| Liquibase | 变更以 XML/YAML 描述、支持结构 diff 生成，功能更强；但多一层抽象、评审成本高、对无编程团队不友好。**不采用** |
| 人工执行 SQL 脚本 | 不可追溯、不可复现、跨环境漂移。**禁止**（红线：任何环境禁止手工改表结构） |
| 自研迁移框架 | "组件只封装、协议不自研"红线逻辑同样适用——迁移版本化协议（历史表、校验和、顺序）不自研。**禁止** |

## 3. 决策（规范正文）

1. **工具**：Flyway（`flyway-core` + `flyway-mysql`，版本由 Spring Boot BOM 统一管理，dependencies.md 登记）；Spring Boot auto-config 承载，服务启动时自动执行；
2. **脚本位置**：各服务 `src/main/resources/db/migration/`（Flyway 默认 locations，不另设目录）；
3. **脚本命名**：`V{版本号}__{业务描述}.sql`（版本号为正整数、严格递增取"该库 history 最大版本+1"；描述用下划线连接的业务可读短语；双下划线分隔符固定）；
4. **一条脚本只做一件事**：一个脚本对应一个可独立评审的结构/数据变更，禁止把多个不相关变更塞进一个脚本；
5. **已应用脚本禁止修改**：Flyway 校验和（checksum）防篡改——脚本应用后再改动将导致启动失败（fail-fast）；确需变更时**新增**版本脚本（数据订正走新 V 脚本），禁止改历史脚本、禁止删除已应用脚本；
6. **只前进不回滚**：不做 undo；错误变更以新版本脚本反向修复（新表→无则补建，错数据→订正脚本）；
7. **禁止乱序**：`spring.flyway.out-of-order=false`（默认），版本号必须递增，防止多环境应用顺序分歧；
8. **脚本评审**：迁移脚本随 PR 走与代码相同的评审链（4 视角评审 + 门禁），脚本即代码；
9. **历史表**：`flyway_schema_history` 为迁移工具内部表，业务代码禁止读写；
10. **密钥零入库**：数据源口令只经环境变量/配置中心注入，迁移配置文件不出现真实口令（章程红线 7）。

## 4. 理由与业务影响说明

- **业务影响**：表结构变更从"人工操作"变为"随版本发布的可评审工件"——每次变更可追溯（谁/何时/哪个版本）、可复现（新环境一键建到最新）、可审计（历史表记录）；演示/验收环境的数据库准备从"按文档手工执行"降为"启动即自动就绪"；
- **无库兼容**：迁移随服务启用以 profile 显式开启（如 example-service 的 `mysql` profile），不接库的服务行为零变化；
- **fail-fast 优于带病运行**：库不可达、校验和不符一律启动失败，杜绝"部分迁移"的中间状态对外服务。

## 5. 影响范围

- 全部含数据库的 services/（现 example-service 示例接入，后续业务服务遵循本规范）；
- 门禁：无新增门禁（脚本随 PR 评审链 + 既有门禁覆盖）；2.4.11 Testcontainers 建成后，条件集成测试升级为容器化自动执行；
- 运维（2.5.x）：部署脚本需保证数据源环境变量注入（CTDS_DB_URL/CTDS_DB_USER/CTDS_DB_PASSWORD 约定，见 example-service `application-mysql.yml`）。

## 6. 可替换性（组件级替换路径，防锁定）

- Flyway 为**可替换组件**而非平台契约：业务代码只依赖"表结构最终状态"，不依赖 Flyway API（示例演示代码亦仅经 JdbcTemplate/仓储访问数据，不 import 任何 Flyway 类）；
- 替换路径：如未来需切换 Liquibase 等工具，仅需各服务替换依赖与转换脚本格式（changelog），`flyway_schema_history` 归档后由新工具接管基线；业务代码零改动；
- 数据库本身的可替换性不在本 ADR 范围（ADR-001 冻结 MySQL 8；国产化替代走 ADR-001 变更流程）。
