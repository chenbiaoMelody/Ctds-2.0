## 1. 背景

E2E 测试要验证"真实浏览器里页面渲染 + 路由跳转 + 用户交互"全链路正确。2.4.9 交付的前端验证 = Vitest + jsdom 单测——jsdom 无法验证真实浏览器渲染、Element Plus 真实交互与路由 history 行为，浏览器链路目前只能人工目测、无自动回归。WBS 2.4.12 产出定义"E2E 框架选型接入 + 登录冒烟示例"，本 ADR 固化平台级 E2E 规范。

## 2. 备选方案与取舍

| 备选 | 取舍结论 |
| --- | --- |
| **Playwright（@playwright/test，选定）** | 微软官方维护、Vite/Vue 官方文档 E2E 章节推荐方案（栈内配套）、自动等待 + 内置断言（AI 生成质量高）、webServer 自动起停 dev server、npm 核验 1.63.0 / engines node>=20 / Apache-2.0 / 无 peer 依赖（npmmirror 2026-09-12 实测）。取舍：需一次性下载 Chromium 二进制（不入库） |
| Cypress | 曾并列主流：对多标签页/多域名架构受限、商业化许可模式近年频繁变动、国内无官方下载镜像。**不采用** |
| WebdriverIO | 配置面大、文档对新手不如 Playwright 友好（章程 4.1"AI 生成质量最高"第一准则）。**不采用** |
| 不做 E2E（维持单测 + 人工目测） | 浏览器链路覆盖缺口不补，违背本工作包产出定义。**不采用** |

## 3. 决策（规范正文）

1. **框架与作用域**：`@playwright/test`（devDependency，版本登记 `docs/dependencies.md` 前端 npm 表）；浏览器二进制（`npx playwright install chromium`）为本机开发资源，gitignore 不入库；**仅 Chromium 最小实现**，多浏览器/移动视口矩阵留观察项；
2. **配置契约**：`frontend/playwright.config.ts`——`testDir: './e2e'`；`webServer` 自动起停 vite dev（5173，`reuseExistingServer: !process.env.CI`）；`trace: 'retain-on-failure'` + `screenshot: 'only-on-failure'`；失败留痕落 `test-results/`（gitignore，不入库）；
3. **定位纪律**：用 `getByRole`/`getByPlaceholder`/`getByText` 语义化定位，**禁止 CSS/XPath 选择器**（防实现细节耦合，UI 重构不破测试）；
4. **webServer 自足纪律**：`npm run e2e` 一条命令闭环（自动起停 dev server 与浏览器），不依赖人工先起服务；端口 5173 被占用时 webServer 探测失败属预期行为（先释放端口再跑；CI 固定端口策略待 2.5.x）；
5. **分层口径**：E2E 不替代单测——组件逻辑/守卫函数断言留 Vitest（jsdom），E2E 只覆盖跨组件真实浏览器链路（登录、导航、权限重定向等冒烟级）；同一守卫规则在单测为**规则级**断言、在 E2E 为**链路级**断言（真实浏览器 history 路由 + localStorage 持久 + Element Plus 渲染）——链路必经的重叠不构成"同一行为两边重复断言"违规（评审③④复核口径留痕）；
6. **演示占位口径**：登录冒烟的演示登录页为骨架期占位（非真实认证，真实认证/令牌签发归属待 3.9.1 规格澄清），E2E 不臆造后端接口；
7. **门禁口径**：`frontendLint`/`frontendTest`（enabled）随 Java 门禁一起跑；`frontendE2E` 登记 PENDING-CI（CI 环境浏览器二进制供给待 2.5.x 部署基建评估），不计入门禁 PASS/FAIL 门数——本机可 `npm run e2e` 手动全量；门禁配置变更以本 ADR + WBS-2.4.12 设计确认记录为留痕（章程红线 3 变更流程载体）。

## 4. 理由与业务影响说明

- **业务影响**：浏览器链路（登录 → 工作台 → 权限重定向 → 退出）从人工目测升级为每次可自动回归——前端回归缺陷在合入前被机器拦截的概率上升；业务人员演示口径不变（打开应用即见登录页，页面明示演示性质）；
- **门禁稳定性**：新增两阶段均为秒级快检（lint 约 10s、单测约 70s），E2E 不进门禁不增加门禁时长与脆弱面（浏览器二进制供给未决前不引入红灯风险）；
- **对无编程团队**：E2E 结果业务可读（"登录流程在真实浏览器里验证通过"），一条命令可复演。

## 5. 影响范围

- `frontend/`（playwright.config.ts、e2e/、登录页与路由守卫改造、既有单测适配）；
- 门禁：gates-config.json + run-gates.ps1 新增前端三阶段（frontendLint/frontendTest enabled，frontendE2E PENDING-CI）——本 ADR 即该变更的留痕载体之一；
- 环境要求（非门禁硬性）：E2E 真实执行需本机一次性 Chromium 二进制；2.5.x 落地后 CI 浏览器供给随其评估；
- 观察项：① 多浏览器/移动视口矩阵；② 视觉回归（截图比对）工具链；③ frontendE2E 门禁阶段启用（待 2.5.x CI 环境评估）；④ E2E 对接真实后端（登录页换真实认证）随 3.9.x；⑤ ADR-010 §5 观察项②（"E2E 框架若需浏览器容器沿 ADR-010 扩展"）**本次不触发**——webServer 本机直起 Chromium，无需浏览器容器；⑥ run-gates.ps1 **Maven 段** allowlist 检出违规后仍继续执行命令的存量语义缺陷（前端段已在 WBS 2.4.12 修复为标志位跳过整阶段）随 2.5.x 门禁基建统一修复。

## 6. 可替换性（组件级替换路径，防锁定）

- Playwright 为**可替换组件**而非平台契约：业务代码（src/）零依赖其 API（E2E 收敛于 `frontend/e2e/` 与配置文件），替换工具时业务代码零改动；
- 替换路径：如未来切换其他 E2E 工具（如 Cypress），仅需重写 `frontend/e2e/` 用例与配置，被测前端代码不变；语义化定位纪律（§3.3）保证用例本身也不耦合实现细节；
- 前端框架本身的替换不在本 ADR 范围（ADR-001 冻结）。
