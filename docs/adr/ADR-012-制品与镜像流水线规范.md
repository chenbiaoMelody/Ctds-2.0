## 1. 背景

WBS 2.2.6 要求产出"nightly 构建、镜像 tag、SBOM 产出"。项目现状：无 CI 平台（2.2.2 已确立"本地门禁脚本、与 CI 平台解耦"先例），编排师裁决（2026-09-12）按**本地脚本版**落地；下游 2.5.1/2.5.2 需要统一的镜像命名与产物目录契约，否则容器化与部署脚本将各自为政。此外信通院测评与供应链安全要求对后端/前端第三方组件出具"材料清单"（SBOM）。

## 2. 备选方案与取舍

- **SBOM 工具**：CycloneDX 双插件（选定）vs Syft CLI（弃：需运行时拉取外部镜像，供应链面更大、版本无法锁定入仓）vs OWASP Dependency-Track 全家桶（弃：超出 1 会话范围，属平台级部署）。
- **落地形态**：本地 PowerShell 脚本（选定，沿 2.2.2/ADR-011 先例）vs 直接搭 CI（弃：无 CI 平台，产出会打折；定时调度/远程推送登记 PENDING-CI）。
- **cyclonedx-maven-plugin 接入方式**：全坐标带版本命令行调用（选定，不进 build 生命周期，避免每次 `mvn package` 都产 BOM 的开销）vs 根 pom build/plugins 固化（备选记录，CI 接入时若需每次构建出 BOM 再启用）。

## 3. 决策（规范正文）

### 3.1 流水线入口与阶段

- 一条命令：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\pipeline\nightly-build.ps1`（退出码 0=全绿 / 1=阶段失败 / 2=环境自检失败，与门禁 0/1/2 契约同形）。
- 阶段顺序固定：N1 环境自检 → N2 质量门禁（复用 `scripts/gates/run-gates.ps1`，非 GREEN 即停）→ N3 后端打包（`mvn -B -ntp package -DskipTests`，测试已由门禁跑过）→ N4 前端打包（`npm run build`）→ N5 SBOM 生成 → N6 镜像 tag 计算 → N7 汇总报告。
- 失败即停：任一阶段非零退出立即中止后续阶段，保留现场并出具报告（含最后 30 行错误摘录）。

### 3.2 镜像 tag 命名规范

```
ctds/<模块名>:<版本>-<yyyymmdd-hhmm>-<git短哈希>[-dirty]
```

- `<模块名>`：Maven 模块取路径末段（errorcode / pagination / logging / auth / crypto / idempotency / std-adapter / example-service）；前端固定 `frontend`；`connector-sdk` 为占位（独立仓库策略，ADR-002，SDK 仓库另计）。
- `<版本>`：Maven 模块 = 根 pom 版本（当前 `2.0.0-SNAPSHOT`）；frontend = `package.json` 的 `version`。
- `[-dirty]`：git 工作区有未提交改动时追加；tag 计算工具 `scripts/pipeline/image-tag.ps1` 是**唯一规范出处**（-ModuleName 单个输出 / -All 全清单）。

### 3.3 SBOM 产出规范

- 后端：根目录 `mvn -B -ntp org.cyclonedx:cyclonedx-maven-plugin:2.9.3:makeAggregateBom -DskipTests`（聚合全模块），版本号由脚本显式给定。
- 前端：`frontend/` 内 `npx @cyclonedx/cyclonedx-npm@6.0.1 --package-lock-only`（以锁定文件为准），JSON 与 XML 各一份。
- 每份 SBOM 计算 sha256 汇总到 `OUT/sbom/SHA256SUMS.txt` 作为对账口径。
- **完整性边界（PENDING-CI 留痕）**：本地版中 SHA256SUMS.txt 与 SBOM 同目录同脚本生成，防篡改能力有限（可被一并重写）；CI 接入时应对账文件外部锚定（制品库元数据/签名），属 2.5.x 部署基建范围。

### 3.4 产物目录契约

```
build-output/<yyyymmdd-hhmmss>/     # 整目录 gitignore，不入库
  backend/<模块名>/*.jar
  frontend/dist/
  logs/<阶段名>.log                  # 各阶段完整输出（N2 门禁另出具报告）
  sbom/{backend,frontend}/… + SHA256SUMS.txt
  reports/                          # 门禁报告（nightly 直接将 -ReportPath 指向此处）
  image-tags.txt
  nightly-report.md                 # 汇总报告（业务可读）
```

## 4. 理由与业务影响说明

- 三段式 tag（版本/时间/代码哈希）让任何一个镜像都能回答"哪个版本、何时构建、来自哪份代码"，缺陷回溯与测评取证不需要人猜；`-dirty` 防止"来路不明"的镜像混入。
- 门禁先行、全绿才打包：保证进入"出厂包装"的代码一定过了质量关，包装线不重复跑测试（时间省一半），也不绕过门禁（无特批红线不变）。
- SBOM 让"我们用了哪些别人的组件"从口口相传变成机器可查清单，测评与漏洞排查（如某组件爆出 CVE 时）可直接定位影响面。
- 本地版与 CI 版的差距（定时调度、远程制品库推送）已在设计中登记 PENDING-CI，接 CI 时只平移不重写。

## 5. 影响范围

新增 `scripts/pipeline/`（nightly-build.ps1、image-tag.ps1、README.md）、ADR-012（本文件）、frontend 开发依赖 1 项、dependencies.md 登记 2 行、.gitignore 1 条。**门禁仅 1 处增量配置**：`gates-config.json` 的 `secretsExcludePaths` 追加 `build-output`（该目录为 gitignore 本地产物、零源码；排除理由：① secretsScan 会读到 nightly 正在写入的阶段日志导致 ReadAllBytes 独占冲突崩溃；② 构建产物入库扫描只会产生假阳性。与既有 node_modules 排除先例同口径，不改变任何检测阶段行为）。**不改**：根 pom、任何业务代码、run-gates.ps1 脚本逻辑。

## 6. 可替换性（组件级替换路径，防锁定）

- SBOM 格式与工具可替换：CycloneDX → SPDX/Syft 只需替换 N5 阶段命令，tag 命名与目录契约不受影响（格式变更需重走依赖审批）。
- 镜像仓库与命名前缀 `ctds/` 可在 CI 接入时按部署环境改写（image-tag.ps1 单点修改）。
- 本地脚本 → CI 流水线平移：CI 系统只需依次执行同批命令并检查退出码（与门禁 D-3"切换接口预留"同思路）。
