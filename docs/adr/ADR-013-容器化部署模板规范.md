# ADR-013 容器化部署模板规范（容器化对象口径、基础镜像、Dockerfile 与 K8s 模板约定）

| 关联任务 | WBS 2.5.1（本 ADR 为其规范载体）；消费方：WBS 2.5.2 一键部署工具链、2.5.3 监控告警基座 |
| 关联 ADR | ADR-001（技术栈冻结）、ADR-010（镜像显式标签禁 latest 的精神来源）、ADR-012（镜像命名与产物目录契约） |

## 1. 背景

WBS 2.5.1 要求"各模块容器化 + K8s 编排模板"。2.2.6（ADR-012）已交付镜像命名契约与制品流水线；本任务交付"集装箱装箱说明书"（Dockerfile）与"机房摆放图纸"（K8s 模板）。边界：模板本身与单箱实测归 2.5.1，注入工具链与集群部署演练归 2.5.2。

## 2. 备选方案与取舍

- **Dockerfile 形态**：运行层 + COPY 预构建产物（选定）vs 多阶段自包含构建（弃：容器内需重新拉取全部 Maven/npm 依赖，本机 aliyun 镜像与 npmmirror 配置均不可进容器，慢且网络不稳；与 2.2.6"流水线产构件、下游消费"契约相悖。留观察项，CI 环境有缓存后再评估）。
- **探针类型**：tcpSocket（选定）vs HTTP 探针（弃：后端业务端点有鉴权，未认证 401 会让 HTTP 探针假红；tcpSocket 只验证端口监听，无假信号）。
- **镜像注入**：模板内占位符（选定）vs kustomize overlay 管理版本（弃：镜像 tag 为时间戳动态生成，kustomize edit 的文件变更会污染工作区；2.5.2 若需多环境 overlay 再引入）。

## 3. 决策（规范正文）

### 3.1 容器化对象口径

"各模块容器化"按**可运行制品**口径覆盖：`example-service`（Boot fat jar，8080）与 `frontend`（nginx 静态）。common/* 六个组件为 jar 库、由服务携带，不单独成箱；connector-sdk 沿 ADR-012 占位（独立仓库策略，ADR-002）。

### 3.2 基础镜像（显式 tag，禁 latest）

| 基础镜像 | 用途 | 约定 |
| --- | --- | --- |
| `eclipse-temurin:17-jre` | 后端运行环境（ADR-001 Java17 冻结栈配套） | 登记于 dependencies.md"容器基础镜像"节；变更走依赖流程 |
| `nginx:1.29-alpine` | 前端静态托管 + SPA fallback | 同上 |

- 拉取通道：直拉 Docker Hub；受网络限制时可经 `docker.m.daocloud.io` 拉取后 `docker tag` 改回规范名（本机操作留痕，不入库）。

### 3.3 Dockerfile 约定（打包说明书，非构建说明书）

- 只做"运行环境 + 拷入预构建产物"：后端 COPY `target/example-service*.jar`（由 nightly N3 或本地 `mvn -B -ntp package -DskipTests` 供给）、前端 COPY `dist/`（N4 或 `npm run build` 供给）。
- 后端：非 root 运行（专用用户 uid 1001；uid 1000 已被基础镜像默认用户占用，实测留痕）、`-XX:MaxRAMPercentage=75.0` 使 JVM 堆随容器内存限制伸缩。
- 前端：`nginx.container.conf` 覆盖 default.conf，SPA history 路由 fallback `try_files ... /index.html`。
- `.dockerignore` 用白名单口径（先 `*` 再例外），build context 只收运行必需文件。

### 3.4 K8s 模板约定（deploy/k8s/）

- 每模块 Deployment + ClusterIP Service 共 4 份 YAML；labels 统一 `app.kubernetes.io/part-of=ctds`。
- 镜像字段占位符 `IMAGE_PLACEHOLDER`，由 2.5.2 工具链注入 ADR-012 canonical tag；未注入直接 apply 属防呆边界（K8s 拒绝非法镜像名）。
- 探针：tcpSocket（后端 8080 / 前端 80），initialDelay 30s（Spring 启动窗）/5s（nginx），period 10s。
- 资源基线：后端 requests 256Mi/250m、limits 1Gi/1000m；前端 requests 64Mi/50m、limits 256Mi/500m。
- 中间件（MySQL/Redis/Nacos）不进本套模板；后端默认 profile 无库自足（WBS 2.4.10 B3）。

## 4. 理由与业务影响说明

- "打包说明书"口径让镜像构建复用 2.2.6 流水线产物，一条流水线串起"构建 → 装箱"，且不受容器内网络限制；代价是 build 前须先有产物（README/ADR 已载明，build 报错即提示）。
- 非 root + 内存感知 JVM + 资源基线：容器安全与稳定性默认项，避免一个箱子吃光整机内存。
- tcpSocket 探针：业务可用性监控在 2.5.3 做，探针只负责"进程活着"，职责分离避免假信号误导自动重启。

## 5. 影响范围

新增 `services/example-service/{Dockerfile,.dockerignore}`、`frontend/{Dockerfile,.dockerignore,nginx.container.conf}`、`deploy/k8s/`（4 YAML + README）、ADR-013（本文件）、dependencies.md"容器基础镜像"节。**不改**：pom、业务代码、scripts/gates、scripts/pipeline。

## 6. 可替换性（组件级替换路径，防锁定）

- 基础镜像可替换：temurin → 任意官方 JRE17 镜像、nginx → caddy 等，只改 Dockerfile 一行（登记更新走依赖流程）。
- 编排模板可替换：K8s YAML → docker-compose/Helm，模板与代码无耦合（镜像名经占位符注入，来源始终是 ADR-012 契约）。
- 部署目标可替换：同一镜像可在任何 OCI 运行时（K8s/Docker/Podman）运行。
