## 1. 背景

ADR-006 交付了全平台唯一加解密入口与 `KeyProvider` 抽象，V1.0 密钥以本地文件实现承载（演示级保护，等保清单"数据保密性"行明确"生产必须先落 2.6.3"）。等保三级"密码管理"控制项与数据分类分级规范（密钥材料 L3、生产 L4 优先 KMS 托管）要求密钥集中托管、可轮换、禁硬编码。WBS 2.6.3 产出 = KMS 接入、密钥轮换策略、禁硬编码检查，预算 1 会话。

## 2. 备选方案与取舍

| 决策点 | 方案 A（采用） | 方案 B/C（弃） | 取舍理由 |
| --- | --- | --- | --- |
| KMS 形态 | **平台内置自建 KMS 服务**（`services/kms`，密钥库加密落 MySQL，根密钥环境变量注入） | B 外接开源 KMS（Vault 等）/ C 云厂商 KMS | 零采购零新中间件（ADR-001 冻结栈内完成）、国密口径可控（复用 common-crypto 不自研）、演示与生产同构；B 需技术栈变更流程且国密支持存疑，C 依赖云采购与外网连通且厂商锁定——两者均超 1 会话预算。业务影响对比表经编排师裁决（2026-09-13） |
| 轮换载体 | **信封格式 v2**（信封头写入 4 字节密钥版本号，解密按版本取历史密钥） | 信封外另存版本映射表 / 解密时逐版本尝试 | ADR-006 §5.3 预留版本位正是此用途：版本随密文自描述，逐版本尝试既慢又在多版本共存时语义含糊 |

## 3. 决策（规范正文，实现 = `services/kms` + `common-crypto` KMS 接入件，设计定稿 `docs/designs/WBS-2.6.3-hifi.md`）

1. **密钥托管**：平台 SM4 数据密钥全部收敛 `services/kms`（编号+版本管理）；密钥材料经根密钥（环境变量 `CTDS_KMS_ROOT_KEY` 注入，缺失/坏值启动失败 fail-fast）SM4-GCM 信封加密落 MySQL，**库中无明文密钥**；业务服务配置 `ctds.crypto.kms.base-url` 即经 `KmsKeyProvider`（覆盖 KeyProvider Bean，ADR-006 §5.1）透明接入，业务代码零改动；KMS 不可达一律收敛 `1001S0001`，禁止静默降级；
2. **信封 v2**：`CTSE`(4B)+`0x02`(1B)+密钥版本(4B 大端)+IV(12B)+密文+GCM 标签(16B)；版本化密钥源（实现 `VersionedKeyProvider`）产出 v2，本地文件实现继续产出 v1（行为零变化）；轮换后旧密文按信封内版本取历史密钥解密，**旧密文不失效**；
3. **轮换策略**：授权管理员显式触发（`kms.admin` 权限注解强制，未认证 401/无权限 403+DENIED 审计），轮换 = 新增版本 + 审计四要素（操作者/时间/编号/新旧版本）同事务落库；自动定时轮换登记非目标；
4. **禁硬编码检查**：secretsScan 门禁在既有 7 条正则上补 2 条（密钥命名旁的 Base64 赋值、`CTDS_KMS_ROOT_KEY` 字面量），红灯即拒、无特批；测试向量以"测试材料"命名语义与真实密钥区分（门禁双向验证留痕：样本红灯×2、正常内容绿灯×2）；
5. **错误码模块位**：KMS 服务取 `02`（`1002C0001` 输入不合法 / `1002B0001` 编号已存在 / `1002B0002` 编号或版本不存在 / `1002S0001` 内部错误）——沿 ADR-006 §3.5"从 1002 顺延"制度，本 ADR 即占用留痕；
6. **红线兑现**：密钥材料/明文禁入代码、日志、异常消息；根密钥只经部署环境注入（配置文件仅允许 `${CTDS_KMS_ROOT_KEY:}` 间接引用）；密钥运算全部复用 common-crypto，本服务不自研任何密码学。

## 4. 理由与业务影响说明

- **理由**：自建 KMS 把"密钥集中托管"落在冻结栈内，演示与生产同构，避免为过等保而引入外部采购；信封 v2 让轮换成为纯密钥库操作，业务与存量密文零感知；
- **业务影响说明**：对运维——根密钥是唯一需要保密注入的部署项（丢了 = 密钥库不可解，属最高级运维资产）；对业务方——加密数据的"身份证"（密钥版本）随密文走，轮换不改历史数据；等保三级"密码管理"控制项由制度级 ✅ 升级为实施级 ✅（证据见等保清单刷新）。

## 5. 影响范围

`common-crypto`（VersionedKeyProvider/KmsKeyProvider/信封 v2/装配）、新增 `services/kms`（根 pom 模块表 +1）、`scripts/gates/gates-config.json`（secretsPatterns +2）、ADR-006（v2 注记）、等保清单三行、等保清单 §S-01 secretsScan 行；下游 3.1.8/3.5.3/4.3.3 的密钥供给口径。

## 6. 可替换性

1. **KMS 服务可替换**：调用方只见 HTTP 供给接口（元数据/材料）与 `VersionedKeyProvider`——未来换商业 KMS 或信封加密模式，只替换 `KmsKeyProvider` 实现与 kms 服务内部，业务代码零改动（与 ADR-006 §5.1 同构）；
2. **存储可替换**：密钥库访问收敛 `KeyRepository` 端口，MySQL 实现可替换；
3. **不可替换边界（红线）**：全平台 SM4 运算仍必须经 common-crypto 唯一入口；KMS 服务自身也不例外（RootKeyConfig 以 KeyProvider Bean 接入即为兑现）。
