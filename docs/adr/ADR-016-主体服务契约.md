## 1. 背景与目的

主体服务（`services/subject-service`）是第一个承载 C 系业务能力的服务模块。沿 ADR-015 先例，将编码期新占用的平台级契约（错误码模块位、库表、状态机、撤销重报语义）固化留痕，供后续包（3.1.3~3.1.5 同服务扩展、C-1.2 DID 衔接）遵守。

## 2. 决策内容

### 2.1 错误码模块位：主体服务占用 1004 段

- 既有占用：1000 平台公共 / 1001 国密组件 / 1002 幂等锁组件 + KMS 服务（双重占用，ADR-015）/ 1003 std-adapter。
- **主体服务段 = 1004**（九位格式 `1004[CBS]nnnn`），首两码：`1004B0001` SUBJECT_ALREADY_REGISTERED（该主体已注册）、`1004C0001` SUBJECT_CANCEL_NOT_ALLOWED（当前状态不可撤销）。
- **认证类扩展（WBS-3.1.3，2026-09-13）**：`1004B0002` CERT_LICENSE_UNRECOGNIZABLE（证照影像无法识别请重传）、`1004B0003` CERT_USCC_MISMATCH（确认值与证照识别结果不一致）、`1004B0004` CERT_LEGAL_PERSON_MISMATCH（法人信息与证照识别结果不一致）、`1004B0005` CERT_VERIFY_LIMIT_REACHED（今日核验次数已用完请次日再试）、`1004B0006` CERT_LICENSE_NOT_CONFIRMED（请先完成证照上传与核对确认）、`1004C0002` CERT_STATE_NOT_ALLOWED（当前状态不允许执行认证操作）、`1004S0001` CERT_CHANNEL_UNAVAILABLE（认证服务暂不可用请稍后重试——本地处理器精确映射 503 并保留业务文案，不落全局 S 型脱敏）。
- 复用 1000 段通用码（参数/未认证/无权限/资源不存在/内部错误），common-errorcode 组件零改动。
- **审核域（WBS-3.1.5，2026-09-13）零新增**：审核状态门槛复用 `1004C0002`、申请编号不存在/归属不匹配同形出站复用 `1000C0003`（§2.6 口径）、参数与权限拒绝复用 1000 通用码——防后续包误以为审核域有独立码段。
- **政务类扩展（WBS-3.1.4，2026-09-13）**：`1004B0007` CERT_CHANNEL_TYPE_MISMATCH（主体类型与认证流程不匹配，请使用对应主体的认证方式——通道互斥双向同码：政务主体调企业认证端点 / 企业主体调政务端点；归属断言在前，能触达者已是本人或授权角色）。政务 CA 验证业务不通过**不是错误码**（结论 FAIL + 明确原因返回，与法人核验同构）。

### 2.2 主体状态机锁定（规格行为 4 V1.0 最小集，实施包不得增删）

`PENDING_CERT 待认证 → PENDING_REVIEW 待审核 → ADMITTED 已入驻`；`PENDING_REVIEW → REJECTED 已驳回`；`PENDING_CERT → CERT_FAILED 认证失败`。流转触发端分工：注册→待认证（3.1.2）；待认证→待审核 / 认证失败（3.1.3）；待审核→已入驻/已驳回（3.1.5）。

**WBS-3.1.5 兑现补记（2026-09-13）**："待审核→已入驻/已驳回"两条流转边已随 WBS-3.1.5 交付（`ReviewService.approve/reject` 经 `SubjectStatusService.transition()`，触发方 `TriggerRole.REVIEWER`、operator=审核员身份，留痕备注"审核通过"/"审核驳回：+理由"）——上句分工表述保留原文、以本补记标注兑现；并发双审核（approval/rejection 竞用同一乐观门槛）恰一人胜出已固化集成测试 `concurrentReviewExactlyOneWinner`；审核域审计动作常量 `certification.review.approve/reject`（沿 certification.* 命名域，hifi 接口契约）；边集六条、状态枚举五值不变。

**WBS-3.1.3 补记（2026-09-13，4 视角评审）**：①增补流转边 `CERT_FAILED 认证失败 → PENDING_REVIEW 待审核`（认证失败主体重新核验通过后自动流转，lofi Q1-A 裁决口径，hifi B11）——边集扩为六条，状态枚举五值不变；②流转执行口径收紧：`appendTransition` 同事务**更新 subject.status 列**（此前仅落留痕不更新状态列，评审打回项——核验通过后库内状态原地不动）并带 `WHERE status = from_status` 乐观门槛（并发重复流转 0 行即拒 1004C0002，hifi 边界值"transition() 状态门槛拒绝"的实现落点）；③时间源统一 Clock 注入。

### 2.3 库表契约（库 `ctds_subject`，Flyway V1/V2 迁移脚本）

- `subject`（主体，一行=一个主体，`uk_uscc` 唯一索引终身占用）、`subject_status_log`（流转留痕，from=NONE 表示注册建档）、`subject_daily_seq`（申请编号当日序号，`INSERT ... ON DUPLICATE KEY UPDATE` 原子取号）。
- **认证类表（WBS-3.1.3，Flyway `V2__add_certification_tables.sql`，2026-09-13；4 视角评审补正同日）**：`cert_material`（证照材料：影像 SM4 密文 LONGBLOB + **content_sm3 影像 SM3 摘要**（完整性锚点，唯一入口 common-crypto，ADR-006 Q2 裁决——评审修正原 SHA-256 自行摘要方案）+ OCR 原始结果 SM4 密文 + 确认要素；**`uk_subject_type (subject_id, material_type)` 唯一键**兜底并发替换窗口；重复上传删旧插新保留最近一次）、`cert_verification_log`（认证渠道调用记录：verify_type 含 LEGAL_PERSON 与 OCR_LICENSE 两类调用、渠道标识/请求流水号/结论/耗时三要素留痕，渠道标识与流水号一律取自渠道接口出口；`counted=1` 仅限法人核验 FAIL，渠道异常与 OCR 调用一律不计失败次数）；`subject` 表加列 `applicant`（申请人身份，归属断言依据，存量行回填 legacy-demo）。
- 申请编号格式：`S + yyyyMMdd + 6 位当日序号`，为认证、审核、查询的统一业务标识。
- L4 字段（证照影像/OCR 原始结果/身份证号）一律 common-crypto SM4 加密落库（影像介质 = SM4 加密落库，lofi Q2 裁决）；政务 CA 材料表随 3.1.4 建表。
- **政务 CA 材料落定（WBS-3.1.4 补记，2026-09-13；PO 确认"五问均采建议"）**：上句"政务 CA 材料表建表"预留收敛为**复用 `cert_material` 表 + `material_type` 新增值 `GOV_CA_CERT`**（两表结构完全同构：证书文件密文进 content_cipher、SM3 摘要进 content_sm3、渠道验证要素 JSON 密文进 ocr_raw_cipher；`uk_subject_type` 唯一键天然保证一主体一证书，重复提交替换保留最近一次）——零 DDL 零迁移（Flyway 无 V3）；`cert_verification_log.verify_type` 新增值 `GOV_CA`（counted 恒 0——政务无失败次数概念，lofi Q3-A）；`ocr_*` 列名对 GOV_CA_CERT 材料语义泛化为"渠道原始要素/渠道结论"，不重命名（V2 已冻结库表契约，改名即破坏性变更）。

### 2.4 撤销重报口径（lofi Q3-A，规格行为 1 第 5 条的落地方案）

- **不新增状态**：撤销 = 撤销流转留痕（待认证→待认证，触发方=申请人，remark=`申请人撤销，待重新提交`），状态保持待认证；"最新留痕 = 撤销备注"即撤销标记契约。
- 重报 = 同一主体记录复用（申请编号不变）：更新可变信息、状态重置待认证、落"驳回后重新申请"/"撤销后重新提交"留痕；已入驻/待审核/认证失败状态不可撤销亦不可重报。
- 管理员账号属重报可变字段集合（PO 确认时未否决 hifi 边界表末行默认口径）。
- **重报可变字段集合（4 视角评审补固化，2026-09-13）**：主体名称/注册地址/联系人姓名/联系电话/管理员账号——**不含主体类型**（hifi 行 126 接口契约枚举口径）。主体类型决定政务 CA 通道归属（规格行为 6），不随重报变更；如需放开须走设计变更流程。

### 2.5 注册幂等契约

- `@Idempotent(key = "#command.uscc")`（ADR-007 模式 B，幂等键 = 统一社会信用代码）：同键重复请求在结果 TTL 窗口内返回首次结果。
- **已知边界（登记观察项）**：幂等窗口内（默认 600s）同信用代码再次注册返回首次结果而非"该主体已注册"拒绝；窗口过后业务重新执行、走唯一性拒绝。规格行为 1 第 2 条（重复注册拒绝）与第 3 条（重复请求返回首次结果）在无客户端请求令牌时无法区分，V1.0 取"窗口内复用、窗口外拒绝"口径。后续如需精确区分，演进方向 = 客户端生成请求令牌并入幂等键（需规格变更流程）。
- **边界后果披露（4 视角评审补记，2026-09-13）**：窗口内第二申请人（含另一申请人以相同信用代码发起的全新注册）将收到**首次申请人的申请编号**作为注册成功结果，与"重复注册不泄露已有账号信息"的立法目的存在张力。V1.0 缓解口径：① 演示/试运行期为受控小范围开放，同信用代码由同一申请人持有；② 可按运维需要调低 `ctds.idempotency.default-expire-seconds`（结果缓存 TTL，默认 600s）收窄窗口（窗口内复用与窗口外拒绝的界线随 TTL 前移）；③ 该口径已由集成测试 `idempotencyWindowReturnsFirstResultEvenWhenPayloadDiffers` 固化为回归锚点。**规格侧留痕与验收剧本同步已于 2026-09-13 经 PO 确认补记（规格 C-1.1 V1.1 行为 1 第 3 条 + 剧本 S1 步骤 2 同步）。**

### 2.6 对象级越权缺口登记（已裁决：方案①，2026-09-13）

- 现状：`GET /{subjectNo}` 与 `POST /{subjectNo}/cancellation` 仅校验功能级权限（subject.read/cancel），**未校验申请编号归属当前身份**——任何持 applicant 角色的用户可查询/撤销他人申请（含联系人信息）。
- 定性：已确认 hifi 接口契约未定义归属校验，实现与设计一致，属**规格/设计缺口**而非实现偏差，按章程不得私自补码。
- **裁决（2026-09-13，编排师预授权"选业务上更合理的方案"，判定留痕如下）**：**采方案①——`subject` 表增加申请人身份列（`applicant`，注册建档时取 `AuthContext.subject()`）+ 查询/撤销（及后续认证操作）归属断言**：当前身份 = 申请人本人或持授权角色（审核员）方可操作，不匹配 → 403 + 拒绝审计留痕。理由（业务语言）：本平台业务本质为**多主体平台**（企业/机构/政府均可入驻），认证档案含 L4 敏感信息（联系人、后续证照影像与 OCR 结果），"谁能查看/操作谁的申请"是数据分类分级规范 §4.4（L4 最小授权）与等保个人信息保护控制项的业务底线；方案②"单租户信任网关"仅在演示链路成立，回写规格等于把安全缺口固化为长期契约，与 PRD"多主体可信空间"矛盾。
- 实现落点：**已随 WBS-3.1.3 交付（2026-09-13）**——`subject.applicant` 列（Flyway V2）、`OwnershipGuard` 归属断言组件（申请人本人或持 subject.review 审核权限方可操作），覆盖查询/撤销/上传/确认/核验/档案查询/影像查看/结束认证全部端点；双向用例（本人通过/他人被拒+审计）已固化集成测试 `ownershipGuardBlocksOtherApplicantAndExemptsReviewer`。"裁决前不得对多用户开放"约束解除。
- **出站口径补正（4 视角评审，2026-09-13）**：归属不匹配的出站由原拟"403"改为**统一 400 + `1000C0003`"申请编号不存在"**——与"编号确不存在"的出站完全同形，消除申请编号枚举探测的存在性侧信道（DENIED 审计照常落痕，actor+reason 可回溯；功能级无权限仍由 @RequirePermission 403 拦截在前）。

### 2.7 身份信任边界补记（AUD-03，2026-09-19）

- **现状声明**：V1.0 演示期，servlet 服务（subject-service / example-service / **kms**，凡依赖 common-auth 的 SERVLET 服务均同）经 `AuthContextFilter` **直连信任客户端明文身份头**（`X-Ctds-Subject` / `X-Ctds-Roles`）；`common-auth` 的 `HeaderStripFilter`（剥离入站身份头）目前装配在**网关侧**（Reactive，3.5.2 交付物），直连链路不经过它——即演示环境下浏览器端可伪造身份头获得任意角色（含审核员）。
- **安全边界口径**：V1.0 演示期的安全边界 = **网络隔离**（演示 profile 绑定 `server.address=127.0.0.1`，服务仅本机可达，不得对外暴露端口）+ **3.5.2 网关**（上线后 `HeaderStripFilter` 剥离外部入站身份头）+ **3.9.1 真实令牌**（签发与鉴权替代演示身份头）。三者全部就位前，本服务**不得对非本机网络开放**。
- **启动纪律（AUD-03 评审②补）**：演示后端**必须带 `--spring.profiles.active=mysql` 启动**（默认 profile 未绑定回环）；**不得以 `--server.address` / `SERVER_ADDRESS` 等参数覆盖回环绑定**；**前端开发服务器（vite, 5173）同样仅本机启动、禁止 `--host` 对外开放**——否则其代理会把外部请求转发到本机回环 8080，形成绕过网络隔离的旁路（AUD-03 评审④补）。残余口径：回环绑定只隔离网络，**同一台机器上的其他程序仍可访问演示服务并伪造身份头——演示机须为可信机器、演示期间不在其上运行不可信程序**。
- **kms 服务暴露面登记（AUD-03 评审②补，M1）**：kms 同为直连信任身份头的 servlet 服务——伪造 `X-Ctds-Roles: admin` 可获 `kms.admin`（KeyAdminController）；`/api/v1/keys/{keyRef}/material` 明文返回密钥材料且无鉴权（其安全前提即审核报告 G-01"内网边界"，网关+令牌就位前不成立）。**kms 的 mysql profile 尚未绑定回环**（本卡边界仅覆盖 subject/example 两服务）；缓解现状：kms 不在 C-1.1 演示链路，且三服务共用 8080 端口不能并存运行——**kms 演示/启用前必须先补 `server.address=127.0.0.1` 并重建构件**（登记于债务账 DB-03 行）。
- **KMS/DID 回环落实补记（WBS-3.1.8，2026-09-21）**：kms `server.port` 8080 → **8081**、mysql profile 补 `server.address=127.0.0.1`；新增 `services/did` 服务 mysql profile 同样绑定 `server.address=127.0.0.1`（端口 **8082**）——本卡"kms 尚未绑定回环"的欠账随 WBS-3.1.8 实施清偿（DB-03 注记同步）。三服务端口分派：主体 8080 / KMS 8081 / DID 8082，均可并存回环运行。DID→KMS 内部回环调用以服务身份头（`X-Ctds-Subject: did-service` + `X-Ctds-Roles: admin`）访问密钥对创建端点，真实边界仍为网络隔离 + 网关 HeaderStripFilter + 真实令牌三件套（本节既定口径不变）。
- **默认 profile 语义更正与防御性回环（清债卡3 / DB-24，2026-09-26）**：kms 与 subject 的 `application.yml` 曾注明"默认 profile 无数据库照常启动"，实测均**不可启动**——仓储构造器硬依赖 `JdbcClient`，排除 `DataSourceAutoConfiguration` 后无该 Bean → `UnsatisfiedDependencyException`（kms 实测 2026-09-25、subject 实测 2026-09-26），注释已对齐事实：**演示与服务一律 `--spring.profiles.active=mysql` 启动**（与本节启动纪律一致；did 注释此前已正确，subject 原"照常启动"表述系失实，随 DB-24 同批更正）。同批为三服务**默认 profile 补配置级 `server.address: 127.0.0.1`**（kms/did/subject，防御性只增不减、无行为影响）——至此三服务**任意 profile 均配置级绑定回环**，上文"启动纪律"中"默认 profile 未绑定回环"的括号注记欠账清偿；回环绑定以配置文件为准，不依赖启动方式与环境注入。
- **风险登记**："身份头可伪造"已登记债务账 **DB-03**；解除条件 = **3.5.2 网关上线 + 3.9.1 真实令牌生效**。`frontend/src/api/client.ts` 等处"越权防护安全边界在后端鉴权"的无条件表述已同步更正（2026-09-19，AUD-03）。
- 对象级越权防护不受本补记影响：`OwnershipGuard` 归属断言（§2.6）在服务端逻辑内生效；但其判定输入仍是身份头（**判定前提 = 身份真实，可信性由本节边界保障**），传输层信任口径收紧前不构成身份之外的额外防线。

## 3. 影响

- 后续包约束：3.1.3/3.1.4/3.1.5 不得新建平行错误码段/状态枚举/主体表；流转一律经 `SubjectStatusService.transition()`（留痕强制 = 仓储写方法一律要求 StatusTransition 参数）。
- 流转触发端分工已全部兑现（WBS-3.1.5 关闭后，C-1.1 状态机无待交付边）。
- 审核驳回、认证自动流转调用本契约时无需再次审批，直接扩展。

## 4. 备选方案与取舍（WBS-3.1.6 补记；结论均引自各决策小节与对应包 lofi 问题确认留痕，无新增裁决）

- 错误码段：A. 新占用 1004 段（**采**，按 ADR-005 模块位分配序）；B. 并入 1000 平台公共段（**不采用**——错误码表按模块登记，混段后归属与演进无法追踪）。
- 状态机：A. 规格五态最小集（**采**）；B. 增设"已撤销"独立状态（**不采用**——规格行为 4 禁增删状态，撤销以"留痕标记 + 同行复用"实现，见 §2.4）。
- 政务 CA 材料：A. 复用 `cert_material` + `material_type=GOV_CA_CERT`（**采**，3.1.4 lofi 五问采建议、§2.3 补记）；B. 新建独立证书材料表（**不采用**——与既有表完全同构，徒增 DDL 与迁移版本）。
- 注册幂等：A. 幂等键=信用代码、"窗口内复用、窗口外拒绝"口径（**采**，§2.5）；B. 客户端请求令牌并入幂等键（**暂缓**——须规格变更流程，登记为演进方向）。
- 对象级越权：A. 方案①申请人列+归属断言（**采**，§2.6，PO 预授权判定留痕）；B. 方案②单租户信任网关+回写规格（**不采用**——把安全缺口固化为长期契约，与多主体平台定位矛盾）。

## 5. 理由与业务影响说明（WBS-3.1.6 补记）

- **理由**：主体服务是第一个 C 系业务服务，编码期占用的平台级契约（模块位/状态机/库表/语义口径）若不集中固化，后续包各自发散将造成不可逆漂移；沿 ADR-015 先例在实施包内留痕。
- **业务影响说明**（业务可读）：错误码统一 → 演示与排障时对外提示口径可预期、不泄露内部实现；状态机锁定 → "谁在何时以何身份流转"全程可审计，准入底线（人工审核不免）稳定；库表契约 → 认证档案（证照/核验/证书）真实落库可回溯，L4 信息密文存储；归属断言 → 任何申请人看不到他人申请；幂等口径 → 网络重试不产生多份申请，但 600 秒窗口内重复注册"复用首结果"的边界已如实登记并固化为回归锚。

## 6. 影响范围（WBS-3.1.6 补记）

- 代码：`services/subject-service` 全部分层（1004 段唯一使用方）；`common-errorcode` 错误码表登记；`std-adapter` 认证域扩展接口（收口契约不变，ADR-008）；库 `ctds_subject` Flyway V1/V2 迁移脚本。
- 后续包：C-1.2 DID 签发以 `ADMITTED` 为衔接入口（衔接契约随 3.1.7 规格定义）；主体冻结/注销等运营态（C-1.3）须走规格变更 + 本契约变更；真实认证渠道接入 = ADR-008 §8 Bean 注册替换点，业务代码零改动。
- 文档：C-1.1 规格 V1.1 与验收剧本 V1.1 已随 3.1.5 前补记同步。

## 7. 可替换性（组件级替换路径，防锁定；WBS-3.1.6 补记）

- 状态机与错误码段属平台契约：任何变更走"规格变更流程 + 本 ADR 变更留痕"，不存在实现层私改通道。
- 库表为可演进契约：Flyway 版本化追加（ADR-009），本 ADR 冻结的是"五态语义 + 1004 段位"而非物理列布局；`ocr_*` 列语义泛化先例（§2.3）即此口径的落地样例。
- 可替换组件登记：模拟认证渠道（替换点 ADR-008 §8）、归属断言（`OwnershipGuard` 组件收敛）、幂等口径（客户端令牌演进口，§2.5）——替换均不影响业务三层代码。
