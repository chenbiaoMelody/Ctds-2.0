# ADR-018 质量度量门禁接入（覆盖率 / 变异测试 / 静态安全扫描）

| 字段 | 内容 |
| --- | --- |
| 状态 | 已采纳（2026-09-26，清债卡1 / DB-06 执行，编排师裁决 Q1=A 命令行形态） |
| 背景 | 债务 DB-06："三个质量刻度尺没装"——覆盖率、变异测试、静态扫描均未接入，历次达标数字是临时手工测的，无法被重新算一遍（审核报告 AUD-06）。章程 4.2 阈值表（核心模块行覆盖 ≥80%、整体 ≥70%、变异杀除率 ≥60%）自项目启动即写入 `gates-config.json` 的 `thresholds` 节，但 `run-gates.ps1` 对其**零引用**（门禁"假执行"核对报告 2026-09-25 实测确认）；coverage/mutationTest/sast/dependencyScan 四段自 V1.0 起固定 PENDING。3.1.12（C-1.2 测试补全与集成）已实证 jacoco / PIT 命令行测量的可行性（did 行覆盖 96.22%、变异杀除率 68.18%），按其设计偏离登记 §11-1 的接入建议，将"只测量"升级为"门禁内常态运行"（WBS-2.2.8 / DB-06 承接）。 |
| 决策 | ① **coverage 段**：jacoco **0.8.12** 经 Maven 全限定插件目标命令行调用（`org.jacoco:jacoco-maven-plugin:0.8.12:prepare-agent test ...:report`，零 pom 变更），一次运行完成插桩测试与报告；runner 解析各模块 `target/site/jacoco/jacoco.xml` 的 LINE counter，聚合整体行覆盖并对 `coreModules`（按模块目录尾名映射，当前存在的核心模块 = did / common-crypto / common-auth——评审①勘误补记：auth 同属 coreModules 清单且模块存在，ADR 初稿漏计；coreModules 中 policy-engine/metering-billing 两项目前无对应模块目录，coverage 核心判定按尾名匹配自然不触发，扩展时自动纳入）逐个判定，阈值取 `thresholds.coreLineCoverage=80` / `overallLineCoverage=70`（**thresholds 节自此被实际读取**）。② **mutationTest 段**：PIT **1.30.0** CLI（主类 `org.pitest.mutationtest.commandline.MutationCoverageReport`）+ `pitest-junit5-plugin 1.2.1`；工具 bundle 经**临时 pom + `dependency:copy-dependencies`** 聚合到 `target/precheck/pit-bundle/`（marker 文件防重复装配；走用户级 settings 阿里云镜像，依赖完整性由 Maven 解析保证）；范围 = config 显式登记的模块/包（当前仅 `services/did` 服务层 `com.ctds.did.application.*`），排除 `*IntegrationTest`（容器化集成用例不可在 PIT 进程内重复运行）；**运行工作目录 = 模块根**（源集守卫测试依赖相对路径读 src/）；杀除率口径 = `(KILLED + TIMED_OUT) / 全部突变`（NO_COVERAGE 计入分母的**保守口径**，与 3.1.12 基线 68.18% 同源可比），阈值 `thresholds.mutationKillRate=60`。③ **sast 段**：semgrep **官方镜像**（`semgrep/semgrep:latest`）+ `p/java` 社区规则集，docker 运行时挂载 **%TEMP% 源集副本**（仓库路径含空格，直接挂载不可靠）；扫描面 = services/common/std-adapter 的 Java 主源集；**热点 = 0 判定**；镜像**不自动 pull**（缺镜像 = ERROR 并提示手动拉取留痕，供应链自查义务留在人机两侧）。④ **dependencyScan 维持 PENDING 不接入**：OWASP Dependency-Check 首次运行需 GB 级 NVD 库全量同步（数小时），本机预算不可行——如实登记另立卡评估（镜像化 + 离线 NVD 库方案），禁止以 PENDING 冒充已接入。⑤ **时长预算**：coverage 900s / mutationTest 1800s / sast 900s 独立计时（config `timeoutSeconds`），与 unitTest 段（241~250s / 上限 600s）互不挤占；超时 = FAIL。⑥ 全部新段失败语义与既有段一致：FAIL=1（代码结论）、ERROR=2（环境/配置）、超时=FAIL。 |
| 理由 | Q1=A（编排师裁决 2026-09-25）：命令行形态零 pom 变更、可回退、与 3.1.12 实证平滑衔接。jacoco/PIT 版本锁定 3.1.12 实证版本（不追新），杀除率口径保守化（NO_COVERAGE 不剔除）以诚实反映测试盲区——3.1.12 中 `DidManagementQueryService` 22 突变无覆盖拉低整体分的教训即该口径的价值（促补测试而非豁免数字）。sast 用容器形态而非本机安装（semgrep 官方不支持 Windows 原生运行）；规则集选社区 `p/java`（官方维护、免自写规则）。dependencyScan 不接入是**如实登记**而非"未开放"语义（台账 DB-06 关闭条件禁止 PENDING 冒充）。 |
| 备选 | ① jacoco/PIT 走 Maven 插件写入各模块 pom（需逐模块 pom 变更 + 依赖登记 + 白名单审批；耦合度高、回退成本大——弃）；② PIT 走 `pitest-maven` 直调（3.1.12 实测不可行：JUnit5 支持必须经 pom 插件依赖，命令行注入无入口——弃，见 3.1.12 hifi §11-1）；③ sonarqube 承载复杂度/重复度/安全扫描（重基建，待 2.5.x 部署基建评估——complexity 段维持 PENDING）；④ OWASP DC 用 docker 镜像 + 预下载 NVD 离线库（可行方向，另立卡）。⑤ semgrep 自写最小规则集入库（维护成本转嫁项目；社区 p/java 官方维护更优——弃）。 |
| 业务影响说明 | ① 门禁单次总时长增加约 10~15 分钟（coverage ~4 分钟 + mutationTest ~3 分钟 + sast ~1 分钟），仍为本地手动触发（无定时 CI），不阻塞任何在线演示链路；② 红灯语义业务可读："覆盖率不达标 = 测试覆盖不足该模块，需补测试后重交"，无业务功能变更；③ 全量门禁 GREEN 后，章程 4.2 的三个质量阈值自本 ADR 起由"手工测量声明"变为"机器每次重算"——质量声明可复核；④ 供数不变：不触碰业务代码、数据库、演示环境。 |
| 影响范围 | `scripts/gates/run-gates.ps1`（新增 coverage/mutationTest/sast 三段 + Invoke-MetricProcess 辅助）、`scripts/gates/gates-config.json`（V1.4：三段 enabled + 配置 + changeLog）、`scripts/gates/selftest.ps1`（S11 三段假执行防护 + 反向探针）、`scripts/gates/README.md`（阶段表与留痕同步）、`docs/dependencies.md`（工具登记）、`target/precheck/pit-bundle/`（运行期产物，不入库）。**零业务代码变更、零迁移、零业务依赖引入**（jacoco/pitest/semgrep 为门禁工具链，不入 pom）。 |
| 可替换性 | 三段全部经 `gates-config.json` 配置驱动：工具版本（jacoco 0.8.12 / PIT 1.30.0 / semgrep 镜像 tag 1.177.0——**评审②勘误：镜像禁用 latest tag**，锁接入实测引擎版本，沿容器镜像登记纪律）、范围（coverage 的报告 glob 与 coreModules；mutationTest 的 modules/包名表——**范围来自 stages.mutationTest.modules 独立清单而非 coreModules**，auth/crypto 等其余核心模块的变异覆盖扩展时在 modules 表加行即可，扩展时点随对应模块的下一张触碰卡）、阈值（thresholds 节）、预算（timeoutSeconds）均可配置更换；任一段可 `enabled=false` 独立回退（回退后该段回到 PENDING 语义须同步恢复 status 字段，不留"静默关闭"）。runner 侧解析器按工具输出格式（jacoco XML / PIT XML / semgrep JSON）实现，更换工具须同步改解析段并在 changeLog 留痕。 |
