## 1. 背景与目的

规格行为 4 规则 2 定义使用控制策略五要素（次数 / 期限 / 用途 / 域内使用 / 禁止再分发）与"至少启用一项或显式声明无使用限制"门槛，规则 3 要求与空间域策略模型"对齐复用"，规则 6 要求要素取值非法在发起与协商提交时即拒绝；三项未定义项（DSL 语法、字段与解析器、与空间策略模型的形态对齐）由规格尾注单归 3.4.4。

WBS-3.4.3 已交付 `UsageControlPolicy` 承载结构（五要素值对象 + 固定字段序 JSON）与两道最小校验（`shapeViolations` 结构 / `basicValueViolations` 取值 / `hasAnyRestrictionOrDeclared` 确认门槛），并在其 hifi §10-7 登记衔接义务：**本卡承载结构为最小口径，其定稿演进须由其设计并做兼容映射，禁止两处并行定义**。本 ADR 固化 DSL 契约与校验单点落点，供 3.4.5 引擎 / 3.4.6 模拟器 / 3.4.7 界面 / C-4.6（V1.5 AI 生成策略草稿）共同遵守。

## 2. 决策内容

### 2.1 DSL 形态 = 结构化声明式策略文档（Q1-A）

- **策略即代码的落地形态 = 结构化声明式 JSON 文档**：带 `dslVersion` 版本位 + 封闭要素目录 + 强类型取值，随条款版本行行级版本化（存于 `contract_clause_version.clause_values_cipher` 的 SM4 密文内）。
- **边界（有意不做）**：不做自定义文本语法（类 Cedar/Rego 一行式）——消费方盘点（3.4.5 引擎直读模型 / 3.4.6 模拟器跑结构化用例 / 3.4.7 界面结构化表单 / C-4.6 AI 生成输出 JSON 最稳且可 schema 校验）无一需要文本语法，文本语法 = 词法/语法解析器维护面，V1.0 零消费方；不做元数据驱动的通用校验引擎（五要素静态已知，直写类型化校验 = 最平庸实现）；不做 dslVersion 多版本分流框架（V1.0 单版本，仅留版本门槛与演进规则）。
- **文档结构**（hifi §2.1）：`{dslVersion?, quota?, term?, purpose?, territory?, noRedistribution?, noRestrictionDeclared}`；字段名与取值形态与 3.4.3 hifi §6.2 完全一致（已验收面零变更），本卡新增仅 `dslVersion` 一个可选字段。`noRestrictionDeclared` 为布尔声明位，**不是要素**（不入目录键集）。
- **JSON 重复键口径**：文档解析沿 Jackson 默认行为——同一对象内同名重复键取**末值**（后写覆盖先写），校验与落库均作用于折叠后的同一文档视图。四类键（版本位 / 声明位 / 目录顶层字段名 / 要素叶子字段名）重复均同此口径；因"校验视图 = 落库视图"（不存在校验后重新解析的缝隙），该行为**不构成校验绕过**（4 视角评审②核实结论）。

### 2.2 五要素字段定稿表与两层命名映射

| 目录键（模型层，对齐空间命名规范） | 文档字段名（载荷兼容层） | 显示名 | 值类型 | 约束 | 判定语义标注（供 3.4.5） |
| --- | --- | --- | --- | --- | --- |
| `usage.quota` | `quota`（值在 `quota.maxCount`） | 使用次数上限 | integer | ≥ 1 | 使用次数上限；计数口径（按调用/按交付）= 3.4.5 未定义项 |
| `usage.term` | `term`（值在 `term.startDate` / `term.endDate`） | 使用期限 | date-range | 起止有序；起始日 ≥ 提交日 | 期限内有效；相对期限（自生效起 N 天）自动换算 = 3.4.5 未定义项 |
| `usage.purpose` | `purpose`（值在 `purpose.text`） | 用途限定 | text | trim 后非空 | 精确等值匹配（约定外用途拒绝）；词表化/多值 = 3.4.5 未定义项 |
| `usage.territory` | `territory`（值在 `territory.text`） | 域内使用 | text | trim 后非空 | 精确等值匹配（域外拒绝）；地域编码化 = 3.4.5 未定义项 |
| `usage.no_redistribution` | `noRedistribution` | 禁止再分发 | boolean | `enabled=true` 即禁止 | 再分发动作（转授/转售/对外提供）拦截 |

**两层命名分离**：目录键 = 治理/渲染/语义标注用的模型层标识；文档字段名 = 载荷兼容层（沿 3.4.3 已验收固定字段序，**不动**）。权威定义点 = `com.ctds.contract.domain.policy.PolicyElementCatalog`（键集与元数据唯一登记处）；扩要素 = 注册表追加一行登记。

### 2.3 与空间 `PolicyCatalog` 同构对齐契约（Q2-A）

- **同构不共码**：使用控制侧建立与 `com.ctds.space.domain.PolicyCatalog` 同构的要素目录注册表——单点权威注册表 / 键命名规范一致（"域.名词小写点分"）/ 封闭约束（空间 = 封闭枚举 + 严格度；本域 = 强类型 + 约束说明）/ 扩目录 = 注册表追加行。两个权威点各自服务本域，**空间域零改动**。
- **不共码理由**：两类策略业务对象不同（规格明文），值类型系统不同（空间 = 封闭枚举 + 严格度；使用控制 = 强类型复合值），强行代码级共用 = 抽象泄漏；空间域无消费使用控制策略的需求。
- **互不漂移评审锚**：本 ADR + 4 视角评审①（规格与设计符合性视角对照两个目录的同构性）为对齐义务的检查点；任一域扩目录或改命名规范须同步复核另一域。
- **迁移触发条件**：若 3.4.5 引擎最终**独立部署**（非同宿主服务），届时按变更流程评估把目录/解析器抽入 `common`（新 common 模块 = ADR-001 冻结面变更，须走审批）；在此之前维持 contract-service 宿主内落地。

### 2.4 解析器落点与校验单点收敛声明（Q3-A）

- **校验单点 = `com.ctds.contract.domain.policy.UsagePolicyDslParser`**（3.4.3 三件校验收敛迁入，兑现 hifi §10-7"禁止两处并行定义"）：
  - 提交路径 `parse(JsonNode)` / `parse(JsonNode, LocalDate)`：严格全查 R1~R7（文档形态 / 字段类型与未知要素封闭集 / 版本门槛 / 次数取值 / 期限取值与时点 / 文本 trim 规范化 / 互斥）；
  - 读路径 `parseTolerant(JsonNode)`：容忍解析（缺省版本 = 1.0、缺字段 = 禁用、不做提交时点校验；未知版本 fail-closed 拒绝解析，不冒充空策略）；
  - 确认门槛 `satisfiesConfirmGate(UsageControlPolicy)`：R8（W7 应用服务单点调用）。
- **调用点收敛清单**（hifi §4.3）：`ClauseValues` 提交载荷解析 / `ContractCommandService` 发起（150 行）与提案（548 行）改为随 `parse` 单点全查（删除二次取值校验）；确认门槛（265 行）改调 `satisfiesConfirmGate`；密文回读 / QC1 / 视图改走 `parseTolerant`，`UsageControlPolicy` 收敛为纯数据 + 序列化载体（校验方法与 `fromJson` 移除）。
- **收敛判据（评审锚）**：全仓 grep 无 `shapeViolations` / `basicValueViolations` / `hasAnyRestrictionOrDeclared` 的**残留调用**。
- **规则表 R1~R8 全量口径**见 hifi §4.2（本 ADR 不复制规则明细，以 hifi V1.0 为编码契约面）；错误码复用 `1008C0015`（POLICY_CLAUSE_INVALID），明细入服务端日志（沿 C0004/C0015 先例），**零新码位**。
- **判读分工**：封闭性（哪些要素/字段名合法）由目录 `fields()` 承载；校验规则（取值与时点）由解析器承载。

### 2.5 版本演进规则（Q4-①）

- **缺省容忍**：`dslVersion` 缺省 = "1.0"（3.4.3 存量密文无版本位，零迁移、零 DDL 回读）。
- **未知值 fail-closed**：提交路径拒绝（1008C0015）；读路径拒绝解析（不冒充空策略），不静默降级。
- **演进流程**：新增版本 = `UsagePolicyDsl.DSL_VERSION` 之外的新版本值 + 解析器多版本分支 + **兼容映射批**（存量读路径容忍 + 写路径按新版本校验），并同步修订本 ADR 与目录表。
- **写路径不持久化版本位**：`UsageControlPolicy.toJson` **不输出** `dslVersion`（DSL v1.0 为唯一版本，无需回写版本位）——提交载荷即使携带 `dslVersion`，落库密文内亦无该字段（集成锚 `t9_versionedPayloadStoredVersionlessAndReadTolerantly` 断言 `strategy.has("dslVersion") == false`）；读路径缺省容忍 = "1.0"。版本位"随行级版本化"的口径据此澄清为：策略文档**整体**随条款版本行保存于该行密文内，历史形态按其写入时点整体回读（读路径容忍），无跨行迁移。
- **v2 演进触发条件**：当且仅当出现"需要一个以上并存版本形态"的诉求（要素语义变更 / 新增要素需与 v1.0 载荷区分 / 消费方需按版本分流）时方启动 v2——触发动作 = 在解析器增加版本分支 + `toJson` 按版本输出版本位 + 兼容映射批（存量读路径容忍）+ 同步修订本 ADR 与目录表；在此之前维持 v1.0 单版本、写路径零版本位。

## 3. 理由

- **结构化声明式 JSON**：三类消费方（引擎直读模型 / 模拟器结构化用例 / 界面结构化表单）+ C-4.6 AI 生成 JSON 可 schema 校验——机器可校验性与"可版本化"同时满足，且无需新增解析器技术栈（零新依赖，ADR-001 冻结面零触碰）。
- **同构不共码**：以"模式契约 + ADR 留痕 + 评审锚"兑现规格"对齐复用"义务，避免为对齐而制造跨域耦合；空间域零改动即风险零外溢。
- **校验单点**：3.4.3 承载的两道校验与确认门槛分散在值对象与三个调用点，规则演进时极易漂移；单点收敛后"规则表 = 一处"（R1~R8），违规则由 4 视角评审与 grep 判据守住。
- **缺省容忍 + 未知值 fail-closed**：既保证 3.4.3 已验收面（存量合约、既有测试夹具、剧本走查载荷）零破坏，又使未来版本必须显式声明，避免"猜版本"。

## 4. 备选方案与取舍

- **Q1 备选 B（自定义文本 DSL，类 Cedar/Rego）**：字面更"policy-as-code"，但解析器复杂度大增、V1.0 无文本消费方——弃。
- **Q1 备选 C（复用空间条目字符串值域模式）**：期限起止/整数次数/布尔塞入字符串 = 类型丢失、校验弱化——弃。
- **Q2 备选 B（`common` 新沉淀共享策略模块 common-policy）**：代码级复用最彻底，但新增 common 模块触 ADR-001 冻结面，且两域需求差异大（抽象泄漏风险）——弃；保留"引擎独立部署时按变更流程抽取"的迁移触发条件（§2.3）。
- **Q3 备选 B（新增解析器但保留 3.4.3 既有校验并行）**：两处并行定义，直接违反 3.4.3 hifi §10-7 义务——弃。
- **Q4 备选 B（不做期限时点校验，仅保留起止有序）**：更保守，但规格"期限早于生效日"例将长期停留登记态；在提交时点唯一可判定的非法形态（期限起点落在过去）成本低且可测——故采时点校验。
- **Q5 备选 B（新占 1008C0020 DSL 版本不支持）**：V1.0 单版本无分流处理需求，码位膨胀无收益——弃，复用 1008C0015。
- **D1 备选（拆分本卡）**：规范—解析器—收敛映射三者不可分（拆则"解析器无规范可依 / 规范无实现可证 / 收敛悬空"）——不拆分。

## 5. 业务影响说明

- **业务语言**：合约里的"使用限制"从此有了一份**写得清、机器能验**的标准格式——次数、期限、用途、域内使用、禁止再分发五项，加上一个可选的"格式版本号"。起草或修改条款时，凡是写错的（版本不认识、期限已经过期、声明"没有限制"却又填了限制、文本只有空格），系统在**提交那一刻**就拒收并给出统一提示，不会再出现"先收下、后面执行时才发现矛盾"。
- **可见变化（用户视角）**：① 新增四类拒收场景（版本不支持 / 声明与要素矛盾 / 期限起始早于提交日 / 出现不认识的字段名）；② 用途与域内使用的首尾空格在保存时自动去掉，避免"看起来一样但不匹配"；③ 存量合约（没有版本号的老数据）照常读取与签署，无需数据迁移；④ 提示文案与错误码不变（仍为既有"策略条款不符合使用控制约定"）。
- **零副作用**：不改数据库表结构、不改加解密链路、不改演示环境；拒收场景不落任何合约或版本数据。

## 6. 影响范围

- **代码**：`services/contract-service` 新增包 `com.ctds.contract.domain.policy`（`UsagePolicyDsl` / `PolicyElementCatalog` / `UsagePolicyDslParser`）；收敛改造 `UsageControlPolicy`（移除三件校验与 `fromJson`，保留纯数据 + 序列化）、`ClauseValues`（提交解析与密文回读委托单点）、`ContractCommandService`（发起 150 行 / 确认 265 行 / 提案 548 行三处调用点委托）。
- **测试**：新增 `UsagePolicyDslParserTest`（合法/非法矩阵，含 R3/R5/R6/R7 四类新规则先红后绿）与 `PolicyElementCatalogTest`；收敛回归既有策略锚期望值与语义零变更（方法主体改线、期望值与语义不变）；集成锚四件（发起路径四类增强拒 C0015 / 提案路径同拒 / 存量兼容读探针 / trim 落库探针）。
- **零改动面**：零 DDL、零迁移、零跨服务改动、零新依赖、零门禁配置改动、零加解密改动、空间域零改动、错误码零新增；演示环境与演示库存量零触碰。
- **下游消费**：3.4.5 引擎（判定语义标注 + 解析产物，QC1 零改动）、3.4.6 模拟器、3.4.7 界面（按目录注册表渲染表单，要素集合零自持）、C-4.6（V1.5 AI 生成策略草稿载体）。

## 7. 可替换性

- **形态可替换路径**：若后续版本引入文本语法表层，`PolicyElementCatalog`（要素集合与元数据）与 `satisfiesConfirmGate`（确认门槛）可原样复用，只需新增"文本 → 文档"编译器并复用 `parse` 校验单点——目录与单点校验不被形态选择绑架。
- **落点可替换路径**：解析器为纯函数式静态组件（无状态、无 I/O、无 Spring 装配），迁移至 `common` 或独立模块仅涉包名与导入调整（迁移触发条件见 §2.3）。
- **版本门槛可演进**：多版本分流 = 在解析器加分支 + 目录表扩登记，存量读路径容忍策略不变（§2.5）。
- **错误码可细分**：若未来需要区分"版本不支持"等子态，可在 1008 段新增码位并改由解析器抛出——调用方仅依赖错误码常量，改动面收敛。
