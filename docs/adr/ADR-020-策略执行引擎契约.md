## 1. 背景与目的

规格行为 5（C-4.3 策略执行与绕过拒绝）要求：策略在调用链路服务端强制执行、五类越界一律拒绝并留痕、放行产生使用计数且双方可查执行记录。此前 3.4.3/3.4.4 已交付策略**载体与校验**（`UsageControlPolicy` 值对象 + `UsagePolicyDslParser` 校验单点 + `PolicyElementCatalog` 五要素目录含判定语义标注），但**没有任何执行判定实现**——策略"配置了但不会被拦"。

本 ADR 固化执行引擎的对外契约与关键口径，供上游（3.4.6 模拟器 / 3.4.7 界面 / 3.7.x 对账 / 3.8.3 存证）与下游（3.5.2 网关 / C-5.x 交付链）共同遵守，并兑现 3.4.4 移交-1 的四项未定义项落定。

## 2. 决策内容

### 2.1 落点与判定入口（Q1-A / Q2-A）

- **落点 = contract-service 同宿主**（沿 QC1 与解析器同宿主先例）：引擎件 `domain.policy`（`UsageRequest`/`UsageActionType`/`UsageVerdict`/`PolicyViolation`/`PolicyJudge`）+ 应用服务 `PolicyExecutionService` + 读面 `UsageQueryService`/`ContractUsageController`；**零跨服务改动**。ADR-019 §2.3 迁移触发条件保留：引擎独立部署时按变更流程抽 common。
- **判定入口 = 应用层方法，无新 HTTP 端点**：`UsageVerdict check(String contractNo, UsageRequest request)`（`@Transactional`）。
- **服务端强制**：判定唯一权威 = 服务端引擎（规格行为 5 规则 3"直接调用接口同样被拦截"）；界面提示不构成执行。
- **既有代码零改动**（上游已验收面）：`ContractQueryService.loadEffectiveStrategy`（QC1）/ `UsagePolicyDslParser` / `UsageControlPolicy` / `PolicyElementCatalog` / 既有控制器 diff 为空。

### 2.2 判定顺序表（顺序即行为）

| 步 | 判定 | 输入 | 拒绝口径 | 副作用 |
| --- | --- | --- | --- | --- |
| 1 | 合约定位 | QC1 `loadEffectiveStrategy` | 不存在 → `1008C0012`（防枚举同形，沿 R6~R11"不存在与非参与方同码同文逐字"口径；引擎不做参与方可见性二判，R12 承载可见性） | 无 |
| 2 | 状态门槛（移交-5 承接，S3-7） | 快照 status | 未生效 / TERMINATED / COMPLETED → `1008C0013`（策略随合约同步失效）+ 拒绝留痕 | 拒绝留痕 |
| 3 | 空策略 / 显式无限制 | `strategy = null` 或 `noRestrictionDeclared = true` | — | 放行 + 放行记录（不计数；usedCount 上限口径 = 无上限） |
| 4 | 期限（`usage.term` 启用） | 注入 Clock 当前日期 vs `[startDate, endDate]` | 当前日期 ∉ 区间（含首末日有效）→ `TERM_EXPIRED` | 无（全查） |
| 5 | 用途（`usage.purpose` 启用） | 请求用途 trim vs `purpose.text` | 不等值（大小写敏感精确比较，口径对称）→ `PURPOSE_MISMATCH` | 无（全查） |
| 6 | 域内（`usage.territory` 启用） | 请求地域 trim vs `territory.text` | 不等值 → `TERRITORY_MISMATCH` | 无（全查） |
| 7 | 再分发（`usage.no_redistribution` 启用） | `actionType = REDISTRIBUTE` | 触发 `REDISTRIBUTION_FORBIDDEN` | 无（全查） |
| 8 | 步 4~7 有触发 → 拒绝 | — | `1008C0020` + violations 全查明细 + 拒绝留痕 | 拒绝留痕；**计数零变化**（拒绝不烧次数） |
| 9 | 配额判检一体（`usage.quota` 启用） | 单条条件 UPDATE（见 §2.5） | 影响行数 = 0 → `1008C0020`（`QUOTA_EXHAUSTED`）+ 拒绝留痕；quota 未启用 → 不计数直接放行 | 放行：计数 +1（原子） |
| 10 | 放行 | — | — | 放行记录（发起方 / 时点 / 合约 / 动作 / usedCount） |

**判定语义唯一权威 = `PolicyElementCatalog.judgmentSemantics()`**（3.4.4 交付的契约面）：引擎**消费不复制**（禁止两处并行定义的要素语义，沿 ADR-019 精神）。**时钟口径**：判定日期/时点与记录写入统一取注入 `Clock`（bean `systemDefaultZone`）——禁止直取 `LocalDate.now()`/`LocalDateTime.now()`（DB-09/DB-22 两把钟教训）。

### 2.3 五类拦截与错误码（Q6-A）

| 拦截类 | 判定步 | 触发要素 | 规格验收标准 |
| --- | --- | --- | --- |
| 次数耗尽 | 9 | `QUOTA_EXHAUSTED` | 第 1~N 次放行且计数可查；第 N+1 次拒绝且留痕含触发要素 |
| 期限届满 | 4 | `TERM_EXPIRED` | 期限内放行 / 届满后拒绝 |
| 用途不符 | 5 | `PURPOSE_MISMATCH` | 约定用途放行 / 约定外拒绝 |
| 域外使用 | 6 | `TERRITORY_MISMATCH` | 域内放行 / 域外拒绝 |
| 再分发动作 | 7 | `REDISTRIBUTION_FORBIDDEN` | 再分发动作拒绝且留痕 |

**统一出站 `1008C0020`（HTTP 403）**，常量文案「越界使用被拒绝，触发要素见留痕」——明细入拒绝留痕与服务端日志（沿 C0015"常量文案 + 明细入日志"先例，不外泄内部判定细节）。**状态失效复用 `1008C0013`**（未生效/终止/完结 = "合约当前状态不允许该操作"同语义域）。**防枚举复用 `1008C0012`**（R12 读面）。

### 2.4 计数口径（Q3-A，移交-1 ①落定）

- **按调用计数**：每次经判定入口的使用尝试，**放行才 +1、拒绝零计数**（拒绝腿在判定步 9 之前不触碰计数表——"拒绝不烧次数"由结构性保证，非补偿逻辑）。
- 与规格验收标准"第 1~100 次合规使用放行、第 101 次拒绝"天然一致。
- **切换触发条件**：C-5.x 交付形态落定后如需改为"按交付计数"，走变更流程；届时本 ADR §2.4 与 hifi §3 步 9 同步修订。

### 2.5 计数存储与并发（Q4-A）

- **表 = `contract_usage_counter`**（PK `contract_no`；`used_count` / `last_used_at`）。
- **判检一体原子递增**：单条条件 UPDATE `SET used_count = used_count + 1, last_used_at = ? WHERE contract_no = ? AND used_count < ?`——**影响行数 = 0 即耗尽**；数据库单语句原子性天然防"先查后增"竞态超卖，无 SELECT FOR UPDATE、无应用层锁（准热路径，锁粒度最小化）。
- **行初始化**：no-op upsert（`INSERT ... ON DUPLICATE KEY UPDATE used_count = used_count`）确保行存在；**刻意不用 `INSERT IGNORE`**——其实现在重复键路径加共享锁，与随后的条件 UPDATE（排他锁）形成 S→X 锁升级，同合约并发首用实测死锁（`CannotAcquireLockException`）；no-op upsert 走排他锁路径，同合约并发在本行串行排队（无循环等待 → 无死锁）。
- **耗尽腿零副作用**：行初始化随外层事务回滚撤销（`check` 抛出 C0020 → 外层回滚），数据库层面无残留。
- **真并发口径**（测试锚）：并发 N 线程对上限 N → 恰好放行 N、拒绝 0、`used_count = N`；并发 N+1 线程 → 放行 N + 拒绝 1 + `used_count = N`。**红相验证**：临时以"先查后增"替代判检一体，同口径实测放行 N+1 次（超卖复现），证据归档后已还原（`.gitignore` 目录，见任务卡 §四 记载）。
- **事务口径**：放行腿"计数递增 + 放行记录"同事务提交；**拒绝留痕独立事务（REQUIRES_NEW）**——拒绝留痕是拒绝的一部分，必须超越拒绝异常的外层回滚存活。

### 2.6 执行记录与摘要读面（Q7-A）

- **表 = `contract_usage_log`**：放行/拒绝统一执行记录（谁 / 何时 / 哪份合约 / 动作类型 / 结果 / 触发要素码 / 计数快照）——留痕四要素口径，**不含条款原文与请求文本原文**（`violations` 只落枚举名），规避 L3 分级纠缠；`reason_code` 落错误码尾号（`C0020` / `C0013`）。
- **R12 摘要端点**：`GET /api/v1/contracts/{contractNo}/usage-summary`（分页参数沿合约域既有口径）→ `{contractNo, quota: {limit, used} | null, allowedCount, deniedCount, records 分页}`；`quota` 非空仅当生效策略的 quota 要素启用。
- **可见性 = 参与方（提供方/需求方）+ 治理（admin 角色头）**，沿 R6~R11 权限口径（复用权限点 `contract.read`，不新增权限点面）；**非参与方与"不存在"同码同文逐字 `1008C0012`**（防枚举）+ `DENIED_ACCESS` 留痕。
- **对账数据源预登记（移交-3）**：counter = 余额口径、log = 流水口径——3.7.x 对账以两表交叉验证。

### 2.7 未定义项落定登记（Q5-A，移交-1 ②③④落定）

| 项 | 落定 | 触发条件 |
| --- | --- | --- |
| 用途限定词表化 / 多值 | **不做**——维持精确等值匹配（`usage.purpose` 判定语义） | C-4.6 / V1.5 出现真实词表权威与消费方后走变更流程 |
| 地域编码化（行政区划码） | **不做**——维持精确等值匹配（`usage.territory`） | 同上 |
| 相对期限自动换算（"自生效起 N 天"） | **不做**——演示与业务载荷按绝对日期构造（`startDate`/`endDate`） | 出现真实相对期限需求后走变更流程 |
| 请求级幂等 | **不做**——"按调用计数"语义下调用方重试 = 新的一次调用；消费方（C-5.x/3.4.6）如需请求级幂等由其在调用侧承接 | 避免双处语义分叉 |

### 2.8 集成面契约（供 3.5.2 网关 / C-5.x 交付链）

1. **调用形态**：消费方在交付/调用链路调用 `check`；**同步判定、同步返回**；
2. **放行时点语义**：放行即计数——消费方**不得**在判定与实际交付之间假设持有"放行凭证"（无令牌/凭证设计）；
3. **网络级控制与限流不承担**（归 3.5.2）——本入口只做应用层策略判定；
4. **接入口径**（端点形态/超时/降级/缓存与否）由消费方设计定，本引擎不预设；
5. **错误码语义**：`1008C0020` = 越界拒绝（含要素明细入留痕）；`1008C0013` = 状态失效；`1008C0012` = 合约不存在/不可见（防枚举）。

### 2.9 诚实边界

- **应用层拦截覆盖**（规格 §6-1 原文）：网关未上线前，执行结论**仅覆盖应用层拦截判定**，不承诺网络级强制；
- **线下扩散不在承诺内**（规格 §6-4 原文）：策略拦截覆盖平台交付与调用链路内的使用行为，"下载后线下扩散"不承诺可控；
- 引擎不做参与方可见性二判（R12 承载）；不校验发起方入驻状态（消费方在真实链路负责身份，引擎只记"谁发起的这次判定"）。
- **R5 期限要素不变式**：期限合法性（`YYYY-MM-DD` 格式、起止有序、起始日不早于提交日）由写入路径单点强校验（`UsagePolicyDslParser` R5）保证——引擎读路径遇异常数据 fail-closed（拒绝、零计数、零计数副作用，全局处理器常量文案），不构成绕过面（评审②登记）。

### 2.10 与 ADR-019 的衔接

引擎**消费** `PolicyElementCatalog` 的判定语义标注（不复制要素语义，禁止两处并行定义）；`UsagePolicyDslParser` 校验单点地位不变（写入路径零改动）；要素扩增（新增第六要素）需同时更新目录 + 引擎判定分支 + 判定顺序表，走 ADR-019 §2.5 版本演进规则。

## 3. 理由

1. **同宿主应用层入口**：QC1 与解析器已同宿主，判定紧随其后不引入网络跳数与部署面；消费方（网关/交付链）均未开工，提前造 HTTP 内部端点属提前暴露且契约未经验证。
2. **判检一体**：条件 UPDATE 用数据库单语句原子性替代应用层锁，在准热路径上锁粒度最小且天然正确（红相验证了"先查后增"会超卖）。
3. **按调用计数**：与规格验收标准（第 1~100 次 / 第 101 次）与 WBS 行 279（"调用拦截、配额计数"）同链路；按交付口径在交付链开工前无法验证。
4. **一码承载五类拦截 + 要素明细入留痕**：码位不膨胀，区分度由留痕的触发要素码承载（沿用 C0015 先例）。
5. **执行记录独立成表**：生命周期留痕（`contract_action_log`）与使用执行记录是两类业务对象，字段语义与查询面互不污染。

## 4. 备选方案与取舍

| 备选 | 未采纳原因 |
| --- | --- |
| 独立 policy-engine 新服务 | WBS 行 279 未要求新服务；演示期无跨服务消费方，新增服务 = 部署/端口/门禁面全面膨胀 |
| 现在即建 HTTP 内部端点 | 无消费方，提前暴露；接口形态未经验证 |
| 只做引擎库不接入口 | 无法演示、无法验证闭环（违反"可演示"原则） |
| 按交付计数 | 交付形态未定，口径悬空 |
| SELECT FOR UPDATE 行锁递增 | 使用判定是准热路径，判检一体更简洁且锁粒度更小 |
| common 分布式锁组件 | 单库单实例演示期无收益，锁粒度大于必要 |
| 五类各占一错误码 | 码位膨胀；触发要素留痕已承载区分度（且 3.7.x 对账读留痕即可分类） |
| 复用 `contract_action_log` 存执行记录 | 生命周期动作与使用执行记录语义混载、查询面互相污染 |
| 只存计数不存记录 | 规则 5"执行记录摘要双方可查"无承载，拒绝留痕四要素缺腿 |
| 通用规则引擎 / 表达式求值 | 五要素直写判定 = 最平庸实现（hifi §11-6 有意不做） |
| 放行凭证 / 令牌、异步事件总线 | 判定时点语义已足够；无消费方（hifi §11-6） |

## 5. 业务影响说明

- **对提供方/需求方**：合约生效后，任何越界使用（超次数/超期/用途不符/域外/再分发）都会被服务端拒绝并留痕；双方可在"使用摘要"查看已用次数、上限与执行流水（治理方亦可查）。
- **对治理方**：强制终止合约后，其策略立即失效（后续使用一律拒绝，剧本 C-4.3 S3-7）。
- **对后续工序**：计费/对账（3.7.x）以计数表与流水表交叉验证；存证埋点（3.8.3）消费执行记录；网关（3.5.2）与交付链（C-5.x）按 §2.8 接入。
- **已知限制（诚实披露）**：网关未上线前拦截仅覆盖应用层；线下扩散不在承诺内。

## 6. 影响范围

- **新增**：`domain/policy` 五件（`UsageRequest`/`UsageActionType`/`UsageVerdict`/`PolicyViolation`/`PolicyJudge`）+ `UsageLogEntry`；`application` 两件（`PolicyExecutionService`/`UsageQueryService`）；`infrastructure` 四件（`UsageCounterStore`/`JdbcUsageCounterStore`/`UsageLogRepository`/`JdbcUsageLogRepository`）；`interfaces` 两件（`ContractUsageController`/`dto.UsageViews`）；迁移 `V3__create_policy_execution_tables.sql`。
- **改动**：`ContractErrorCodes`（新增 C0020 一位，既有码语义零变更）+ `ContractExceptionHandler`（映射同步）+ 一致性测试计数（22 → 23）。
- **零改动**：QC1 / 解析器 / 值对象 / 要素目录 / 既有控制器 / 迁移 V1·V2 / 空间域 / 目录域 / 网关（未开工）/ 门禁配置 / 加解密组件。
- **配置**：零门禁配置改动；`Clock` 复用既有 bean（无新配置）。
- **数据**：新增两表（L1 分级，见分级规范 §6.1 回写行）；演示环境仅走查期产生使用记录。

## 7. 可替换性

- 判定入口为普通 Java 方法 + 端口接口：替换为 HTTP/消息驱动消费只需在调用侧新增适配，不改判定逻辑；
- 计数存储为端口（`UsageCounterStore`）：换存储或改用分布式锁按 ADR-019 §2.3 迁移触发条件走变更流程；
- 判定语义唯一权威在 `PolicyElementCatalog`：要素语义调整只改目录 + 引擎分支，不产生第二套定义。
