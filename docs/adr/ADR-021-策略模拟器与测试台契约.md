## 1. 背景与目的

规格行为 5（C-4.3 策略执行与绕过拒绝）规则 4 要求「**双向用例硬约束**」：每个使用控制要素都必须有"合规放行"与"越界被拒"两条用例，且由 3.4.6 / 3.4.8 承接；规格尾注同时把未定义项「双向用例的模拟器形态」明确划归 WBS-3.4.6。

WBS-3.4.5 交付了执行引擎（判定入口 `check`、四要素 + 配额两腿判定、计数与留痕），但存在三处结构性缺口：① **判定入口零 HTTP 端点**——剧本 C-4.3 的 S2/S3 幕（放行计数、越界拒绝留痕）在走查期只能靠"临时 Java harness"承载，每次走查现搭、不入库、不可演示；② **无试算能力**——3.4.7 合约工作台的"模拟执行/试算"按钮与"配置前先看看会不会通过"的诉求无落点；③ **配额判定只在数据库条件 UPDATE 里**（判检一体原子递增），模拟通道无法零副作用地复现"次数是否耗尽"。

本 ADR 固化模拟器与测试台的对外契约与关键口径，供上游（3.4.7 界面 / 3.4.8 测试与集成 / 3.8.3 存证）与下游（C-5.x 交付链）共同遵守，并兑现规格尾注未定义项的落定。

## 2. 决策内容

### 2.1 形态与落点（Q1-A）

- **落点 = contract-service 同宿主三端点**（零新模块、零新表、零新迁移）：模拟试算 `POST /api/v1/contracts/{contractNo}/policy-simulations`；测试台 `POST /api/v1/contracts/{contractNo}/policy-testbench-runs`；受控执行 `POST /api/v1/contracts/{contractNo}/usage-executions`。编排在新增 `application.PolicySimulationService`（承载三端点的应用层编排），控制器落 `interfaces`（两个新控制器，**既有 7 控制器 diff 为空**），出站载体 `interfaces.dto.SimulationViews`（单文件承载请求与视图）。
- **权限点复用 `contract.deal`**（不新增权限点面）；发起主体取 `AuthContext.subject()`。
- **零新码位**：复用 `1008C0008`（参数非法）/ `1008C0012`（防枚举）/ `1008C0013`（状态失效）/ `1008C0015`（策略校验）/ `1008C0020`（越界）；`ContractErrorCodes` / `ContractExceptionHandler` / 一致性测试计数**均不改**。
- **三端点不提供任何"跳过判定/强制放行"参数**（fail-closed；结构锚 `endpointsExposeNoBypassParameter` 以入参白名单全等断言钉死）。

### 2.2 双通道语义（Q2-A：模拟 vs 执行）

| 维度 | 模拟通道（模拟试算 / 测试台） | 执行通道（受控执行） |
| --- | --- | --- |
| 判定件 | `PolicyJudge.judge` + `PolicyJudge.judgeQuota`（纯函数） | `PolicyJudge.judge` + `UsageCounterStore.tryIncrement`（条件 UPDATE） |
| 计数来源 | 假想计数（缺省 = 真实 `used_count`） | 真实计数（原子递增） |
| 日期来源 | 假想日期（缺省 = 注入 Clock 当天） | 注入 Clock 当天 |
| 策略来源 | 合约当前生效策略（QC1）或调用方提交的**草稿**（经解析器单点校验） | 合约当前生效策略（QC1） |
| 副作用 | **零**（不写计数器、不写执行记录、不落库） | 计数递增 + 放行记录 / 拒绝留痕（REQUIRES_NEW） |
| 拒绝表达 | **结论数据**（HTTP 200 + `allowed = false`；报告 `FAIL`） | **异常**（`1008C0020` → 403 等） |
| 语义定位 | "试算不改动任何状态"——模拟拒绝不是系统错误 | "真实使用动作"——唯一的正式放行通道 |

- **模拟结论不是放行承诺**（正式放行只经执行通道）；两条通道的判定语义**同源**（同一 `PolicyJudge` + 同一要素目录 + 同一配额判据），差异只在副作用与错误表达。
- **对照一致性锚**（可执行证据）：当假想上下文 = 真实状态时（假想计数 = 真实 `used_count`、假想日期 = 注入 Clock 当天），**模拟结论必须与真实执行结论逐项一致**（放行/拒绝 + 触发要素集合），含 100/101 边界与各要素越界腿（测试 `simulationMatchesRealExecutionForAllowedAndDeniedPaths`）。

### 2.3 假想上下文口径与边界值（Q2-A）

- **入参**（白名单）：`actionType`（必填，`USE` / `REDISTRIBUTE`）/ `purpose?` / `territory?` / `assumedUsedCount?`（`0 ≤ 值 ≤ 1_000_000`，越界 → `1008C0008`）/ `assumedDate?`（ISO 本地日期，格式非法 → `1008C0008`）/ `strategyDocument?`（策略**草稿**，非空时经 `UsagePolicyDslParser.parse(document, 注入 Clock 当天)` 单点校验，不过 → `1008C0015`）。
- **缺省填充**：假想计数缺省 = 真实 `used_count`（无计数记录 = 0）；假想日期缺省 = 注入 Clock 当天。假想上下文为**显式假设口径**，与真实执行腿的注入 Clock 分离登记；**禁止直取 `LocalDate.now()`**（DB-09 / DB-22 两把钟教训）。
- **编排次序**（顺序即行为，校验前置不触策略读取）：① 可见性守卫 → ② 入参校验（`1008C0008`）→ ③ 策略来源（草稿 `1008C0015`）→ ④ 状态门槛（合约非生效 → `strategyEffective = false`、`allowed = false`、`violations = []`、`policySnapshot = null`，**不抛异常**）→ ⑤ 四要素全查（有触发 → 拒绝 + 全查明细，**不再判配额**）→ ⑥ 配额纯判定（四要素全过时）。
- **响应回显**：`assumedUsedCount` / `assumedDate` 为本次**实际使用**的假想上下文（界面与报告可核对）；`policySnapshot` 为参与判定的要素取值快照（仅启用项，目录键声明序）。

### 2.4 配额两腿同源（Q3-A）

- **纯判定补齐**：`PolicyJudge` **新增** `judgeQuota(policy, assumedUsedCount)`（与四要素判定**同址**，既有 `judge(...)` 与 `judge` 判检一体链路**零改动**）；要素未启用 / 空策略 / 显式无限制 → 空列表；入参边界由应用层校验（纯函数不承担参数错误表达）。
- **同源声明**：配额语义在平台内只有一套——**限值来源 = 策略 `quota.maxCount`**；**耗尽判据 = `assumedUsedCount >= limit`**。真实执行腿以数据库单语句条件 UPDATE（`WHERE used_count < limit`）实现（并发安全），模拟腿以纯函数实现（可零副作用试算）；**禁止出现第二套限值来源或第二套耗尽判据**。要素语义的单点权威继续由 `PolicyElementCatalog` 承载（含"次数"要素的判定语义标注）。
- **对照一致性锚**（硬性，见 §2.2）：这是"同源"的可执行证据，而非文字承诺。

### 2.5 场景集与要素目录同源（Q4-A，承接 3.4.4 移交-2）

- **内置场景集 11 条**：五要素 × 双向 10 条 + 空策略/显式无限制 1 条（`U1`~`U11`）；场景按 `PolicyElementCatalog.keys()` **声明序**生成，要素扩展而场景集未同步 → 计划阶段 fail-fast（结构锚 `testbenchScenariosCoverEveryCatalogElement` 红）。
- **场景构造不复制要素语义**：限值取策略 `quota.maxCount`、期限边界取策略起止日、用途/域取策略文本；每个 `DENY` 场景只在其自身要素上越界，其余要素取**合规基准值**（期限启用则基准日 = 起始日、计数基准 = 0、用途/域基准 = 策略文本、动作基准 = `USE`），故触发要素集合唯一（比对为集合相等而非包含）。
- **目录字段 ↔ 策略要素访问器单点**：`PolicyTestbenchScenarios.elementOf(policy, field)` 为模拟器内唯一映射点（快照装配与场景集共用），禁止第二处并行映射。

### 2.6 报告形态、零落库与事务口径（Q4-A）

- **报告形态**：`scenarios[{code, elementKey, direction, expectation, outcome, actual{allowed, violations[]}, note}]` + `summary{total, pass, fail, skipped}`；三态判定（**诚实不假绿**）：① 要素未启用 → `SKIPPED`；② 合约非生效态 → 全场景期望"拒绝（策略失效）"（`actual.allowed = true` 记 `FAIL`）；③ 生效且适用 → 按期望与实际（放行/拒绝 + 触发要素集合）比对。
- **零落库**：报告**不写** `contract_usage_log` / `contract_usage_counter`——自检动作不是业务使用事件（与 V3 执行记录语义不混载）；归档/审计需求登记移交-3（3.8.3 存证埋点）。
- **零副作用担保（结构性）**：模拟与测试台**不调用** `UsageCounterStore.tryIncrement`、**不写** `contract_usage_log`（结论与报告全部在内存完成）；由集成锚 `simulationAndTestbenchLeaveCounterAndUsageLogUntouched` 钉死。
- **事务口径（编码段实测登记，替代 hifi §8 "`@Transactional(readOnly = true)`"）**：三方法**均不加 `@Transactional`**。理由（实测证据）：① `readOnly = true` 连接下，可见性守卫的 `DENIED_ACCESS` 留痕写库被拒（`TransientDataAccessResourceException: Connection is read-only`，实证见编码段验证记录）；② 若改用可写事务，拒绝异常的**回滚会一并吞掉留痕**（留痕必须超越拒绝异常存活）。故沿 R12 `UsageQueryService.summary` 既有口径（**无事务标注**、留痕走自提交）；受控执行腿的计数递增 / 放行记录 / 拒绝留痕的事务语义仍由 3.4.5 `check` 与其仓储传播口径承载（**零改动**）。
- **时钟**：`runAt` / `occurredAt` = `LocalDateTime.now(clock)`；假想日期缺省 = `LocalDate.now(clock)`。

### 2.7 可见性与权限（Q5-A，跟踪-17 兑现）

- **应用层共享守卫抽取**（第三消费方出现 = 跟踪-17 登记时预设的触发条件成立）：`application.ContractVisibilityGuard` 两种口径 + `DENIED_ACCESS` 留痕单点——`requireReadable`（参与方 + 治理 `admin` 角色头）供 R12 / 模拟 / 测试台使用；`requireParticipant`（**仅参与方，治理不例外**）供受控执行使用。
- **失败同码同文**：`1008C0012` 与"合约不存在"逐字一致（防枚举）+ `DENIED_ACCESS` 留痕（`reason_code` = `C0012` 尾号）。
- **治理方不发起使用动作**（防"代他人使用"污染计数与流水）；治理的对照面经摘要读面（R12）与模拟/测试台承载。
- **行为零变更**：R12（`UsageQueryService.summary`）改调共享守卫，错误码/文案/留痕动作逐字不变，由既有可见性矩阵锚回归保护；合约域其余守卫（R7/R8/R11）本卡不动（统一收敛沿跟踪-17 登记续办）。

### 2.8 错误码与 HTTP 语义（Q7-A：零新码位）

| 情形 | 错误码 | HTTP | 说明 |
| --- | --- | --- | --- |
| 请求体/参数非法（动作类型、假想计数越界、日期格式） | `1008C0008` | 400 | 复用 |
| 策略草稿校验不过（`strategyDocument`） | `1008C0015` | 400 | 复用解析器单点结论 |
| 合约不存在 / 不可见（非参与方） | `1008C0012` | 404 | **防枚举同码同文** |
| 受控执行：合约状态失效 | `1008C0013` | 409 | 复用（S3-7 联动） |
| 受控执行：越界使用 | `1008C0020` | 403 | 复用（五类拦截统一） |
| 模拟试算 / 测试台判定为拒绝 | —（非错误） | 200 | **结论以数据返回** |
| 权限点缺失 | `1000C0005` | 403 | common-auth 既有口径（零改动） |

### 2.9 诚实边界

- **模拟结论 ≠ 放行承诺**：正式放行只经执行通道（受控执行 → 后续 C-5.x 交付链）。
- **受控执行端点 = 演示期形态**：它是剧本 S2/S3 幕的**受控调用入口**，**不是交付链本体**；C-5.x 上线后由 3.4.8 复核"本端点 ≡ 交付链判定面"并评估保留/收敛（移交-2）。
- **网关未上线前仅应用层拦截**（规格 §6-1 原文）；**"下载后线下扩散"不在承诺内**（规格 §6-4 原文）。
- **报告不落库**（归档需求登记移交-3）；**无幂等键**——按调用计数语义下重试 = 新一次调用（沿 ADR-020 §2.7，消费方如需请求级幂等自行在调用侧承接）。

### 2.10 迁移与退役触发条件

- **零 DDL**：复用 V3 两表（下一可用迁移版本仍为 V4，本卡不用）。
- **端点退役**：C-5.x 交付链上线并经 3.4.8 复核后，受控执行端点按变更流程评估保留/收敛（不得静默移除——剧本 S2/S3 的演示入口依赖它）。
- **抽 common 条件**：引擎若按 ADR-019 §2.3 / ADR-020 §2.1 独立部署，模拟器与守卫随之迁移（本卡不触发）。
- **报告落库**：若存证/审计侧（3.8.3）提出归档口径，走变更流程新增（不得直接写 V3 执行记录表）。

## 3. 理由

1. **同宿主三端点**：上游件（QC1 / 解析器 / 要素目录 / 引擎）全在本宿主，跨服务调用无消费方且会全面膨胀部署与门禁面；3.4.5 走查已实证"临时 harness"的重建成本（不入库、每次走查现搭）——产品化为端点是演示与自动化的最小代价路径。
2. **双通道而非单通道**：若模拟走真实 `check`，试算会烧次数、写留痕，语义上不是"模拟"；若不支持假想上下文，"期限届满 / 次数耗尽"两条双向场景无法零副作用构造，测试台将缺腿（违反规格规则 4）。
3. **配额纯判定放在判定位**：模拟腿必须能零副作用回答"次数是否耗尽"；另建判定类会使判定逻辑分散两处（与"禁止两处并行定义"精神冲突），新增同址纯函数 + 两腿同源 + 对照锚是最小且可验证的方案。
4. **目录驱动场景集**：要素语义的唯一权威是 `PolicyElementCatalog`；场景集若复制要素语义，第六要素落地时必然出现"目录改了、场景忘了"的静默漏配——同源 + 结构锚把漏配变成红灯。
5. **报告零落库**：自检是配置期动作，不是业务事件；落进 `contract_usage_log` 会污染"使用流水"对账口径（3.7.x 以 V3 两表为对账源）。
6. **守卫抽取而非第三份复制**：评审③已把"可见性 + 留痕"重复判为 P2；第三消费方出现正是跟踪-17 预设的抽取触发条件，抽取同时保持 R12 行为零变更（回归锚保护）。

## 4. 备选方案与取舍

| 备选 | 未采纳原因 |
| --- | --- |
| 独立模拟器服务 | 无跨服务消费方；部署/端口/门禁面全面膨胀（Q1-B） |
| 纯测试层 harness（不入库） | 不可演示——3.4.5 走查已实证重建成本（Q1-C） |
| 模拟只判真实状态（无假想上下文） | "期限届满 / 次数耗尽"无法零副作用构造，测试台缺双向腿（Q2-B） |
| 模拟直接调 `check` | 会烧次数、写留痕——语义上不是"模拟"（Q2-C） |
| 模拟通道不做配额腿 | 次数要素双向缺越界腿，违反规格规则 4 硬约束（Q3-B） |
| 另建 `PolicySimulationJudge` 承载配额 | 判定逻辑分散两处（Q3-C） |
| 支持调用方自定义场景 | 无消费方（等于提前造通用 DSL），超范围（Q4-B） |
| 报告落库新表 | DDL 膨胀；报告非业务事件，与 V3 执行记录语义混载（Q4-C） |
| 不建受控执行端点 | 剧本 S2/S3 仍只能靠临时 harness；3.4.7 界面亦无"使用动作"可演示（Q5-B） |
| 受控执行建在网关侧 | 3.5.2 未开工，无宿主、无消费方（Q5-C） |
| 复制第三份可见性判定 | 评审③已判 P2 重复项，第三份使重复固化（Q6-B） |
| 本卡不做可见性 | 受控执行必须挡非参与方（否则防枚举与治理例外缺腿）（Q6-C） |
| 新占错误码 / 并入 ADR-020 改版 | 排障收益低、码位膨胀；两套消费契约语义混载且改已验收契约风险更高（Q7-B/C） |
| 通用规则引擎 / 表达式求值 / 放行凭证 / 请求级幂等 / 界面 / 网络级控制 | 有意不做（范围外，沿 ADR-020 §2.7 与 hifi §11-5） |

## 5. 业务影响说明

- **配置前可试算**：合约双方（与治理方）可在配置策略前"试算"某次使用会不会通过、被哪条限制拦住——试算**不改动任何数据**（不烧次数、不产生流水）。
- **配置后可自检**：一键运行"每个限制要素：合规应放行 + 越界应被拒"的双向对照，给出**通过 / 未通过 / 已跳过（该要素没配）**三态报告，且报告**不落任何业务记录**。
- **演示可动手**：合约双方可在演示环境真实发起一次使用动作（放行计数、越界拒绝留痕），剧本 C-4.3 的 S2/S3 两幕从此有正式演示入口（此前只能临时搭脚本）；演示数据清理不受本卡影响（沿跟踪-14）。
- **对下游**：3.4.7 界面消费三端点（模拟按钮 / 使用动作入口 / 测试台报告 + R12 摘要）；3.4.8 复核"受控执行端点 ≡ 交付链判定面"+ 覆盖率达标 + 双向用例脚本级固化；3.7.x 对账仍以 V3 两表为源（模拟与测试台不产生流水）。
- **已知限制（诚实披露）**：模拟结论不是放行承诺；受控执行端点为演示期形态；网关未上线前不承诺网络级；线下扩散不在承诺内。

## 7. 可替换性

- 三条通道共用同一判定件与目录：把模拟/测试台改造成独立服务或测试层 harness，只需替换编排层与端点适配，判定语义零变更。
- 端点形态为普通 REST 子资源：3.4.7 界面或 3.5.2 网关接入无需改判定逻辑；受控执行端点退役（§2.10）不影响模拟与测试台。
- 场景集为目录驱动的纯函数：要素扩展只需在 `PolicyElementCatalog` 注册 + 场景映射补 `switch` 分支（未补即红灯），不产生第二套要素语义定义。
