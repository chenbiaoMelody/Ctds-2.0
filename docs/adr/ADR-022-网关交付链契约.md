## 1. 背景与目的

规格行为 2 要求"数据产品的 API 交付调用**一律经网关**进入平台，转发前先判定策略，越界不触达数据源，放行才计量"。WBS 行 289 把该能力拆为四件（鉴权 / 限流 / 策略执行点 / 计量埋点）并归 3.5.2；本 ADR 固化该交付链的对外契约，供下游 3.5.3~3.5.7（文件传输 / 沙箱 / 审核导出 / 界面 / 集成）与 3.7.5·3.7.6（计量采集与计费）、3.8.3（存证）、3.9.1（真实令牌）、4.2.3（网关压测）共同遵守。

## 2. 决策内容

### 2.1 链路顺序（固定不可调）

```
入站请求
 → [ -300 反应式 traceId 过滤器 ]（入站 X-Trace-Id 合法则透传、否则生成；写上下文与响应头）
 → [ -200 common-auth HeaderStripFilter ]（无条件剥离入站 X-Ctds-Subject / X-Ctds-Roles）
 → [ 安全链 ]（JWT 校验；失败 → 401 + 1000C0002，traceId 非 "-"）
 → [ -90 common-auth ContextHeaderInjectFilter ]（注入权威 X-Ctds-Subject / X-Ctds-Roles）
 → [ -300 交付面白名单 ]（routeId 不在 ctds.gateway.delivery.routes → 404 + 1009C0004，默认空 = fail-closed）
 → [ -250 限流 ]（主体 + 接口令牌桶；超阈 → 429 + 1009C0002，不触达上游）
 → [ -200 凭据解析 ]（X-Ctds-Contract-No 缺失/非法 → 400 + 1009C0001，不调判定）
 → [ -150 策略执行点 ]（转发前调用合约域内部判定端点；越界原码透传；不可达/超时 → 503 + 1009S0001）
 → [ -140 计量埋点 ]（放行 1 次 ≡ 事件 1 条；拒绝 0 条）
 → [ 转发数据源 ]（V1.0 = 演示探针路由）
```

- **判定在转发之前**，越界一律**不触达数据源**（验收标准 2）；
- **判定不缓存**（ADR-020 §2.8"放行即计数"）：缓存结论会导致"未计数即放行"，**禁止**；
- 网关自身 GlobalFilter 顺序见 `GatewayFilterOrders`（常量即契约）。

### 2.2 判定唯一与集成面

1. 合约域新增**内部判定端点** `POST /api/v1/contracts/internal/usage-checks`（权限点 `contract.internal.read`，仅 `gateway-internal` 服务身份持有）：请求体 `{contractNo, requesterNo, actionType(=USE), purpose?, territory?}`，处理 = ① 参与方可见性（`ContractVisibilityGuard#requireParticipant`，非参与方/不存在 → `1008C0012` 同码同文防枚举 + `DENIED_ACCESS` 留痕）→ ② 委托既有 `PolicyExecutionService#check`（**零第二语义**：状态门槛 `1008C0013` / 越界 `1008C0020` / 参数非法 `1008C0008` 全沿既有链路）；响应 = 判定摘要 + 参与方摘要（`applicantNo`/`providerNo`/`status`/`effectiveAt`），**不含条款原文与数据本体**；
2. 网关**只消费不复制**判定语义；越界**原码透传**（C0020→403 / C0013→409 / C0012→404 / C0008→400）；出站映射沿 `ContractExceptionHandler` 既有映射；
3. 网关不出站任何"跳过判定 / 强制放行"入参；
4. **不复用** ADR-021 §2.10 受控执行端点 `POST /api/v1/contracts/{contractNo}/usage-executions`（演示期形态、权限面向参与方；复用会把演示端点变成生产链路）；
5. 判定服务不可达 / 超时（默认 2s，可配，ADR-020 §2.8 授权消费方定）→ **fail-closed**：503 + `1009S0001`，不放行、不触达数据源、不产生计量事件；判定响应为非合约域业务码（S 型 / 未知形态）同样 fail-closed（不把"未能判定"当作"已放行"）。

### 2.3 限流与配额分工

1. 限流 = **网络级频率保护**：维度 = 调用主体 + 接口（key = `主体#routeId#方法 路径模板`，用路径模板避免路径参数导致 key 爆炸）；算法 = 进程内令牌桶（容量/速率可配，`enabled=false` 可关）；超阈 → 429 + `1009C0002`（附 `Retry-After`），**不触达上游、不产生计量事件、不影响业务配额计数**；
2. **业务次数配额唯一由合约域策略执行引擎判定与计数**（规格行为 2 规则 5）：网关不得以任何形式承担或旁路配额语义；
3. 边界（诚实）：进程内实现 = 单实例语义；多实例部署前须换分布式实现（演进项）；正式吞吐承诺归 4.2.3（≥2000 TPS / P99<500ms）。

### 2.4 信任边界与头处置

1. **入站**：`X-Ctds-Subject` / `X-Ctds-Roles` **无条件剥离**（先于安全链）——伪造头不可能进入下游；
2. **出站**：网关仅注入**权威身份头**（JWT `sub` → subject、角色 claim → 逗号分隔 roles）；不转发调用方原始身份头；`X-Forwarded-*` 族本卡不引入（登记演进项：common 现状无该族处理）；
3. **口径分离**：身份头**不参与**判定——判定主体由判定请求体 `requesterNo`（JWT `sub`）显式给出，避免"网关注入头"与"交付判定主体"两套口径漂移；
4. **发起人唯一**：判定响应携带合约需求方（`applicantNo`），发起人 ≠ 需求方 → 403 + `1009C0003`（提供方/运营方不可发起交付）；
5. **DB-03 关口**：网关上线 = ADR-016 §2.7 长期解除条件**之一**兑现；另一条件（3.9.1 真实令牌）未生效 → **不改 DB-03 状态**，关闭判定由编排师/后续包裁量。

### 2.5 交付面与凭据

1. 交付面 = **配置化白名单** `ctds.gateway.delivery.routes`（显式列举 routeId；**默认空 = 无交付面可用**，fail-closed）；路由 = 静态配置 `ctds.gateway.routes`（id/uri/predicates:Path/filters），**不引入服务发现**（演进项）；
2. 凭据与判定要素（头名可配置）：`X-Ctds-Contract-No`（交付凭据 = 已生效合约编号；格式 = 非空且仅 `[A-Za-z0-9._-]`、≤64，违者 400 + `1009C0001`）、`X-Ctds-Purpose`、`X-Ctds-Territory`（策略要素，可空，交判定）；
3. 动作类型固定 `USE`（再分发 `REDISTRIBUTE` 不在交付调用面）；
4. **独立 API Key 的签发/轮换/吊销 = 未定义项**（规格 §6-5），归后续包；
5. 前端代理与部署单入口收敛**不在本卡**（切换动作登记，建议归 3.5.6/3.5.7 前统一执行）。

### 2.6 计量口径

1. 出口 = `common-logging` `AuditRecorder` 落 `logs/audit-*.jsonl`；**放行 1 次 ≡ 计量事件 1 条**（动作名 `gateway.delivery.metering`，SUCCESS），**拒绝 0 条**（拒绝留痕以独立动作名 `gateway.delivery.denied` 承载，不与计量混算）；
2. 事件字段最小必要：`traceId` / 主体编号 / 合约编号 / 被交付资源（routeId + 方法 + 路径模板）/ 结果 / 时点；**禁止**请求体、响应体、数据原文、令牌、密钥；
3. **计量事件模型、流水落库、采集与计费归 3.7.5 / 3.7.6**；存证上链归 3.8.3——本卡只保证"事件按口径产生且可对账"。

### 2.7 错误码

网关自身错占 **1009 段**（交付与沙箱域，3.5.1 Q8-A 预留）：`1009C0001` 凭据缺失/非法（400）/ `1009C0002` 频率超限（429）/ `1009C0003` 非需求方发起（403）/ `1009C0004` 白名单外（404）/ `1009S0001` 判定不可达（503）；未认证复用 `1000C0002`（401）；**越界一律透传合约域原码**（禁改写）。

### 2.8 诚实边界与未收敛面

不经网关的直连（回环 / 内网 / 服务直连）不在平台承诺范围；"下载后线下扩散"不在承诺范围（沿 ADR-020 §2.9 措辞）；V1.0 被交付资源以既有只读端点承载（真实数据源接入归连接器 3.6.x）；用户身份透传归 3.9.1（本卡为服务身份 + 请求体携带主体编号，服务间调用不落用户令牌）。

## 3. 后果

- 下游交付类包（3.5.3~3.5.7）与计量/存证包获得统一链路锚：判定面、限流与配额分工、信任边界、凭据形态、计量口径不再各自解释；
- 网关成为"唯一入口"的**技术事实**始于 3.5.2 的交付调用面；"全量端点收敛"（前端代理与部署清单切换）为登记切换动作，未生效前平台不就直连做承诺（诚实边界）；
- 实现期已登记观察项：合约域 `check` 为"放行即计数"，故"发起人 ≠ 需求方"的交付域拒绝发生在计数之后（本 ADR §2.1 次序 = 判定 → 发起人校验，按已确认设计实现）；如需把该规则前置到计数之前，须走变更流程（关联：3.7.5 计量口径复核）。

## 4. 理由

1. **判定语义唯一**（ADR-019 / ADR-020）：把判定收敛为"合约域内部端点 + 网关只消费"，一笔集成面同时满足"越界不触达数据源"（转发前判定）与"放行即计数"（判定在合约域单点完成计数），避免第二套判定与两侧计数漂移；
2. **fail-closed 优先**：白名单默认空、判定不可达/超时/不可信一律拒绝——交付链的安全默认必须是"拿不到结论就不放行"，而不是"拿不到结论就放行"；
3. **选型不新开**：`spring-cloud-starter-gateway` 落实 ADR-005 已批准方案 A，依赖走 `docs/dependencies.md` 四步登记 + 官方兼容矩阵核验（2025.0.x ↔ Boot 3.5.x），符合章程 4.1"技术栈平庸化 / 不擅自引入框架"；
4. **限流与配额分工不可混**：限流是网络级频率保护（网关），配额是业务次数（合约域策略引擎）——混算会使"业务配额被频率策略悄悄改写"，破坏 C-4.3 与 C-5.1 的计量一致性；
5. **复用优先**：鉴权链整体复用 `common-auth`（零新研发）、计量出口复用 `common-logging`（异步有界队列，绝不阻塞/抛错）、凭据与判定要素沿 `ApiResult` 与错误码体系——横切能力先查 `common`，未新增重复实现。

## 7. 可替换性（组件级替换路径，防锁定）

1. **网关本体**：替换实现只需改模块内部——对外契约 = 本 ADR §2（下游消费"交付调用面 + 判定面 + 错误码口径"，不依赖网关内部类）；
2. **限流**：进程内令牌桶 → 分布式实现，替换点 = `RateLimitGlobalFilter` 的令牌存取（key 口径与出站码不变）；
3. **判定面**：合约域内部端点（HTTP + `ApiResult` 封套）为稳定契约，替换判定实现（如策略引擎版本演进）不影响网关消费形态；
4. **计量出口**：`common-logging` 的 `AuditRecorder` 接口为唯一依赖点（3.7.5 落库实现替换不改网关调用点）；
5. **鉴权**：JWT 校验走 `common-auth` 组件与配置化密钥来源（`ctds.auth.jwt.secret` / `jwk-set-uri` 二选一）——3.9.1 真实令牌仅在签发侧与密钥来源变更，网关侧链路零改动；
