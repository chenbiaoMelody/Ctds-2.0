## 1. 背景

规格 C-5.1 要求平台把数据以**国密加密交付包**形式提供需求方下载/领取，并保证“凭已生效合约交付、按合约最小必要、完整性可核、交付记录可查、本体不进留痕”。WBS-3.5.2 已交付 API 调用链（网关四件），但交付记录面按 Q5-A 未纳入；WBS-3.5.3 需同时兑现**交付记录宿主**（API + 文件两类）与**加密文件传输**，并为下游 3.5.6（界面）、3.7.5（计量）、3.8.3（存证）提供统一契约锚。本文固化该通道的对外契约，避免下游各自解释。

## 2. 决策内容

### 2.1 交付记录模型与编号

1. `delivery` 表一行 = 一次交付动作（API 或 FILE）：`delivery_no`（`DL`+6 位全局序号）、`contract_no`、`product_id/product_name`（发起时快照）、`delivery_type`（API/FILE）、`requester_no/provider_no`（合约参与方快照）、FILE 的 `file_id/file_name/file_size/package_id/checksum/key_ref`、`result`（本卡 SUCCESS）、`idempotency_key`、`created_at`。
2. **只存业务要素与校验值**：无文件本体、无数据原文、无文件路径、无密钥材料；`key_ref` 仅为密钥编号。
3. `delivery_action_log` 承载创建/读取/下载/治理读取/拒绝留痕（与 common-logging 审计 JSONL 并行）；`delivery_no_seq` 为全局序号（1 行原子取号，缺口可接受）。
4. 资源名 `deliveries`、错误码 `1009` 段（3.5.1 Q8-A 预留）——沿规格 §7 Q8-A。

### 2.2 准入链路（固定顺序）

```
身份 → 幂等查重 → [contract] 内部只读摘要（参与方 + 生效 + productId/productName，不计数）
 → 发起人 = 合约需求方（否则 1009C0003，先于计数）
 → [catalog] 内部产品 productType → 形态/范围校验
 → （FILE）[contract] 既有内部判定 check（USE，放行即计数一次）
 → （FILE）读取文件源 → SM3 → SM4/GCM 加密 → 原子落盘
 → 取 deliveryNo → delivery + action_log（事务）→ 审计 → 返回
```

1. **API 交付发起不调用 check**：真正 API 调用的判定与计数仍在 3.5.2 网关（ADR-022），避免双计。
2. **FILE 交付调用 check 一次**：文件交付 = 一次数据使用；拒绝零计数；放行后若包生成失败，已计数但无记录/包，属平台失败并审计（诚实边界，不改写计数）。
3. **判定不复制**：合约状态、参与方、策略越界一律由合约域回答；合约 C 型码原码透传（1008C0008/0012/0013/0020）。
4. **产品下架不阻断既有合约**：只读摘要只看合约生效；产品状态不构成交付门槛（沿 C-4.1 行为 6 规则 3）。

### 2.3 跨服务集成（最小加性）

1. 合约域新增 `GET /api/v1/contracts/internal/contract-summaries/{contractNo}?requesterNo=`（权限 `contract.internal.read`）：参与方可见性 + 生效门槛 + `productId/productName/applicantNo/providerNo/status/effectiveAt`；**不计数、不写 usage_log**；非参与方/不存在 1008C0012 同码同文，非生效 1008C0013。
2. 目录域内部产品视图追加 `productType`（7 字段；`API/DATASET/REPORT/MODEL`），供交付形态校验；既有 6 字段消费者不受影响。
3. 服务身份：`delivery-service` / `delivery-internal`；contract/catalog yml 各 1 行授权；ADR-016 §6 第 8 消费方。
4. **ADR-022 零改动**：网关内部判定响应保持原样；文件交付不重复网关链路。

### 2.4 文件源与加密交付包

1. **文件源 = 配置化清单**（`ctds.delivery.files[]`：fileId/productId/相对路径/展示名）+ 源根/存储根；启动校验 fileId 唯一、路径在源根内、非符号链接、普通文件、0 < size ≤ max；fileId 仅精确键，**不接受用户路径**（Q3-A）。
2. **国密**：`common-crypto` `Sm4Service`（SM4/GCM 信封 v1/v2）+ `Sm3Service`（SM3 小写 hex）；明文 **≤64MiB**（ADR-006 硬上限），超限 1009C0008；流式分块登记演进。
3. **包存储**：包标识 = `deliveryNo + ".sm4"`；写临时文件 → 原子移动；DB 失败删除包；只落加密件，明文不落盘。
4. **领取**：仅合约需求方可下载加密包（`application/octet-stream` + `X-Ctds-Sm3`）；提供方/运营方不可领取数据；非参与方/不存在同码同文 1009C0007。
5. **接收方密钥分发不在 V1.0**：包需接收方持有 keyRef 对应密钥才能解密；本卡不做密钥分发/封装（登记 3.6.x/3.9.1/后续包）。剧本 S2 只校验“包 + 校验值 + 记录”。

### 2.5 幂等

1. `@Idempotent`（memory 结果复用）+ DB 唯一键 `(requester_no, idempotency_key)` 永久兜底。
2. 同一幂等键重放返回首次结果，不增加记录、不重复生成包；同键不同请求体亦返回首次结果（规格行为 1 规则 5 / 行为 3 规则 5）。
3. 多实例部署前换分布式幂等（DB 唯一键已提供永久兜底；应用层 memory 为单实例语义，登记演进）。

### 2.6 错误码

| 码值 | 含义 | HTTP |
| --- | --- | --- |
| `1009C0003` | 非合约需求方不可发起交付（与网关同值同义） | 403 |
| `1009C0005` | 交付请求参数非法 | 400 |
| `1009C0006` | 交付形态或范围与合约约定不符 | 400 |
| `1009C0007` | 交付记录不存在或无权查看（同码同文） | 404 |
| `1009C0008` | 文件超出交付上限（64MiB） | 400 |
| `1009C0009` | 仅合约需求方可领取交付包 | 403 |
| `1009S0002` | 交付依赖不可用（合约/目录/文件源） | 503 |
| `1009S0003` | 交付包生成或读取失败 | 500 |

未认证 `1000C0002`（401）、无权限 `1000C0005`（403）、分页参数 `1000C0001`；合约 C 型码原码透传；禁止改写合约域结论码。

### 2.7 访问边界与留痕

1. 交付记录可见范围 = 合约参与方（需求方 + 提供方）；平台运营方走治理读面（唯一例外，读即留痕）；其余同码同文 1009C0007。
2. 服务端强制：界面隐藏、参数篡改、直调接口均不构成权限。
3. 留痕四要素（谁/何时/对象/动作）+ 业务要素（形态/结果/校验值/触发码）；**不含文件本体、原文、路径、密钥材料**；审计落 `delivery_action_log` + common-logging JSONL。

### 2.8 诚实边界与未收敛面

1. 接收方密钥分发/解密能力、提供方文件上传/对象存储接入、>64MiB 流式分块、每交付独立密钥、分布式幂等：均登记后续包（3.6.x / 3.9.1 / 4.3.3 前 / 部署演进）。
2. V1.0 交付包为加密件；接收方在 V1.0 不能自行解密（无密钥分发通道）——验收只校验包与校验值。
3. 前端交付界面归 3.5.6；本 ADR 只固化后端契约。
4. 计量：`delivery` 记录 = 3.7.5 文件交付事件源；合约 `usage_log` = 策略计数；两者分工不双计。存证上链归 3.8.3。

## 3. 理由

1. **判定唯一**：准入/状态/策略一律由合约域回答，交付服务只消费；避免第二套状态与策略口径。
2. **最小加性**：contract 只加只读摘要端点，catalog 只加 `productType` 字段；不改 ADR-022/网关/既有码值。
3. **安全默认**：fail-closed（依赖不可用 503、文件源未配置不可用、包只加密落盘、路径不接受用户输入）；密钥/明文/本体零入日志、DB、审计。
4. **复用优先**：SM4/SM3 走 `common-crypto`（ADR-006 唯一入口），幂等走 `common-idempotency`，分页/审计/错误码走 common；零新第三方依赖。
5. **契约可核**：交付记录不含本体但含校验值/结果，满足行为 3 规则 4 与行为 7 规则 5；3.7.5/3.8.3 有统一事件源。

## 4. 备选方案与业务影响说明

| 备选 | 业务影响 | 结论 |
| --- | --- | --- |
| B1 交付记录塞进网关/合约服务 | 网关无库/反应式，合约域与交付域混载；后续沙箱/界面难拆分 | **不采**（新建 delivery-service） |
| B2 文件源用提供方上传端点 | 更接近生产，但新增规格外业务端点、权限与存储面，1 会话不可控 | **不采**（配置化清单；上传登记演进） |
| B3 请求直接携带文件路径 | 用户可控路径 = 目录穿越/越权读取风险 | **不采**（fileId 精确键） |
| B4 文件交付不调用策略 check | 实现简单，但存在绕开次数配额反复取文件的风险 | **不采**（Q4-A：消费 check 一次） |
| B5 文件交付只返回明文/服务端解密下载 | 弱化“加密交付包”语义与安全面；接收方密钥分发仍未解决 | **不采**（V1.0 只交付加密件，密钥分发登记边界） |
| B6 每次交付新建 KMS SM4 密钥 | 隔离性更好，但需 KMS admin/密钥生命周期，超预算 | **不采**（单一 keyRef；每交付独立密钥登记演进） |
| B7 扩展现有内部判定响应加 productId | 改变 ADR-022 已固化响应；仍存在“计数先于发起人校验”观察项 | **不采**（新增只读摘要端点，发起人校验先于计数） |
| B8 改写 ADR-022 承载文件通道 | 网关契约与文件通道混载，语义污染 | **不采**（新建本 ADR） |

## 5. 影响范围

1. **新增模块**：`services/delivery-service`（端口 8087，MySQL `ctds_delivery`，Flyway V1）；根 `pom.xml` 模块注册；零新第三方依赖。
2. **合约域**：新增 `InternalContractSummaryController/Service/Views` + yml 1 行 `delivery-internal`；既有端点/码值/库表零改动。
3. **目录域**：`InternalProductView` 增 `productType`（7 字段）+ yml 1 行 `delivery-internal`；既有 6 字段消费者不受影响。
4. **部署**：`deploy/k8s/delivery-{deployment,service}.yaml` + `kustomization.yaml` 2 行；`ctds_delivery` 库需运维 bootstrap（沿 catalog/contract 先例）。
5. **界面/剧本**：前端零改动（3.5.6）；C-5.1 S2 凭证口径按 G1-A 修订（待 PO 批准）；C-5.2 无需更新。
6. **安全/合规**：新增交付记录/动作留痕字段（分级规范 §6.1/§6.2 回写）；无密钥/明文/本体出站；传输层演示期仅本机可达（ADR-016 §2.7）。
7. **下游**：3.7.5/3.7.6 消费交付事件；3.8.3 消费交付环节存证口径；3.6.x 接文件源/跨机构通道；4.3.3 国密合规验证覆盖 `common-crypto` 调用路径。

## 6. 可替换性

1. **交付服务**：对外契约 = 本 ADR §2（记录/端点/错误码/访问边界）；替换实现不改下游消费形态。
2. **文件源**：配置清单 → 后续对象存储/上传端点，替换点 = `FileSourceRegistry` + 读取口；包格式/记录/校验口径不变。
3. **加密**：`Sm4Service`/`Sm3Service` 为唯一入口；算法库替换只改 `common-crypto` 内部，交付侧零改动（ADR-006 §5）。
4. **密钥**：KeyProvider/KMS 为唯一抽象；每交付独立密钥/轮换只改 keyRef 供给与记录字段，准入/包/读面不变。
5. **幂等**：`@Idempotent` → 分布式实现，替换点 = 幂等存储；DB 唯一键与业务语义不变。
6. **存储**：加密包存储根可替换为对象存储；`FilePackageStore` 为唯一依赖点，记录/下载契约不变。
