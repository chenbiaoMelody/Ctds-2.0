## 1. 背景

规格 C-5.2 要求为需求方提供**隔离的容器环境**，在环境内按合约约定使用数据，并保证"数据带不出、环境互相隔离、使用可留痕、策略仍生效、配额到顶即止"。WBS-3.5.5 才提供结果审核与导出，WBS-3.5.6 才提供界面；本卡必须先把**环境 + 配额 + 生命周期 + 使用承载 + 数据面出口**的平台侧契约钉死，否则下游各自解释会导致数据面出现绕过口。

本文固化：沙箱任务模型与编号、开通 / 关闭 / 到期 / 对账状态机、容器安全基线、受控作业口径、数据面零出口、留痕字段集、部署边界与演进。

## 2. 决策内容

### 2.1 落位与编号

1. 沙箱子域落在既有 `delivery-service`（`com.ctds.delivery.sandbox`），同库 `ctds_delivery` + Flyway **V2**；零新模块、零新 Maven 依赖、端口 8087 不变（Q1-A）。
2. 资源名 `sandboxes`（规格 §7 Q8-A）；编号 `SB`+6 位（任务）/ `SJ`+6 位（作业），各自独立序号表原子取号（`UPDATE … LAST_INSERT_ID(next_no + 1)`，沿 `delivery_no_seq` 先例）。
3. `sandbox_task` 只存业务要素与配额快照：合约编号、产品 id/名快照、参与方快照、状态、CPU/内存/时长快照、到期时刻、数据文件数、关闭原因、幂等键、时间。**无宿主机路径、无容器 ID/名、无镜像、无内容、无密钥材料**。
4. `sandbox_job` 一行 = 一次受控作业 = **一次数据使用**（3.7.5 计量事件源）；只存状态、退出码、耗时与策略要素。**stdout/stderr 一律丢弃**（可能含数据）。

### 2.2 准入与状态机

1. 固定顺序：幂等查重 → [contract] 内部只读摘要（参与方 + 生效，不计数）→ 发起人 = 需求方 → [catalog] 产品形态（**G1-A：仅 DATASET / REPORT / MODEL**，API 形态 `1009C0006`）→ 数据文件（0 个 → `1009S0004` fail-closed）→ 并发配额 → 取号 → 工作区 → 容器 → 事务落库 → 审计。
2. 状态：`RUNNING` / `STOPPED` / `EXPIRED`。`STOPPED`、`EXPIRED` 的任何使用一律 `1009C0011`（409）；关闭幂等返回当前视图。
3. 到期双保险：`@Scheduled` 扫描（默认 60s，条件更新 `WHERE status='RUNNING' AND expires_at <= NOW()`）+ 每次使用前实时判定（命中即条件更新为 `EXPIRED` 并停容器）。
4. 启动对账：`RUNNING` 任务逐条探活，容器缺失 → `STOPPED/RECONCILED` 并留痕；残留 `RUNNING` 作业 → `FAILED`。服务崩溃 / 宿主重启后可自纠。
5. **单实例语义**：幂等结果复用走 memory、到期扫描为本机扫描；多实例部署前须换分布式锁 / 选主（common-lock 可承接），登记演进。

### 2.3 容器安全基线（缺一不可）

`docker run` 固定 argv（`ProcessBuilder` 仅 `DefaultProcessRunner` 一处，不经 shell）：

1. `--network none`（无网络出口）；不挂 docker socket；不用 `--privileged`、host 网络 / host PID。
2. `--user 1000:1000`（非 root）+ `--cap-drop ALL` + `--security-opt no-new-privileges=true`。
3. `--read-only` 根文件系统 + `--tmpfs /tmp:rw,noexec,nosuid,size=16m`。
4. `--pids-limit`、`--memory` 与 `--memory-swap` 等额（硬限，不启用 swap）。
5. 仅三段挂载：输入只读 / 输出可写 / 作业脚本只读；不挂交付源目录，argv 中不出现用户输入。
6. 镜像必须显式 tag（禁 `latest`），`image` 与作业命令全部来自配置白名单，启动 fail-fast。

### 2.4 受控作业与策略

1. 请求只给 `jobId` + 用途 / 地域；**不开放任意命令、脚本上传或代码执行**（V1.0 诚实边界，自由开发工作台登记演进）。
2. 作业命令来自配置清单（固定 argv + 逐作业超时），容器内 `timeout -s KILL` 负责杀进程，Java 侧以"作业超时 + 10s"兜底。
3. 每次作业调合约域 `check`（`USE`，带用途 / 地域）：**放行才执行并计数 1 次**；拒绝原码透传（`1008C0020` 等），**零计数、零作业记录**。幂等重放返回首次作业，不重复计数。
4. 退出码语义：`0` → `SUCCEEDED`；`124` / Java 侧超时 → `TIMEOUT`；其余 → `FAILED`。`check` 放行后平台侧失败不改写已发生的计数。

### 2.5 数据面零出口

1. `/api/v1/sandboxes/{sandboxNo}/data/**` **一律 403 + 留痕**（`1009C0012`；非参与方 `1009C0010` 同码同文）。参与者、提供方、运营方同样不可直取。
2. `/results` 只返回元数据：`fileName / sizeBytes / checksum(SM3) / createdAt`；>64MiB 文件 `checksum=null`（流式摘要登记演进）。**不提供内容读取**。
3. 结果"带出"只能经 WBS-3.5.5 的审核与导出通道；本卡不提供任何下载 / 导出入口。

### 2.6 留痕字段集

1. 动作：`sandbox.create` / `close` / `expire` / `reconcile` / `read` / `job` / `governance.read` / `denied` / `data.denied`；治理读面**读即留痕**。
2. 允许字段：`sandboxNo / jobNo / contractNo / operatorNo / action / result / reasonCode / status / jobId / purpose / territory / dataFileCount / 时间`。
3. **禁止**：文件内容与原文、宿主机路径、容器 ID / 名、镜像名、命令 argv、stdout / stderr、密钥材料、令牌。

### 2.7 错误码（1009 段顺延）

`1009C0010`（不存在或无权查看，404）/ `1009C0011`（状态冲突，409）/ `1009C0012`（原始数据不可导出，403）/ `1009C0013`（任务数达上限，429）/ `1009C0014`（作业不在清单，400）/ `1009S0004`（运行环境不可用，503）/ `1009S0005`（环境操作失败，500）；复用 `1009C0003` / `1009C0005` / `1009C0006` 与合约域 `1008C` 原码透传。

### 2.8 部署边界

1. **生产 k8s 不注入 docker socket**；`CTDS_SANDBOX_RUNTIME_ENABLED` 默认 `false` → 沙箱接口 fail-closed 503（`1009S0004`），不影响交付记录与文件交付。
2. 演示期本机 Docker Desktop（`OSType=linux`）+ `python:3.12-alpine`（已登记 `docs/dependencies.md` 容器基础镜像节）；路径统一 `--mount type=bind`（Windows 冒号 / 空格安全）。
3. Linux 生产需部署侧保证工作区输出目录对 `uid 1000` 可写（`chown 1000:1000`），代码在 POSIX 下尽力设置权限。

## 3. 理由

1. **容器隔离是规格 Q5-A 的平台侧唯一可验证承载**：进程内"逻辑隔离"无法向需求方证明"数据带不出、看不到别人的环境"；OS 级隔离 + 三段挂载 + 无网络是可演示、可测试的最小可信边界。
2. **同库扩展而非新服务（Q1-A）**：沙箱是交付域子域（资源名 `sandboxes`，凭合约开通），复用既有准入 / 幂等 / 留痕 / 错误码骨架；新模块会带来第二套横切实现与 2 人日不可控的部署面，且 3.5.5 需要读同一批表。
3. **Docker CLI 子进程（Q2-A）**：零新 Maven 依赖；argv 数组 + 配置白名单 + 无 shell 把注入面收敛到"配置本身可信"，配合逐命令超时与正则校验足以支撑 V1.0；SDK / TCP API 的收益不足以抵消依赖变更或攻击面扩大。
4. **受控作业清单（Q4-A）**：行为 5 需要一个可执行的"使用载体"，而开放任意命令 / 代码上传的滥用与审计成本不可控；以"够演示、可验证、可拒绝"为界，是 V1.0 的诚实最小面。
5. **数据复制进平台工作区（Q5-A）**：直接挂交付源目录会让沙箱获得写源能力并暴露宿主机路径；复制后"输入只读 / 输出可写 / 作业只读"成为强制边界，跨沙箱天然隔离。
6. **平台统一配额（Q6-A）与一次作业一次计数（Q7-A）**：配额可自选必然被滥用；开通时计数则无法演示"约定外用途被拒"，也使计量与作业流水脱钩。

## 4. 备选方案与业务影响说明

| 备选 | 业务影响 | 结论 |
| --- | --- | --- |
| 新建 `sandbox-service`（Q1-B） | 新模块 + 新库 + 新端口，2 人日不可控；准入 / 幂等 / 留痕 / 错误码重复实现，3.5.5 跨服务读表 | 弃 |
| 塞进网关或合约服务（Q1-C） | 职责冲突（网关只做交付链路由、合约域只做判定），越界且污染既有契约 | 弃 |

| 引入 `docker-java` SDK（Q2-C） | 新依赖须走变更流程；仅省一次 argv 构造，收益不抵流程与供应链成本 | 弃 |
| 复用 `nginx:1.29-alpine` + shell/awk（Q3-B） | 零新镜像，但作业脚本能力弱、可读性差，分析类作业难以维护 | 弃 |
| 自建 `ctds/sandbox-runtime` 镜像（Q3-C） | 需镜像构建与漏洞治理链，超出 2 人日预算 | 弃 |
| 任意命令执行（Q4-B） | 演示自由度最大，但滥用面不可控、无法审计到作业粒度 | 弃 |
| 只起容器不提供使用（Q4-C） | 行为 5 无承载，剧本"使用与隔离"全部无法演示 | 弃 |
| 直接挂交付源目录（Q5-B） | 省一次复制，但沙箱可改源、泄露宿主机路径，隔离承诺失效 | 弃 |

| 等规格变更后再实施（G1-C） | 阻塞 3.5.4 与下游 3.5.5 | 弃 |

## 5. 影响范围

1. **下游消费方**：3.5.5（审核导出）以 `sandbox_task` / `sandbox_job` / 结果元数据为输入；3.7.5 以 `sandbox_job` 为计量事件源；3.8.3 存证引用作业编号。
2. **数据保留**：关闭 / 到期**不删除工作区**（3.5.5 需要产物）；工作区清理归 3.5.5 / 运维收口，构成磁盘增长风险（登记债务候选）。
3. **并发与部署**：并发配额 `count → insert` 非严格串行，极端并发可能短暂超限（单实例演示可接受，登记观察项）；到期扫描为单实例语义，多实例须先换分布式锁 / 选主。
4. **运行时边界**：沙箱能力依赖容器运行时；k8s 默认关闭（`CTDS_SANDBOX_RUNTIME_ENABLED=false`）时接口 fail-closed 503，**交付记录与加密文件交付不受影响**（不降级为"假隔离"）。
5. **可观测面**：新增 9 类审计动作与 7 个错误码；既有 1009 段码值语义零改动。
6. **前端**：本卡不含界面（3.5.6），无前端影响。

## 6. 可替换性

1. **运行时**：`SandboxRuntime` 为唯一端口；Docker CLI 可替换为 K8s Job / 远程容器服务，应用层与数据面契约不变。
2. **工作区存储**：`SandboxWorkspaceStore` 为唯一落点，本地目录可替换为共享存储 / 对象存储，结果元数据契约不变。
3. **扫描与配额**：单实例扫描可替换为分布式锁 / 选主（common-lock），`status + expires_at` 语义不变。
4. **作业清单**：配置化，新增作业只需加配置与脚本（`command[0]` 白名单扩展须走变更流程），不改代码。
5. **编号**：`SB` / `SJ` 序号表可替换为号段服务，格式契约与错误码不变。
