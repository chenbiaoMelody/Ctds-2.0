## 1. 背景

规格 C-5.2 行为 6 定义"结果审核后导出"为本域核心管控点：沙箱结果物的**唯一合规出口 = 平台审核通过后的导出**；审核通过 ≠ 免策略（导出仍受合约策略校验）；一切判定在服务端；导出产生记录且全程留痕。PRD 行 137 将其列为 P0。ADR-024 交付了环境与数据面零出口（`/data/**` 403），本卡补上**唯一出口本身**：提交审核 / 治理审核 / 审批后导出 / 记录与读面。

本文固化：结果物登记与状态机（含 G2 驳回后重新提交口径）、治理审核写面与读写分权、导出链路与"一次导出 = 一次交付动作"的载体选择、错误码与防枚举、留痕字段集、以及对两处 hifi 契约与 V1 现状物理冲突的最小偏差处置。

## 2. 决策内容

### 2.1 落位与模型

1. 落位既有 `delivery-service` 沙箱子域（Q1-A 沿 3.5.4）：同库 `ctds_delivery` + Flyway **V3**；零新模块、零新 Maven 依赖、零新容器镜像、零新 ADR-016 §6 消费方；端口 8087 不变；`Sandbox*` 前缀划界不变。
2. `sandbox_result`（结果物登记）：**一任务 + 一文件名 = 一行**；**提交审核时登记**（Q1-A）——状态 `PENDING → APPROVED / REJECTED`，`review_round` 首次提交 = 1；**提交时快照**（`size_bytes` + `checksum` SM3 小写 hex）为导出复核锚点；恒非空（>64MiB 文件提交即拒 `1009C0008`，工作区 checksum 为 null 的文件同语义拒绝）。
3. `sandbox_result_review`（审核留痕）：**一轮一行，不可变**（谁审 / 何时 / 结论 / 理由 / 轮次）；只追加，永不 UPDATE / DELETE；驳回理由为业务文本独立成列，不污染动作留痕的错误码语义（Q7-A）。
4. 状态机（hifi §3.1）：未登记 / REJECTED 可提交；PENDING / APPROVED 提交 → `1009C0016`；**G2-A（PO 已批准，规格 V1.2 留痕）：REJECTED → 重新提交 → PENDING（round+1、快照刷新、历史全留痕）**；APPROVED 导出可多次（每次一次计数一条记录），状态不变；任意状态下导出非 APPROVED → `1009C0016`。

### 2.2 审核面（治理唯一写面）

1. `POST /api/v1/sandboxes/governance/{sandboxNo}/results/{fileName}/actions/review`，新权限点 **`sandbox.review`（仅 admin）**——与 `sandbox.governance`（只读）**读写分权**（Q2-A）；非 admin 由权限层拒绝（`1000C0005`）。
2. body `{conclusion: APPROVE|REJECT, reason?}`；REJECT 时 reason 必填（1~256 字）否则 `1009C0005`；**结论一经作出不可修改**（已定论再审 → `1009C0016`）；纠错路径 = 需求方重新提交触发新轮次（G2）。
3. 生命周期门槛（Q4-A）：提交 / 审核 / 导出均要求任务 **RUNNING**；到期 / 已关闭一律 `1009C0011`（锚剧本 S3-6）。
4. 审核留痕列表 `GET …/governance/{sandboxNo}/reviews`（治理读面，**读即留痕**）。

### 2.3 导出链（一次交付动作）

1. `POST /api/v1/sandboxes/{sandboxNo}/results/{fileName}/actions/export`（`sandbox.use`；`X-Idempotency-Key` 必填；body 携带可选 purpose / territory）。固定顺序：参数 → 可见性（0010 任务级同码同文）→ 需求方（0003）→ RUNNING（0011）→ **登记存在且 APPROVED**（否则 0016）→ [contract] `check`（USE；放行即计数，越界 1008C 原码透传、零计数零记录零包）→ **快照复核**（工作区当前 SM3/字节数 vs 登记快照，不一致 → 0016，防"审 A 交 B"）→ 受控读取（≤max-bytes）→ **SM4 加密包**（common-crypto 唯一入口，key-ref 复用 `ctds.delivery.file.key-ref`；packageId = `<deliveryNo>.sm4`）→ 交付记录 → 留痕。
2. **导出记录复用 `deliveries`**（Q3-A）：新增 `SANDBOX_EXPORT` 类型 + 加列 `sandbox_no` / `result_name`（既有行恒 NULL）；**3.7.5 计量与 3.8.3 存证读单一交付事件源，不双轨**；不与 `sandbox_job` 双计。
3. `check` 放行后平台侧失败（加密 / 存储）→ 不写导出记录 + 删包回滚 + 审计 FAILURE，**不改写已发生的计数**（沿 3.5.3 Q4 诚实边界）；幂等 = 内存 `@Idempotent`（key = requester + X-Idempotency-Key）+ `deliveries` 唯一键兜底（重放返回首次记录，计数不重复）。
4. **导出包领取复用 3.5.3 下载端点**（`GET /api/v1/deliveries/{deliveryNo}/package`，密文 + `X-Ctds-Sm3` 头，仅合约需求方）。
5. **工作区内容读取的唯一受控出口**：`SandboxWorkspaceStore.readResult`（有界 64MiB + 输出目录 containment + 符号链接拒绝），仅供本导出链在"登记 APPROVED + 策略放行 + 快照复核通过"之后调用；ADR-024 数据面零出口口径不变——内容只以 SM4 密文离开服务进程。

### 2.4 错误码与防枚举（Q6-A）

1. `1009C0015` 结果物不存在或无权查看（404，**同码同文防枚举**，结果物级）。
2. `1009C0016` 结果物当前状态不允许该操作（409：未审核 / 审核中 / 已驳回 / 快照不一致 / 重复审核 / 已通过再提交）。
3. 任务级沿用 `1009C0010`（非参与方与"任务不存在"同码同文）；两级防枚举各自同码同文；既有码值零改动。

### 2.5 与 hifi 契约的两处最小偏差（编码实测发现，纯技术必要）

1. **`delivery.delivery_type` 列放宽 VARCHAR(8) → VARCHAR(16)**：hifi §2.3 称"列类型不变"，但 V1 现状 8 字符容不下 `SANDBOX_EXPORT`（14 字符，MySQL 严格模式直接拒绝写入）；V3 以 `MODIFY` 放宽列宽，**既有 API/FILE 值零变更**，语义与取值域断言不受影响。
2. **下载端点包形态门槛加性放宽**：hifi §5 称领取"零新下载代码"，但 3.5.3 `DeliveryQueryService.download` 有 `deliveryType != FILE → 1009C0006` 门槛，SANDBOX_EXPORT 行会被拒；加性放宽为 **FILE 或 SANDBOX_EXPORT**（API 行与缺包行仍拒绝，既有语义零变更）。

以上两处均为"hifi 文字与既有物理实现的冲突消解"，未改变任何已确认的业务口径；留痕于任务卡 §四 / 开发日志，供评审与 PO 复核。

## 3. 理由

1. **唯一出口必须有锚**：审核对象与导出物必须严格一一对应——"提交时快照 + 导出时复核"是"审 A 交 B"攻击的唯一服务端防御（Q5-A）；无登记（B/C 备选）则审核留痕无载体、复核无锚、结果物级防枚举无判定基础。
2. **导出记录进 `deliveries` 是事件源唯一性要求**：计量（3.7.5）与存证（3.8.3）按规格 Q7-A 读"交付事件源"；若沙箱导出另立 `sandbox_export` 表，下游须读两表对账，双轨必然漂移（Q3-B 的业务影响）。
3. **读写分权是最小越权面设计**：审核是治理**写**动作（改变结果物可导出性），与治理**读**（查看）分离后，"可看"不再蕴含"可放行"（Q2-C 的风险）；结论不可修改 + 驳回重提交新轮次，使纠错路径全程留痕而非改写历史。
4. **G2（驳回可重新提交）是业务闭环的必要补定义**：沙箱作业产物文件名固定、重跑覆盖同名文件；若驳回即终态，该文件名永不能再审（规格 V1.1 未定义项；PO 已批准补定义，零规则文字变更）。
5. **策略复核在导出而非提交**：审核是"内容可否带出"的判定，策略是"本次使用可否发生"的判定——两者语义不同时点不同；导出时 `check` 保证"审核通过 ≠ 免策略"（行为 6 规则 3），拒绝零计数零记录。

## 4. 备选（不采纳及业务影响）

| 备选 | 不采纳原因 / 业务影响 |
| --- | --- |
| 结果物产出即自动全量登记（Q1-B） | 无"提交"动作，剧本 S2-5 无承载；审核队列被未提交文件淹没 |
| 不落库纯文件判定（Q1-C） | 审核留痕无载体、导出复核无锚、结果物级防枚举无判定基础 |
| 需求方自审自导（Q2-B） | 违反行为 7 规则 2"治理例外唯一"，审核形同虚设 |
| 复用治理读权限点做审核（Q2-C） | 读写不分权：可查看即可放行导出，越权面扩大 |
| 独立 `sandbox_export` 表（Q3-B） | 交付事件源双轨，计量 / 存证需读两表对账 |
| 导出即明文流式下载（Q3-C） | 违反国密唯一入口与 CAT-04 传输加密口径 |
| 关闭后仍可审核导出（Q4-B） | 与剧本 S3-6"到期 / 关闭被拒"直接冲突 |
| 不复核快照（Q5-B） | 审后覆盖可绕过审核，唯一出口失去意义 |
| 复用 1009C0010 做结果物级防枚举（Q6-B） | 任务级与结果物级语义混载，文案不贴切 |
| 审核记录并入 `sandbox_action_log`（Q7-B） | 驳回理由为自由文本，与 reason_code 错误码语义混载；轮次无处落 |
| 并入 ADR-024（Q8-B） | 环境契约与审核导出契约混载，语义污染（沿 ADR-023/024 分立先例） |
| 驳回即终态（G2-B） | 重跑覆盖同名文件后永不能再审，业务闭环卡死 |

## 5. 业务影响说明

1. **对需求方**：沙箱成果必须"提交审核 → 平台结论 → （通过后）导出"三步才能带出；被驳回的结果物修改后可重新提交（新轮次，历史全留痕）；导出得到的是国密加密包 + SM3 校验值，凭导出记录领取；每次导出消耗一次合约使用次数（策略拒绝则零消耗）。
2. **对提供方**：全程只读可见（结果物状态 / 结论 / 驳回理由 / 导出记录），不可提交、不可审核、不可导出、不可领取加密包。
3. **对平台运营方**：获得唯一的审核写面（通过 / 驳回 + 理由），审核留痕专用表 + 治理读面（读即留痕）；结论一经作出不可修改。L4 分级规范"双人复核"演示期为单审核人（诚实边界登记，"待生效"口径）。
4. **对下游**：3.7.5 计量与 3.8.3 存证直接消费 `deliveries`（SANDBOX_EXPORT 行 + 合约 `check` 计数）为单一交付事件源；3.5.6 界面按本契约端点做导出审批页；零新增消费方登记义务（同服务身份）。

## 6. 影响范围

- **代码**：`services/delivery-service` 单服务内（`Sandbox*` 划界 + 交付面两处加性放宽：`DeliveryType` 枚举 +1 值、`DeliveryQueryService.download` 包形态门槛；`Delivery`/`JdbcDeliveryRepository`/`SandboxActionLog`/`JdbcSandboxRepository`/`SandboxAuditService`/`SandboxViews`/`DeliveryExceptionHandler`/`application.yml` 加性扩展）；交付域外零改动。
- **数据库**：`ctds_delivery` Flyway **V3**（2 新表 + `delivery` 加列 `sandbox_no`/`result_name` + `delivery_type` 列宽放宽 + `sandbox_action_log` 加列 `result_name`）；既有行加列恒 NULL、既有类型值零变更。
- **契约面**：新端点 3 个（提交审核 / 导出 / 导出记录列表）+ 治理 2 个（审核 / 审核留痕列表）；新权限点 1 个（`sandbox.review`，仅 admin）；新错误码 2 个（`1009C0015`/`1009C0016`）。
- **不改**：既有端点语义、既有错误码码值、`/data/**` 拒绝面、门禁配置（`gates-config.json` 零改动）、ADR-001 技术基线；零新 Maven 依赖、零新镜像、零新 ADR-016 §6 消费方。
- **登记演进（本卡不做）**：工作区与导出包清理回收（延续 ADR-024 §6.2 债务）；导出包保留期 / 领取次数限制；审核排队 / 通知机制；大文件流式加密；L4 双人复核。

## 7. 可替换性

1. **导出记录载体**：`deliveries` 复用为"单一交付事件源"决策；若后续规模需要分表，可按 `delivery_type='SANDBOX_EXPORT'` 平滑拆出（行结构与编号序列自洽），下游对账口径须同批迁移。
2. **审核写面形态**：治理写端点 + `sandbox.review` 权限点为演示期单审核人口径；接双人复核 / 会签时在 `sandbox_result_review` 上加签核轮次即可（表按"一轮一行"追加式设计，无 UPDATE 面需要迁移）。
3. **加密与存储**：SM4 加密 / SM3 校验 / 包存储全部经 `common-crypto` 与 `FilePackageStore` 间接依赖；换 KMS 接入方式或对象存储只动 `ctds.delivery.file.key-ref` / `storage-root` 配置面，导出链代码零改动。
4. **快照算法**：SM3 快照锚点若需升级（如加盐 / 分块），只影响 `sandbox_result.checksum` 语义版本，导出复核逻辑同批升级；状态机与留痕结构不变。
5. **国密组件替换风险**：全部密码学经 `common-crypto` 唯一入口（ADR-006/015），本卡零自行实现；组件升级对本卡的替换面 = 无。
