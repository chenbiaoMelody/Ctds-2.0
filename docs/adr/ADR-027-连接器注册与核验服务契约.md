| 字段 | 内容 |

| 日期 | 2026-10-26 |

## 1. 背景

PRD C-6.2（P0）要求平台侧对连接器完成"注册、核验、升级、注销"全生命周期管理；本卡（WBS 行 302）落地其中的**注册申请与核验**（WBS-3.6.4 承接升级与注销）。上游已闭环：C-1.1 主体域（ADMITTED 门槛 + 内部只读面 `subject.internal.read`）、C-1.2 DID 域（解析与状态、下游消费方口径）、C-6.1 连接器 SDK（`ConnectorContext.connectorNo` 为占位）。本 ADR 固化连接器域**平台侧首个服务**的契约，供 3.6.4 / 3.6.7 / 3.6.8 与 SDK 消费。

## 2. 决策

**2.1 服务落位**：新建 `services/connector-service`（端口 **8088**，库 **`ctds_connector`**，Maven artifact `connector-service`），四层沿 delivery-service（`interfaces / application / domain / infrastructure`），`spring-boot-starter-jdbc` 手写 SQL + Flyway，**零新第三方依赖**；根 pom 挂 1 行 module；不声明 jacoco（覆盖率由门禁脚本承载，沿 9 服务惯例）。

**2.2 库表与迁移**（`V1__create_connector_tables.sql`，4 表）：

| 表 | 用途 | 关键约束 |
| --- | --- | --- |
| `connector_registration` | 注册申请与档案（一表两阶段） | `uk_application_no`(CA) / `uk_connector_no`(CN) / **`uk_subject_active_name(subject_no, active_name_norm)`**（活跃态同主体同名唯一；注销后可重注册） |
| `connector_did_binding` | 连接器 ↔ 主体 DID 绑定 | `uk_connector_binding`(connector_no)；**不冗余 DID 状态** |
| `connector_action_log` | 域内动作留痕（只插不改） | `idx_log_application` / `idx_log_connector` |
| `connector_application_no_seq` / `connector_no_seq` | 双轨取号（各 1 行） | `UPDATE … SET next_no = LAST_INSERT_ID(next_no + 1)` |

状态列 `VARCHAR(16)` 存枚举名，列注释全量定义**三主态** `PENDING_REVIEW / REGISTERED / CANCELLED`；本卡代码**只实现前两态**，`CANCELLED` 归 3.6.4（注销）。`active_name_norm` 为 `STORED` 生成列：`IF(status = 'CANCELLED', NULL, LOWER(TRIM(connector_name)))`。

**2.3 编号双轨**：**申请单号 `CA` + 6 位**（登记即签发，待核验态寻址 / 补正 / 核验用）；**连接器编号 `CN` + 6 位**（**核验通过事务内签发**，规格行为 6-4 / 7-3 明文）；单调递增、**终身不复用**（注销不回退，3.6.4 沿承）。

**2.4 核验三查与跨域装配**（规格行为 7 规则 1）：① **主体资格** = 主体域既有内部端点 `GET /api/v1/subject/internal/subjects/{subjectNo}/admission`（`subject.internal.read`；subject `application.yml` 追加 1 行 `connector-internal` 映射，零代码改动）；② **DID 有效** = DID 域**新增内部只读端点** `GET /api/v1/did/internal/subjects/{subjectNo}/current`（`did.internal.read`，仅 `connector-internal` 持有；**ADR-017 §11 补记**）；③ **信息完整** = 本域校验（名称 2~64 / 类型 `STANDARD` / 版本 `主.次.修订`）。**跨域不可用（不可达 / 超时 / 非 200 / 不可解析）→ 503，不冒充业务结论**（fail-closed）。

**2.5 绑定与 DID 状态联动**：核验通过事务内建 `ACTIVE` 绑定（`connector_no / subject_no / did / bound_at`）；绑定表**不写 DID 状态快照**；详情 / 绑定查验 / 内部面**每次实时查 DID 域**，`status != ACTIVE` → `verified = false`（如实反映吊销），DID 不可达 → 503。

**2.6 核验结论语义**：三查任一不通过 = **HTTP 200 业务结论**（`verified=false` + `failedCheck` 首个失败项 + `reasonCode` + 可读理由 + 留痕），档案保持 `PENDING_REVIEW`、可补正重提；**不设 B 型错误码**。

**2.7 1010 段占用表**（Q9-A 兑现，占用留痕即本节）：

| 码 | 常量 | 语义 | HTTP |
| --- | --- | --- | --- |
| `1010C0001` | `PARAM_INVALID` | 要素 / 编号格式 / 路径变量非法 | 400 |
| `1010C0002` | `NAME_DUPLICATED` | 同主体同名活跃档案已存在 | 400 |
| `1010C0003` | `NOT_FOUND_OR_DENIED` | 未找到或无权访问（**防枚举同码同文**） | 400 |
| `1010C0004` | `STATE_NOT_ALLOWED` | 状态门槛不通过 | 400 |
| `1010C0005` | `INFO_INCOMPLETE` | 核验第三查不通过 | 200 结论 |
| `1010C0006` | `SUBJECT_NOT_ADMITTED` | 主体资格不满足 | 400 / 200 结论 |
| `1010C0007` | `DID_NOT_VALID` | 主体 DID 非 ACTIVE | 200 结论 |
| `1010S0001` | `SUBJECT_UNAVAILABLE` | 主体服务不可用 | 503 |
| `1010S0002` | `DID_UNAVAILABLE` | DID 服务不可用 | 503 |
| `1010S0003` | `INTERNAL_ERROR` | 内部错误 | 500 |

**2.8 最小健康度**（规格 §7 Q8-A）：`last_heartbeat_at` + `POST /api/v1/connectors/{connectorNo}/heartbeats`（仅属主 + 仅已注册）；在线 = 最近心跳未超 `ctds.connector.health.offline-after`（默认 5m，启动校验 1m~1440m）；**读时派生、零调度**，展示归 3.6.7、监控归 3.9.4。

**2.9 权限点与角色**：`connector.register` / `connector.read` / `connector.review` / `connector.heartbeat` / `connector.internal.read`；角色映射 `applicant`（参与方）、`admin`（运营方 + 内部面直调）、`connector-internal`（服务身份内部面；3.6.4 / 3.6.7 / 3.6.8 消费）。运营方判定 = `admin` 角色（演示期角色模型）。

**2.10 内部消费面**：`GET /api/v1/connectors/internal/connectors/{connectorNo}` 返回连接器 + 绑定 + 实时 DID 状态（最小暴露；不含凭据）。

## 3. 理由

1. **独立服务**：连接器生命周期（注册 → 核验 → 升级 → 注销）与主体入驻生命周期不同步，独立库可独立演进与回滚；3.6.4 在同服务增量扩展（沿 3.5.4 在 delivery 内增 sandbox 包先例）。
2. **双轨编号**：待核验档案必须有可寻址标识（补正 / 核验 / 防枚举都需要），而"连接器编号"按规格只能在核验通过时产生；共用一个编号会让被拒申请占用编号（语义污染 + 3.6.4 编号审计复杂）。
3. **活跃态生成列**：MySQL 唯一索引允许多个 NULL，故注销态 `active_name_norm` 置 NULL 即可实现"注销后同名重注册"（行为 10 验收 4），3.6.4 **零改表**。
4. **DID 状态不冗余**：快照式冗余在对方 DID 吊销后仍显示有效 = **fail-open**，直接违反行为 8 规则 3；实时读 DID 域（内部面 + 回环边界）成本可接受（单条 3s 超时，仅详情 / 绑定 / 内部面调用）。
5. **新增 DID 内部只读点**：复用管理面 `GET /api/v1/did/records` 需 `did.admin`（吊销 / 重签能力），给服务身份授权违反最小权限；参与方自报 DID 则把"平台取 DID"降级为"参与方自报"，与 Q2-A 身份锚语义偏离。
6. **拒绝即 200 结论**：核验拒绝是正常业务结论（含理由 + 留痕 + 可补正），用 4xx 会让前端与审计把业务结论记成失败。
7. **服务身份传法沿既有惯例**：`X-Ctds-Subject: connector-service` + `X-Ctds-Roles: connector-internal`，被调方 1 行角色映射（subject / catalog / contract / did 同款）。

## 4. 备选（不采及原因）

| 备选 | 不采原因 |
| --- | --- |
| 并入 `subject-service` | 主体状态机与连接器状态机同库耦合；3.6.4 继续膨胀，回滚面变大 |
| 并入 `gateway-service` | 网关无库无迁移、Reactive 栈，职责冲突 |
| 登记即签 `CN` 编号 | 与"核验通过时签发"规格明文冲突；被拒申请占用编号 |
| 暴露自增主键寻址 | 可枚举相邻申请（信息泄露），与既有可读编号惯例不一致 |
| 复用 DID 管理面取 DID | 需 `did.admin` 全量管理权限（服务身份越权） |
| 参与方自报 DID + 文档 controller 比对 | 身份锚语义降级；吊销联动需二次解析 |
| 绑定表冗余 `did_status` | 双写不一致 → 吊销后 fail-open |
| 核验拒绝用 4xx | 业务结论被当接口失败，审计口径失真 |
| 列表逐条查 DID 状态 | N 次跨域调用（分页 100 → 最坏 100×3s），不可接受；列表改为摘要（`did/didStatus` 为空），详情 / 绑定 / 内部面给实时状态 |
| 引 `common-idempotency` 做申请幂等 | 本卡无幂等注解使用点；防重由活跃态唯一索引 + `1010C0002` 天然承载（零冗余依赖） |

## 5. 业务影响说明

- 参与方提交连接器注册后**立即得到申请单号**，可随时查询进度与补正；被拒不会"烧掉"连接器编号。
- 平台运营方核验时系统**自动三查**（主体资格 / DID 有效 / 信息齐全），拒绝给出可读原因并留痕，补正后可重审。
- 核验通过后连接器**获得终身唯一编号**并与该参与方 DID 绑定；对方 DID 一旦吊销，任何绑定查验**立即不通过**（不存在"库里写着有效"的窗口）。
- 运营方看到的"在线/离线"来自连接器心跳（默认 5 分钟无心跳 = 离线），只做判读、不发告警。
- 面向后续：3.6.4（升级/注销）、3.6.7（控制台）、3.6.8（集成演练）与 SDK 编号校验均可直接消费本 ADR 的内部面，无需再碰库表。

## 7. 可替换性

- **可替换**：编号前缀与位数（`CA`/`CN` + 6 位，取号表可扩位）；健康度阈值与派生位置（读时 → 可演进为调度 + 缓存，3.9.4 时评估）；内部面路径形态（可并入统一 internal 前缀）；列表是否附带 DID 状态（如后续引入批量查询可恢复）。
- **有意不可替换**：身份锚 = 所属主体 DID（不设连接器独立身份，Q2-A）；绑定查验与 DID 状态**实时联动**（fail-closed，不冗余快照）；1010 段位归属（一域一段惯例，跨域复用须走变更流程）；核验结论的"200 业务结论"语义（拒绝不是接口错误）。
