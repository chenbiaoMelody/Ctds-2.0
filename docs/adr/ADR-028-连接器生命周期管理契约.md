# ADR-028 连接器生命周期管理契约

| 字段 | 内容 |
| --- | --- |
| 状态 | 已批准（编码段落盘，随 WBS-3.6.4 交付） |
| 日期 | 2026-10-26 |
| 关联 | 规格 `docs/specs/C-6.1-6.3-接入连接器.md` V1.0（行为 9 / 10 + 行为 8 规则 1 后半 + §7 Q5-A）；设计 `docs/designs/WBS-3.6.4-lofi.md` / `-hifi.md` V1.0；上游 ADR-005 / 009 / 027 |

## 1. 背景

C-6.2 要求平台侧对连接器"注册、核验、升级、注销"全生命周期管理。注册与核验已由 WBS-3.6.3（ADR-027）交付：`connector-service`（8088 / `ctds_connector`）已建 `connector_registration`（三主态含 `CANCELLED` 预留、活跃态生成列）、`connector_did_binding`（`RELEASED` 与 `released_at` 预留）、`connector_action_log` 与 CA/CN 双轨取号。

WBS-3.6.4 只做规格行为 9（升级与版本兼容）与行为 10（注销）。立卡实测两项事实决定了本 ADR 的关键裁决：

1. 3.6.3 的建表前瞻已覆盖注销所需结构（状态取值 / 绑定解除 / 解除时间 / 注销后同名重注册），**本卡零改既有表结构**（仅 +1 列 `cancelled_at`）；
2. **交付域当前无法判定"进行中交付作业"**：`delivery` 表零连接器关联列且只存 `result=SUCCESS` 行，`sandbox_job` 亦无连接器列，delivery 模块无内部只读端点。规格行为 10-1 的前置检查因此**没有上游数据源**。

## 2. 决策

### 2.1 能力落位

在既有 `connector-service` 增量：迁移 `V2__create_connector_lifecycle_tables.sql`（3 表 + 1 列）、9 组端点（对外 6 + 内部 3 + 撤回 1，见 §2.5）、零新服务 / 零新端口 / 零新库 / 零新依赖 / **零出站跨域调用**。

| 表 | 用途 | 关键约束 |
| --- | --- | --- |
| `connector_version_change` | 升级登记 + 版本历史链（单表承双职责） | `uk_upgrade_no`(UC) / **`uk_pending_connector(pending_connector_no)`**（生成列；同连接器至多 1 条待确认） / `idx_version_connector` / `idx_version_status` |
| `connector_job_occupancy` | 在途交付作业占用台账（注销前置检查口径） | `uk_connector_job(connector_no, job_ref)`（幂等 upsert） / `idx_occupancy_status` |
| `connector_upgrade_no_seq` | UC 取号（1 行） | `UPDATE … SET next_no = LAST_INSERT_ID(next_no + 1)` |
| `connector_registration`（既有，+1 列） | 注销终态时间 | `cancelled_at DATETIME NULL`（其余结构零改动） |

### 2.2 升级与版本兼容（行为 9）

- **升级 = 登记动作**，不含运行中实例在线热升级（部署动作归实施）；
- **兼容** → 同一事务：`updateVersion`（门槛 = `REGISTERED` 且 `connector_version = from_version`）→ 变更行 `APPLIED` + `applied_at` → 留痕含 `from/to`；
- **不兼容** → 变更行 `PENDING_CONFIRM`（**当前版本一行不动**，旧版本继续有效）→ 运营方确认端点 → 同一事务：`updateVersion` + 行转 `APPLIED` + `confirmed_by/applied_at` + 留痕；
- **同连接器至多 1 条待确认**（生成列唯一索引兜底，并发第二条 `1010C0004`）；目标版本 = 当前版本 → `1010C0009`；
- **版本历史链** = 该表全部行按时间倒序（低频操作，读面上限 200 行防御）+ 链起点为最早一行 `from_version`；无变更行时链 = 当前版本单点——由此**零双写、零改 3.6.3 数据模型**。

### 2.3 注销（行为 10）

- 前置检查（顺序）：属主或运营方（否则 `1010C0003` 同码同文）→ 状态 `REGISTERED`（否则 `1010C0004`）→ **在途作业占用 = 0**（否则 `1010C0008` + 拒绝留痕，业务状态不变）；
- 终态事务四步：`status=CANCELLED` + `cancelled_at` → 绑定 `ACTIVE→RELEASED` + `released_at`（**记录保留**）→ 待确认升级行 `VOIDED` → 留痕 `connector.cancelled`；
- **待核验申请可撤回**（hifi §5 #10）：待核验档案无连接器编号（`connector_no` 为 NULL），故以 `DELETE /api/v1/connectors/registrations/{applicationNo}` 寻址，语义 = 撤回申请（`PENDING_REVIEW → CANCELLED` + `cancelled_at` + 留痕）；
- 注销后拒绝边界：心跳 / 升级 / 重复注销 / 占用登记 → `1010C0004`；绑定查验 / 内部面 → `1010C0003`；详情 / 留痕 / 版本链 / 生命周期聚合读 → **200（历史可查）**。前四项均由 3.6.3 既有读面逻辑天然产生，**零改既有端点**。

### 2.4 在途作业占用口径（关键裁决）

连接器域建占用台账，使用方（交付链 / SDK）在取数前登记、完结后释放；注销按 `connectorNo` 数在途。

- **接入方归 WBS-3.6.8 端到端演练**；本卡交付内部面 + 裁决口径，以内部端点代登记即可完成 C-6.2 剧本 S3-1 演示（剧本原文已标"技术侧配合项构造在途作业"）；
- **诚实声明**：V1.0 期交付链尚未接入 → 在途计数恒 0，属"口径已就位、使用方未接入"，**不虚报已防护**；
- 登记 / 释放均幂等（`ON DUPLICATE KEY UPDATE`；重复释放直接返回既有记录、不重复留痕）。

### 2.5 端点与权限（1010 段增量）

新增端点 10 个：升级登记 / 版本链 / 待确认队列 / 显式确认（4）+ 注销 / 生命周期聚合读 / 撤回申请（3）+ 内部占用登记 / 释放 / 清单（3）。
新增权限点 4 个：`connector.upgrade`（属主登记）、`connector.upgrade.confirm`（运营方队列与确认）、`connector.cancel`（属主与运营方注销/撤回）、`connector.internal.write`（内部占用写）。

| 码 | 常量 | 语义 | HTTP |
| --- | --- | --- | --- |
| `1010C0008` | `JOB_IN_PROGRESS` | 存在进行中的交付作业，暂不能注销 | 400 |
| `1010C0009` | `VERSION_UNCHANGED` | 目标版本与当前版本相同 | 400 |

复用 `1010C0001` / `1010C0003` / `1010C0004`；**无新 `1010S` 码**（零出站跨域调用），`1010S0003` 维持段位预留不启用。**1010 段在用码 9 → 11**（`1010C0001~0009` + `1010S0001~0002`）。

## 3. 理由

1. **单一事实源**：连接器状态机与生命周期在同一库，注销的"状态 + 绑定解除 + 升级作废 + 留痕"可在**一个事务**内完成；拆服务会产生跨库事务与状态不可原子流转。
2. **不双写**：一张 `connector_version_change` 同时是"升级申请"与"版本历史链"，避免两表一致性风险，也让 3.6.3 数据模型零改动。
3. **不给已验收域返工**：在途作业口径落在连接器域，避免回改 3.5.x 交付域与 3.6.2 SDK（两卡均已验收合并），返工与回归面最小。
4. **最小权限**：版本确认与核验、注销与登记各用独立权限点，审计可按角色还原。
5. **零跨域出站**：生命周期读面不查 DID 域（绑定状态读本域，DID 实时有效性仍由 3.6.3 绑定查验承载），因此无新增 503 语义。

## 4. 备选（不采及原因）

| 备选 | 不采原因 |
| --- | --- |
| 新建 `connector-lifecycle-service` | 连接器档案与生命周期拆两库：升级要跨服务改版本、注销要跨服务事务，状态不可原子流转；3.6.7 控制台需跨两服务聚合 |
| 并入 delivery-service | 交付域无连接器档案（零关联列），反向依赖；职责错位 |
| 交付域加 `connector_no` 列 + 内部端点 + SDK 改头 | 需回改两张已验收卡并双域同步迁移；交付记录仍无"在途"态（仅 `SUCCESS`），需再引作业态，超本卡边界 |
| 不做注销前置检查 | 剧本 S3-1 不可演示、规格行为 10-1 未实现，属规格缺项，须走变更流程 |
| 两表（申请 + 历史）双写 | 同事务双写 + 顺序约束，回滚与补偿面变大，表达冗余 |
| 不兼容升级直接替换 + 事后审核 | 直接违反规格行为 9-2"不自动替换"与验收 3"未经确认版本保持旧值" |
| 同连接器多条待确认并存 | 版本争先：确认顺序决定最终版本，审计口径歧义 |
| 复用 `connector.review` 承载版本确认 / 复用 `1010C0004` 表达在途 | 核验权与版本确认权混同（最小权限受损）；"在途挡注销"与"状态不允许"不可区分（对账/告警口径失真） |
| 注销后读面全拒 | 违反规格行为 10-3 可追溯义务，且需给既有端点加状态门槛（回归面扩大） |

## 5. 业务影响说明

- **升级不中断业务**：兼容升级登记即生效；不兼容升级在运营方确认前**旧版本继续服务**，避免"声明不兼容即停摆"。
- **注销有闸门**：有在途交付作业时拒绝注销并提示先完结或终止，防止"作业中途失源"。
- **注销可追溯**：绑定解除但记录保留（含解除时间），登记 / 版本链 / 留痕全部可查；编号终身不复用，同名重注册得新编号。
- **数据完整性**：注销时未确认的不兼容升级自动作废（`VOIDED`），不会出现"已注销连接器事后被替换版本"的错乱。
- **诚实口径**：V1.0 期交付链未接入占用登记，在途计数恒 0；接入动作归 3.6.8，**不虚报已防护**。

## 6. 影响范围

- `services/connector-service`：新增迁移 1 个（3 表 + 1 列）、新增类 16 个、修改既有 6 个（`ConnectorErrorCodes` +2 码 +2 文案、`ConnectorRegistration` +1 字段、`ConnectorRepository` +3 方法、`JdbcConnectorRepository` 读映射与 +3 方法、`ConnectorBindingRepository` +2 方法、`ConnectorAuditActions` +6 常量）+ `application.yml` 三行权限映射 + 测试 6 类与测试基类清理清单；
- **零改动**：网关与路由、其它 9 个服务、3.6.3 既有 12 个端点语义、门禁配置、根 pom 与依赖坐标；
- 文档：本 ADR + lofi / hifi（**V1.1 勘正 2 处**）+ 任务卡 + 台账 + 会话日志。

## 7. 可替换性

- **可替换**：升级单号前缀（`UC`）、占用台账的登记形态（若将来交付域具备连接器关联，可切换为直接查交付域）、待确认队列分页口径、生命周期聚合读的字段集合、`HISTORY_LIMIT` 上限；
- **有意不可换**：不兼容升级必须运营方显式确认（规格 9-2）、注销前置检查必须在场（规格 10-1）、编号终身不复用（规格 10-2）、绑定解除但记录保留（规格 8-1 / 10-3）、1010 段位与"一域一段"占用制度、防枚举同码同文（`1010C0003`）。
