## 1. 背景

C-6.3（PRD 行 147，P0）要求"多源适配：政务共享交换平台、数据库、对象存储、API 网关等"；规格行为 11 规则 1 要求**四类源全量**、每类由适配器承载。WBS-3.6.5 已交付政务源适配器与登记 / 凭据 / 自检 / 读取面，但**数据库 / 对象存储 / API 网关三类适配器零实现**，自检 / 读取对三类源返回 `1010C0011`（承载未开放）。

立卡实测三项事实决定了本 ADR 的关键裁决：

1. `connector-sdk` 只依赖 `spring-web` + `jackson-databind`，**无 JDBC 驱动、无对象存储 SDK**（全仓零 MinIO/S3/OSS 客户端）；
2. `connector-service` classpath 已有 `mysql-connector-j`（runtime）与 `spring-boot-starter-jdbc`，JDBC 驱动可由宿主提供；
3. 3.6.5 的源地址受理只做**字面量**判定（scheme 白名单 / 禁内嵌凭据 / 字面量私网拒绝），**不做 DNS 解析**——主机名解析到内网的绕过面（DB-91）与"自检结论由源仓储直读留痕表"（DB-90）两条债务挂在本卡。

## 2. 决策

### 2.1 适配器落位与零新增依赖

- 三类适配器落 `connector-sdk`：`adapter/database`（`DatabaseSourceAdapter` / `DatabaseSourceClient` / `JdbcUrlPolicy` / `DatabaseCredential`）、`adapter/objectstorage`（`ObjectStorageSourceAdapter` / `PresignedUrlClient` / `ObjectStorageCredential`）、`adapter/apigateway`（`ApiGatewaySourceAdapter` / `ApiGatewayClient` / `HttpProbeResult`）；
- **零新第三方依赖、`connector-sdk/pom.xml` 零改动**：只用 JDK 标准 API（`java.sql` / `java.net.http` / `java.net.URI`）+ 既有 `spring-web`；数据库驱动由**运行宿主**提供（`connector-service` 已有 `mysql-connector-j` 9.7.0），驱动缺失时 `DriverManager` 报 "No suitable driver"，按**非预期异常**上抛（平台 502 中性文案），不虚报"网络不可达"；
- 装配改动 = `SourceAdapterConfig` 追加 3 个 `@Bean` + guard `@Bean`（注册表按 `type()` 自动索引，同类型重复仍启动失败），并统一注入 `ctds.connector.source.adapter-timeout`（四类适配器同源）；**端点契约 / 控制器 / 响应视图对外零改动**，服务侧编排与留痕读面的内部改动见 §6。

### 2.2 三类源的访问形态（诚实边界）

| 源类型 | 访问形态 | 只读语义 | 摘要口径 |
| --- | --- | --- | --- |
| `DATABASE` | `jdbc:mysql://host[:port]/schema[?params]`；凭据 `用户名:密码`（首个冒号切分） | `SELECT 1` 探针（连接 `readOnly=true`）；读取只查 `information_schema.TABLES` 计数 | `database=<schema>;tables=<n>`（无表名清单、无行数据） |
| `OBJECT_STORAGE` | 凭据 = 提供方生成的**完整预签名 URL**（`http(s)://`，≤1024）；源地址仅登记标识 | 自检 `GET` + `Range: bytes=0-0`；读取 `GET` 只取响应头，内容不落内存 | `contentType=<…>;size=<n>` |
| `API_GATEWAY` | 凭据 = 完整 `Authorization` 头值（原样出站，不解析 / 不拼接 / 不改写） | `GET`；读取至多消费 1MB **仅计字节数**后丢弃 | `status=<code>;bytes=<n>;contentType=<…>` |

**不做签名实现**（对象存储不做 SigV4 / OSS 签名；红线：不自实现密码学），凭据一律 `common-crypto` SM4 信封存储。**诚实边界**：数据库仅 MySQL 协议；对象存储仅预签名 URL 形态（URL 有有效期，过期后需变更凭据）；API 网关仅 GET 只读；端到端取数归 3.6.8。

### 2.3 JDBC 攻击面收敛（Q3-A）

- **参数白名单（默认拒绝）**：仅允许 `sslMode` / `useSSL` / `requireSSL` / `characterEncoding` / `serverTimezone` / `connectTimeout` / `socketTimeout` / `allowPublicKeyRetrieval` / `useUnicode`（大小写不敏感）；白名单外一律 400 `1010C0001`（含 `allowLoadLocalInfile` / `allowUrlInLocalInfile` / `autoDeserialize` / `allowMultiQueries` 等危险参数）；
- 受理期（登记 / 变更）即校验 JDBC URL 形态与参数，**失败早于落库**；不执行用户 SQL、不写源端。

### 2.4 三类失败原因映射（Q4-A）

| 源类型 | `NETWORK_UNREACHABLE` | `INVALID_CREDENTIAL` | `INSUFFICIENT_PERMISSION` |
| --- | --- | --- | --- |
| 数据库 | SQLState `08xxx` / 连接超时 / 未知主机 | SQLState `28xxx` / MySQL `1045` | SQLState `42000` / MySQL `1044`·`1142`·`1227` |
| 对象存储 | `IOException` / 超时 / 未知主机 | 401；403 + 签名 / 凭证类关键字 | 403 其它；404（不泄露存在性） |
| API 网关 | `IOException` / 超时 / 未知主机 | 401 | 403 |

不可归类 → 上抛非预期异常 → 平台 502 `1000S9999` 中性文案（不猜测语义）。

### 2.5 调用边界解析级主机防护（DB-91，Q5-A）

- 领域端口 `SourceHostGuard` + 实现 `InetAddressSourceHostGuard`：在自检 / 读取**调用适配器前**用 `InetAddress.getAllByName` **全量**判定，命中回环 / 任意本地 / 内网 / 链路本地 / 组播 / IPv6 唯一本地（`fc00::/7`）/ 保留段（`0.0.0.0/8`、`100.64.0.0/10`、`192.0.0.0/24`、`198.18.0.0/15`、`240.0.0.0/4` 等）/ IPv6 内嵌 IPv4 私网（NAT64 `64:ff9b::/96`、6to4 `2002::/16`）或**解析失败**即拒绝；**提取不到主机同样拒绝**（fail-closed，不允许静默放行）；受理期字面量判定（`SourceEndpointPolicy`）与调用期判定集**保持相等**；
- 对象存储同时校验**凭据中的预签名 URL 主机**；数据库主机来自 JDBC URL；`mock://` 与 `s3://` / `oss://`（bucket 非主机）不解析；
- **受理期不解析**（避免校验期联网与 TOCTOU）；自检拒绝 = 200 业务结论（`NETWORK_UNREACHABLE`），读取拒绝 = 400 `1010C0010` + `source.denied` 留痕；两种情况**适配器零触达**；
- `ctds.connector.source.allow-private-endpoint` **默认 false 不变**；测试 / 演示显式放开（放开只对"已解析且属受限网段"生效，**解析失败始终拒绝**）。演示环境须在配置与文档留痕。

### 2.6 留痕读面泛化（DB-90，Q6-A）与实现偏差登记

- `ConnectorLogRepository` 新增通用读面 `findLatestByDetailPrefix(connectorNo, action, detailPrefix)`（只取 `SUCCESS / FAILURE` 结论行）；`JdbcConnectorSourceRepository.findLastCheck` 改为复用，**detail 解析保留在源仓储**（派生视图口径），删除自造查询 SQL；
- **实现偏差（设计缺口，已在任务卡 §五 登记）**：hifi §4 拟定返回 `Optional<String> detail`，但既有响应契约 `lastCheck.checkedAt` 需要结论时间 → 实际返回既有领域记录 `ConnectorActionLog`（含 `detail` + `createdAt`，**零新增类型**），语义等价、响应字段零变化；
- **实现偏差（命名对齐）**：hifi 写作 `ConnectorAuditRepository` / `JdbcConnectorAuditRepository`，仓库实际类型为 `ConnectorLogRepository` / `JdbcConnectorLogRepository`，按实际类型落地（零新增类型）；
- **实现偏差（包位置，评审循环 1 ③P2 补登记）**：公共契约 `CredentialResolver` 历史落位在实现包 `com.ctds.connector.sdk.adapter.gov`，三类新适配器（database / objectstorage / apigateway）与服务侧装配均跨包引用该类型。**不迁移**的理由：SPI 七类型已冻结，搬迁或新增同义类型会扩大变更面并触发对外分发库的兼容问题；该接口实质是**平台注入端口**（由 `SourceAdapterConfig` 注入解密实现），不是政务适配器私有工具。后续若开放 SDK 对外分发，应随 SPI 版本化一并迁入 `spi` 包（列为观察项，不在本卡实施）；
- **实现偏差（HTTP 客户端形态，评审循环 1 ③P1 处置）**：政务适配器用 Spring `RestClient`，三类新适配器用 JDK `HttpClient`（`java.net.http`）。理由 = ADR-026 §3-A2 的"零新增依赖 + 主流写法"在本卡口径为零第三方依赖（JDK 标准库亦属主流）；差异仅限传输实现，**超时统一由 `ctds.connector.source.adapter-timeout` 注入**（四类适配器同源，不再各自硬编码），因此"运维配置只对政务源生效"的缺陷已消除。若后续引入统一 HTTP 客户端组件，整体替换点在各适配器包内（端口不变）。

### 2.7 错误码与权限

- **+1 码** `1010C0010 SOURCE_ENDPOINT_NOT_ALLOWED`（400，文案"源地址不被允许（解析到受限网络或访问形态不支持）"）；
- `1010C0011` 保留为**防御性兜底**（四类全开放后理论不达）；复用 `1010C0001` / `1010C0003` / `1010C0004` / `1010S0004` / `1000S9999`；
- **零新增权限点、零新增端点、零迁移**（`credential_ciphertext VARCHAR(2048)` 对 1024 明文实测 1412 字符，无需扩列）。

## 3. 备选方案

| 备选 | 未采纳原因 |
| --- | --- |
| 引入 MinIO 官方 SDK + AK/SK 直连 | 新依赖须审批 + 供应链扫描 + `dependencies.md` 登记；且 AK/SK 签名属密码学实现面（红线 7） |
| 只做模拟源（不接真实协议） | 虚报能力，违反诚实边界；S1 步骤 3~6 无法验收 |
| 数据库只连接不查询 | 权限维度不可验证，"三查"退化为"两查" |
| 放开全部 JDBC 参数 | `allowLoadLocalInfile` / `autoDeserialize` 构成文件读取与反序列化攻击面 |
| 受理期解析并固化 IP | DNS 漂移 + TOCTOU（登记合法、调用期漂移） |
| 维持源仓储直读留痕表（DB-90 延期） | 债务不闭环，detail 编码二次实现 |
| 每类源专属错误码 | 码位膨胀，`1010C0010` 语义已覆盖"地址不被允许" |

## 4. 理由

1. **零供应链新增**：无新依赖、无新模块、无新部署资产；数据库驱动由宿主提供，符合"最小实现"；
2. **零密码学实现**：对象存储走预签名 URL（签名由提供方生成），凭据一律 `common-crypto`；
3. **可证伪**：三类失败原因均有协议特征映射与对应用例；DB-91 拒绝可证伪为"适配器零触达"（桩计数器）；
4. **与 3.6.5 同构**：适配器注册表、凭据引用制、自检 200 业务结论、读取摘要与五要素留痕全部复用，零第二套语义。

## 5. 业务影响说明

1. 参与方现在可以用**四类数据源**接入连接器：政务共享交换平台、数据库、对象存储、API 网关——登记、自检、读取都能走通；
2. 数据库源只做"连通 / 凭据 / 权限"三查与目录级摘要（表数量），**不会读取业务数据**；API 网关源只读一次 GET（最多计 1MB 字节数），**不保存任何响应内容**；对象存储源使用临时授权链接，**不接触长期密钥**；
3. 源地址在真正访问前会再做一次"解析后判定"：解析到内网 / 本机 / 不可解析的地址会被拒绝，**不会把请求打到内网**；
4. 三类失败原因（网络不可达 / 凭据无效 / 权限不足）在界面上是**可读中文**，便于参与方自行排查；无法归类的异常统一提示"稍后重试"，不暴露内部实现；
5. 对象存储的授权链接**有有效期**，过期后需要更新凭据（操作说明与 ADR 已写明）；
6. 内网源默认不可用；演示环境需显式打开开关（配置留痕），生产默认保持拒绝；
7. 本卡不涉及界面（3.6.7）与端到端取数（3.6.8），验收以接口级为准。

## 7. 可替换性

- 适配器按 `SourceType` 注册，可**整类替换**为其它实现（如引入官方 SDK 的数据库 / 对象存储适配器），装配点仍只有 `SourceAdapterConfig`；
- 对象存储升级 AK/SK 直连 = 换 `ObjectStorageSourceAdapter` 客户端实现 + 走依赖审批流程，SPI 与服务侧零改动；
- 主机防护可替换为"白名单解析器"或企业 DNS 策略（端口签名不变）；
- `findLatestByDetailPrefix` 为通用留痕读面，可被后续任何"由留痕派生结论"的场景复用。
