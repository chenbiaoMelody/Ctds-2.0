## 1. 定稿目标与诚实边界

1. 资源“存在但非属主”与“对象不存在”在统一拒绝分支执行同一限流、同一审计写入口、同一异常处理。
2. 同一主体 + 对象 + 动作每分钟最多新增一条拒绝审计；数据库唯一键跨实例兜底。
3. 审计写入故障时，两态均返回统一 500，不再以 500 / 400 区分存在性。
4. 保留极小查询耗时差、服务内限流的单实例边界与固定窗口边界，不声称“所有侧信道彻底消失”。
5. V1.2 追加主体级跨对象拒绝保护：同一主体不断轮换不存在对象 ID 时，拒绝审计写入仍受主体 + 动作窗口上限约束；属主正常操作不受影响。

## 2. 端点与行为契约

端点、鉴权、权限点、业务校验顺序均不新增、不删除。仅“对象存在性拒绝”分支改造。

| # | 端点 | 拒绝动作 | 非属主 | 不存在 | 治理例外 |
| --- | --- | --- | --- | --- | --- |
| E1 | `GET /api/v1/datasets/{datasetId}` | `DENIED_READ` | 统一拒绝 + 审计 | 统一拒绝 + 审计 | 无 |
| E2 | `GET /api/v1/datasets/{datasetId}/action-logs` | `DENIED_READ` | 统一拒绝 + 审计 | 统一拒绝 + 审计 | 持 `catalog.governance` 且对象存在时允许，不记拒绝 |
| E3 | `PUT /api/v1/datasets/{datasetId}` | `DENIED_UPDATE` | 统一拒绝 + 审计 | 统一拒绝 + 审计 | 无 |
| E4 | `POST /api/v1/datasets/{datasetId}/cancellation` | `DENIED_CANCEL` | 统一拒绝 + 审计 | 统一拒绝 + 审计 | 无 |
| E5 | `POST /api/v1/data-products` | `DENIED_CREATE` | 统一拒绝 + 审计 | 统一拒绝 + 审计 | 无 |

E1 / E2 共用 `DENIED_READ` 限流与去重键，交替调用不能绕过；E3 / E4 / E5 各按动作独立计数。

### 2.1 出站矩阵

| 场景 | HTTP | code | message | data | Retry-After | 审计表 |
| --- | ---: | --- | --- | --- | --- | --- |
| 窗口内未超限的对象不存在 / 非属主 | 400 | `1000C0003` | `资源不存在` | `null` | 无 | 两态同一写法；每分钟同键最多新增 1 行 |
| 同一主体 + 对象 + 动作 60 秒内第 21 次起 | 429 | `1007C0022` | `对象访问频率超出限制` | `null` | 1~60 秒 | 不再新增业务拒绝行；前 20 次已留痕 |
| 同一主体 + 动作跨对象累计 60 秒内第 101 次起（V1.2 定稿值） | 429 | `1007C0022` | `对象访问频率超出限制` | `null` | 1~60 秒 | 不再新增业务拒绝行；前 100 次已留痕；已知/未知对象同口径 |
| 审计 INSERT / UPSERT 失败 | 500 | `1000S9999` | `系统繁忙，请稍后重试` | `null` | 无 | 未确认写入，异常进服务端日志 |
| 属主正常访问 / 操作 | 现状 | 现状 | 现状 | 现状 | 无 | 成功留痕逻辑不变 |

封套根字段保持 `code,message,traceId,data`；traceId 允许逐请求不同。429 与 500 均不得回显对象属性或用户输入。

### 2.2 错误码新增

- 新增目录模块码 **`1007C0022`**，语义 = 对象级或主体级拒绝探测超限，HTTP 429。
- 不复用网关 `1009C0002`，避免目录服务跨模块占用网关码段。
- `CatalogExceptionHandler.MAPPED_CODES` 增加该码，`statusOf` 映射 429；码表一致性测试期望从 23 增至 24。
- 新增 `CatalogRateLimitException`（或等价目录异常）携带 `retryAfterSeconds`，由目录 advice 输出 `Retry-After`；不修改 common 全局处理器。

## 3. 统一拒绝流程

### 3.1 读面

1. 现有认证、权限点、参数校验保持不变。
2. 查询对象；不存在直接进入统一拒绝分支。
3. 对象存在时判属主；E2 额外保留治理例外。非属主且非治理例外进入同一拒绝分支。
4. 拒绝分支调用 `DatasetDenialService.record(subject, action, datasetId)`。
5. 记录成功后抛既有 `1000C0003`；超限抛 429；写失败原样上抛由全局处理器转 500。

### 3.2 写面与产品封装

1. 保留现有校验链顺序：E3 空载荷校验、E5 ADMITTED / 名称 / 形态 / 定价校验均仍在对象查询前；E4 沿用基线顺序，在对象查询、属主判定、终态判定后校验 `confirmCancellation` 语义。
2. 对象查询后，不存在与非属主进入同一拒绝分支。
3. 调用同一 `DatasetDenialService.record`，动作分别为 `DENIED_UPDATE` / `DENIED_CANCEL` / `DENIED_CREATE`。
4. 属主通过后，状态门槛、字段校验、幂等、成功事务全部不变。

**为什么限流放在统一拒绝分支**：若在查询前对所有请求限流，属主正常访问也会被误限；若按存在性分支限流，429 本身会泄露存在性。统一拒绝分支同时避免这两个问题。

## 4. 限流契约（Q2 建议值）

| 项 | 定稿建议 |
| --- | --- |
| 窗口 | 固定 60 秒，按 UTC epoch 分钟对齐 |
| key | `主体 + datasetId + action`；不含属主、空间、状态、对象是否存在 |
| 阈值 | 每 key 每窗口最多 20 次拒绝；第 21 次起 429 |
| Retry-After | 当前窗口剩余秒数，取值 1~60 |
| 作用范围 | 只统计已判定拒绝的请求；不影响属主成功请求 |
| 存储 | 服务进程内有界 LRU 映射；默认最多跟踪 10,000 个 key |
| 并发 | 同一 key 的计数更新 synchronized，保证第 21 次判定确定 |
| 重启 | 计数重置；数据库去重键仍防止重复审计行 |
| 多实例 | 每实例各 20 次；数据库唯一键保证每实例合计每分钟最多新增 1 行 |

固定窗口边界允许相邻分钟各新增一条；LRU 淘汰会重置对应 key 的窗口计数，属于明确的单实例保护边界。不得将其描述为分布式精确限流。

### 4.1 主体级跨对象保护（V1.2 定稿）

| 项 | V1.2 定稿契约 |
| --- | --- |
| 窗口 | 固定 60 秒，按 UTC epoch 分钟对齐，与对象级窗口同源 Clock |
| key | `主体 + action`；不含 `datasetId`，因此轮换对象 ID 不能重置主体窗口 |
| 阈值 | 每 key 每窗口最多 100 次拒绝；第 101 次起 429 + `Retry-After` |
| 作用范围 | 只统计已判定拒绝的请求；不影响属主正常访问/操作 |
| 存储 | 独立进程内有界 LRU 映射，默认最多跟踪 10,000 个主体 + 动作 key |
| 判定顺序 | 先对象级 20 次判定，再主体级 100 次判定，最后写审计；任一超限均抛同一 429 |
| 失败回滚 | 主体级判定失败时释放对象级预留；审计写失败时同时释放主体级与对象级预留，随后原样上抛 |
| 多实例 / 多主体 | 每实例、每主体 + 动作分别计数；数据库去重键仍兜底同对象重复写。主体级保护关闭“同一主体轮换对象 ID”放大，不声称全局存储有界 |

业务影响：同一主体在一分钟内对大量不同对象发起拒绝请求时，可能比原对象级设计更早收到 429；超过主体级上限后不再新增拒绝审计，但已知/不存在对象的响应仍同形。正常属主请求不进入拒绝窗口。

## 5. 审计数据契约

### 5.1 两态统一行结构

| 字段 | 不存在 | 非属主 | 说明 |
| --- | --- | --- | --- |
| `actor_subject_no` | 当前主体 | 当前主体 | 谁 |
| `space_id` | `NULL` | `NULL` | 不读取 / 不写入分支属性，确保写入形状一致 |
| `dataset_id` | 请求中的目标 id | 请求中的目标 id | 对象 |
| `action` | 对应拒绝动作 | 对应拒绝动作 | 动作 |
| `from_value` / `to_value` | `NULL` | `NULL` | 不记录分支属性 |
| `result` | `DENIED` | `DENIED` | 结果 |
| `reason_code` | `C0003` | `C0003` | 与统一出站一致 |
| `created_at` | Clock 当前时间 | Clock 当前时间 | 何时 |
| `dedup_key` | 非空 | 非空 | 内部去重字段，不对外暴露 |

`DatasetActionLog.spaceId` 从 `long` 改为 `Long`；成功日志仍写真实 spaceId。`DatasetActionLogView` 已不暴露 spaceId/datasetId，对外 DTO 不变。

### 5.2 去重键

`dedup_key = actorSubjectNo.length() + ":" + actorSubjectNo + "|" + datasetId + "|" + action + "|C0003|" + epochMinute`

- 主体号长度前缀避免分隔符歧义；认证契约 subject ≤128，当前动作/对象/分钟组合下键长小于 255。
- 主体审计列 `actor_subject_no` 扩容为 `VARCHAR(128)`；去重键列定义 `VARCHAR(255) COLLATE utf8mb4_bin NULL`，按大小写精确去重，与 Java String 键语义一致。
- 唯一索引 `uk_dataset_action_denial_dedup(dedup_key)`。
- 历史行、成功行该列为 `NULL`；MySQL 唯一索引允许多个 `NULL`。
- 新拒绝写使用参数化 `INSERT ... ON DUPLICATE KEY UPDATE id = id`；重复键不新增、不修改既有行。
- 唯一键是跨实例同对象写放大兜底；不依赖应用缓存。V1.2 不改变去重键结构，跨对象轮换由主体级限流在写审计前拦截。

### 5.3 V6 迁移（编码时新建，不改 V1~V5）

```sql
ALTER TABLE dataset_action_log
    MODIFY COLUMN actor_subject_no VARCHAR(128) NOT NULL COMMENT '操作者主体编号；与认证 subject ≤128 契约对齐',
    MODIFY COLUMN space_id BIGINT NULL COMMENT '归属空间 id；对象不存在性拒绝审计为 NULL',
    ADD COLUMN dedup_key VARCHAR(255) COLLATE utf8mb4_bin NULL COMMENT '拒绝审计去重键：主体+对象+动作+原因+UTC分钟',
    ADD UNIQUE KEY uk_dataset_action_denial_dedup (dedup_key);
```

迁移遵循 ADR-009：只新增 V6、不手工改表、不回改历史数据。迁移测试需更新 `dataset_action_log` 最终列清单，并验证唯一键与 NULL 语义。

## 7. 异常与边界

1. **限流超限**：对象级第 21 次或主体级第 101 次起两态同 429；不写业务拒绝表。若实例重启或 LRU 淘汰导致计数重置，数据库仍按同对象分钟去重；主体级轮换保护随计数重置而恢复。
2. **审计写失败**：捕获仅用于回滚限流预留，随后原样上抛；不降级、不伪造成功，两态统一 500。异常不得进入对外文案。
3. **重复键**：视为审计已存在，请求仍按统一 400 拒绝；不修改首条时间或内容。
4. **分钟边界**：59.999s 与下一分钟首秒可各新增一条；Q2 确认时作为固定窗口代价接受。
5. **并发**：对象级同 key 与主体级同 key 均在各自 synchronized 边界内判定；数据库唯一键保证同对象最多一行。可能部分请求得到 400、部分 429，但不泄露存在性。主体级上限按实例独立计数，不声称全局精确配额。
6. **治理例外**：E2 仅对象存在且持治理权限时放行；缺失对象仍走统一拒绝，不因治理权限改变防枚举口径。
7. **历史数据**：不回改、不补 dedup_key、不删除。
8. **非改造面**：认证 401、权限点 403、状态门槛、参数校验、幂等、成功事务、产品已成行后的拒绝均不变。
