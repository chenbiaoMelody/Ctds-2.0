### 1.2 处置方向（对产品与用户 = 零影响）

1. **① 成功/失败双态留痕**（方向 Q-ID 由 hifi 定稿）：mvn 三段（compile/lint/unitTest）**无论成功、失败还是超时**都落一份完整原始输出到 `%TEMP%\ctds-gate-<阶段>-out.log`，文件开头加一段机器可核摘要（`stage / command / exitCode / elapsed / time`）——"0 字节日志"类问题从此不可能再出现（成功也有自证记录）；
2. **② 副本跟随真源自动校验**：把前端守卫升级为**真读后端源文件**（`ContractErrorCodes.java`）逐条比对 8 对文案——后端改了、前端没跟 → 门禁前端测试红灯；另保留"页面不得散写文案"的既有反向探针（断言只增不减）；
3. **③ 失败/超时取证落盘**：npm 段（4 个检查）与 metric 段（覆盖/变异/安全扫描）失败或超时时，**完整原始输出落盘** `%TEMP%\ctds-gate-<阶段>-out.log`（同一命名惯例），报告失败行尾部附"完整输出位置"——以后红灯必有证据，不再"错误正文未取得"。

**用户可见影响 = 零**：界面渲染、交互流程、接口、错误提示、数据库一律不变；门禁判定阈值、阶段范围、扫描面一律不变（**只增加记录，不放宽任何判定**）。对团队工作方式的影响 = 以后门禁红灯必有可查证的完整证据。
