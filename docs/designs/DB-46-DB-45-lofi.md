### 1.2 处置方向（对产品与用户 = 零影响）

1. **A1（DB-46）= 修测试不松断言**：把"窗口内去重"类断言从 1s 窗口移到**生产默认窗口**（60s/600s）下执行——断言的业务含义（"窗口内不重复执行"）一字不减，只是不再把"机器忙"误判为"产品坏"；"过期重执行"语义由独立测试类持 1s 配置验证（sleep 写法稳健：只会多等、不会少等）。**Q2 备选** = 确定性时钟注入（产品侧 `InMemoryIdempotencyStore` 注入 `Clock`，默认行为等价）——彻底去时间假设，但触碰 common 产品代码；
2. **A2（⑨）= 窗口核对留痕**：修复后用"竞争负载复跑"证明稳定性（连跑 N 次 + 全量门禁复跑），并把"该用例通过不再依赖时间假设"的核对结论写进任务卡；
3. **A3（⑩）= 最终一致断言**：给审计计数断言加**有界等待**（截止期轮询，超时即失败——不等同于放宽：等不到照样红）；对同类计数断言（拒绝事件 / 放行对账）同款处理；
4. **A4（DB-45）= 窄特征兜底清理**：超时分支在 `taskkill /T /F` 之后追加"按构建产物特征认出脱缰孙进程"的兜底（surefire 分支 JVM 命令行含模块 `target\surefire` 路径），**排除自身与祖先进程**，best-effort（清理失败不影响段判定——沿"记录是加菜，不是判定"原则）；机器护栏 = selftest 新场景（红相：放一个带特征命令行的幸存 stub → 断言被清；绿相：无关进程不误伤）；
5. **B/C 组 = 移交卡 2b**（Q1-B）：18 项评审承接项的清单与出处完整移交（任务卡 §六），待编排师排期后另立卡清算——本卡（2a）不夹带。

**用户可见影响 = 零**：界面、接口、错误提示、数据库一律不变；门禁判定阈值、阶段范围、扫描面、退出码语义一律不变（**只修可信性与补记录，不放宽任何判定、不放松任何断言**）。对团队的影响 = 门禁重新值得信：绿灯就是绿灯。

## 2. 不做什么（范围边界）

1. **不放宽任何测试**：DB-46/⑩ 是"脆性断言改稳健断言"，断言的业务语义（去重窗口内不重复执行 / 放行≡计量 1:1 / 事件不含令牌与数据本体）一字不删——发现"修复必须以放松断言为代价"处 → 停止上报（红线 4）；
2. **不改任何判定**：阈值 / 阶段启停 / 扫描面 / 报告五态 / 退出码语义零改动；DB-45 清理失败**不改变**超时段的 FAIL 结论；
3. **不动业务代码与产品行为**：A 组默认路线纯测试侧；若 Q2 采 B（时钟注入）也仅触及 common 测试基建与 store 构造签名（默认 `systemUTC` 行为等价，契约测试同跑）；
4. **不做"顺手优化"**：B2（内联收敛）限"收敛重复、零行为变更"，不借机重构运行器其他结构；报告格式、行文口径除登记项外不动；
5. **不夹带**（均按各自归属）：**B/C 两组 18 项评审承接 → 卡 2b**（Q1-B）；DB-40（4.2.1 清理前守卫）/ DB-50~52 / DB-35 余项（运维确认）/ 其他债务行 / 前端与业务线任何事项；
6. **B3（WBS-2.2.x 引用）不代选**：归编排师裁定（Q4），裁定后按选定口径执行；
7. 不新增门禁阶段、不改 CI 触发模型、不引入新依赖（selftest 探针全用既有 stub/PATH 前插手法）；
8. 造数/清理脚本**严禁对演示库执行**（沿承纪律，本卡不触碰）。
