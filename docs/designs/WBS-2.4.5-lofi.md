## 低保真内容（结构草图）

### 场景判定（决定依赖选型，结论先行）

按 PO 给定判断原则核对制度依据：本组件在架构中的位置是"**网关统一校验、服务内部只认网关注入的上下文头**"（ADR-005 §3 第 4 项），WBS 产出定义只列"RBAC 接口、**Token 校验**"——**本组件只需要校验 JWT，不需要签发 JWT（资源服务器场景）**。

→ 按原则判定：**选 Spring Security Resource Server**（`spring-boot-starter-oauth2-resource-server`）。理由（业务语言）：
1. Spring 官方自带、与本项目 Spring Boot 3.5 同生态（ADR-001 冻结栈），版本由框架统一管理，无需单独锁版；
2. 校验规则最全（签名、有效期、签发方、时钟偏移都有现成成熟实现），不自己拼装校验逻辑；
3. 放弃 jjwt 的原因：jjwt 的强项在"生成令牌"，本组件不生成；只用它做校验反而要自己拼全部校验规则。
4. 前向兼容：若未来平台登录功能需要"签发"令牌，届时按同一原则对签发方另选依赖（如 jjwt），两者可共存于不同模块，本判定不作废。

依赖核验与登记：PO 已授权按上述原则自主选定、免审批；仍将履行 ① Maven Central 官方注册表核验真实存在 → ② 登记 `docs/dependencies.md`（审批栏注明"PO 预授权：按判定原则自主选定，2026-09-07"）。

### 做什么（逐条对应产出定义）

1. 新建公共组件 `common/auth`（模块名=目录=artifactId=`common-auth`，与 errorcode/pagination/logging 平级）；依赖 `common-errorcode`（拒绝时用统一错误码）、`common-logging`（拒绝/失败联动审计事件，可开关）；
2. **服务侧·身份上下文**：网关校验令牌后，把"当前用户/主体、所属角色"等写入标准请求头转发；本组件提供统一读取入口——业务代码一行取用"当前用户是谁"，请求结束自动清理上下文（防线程池串号，模式同 2.4.4 的 LogContextCleanupFilter，且不受组件开关约束）；
3. **服务侧·RBAC 判断接口**：统一的"这个用户能不能做这件事"判断——支持方法注解（在方法上标注"需要某角色/权限"）与代码内调用两种写法；不通过时按统一错误码拒绝，对外文案不暴露内部实现；
4. **网关侧·令牌校验**：可复用的 JWT 校验配置（验签名、有效期、签发方），校验通过→把身份与角色注入上下文头；校验失败→统一"未认证"错误；
5. example-service 端到端接入：现有问候服务加一条演示性权限规则，演示"合法身份放行 + 权限不足拒绝 + 未认证拒绝"三种结果。

### 不做什么（V1.0 边界，防蔓延）

- **不做令牌签发/登录**：本组件只校验（场景判定如上）；平台账号登录与令牌签发属后续业务包（观察项见规格缺口声明），届时按 PO 判定原则另行选型，另开任务卡；
- 不做用户/角色/权限的库表存储与角色管理界面（属 3.9.2"RBAC 与三员分立"业务侧；本组件提供判断框架，映射数据来源见待确认问题 2）；
- 不做 SM2 签名校验增强的实现（ADR-005 标注"可选增强"，本组件预留校验器扩展点，V1.0 不实现）；
- 不做 OAuth2 授权服务器、第三方登录、单点登录对接；
- 不做会话/Session 管理（JWT 无状态基线，ADR-005）。

### 结构组成（common/auth 内）

- `AuthContext`：身份上下文读取入口（当前用户/角色清单，读网关注入头）+ 请求结束清理过滤器；
- RBAC 判断：权限注解 + 判断器 + "角色→权限"映射解析器（来源可插拔：V1.0 先配置文件，3.9.2 后接库表）；
- 网关侧 JWT 校验自动装配（基于 Spring Security Resource Server；校验密钥/公钥来源配置化）；
- 自动装配注册 + 配置项（组件开关、上下文头命名、映射来源、审计联动开关）；
- 新依赖：spring-boot-starter-oauth2-resource-server（版本由 Spring Boot 3.5 BOM 管理）。

### 主要流程（3–5 步）

1. 用户请求携带令牌到达网关；
2. 网关用本组件校验令牌（签名/有效期/签发方）——失败返回统一"未认证"错误（可联动审计 FAILURE）；
3. 校验通过，网关把"用户/主体 + 角色"写入标准上下文头，转发内部服务；
4. 内部服务用 AuthContext 取当前用户，RBAC 接口按注解/调用判断——无权限返回统一错误码（可联动审计 DENIED）；
5. 请求结束，上下文自动清理，防线程池串号。
6. 演示：对 example-service 分别发起"带头合法 / 带头无权 / 不带头"三类请求，分别看到放行、无权限拒绝、未认证拒绝三种结果。

### 待确认问题（需要你裁决）

1. 【依赖判定留痕】按你给定的判断原则，本组件属"只校验"场景 → **Spring Security Resource Server**。你已授权免审批，此条仅作留痕确认：**是否认可该判定**？（备选 jjwt 仅在需要"签发+校验"时适用，本组件不签发，故不选。）
2. 【角色权限映射来源】服务侧判断"某角色能否做某事"需要一张"角色→权限"对照关系。两个业务模式：
   - **模式 A（推荐）**：请求头带来"角色"，服务按对照表判断；V1.0 对照表用配置文件维护，3.9.2 上线后无缝切换为库表来源——结构清晰，为三员分立预留；
   - **模式 B**：请求头直接带来"权限清单"，服务只对照清单——最简单，但权限一多请求头膨胀，且授权逻辑被迫前移到网关侧。
3. 【拒绝表现口径】未携带/无效/过期令牌 = "未认证"（HTTP 401）；身份有效但权限不足 = "无权限"（HTTP 403）。组件默认给标准对外文案（不暴露内部实现）。**是否同意此口径**？
4. 【审计联动】令牌校验失败（FAILURE）与 RBAC 拒绝（DENIED）默认自动记审计事件（复用 2.4.4 AuditRecorder，可配置关闭）。**是否同意默认开启**？
5. 【演示规则】example-service 演示规则拟为"仅管理员角色可删除问候语，普通角色可查询"。**是否可以**？
