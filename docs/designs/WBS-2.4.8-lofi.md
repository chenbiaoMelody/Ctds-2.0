## 低保真内容（结构草图）

### 场景判定（决定骨架形态，结论先行）

**本模块存在的意义是"标准解耦"**：信通院的互联互通规范、测评要求会随时间演进（风险手册 PR-3：标准演进导致测评返工）。对策 = 所有"跟外部标准打交道"的代码收进 std-adapter 这一个模块，标准变了只改这里，业务服务不动。WBS 强依赖清单明确：DID 互认、互联互通、测评证据三类后续工作包都以上本骨架为地基——**先有门牌号，后有房子**。

**关键事实（诚实声明）**：信通院《互联互通规范》正式文本未入库，本仓库现有文档只给出能力域级别的需求（目录互挂、身份互认、产品互挂、智能体互认），不含协议字段、报文格式、接口路径级别的规定。因此本任务严格做"骨架 + 占位"：
- **做**：Maven 模块、能力域包结构、每域一个"能力探活"接口与占位实现（状态 = 未开放）、统一"未开放"错误码段、契约固化进新 ADR——让下游任务有一致的落点、让调用方拿到"标准功能尚未开放"的明确信号而不是"找不到这个类"；
- **不做**：不臆造互联互通协议的方法签名（那是 3.1.x/4.x 工作包拿到规范文本后的活，届时按变更流程冻结具体接口）。

### 做什么（逐条对应产出定义"标准适配层骨架 + 互联互通接口占位"）

1. **新建根目录 Maven 模块 `std-adapter/`**（目录=artifactId=`std-adapter`；**纯 jar 库模块，不是独立服务**：无启动类、无端口、不单独部署——与 common 各组件同级，业务服务以依赖方式引入，章程与 ADR-002 均如此定位）；当前 `std-adapter/` 只有一个 `.gitkeep` 占位，本任务将其建成真模块；
2. **三个标准能力域**（对应 WBS §1.7 强依赖清单的下游三块）：
   - `interconnect` **互联互通**：对接国家/区域枢纽（C-9.1 目录互挂、C-9.2 产品互挂的收口位置）；
   - `did` **DID 互认**：跨空间身份互认（政务 CA 3.1.4、跨空间身份互认 3.1.10、智能体互认 C-9.3 的收口位置）；
   - `evidence` **测评证据**：信通院测评证据采集与契约测试的收口位置（章程 G1 门禁："std-adapter 通过互联互通契约测试后申报"）；
3. **互联互通接口占位**：每个能力域一个 Java 接口，只带一个通用方法 `status()`——返回"域状态"记录（域名、实现状态=未实现、说明文案）；各域提供一个占位实现返回"未开放"状态。这是"占位"的最小可用形状：有类型、可注入、可演示，但不含任何臆造的协议细节；
4. **统一错误码段 `1003`**（沿 1001=国密、1002=幂等锁的顺延规划；ADR-005 九位格式）：首码 `1003C0001`"该标准互联功能尚未开放"（C 型 → HTTP 400，默认映射，不暴露内部实现）。本骨架只冻结码值与文案供下游使用，占位实现走"状态=未开放"的返回值形态、不抛错（见待确认 3）；
5. **example-service 演示端点**（沿 2.4.5/2.4.6/2.4.7"每交付可演示"惯例）：`GET /api/v1/std-capabilities` 返回三个标准能力域的状态清单——PO 用浏览器或 curl 即可看到"骨架已建、三个标准域就位、状态均为未开放"；
6. **契约固化**：新建 `ADR-008-标准适配层契约`（沿 ADR-006 国密 / ADR-007 幂等锁先例），固化模块边界、三域清单、错误码段、占位规则、"标准演进只改 std-adapter"的收口纪律；
7. **最小测试**：std-adapter 模块内单元测试（占位实现状态断言、错误码值断言）+ example-service 集成测试（演示端点返回三域状态、封套格式符合 ADR-005）。

### 不做什么（V1.0 边界，防蔓延）

- **不实现任何真实互联互通协议逻辑**：规范文本未入库，方法签名、报文格式、枢纽地址配置等一律留待 3.1.x/4.x 对应工作包（届时走变更流程在本模块内冻结具体接口）；
- **不建互联互通契约测试自动化轨道**：章程 G1 门禁"契约测试通过后申报"属 M2 起测评演练内容，本次只预留 evidence 域落点；
- **不做 Spring 自动装配**：骨架无 Bean、无配置项（未来实现包按 2.4.x 惯例自带 AutoConfiguration）；
- **不建独立服务/容器化/网关路由**：部署单元在 WBS 中没有 std 服务，它是被依赖的库；
- **不实现 DID/CA 业务**：3.1.x 的活，本模块只收口"标准协议适配"部分。

### 结构组成（std-adapter 内）

- `com.ctds.std.StdDomainStatus`——域状态记录（域名、实现状态、说明），三域共用；
- `com.ctds.std.StdAdapterErrorCodes`——模块码表（1003 段）；
- `com.ctds.std.interconnect/`——互联互通域：接口 + 占位实现；
- `com.ctds.std.did/`——DID 互认域：接口 + 占位实现；
- `com.ctds.std.evidence/`——测评证据域：接口 + 占位实现；
- 依赖：仅 `common-errorcode`（错误码 + BizException 体系），零新外部依赖。

### 主要流程（本任务是库骨架，流程 = 使用方式）

1. 未来工作包（如 3.1.10 跨空间身份互认）需要对接外部标准时：在对应域内新增正式接口与实现（走该任务卡的规格/设计/ADR 变更），替换或旁路占位实现；
2. 业务服务在能力尚未交付时注入占位实现 → 调用 `status()` 得到"未开放"，自行决定降级提示；若误调用未交付能力 → 抛 `1003C0001`，统一封套"该标准互联功能尚未开放"；
3. 信通院测评/互联互通测试（M2）：所有对外标准接口在 std-adapter 内可见、可审计（单一审计面，沿 ADR-006 国密口径）。

### 待确认问题（需要你裁决；任务 ≤1 天，两级设计一并提交）

1. 【模块形态】std-adapter = **纯 jar 库模块**（不是独立服务：无启动类、无端口、不单独部署，业务服务引入依赖使用），章程"实现收敛 std-adapter"的定位与 ADR-002 目录规划都指这里。**是否认可**？（备选：独立微服务——多一个部署单元与运维面，且 WBS 没有对应服务包，不推荐）
2. 【占位粒度】三个能力域（互联互通 / DID 互认 / 测评证据）各放**一个只含 `status()` 探活方法的接口 + 占位实现**，不臆造协议方法签名。**是否认可**？（备选 B：纯空接口无方法——最保守但没有可演示行为，评审易判"无意义代码"；备选 C：按公开资料拟定协议方法签名——规范文本未入库等于猜测需求，返工风险高，违背"禁止猜测需求"）
3. 【错误码】新模块段 **1003**（九位格式，首码 `1003C0001`"该标准互联功能尚未开放"，C 型默认映射 400）；骨架内冻结码表供下游使用，占位实现本身返回状态、不抛错。**是否认可**？
4. 【演示与验收】example-service 增加只读端点 `GET /api/v1/std-capabilities`，浏览器直接可见三个标准域"未开放"状态。**是否认可**？（备选：无演示端点，验收只看编译+测试绿灯——不推荐，违背"人可验证"原则）
5. 【契约固化】新建 **ADR-008-标准适配层契约**（沿 2.4.6/2.4.7 先例）：固化模块边界、三域清单、1003 错误码段、占位替换规则、标准演进收口纪律。**是否认可**？

### 规格缺口声明

1. **信通院互联互通规范正式文本未入库**：本骨架的域接口方法签名只到"探活"粒度；各域具体协议接口（报文、路径、字段）由后续工作包（3.1.4 政务 CA、3.1.10 跨空间身份互认、4.x 枢纽对接与测评演练）取得规范文本后按变更流程冻结。域划分届时如与规范冲突 → 走 ADR-008 变更（属预期演进，非本次返工）；
2. 互联互通契约测试（章程 G1 自动轨）为 M2 内容，evidence 域本次仅预留落点，观察项不阻塞；
3. 制度依据缺口：无——基建任务以 WBS 2.4.8 产出定义 + 章程 4.3 + WBS §1.7 + ADR-002/005 为依据。
