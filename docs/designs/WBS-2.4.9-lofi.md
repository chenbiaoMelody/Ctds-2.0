## 低保真内容（结构草图）

### 场景判定（决定骨架形态，结论先行）

**本任务是全平台第一块前端工程**（`frontend/` 当前仅 .gitkeep）。它的意义不是"做一个页面"，而是把**未来 10+ 业务前端页面的地基一次打好**：所有页面共用同一套布局、同一套路由规则、同一套权限菜单机制、同一套组件风格与主题色。后续所有业务工作包（门户 C-7.x、系统管理 3.9.x 等）都在这块地基上盖楼，地基错了返工面是全平台。

**关键事实（诚实声明）**：
1. **平台账号登录/令牌签发尚未有归属工作包**（2.4.5 观察项已登记：令牌"谁来发"待 3.9.1 澄清；2.4.12 E2E 才含"登录冒烟示例"）。因此本任务**不做真实登录链路**，权限菜单以"骨架机制 + 演示占位"落地——**不臆造后端登录接口**；
2. **后端已有真实可对接的演示端点**：example-service `GET /api/v1/std-capabilities`（WBS 2.4.8 已合并），前端示例页可真实调用它，形成"前端→后端"首个端到端演示（Vite dev proxy 转发 8080，无需真实网关）；
3. **现有门禁不覆盖前端**（run-gates.ps1 仅 Maven 三阶段）。按章程红线 3"不擅自修改 CI 门禁配置"，本任务**不改门禁脚本**，前端验证以本地命令 + 交付说明附结果为闭环，门禁扩展另走变更流程（待确认问题 5）。

### 做什么（逐条对应产出定义"布局/路由/权限菜单/组件库/主题 + 示例页"）

1. **前端工程落位 `frontend/`**（ADR-002）：Vite + Vue 3 + TypeScript 标准工程（`npm create vite` vue-ts 模板起步，最主流、AI 语料最全），入口 `frontend/package.json`；不进 Maven、不进根 pom（前后端构建分离，沿 ADR-002 目录规划）；
2. **布局**：经典管理后台三区布局（左侧菜单栏 + 顶部栏 + 主内容区），Element Plus 布局组件实现——**一套布局骨架，全平台页面共用**；登录态区域留占位（骨架期显示"演示模式"标识）；
3. **路由**：Vue Router 4，路由表集中管理；含路由守卫骨架（未登录/无权限跳转逻辑的占位实现，真实令牌校验待登录工作包接入）；
4. **权限菜单**：菜单由路由表驱动（添加业务页 = 注册一条路由 + 声明菜单属性，菜单自动出现）；**菜单显隐与路由访问控制预留"权限点"机制**（骨架期用静态演示权限点演示"有权限可见/无权限隐藏"，真实授权数据源待 3.9.x 接入，不臆造后端接口）；
5. **组件库**：Element Plus（ADR-001 冻结）全量引入，图标包一并纳入；
6. **主题**：主题色统一配置（Element Plus CSS 变量覆盖），全站一套品牌色，后续换肤只改一处；
7. **示例页**（两块，均属产出定义"示例页"范围）：
   - **工作台示例页**：展示布局/菜单/组件库/主题的静态综合示例（统计卡片、表格、表单各一，全部用 Element Plus 组件）；
   - **标准能力示例页**：真实调用 2.4.8 演示端点，表格展示三个标准域（互联互通/跨空间身份互认/测评证据）的"未开放"状态——前后端首次端到端演示；
8. **工程化最小配套**：`npm run dev`（开发）/ `build`（构建校验）/ `test`（单元测试，Vitest）/ `lint`（ESLint）四命令可跑；`.gitignore` 已含 node_modules/dist；
9. **最小测试**：路由表结构断言（每个路由必含标题/菜单属性）、权限守卫行为单测（放行/拒绝两分支）、示例页组件渲染冒烟（Vitest + Vue Test Utils）。

### 不做什么（V1.0 边界，防蔓延）

- **不做真实登录/令牌签发**：归属工作包未定（观察项待 3.9.1），本任务只做路由守卫占位与演示模式入口；2.4.12 E2E 的"登录冒烟"是它自己的产出，不提前实现；
- **不建后端网关/鉴权联调**：Vite dev proxy 只转发 example-service 演示端点，不做网关/认证代理；
- **不做状态管理库（Pinia/Vuex）**：骨架期页面间无共享状态需求，引入即规格外依赖；有需要时由后续工作包按变更流程引入；
- **不接入任何后端业务接口**（除 2.4.8 演示端点外）：业务接口属 3.x 工作包，骨架不猜接口形状；
- **不做国际化/暗色主题/多端适配**：规格外能力，观察项登记；
- **不改门禁脚本/CI 配置**：红线 3，前端门禁扩展走变更流程（见待确认问题 5）；
- **不引入 UI 组件库替代品**（Ant Design 等）：ADR-001 冻结 Element Plus。

### 结构组成（frontend/ 内）

- `package.json` + `vite.config.ts`（含 dev proxy → 8080）+ `tsconfig*.json` + 工程入口（`index.html`/`src/main.ts`/`src/App.vue`）；
- `src/router/`：路由表（集中声明，含菜单属性）+ 守卫；
- `src/layouts/`：三区布局骨架（侧边栏菜单/顶栏/内容区）；
- `src/views/`：工作台示例页、标准能力示例页（对接 2.4.8）；
- `src/styles/`：主题变量（品牌色一处配置）；
- 新依赖（npm，待确认 1 授权后核验登记）：`vue` / `vue-router` / `element-plus` / `@element-plus/icons-vue` / `vite` / `typescript` / `vitest` / `@vue/test-utils` / `eslint` 系列——全部属 ADR-001 冻结技术栈配套。

### 主要流程（3–5 步，业务语言）

1. 开发者在 `frontend/` 下执行 `npm install`（一次性）与 `npm run dev`，浏览器打开开发地址，看到三区布局 + 左侧菜单（工作台/标准能力）；
2. 点左侧菜单切换页面：工作台展示组件库综合示例，标准能力页展示三个标准域"尚未开放"状态（数据来自 example-service 真实接口）；
3. 菜单中有一条"仅演示管理员可见"的示例项——骨架期用它演示权限机制：切换演示角色后该菜单出现/消失（权限点占位生效）；
4. 以后新增业务页面：在路由表加一条带菜单属性的路由，菜单自动生成、布局自动套用——业务工作包无需再搭框架；
5. 交付验证：`npm run lint` / `test` / `build` 三绿 + 浏览器截图，门禁与 Maven 侧互不影响。
