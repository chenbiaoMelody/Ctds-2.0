## 低保真内容（方向草图）

### 复用与依赖判定（结论先行）

按"先查 common、找到即复用"核对，本任务**不引入任何新框架/中间件/依赖**（ADR-001 冻结栈内完成）：

| 能力 | 复用来源 | 说明 |
| --- | --- | --- |
| 加解密算法 | `common-crypto`（ADR-006） | KMS 只做密钥的生成/存储/供给，**不做任何算法实现**；密钥库加密用本组件 SM4 信封 |
| 错误码 | `common-errorcode` | KMS 服务申请模块位 `02`（1002 段，沿 ADR-006 §3.5 顺延制度，ADR-015 留痕） |
| 统一响应 | `common-api`（ApiResult） | `{code,message,traceId,data}`，code 字符串 |
| 鉴权 | `common-auth`（AccessControl） | 轮换/创建接口权限断言 `kms:admin`，未认证/无权限拒绝并留 DENIED 审计 |
| 数据库 | MySQL 8 + Flyway（ADR-009） | 新服务 `services/kms` 同构 example-service 工程结构 |
| 门禁 | `scripts/gates` secretsScan | 禁硬编码检查 = 既有扫描**增强规则**，不建第二套 |

### 做什么（逐条对应规格三大行为）

1. **新建密钥管理服务 `services/kms`**（包名 `com.ctds.kms`，分层 interfaces→application→domain→infrastructure）：
   - 密钥按"编号 + 版本"管理；创建密钥 = 生成 16 字节随机 SM4 密钥材料（安全随机数，属密钥管理动作而非算法实现）作为版本 1；
   - 密钥材料**加密落库**：以部署环境注入的根密钥（环境变量 `CTDS_KMS_ROOT_KEY`，Base64 16 字节；缺失/坏值 = 启动失败 fail-fast）经 common-crypto SM4 信封加密后存 MySQL——库中无明文密钥；
   - 轮换 = 新增版本（版本号 +1）+ 审计留痕（操作者/时间/编号/新旧版本）；旧版本保留供解密；
   - 对内提供密钥供给接口（按编号取当前版本、按编号+版本取历史版本）与密钥管理接口（创建/轮换/查询元数据）。
2. **`common-crypto` 新增 `KmsKeyProvider`**（覆盖 KeyProvider Bean 接入，业务零改动，ADR-006 §5.1）：
   - 通过 JDK 内置 HTTP 客户端调用 KMS 服务（零新依赖）；KMS 不可达/查询无果一律收敛 `1001S0001`（密钥服务暂不可用），**不静默降级**；
   - 配置 `ctds.crypto.kms.base-url` 存在即启用并覆盖本地文件实现；未配置沿用 `LocalFileKeyProvider`（既有行为零变化）。
3. **信封格式 v2（密钥轮换载体，兑现 ADR-006 版本位预留）**：新密文带密钥版本号，解密按密文归属版本取对应历史密钥——轮换后旧密文不失效；本地文件实现（无版本概念）继续产出 v1 信封，行为不变；
4. **禁硬编码检查增强**：secretsScan 门禁在既有 7 条正则上补国密密钥材料样式（根密钥/主密钥/数据密钥等命名旁的 Base64 赋值、根密钥字面量），红灯即拒；随本任务分支留痕提交。

### 不做什么（规格非目标，防蔓延）

- 自动定时轮换（手动触发；建议登记后续）；SM2 身份密钥（归 3.1.8）；TLS/HTTPS 传输加密（G-01）；云/商业 KMS 对接；算法与信封 v1 格式变更；多区域同步。

### 主要流程（业务语言）

1. **加密**：业务服务调用统一加解密入口 → 组件向 KMS 取"该编号当前版本"密钥 → 用带版本号的新信封加密落库（KMS 不可用 → 明确报错"密钥服务暂不可用"，绝不降级）；
2. **解密**：读信封版本号 → v2 按版本向 KMS 取历史密钥 → 解密（密文被篡改/错版本 → 拒绝）；
3. **轮换**：授权管理员调轮换接口 → KMS 生成新版本密钥材料加密落库、写审计 → 此后新数据用新版本，旧密文按旧版本照常解密；
4. **门禁**：提交时 secretsScan 增强规则扫描全库，命中硬编码密钥 → 红灯禁止合入。

### 业务需知悉的两个诚实边界（非打回项，知悉即可）

1. **组件到 KMS 之间密钥材料经内网明文传输**（HTTP）——传输加密属 G-01 缺口，本任务不解决、不虚报；演进方向（信封加密模式：密钥不出 KMS）登记为改进建议；
2. **本地密钥时期的存量 v1 信封与轮换互斥**：v1 信封不带版本号，轮换后无法定位历史密钥——运维口径：需要轮换的密钥先完成存量数据重加密（写入交付注意事项）。
