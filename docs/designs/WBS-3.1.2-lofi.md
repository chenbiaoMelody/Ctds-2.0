## 低保真内容（方向草图）

### 场景判定（结论先行）

1. **服务落位**：新建业务服务 `services/subject-service`（主体服务，模块名=目录=artifactId），承载 C-1.1 的库表与注册/状态流转/查询能力。**3.1.3（实名认证集成）、3.1.4（政务 CA 适配）、3.1.5（审核后台）都在同一服务内扩展**——它们操作同一份主体档案与状态机，拆成多个服务只会引入跨服务一致性负担，属过度设计。结构沿 kms 先例四层：`interfaces → application → domain → infrastructure`（Controller 不得直连数据层，ArchUnit 分层守卫测试随包交付）。
2. **复用判定（全部复用既有 common 组件，不新造平行能力）**：

| 能力 | 复用来源 | 用途 |
| --- | --- | --- |
| 防重复提交（幂等，模式 B 结果复用） | common-idempotency（ADR-007） | 注册接口 `@Idempotent(key=信用代码)`——重复请求返回首次结果，对应规格行为 1 第 3 条 |
| L4 字段加密存储唯一入口 | common-crypto `Sm4Service`（ADR-006） | 本包表暂无 L4 字段；介质取舍结论（见待确认问题 2）供 3.1.3 证照影像表执行 |
| 统一响应与错误码 | common-errorcode（ADR-005） | 主体服务新占错误码段 **1004**（1001 国密/1002 幂等锁+KMS/1003 std-adapter 已占用；占用以 ADR-016 留痕，沿 ADR-015 惯例） |
| 鉴权 RBAC | common-auth `@RequirePermission` + 配置式角色映射（2.4.5） | 注册/查询/撤销端点的权限断言（行为 5 第 3 条的权限机制同源，审核端点本身随 3.1.5） |
| 审计留痕 | common-logging `AuditRecorder`（2.4.4） | 注册/撤销/越权访问留痕 |
| 数据库迁移 | Flyway（ADR-009） | 主体库 `ctds_subject` 建表脚本 |
| 分页 | common-pagination | （预留）主体清单查询，本包仅进度查询按申请编号点查，清单接口随 3.1.5 |

3. **数据库**：MySQL 8（ADR-001 冻结栈），独立库 `ctds_subject`，Flyway `V1__` 建表。**本包只建主体与流转留痕两类表**：证照影像/OCR 结果表归 3.1.3（其表结构依赖 OCR 集成设计），政务 CA 材料表归 3.1.4——本包确认它们的 L4 存储介质口径即可（待确认问题 2），不提前建表。

### 做什么（逐条对应规格行为）

1. **主体表 + 状态流转记录表**（Flyway V1）：主体表存注册信息（主体名称、统一社会信用代码、主体类型、注册地址、联系人及联系方式、管理员账号）与当前状态；流转记录表存每次状态流转的前状态、后状态、触发方（申请人/系统/审核员）、时间、备注四要素以上（对应规格行为 4 第 2 条）。
2. **注册服务**（对应规格行为 1）：提交注册 → 必填与格式校验（逐字段提示，不产生半成品档案）→ 统一社会信用代码全平台唯一校验（重复提示"该主体已注册"，不泄露已有账号信息）→ 注册成功主体进入**待认证**，返回**申请编号**（后续认证、审核、查询统一以此编号跟踪）。
3. **状态机与流转留痕**（对应规格行为 4）：状态枚举锁定规格 V1.0 最小集——待认证/待审核/已入驻/认证失败/已驳回，**不私自增删**；流转动作统一经"状态流转服务"执行并强制落留痕（前状态、后状态、触发方、时间、备注）；本包交付流转服务能力，**触发端**分别随后续包交付（OCR+核验通过的自动流转随 3.1.3、审核通过/驳回随 3.1.5），本包只实际启用"注册→待认证"这一条。
4. **撤销重报**（对应规格行为 1 第 5 条的 V1.0 口径）：认证通过前关键信息不可变更；确需修改 = 撤销当前申请后重新注册。撤销的语义取舍见**待确认问题 3**（规格未定义撤销后状态，属规格缺口，本设计给方案不私自定）。
5. **注册进度查询**（支撑申请人跟踪与验收剧本 S1/S2）：按申请编号查询单个主体的注册信息（联系方式等敏感字段脱敏展示）与当前状态、流转记录。
6. **错误码段 1004**：主体服务错误码表（C/B/S 三型，对外文案为服务端常量），占用以 **ADR-016 主体服务契约**留痕（沿 ADR-015 KMS 先例）。
7. **测试**：单测 + 集成测试（Testcontainers-MySQL，沿 kms 先例）覆盖规格行为 1/4 的全部 Given/When/Then；ArchUnit 分层守卫；注册幂等与并发唯一性用例（同信用代码并发提交只产生一份申请）。

### 不做什么（防蔓延，边界与规格非目标对齐）

- **不做** OCR/法人核验/政务 CA 的一切对接（行为 2/3/6 归 3.1.3/3.1.4）；**不做**审核端点与审核工作台（行为 5 归 3.1.5）；**不做** DID 签发衔接（非目标 1，归 3.1.7）；**不做**主体冻结/注销/退出（规格非目标 7，WBS 产出定义中"注销服务"字样按规格口径收敛——见待确认问题 4）；**不做**真实第三方认证渠道（非目标 6）；**不做**传输加密 TLS（非目标 8，G-01 独立裁决）。
- **不做**主体管理员账号的开通/登录（注册信息中的管理员账号 V1.0 仅作为信息收集存储，账号体系归后续身份相关工作包）。
- **不新建**证照影像/OCR 结果/政务 CA 材料的库表（随 3.1.3/3.1.4 建表）。

### 主要流程（业务语言）

**注册流程**：申请人提交注册信息 → 逐字段校验（不合法即逐字段提示，终止）→ 幂等拦截（同信用代码重复请求直接返回首次结果）→ 唯一性校验（该信用代码已存在有效主体 → 提示"该主体已注册"）→ 建档：主体记录（状态=待认证）+ 流转留痕（无→待认证，触发方=申请人）→ 返回申请编号。

**进度查询流程**：申请人/审核员按申请编号查询 → 返回注册信息（敏感字段脱敏）+ 当前状态 + 流转记录列表。

**撤销流程**：申请人对待认证主体发起撤销 → 校验当前状态允许撤销 → 按待确认问题 3 的裁决口径处置 → 留痕 → 申请人可重新注册。

### 待确认问题（需要你裁决）

1. **【注册页面归属】**规格 §6.3 写"注册页面（申请人侧）界面原型归 3.1.2/3.1.3 设计交付"，WBS 3.1.2/3.1.3 均为纯后端包、无界面产出定义。**建议：注册页面静态原型随 3.1.3 的 lofi 一并提交**（页面核心交互是认证流程——上传证照、OCR 回填、核验发起，与 3.1.3 设计天然一体；本包先交付后端接口契约供页面设计对齐）。是否认可？（备选：本包先出页面原型——但页面一半交互依赖 3.1.3 未设计的能力，会返工）
2. **【证照影像存储介质取舍】**（规格 §5 登记的缺口，随本包确认）：**建议 A：SM4 加密后落库（MySQL LONGBLOB 密文列）**——零新增基建、复用 common-crypto 唯一入口、备份恢复随库走（G-02 缺口后续统一处理时介质单一）；备选 B：本地加密卷（文件系统 + 加密目录）——库外大文件不拖累库备份，但新增部署面、演示期多此一举。演示期影像量小（每个主体 1~2 张），**采 A**。
3. **【撤销后状态语义】**规格状态机 V1.0 最小集未含"已撤销"态，且行为 4 约定实施包不得私自增删状态；而行为 1 第 5 条要求"撤销当前申请重新注册"。**建议 A：撤销 = 主体记录复用、状态重置为"待认证"**——即"撤销重报"在系统里表现为：原申请清空待认证状态下的可变信息（名称/地址/联系人等），申请人重新提交即更新同一主体记录，全程以流转留痕记录"待认证→待认证（申请人撤销重报）"的口径变化，不新增状态、信用代码占用关系不变；备选 B：走规格变更流程为状态机增补"已撤销"终态 + 重报新建记录。A 改动最小且不触碰"不得私自增删状态"红线，**采 A**。
4. **【WBS"注册/变更/注销服务"口径收敛】**WBS 3.1.2 产出定义含"变更/注销服务"，但规格明确：变更 = 撤销重报（行为 1 第 5 条）、注销 = 非目标（非目标 7，归运营机制）。**建议：按规格口径执行**——本包交付"注册 + 撤销重报 + 状态流转 + 查询"，"注销"不做并已在规格非目标登记；此为规格对 WBS 措辞的正常收敛（设计只从规格派生），无需规格变更。是否认可？
5. **【参数校验依赖引入】**规格行为 1 要求"格式校验不通过即时提示、逐字段提示"。Java 主流做法是 Spring 官方参数校验组件 `spring-boot-starter-validation`（Jakarta Validation 标准，版本由 Spring Boot 3.5.16 BOM 管理，无需锁版）。该依赖此前无先例，需走登记流程：**建议按 PO 预授权先例（沿 2.4.7 Redisson 口径）由本设计确认即视为审批**，编码会话履行核验（官方注册表实测）→ 登记 `docs/dependencies.md` → 引入。是否认可？（备选：手写校验代码——多造轮子，违背"最主流实现"原则）

### 规格缺口声明

1. 撤销后状态语义缺口：规格未定义，本设计以待确认问题 3 给出方案，**不私自定**——PO 裁决后随高保真定稿。
2. 认证失败态的再流转路径（认证失败→重新发起核验→?）：规格行为 3/4 未明确"认证失败"再次核验通过后的流转目标，属 3.1.3 设计范围，本包状态机只锁定枚举与留痕能力，不提前定义该流转。
3. 错误码段 1004 占用、ADR-016 新建：沿 ADR-015 惯例，随编码固化。
