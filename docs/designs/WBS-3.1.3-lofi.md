## 低保真内容（方向草图）

### 场景判定（结论先行）

1. **服务落位**：沿 ADR-016 影响条款，认证能力在 `services/subject-service` 内扩展（新增 `certification` 包，四层结构不变）；不新建服务。认证渠道接口与模拟渠道实现**收口 `std-adapter` 模块**（规格行为 7 第 1 条 + ADR-008 收口纪律）——subject-service 引入 std-adapter 依赖，业务代码只见 `CertificationStandardApi` 接口不见模拟实现。
2. **std-adapter 新增认证域（须 ADR-008 变更留痕）**：`StdDomain` 增加第四值 `CERTIFICATION("certification","实名认证")` + 标记子接口 `CertificationStandardApi`（本包冻结 OCR 识别与法人核验两个方法；政务 CA 验证方法随 3.1.4 同域扩展）；模拟实现 `MockCertificationChannel`（占位替换规则同 ADR-008 第 4 条：交付真实渠道时替换 Bean 注册，业务零改动）。**新增域 = ADR-008 变更**（其第 2 条明文要求），规格 C-1.1 已裁决收口位置，本变更属"规格派生"而非新需求；本包内完成 ADR-008 补记（沿 ADR-016 补记先例）。
3. **复用判定（全部复用既有组件，不新造平行能力）**：

| 能力 | 复用来源 | 用途 |
| --- | --- | --- |
| L4 加密存储唯一入口 | common-crypto `Sm4Service`（ADR-006） | 证照影像、OCR 原始结果、法人身份证号三项 L4 数据 SM4 加密落库（subject-service **新增 common-crypto 依赖**，密钥经 KeyProvider——运行期接本机 KMS（ADR-015，集群绿态在跑），测试用 LocalFileKeyProvider，密钥文件不入库） |
| 鉴权 RBAC | common-auth `@RequirePermission`（2.4.5） | 认证端点权限断言：`subject.certify`（申请人）；影像查看与档案查询同 `subject.read` |
| 审计留痕 | common-logging `AuditRecorder`（2.4.4） | 影像查看留痕（规格行为 2 验收标准）、越权拒绝留痕（ADR-016 §2.6） |
| 统一响应与错误码 | common-errorcode（ADR-005） | 1004 段扩展认证类错误码（ADR-016 §2.1 补记） |
| 状态流转 | 本服务 `SubjectStatusService.transition()`（ADR-016 §3） | 认证双通过自动流转"待认证→待审核"，触发方=SYSTEM（ADR-016 §2.2 流转触发端分工） |
| 数据库迁移 | Flyway（ADR-009） | `ctds_subject` 库 **V2 迁移**：认证材料表 + 核验记录表 + subject 表加申请人列 |

4. **数据库（V2 迁移，三件事）**：
   - `cert_material`（证照材料表）：一行 = 一张证照影像及其 OCR 结果；影像密文 LONGBLOB（SM4）、OCR 原始结果密文（SM4，规格行为 2 第 5 条"L4 管控"双要素）、申请人确认后的要素明文（组织信息非 L4）；同一主体重复上传 = 替换（保留最近一次）。
   - `cert_verification_log`（核验记录表）：一行 = 一次法人核验；法人姓名、身份证号密文（L4）、渠道标识/流水号/结论/耗时（规格行为 7 第 3 条三要素 + 耗时）、失败原因；**当日失败次数 = 本表按主体+当日+结论=不通过计数**（渠道技术异常不计入，规格行为 7 第 4 条）。
   - `subject` 表加列 `applicant VARCHAR(64)`（申请人身份，注册建档时取 AuthContext 当前身份）+ 存量行回填演示口径（演示库可整库重建，详见待确认问题 4）。
5. **界面（静态原型，本包交付）**：注册与认证页面静态 HTML 原型（`docs/designs/WBS-3.1.3-原型-注册与认证.html`，纯前端演示交互不连后端）覆盖规格行为 1（注册表单）、行为 2（上传→OCR 回填→核对确认→不一致阻断）、行为 3（核验发起→结论展示→重试上限提示）与状态展示；界面说明书（页面清单/字段/交互/脱敏规则）随高保真交付。真实前端页面归属见待确认问题 2。

### 做什么（逐条对应规格行为）

1. **证照上传与 OCR 识别**（行为 2 第 1~2 条）：申请人上传营业执照影像（大小/格式限制随 hifi 定参）→ 经认证渠道 OCR 识别 → 返回识别要素（名称/信用代码/法定代表人/注册地址）回填表单供核对——OCR 是辅助录入，不直接生效。影像密文与 OCR 原始结果密文即时落库（上传即落，确认与否不丢失材料）。
2. **OCR 结果核对确认与差异阻断**（行为 2 第 3~4 条）：申请人确认回填要素时，系统比对**确认提交的信用代码与 OCR 识别值**，不一致 → 阻断并明确提示差异，修正后才能进入核验环节；识别置信度过低/影像不可读（模拟渠道返回"无法识别"）→ 提示重传，不产生部分识别结果。
3. **法人实人核验**（行为 3）：提交法人姓名 + 身份证号发起核验 → 前置校验"与 OCR 识别的营业执照法人信息一致"（不一致阻断，规格行为 3 第 4 条）→ 调认证渠道 → 结论与要素、渠道流水号全程留痕（行为 3 第 2 条）。**不通过可重试，当日 5 次上限、超限当日锁定次日自动恢复**（规格 §7 Q3 已裁决；数值走配置参数随 hifi 定）；**渠道不可用 fail-fast**："认证服务暂不可用，请稍后重试"，不计失败次数、不留半完成状态（行为 3 第 5 条 + 行为 7 第 4 条）。
4. **认证双通过自动流转**（行为 4 第 1 条）：证照确认完成 + 法人核验通过 → 系统自动流转"待认证→待审核"（触发方=SYSTEM，经 `SubjectStatusService.transition()` 强制留痕）——**不自动入驻**。
5. **对象级归属断言（ADR-016 §2.6 裁决落地）**：subject 表加申请人列；查询/撤销（存量端点补齐）与本包新增认证端点一律校验"当前身份 = 申请人或持授权角色"，不匹配 → 403 + 拒绝审计留痕。**"双向用例"随包交付**：本人可操作 + 他人操作被拒（章程 4：使用控制策略双向用例纪律同源）。
6. **模拟认证渠道**（行为 7 + 剧本附录 A）：预置规则与验收剧本严格对应——预置模拟影像 A1 → 返回固定识别要素（蓝天数据科技有限公司）；其余影像 → "无法识别请重传"；身份证号尾号 `8` → 核验不通过；其余 → 通过；技术异常注入开关 → "服务暂不可用"。渠道调用留痕：渠道标识、请求流水号、结论、耗时。
7. **错误码扩展（1004 段，ADR-016 §2.1 补记）**：证照信用代码不一致、法人与证照不一致、当日核验超限、认证材料缺失（未确认证照即发起核验）、认证服务暂不可用（渠道异常转译）等 B/S 型错误码，随 hifi 定稿编码表。
8. **测试**：单测 + 集成测试（Testcontainers-MySQL，沿 3.1.2 先例）覆盖规格行为 2/3/4/7 全部 Given/When/Then；越权双向用例（本人通过/他人 403+审计）；核验重试上限与跨日恢复（时钟注入）；渠道异常 fail-fast 断言（无脏数据残留）；影像密文落库断言（库内查证为密文形态）+ 查看审计断言；ArchUnit 分层守卫延续。

### 不做什么（防蔓延，边界与规格非目标对齐）

- **不做**政务 CA 证书验证（行为 6 归 3.1.4，本包不动政务通道；政府部门主体注册后停留待认证——其认证路径随 3.1.4 打通）；**不做**审核端点与审核工作台（行为 5 归 3.1.5）；**不做**真实第三方认证渠道（非目标 6）；**不做** DID 签发衔接、主体冻结/注销、传输 TLS（非目标 1/7/8）。
- **不做**审核工作台对认证档案的展示接口（3.1.5 复用本包的档案查询能力扩展，本包只保证申请人侧与授权角色可见性口径正确）。
- **不做** OCR 置信度数值体系（模拟渠道只有"可识别/不可识别"两态，置信度过低 = 不可识别口径；真实渠道接入时再定义置信度阈值参数）。

### 主要流程（业务语言）

**认证流程（企业/机构）**：申请人上传营业执照影像 → 渠道 OCR 识别（影像+原始结果即时加密落库）→ 识别成功回填表单 → 申请人核对确认（信用代码不一致 → 阻断修正）→ 确认生效 → 发起法人核验（法人与证照不一致 → 阻断；当日超限 → 拒绝；渠道不可用 → fail-fast 提示重试）→ 渠道返回结论并留痕 → **证照确认+核验通过 → 自动流转"待审核"**。

**越权防护**：任何按申请编号的操作（查询/撤销/上传/确认/核验/影像查看）先断言归属——申请人本人或授权角色之外一律 403 + 拒绝留痕。

### 待确认问题（需要你裁决）

1. **【认证失败态触发口径】**规格状态机含"认证失败"态（行为 4：核验不通过**且申请人主动结束或超限**），但"超限"与行为 3"超限当日锁定、**次日自动恢复**"存在张力：若超限即转"认证失败"终态，次日恢复需要定时任务把状态拨回去（复杂且无规格依据）。**建议 A：超限只做"当日锁定"（计数拒绝），不转态，主体保持"待认证"；"认证失败"态仅由申请人主动"结束认证"触发，且"认证失败 → 重新发起核验 → 通过 → 待审核"路径打通**（规格行为 4 验收标准第 2 条"可修改后重新提交"同源）。备选 B：超限自动转"认证失败"并引入定时次日回拨任务（新增定时基建，V1.0 不建议）。**采 A**。
2. **【注册页面真实前端实现归属】**本包交付静态 HTML 原型 + 界面说明书 + 全部后端认证接口（演示口径 = 沿 3.1.2 先例接口级演示 + 原型走查）；`frontend/` 的 Vue 真实页面（注册表单、上传、核验交互）**建议随 3.1.5（界面包：审核工作台）同批实现**——同一套前端基建一次搭好，避免本包预算内两线作战。是否认可？（备选：本包一并实现 Vue 页面——预算 1 会话偏紧，且审核端未交付时页面半数入口不可用）
3. **【std-adapter 新增认证域的留痕方式】**新增 `CERTIFICATION` 域按 ADR-008 第 2 条属"ADR 变更"。**建议：本包内补记 ADR-008（域清单增第四值 + 认证域协议方法随本包冻结的特别说明），沿 ADR-016 补记先例，随分支提交留痕**，不另开变更会话。是否认可？
4. **【申请人列存量数据回填口径】**V2 迁移给 `subject.applicant` 加列时，存量行（演示数据）无注册时身份可回填。**建议：迁移默认回填 `legacy-demo`（业务可读的迁移占位标识），演示前可整库重建（交接提醒既有口径），新建主体一律取真实注册身份**；3.1.2 已合并代码的注册建档逻辑随本包补一行取 AuthContext 写入。是否认可？
5. **【影像上传限制参数】**规格行为 2 第 1 条"大小/格式限制随设计细化"。**建议：单张 ≤ 5MB；格式 jpg/jpeg/png；同一主体重复上传替换保留最近一次**（演示期影像量小，SM4 加密落库 LONGBLOB 容量充裕；数值走配置参数可调）。是否认可？

### 规格缺口声明

1. 认证失败态再流转路径（"认证失败→重新发起→?"）：规格未明确，本设计以待确认问题 1 给方案，**不私自定**——PO 裁决后随高保真定稿。
