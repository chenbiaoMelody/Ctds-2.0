## 低保真内容（方向草图）

### 场景判定（结论先行）

1. **服务落位**：审核端点扩展在 `services/subject-service`（`ReviewController` 新增 + `CertificationService`/应用层审核方法）；状态流转一律经既有 `SubjectStatusService.transition()`（ADR-016 §3 约束：不新建平行流转通道）；不新建服务、不新建状态、不新建错误码段。
2. **复用判定（零新外部依赖）**：

| 能力 | 复用来源 | 用途 |
| --- | --- | --- |
| 待审核清单分页 | common-pagination `PageQuery`/`PageResult` | 清单端点分页返回（横切能力复用纪律） |
| 档案查询 | 既有 `GET /registrations/{subjectNo}/certification`（`subject.read` + reviewer 归属豁免已通） | 审核详情页档案数据源（3.1.3 lofi 预留口径） |
| 状态流转 | `SubjectStatusService.transition()` + `TriggerRole.REVIEWER` | 通过/驳回流转 + 四要素留痕（乐观状态门槛兜并发） |
| 权限 | `@RequirePermission("subject.review")`（reviewer 角色映射已在 application.yml） | 审核清单/操作端点功能级鉴权 |
| 审计 | `AuditRecorder` + 动作常量 | 审核结论、越权拒绝留痕 |
| 前端基建 | 既有 `frontend/` 骨架（MainLayout/路由驱动菜单/演示登录/权限守卫/fetch 封装） | Vue 真实页面挂载点（2.4.9/2.4.12 交付） |

3. **数据库（零迁移）**：审核结论留痕复用 `subject_status_log`（transition 四要素：前后状态/触发方=审核员/时间/备注=驳回理由或"审核通过"）；审核人=操作者身份已随留痕 `operator` 列落库，不新增表不加列。

### 做什么（逐条对应规格行为）

1. **待审核清单（行为 5 第 1 条前半）**：新增审核清单端点——按状态 `PENDING_REVIEW` 过滤、分页返回（申请编号/主体名称/主体类型/申请时间）；`@RequirePermission("subject.review")`。
2. **认证档案查看（行为 5 第 1 条后半）**：审核员经既有档案查询端点查看注册信息、证照影像、OCR 结果、核验记录、政务证书验证流水；**证照影像放大查看**复用既有影像查看端点（前端放大呈现）；政务主体不显示法人核验段（3.1.4 档案政务段口径已交付）。
3. **审核二选一（行为 5 第 2 条）**：通过端点（`PENDING_REVIEW→ADMITTED`，留痕"审核通过"）/ 驳回端点（`PENDING_REVIEW→REJECTED`，**驳回理由必填**，理由随留痕备注落库）；非待审核状态调用 → 既有 1004C0002 门槛拒绝（乐观门槛保证并发双审核只有一人成功，并发负向用例随测试交付）。
4. **权限与拒绝留痕（行为 5 第 3~4 条）**：审核操作仅 `subject.review` 授权角色可执行（功能级 403 拦截在前）；拒绝审计留痕复用既有口径；审核结论+操作者+时间随流转留痕闭环。
5. **3.1.4 登记观察项随包处置**：①文件名控制字符归一化（随上传口径一并，编码前先落地）；②并发 TOCTOU 用例（双审核员并发审核同一主体，乐观门槛单胜出，负向用例固化）；③政务写放大监控评估（登记升级至 2.5.x 监控基座任务，本包不实现——最小实现原则）；④requireCertFile/requireImage 参数化评估（审核端点若复用该类工具则随包参数化，评估结论随 hifi 定）。
6. **真实 Vue 页面（3.1.3 lofi Q2 裁决随本包）**：①**审核工作台**（清单页 + 详情档案 + 通过/驳回操作，静态原型线框见原型文件）；②**申请人侧注册与认证页**（注册表单企业/政务分支、证照上传、OCR 确认、法人核验交互、政务 CA 证书提交——3.1.2/3.1.3/3.1.4 静态原型的 Vue 化）；③路由/菜单接入（"主体审核"菜单项按 `subject.review` 权限点显隐）。
7. **测试**：后端单测+集成（Testcontainers-MySQL）覆盖行为 5 全部 Given/When/Then：通过流转直查库、驳回理由必填拒绝、非授权角色 403+留痕、状态门槛拒绝态（非待审核调审核）、并发双审核单胜出、清单分页与过滤；前端 Vitest 组件/路由守卫用例。

### 不做什么（防蔓延，边界与规格非目标对齐）

- **不做**真实登录/令牌签发（3.9.1 归属，前端沿用演示登录；后端沿用网关身份头）；**不做**角色管理界面（3.9.x）；**不做**清单多状态筛选/搜索（规格只要求"待审核"清单——最小实现，筛选沉淀建议写交付说明）；**不做**政务 CA 证书原件查看/下载（L4 最小授权，见待确认问题 2）；**不做**审核驳回后的自动通知（规格未定义）；**不做** DID 签发衔接（已入驻后的下一环节归 3.1.7~3.1.12）。

### 主要流程（业务语言）

**审核流**：审核员登录 → 侧边栏"主体审核"→ 待审核清单 → 点开某主体查看认证档案（影像可放大、政务证书验证流水可见）→ **通过**：主体转"已入驻"（入驻完成，后续 DID 归下一环节）／**驳回**（必填理由）：主体转"已驳回"，申请人可见理由并可修改后重新申请（既有重报机制）。

### 待确认问题（需要你裁决）

1. **【前端演示角色：admin 兼审核员还是新增独立审核员角色】**前端演示机制目前只有 user/admin 两角色（admin 拥有全部权限点）。剧本 S3 步骤 4 操作人是"审核员"。**建议 A：沿用 admin 兼审核员**（零演示机制改动，界面说明书注明"演示期 admin 兼任审核员"；真实角色体系归 3.9.x）；备选 B：新增独立"审核员"演示角色（更贴剧本角色语义，但演示登录机制改动仅服务演示观感）。**采 A**。
2. **【政务 CA 证书原件是否提供查看/下载】**企业证照影像规格明确"可放大查看原始影像"；政务证书原件规格未提查看要求。**建议 A：不提供原件查看/下载**，档案只展示证书文件名、验证结论与流水（证书内容对审核无增量价值，减少 L4 敏感材料暴露面；真实渠道替换后如需查看走规格变更）；备选 B：提供原件下载（与证照影像对称，但扩大 L4 暴露面）。**采 A**。
3. **【Vue 页面交付范围的预算风险确认】**3.1.3 lofi Q2 已裁决"申请人侧 Vue 页面随 3.1.5 同批实现"，本设计按此口径把范围定为"审核工作台 + 申请人侧注册/认证页"两块。该口径使本包为 C-1.1 各包中界面体量最大的一包（预估前端页面 3~4 个 + 后端端点 3 个 + 观察项 4 项）。**请确认按全量范围开工**；若你判断预算风险优先，可裁"本包仅审核工作台，申请人侧 Vue 页面另拆任务卡"（偏离 3.1.3 Q2 裁决需留痕）。

### 规格缺口声明

1. 驳回理由长度上限：规格只说"必填"，长度参数随高保真设计细化（规格授权"设计细化"）。
2. 清单展示字段：规格未逐一列举，随高保真界面说明书定稿（派生自行为 5 第 1 条"注册信息、证照影像、OCR 结果、核验记录"）。
3. 无规格外需求：本设计未发现规格缺口需要走变更流程（行为 5 与已交付行为 1~4/6/7 边界清晰）。
