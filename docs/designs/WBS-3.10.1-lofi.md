## §2 业务可读行为清单（插座 metaphor 对照）

| 场景 | V1.0 行为 | 业务含义 |
| --- | --- | --- |
| 将来业务要调模型 | 走统一入口 `ModelGateway.chat`（V1.0 只有接口，没有实现） | 所有 AI 调用一个门，审计/护栏将来挂在门上 |
| 换模型供应商 | 改配置（默认供应商或调用时指定），代码不动 | ADR-003 核心价值：换模型 = 改配置 |
| 指定了没接入的供应商 | 明确拒绝"供应商未注册"，不静默换一个 | 防"以为换了模型其实没换" |
| 网关开关关着（V1.0 缺省态） | 一切调用判定拒绝 | 零消耗安全默认 |
| token 预算用满 | 判定拒绝"超出预算" | 成本失控防线预留（C-11.6 承接运行时） |
| 拿契约 JSON 做序列化往返 | 字段名/值逐字一致（OpenAI 兼容 snake_case） | 将来对接任何 OpenAI 兼容供应商零翻译成本 |
| 真实联网调模型 / 花钱 | **不会发生**（无实现、无 HTTP 客户端、测试离线） | V1.0 只装插座不通电 |

## §5 体量与拆分预案

- 预估 **250~400 行有效变更**：主源 ≈180~230 行（5 record + 2 接口 + 配置/路由/判定 ≈13 个紧凑类）；测试 ≈120~180 行（T1~T6）；模块 pom ≈30 行；根 pom +≈9 行（模块行 + dependencyManagement 节）。

## §6 风险与诚实边界

1. **"路由可用"的证明边界**：V1.0 无真实适配器，路由逻辑以**测试桩适配器**验证——交付说明不得声称"已接通某模型"；
2. **预算判定无用量来源**：V1.0 判定接口接收"已用量"入参，用量累计/落库归 V1.5；不得声称"预算控制已生效"；
3. **OpenAI 兼容 = 字段命名与结构兼容**，非官方 SDK 一致性认证；字段集合为 Chat Completions 最小常用集（hifi §3），扩展字段归 V1.5 按需增补；
4. **规格 V0.9 派生自 PRD P0 预留口径**，未覆盖 PRD C-11.1 P1 全量——V1.5 须另行规格化，不在本卡扩面。
