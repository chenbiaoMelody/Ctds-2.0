## §2 业务可读行为清单（安检门 + 留痕本 metaphor）

| 场景 | V1.0 行为 | 业务含义 |
| --- | --- | --- |
| 未来业务要调模型 | 经"安检门"包装后的统一入口调用（V1.0 无真实模型实现，门是休眠的） | 所有 AI 调用都会经过同一道门，规则将来插入 |
| 输入不合规 | 直接拒绝，**不调用模型** | 不让有问题的请求进入模型，省成本也降风险 |
| 输出不合规 | 不把结果交给业务，直接拒绝 | 不让有问题的内容流到用户/下游 |
| 放行 | 模型调用照常进行/结果照常返回 | 正常路径无感 |
| 未配置任何护栏 | 直通（放行） | V1.0 默认不改变任何行为 |
| 护栏自身坏了 | **按拒绝处理**（安全优先） | 宁可误拦，不可漏拦 |
| 每次调用 | 留一条"元数据记录"（谁、什么用途、哪个模型、耗时、token、结果、护栏判定） | 未来审计/成本治理的数据底座 |
| 真实落库/建表 | **不会发生**（V1.0 空记录器、无迁移） | 结构先预留，V1.5 再启用 |
| 真实联网调模型/花钱 | **不会发生**（无实现、无网络客户端、测试离线） | V1.0 只装"安检门"和"留痕本" |

## §6 风险与诚实边界

1. **框架 ≠ 护栏能力**：V1.0 只有接口、执行链和空装饰器；prompt 注入检测等真实能力全部归 V1.5。交付说明不得写成"平台已具备护栏能力"。
2. **预留 ≠ 已建表**：AI 调用日志只有 DDL 结构定稿；V1.0 不建表、不写库，不得写成"已实现 AI 审计落库"。
3. **装饰器为休眠态**：3.10.1 没有真实模型实现，装饰器无法产生真实调用/审计数据；验收只能用测试替身证明框架语义。
4. **fail-closed 是取舍**：护栏自身故障时拒绝调用，安全优先但可能影响未来可用性；若未来要改 fail-open，须走规格变更。
5. **审计字段有限**：V1.0 仅元数据，不含 prompt/响应原文；未来若要对内容做审计，必须按数据分级"就高"原则另行变更，不能在本卡悄悄加列。
6. **上下文由调用方提供**：用途/主体/链路标识/供应商由未来调用方传入（V1.0 无调用方），缺省为 `-`；不得据此认为已实现自动归属。
7. **门禁基线**：新模块非核心模块，走 overall ≥70% 判定；目标不劣于现行 92.43%；ConfigSha256 必须逐字一致。
