## 低保真内容（方向草图）

### 场景判定（结论先行）

- **非界面类**实施包：交付"库表 + 领域模型 + 约束证据"，无页面无接口；设计载体 = 行为清单映射 + 库表契约 + 边界值（章程 2.6 非界面类口径）。
- **空间域是全新起点**：仓库无 space/tenant 任何代码与迁移（3.2.1 立卡时已核查），无历史包袱；本包为 3.2.3~3.2.7 五个下游包的共同地基，表结构一次定稿避免下游反复改表。
- **本包不产生可演示功能**（无服务行为）——业务验收点 = 建表正确 + 约束真实生效（探针测试），可演示能力自 3.2.3 起。

### 做什么（逐条对应规格行为）

1. **新建服务模块 `services/space-service`**：pom（沿 subject-service 惯例，parent `relativePath=../../pom.xml`）+ 主类 + application.yml（端口 8083、库 `ctds_space`、Flyway 启用）+ application/domain 分层包骨架；**不含** Controller / Repository / 业务逻辑。
2. **V1 迁移建 6 张表**（MySQL 8，沿 subject 迁移惯例：InnoDB/utf8mb4/注释齐备）：
   - `space` 空间主表——名称（原始+归一化两列）、场景类型、参与方范围（三档）、可见性（两档）、可选要素（简介/生效期）、所有者主体编号、状态机（CREATED→ACTIVE⇄FROZEN→DISSOLVED 终态）；
   - `space_name_lock` 解散名称锁定表——解散空间名称全平台不可复用的硬兜底（规格行为 2 规则 4，Q4 裁决"全平台口径"）；
   - `space_member` 成员表——空间×主体×角色（owner/admin/member）×关系状态（生效/退出/移除，终态行保留追溯）；
   - `space_admission` 准入单表——申请/邀请/审批流程载体（"未确认的邀请不产生成员关系"的落点，规格行为 3 规则 2）；
   - `space_policy` 策略条目表——**载体级**（作用域=平台级/空间级、条目键/值、红线标记、生效/归档状态）；条目语言与可配置项集合归 3.2.5（规格行为 7 规则 6"禁止两处各自定义策略模型"）；
   - `space_action_log` 统一留痕表——四要素（谁/何时/对象/动作）+ 结果（成功/拒绝）+ 变更前后值 + 理由；创建/状态变更/准入/角色/策略/越权拒绝共用一张（动作码区分），沿 C-1.1 留痕表模式。
3. **领域模型类**（domain 包）：5 张业务表的 POJO 实体 + 状态/枚举类（SpaceStatus、AccessMode、Visibility、SceneType、MemberRole、MemberStatus、AdmissionType、AdmissionStatus、PolicyScope、PolicyStatus、TargetType、ActionResult），与表结构逐列对应——3.2.3~3.2.5 直接消费，不再各自造模型。
4. **约束探针测试**（Testcontainers MySQL 8 实跑，沿 2.4.11 先例与"方法级容器防状态串扰"教训）：迁移冒烟 + 6 组唯一性/约束反向探针（详见 hifi 测试计划）——把"安全断言必须代码强制"的教训落到数据库约束层：规格的三条唯一性规则不允许只有应用层判定，必须有 DB 硬兜底 + 失败路径测试。
5. **数据分级落级复核**（规格合规锚点指派义务）：逐表逐字段落 CAT 类目与 L 级，回写分级规范 §6.1（Q9）。

### 不做什么（防蔓延，与规格非目标对齐）

1. 不写接口、应用服务、Repository、权限判定、继承引擎（归 3.2.3/3.2.4/3.2.5）；
2. 不定义策略本体（条目集合/语言/算法——归 3.2.5，与 C-4.x 对齐）；
3. 不落错误码码值（1006 段仅预留，归 3.2.3/3.2.4）；不接 common 幂等/鉴权/分页组件（无接口，接入随 3.2.3+）；
4. 不自建主体资格判定（ADMITTED 一律跨库只读 C-1.1，规格边界声明 4）；
5. 不动部署清单/docker-compose（服务入部署随 3.2.3 交付可启动服务时）；不改既有四服务与 common；
6. 不做网络级隔离、配额计费、AI 策略生成（规格 §4 非目标 4/5/6）。

### 主要流程（业务语言——本包只落"数据承载"，动作时序归下游包）

- **创建空间** → `space` 插一行（status=CREATED），创建者主体编号落 owner 列；同 owner 归一化同名被唯一索引拒绝；
- **启用/冻结/恢复/解散** → `space.status` 变更 + `space_action_log` 留一行（含前状态→后状态）；解散时同事务写 `space_name_lock`（PK 撞=名称已锁定）并将该空间策略条目全部置 ARCHIVED；
- **邀请/申请/审批/确认** → `space_admission` 插单据行并随流程改状态；通过后 `space_member` 建立生效关系行（准入单回填 member_id）；未确认/未审批的准入单**不产生**成员行；
- **角色授予/收回、退出/移除** → `space_member` 行更新（终态行保留）+ 留痕；同空间"活跃 OWNER"唯一由生成列唯一索引兜底；
- **策略覆盖** → `space_policy` 空间级行落当前值 + 留痕记"从何值→到何值"；被拒绝的覆盖请求只落留痕（result=DENIED）不落数据行——红线判定逻辑归 3.2.5，本包只保证载体与唯一性。
