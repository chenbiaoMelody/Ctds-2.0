## 低保真内容（方向草图）

### 场景判定（结论先行）

- **非界面类实施包**：交付"空间的创建、配置、启用/冻结/恢复、解散"完整服务面（REST API），无页面；设计载体 = 行为清单映射 + 端点契约 + 错误码表 + 边界值（章程 2.6 非界面类口径）。
- **规格行为 1（创建）与行为 2（生命周期）的全部规则逐条落地**；行为 6 只承载"可见性=空间可否被检索"的读面最小集；成员域（行为 3/4/5 的准入角色退出）与策略域（行为 7）零触碰。
- **本包是 space-service 首个有行为的服务包**：服务可启动、可演示（剧本 C-2.1 的创建/启用/冻结/解散步骤自此可走 API 演示）；部署清单随本包入列（3.2.2 纪律声明的顺延项）。

### 做什么（逐条对应规格行为）

1. **创建**（行为 1）：`POST /api/v1/data-spaces`——资格门槛（ADMITTED，调 subject 内部端点，防枚举同形）+ 要素必填 + 名称归一化判重（含 Unicode 空白集，`uk_owner_norm_name` DB 兜底）+ `@Idempotent` 幂等 + 留痕 + 初始 CREATED；
2. **生命周期**（行为 2）：`POST /data-spaces/{id}/enablement|freezing|unfreezing|dissolution`——状态机乐观门槛沿 subject 先例；解散 = 二次确认必填 + **同事务三写**（DISSOLVED + 名称锁定 + 策略归档）+ 留痕（from→to）；
3. **配置变更**：`PUT /data-spaces/{id}`——仅简介与生效期可改（Q5），owner/admin 权限，留痕（从何值→到何值）；
4. **最小读面**（行为 6 可见性消费）：`GET /data-spaces`（公开可检索 + 平台运营方全量）+ `GET /data-spaces/{id}`（公开摘要 / 成员与运营方全量）；
5. **权限双轨**（行为 2 规则 5）：空间内 owner/admin 查 `space_member` 表；平台运营方 = 角色头 `platform.operator` 档（Q4）；逐动作判定+拒绝留痕（DENIED）；
6. **错误码 1006 段定稿**（规格 Q7 预留兑现）：资格不足/状态门槛/名称唯一/要素缺失/二次确认缺失/资源不存在等业务码，`SpaceErrorCodes` 常量类；
7. **部署清单**：space-service 入 `deploy/k8s/`（deployment/service/kustomization 追加，沿 backend 模板）。

### 不做什么（防蔓延，与规格非目标/下游包对齐）

1. 不做成员准入/邀请/角色/退出移除（行为 3/4/5 → 3.2.4）、不做空间内资源的隔离判定与拒绝留痕的完整权限面（行为 6 判定主体 → 3.2.4，本卡只做读面可见性过滤）；
2. 不做策略条目管理与继承引擎（行为 7 → 3.2.5；本卡解散时只把既有条目置 ARCHIVED）；
3. 不做界面（3.2.6）；不做测试达标（覆盖率/变异 → 3.2.7）；不做跨空间授权/合约（C-4.x）；
4. 不改既有服务除 subject yml 1 行授权外的任何代码；不动门禁配置；不引新依赖；
5. 名称/场景/参与方范围/可见性**不可变更**（Q5——规格未定义其变更规则，开放须走变更流程）。

### 主要流程（业务语言）

- **创建**：请求（名称+场景+参与方范围+可见性+可选简介/生效期）→ 资格判定（subject 内部端点；不可达=UNAVAILABLE 统一文案）→ 归一化（去控制字符+显式空白集 trim）→ 唯一判定（DB 硬兜底）→ 落库（CREATED，创建者=owner 写成员行）→ 留痕；
- **启用/冻结/恢复**：动作 → 权限判定（owner/admin/运营方）→ 状态机乐观门槛 → 留痕（from→to）；
- **解散**：动作 → 权限判定（owner/运营方）→ `confirmDissolve=true` 校验 → 同事务三写（DISSOLVED + 名称锁定【已锁定即跳过，Q6】+ 策略 ARCHIVED）→ 留痕；
- **检索/详情**：可见性过滤（公开可检索；不公开仅成员与运营方可见）。
