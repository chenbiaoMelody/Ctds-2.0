## 低保真内容（方向草图）

### 场景判定（结论先行）

- **非界面类实施包**：交付"成员准入（申请/邀请/审批/确认）、角色授予与收回、退出与移除、所有权转移、统一权限面"的完整服务面（REST API），无页面；设计载体 = 行为清单映射 + 端点契约 + 错误码表 + 边界值（章程 2.6 非界面类口径）。
- **规格行为 3（准入）/ 行为 4（角色与权限边界）/ 行为 5（退出与移除）全部规则逐条落地**；行为 6 只补"读面拒绝留痕"一个缺口（3.2.3 hifi §10 E9 移交）；策略域（行为 7）与界面（3.2.6）零触碰。
- **3.2.3 移交五项随本包全部兑现**：① 统一权限面收敛 + 权限点命名定稿；② 所有权转移双处同步；③ 读面拒绝留痕；④ `appendTransition` from/to 双表达收敛；⑤ 幂等键长边界（本域业务幂等自然规避 + 沉淀候选保留登记）。
- **零库表迁移包**：准入单 / 成员表 / 留痕表全部复用 3.2.2 六表既有载体（`space_admission` 状态机流转细则归本包 = 3.2.2 hifi §1.4 预告），动作码全部复用 `space_action_log` 注释既有预留值域（ADMIT_* / LEAVE / REMOVE / ROLE_* / ACCESS_DENIED），**无 V3 迁移**。

### 做什么（逐条对应规格行为）

1. **成员准入**（行为 3）：申请（公开/审批制空间，申请人提交）→ 待审批；邀请（邀请制空间，owner/admin 发出）→ 待被邀方确认；确认/谢绝；审批通过/拒绝（含理由）；被准入主体须 ADMITTED（提交时即拒，统一文案防枚举，复用 `SubjectAdmissionGate`）；空间须 ACTIVE 才可准入（未启用/冻结/解散一律拒）；重复准入幂等（已是成员/已有待处理单返回既有，不新增行）；准入单状态机（PENDING_APPROVAL / PENDING_CONFIRMATION → APPROVED / REJECTED / DECLINED）乐观门槛 + 回填 `member_id` 贯通追溯；
2. **角色与权限边界**（行为 4）：角色授予与收回（member⇄admin，owner 行不参与角色变更）；不得自我提权；admin 不可执行仅所有者动作（解散已实现、所有权转移本包新增）；逐动作权限判定 + 拒绝留痕（DENIED）；
3. **退出与移除**（行为 5）：成员主动退出（owner 拒）；owner/admin 移除成员（reason 必填，不得移除 owner）；唯一所有者保护（owner 行退出/移除/角色变更一律拒，`uk_active_owner` DB 兜底）；冻结期可退出不可准入/授权；退出/移除后访问立即失效（判定源 = 活跃成员行，终态行自然出局）；
4. **所有权转移**（行为 4 规则 5 / 行为 5 规则 1 授权 + 移交②）：仅 owner 发起，目标 = 本空间活跃成员；单事务四写 = `space.owner_subject_no` 列乐观更新 + 原 owner 成员行降级 + 目标成员行升 OWNER（顺序先降后升避 `uk_active_owner` 冲突）+ 留痕两行（ROLE_GRANT / ROLE_REVOKE）；
5. **统一权限面**（行为 4 规则 4 + 移交①）：权限点定稿 `space.admin` / `space.member` 两点；动作→权限点矩阵单点化（`SpaceAccessGuard` 重构为统一判定协作件，逐动作判定语义不变）；角色映射：空间内 OWNER/ADMIN → `space.admin,space.member`、MEMBER → `space.member`；平台运营方经 yml `platform.operator: space.admin,space.member`（**替换 3.2.3 零消费的 `space.manage`**）；owner 专属动作（解散/转移）走属主判定（`space.owner_subject_no` 列口径）与权限点正交；
6. **读面拒绝留痕**（行为 6 规则 5 + 移交③）：非成员访问不公开空间详情保持 404 同形（防存在性探测，3.2.3 既有口径不变），对内落 `ACCESS_DENIED` 留痕（谁/何时/目标/结果，无数据原文）；成员列表非成员访问拒绝同样留痕；
7. **最小配套读面**：成员列表（成员可见，剧本判定工具）+ 空间准入单列表（owner/admin 发现待办）+ 我的准入单（申请人/被邀方获取自己的申请与邀请，演示链路闭环）。

### 不做什么（防蔓延，与规格非目标/下游包对齐）

1. 不做策略条目管理与继承引擎（行为 7 → 3.2.5）；不做界面（3.2.6；剧本界面入口占位不变，Q8-A 口径）；不做测试达标覆盖率/变异（→ 3.2.7）；
2. 不做跨空间授权/合约（C-4.x）；不做只读审计角色（规格 Q3 裁决归 C-9，不新增档位）；
3. 不动 common 组件代码（权限面收敛 = space-service 内部协作件 + yml 映射修正；`@RequirePermission` 注解静态门不适用于含成员表数据的动态判定，口径不变）；幂等键长 256/257 的 common 沉淀**不在本包做**（移交⑤：本域采业务幂等自然规避，沉淀候选保留登记）；
4. 不做准入单撤回（`CANCELLED` 值域保留不启用——规格无撤回行为的验收标准，开放属需求扩展走变更流程）；
5. 不改既有服务其他代码；不动门禁配置；不引新依赖；零迁移（见结论先行）。

### 主要流程（业务语言）

- **邀请制准入**：owner/admin 发邀请（被邀主体须 ADMITTED）→ 单据 `PENDING_CONFIRMATION` → 被邀方确认（APPROVED + `space_member` 新行 + 回填 `member_id`）或谢绝（DECLINED + 理由）；未确认/未谢绝不产生成员关系；
- **公开/审批制准入**：ADMITTED 主体提交申请 → `PENDING_APPROVAL` → owner/admin 审批：通过（同上生效）或拒绝（REJECTED + 理由必填）；
- **准入门槛**：每步先判空间状态（非 ACTIVE 一律拒，1006C0002 表意"空间当前不可接纳成员"，与"主体未入驻"1006C0001 天然两码区分）→ 判主体资格（ADMITTED）→ 判重复（已是成员/已有待处理单 → 返回既有）；
- **角色授予/收回**：owner/admin 指定目标成员行与目标角色（ADMIN/MEMBER）→ 状态门槛（空间 ACTIVE）→ 目标行门槛（活跃且非 OWNER 行）→ 自我提权门槛 → 乐观门槛更新 + 留痕（ROLE_GRANT / ROLE_REVOKE）；
- **退出/移除**：定位活跃成员行 → owner 行保护判定 → 终态化（`LEFT`/`REMOVED` + `exited_at`）+ 留痕（LEAVE / REMOVE 含理由）——判定源即时生效；
- **所有权转移**：owner 发起 + 目标活跃成员 → 先降原 owner（ADMIN）→ 再升目标（OWNER）→ 同步 `space.owner_subject_no` → 留痕两行；任一步失败整体回滚（移交②双处同步，`uk_active_owner` 兜底）；
- **统一权限判定**：动作 → 所需权限点（矩阵单点）→ 权限点来源折算（角色头映射 ∪ 空间内活跃角色映射）→ owner 专属动作另行走属主判定 → 失败 = 1006C0007 + DENIED 留痕。
