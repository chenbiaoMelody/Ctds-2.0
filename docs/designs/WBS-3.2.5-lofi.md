## 低保真内容（方向草图）

### 场景判定（结论先行）

- **非界面类实施包**：交付"平台级策略条目治理 + 空间级覆盖 + 有效策略解析（继承/取严/来源可解释）"的完整服务面（REST API），无页面；设计载体 = 行为清单映射 + 端点契约 + 引擎契约 + 错误码表 + 边界值（章程 2.6 非界面类口径）。
- **规格行为 7 六条规则逐条落地**；§6.5 硬约束（红线放宽拒绝须代码强制 + 反向探针）以写入门 + 必红反向测试兑现；行为 1~6 零触碰（既有端点复用：生命周期三写归档已就位、准入门槛已就位）。
- **零新表包**：`space_policy` 载体全复用（3.2.2 hifi §1.5 契约兑现 = 本包核心承接项①）；V3 迁移仅两件事（动作码注释登记 + 平台基线种子），无建表无列变更。
- **引擎 = 领域纯函数**：取严解析与放宽判定收敛在领域层目录注册表 + 解析器（无 IO），集成测试之外另有纯单测封闭性锚——目录键/值域/严格度单射为封闭集合，测试可枚举。

### 做什么（逐条对应规格行为）

1. **目录定稿**（行为 7 规则 6"随 3.2.5 定稿"）：封闭目录 **3 键**（V1.0 演示可复现的最小可解释集，扩展=登记目录注册表）：
   - `data.visibility` **数据可见范围**：`SPACE_MEMBER`（仅空间成员可见，严格度 2）/ `ALL_PLATFORM`（平台内可见，严格度 1）；
   - `data.retention` **数据留存期限**：`D30`（4）/ `D90`（3）/ `D180`（2）/ `D365`（1）——期限越短越严；
   - `member.data_export` **成员数据导出**：`FORBIDDEN`（3）/ `APPROVAL_REQUIRED`（2）/ `ALLOWED`（1）；
   - 每键值域内**严格度单射**（无并列值——同严格度即同值，消除平局歧义）；红线标记沿用载体列 `is_redline`（仅平台级条目可标，载体契约）；
   - 目录 = 代码注册表 `PolicyCatalog`（键→值域→严格度→业务文案），**策略模型权威定义点**（C-4.x 对齐义务登记移交）。
2. **平台级条目治理**（规则 1"平台级策略为默认"的来源权威）：platform.operator 创建条目（键+值+红线标记）与变更值/红线标记，动作码 POLICY_DEFINE（V3 注释登记），from→to 落留痕；条目列表查询（治理面只读）。
3. **空间级覆盖**（规则 2）：空间 owner/admin（`space.admin` 权限点，承接项③）按 entryKey 提交覆盖值——写入门链 = 值域与目录校验（0012）→ 覆盖目标平台条目定位（0014 统一文案防探测）→ **红线放宽判定**（`is_redline=1` 且新值严格度 < 平台值严格度 → 拒绝 0013 + POLICY_OVERRIDE_REJECTED 留痕含业务文案）→ 落库（该空间同键已有 ACTIVE 覆盖行则 UPDATE 值，否则 INSERT 并回填 platform_entry_id 显式指向——载体契约；scope_uniq 生成列兜底同键唯一）+ POLICY_OVERRIDE 留痕（from=原生效值 → to=新值）；同值重复覆盖 = 幂等无操作无留痕（沿 3.2.4 E7 先例）。
4. **有效策略解析**（规则 1/3）：每键取平台级与空间级**更严一侧**（严格度大者）——无空间覆盖=继承（来源标注"继承自平台"）；空间更严=覆盖生效（标注"空间级"）；空间存在但平台更严=取严平台（标注"空间覆盖未生效（取严）"）——三态来源标注满足"判定结果可解释（依据哪一条、取了哪一侧）"；解析为领域纯函数（输入=平台条目集+空间条目集，输出=有序视图行）。
5. **有效策略视图与平台列表读面**：`GET /{id}/policies/effective`（成员可读自己空间的策略；含平台值/空间值/生效值/红线标记/来源标注）；`GET /api/v1/platform-policies`（platform.operator 治理面只读）。
6. **生命周期联动**（规则 5）：冻结/解散空间的策略**写**动作一律拒（复用 `1006C0002` 空间状态门槛——文案表意"空间当前不可变更策略"）；解散空间条目已由 3.2.3 三写置 ARCHIVED——归档条目**不可变**（写门拒绝 + 测试固化）且**可查看**（有效视图对归档空间沿 3.2.3 解散后可见口径呈现归档值）；冻结期间已配置覆盖**保留**（视图不变）、恢复后仍生效（剧本 S3-3 口径，测试固化）。

### 不做什么（防蔓延，与规格非目标/下游包对齐）

1. 不做界面（3.2.6；剧本界面入口占位不变）；不做测试达标覆盖率/变异（→ 3.2.7）；不做 C-4.x 使用控制策略的执行/合约形态（C-4 包）——仅登记"目录=策略语言权威定义，C-4.x 设计时须对齐复用"移交项；
2. **不做策略条目对空间要素（可见性/准入形态）的联动改写**：空间创建要素（`visibility`/`access_mode` 列）与策略条目是两套口径——策略条目是治理声明层，V1.0 不回写空间列（回写=双重权威冲突源，如需联动属规格扩展走变更流程）；行为 1~6 的既有执行面零触碰；
3. 不做策略智能生成（C-2.4 = P2）、不做配额/计费类策略键（C-12.2 域）；
4. 不动 common 组件代码（平台面门 = 既有 `hasPermission` 以空成员表退化角色头判定复用，Guard 零改动；`platform.policy` 常量与 yml 映射追加在 space-service 侧）；不做幂等键长 common 沉淀（承接项④：本域业务幂等，候选保留登记）；
5. 不建新表、不改列（V3 仅动作码注释登记+种子）；不动门禁配置；不引新依赖；不改既有服务其他代码。

### 主要流程（业务语言）

- **平台条目设定**：platform.operator 创建条目（键须在目录/值须在值域/红线标记可标）→ POLICY_DEFINE 留痕；变更值或红线标记 → 同上留痕 from→to；
- **空间覆盖提交**：owner/admin 选目录键提交新值 → 值域校验 → 平台条目定位 → 红线判定（放宽=拒+留痕；收紧/非红线=落库+留痕）→ 覆盖行落库（首覆盖 INSERT 指向平台条目；再覆盖 UPDATE 值）→ 响应含生效结果与来源标注；
- **有效策略读取**：按空间取平台条目全集 ∪ 空间覆盖行 → 逐键取严 → 输出视图行（键/生效值/来源标注/平台值/空间值/红线标记）；
- **生命周期门槛**：策略写动作前置空间状态判定（非 ACTIVE 一律拒，复用 0002）；归档条目只读。
