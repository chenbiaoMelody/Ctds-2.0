## 1. 方向（业务可读）

逻辑空间全链六包（规格 `3.2.1` → 数据模型 `3.2.2` → 生命周期 `3.2.3` → 成员权限 `3.2.4` → 策略继承 `3.2.5` → 管理界面 `3.2.6`）+ 缺陷修复卡 DB-28 已陆续交付并验收。本包**不加任何新业务功能**，只做三件事：

1. **补缺口**：把规格 C-2.1~2.3 八大行为的验收标准与既有 **145 例测试**（73 集成 + 72 单测/守卫）逐条对账——盘点结论：**行为 1~5、7 覆盖充分**；**行为 6（逻辑隔离）有三处缺口**（跨空间隔离字面用例缺、拒绝留痕"何时"要素未断言、运营方治理 visit 留痕断言归 DB-29〔见边界〕）；另吸收 **DB-28 卡 §6.6 登记的三项补测候选**（FROZEN 态重放字面用例、T22 B 路径"无新 CREATE 留痕"断言、要素非法 + 名称锁优先序组合用例）。每条补测都要求"**删掉实现必变红**"（红锚）；
2. **测出达标数字**：space-service **非核心模块**（AGENTS.md §4 核心模块 = policy-engine / metering-billing / crypto / auth / did）→ 达标线 = **整体行覆盖 ≥70%**（章程 4.2）。现状：**无 HEAD 基线数字**（在树 `target/site/jacoco` 报告陈旧、缺 3.2.4/3.2.5 全部类；门禁 `coverage` 已启用但不打印分模块值）。本包**只测量、不开门禁**（沿 WBS-3.1.12 先例：jacoco 命令行临时注入，不改 pom / 不改 `gates-config.json` / 不改 `dependencies.md`，红线 3）；
3. **联调验证**：真实环境（subject 8080 + space 8083 + Docker 三容器在线）复验三份剧本关键链路 + subject 资格门真链（现有集成测试的资格端口全部为 mock，真链从未在测试中走通过——只在各次验收走查中人工验证过）。

**关于"联调"的边界**：WBS 行 257 写"测试达标（含跨空间隔离用例）、联调"。本包联调 = **真实环境剧本关键链路复验 + subject 资格联动真链**；不新建自动化 e2e 资产（Playwright e2e 门禁段 PENDING-CI，涉 CI 供给，不在本卡）。

## 2. 盘点结论摘要（详见高保真设计）

**缺口来源三类**（立卡前只读子智能体全量盘点，证据见 hifi §2）：

- **① 行为 6 逻辑隔离缺口**：现有隔离用例的"非成员"全部是**无成员身份的第三方**（outsider-t10 / outsider-t18 / prober-t3），**没有"A 是空间甲的成员、去访问空间乙"的跨空间字面用例**；拒绝留痕只断言"谁/对象/动作/结果"四要素中的四项，**"何时（created_at）"未断言**；"公开可见 ≠ 可访问"与"第三方访问被拒"已覆盖；
- **② DB-28 登记补测候选三项**（卡 §6.6 第 2 条白纸黑字移交）：FROZEN 态重放字面用例（现有重放用例载体 = ACTIVE / DISSOLVED，无 FROZEN）；T22 B 路径"无新 CREATE 留痕"断言；要素非法 + 名称锁命中优先序组合用例；
- **③ 达标数字缺失**：space-service 行覆盖**无 HEAD 基线**（陈旧报告约 94.2% 仅代表 3.2.3 时代）；变异杀除率全仓对 space 域**零实测先例**。

**现状基线**：space-service **145 例全绿**（DB-28 收口实测 145/145 + checkstyle 0 + package BUILD SUCCESS）；全仓门禁 GREEN；三份剧本（C-2.1 / C-2.2 / C-2.3）3.2.6 走查期已全链走查（C-2.1 的 S3-6 已由 DB-28 修复复验转 PASS）。

**本包硬边界**：**零新增依赖、零门禁配置改动、零新增错误码/状态枚举/库表/迁移**；**补测只允许新增与强化断言，禁止弱化**；**运营方治理查看 visit 留痕的实现与断言归 DB-29 小卡**（本卡不重复造、也不提前断言）；不夹带 DB-27（框架层请求体上限）、不动既有端点语义。
