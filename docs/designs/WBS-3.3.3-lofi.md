## 1. 做什么 / 不做什么

**做**（= 任务卡交付物 ①~⑧；**按建议口径 A 书写，Q1 若改选 B/C 则本设计随确认重写**）：

1. 在既有宿主 `services/catalog-service`（8084 / 库 `ctds_catalog`）上续建，迁移顺延 **V2**（不新建服务、不新建库）；
2. **受控词表 2 表** + 种子词条随迁移内置（沿 3.2.5 V3 平台基线种子先例）；
3. **词条读面 2 端点**（词表册清单 / 词条分页查询）——提供方登记与变更时"从词表选词"的唯一入口（3.3.6 界面消费）；
4. **写面成员校验接入**：登记（W1）与变更（W2）的语义标签校验链增加"词条成员校验"，非受控词表标签一律拒绝（新错误码顺延）；
5. **数据标识承接确认**（3.3.2 已交付 `DS+yyyyMMdd+6 位当日序号`；本卡零改动、只在映射表登记口径一致）；
6. 迁移探针 + 读面/校验正反向测试 + **3.3.2 既有 58 例零回归**；
7. 分级落级复核回写（分级规范 §6.1 一行）。

**不做**（归下游，任务卡纪律声明同）：

- **来源系统对接 → 按 Q1 裁决**（建议 A：规格无业务行为承载 → 本卡不实现，登记为规格缺口，待 PO 决定是否提 B 级变更单后另行立卡）；
- 统一目录检索 / 分类过滤 / 类目树 / 订阅收藏 / 排序 → **3.3.4**（规格行为 5 规则 3 明示"类目树与种子类目随 3.3.4 落定"；台账"下一包"原记"受控类目树载体"属口径串行，本批已校正）；
- 产品封装 / 定价 / 上下架 / 注销引用保护实体化 → **3.3.5**；
- 界面（检索门户 / 资源登记页）→ **3.3.6**；覆盖率达标 / 万级目录数据集 → **3.3.7**；
- **元数据 AI 自动识别与补全（C-3.5）/ AI 分类分级（C-3.6）** → 规格 §4 非目标 3，V1.0 不做（P1）；
- 词表维护写面（新增/停用词条）→ 建议 Q7-A 不做（规格无对应行为，V1.0 词表随迁移内置）。

## 2. 方向要点（设计骨架）

### 2.1 宿主与迁移

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 服务 / 端口 / 库 | `services/catalog-service` / 8084 / `ctds_catalog`（**均不变**） | 一域一服务（3.3.2 Q1-A 已裁决）；3.3.3~3.3.5 同宿主续建，避免域内碎服务跨库 |
| 迁移版本 | **V2**（V1 = 3.3.2 四表） | 沿 ADR-009 顺序迁移；既有 V1 零改动（不新增列、不改语义） |
| 词表册命名 | 词表码 `SEMANTIC_TAG`、词表名「数据资源语义标签」 | 单册起步、码位预留多册（词表集合随本包落定 = 规格 §末未定义项） |
| 与标签载体的关系 | **结构不变**：`dataset.semantic_tags` 仍为 JSON 文本载体，词表只作"字典校验" | 3.3.2 hifi §10.1 明示"**届时如改关联表结构走变更流程**"——保持文本载体可免变更流程、免迁移既有 3 行演示数据（Q2-A） |

### 2.2 表清单（2 表 + 种子；**不加未用列**）

| 表 | 承载 | 硬约束（DB 兜底） |
| --- | --- | --- |
| `tag_vocabulary` | 词表册：id / vocabulary_code / vocabulary_name / created_at | `uk_vocabulary_code` |
| `tag_term` | 词条：id / vocabulary_id / term_code / term_name / **normalized_term** / created_at | `uk_term_code`（词条业务编号，沿 data_no/subject_no"业务编号与技术主键分离"先例）；`uk_vocab_norm_term(vocabulary_id, normalized_term)` |

- 种子词条经 V2 迁移 `INSERT` 内置（约 12 条，见 §3 Q4 建议集）；本卡**不建**停用/排序列（无维护写面即无生命周期，避免未用列）；`category` 等 3.3.4 需要的列随其迁移增补，不在本卡预置。

### 2.3 校验通道（写面接入点，**零跨服务改动**）

```
catalog-service（本卡改动面全部在模块内）
├─ interfaces/TagVocabularyController       ← 新建（2 读端点）          ← 本卡新增
├─ application/DatasetCommandService         ← 校验链插入"词条成员校验"   ← 既有文件改 2 处
│    create(): SemanticTags.validate → 新增 tagVocabularyPort.findUnmatched(tags)
│    update(): validTagsJson()        → 同上
└─ infrastructure/JdbcTagTermRepository + domain/TagTerm/TagVocabulary/TagTermPort   ← 新建
```

- 判定为**纯本地**（同库同服务，无内部端点、无网络调用、无 UNAVAILABLE 语义）——与 3.3.2 两道跨域判定形成对比，本卡**不触碰 subject / space / did / kms 任何文件**；
- 匹配口径：入参标签经 `DatasetNameNormalizer.normalize` 后，与词条 `normalized_term` 在 **DB 侧 `IN` 比对**（`utf8mb4_0900_ai_ci` 天然折叠大小写；沿 3.3.2 判重前提），应用层不做第二套归一化（呼应 DB-30：不新增重复实现）。

### 2.4 端点清单（2 读端点；写面不新增端点）

| # | 端点 | 说明 |
| --- | --- | --- |
| R3 | `GET /api/v1/tag-vocabularies` | 词表册清单（认证 + 权限点 `vocabulary.read`） |
| R4 | `GET /api/v1/tag-vocabularies/{vocabularyCode}/terms` | 词条分页（`keyword` 可选过滤；复用 `common-pagination`，`pageNum/pageSize`） |

> 读面编号**续 3.3.2 的 R1/R2** 排为 R3/R4（不用 V1/V2 字样——那留给迁移版本与规格版本）；写面 W1/W2 为 3.3.2 既有端点，本卡只升级校验链、路径与入参不变。

> 命名沿 ADR-005（复数名词小写连字符 + 版本在路径）；域内既有写面 W1/W2 的语义标签校验升级，**路径与入参字段名（`tags`）不变**——3.3.6 界面与既有剧本步骤零返工。
