## 1. 目标与非目标（做什么 / 不做什么）

**做什么（本卡交付）**

1. 合约域宿主服务 `contract-service`（端口 8085 / 库 `ctds_contract`）的骨架与模板库本体；
2. 模板数据模型（模板主表 + 版本表 + 留痕表）与预置三类模板种子（公共数据授权 / API 调用 / 隐私计算）；
3. 模板管理完整服务：运营方写面（新增 / 修订出新版本 / 启停）+ 已入驻读面（启用中浏览 / 详情）+ 运营方读面（全量 / 版本历史 / 留痕）；
4. 供 3.4.3 发起侧使用的查询校验能力（模板存在 + 版本有效 + 启用态）；
5. 条款槽位集合落定（规格授权本卡的未定义项，业务清单见 §3）；
6. 1008 段错误码定稿、留痕四要素、越权拒绝与防枚举同形、集成测试。

**不做什么（规格边界 + WBS 分工，纪律声明复述）**

1. 不做合约发起 / 协商 / 签署 / 存证对接（归 3.4.3）——含"以停用模板发起被拒"的发起侧兑现与"协商中草案按 V1 快照"联调（移交义务双登记）；
2. 不做策略 DSL / 执行引擎 / 模拟器（归 3.4.4 / 3.4.5 / 3.4.6）；
3. 不做界面（归 3.4.7；剧本界面入口占位核对修订同归 3.4.7）；
4. 不做测试达标（覆盖率口径）与交付 / 计费联调（归 3.4.8；计费归 3.7.x）；
5. 不改 subject / did / kms / space / catalog 任何代码（subject 仅 yml 加 1 行 client 授权）；不动门禁配置、不改 ADR、不引新依赖。

## 2. 服务落点与模块骨架

- **新建域级服务 `contract-service`**（合约域 3.4.2~3.4.8 七实施包共用宿主，沿 catalog-service 域级先例）：端口 **8085**（8080~8084 已占用顺延）、库 **`ctds_contract`**、根 pom modules 追加；
- 四层骨架沿 catalog 先例：`interfaces`（控制器 + 请求/响应 DTO）→ `application`（ContractTemplateAppService 等应用服务）→ `domain`（实体 / 枚举 / 仓储接口）→ `infrastructure`（JDBC 仓储实现 + 内部 client）；
- ORM = `spring-boot-starter-jdbc`（平台冻结栈，ADR-001）；部署清单 deploy/k8s 追加 deployment + service 两件。

## 3. 条款槽位业务清单（规格未定义项授权落定；业务可读，请按业务语义确认）

> **说明**：合约模板 = 平台预置的"条款框架"——发起合约时按框架逐槽位填写具体约定值。槽位本身不含任何真实数据，只有条款名称、必填性与填写说明。以下清单为建议口径（Q2），编排师确认后即为 3.4.3 起草合约的填写框架。

**3.1 公共骨架槽位（三类模板共有，均为必填）**

| # | 槽位 | 填写说明（发起时填写什么） |
| --- | --- | --- |
| 1 | 授权标的 | 授权的数据 / 服务是什么（对应目录产品，含标识与名称） |
| 2 | 授权范围 | 允许的使用方式（如：内部 analytics / 对外服务集成 / 二次加工边界） |
| 3 | 授权期限 | 起止时间或条件 |
| 4 | 使用目的与限制 | 允许的使用目的清单 + 明确禁止项（含**禁止再分发**默认表述） |
| 5 | 安全与保密义务 | 数据保护要求、泄露责任 |
| 6 | 违约责任 | 违约情形与责任承担方式 |
| 7 | 争议解决 | 争议处理途径与适用规则 |

**3.2 类型差异化槽位**

| 模板类型 | 槽位 | 必填性 | 填写说明 |
| --- | --- | --- | --- |
| **公共数据授权** | 数据格式与交付方式 | 必填 | 交付格式（如库表 / 文件 / 接口拉取）与交付渠道 |
| | 数据更新与维护义务 | 必填 | 更新频率、通知义务、中断处理 |
| | 数据质量承诺 | 可选 | 准确性 / 完整性承诺口径 |
| **API 调用** | 接口范围与调用方式 | 必填 | 可调用接口清单、鉴权方式、协议版本 |
| | 调用频次上限 | 必填 | 总量 / 峰值限制（为 3.4.5 配额计数、3.7 计费提供约定载体） |
| | 服务可用性承诺 | 可选 | 可用率口径与补偿方式 |
| **隐私计算** | 计算环境与安全要求 | 必填 | 可用计算环境、安全管控要求 |
| | 计算结果交付方式 | 必填 | 结果形态与交付渠道 |
| | 原始数据不出域承诺 | 必填 | 原始数据不离开提供方域的强约束表述（隐私计算核心特征） |
| | 审计与核查 | 可选 | 审计权、核查方式与频次 |

**3.3 槽位载体形态**：每槽位 = 槽位键（英文标识，如 `subject_matter`）+ 名称 + 必填性 + 填写说明（+ 可选参考文案）；条款框架 JSON 载体存于版本行（结构见 hifi）；**槽位集合在本卡一次性落定后即预置模板的 V1 框架**；后续槽位演进走模板修订流程（出新版本），不走本卡外渠道。

## 4. 数据模型方向（3 表，详细 DDL 见 hifi）

1. **contract_template 模板主表**：模板编号（业务编号，形态随 hifi）、模板名称、模板类型（三类枚举）、当前版本号、状态（ENABLED / DISABLED）、审计字段；模板编号唯一索引 +（类型+名称）唯一约束（同类型模板名不重复，防运营方误建重复模板）；
2. **contract_template_version 模板版本表**：模板外键（逻辑引用，跨表同库物理外键沿 catalog 先例）、版本号（模板内递增）、条款框架 JSON（§3 槽位集合的实例化骨架）、发布人 / 发布时间；**（模板+版本号）唯一索引；版本行不可变**（应用层无更新路径 + 设计约束，快照语义由此保证——修订永远新增行，旧版本天然保留可查）；
3. **contract_template_action_log 模板留痕表**：四要素（操作者 / 时间 / 模板+版本号 / 动作 CREATE / REVISE / ENABLE / DISABLE + 拒绝类 DENIED_*），沿 catalog action_log 先例（拒绝留痕含理由码）。

## 5. 判定通道（两道，均不新建对端代码）

1. **已入驻判定**（读面浏览门槛）：复用 subject 内部端点 `/api/v1/subject/internal/subjects/{no}/admission`（ADR-016 §6；did / space / catalog 三处 client 先例现成）——本卡新增 `SubjectAdmissionClient`（JDK HttpClient 零依赖，三态判定：ADMITTED / NOT_ADMITTED 同形 / UNAVAILABLE 不冒充）；**subject 侧唯一改动 = application.yml 加 1 行 client 授权**（`contract-internal`，沿 catalog 先例）；
2. **平台运营方判定**（写面 + 运营读面）：沿 3.3.6 目录域 admin 角色头先例——请求要求 admin 档（`@RequirePermission` + 角色头校验）；非 admin（provider 档 / 普通档 / 无头）一律拒绝并**拒绝留痕**（规则 1 服务端强制；含直调接口变体，剧本 S3-1）。

## 6. 状态机（模板生命周期）

```
[种子/新增] ──ENABLED──▶ 启用中 ◀──ENABLE──┐
                  │                        │
                DISABLE                DISABLE
                  ▼                        │
              停用 ────────────────────────┘
```

- 新增模板（含预置种子）即 **ENABLED**（规格未定义"草稿态"，V1.0 不引入——运营方新增即发布 V1 并可被发起，最小状态机；如需草稿态属规格变更，走变更流程）；
- **DISABLED → 停用**：退出已入驻浏览列表（Q6）、internal 校验返回"不可用于新发起"（3.4.3 发起侧以此拒绝）、**不影响既有合约与协商中草案**（该语义的兑现归 3.4.3 快照机制）；
- **ENABLED → 恢复**：重新进入浏览列表、可被新发起（剧本 S2-6）；
- 启 / 停均留痕；重复启停（同态操作）拒绝并留痕（幂等拒绝语义，沿目录域先例）。

## 8. 测试方向（详细计划见 hifi）

Testcontainers 实跑（`disabledWithoutDocker` 语义、Skipped 0 口径）：

1. **迁移与种子探针**：3 表结构 + 预置三类模板（各 1 条 + V1 启用中）；
2. **维护权矩阵**：admin 过 / provider 档 / 普通档 / 无头拒 + 拒绝留痕（含直调变体同拒）；
3. **版本化**：修订出新版本、旧版本保留可查、当前版本指针前移、留痕 from→to；版本行不可变反向探针；
4. **启停门槛**：停用 → internal 校验"不可用于新发起"、退出浏览列表、重复停用拒绝；重新启用恢复；启停留痕；
5. **浏览边界**：未入驻/不存在防枚举同形逐字对照、UNAVAILABLE 不冒充、已入驻浏览启用列表与详情；
6. **留痕四要素**：新增/修订/启停/拒绝四类动作断言、无敏感原文；
7. **幂等**：新增模板 @Idempotent（运营方误双击同请求键重放返回首次结果）。
