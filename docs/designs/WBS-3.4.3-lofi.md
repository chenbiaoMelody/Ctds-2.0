## 1. 目标与非目标（做什么 / 不做什么）

**做什么（本卡交付）**

1. 合约发起完整链路：资格与状态门槛（需求方已入驻 + 产品已上架 + 双方非同一主体 + 模板启用）、模板版本快照锁定、定价快照、条款值校验、幂等；
2. 在线协商：交替提案 / 反提案，每轮条款版本 +1（行级版本化、变更明细"从何值→到何值"），双方先后确认 → 条款锁定进入"待签署"；
3. 电子签署：双方各以主体 DID + 国密 SM2 签署条款快照哈希；部分签署 → 双签生效（生效时间 = 最后一签）；签署不可撤销；
4. 签署存证事件（合约哈希 + 双方签署要素）本地落库，预留 3.8.3 埋点口径；
5. 状态与生命周期：六状态 + 协商终止 / 拒签终止 / 双方合意解除 / 运营方强制终止（理由必填）四终止分支；终态不可逆；产品下架既有合约效力不变；
6. 访问边界与治理：合约与协商详情仅双方可见（非参与方读写"不存在"同形防枚举 + 拒绝留痕）；运营方治理面（列表 / 详情含协商过程）+ 查看留痕；验签核验（双方 + 运营方）；
7. 策略条款承载与最小门槛校验（五要素 + 显式"无使用限制"声明；完整 DSL 归 3.4.4）；供 3.4.5 的合约-策略读取应用层方法；
8. **承接 3.4.2 移交两项**：停用模板发起被拒（C-4.1 S2-5）与协商中草案按 V1 快照（C-4.1 S2-3）。

**不做什么（规格边界 + WBS 分工，纪律声明复述）**

1. 不做策略 DSL 语法 / 解析器 / 完整策略校验增强（归 3.4.4）；
2. 不做策略执行引擎、五类拦截、配额计数、使用计数（归 3.4.5；本卡只交付合约侧状态与策略读取）；
3. 不做模拟器与测试台、双向用例（归 3.4.6 / 3.4.8）；
4. 不做界面（归 3.4.7；剧本界面入口占位核对修订同归 3.4.7）；
5. 不做链上存证对接（归 3.8.2/3.8.3；本卡只落存证事件）；不做履约监测（C-4.4 P1）；不做第三方电子签对接（非目标）；
6. 不做计费与账单（归 3.7.x；定价仅作合约快照）；
7. **不做完整合约变更流程（变更态 + 重新双签）与主体资格异常自动联动**——按 Q8 落定：最小兑现（单方变更拒绝 / 动作时校验）+ 深化登记移交；
8. 不改 subject / space / kms 代码；catalog / did 两处最小必要改动随卡设计留痕；不动门禁配置、不引新依赖、不自行实现密码学。

## 3. 业务链路与状态机（业务可读）

**一次合约的完整旅程**

```
需求方发起（选模板+填条款）──▶ 协商中
                                │  双方交替提案/反提案（每轮条款版本 +1，变更可查）
                                │  双方先后确认（条款锁定）
                                ▼
                             待签署 ──任一方拒签终止──▶ 已终止
                                │  一方签署
                                ▼
                            部分签署 ──任一方拒签终止──▶ 已终止
                                │  另一方签署（有效期开始 = 最后一次签署时间；存证事件登记）
                                ▼
                             已生效 ──双方合意解除──▶ 已完结（终态）
                                └──运营方强制终止（理由必填）──▶ 已终止（终态）
            协商中 ──任一方协商终止──▶ 已终止（终态）
```

**状态机口径（细化，Q2）**：六状态 = 协商中（NEGOTIATING）/ 待签署（PENDING_SIGNATURE）/ 部分签署（PARTIALLY_SIGNED）/ 已生效（EFFECTIVE）/ 已完结（COMPLETED）/ 已终止（TERMINATED，附终止类型：协商终止 / 拒签终止 / 运营方强制终止）；**发起成功即"协商中"**（"草案"为图示起始瞬态，不落地为可停留态）。已完结与已终止为终态，零出边（不可逆），留痕保留可追溯。

**协商机制（Q3）**：交替提案（当前版本提案方须待对方反提案，不得连续提案）；**每方对当前版本各确认一次**，双方齐 → 待签署；任一方新提案自动开启新版本（前版确认作废——新版本行天然重置）；**不设轮次上限**（无业务依据；协商终止随时可用兜底）。

**拒签终止（Q4）**：**未双签生效前（待签署 / 部分签署）任一方均可拒签终止**（已签方的撤回与未签方的拒签同一载体内涵；生效后不可单方动作——解除走合意，治理走强制终止）。

## 4. 数据模型方向（6 表，详细 DDL 见 hifi）

1. **contract 合约主表**：合约编号（`CO` + 6 位全局序号）/ 产品快照（id / 名称 / 属主主体编号 / 定价档 + 定价数值）/ 模板引用（template_no + template_version_no——**版本快照锁定**，模板版本行不可变保证稳定性）/ 当前条款版本指针 / 状态 + 终止类型与理由 / 生效时间与结束时间 / 合意解除双方确认时间 / 审计字段；编号唯一索引 + 双方与状态检索索引；
2. **contract_clause_version 条款版本表**：合约外键 + 版本号（合约内递增）+ **条款值密文**（槽位值 + 策略条款）+ **变更明细密文**（相对上一版的"从何值→到何值"）+ 提案方与时间 + 双方确认时间 + 锁定时的**规范化原文密文**与**内容哈希（SM3，明文）**；**（合约+版本号）唯一；版本行不可变**（修订永远新增行）；
3. **contract_signature 签署记录表**：合约 + 签署方角色（提供方 / 需求方）+ 主体编号 + DID + 内容哈希 + **签名值密文**（SM2 DER Base64 的 SM4 密文）+ 签署时间；（合约+角色）唯一；
4. **contract_attestation 存证事件表**：合约 + 内容哈希 + 双方签署要素（主体 / DID / 签署时间）+ 存证时间；（合约）唯一；链上对接归 3.8.x（预留埋点口径 = 本行事件 + 哈希）；
5. **contract_action_log 合约留痕表**：四要素（操作者 / 时间 / 合约+版本号 / 动作）+ 拒绝理由码 + from→to（版本号或状态；**不含敏感原文**——值级变更明细在条款版本密文列可查）；
6. **contract_no_seq 编号序号表**：全局 1 行原子取号（沿模板 `CT` 先例，`CO` + 6 位）。

**L3 加密承载（Q1）**：合约文本（条款值 / 变更明细 / 规范化原文）与签署记录（签名值）按 CAT-04 **L3 管控硬约束**走 SM4 密文列落库（`common-crypto` 唯一入口，ADR-006；沿 subject 证照材料密文先例）；内容哈希为不可逆摘要、明文落库（登记口径）；留痕表零敏感原文（沿全仓同源口径）。

## 5. 判定通道（三道，见 Q5/Q6）

1. **主体资格**（需求方发起 / 各写动作操作者）：复用 subject 内部端点（3.4.2 已授权 `contract-internal`，**本卡零改动**）——ADMITTED / 未入驻统一文案（防枚举）/ UNAVAILABLE 不冒充；
2. **产品事实**（发起门槛 + 定价快照）：**catalog 新增内部只读端点**（Q6-A；最小暴露 6 字段），三态 = 可用 / 不存在同形 / UNAVAILABLE 不冒充；
3. **签署能力**（解析 / 代签 / 验签）：did 既有三端点（Q5-A）——解析校验 DID 归属与状态；演示签名入口代签（服务间专用权限点）；验证端点三查验签。

## 6. 签署机制（业务口径 + 诚实边界）

- 签署内容 = **条款快照的内容哈希**（条款值 + 策略条款 + 双方 + 产品 + 模板引用的规范化序列化 → SM3 摘要；锁定（双方确认）时计算并固化）；
- 双方各签同一哈希：签名 = 主体 DID 私钥（KMS 托管、私钥不出 KMS）经国密 SM2 生成；签署前校验 DID 登记、状态有效、归属该签署方；
- **双签生效**：后签时间即生效时间；生效事务内登记存证事件；签署不可撤销（无撤回端点，生效前退出走拒签终止）；
- **验签可核**：双方与运营方可发起核验（did 三查：签名 / 状态 / 绑定），不通过按异常处置留痕；
- **诚实边界（沿 C-1.2 §6-6 / ADR-017 登记）**：V1.0 演示期签署经**平台侧代签入口**（演示开关开启）完成，签名仍为真实国密 SM2、私钥不出 KMS、不可抵赖；**生产环境该入口默认关闭**——主体侧签名通道（真实令牌 + 网关）归后续包；本卡不承诺第三方电子签资质（规格 §6-3）。

## 7. 可见性与治理（业务可读）

- **默认可见对象**：合约与协商详情、策略全文仅**合约双方**可见；非参与方（含同空间成员与其他入驻主体）读写一律"合约不存在或不可见"同形拒绝（防枚举）+ 越权探测留痕；
- **治理例外唯一**：平台运营方可查全部合约（含协商中 / 已终止）与协商过程——每次治理查看写**查看留痕**（沿目录域治理查看留痕先例）；
- **强制终止**：运营方对已生效合约可强制终止，**理由必填**、留痕含理由与操作者；被终止合约的条款随之失效（策略同步失效的执行判定归 3.4.5 引擎）；
- **服务端强制**：一切可见性与动作判定在服务端；界面隐藏不构成权限；直调接口同样受控。

## 9. 测试方向（详细计划见 hifi）

Testcontainers 实跑（`disabledWithoutDocker` 语义、Skipped 0 口径；client 桩沿 JDK HttpServer 先例）：

1. **迁移与结构探针**：6 表 + 索引/唯一键 + 取号初始值；密文列存在性；
2. **发起门槛矩阵**：未入驻统一文案 / 非在架四态 / 提供方本人发起 / 停用模板（承接-1）/ 模板不存在与版本无效 / 条款值不符框架 / 非**已上架**产品定价快照 / 幂等重放；
3. **快照稳定性**（承接-2）：模板修订 V2 后草案仍按 V1；模板停用后草案继续协商；

7. **可见性与治理**：非参与方读写 404 同形逐字 + DENIED_ACCESS 留痕；治理列表/详情 + GOVERNANCE_VIEW 留痕（实际登录主体）；直调变体；
