## 一、这卡做什么（业务语言）

合约里那份"使用限制"（次数上限 / 使用期限 / 用途限定 / 域内使用 / 禁止再分发——五要素），在 3.4.3 已经能**装进合约条款**并随双签生效了。但这套承载是**最小口径**：结构能装、基础取值能查错，还没有一份正式的"写法规范"，也没有把"什么样的策略文档算合法"这件事**收敛到一个权威判定点**。

本卡把这件事补齐，业务效果三句话：

1. **策略有了一份正式的"写法规范"（DSL v1.0）**——五要素各叫什么、取什么类型的值、什么算非法，白纸黑字且有版本号；以后写进合约的策略文档都按这份规范校验，规范演进也有据可依（这是"策略即代码"的落点：策略像代码一样有语法、有校验、有版本，而不是一段自由文本）。
2. **"什么算合法策略"只有一个裁判**——3.4.3 分散在两处的校验收拢到解析器一个点，今后任何要判定"这份策略文档合不合法"的地方（协商提交、引擎执行、界面渲染、未来的 AI 生成草稿）都问同一个裁判，不会出现两个地方判得不一样。
3. **校验从"基础"升到"完整"**——新增四类拦截：版本不认识、既声明"无使用限制"又启用了限制要素、文本前后带空白、期限起点写在过去。策略文档更干净，给 3.4.5 策略执行引擎的判定供料更可靠。

**不做什么**：策略的**执行**（放行/拦截/计数——3.4.5 引擎）、策略的**模拟执行**（3.4.6）、策略的**配置界面**（3.4.7）、AI 生成策略草稿（V1.5 C-4.6）；五要素的业务语义（哪些要素、至少一项或显式声明）**零变更**——那是 3.4.3 已验收的承载，本卡只定"写法"与"校验"。

## 三、DSL 形态（Q1：本卡最重的方向决策）

**建议口径 A：结构化声明式策略文档。**

- 策略文档 = 一份带 `dslVersion` 版本字段的规范 JSON 文档（字段集沿 3.4.3 固定字段序，兼容零破坏），由**封闭要素目录**约束合法要素集合，由**解析器**做唯一裁判。
- "策略即代码"在这里的落点 = 策略像代码一样**有语法**（规范文档）、**有校验**（解析器单点）、**有版本**（dslVersion + 演进规则）、**可执行判定**（判定语义标注供 3.4.5）——而不是"必须长成一行文本"。
- **为什么不做文本语法**：消费方盘点（引擎直读模型 / 模拟器跑结构化用例 / 界面结构化表单 / AI 生成 JSON 最稳）无一需要文本形态；自定义文本语法要配词法/语法解析器，是全仓最不平凡的实现方式，违背技术栈平庸化；文本表层如未来出现真实消费方（如自然语言之外的专家手写场景），届时作为 DSL v2 的表层语法走变更流程演进——dslVersion 机制就是为这一天留的。

## 四、与空间策略模型的"对齐复用"（Q2）

规格说"使用控制策略模型与空间域策略模型**对齐复用**（禁止两处各自定义策略模型）"，同时又说"两类策略的**业务对象不同**"。这两句合起来的正解（本卡的裁决落点）：

- **对齐的是"模式"，不是"同一份代码"**：空间域用"条目键目录注册表"模式（单点权威定义点 + 键命名规范 + 封闭值域）；使用控制侧建一个**同构**的要素目录注册表——键命名遵守同一套规范（`usage.quota` / `usage.term` / `usage.purpose` / `usage.territory` / `usage.no_redistribution`），要素集合封闭、扩要素 = 注册表追加登记。
- **不共用代码的理由**：空间策略的值系统是"封闭枚举 + 严格度排序"（放宽判定），使用控制策略的值系统是"强类型复合值"（整数/日期区间/文本/布尔）——强行塞进一个共享模型 = 抽象泄漏，且空间域没有任何消费使用控制策略的场景。两个注册表各自服务本域，**同构契约**（键命名规范一致 + 注册表模式一致 + 互不漂移评审锚）落 ADR-019 留痕。
- **两层命名分离**：目录键（对齐空间命名规范，供治理/渲染/语义标注）与文档字段名（`quota` 等，沿 3.4.3 已验收的固定字段序，兼容零破坏）是两层，映射表在 hifi §3 留痕——**文档字段名不动**是 3.4.3 验收面零回归的前提。

## 五、解析器与单点收敛（Q3）

- 解析器 = `UsagePolicyDslParser`（`domain.policy` 包）：输入策略 JSON 节点 → 输出（模型 or 违规明细清单）。**全部校验规则单点在此**。
- 收敛改造：3.4.3 三件校验（结构 / 取值 / 确认门槛）从 `UsageControlPolicy` 迁出；四个调用点（`ClauseValues` 解析、`CommandService` 发起/确认/提案）改为委托解析器；值对象保留纯数据 + 序列化（toJson/fromJson/empty）。
- 这就是 3.4.3 hifi §10-7"由 3.4.4 设计并做兼容映射，禁止两处并行定义"的**兑现动作**——收敛后全仓只剩一个"什么算合法策略"的裁判。
- 3.4.5 引擎同宿主直调解析产物（沿 QC1 先例）；若引擎设计为独立服务，届时按变更流程把本包抽 common（ADR-019 登记该触发条件）。

## 六、完整校验增强（Q4）

在 3.4.3"基础取值合法"之上新增四类（全部在提交时点拦截，拒绝码复用 C0015）：

1. **版本门槛**：文档可携 `dslVersion`；缺省容忍 = "1.0"（3.4.3 既有载荷零破坏）；**未知版本值拒绝**（fail-closed——不认识的结构绝不放行，这是"可演进"的根基：未来 v2 必须显式声明，解析器按版本分流）。
2. **互斥校验**：显式声明"无使用限制"时五要素必须全禁用——"无限制"与"限制"并存是语义矛盾（规格行为 4 规则 2 的语义推论）。
3. **文本规范化**：用途/域内文本 trim 后判空（前后空白会让 3.4.5 的等值判定漏拦——"␣风控建模␣" ≠ "风控建模"）。
4. **期限时点**：起始日不得早于提交日（规格行为 4 规则 6"期限早于生效日"在提交时点的可判定化——提交时生效日未知，"起点已在过去"是唯一可判定的非法形态；备选 B = 维持 3.4.3 起止有序口径并将时点校验登记 3.4.5）。

## 七、错误码、测试与门禁面（Q5）

- **错误码**：全部复用 1008C0015（同语义域"策略条款校验失败"），明细入服务端日志（沿 C0004/C0015 先例），不新占段位。
- **测试三面**：① 解析器单测矩阵（五要素 × 合法/非法：类型错/值域错/未知版本/互斥矛盾/文本空白/起始日过早——新校验**测试先行先红后绿**）；② 收敛回归（3.4.3 既有策略测试锚**断言零变更**全绿——夹具按需补 dslVersion 属兼容映射）；③ 集成锚（写路径四类增强拦截 + C0015 留痕 + 存量兼容读探针）。
- **门禁**：contract 模块 + 全仓既有模块回归，零门禁配置改动；解析器在合约写路径（低频业务），非网关/检索/计量类热路径——AGENTS §4 基准义务不触发（沿 3.4.3 豁免口径）。

## 九、交付后业务可读验收指引（演示口径预告，终稿随交付说明）

1. 发起/协商提交一份**带非法要素**的策略（如次数为 0、起始日写昨天、既声明无限制又启用次数）→ 被拒绝，页面/接口得到统一校验失败文案（服务端日志有明细）。
2. 提交一份**五要素合规**的策略（沿 C-4.3 剧本附录 B 预置值口径）→ 正常进入协商与签署——既有演示流程**零变化**。
3. （对照）3.4.3 存量合约的策略视图照常可读——兼容映射生效，零迁移。
