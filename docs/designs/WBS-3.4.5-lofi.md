## 一、这卡做什么（业务语言）

合约里约定的"使用限制"（次数/期限/用途/域内/禁止再分发），前两包已经能**规范地写进合约**并随双签生效了——但直到现在，它还只是"写在纸上的约定"：没有任何一个环节**真的按它拦人**。本卡把这份约定变成**机器执行的硬约束**，业务效果三句话：

1. **越界使用一律被拒、且拒得有据**——五类越界（次数用完/期限过期/用途不符/域外使用/再分发动作）都在**服务端**判定并拒绝，拒绝记录写明"谁、何时、哪份合约、触发了哪条限制、结果如何"。
2. **合规使用自动计数、双方可查**——每次放行产生使用计数；合约双方（与平台治理）随时能查这份合约"用了多少次、放行多少、拒绝多少"。
3. **合约一终止，策略立刻失效**——强制终止或完结的合约，使用尝试立即被拒（与剧本 C-4.3 S3-7 联动，承接 3.4.3 移交-5）。

**不做什么**：网络级拦截与限流（网关本体归 3.5.2——网关上线前，策略执行结论**只覆盖应用层拦截判定**，这是规格明文的诚实边界）；数据交付与沙箱执行本体（归 C-5.x——本卡交付判定入口，交付链接入时按 ADR-020 契约调用）；策略的模拟执行演示台（归 3.4.6）；策略配置界面（归 3.4.7）；按次计费对账（归 3.7.x）；链路外的"下载后线下扩散"拦截（规格 §6-4 明示不承诺）。

## 三、引擎落点与执行入口（Q1/Q2：本卡最重的方向决策）

**落点 = contract-service 同宿主**（Q1-A）：判定引擎件落 `domain.policy`（判定纯函数 + 要素判定器），应用服务 `PolicyExecutionService` 编排（QC1 消费 + 判定 + 计数 + 记录），读端点 R12 落 interfaces。理由：QC1/解析器/值对象全在本宿主，直调零跨服务开销；WBS 行 279 未要求新服务；ADR-019 §5 的迁移触发条件（引擎独立部署）在演示期不成立——真触发时按变更流程抽 common，落点决策留痕 ADR-020。

**入口 = 应用层方法，不建 HTTP 端点**（Q2-A）：`check(contractNo, UsageRequest)` —— 演示期消费方是同宿主测试与 3.4.6 模拟器（未来）；真实交付链/网关（C-5.x/3.5.2）开工后按 **ADR-020 集成契约**（方法签名 + 判定结果对象 + 错误码语义）接入，届时的端点形态（同步 REST / 内部直调）由其设计定。**现在不建端点的理由**：无真实调用方的接口 = 提前暴露未经消费验证的契约；沿 QC1"无 HTTP 端点、同宿主直调"先例。

**服务端强制**（规格行为 5 规则 3）：判定唯一权威在服务端引擎——无论调用来自界面、直调接口还是未来网关，都走同一个 `check`；"直接调用接口同样被拦截"由判定入口的唯一性天然承载。

## 四、判定怎么做（方向：顺序 + 口径）

**判定顺序**（短路前置、全查中段、计数殿后）：

1. **合约状态门槛**（QC1 快照）：合约不存在 → 防枚举口径；未生效 / 已终止 / 已完结 → 拒绝（C0013——策略随合约失效，S3-7 联动）；
2. **空策略 / 显式无限制**：无任何启用要素且显式声明无限制 → 放行、不计数（没有限制就没有违反）；
3. **期限 / 用途 / 域 / 再分发全查**：启用即判——期限 = 注入 Clock 当前日期 ∈ [起始日, 截止日]（含首末日）；用途/域 = 精确等值（3.4.4 trim 规范化保证可比性）；再分发 = 动作类型为"再分发"且要素启用即拒。任一触犯 → 拒绝（C0020，明细含全部触发要素），**拒绝零副作用**（不计数、只留痕）；
4. **配额判检一体**（仅前三步全过才执行）：单条 `UPDATE ... SET used_count = used_count + 1 WHERE contract_no = ? AND used_count < 上限`——影响行数 = 0 即"次数耗尽"拒绝（C0020）；成功 = 放行 + 计数 +1。**拒绝不烧次数**（用途不符的尝试不消耗配额——计数口径语义自洽）。

**四项未定义项落定**（Q3/Q5，承接 3.4.4 移交-1）：计数口径 = **按调用**（放行才计数）；用途/域 = **维持精确等值匹配**（词表化/多值/编码化登记不做，无消费方）；相对期限自动换算 = **登记不做**（演示载荷按绝对日期构造——3.4.4 已定）。全部落笔 ADR-020，出现真实需求走变更流程。

## 五、记录与读面（方向）

- **放行与拒绝统一入 V3 新表 `contract_usage_log`**：谁（主体号）/ 何时（注入 Clock）/ 哪份合约 / 动作类型（使用/再分发）/ 触发要素（拒绝时）/ 结果（放行/拒绝+原因码）——规格规则 5 留痕四要素口径，**不含条款原文与请求文本原文**（分级纪律，规避 L3 纠缠）。
- **计数器独立表 `contract_usage_counter`**（uk contract_no + used_count）：判检一体的载体，也是 3.7.x 未来对账的数据源。
- **R12 摘要端点**（参与方 + 治理可见，防枚举沿 R6~R11 同码同文）：本合约已用次数/上限 + 放行/拒绝计数 + 记录分页——规格规则 5"双方可查本合约执行记录摘要"的承载。

## 六、错误码、测试与门禁面（Q6）

- **错误码**：五类拦截统一新占 **1008C0020**（POLICY_USAGE_DENIED，HTTP 403），触发要素明细入拒绝留痕与服务端日志（沿"常量文案 + 明细入日志"先例）；**合约状态失效拦截复用 1008C0013**（同语义域"状态不允许该操作"）。
- **测试四面**：① 判定矩阵单测（五要素 × 生效/越界**双向** + 边界：第 N/N+1 次、期限首末日、显式无限制放行不计数、拒绝不烧次数——新判定**测试先行先红后绿**）；② 真并发配额（两线程交错第 N 次使用，总数不超限——沿 3.4.3 真并发先例）；③ 全链集成（发起→双签→生效→放行计数可查→耗尽拒绝留痕 / 终止→失效 / 再分发拦截 / R12 权限矩阵）；④ 既有 contract 158 例零回归（QC1/解析器/值对象零改动——上游已验收面零触碰）。
- **门禁**：contract 模块 + 全仓回归；判定在准热路径（未来交付链每调用一次），非网关/检索/计量级——AGENTS §4 基准义务本卡不触发（无真实调用链路可基准；3.4.8 联调时如有要求再评估，登记）。
- **分级**：V3 两表均为 L1（业务元数据，不含敏感原文）；分级规范 §6.1 回写两行随编码批。

## 七、交付后业务可读验收指引（演示口径预告，终稿随交付说明）

1. 一份次数上限 3 的生效合约：连做 3 次合规使用全部放行、计数涨到 3；第 4 次 → 拒绝，拒绝记录写明触发要素 = 次数上限。
2. 同一份合约换约定外用途 / 域外 / 再分发动作 → 各自被拒，记录可查；期间计数不涨（拒绝不烧次数）。
3. 治理强制终止该合约后再尝试使用 → 立即被拒（策略随合约失效）。
4. R12 查询：双方与治理都能看到"已用 3/上限 3、放行 3、拒绝 N"与逐条记录；非参与方查 → 防枚举同形拒绝。
5. （对照）未接入交付链期间，以上经判定入口与集成测试执行——演示入口的界面形态待 3.4.6。
