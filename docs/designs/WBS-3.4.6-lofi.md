## 一、这卡做什么（业务语言）

上一包把合约里的使用限制变成"**真会拦人**"的硬约束了——但业务人员在配置策略时仍然没有两个最需要的东西：**配置前的"试一试"**与**配置后的"验一验"**。本卡补上这两件事，业务效果三句话：

1. **配置前能试算**：给一份合约（或一份还没提交的策略草稿），模拟"如果用成这样会怎样"——放行还是拒绝、被哪条限制拦下，一次点击看到结论；**试算不改动任何数据**（不消耗次数、不留痕），可以反复试。
2. **配置后能自检（双向用例）**：一键跑"违规场景测试台"——对每个限制要素自动跑两条对照（**合规使用应放行 + 越界使用应被拒**），给出"哪条通过、哪条没通过"的报告；这是章程硬性要求的"双向用例"从纸面落到可执行。
3. **演示能动手**：合约双方可以在演示环境里**真实发起一次使用动作**——合规就放行并计数，越界就被拒并留痕；剧本 `C-4.3` 的 S2/S3 两幕从此有了正式的演示入口（此前只能由技术侧临时搭脚本）。

**不做什么**：界面（页面、按钮、结果展示归 **3.4.7** 合约工作台界面）；真实数据交付与沙箱（归 C-5.x）；网络级拦截与限流（归 3.5.2，网关未上线前不承诺网络级——规格 §6-1 诚实边界）；按次计费对账（归 3.7.x）；存证上链与埋点（归 3.8.3）；覆盖率达标与脚本级联调（归 3.4.8）；AI 生成策略（C-4.6 = P1，v1.5）；通用规则引擎/表达式求值（3.4.5 已登记的有意不做）。

## 三、形态与落点（Q1：本卡最重的方向决策）

**落点 = contract-service 同宿主，三组 HTTP 端点**（Q1-A）：

| 通道 | 端点（草案，hifi 定稿） | 语义 |
| --- | --- | --- |
| **模拟试算** | `POST /api/v1/contracts/{contractNo}/policy-simulations` | 零副作用试算（假想上下文 / 策略草稿）——**"配置前试一试"** |
| **违规场景测试台** | `POST /api/v1/contracts/{contractNo}/policy-testbench-runs` | 一键跑双向场景集 → 结构化报告——**"配置后验一验"** |
| **受控执行** | `POST /api/v1/contracts/{contractNo}/usage-executions` | 真实使用动作（计数 + 留痕）——**S2/S3 演示入口** |

**理由**：① 上游件（QC1 / 解析器 / 目录 / 引擎 / V3 两表 / R12）全在本宿主，直调零网络跳数；② WBS 行 280 未要求新服务；③ 3.4.7 界面将来在同一服务内调用这三个端点（同域，无跨服务契约负担）；④ ADR-019 §2.3 / ADR-020 §2.1 的"独立部署迁移触发条件"在演示期不触发（真触发时按变更流程抽 common）。

**与 3.4.5 的口径关系**：3.4.5 说"入口 = 应用层方法，不建 HTTP 端点"——**不是矛盾**：3.4.5 的"不建端点"理由是"无真实消费方，提前暴露未经验证的契约"；本卡恰恰**就是那个消费方与演示入口**（模拟器/测试台/剧本），端点在有了明确消费方与判定面验证之后建立，且 **ADR-020 §2.8 的集成面契约不变**（交付链仍按方法契约接入，受控执行端点是**演示期形态**，不是交付链本体）。

**分层纪律**：三端点 → 新增 `application.PolicySimulationService`（模拟服务：试算 + 测试台编排）/ 既有 `PolicyExecutionService`（受控执行，零改动）；Controller 不直连数据层。

## 四、模拟通道怎么做（Q2/Q3：核心机制）

**通道划分（本卡的核心概念）**：

| 维度 | 模拟通道（试算 / 测试台） | 执行通道（受控执行 = 真实使用） |
| --- | --- | --- |
| 副作用 | **零**（不计数、不留痕、不落库） | 计数 +1、写执行记录（复用 3.4.5 链路） |
| 计数来源 | **假想计数**（入参 `assumedUsedCount`，缺省 = 真实计数） | 数据库判检一体原子递增（真实余额） |
| 判定日期 | **假想日期**（入参 `assumedDate`，缺省 = 注入 Clock 当天） | 注入 Clock 当天（纪律不变） |
| 策略来源 | 合约当前生效策略（QC1）**或**调用方提交的策略草稿（经解析器校验） | 合约当前生效策略（QC1） |
| 拒绝表达 | **数据主体**（HTTP 200 + `allowed=false` + `violations`） | **异常**（C0020 403 / C0013 409 / C0012 404） |
| 用途 | 配置前试算、双向场景自检 | 真实使用、剧本演示 |

**为什么拒绝要分两种形态**（Q2-A 要点）：模拟是"问一句会怎样"，答案本身不是失败——若模拟拒绝也抛异常，调用方（界面/测试台）无法把"越界场景如期被拒"与"系统报错"区分开，测试台报告也无法表达"预期拒绝且确实被拒 = PASS"。因此模拟通道**参数非法才报错**（C0008/C0015/C0012），判定结论一律以数据返回。

**假想上下文为什么必要**（Q2 备选 B 的否决理由）：规格规则 4 要求"每一类策略要素：**策略生效放行 + 绕过被拒**双向用例"。要做"期限届满被拒"这条腿，必须能构造'已经过期'的判定时点；要做"次数耗尽被拒"，必须能构造'次数已用完'的计数——**若不引入假想上下文，只有两条路：真改合约期限（不可逆的业务数据）或真烧满配额（100 次调用、污染演示数据与计数）**。假想上下文把这两类场景变成纯计算，零副作用、可反复。

**配额纯判定（Q3，补齐 3.4.5 遗留缺口）**：模拟通道需要"给定假想计数 + 上限 → 是否耗尽"的判定，而现状配额只存在于数据库条件 UPDATE 中（`PolicyJudge` 不含次数）。方案 = **`PolicyJudge` 新增 `judgeQuota(policy, assumedUsedCount)` 纯函数**（与四要素判定同址，判定不散落），并登记两腿同源：

- **同源声明**（落 ADR-021）：配额语义 = "限值来源（策略 `quota.limit`）+ 耗尽判据（`usedCount >= limit`）"同一套；真实执行腿的原子递增是该判据的并发安全表达，模拟腿是该判据的纯计算表达；
- **对照一致性锚**（测试）：当假想上下文 = 真实状态（`assumedUsedCount` = 真实 `used_count`、`assumedDate` = 今天）时，**模拟结论必须与真实执行结论逐项一致**（放行/拒绝 + 触发要素集合）——这是"两腿同源"的可执行证据，含 100/101 边界。

**既有件零改动**：`judge(...)`（四要素）、`check`（判检一体 + 留痕）、QC1、解析器、值对象、R12 —— 全部行为不变（回归保护）。

## 五、违规场景测试台（Q4：双向用例的承载）

**场景集（内置，目录驱动）**：对**五要素各两向**，共 11 条：

| 场景码 | 要素 | 方向 | 构造（经模拟通道） | 预期 |
| --- | --- | --- | --- | --- |
| U1 | 次数 | 生效 | 假想计数 = 上限 − 1 | 放行 |
| U2 | 次数 | 越界 | 假想计数 = 上限 | 拒绝（次数耗尽） |
| U3 | 期限 | 生效 | 假想日期 = 起始日 | 放行 |
| U4 | 期限 | 越界 | 假想日期 = 截止日 + 1 天 | 拒绝（期限届满） |
| U5 | 用途 | 生效 | 用途 = 约定值 | 放行 |
| U6 | 用途 | 越界 | 用途 = 约定值 + 后缀（≠） | 拒绝（用途不符） |
| U7 | 域内 | 生效 | 域 = 约定值 | 放行 |
| U8 | 域内 | 越界 | 域 = 约定值 + 后缀（≠） | 拒绝（域外使用） |
| U9 | 再分发 | 越界 | 动作 = 再分发 | 拒绝（禁止再分发） |
| U10 | 再分发 | 生效 | 动作 = 使用 | 放行 |
| U11 | 空策略/显式无限制 | 生效 | 无启用要素的合约 | 放行（且不计数） |

**三态语义（诚实不假绿）**：
- 要素**未启用** → 该要素的两条场景 `SKIPPED`（不判"通过"，也不判"失败"）；
- 合约**非生效态**（未生效/已终止/已完结）→ 全场景预期改为"失效拦截"（S3-7 联动），报告标注合约状态与策略失效；
- 合约策略**五要素全启用** → 11 条全部可判（U11 转 SKIPPED 或按实际策略判定，hifi 定稿）。

**报告形态**：实时返回结构化报告（场景码 / 要素 / 方向 / 期望 / 实际（放行 + 触发要素）/ 结论 / 说明 + 汇总 `total/pass/fail/skipped`）；**零落库**（报告不是业务事件，不写 V3 执行记录，避免"自检动作污染业务流水"）。

**同源约束（承接 3.4.4 移交-2）**：场景集**不自己定义要素语义**——要素清单来自 `PolicyElementCatalog.keys()`，场景的构造与预期按要素的 `judgmentSemantics()` 解释；结构锚测试保证"目录里有的要素，场景集必须有两条"（将来加第六要素而漏配场景 → 测试红）。

## 六、受控执行与可见性（Q5/Q6）

**受控执行 = 真实使用动作**（Q5-A）：`POST /api/v1/contracts/{contractNo}/usage-executions`，把 3.4.5 的应用层判定入口产品化为受控调用端点，用于剧本 `C-4.3` S2/S3 演示（也是"直接调用接口同样被拦截"这条验收标准的直调路径承载）。要点：

- 发起方 = 认证主体（`AuthContext.subject()`），请求体只带动作类型/用途/域——**不接受"以他人身份发起"参数**；
- **无幂等键**（沿 ADR-020 §2.7：按调用计数语义下重试 = 新一次调用；需求方如需幂等自行承接）；
- 拒绝沿既有异常语义（C0020 / C0013 / C0012，由既有处理器映射）；
- **诚实边界**：演示期受控调用入口——交付链 C-5.x 上线后由 3.4.8 复核"本端点 ≡ 交付链判定面"，并决定该端点保留或收敛（登记移交-2）。

**可见性守卫抽取**（Q6-A，跟踪-17 兑现）：本卡的三个新端点都需要"合约参与方可见 + 治理可查 + 非参与方防枚举同形 + 拒绝留痕"这一套判定——加上 R12，消费方将从两份（R12 与合约查询）变为**多份**，跟踪-17 预设的触发条件（第三消费方出现）成立。方案 = 抽取**应用层共享可见性守卫**（参与方 + 治理判定 + `DENIED_ACCESS` 留痕单点），R12 与新端点共用；R12 行为**零变更**（既有可见性矩阵锚 + 防枚举同码同文断言回归保护）。

**权限点**：三端点均复用既有 `contract.deal`（合约双方的业务动作）；**零新权限点**（不新增 yml 映射）。

## 七、错误码、ADR、测试与门禁面（Q7）

- **错误码零新码位**：复用 `1008C0008`（参数非法，含假想计数/日期取值非法）、`1008C0012`（合约不存在/不可见，防枚举）、`1008C0013`（合约状态失效）、`1008C0015`（策略草稿校验不过）、`1008C0020`（越界使用，仅执行通道）；**测试台"场景未通过"不是业务错误**（HTTP 200 + 报告 `fail` 计数）。
- **ADR-021《策略模拟器与测试台契约》**：双通道语义与零副作用边界 / 假想上下文口径 / 配额两腿同源与对照锚 / 场景集与目录同源 / 报告形态与零落库理由 / 可见性与权限 / 诚实边界（演示期受控入口）/ 迁移与退役触发条件。
- **测试五面**：① 模拟判定矩阵（五要素 × 双向 + 计数/日期边界 + 草稿试算合法/非法 + 空策略）；② **零副作用锚**（模拟与测试台执行后 `contract_usage_counter`/`contract_usage_log` 零变化）；③ **对照一致性锚**（模拟 ≡ 真实执行，含 100/101 边界）；④ 测试台报告三态（全要素 / 未启用 SKIPPED / 非生效合约失效预期）+ 结构锚 2 例（目录 ↔ 场景覆盖一致；三端点无"跳过判定"入参）；⑤ 受控执行集成全链（放行计数可查 / 耗尽拒绝留痕 / 终止 C0013 / 非参与方防枚举 / 直调越界被拒）+ 既有 **196 例零回归**。
- **门禁**：contract 模块 + 全仓回归 + checkstyle 0；三端点均为演示/自检用途（无真实调用链路压力面），**AGENTS §4 基准义务本卡不触发**（登记；3.4.8 联调期如量化要求再评估）。
- **DDL / 分级**：**零 DDL**（V3 两表复用）；模拟与测试台零落库 → **零新增分级行**（分级规范 §6.1 本卡不改）。

## 八、交付后业务可读验收指引（演示口径预告，终稿随交付说明）

1. **配置前试算**：对一份生效合约，试算"期限内 + 约定用途 + 域内 + 使用动作"→ 结论"放行"；把用途改成"营销外呼"→ 结论"拒绝（用途不符）"；期间合约的已用次数**不变**。
2. **草稿试算**：提交一份"次数为负数"的策略草稿试算 → 提示策略不合法（要素校验）；换成合法草稿 → 正常给出判定结论。
3. **一键自检**：对五要素齐全的合约运行测试台 → 报告 11 条场景，**每要素都有"合规放行"与"越界拒绝"两条通过**；对只配了次数与期限的合约 → 其余要素场景显示"跳过（要素未启用）"。
4. **演示使用动作（剧本 S2）**：需求方连续发起 3 次合规使用 → 全部放行，计数涨到 3，双方与治理均可在使用摘要看到。
5. **演示越界（剧本 S3）**：换约定外用途 / 域外 / 再分发动作 → 各自被拒（提示"越界使用被拒绝"），执行记录可查且写明触发要素；治理强制终止该合约后再发起 → 被拒（策略随合约失效）。
6. **口径提示**：以上均为平台**应用层**判定（网关未上线前的诚实边界）；"下载后线下扩散"不在承诺内。
