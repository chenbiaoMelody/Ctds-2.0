## 3. 主要流程（业务语言）

1. **逛模板**：打开「合约模板」→ 模板列表（三类预置：公共数据授权 / API 调用 / 隐私计算，均为"启用中"）→ 点开详情：条款框架（每个条款项的名称、是否必填、填写说明），**没有任何数据本体**。未入驻的演示身份打开本页会被拒，提示为统一业务文案（不区分"主体不存在"，防枚举）。
2. **发起合约（需求方）**：打开「合约工作台」→「发起合约」→ 填产品编号（可点「检索产品」从目录里挑，自动回填）→ 选一个启用中的模板（自动锁定当前版本）→ 按模板条款框架逐项填写约定内容 + 配置使用控制策略（次数 / 期限 / 用途 / 域内 / 禁止再分发，至少启用一项；没有限制就勾选"无使用限制"显式声明）→ 提交 → 进入合约详情（状态"协商中"）。对已下架产品、对自己产品、被停用模板发起都会被**明确拒绝**（原样展示后端文案）。
3. **协商（双方）**：提供方打开详情 →「提案」（改条款值 / 排列策略要素），版本 +1 并留痕"从何值 → 到何值"；需求方再提案、双方先后点「确认」→ 条款锁定、进入"待签署"。谈不拢：任一方「终止协商」（二次确认）。
4. **签署生效（双方）**：A 填自己的 DID 点「签署」→ 状态"部分签署"（A 已签 / B 未签）；B 同样签署 → 合约**已生效**，生效时间 = 最后一签的时间，存证事件登记（含合约哈希与双方签署要素）；点「验签核验」逐方核对签名与身份（不可抵赖）。对方未签前可「拒签终止」；已生效后**没有**单方撤回入口（服务端强制，不可撤销）。
5. **看策略、先试一下**（"策略与使用"区）：双方可看策略全文（五要素取值）；点「模拟试算」可以"假设已用到第 100 次 / 假设日期到期限后"先试算——结论以数据形式给出（放行或拒绝 + 触发哪个要素），**不会真的消耗次数**；点「测试台」一键跑双向场景报告（每个策略要素的"合规放行 / 越界拦截"逐条 PASS/FAIL，要素没启用的如实标 SKIPPED）。页面上写明：模拟不是放行承诺。
6. **用起来**（需求方）：点「发起使用」发起一次真实使用（选动作类型、填用途与地域）→ 合规则放行并显示已用次数；越界（超次数 / 超期 / 用途不符 / 域外 / 再分发）被拒并留痕；下方"使用记录"逐条可查（含被拒行与触发要素）。次数用满后再点就会被拒——界面与直接调接口一样拦。
7. **平台治理（平台运营方）**：切档到"平台运营方"→「合约治理」→ 看全量合约（含协商中与已终止）→ 按编号直查治理详情（协商过程、签署状态、留痕）→ 对生效中违规合约填理由「强制终止」；每次查看都会留下"治理查看留痕"（合约双方在详情的留痕区能看到"某运营方主体何时看过这份合约"）。
8. **留痕核对**：合约详情带**留痕区**：发起 / 每轮提案 / 确认 / 终止 / 签署 / 拒签 / 存证 / 合意解除 / 强制终止，以及**越权访问被拒**（DENIED）与验签异常都在这里逐条可见（谁 / 何时 / 哪个合约与版本 / 动作），不含敏感原文。模板页运营区带模板维护留痕页签（含"非运营方尝试维护被拒"的拒绝行）。
9. **切换演示身份**（演示期）：顶栏沿用"演示身份"控件（主体编号 + 档位）——换主体即可扮演剧本中的 A / B / C 主体；切"平台运营方"档即可执行模板维护与治理动作。**普通档绝不携带平台角色**（否则"越权被拒"类剧本步骤会被放行，让判定失真）。

**Q5｜3.4.6 移交-1 的界面承载口径（模拟 / 测试台 / 使用动作 / 使用摘要）？**

**Q6｜合约发起 / 协商的条款与策略编辑形态？**
- **A（建议）结构化的表单编辑（框架驱动 + 值驱动两模式）+ 非法取值可提交**：
  - **发起**：条款槽位表单由模板框架（R5 `clauseFramework`）驱动——逐槽位一行（**名称 / 必填标记 / 填写说明 / 值输入框**；值 ≤2000 字符）；策略编辑器（五要素：开启开关 + 取值输入〔次数整数 / 期限起止日期 / 用途文本 / 地域文本 / 禁止再分发开关〕+ 显式"无使用限制"勾选；互斥由服务端判定，界面做**提示性**禁用与说明）；

**Q7｜承接待办：剧本界面入口核对修订 + 演示数据清理口径？**

- B 剧本只改名称路径不改承载说明（执行人按字面找不到"技术侧配合"步骤的落实方式，易误判缺陷）。

**已知风险**：
1. **越权步骤与角色头相互影响**（Q4）：若合约域角色头写错（普通档带 `admin`），模板维护类与"越权被拒"类剧本步骤会被服务端放行 → 必须由**测试锚点**钉死"普通档不含 `admin`"，走查前确认档位默认值 = 普通主体；
2. **越权类步骤的界面承载**（W15）：界面不提供"对他人合约提交写操作 / 读他人合约"的入口（安全面正确行为）→ 相关剧本步骤的承载口径（界面观察点 + 技术侧配合）须在核对修订时逐条标注并由 PO 批准，避免执行人"找不到入口"误判为缺陷；
3. **剧本界面名称漂移**：三份剧本均写"待 3.4.7 交付后核对修订" → 交付后必须一次性核对修订并提示 PO 批准，否则执行人找不到入口；
4. **同形提示口径**：`1008C0001` / `1008C0002` / `1008C0003` / `1008C0010` / `1008C0012` / `1008C0017` 等拒绝在界面上各用**同一条**提示常量与样式（防存在性探测口径一致），不得前端区分"不存在 / 无权 / 未上架 / 停用"；
5. **演示数据冲突**（Q7）：存量留置载体（`CO000008~12` 等）与剧本步骤的字面对象不一致会让"逐字执行"失真 → 清理授权与执行须在走查准备段留痕；
6. **签署 DID 取值链路**：界面不代查 DID（避免与"签署人 = 认证主体 + DID 归属校验"服务端判定歧义）→ 走查准备需先核对 A / B 双方 DID 可用（3.1.8 签发链路）并在剧本修订的承载说明中写明取值路径（「DID 管理」页）；
7. **受控执行的"演示期形态"**：放行计数会**真实消耗配额与产生留痕**（设计使然）→ 走去查前按 Q7 清理口径重置对照对象，避免续演时计数已耗尽（剧本 S2 建议 3 次合规使用）。
