## §1 做什么（业务可读行为清单，8 条）

> 每条对应规格的承载点，业务人员可据此验收；技术实现见 hifi。

1. **结果物先提交审核，才有资格导出（行为 6 规则 1；剧本 S2-5 / S3-2）**：需求方从沙箱任务的结果物里挑一份**提交审核**；提交那一刻平台给这份文件**拍快照**（大小 + 国密 SM3 校验值），状态进入"待审核"；没提交过、还在等审核的结果物**一律不能导出**。
2. **平台审核是唯一放行口（行为 6 规则 2；行为 7 规则 2；剧本 S2-6 / S2-7）**：只有**平台运营方**能审，结论只有两种——**通过**或**驳回**（驳回必须给理由）；谁审的、什么时候、什么结论、什么理由，全部留痕可查；**结论一经作出不可修改**。
3. **驳回不是死路（G2 口径，待 PO 批准）**：被驳回的结果物，需求方修改后（重跑作业覆盖产出）**可以重新提交**，进入**新一轮审核**（轮次 +1，历史全留痕）；已通过的结果物不能再提交。
4. **审核通过 ≠ 随便带走——导出仍要过策略（行为 6 规则 3；剧本 S3-1 / S3-5）**：导出前平台再问一次合约策略（用途 / 地域 / 再分发等），**越界照样拒绝**、零计数、零导出记录；沙箱不是合约的例外通道，出口也不是。
5. **导出物是加密包，全程留痕（行为 6 规则 5；剧本 S3-1）**：导出时平台把结果文件用**国密 SM4 加密**成导出包（明文 SM3 校验值随包给到），需求方凭导出记录**领取加密包**；每一次导出都产生**导出记录**（谁 / 何时 / 哪份合约与沙箱任务 / 结果物标识 / 结果），合约双方可查。
6. **导出的是"审过的那一份"（完整性复核；Q5）**：导出时平台复核文件与**提交审核时的快照**是否一致；审核之后文件又被作业覆盖（审的是版本 A、想带走版本 B）→ **拒绝导出**，必须重新提交审核。
7. **服务端强制 + 防枚举（行为 6 规则 4；行为 7 规则 1 / 3；剧本 S3-4 / S3-8）**：一切判定在服务端——绕过界面直接调接口同样被拒；非合约参与方查看 / 导出他人结果物，与"结果物不存在"**同码同文**，拒绝留痕可取证。
8. **生命周期到点，出口关闭（行为 4 规则 3 引申；剧本 S3-6）**：沙箱任务**到期或关闭后**，提交审核、审核、导出一律拒绝——环境没了，出口也没了；全程记录**不含数据本体与原文**（剧本 S3-11）。

**本卡不做（划清）**：交付管理界面与导出审批页面（3.5.6）/ 计量流水与计费（3.7.5、3.7.6）/ 上链存证（3.8.3）/ 连接器跨机构通道（3.6.x）/ 工作区与导出包的清理回收（登记演进）/ L4 双人复核审核（分级规范"待生效"口径，登记诚实边界）/ 结果物在线预览（3.5.6 界面范畴）。

## §2 不做什么（边界划清）

1. **不改 3.5.4 既有端点语义**：申请 / 详情 / 关闭 / 作业 / 结果元数据 / `/data/**` 拒绝面零改动；结果列表**只加字段**（状态 / 结论 / 理由 / 轮次），既有字段与判定不变。
2. **不改合约 / 目录域**：策略判定与参与方口径一律消费合约域回答（`check` / 摘要），1008C 结论码原码透传；**零跨域改动**（ADR-016 §6 消费方不新增）。
3. **不做第二套策略判定**：导出策略校验 = 消费 3.4.5 `check`，不另设导出专用策略口径。
4. **不自行实现密码学**：SM4 加密导出包与 SM3 校验一律 `common-crypto`（`Sm4Service` / `Sm3Service`）。
5. **不让本体进留痕**：登记 / 审核记录 / 导出记录 / 审计 / 日志 / 错误消息只含业务要素（文件名 / 字节数 / SM3 / 结论 / 理由 / 结果码）；**密文导出包是唯一带内容物**，且仅存于平台存储、密文出服务。
6. **不实现规格外功能**：不做审核委托 / 会签 / 双人复核、不做导出审批流多级、不做结果物版本树、不做在线预览、不做工作区清理（登记演进）。
7. **不改门禁配置 / 技术基线**：`gates-config.json`、`run-gates.ps1`、ADR-001 条目零触碰；零新 Maven 依赖、零新容器镜像。
8. **不擅自改剧本**：剧本缺口走变更流程（本卡登记的 G2 为规格未定义项，走 PO 批准留痕）。

### G2 规格未定义项：驳回后的后续处理（需变更流程留痕）

**事实**：规格行为 6 规则 2 只定义"审核结论 = 通过 / 驳回（驳回含理由）"，**未定义驳回之后**该结果物能否重新提交；C-5.2 剧本 S2-7 驳回后即转入 S3-3（驳回导出被拒），**无重新提交步骤**。而沙箱作业的产物文件名固定（如 `dataset-profile.md`），重跑作业会**覆盖同名文件**——若驳回即终态，需求方对该文件名永远无法再审，演示链与真实使用都会卡死。

| 口径 | 内容 | 业务影响 |
| --- | --- | --- |
| **A（建议，待 PO 批准）** | 已驳回结果物可**重新提交审核**（REJECTED → 重新提交 → 待审核，轮次 +1，全部历史留痕）；已通过不可再提交；规格 §7 决策记录表**补 G2 行留痕**（零规则文字变更——行为 6 规则与验收标准不动）；剧本步骤与业务判定**一字不改** | 驳回后"修改再审"的业务闭环成立；审核历史完整可追；无规格规则冲突（补未定义项，沿 G1 先例） |
| B | 驳回即终态（同文件名永不能再审） | 零规格动作；但重跑覆盖后无路可走，演示链（S2-7 驳回后）若需再演示通过只能换文件名，业务语义别扭 |
| C | 等规格变更后再实现 | 本卡阻塞（G1-C 同型问题） |

| 待审核中的结果物导出 | 拒绝（`1009C0016`，409） |

| 非运营方调用审核端点 | 权限层拒绝（`1000C0005`，403）；运营方读审核留痕列表 → 可查看且留痕 |

| 导出包生成 / 存储失败 | 拒绝（`1009S0003`，500），不写导出记录、不残留半成品包 |
