## 1. 做什么 / 不做什么

### 做什么（W1~W10）

- **W1 「交付记录」页**（`/deliveries`，menuOrder 17，登录可见）：过滤栏（合约编号 / 交付形态）+ 分页列表（交付编号 / 合约 / 产品 / 形态 / 发起方 / 文件名 / 大小 / 结果 / 时间）+ 行操作「详情」**抽屉**（全字段 + SM3 校验值 + 「下载加密包」按钮〔仅合约需求方 + FILE / SANDBOX_EXPORT 形态；下载后提示校验值比对〕）。
- **W2 「发起交付」弹窗**（交付记录页操作栏）：合约编号**直填 + 检索回填**（跨域只读复用 `api/contract.ts`）+ 形态单选（API / FILE）+ FILE 时文件标识 `fileId` + 用途 / 地域要素（自由填写，服务端判定）+ 必填前置拦截；弹窗实例级幂等键。
- **W3 「沙箱任务」页**（`/sandboxes`，menuOrder 18，登录可见）：过滤栏（合约编号 / 状态）+ 分页列表（任务编号 / 合约 / 产品 / 需求方 / 提供方 / 状态 / 配额 / 到期时间）+ 行操作「详情」→ 深链页。
- **W4 「申请沙箱」弹窗**：合约编号直填 + 检索回填；幂等键；G1 口径提示（仅数据集 / 报告 / 模型形态合约，API 形态拒绝——提示文案，判定在服务端）。
- **W5 沙箱任务详情深链页**（`/sandboxes/:sandboxNo`，不占菜单）：① 基本信息与**配额生命周期区**（状态 / cpus / memoryMb / ttlSeconds / expiresAt / 关闭原因 +「关闭任务」动作〔仅 RUNNING〕）；② **「沙箱工作台」区** =「运行作业」弹窗（jobId 白名单下拉 + 用途 / 地域要素）+ 作业历史分页（jobs）；③ **「结果物」区** = 结果物表（fileName / sizeBytes / SM3 / 时间 / 状态 / 结论 / 驳回理由 / 轮次）+ 行操作「提交审核」〔按 `status`：未登记 / 已驳回可提交，待审核禁用，已通过不可再提交〕与「导出」〔仅 APPROVED；导出弹窗可带用途 / 地域要素〕+ **唯一出口诚实边界文案**；④ **「导出记录」区** = exports 分页。
- **W6 「交付治理」页**（`/delivery-governance`，menuOrder 19，admin）：Tab1 **「导出审批」** = 沙箱治理列表（`/sandboxes/governance`）→ 治理详情（基本信息 + 结果物 + 审核留痕〔含轮次〕）+「审核」弹窗（结论 通过 / 驳回；驳回理由必填 ≤256 字；**结论一经作出不可修改**提示——纠错走需求方重新提交流程）；Tab2 **「交付记录治理」** = 交付治理列表（`/deliveries/governance`）+ 详情；双 Tab 均**读即留痕提示**（治理查看将产生留痕）。
- **W7 演示身份扩展**：`deliveryRolesHeader()` = 普通档 `requester,provider` 双头 + 运营档 `admin`（Q2-A）；普通档不带 `admin` 硬约束。
- **W8 幂等键传递机制**：`apiJson` 扩展自定义头入参；5 个写操作（发起交付 / 申请沙箱 / 运行作业 / 提交审核 / 导出）弹窗实例级 UUID（Q3-A）。
- **W9 转发配置**：`vite.config.ts` 新增 `/api/v1/deliveries`、`/api/v1/sandboxes` → 8087 两键（置于通用 `/api` 之前，沿先例）；`nginx.main.conf` / `nginx.container.conf` 同步新增（部署面加性）。
- **W10 剧本核对修订**：C-5.1 / C-5.2 两剧本界面入口整段核对修订 + 承载说明补充 + 未开工依赖口径修订建议（Q6-A，PO 批准留痕）。
- **（Q5-A 时）W11 后端留痕读面**：delivery 域动作留痕分页只读端点（参与方 + 治理例外；防枚举同码同文；读即留痕；零新表零新码零迁移——沿 3.4.7 R13 先例）。

### 不做什么（N1~N8）

- **N1 不做网关 API 调用链**：C-5.1 S1-2"经网关合规调用放行"= 技术侧配合项（网关 JWT 直调，归 3.9.1 真实令牌体系）；界面不模拟"调用返回数据"。
- **N2 不做"已计量"标记**：3.7.5 计量采集未开工，无数据源（剧本 S1-2 该口径 → 核对修订建议交 PO 裁决，Q6-A）。
- **N3 不触碰 `/data/**` 数据面**：服务端一律 `1009C0012` 拒绝；界面不造任何"沙箱内数据内容"入口（唯一出口 = 审核后导出）。
- **N4 不做真实登录 / 令牌 / 网关鉴权**（归 3.9.1）；不做连接器跨机构通道（归 3.6.x）；不做计量 / 计费 / 存证上链界面（归 3.7.x / 3.8.x）。
- **N5 不改后端既有语义**：22 端点零改动；唯一例外 = Q5-A 加性只读端点；零新错误码 / 零新状态枚举 / 零迁移。
- **N6 不做乐观更新 / 前端拦截业务判定**：一切判定以服务端响应为准；非法值可提交（剧本对照步骤可执行）；必填留空才前置拦截（零请求）。
- **N7 不做导出包内容预览 / 解密**：下载 = 密文落盘 + 校验值提示；解密归需求方线下（3.5.3 / 3.5.5 交付口径）。
- **N8 不夹带**：工作区清理（ADR-025 演进债）、DB-63/66 错误码分层裁决、DB-65 设计文案勘正、E2E 扩展——均按各自归属，不在本卡。

## 3. 主要流程（用户旅程概述）

1. **需求方发起交付**：交付记录页 →「发起交付」→ 选 / 填已生效合约 → 选形态（API / FILE；FILE 填文件标识）→ 填用途 / 地域 → 提交（幂等键）→ 成功刷新列表可见新记录；被拒（合约未生效 / 形态不符 / 越界）→ 后端文案原样展示。
2. **需求方领取加密包**：交付详情抽屉 → 校验值可见 →「下载加密包」→ 密文落盘 + 提示 SM3 比对。
3. **需求方沙箱全流程**：沙箱任务页 →「申请沙箱」→ 选 / 填数据集形态合约 → 详情页工作台「运行作业」→ 作业历史可查 → 结果物列表 →「提交审核」→ 状态待审核（导出禁用）→（运营审核通过后）「导出」→ 导出记录可见；被驳回 → 理由可查 →（修改后作业重跑）重新提交（轮次 +1）。
4. **提供方只读对照**：普通档主体编号切提供方 → 两列表可查（只读，无发起 / 操作面文案提示）。
5. **运营方审核与治理**：交付治理页 Tab「导出审批」→ 治理列表 → 治理详情 → 对待审核结果物「审核」（通过 / 驳回含理由）→ 审核留痕（轮次 / 结论 / 理由）齐备；Tab「交付记录治理」→ 治理列表 + 详情；读即留痕提示常驻。
6. **边界对照（剧本 S3）**：到期 / 关闭任务操作被拒（`1009C0011`）；未审核 / 已驳回导出被拒（`1009C0016`）；非参与方查看同码同文（`1009C0007` / `1009C0010` / `1009C0015`）；策略越界原码透传（`1008C0020`）。

### 待确认问题（Q1~Q7 + D1，请一次确认）

> 摘要见任务卡 §二；此处为全文与备选业务影响。

- **Q1 菜单结构与页面形态**：建议 **A** = 3 菜单 4 视图 + 1 深链（交付记录〔列表 + 详情抽屉〕/ 沙箱任务〔列表 + 详情深链页——多区块承载配额、工作台、结果物、导出记录〕/ 交付治理〔admin 双 Tab：导出审批 + 交付记录治理〕；menuOrder 17/18/19；剧本占位「交付管理」菜单在现有平铺一级菜单结构下映射为三个菜单项，核对修订时说明）。备选 **B** = 4 菜单（导出审批独立菜单——admin 菜单项膨胀，治理面碎化）；**C** = 2 菜单合并交付与沙箱（列表过滤语义混载，剧本"「交付记录」页 / 「沙箱任务」页"入口对照变差）。业务影响：A 与剧本占位口径一一对应、走查指引最短。
- **Q2 演示身份与角色头映射**：建议 **A** = 普通档 `requester,provider` **双头** + 运营档 `admin`；主体编号决定视角（服务端按合约参与方判定），一个普通档即可演示：需求方全操作（星河）+ 提供方只读对照（蓝天，S1-4）+ 提供方代发起被**业务层**拒（准确文案"发起主体唯一"，规避 DB-63/66"权限层先拦"文案失真同型问题）。备选 **B** = 普通档单头 `requester`（提供方对照步骤转技术侧——剧本 S1-4 屏幕不可执行）；**C** = 域内"需求方 / 提供方"视角切换控件（新增 UI 状态与测试面，超最小实现）。硬约束（各案相同）：普通档不得携带 `admin`。
- **Q3 幂等键前端传递机制**：建议 **A** = 弹窗实例级 UUID：写弹窗打开时 `crypto.randomUUID()`，提交随 `X-Idempotency-Key` 头（`apiJson` 加性扩展自定义头入参，既有调用零感知）；同弹窗重复提交 = 同键重放返回首次结果（剧本 S1-5 / S2-3 演示口径）；关闭重开换新键。备选 **B** = 全局拦截器每请求自动生成（键永不复用 = 幂等语义失效，剧本重放步骤无法演示）；**C** = 不传（5 个写端点全被 `1009C0005` 拒——功能不可用，不可行）。
- **Q4 发起 / 申请表单形态**：建议 **A** = 合约编号**直填 + 检索回填**（跨域只读复用 `api/contract.ts` 我的合约，沿 3.4.7 产品选择跨域先例，各带各的域角色头）；形态 / 文件标识 / 用途 / 地域**自由填写**（服务端判定，"已终止合约发起被拒""约定外用途被拒""形态不符被拒"等剧本对照步骤屏幕可执行）；必填留空前置拦截（零请求）。备选 **B** = 仅编号直填（零跨域依赖，但演示体验差）；**C** = 下拉仅列可用合约（对照步骤字面不可执行——**违反剧本可执行性，不建议**）。
- **Q5 治理留痕读面缺口（C-5.1 S3-7"查看被拒的越权探测记录"承载）**：建议 **A** = 后端新增 **1 个只读留痕读面端点**（delivery 域动作留痕分页查询；可见范围 = 合约参与方 + 治理例外；非参与方与"不存在"同码同文防枚举；治理读即留痕；**零新表 / 零新错误码 / 零迁移**——完全沿 3.4.7 R13 先例：`contract_action_log` 当时同样只有写路径）。备选 **B** = 不新增，S3-7 转**技术侧配合项**（DB / 审计文件取证——判定面仍成立，但剧本步骤"屏幕可核对"落空，核对修订时需标注）。业务影响：A 多一个后端小端点（+250~350 行含测试），换取治理留痕屏幕可见；B 零后端改动但剧本承载面缩一。
