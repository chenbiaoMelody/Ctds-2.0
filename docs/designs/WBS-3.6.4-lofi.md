## §1 做什么（业务可读行为清单，9 条）

1. **提交升级登记**：连接器属主对**已注册**连接器提交升级——填写**新版本号**并声明**兼容**或**不兼容**；平台登记一条升级记录（升级单号 `UC` + 6 位）并留痕。**升级只是登记动作**，不涉及运行中实例的在线热升级（部署动作归实施）。
2. **兼容升级立即生效**：声明兼容 → 平台**原子替换**当前版本并留痕（新旧版本号入留痕），连接器**业务动作不中断**（状态保持已注册）。
3. **不兼容升级须显式确认**：声明不兼容 → **不自动替换**；生成一条「**待确认**」升级记录，运营方**显式确认**后才替换生效（确认人与时间入留痕）；**确认前旧版本继续有效**，连接器照常工作。
4. **同连接器至多一条待确认升级**：已有待确认记录时再次提交升级 → **拒绝**并提示先处置前一条（避免版本争先、确认顺序歧义）；目标版本与当前版本**相同** → **拒绝**（无意义变更）。
5. **版本历史全链可查**：属主与运营方可查版本变更链（旧版本 → 新版本、兼容性声明、确认人〔如走显式确认〕、生效时间、提交人、提交时间），时间倒序。
6. **运营方待确认队列**：运营方可分页查看全平台待确认的不兼容升级（提交时间升序，先到先处置）。
7. **注销前置检查**：注销前检查该连接器**无进行中交付作业**；存在 → **拒绝注销**并给可读提示（请先完结或终止），状态不变且留痕。
8. **注销终态不可逆**：注销（属主或运营方发起）→ 状态 = **已注销（终态）**、记录注销时间、**DID 绑定解除但记录保留**（含解除时间）、留痕；注销后**不可发起任何业务动作**（心跳、升级、重复注销一律拒绝；身份查验 / 绑定查验如实拒绝）；连接器编号**终身不复用**，同名重新注册得到**新编号**。
9. **历史保留可查 + 生命周期聚合读**：已注销连接器的登记信息、版本链、绑定（含解除状态与时间）、在途占用、业务留痕**全部保留可查**；并提供**生命周期聚合读面**（当前状态 + 在线派生 + 版本链 + 待确认升级 + 绑定状态 + 在途占用数 + 注销时间），供运营方与下游（3.6.7 控制台 / 3.6.8 集成演练）单一来源消费。

## §2 不做什么（边界划清，10 条）

1. **不做适配器**（规格行为 11~14 归 **3.6.5 / 3.6.6**）；**不做管理界面**（归 **3.6.7**，本卡只交接口）；**不做端到端接入演练**（归 **3.6.8**）。
2. **不做运行中实例的在线热升级**（规格行为 9-1 明文：升级 = 平台侧登记与留痕动作，部署动作归实施）。
3. **不增中间管控态**：不设"停用 / 恢复"，不设"升级中 / 注销中"过程态（规格 §7 Q5-A 明文不采）；状态机仍只有 `PENDING_REVIEW / REGISTERED / CANCELLED` 三主态。
4. **不改 3.6.3 既有端点语义**：注销后"绑定查验 → `1010C0003`""内部面 → `1010C0003`""心跳 → `1010C0004`""详情 → 200"均为 3.6.3 既有读面与状态门槛的既有结果（立卡实测 `ConnectorQueryService` 101~161 / 128~146 行），**本卡零改动这 12 个端点**。
5. **不回改交付域（3.5.x）与 SDK（3.6.2）**：立卡实测交付域 `delivery` 表零连接器关联列、仅存 `result=SUCCESS` 行、`sandbox_job` 亦零连接器列、delivery 模块无 `/internal/` 端点 ⇒ "进行中交付作业"无上游可判定源。本卡在连接器域建**占用台账**承载该口径（Q2-A），**交付链 / SDK 的接入动作归 3.6.8**。
6. **不设连接器独立身份**（Q2-A 沿承）：不签发连接器 DID、不引 API Key / 证书体系；注销只动连接器档案与绑定，不动主体 DID。
7. **零加解密面、不落任何秘密材料**：本卡无凭据 / 密钥字段；留痕 `detail` 只含版本号、兼容性、状态、时间等业务要素。
8. **不做策略下发 / 本地执行、不做计量 / 存证**（规格 §4 非目标 5/6/10 沿承）。
9. **不改网关与路由、零新依赖、零门禁配置改动**：本卡端点一律服务直连（演示期回环边界，ADR-016 §2.7）；无新增 Maven 坐标。
10. **不碰演示库**（DB-64 沿承）：`ctds_connector` 结构变更由 Flyway 自建 / 演进；造数 / 清理脚本严禁对演示库执行。
