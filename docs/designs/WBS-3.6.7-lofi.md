## 1. 做什么 / 不做什么

### 做什么（W1~W10）

- **W1 「连接器管理」页**（`/connectors`，menuOrder 20，**登录可见、无权限点**——沿交付记录先例，门槛在服务端）：双 Tab + 操作栏。
  - **Tab1「注册申请」**：过滤（状态 / 关键字〔申请单号 / 连接器名称，前端过滤当前页〕）+ 分页列表（申请单号 / 连接器编号 / 名称 / 类型 / 版本 / 状态 / 最近拒绝理由 / 申请时间 / 更新时间）+ 行操作「补正」〔仅待核验〕/「撤回」〔仅待核验〕/「查看连接器」〔已签发编号时〕；顶部「申请接入」按钮。
  - **Tab2「我的连接器」**：过滤（在线状态〔本页前端过滤〕/ 关键字）+ 分页列表（连接器编号 / 名称 / 类型 / 当前版本 / 状态 / **在线** / **最近心跳** / 更新时间）+ 行操作「详情」/「上报心跳」〔仅已注册〕；在线/离线标签与最近心跳共同构成规格 §7 Q8-A 的**健康度展示**（WBS 行 307「健康度页面」的承载口径，见 Q1）。
- **W2 「申请接入」弹窗**（连接器管理页）：名称 / 类型（V1.0 仅「标准连接器」= `STANDARD`）/ 版本（`主.次.修订`）三要素；**不做前端业务预判**——留空或非法格式可提交，由服务端返回可读文案（C-6.2 S1-2「缺版本号 → 拒绝受理」依赖此口径；沿 3.5.6 N6「非法值可提交、判定在服务端」）。
- **W3 「连接器详情」深链页**（`/connectors/:connectorNo`，不占菜单）：单页分区承载——
  1. **基本信息区**：编号 / 所属主体 / 名称 / 类型 / 当前版本 / 状态 / 在线 / 最近心跳 / 更新时间 / **注销时间**（已注销时）；
  2. **健康度区**（规格 §7 Q8-A）：在线状态 + 最近心跳 + 离线阈值说明（服务端 `ctds.connector.health.offline-after` 默认 5 分钟，界面只展示服务端 `online` 字段、不本地计算）+「上报心跳」按钮〔仅属主 + 已注册〕+「刷新」；
  3. **DID 绑定区**（行为 8）：绑定状态（`ACTIVE` / `RELEASED`）+ 所属主体 DID + 建立时间 + 解除时间（已注销时）+「绑定查验」按钮 → 实时 DID 状态与 `verified` 结论（查验动作服务端留痕；失败文案原样展示）；
  4. **版本管理区**（行为 9）：当前版本 + 待确认升级提示（`pendingUpgrade`）+「升级登记」表单/弹窗〔仅属主 + 已注册〕（目标版本 + 兼容性声明）+ **版本历史链**（旧 → 新 / 兼容性 / 状态 / 确认人 / 生效时间 / 提交时间，来自生命周期聚合读）；
  5. **源接入区**（行为 11~13，**仅普通档可见**）：源清单（源编号 / 类型 / 源地址 / 凭据掩码 / 更新时间）+「登记源」/「变更」/「自检」/「查看最近自检」；政务共享交换平台**如实标注「模拟源」**；凭据**只显掩码**；Q4-A 生效时落地；
  6. **动作留痕区**（行为 1/7/8/12/13 的留痕可追溯）：分页列表（动作 / 结果 / 原因码 / 操作人 / 详情 / 时间）；
  7. **注销动作**（行为 10）：在途作业数展示 +「注销连接器」〔属主或运营方 + 已注册〕+ 二次确认；前置检查失败（`1010C0008`）文案原样展示。
- **W4 「连接器治理」页**（`/connector-governance`，menuOrder 21，**permission `connector.review`**，演示角色 admin 可见）**三 Tab**：
  - **Tab1「全平台连接器」**：状态过滤（全部 / 待核验 / 已注册 / 已注销）+ 分页列表（编号 / 所属主体 / 名称 / 类型 / 版本 / 状态 / **在线** / **最近心跳**）+ 行操作「详情」（复用 W3 详情深链，运营档视角）；在线/离线合计条 = **运营方健康总览**；Q3-A 生效时由新增只读端点承载；

### 不做什么（N1~N9）

- **N1 不做网关调用链 / 真实令牌**：C-6.1 S2 六项功能经连接器 SDK 与网关的调用属技术侧（3.6.2 / 3.6.8 / 3.9.1），界面不模拟；界面只做连接器域端点。
- **N2 不做连接器独立身份**：不签发连接器 DID / API Key / 证书，界面不出现「连接器令牌」类入口（规格 §6-2）。
- **N3 零凭据明文**：源凭据只在登记 / 变更弹窗输入（`type=password`），提交后清空；列表 / 详情 / 留痕 / 测试断言只出现掩码与不透明引用；界面不提供「查看凭据」。
- **N4 零数据本体与源数据原文**：连接器域界面只展示登记要素、状态、结论、留痕五要素；不展示任何源数据内容。
- **N5 不改 3.6.3~3.6.6 端点语义**：零新错误码 / 零新状态枚举 / 零迁移 / 零权限点 / 零 `application.yml` 改动；唯一例外 = Q3-A 的 1 个加性只读端点。
- **N6 不做前端业务判定**：状态门槛 / 可见性 / 资格 / 兼容性 / 前置检查一律以后端响应为准；仅「演示主体编号为空」前置拦截（零请求，沿 DB-41 口径）；非法值可提交、服务端文案**原样展示**（不吞、不改写）。
- **N7 不做运营方源读面**：DB-88（规格行为 12 验收 3「非本归属不可读」与既有运营方读面口径冲突）**未裁决前**，治理页与运营档详情**不展示源接入区**；服务端既有语义零改动，冲突继续挂起。
- **N8 不做内部面与在途作业代造**：`/internal/**` 端点（连接器内部读、占用登记/释放、源读取）一律不调用；C-6.2 S3-1 / C-6.3 S2 的在途作业与坏源对照由技术侧代造。
- **N9 不夹带**：DB-92（DNS 重绑定残余）/ DB-93~95（测试补强）/ DB-88（规格变更）/ 3.6.8 端到端演练 / 3.9.4 健康度监控均按各自归属，不在本卡处理。

## 3. 主要流程（用户旅程概述）

1. **参与方申请接入**：连接器管理 →「申请接入」→ 填名称 / 类型 / 版本 → 提交 → Tab1 出现「待核验」记录；被拒（未入驻 `1010C0006` / 要素不合法 `1010C0001`）→ 服务端文案原样展示 → 补正或重新提交。
2. **待核验期补正 / 撤回**：Tab1 行操作「补正」→ 预填三要素 → 提交（状态保持待核验，留痕）；「撤回」→ 二次确认 → 状态转已注销（编号未签发、无绑定）→ 同名可重新申请。
3. **运营方核验**：连接器治理 → Tab2 待核验队列 →「核验」→ 三查结论（通过 = 编号 + 绑定；拒绝 = 不通过项 + 理由）→ 队列刷新；拒绝后参与方补正重提。
4. **属主查看健康度与绑定**：连接器管理 Tab2 →「详情」→ 基本信息 + 健康度（在线 / 最近心跳 / 阈值）+「上报心跳」→ 在线变绿；「绑定查验」→ 实时 DID 状态 + `verified` 结论；失败文案原样展示。
5. **版本管理**：详情 →「升级登记」→ 目标版本 + 兼容性 → 兼容 = 当前版本立即替换；不兼容 = 待确认提示 + 当前版本不变 → 运营方在治理 Tab3「显式确认」→ 版本替换；版本历史链在详情可见。
6. **源接入与自检**：详情 → 源接入区 →「登记源」（四类；政务 = 模拟源标注；凭据密码输入、提交后仅掩码）→「自检」→ 通过 / 三类失败原因（网络不可达 / 凭据无效 / 权限不足）；「变更」→ 地址必填、凭据可留空（不变）→ 自检复验；自检结论**不构成业务授权**（提示常驻）。
7. **注销**：详情 →「注销连接器」→ 二次确认 → 成功 = 已注销终态（绑定解除、历史保留）；存在在途作业 → `1010C0008` 文案原样展示 → 完结/终止后重试；已注销档案经 Tab1「注册申请」（含全部状态）持续可查，详情仍可打开（只读）。
8. **运营方总览与注销管控**：连接器治理 Tab1 全平台连接器（状态过滤 + 在线/最近心跳）→「详情」→ 运营档视角（无源接入区、无属主动作）→ 可对已注册连接器发起注销。

## 4. 待确认问题（Q1~Q7 + D1，请一次确认）

> 摘要见任务卡 §二；以下为全文与备选业务影响。

- **Q1 菜单结构与页面形态**：建议 **A** = **2 菜单 + 1 深链**：「连接器管理」（`/connectors`，menuOrder 20，登录可见；双 Tab = 注册申请 / 我的连接器）、「连接器治理」（`/connector-governance`，menuOrder 21，`connector.review`；三 Tab = 全平台连接器 / 注册核验 / 升级确认）、详情深链 `/connectors/:connectorNo`（健康度 / DID 绑定 / 版本管理 / 源接入 / 留痕 / 注销均落详情分区）。WBS 行 307「连接器列表 / 健康度 / 版本管理页面」为**概称**，映射为：列表 = 两页清单；健康度 = 列表在线列 + 最近心跳 + 运营方总览条 + 详情健康度区；版本管理 = 详情版本区 + 治理升级确认 Tab（核对修订时向 PO 说明，沿 3.5.6「交付订单」概称先例）。备选 **B** = 3 个字面菜单（连接器列表 / 健康度 / 版本管理）——健康度与列表数据重复、版本管理须先选连接器（多一次跳转），菜单膨胀且与剧本入口对照更碎；**C** = 1 菜单内按角色混排 Tab——参与方与运营方数据面混载，治理动作误入风险高。业务影响：A 与三剧本入口一一对应、走查路径最短。
- **Q2 演示身份与角色头映射**：建议 **A** = `connectorRolesHeader()` 普通档 **`applicant`**（持 register / read / heartbeat / upgrade / cancel / source.manage）/ 运营档 **`admin`**（持 review / read / internal.read / upgrade.confirm / cancel）。主体编号决定数据视角（服务端按属主 / 运营方判定）。硬约束：普通档**不得携带 `admin`**；任何档位**不得携带 `connector-internal`**（服务身份内部面）。备选 **B** = 普通档 `applicant,admin`——权限层直接放行核验类动作，C-6.2「非运营方不可核验」对照失真（**违反测试纪律，不建议**）；**C** = 沿用全局 `demoRolesHeader()`（`applicant` / `applicant,reviewer`）——运营档缺 `connector.review` / `upgrade.confirm`，治理页全不可用。业务影响：A 用现有两个角色即可走完三剧本，零 `application.yml` 改动。
