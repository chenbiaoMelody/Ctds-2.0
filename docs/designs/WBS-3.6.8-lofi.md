## 3. 主要流程（端到端时序，业务语言）

**链 A（六门面受理，W2）**：连接器 SDK（baseUrl = 网关 8086）→ 网关普通代理路由 → subject / did / 目录 / 合约 / 交付各服务既有鉴权与业务逻辑 → 受理结果原路返回。六类动作各一次全受理 + 三条拒绝腿全拒绝；每类动作在平台对应域产生与直接操作同源的留痕。

**链 B（真实源交付，W3+W4+W6，本卡核心）**：

```
需求方经 SDK 发起 CONNECTOR 交付（合约号 + 连接器编号 + 源编号 + 幂等键）
  → delivery-service：合约摘要（申请人 = 需求方）→ 产品形态校验
  → 策略判定 contractPort.check（先判定——拒绝则终止，零触达源、零计量）
  → 签发交付编号 → 占用登记 occupy（作业号 = 交付编号；连接器须已注册——DB-75 谓词）
  → 调连接器内部源读取（携带作业凭证 jobRef + 合约号 + 用途；连接器侧四校验 + 占用核验）
      → 适配器自真实源取数（数据库 MySQL / 对象存储 / API 网关 / 政务模拟源）
  → 释放占用 release（成功 / 失败均释放，finally 兜底）
  → SM4 加密落包 + SM3 摘要 → 交付记录 + 动作留痕落库（统一事件源，计量口径不变）
  → 失败路径：业务可读错误（1009 段映射，不暴露内部实现）；已占用则先释放
```

**链 C（注销前置真实生效，W4）**：连接器存在 OCCUPY 在途记录 → 发起注销 → 拒绝（提示先完结或终止）→ 释放后注销成功。
