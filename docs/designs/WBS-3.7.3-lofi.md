## 1. 做什么 / 不做什么

### 做什么（W1~W9）

- **W1 订单后端子域（`contract-service` 内）**：迁移 V4 三表（订单主表 / 订单留痕表 / 订单编号序号表）；订单号 `OD`+6 位；`active_order_key` 生成列唯一索引（同需方同产品仅一份进行中订单）；订单状态三态 `IN_PROGRESS / COMPLETED / CLOSED`。
- **W2 订单创建（W-OR1）**：请求 = 产品 + 模板（编号 / 版本）+ 条款值 + 客户端 `requestId`；服务端复用合约发起门槛链（ADMITTED / 在架 / 异主体 / 模板 / 条款），**同事务**落订单 + 合约草案 + 双方留痕；定价快照与合约快照同源；响应含订单号 / 状态 / 合约号 / 快照。
- **W3 订单读面（R-OR1 / R-OR2 / R-OR3）**：需方 + 供方双角色「我的订单」列表与详情（B4-1 / B12-1；`myRole` 标注）；运营方治理检索（B4-2；界面归 3.7.7）；非本方同形 404 + 拒绝留痕；分页 / 状态与产品过滤。
- **W4 合约状态联动（B3-4）**：合约生效 → 订单已完成；合约生效前终止（协商终止 / 拒签终止）→ 订单已关闭，关闭原因业务可读；与合约状态转移**同事务原子提交**；订单留痕时间线（创建 / 完成 / 关闭）可读。
- **W5 合约发起复用重构**：抽 `ContractInitiationService`（`prepare` 门槛链 + `persist` 快照落库）；W5 发起端点行为 / 幂等 / 错误码零变更；订单专用通路绕开内容幂等注解（保证关闭后同内容重购生成新合约）。
- **W6 门户订购入口**：产品详情「发起订购」由禁用占位改为可用（普通档）；订购弹窗 = 选择启用模板 + 条款框架表单 + 策略编辑器（复用 `ClauseEditor` / `StrategyEditor`）+ 必填前置 + 幂等 `requestId`；成功跳转订单详情。
- **W7 门户订单界面**：新增「我的订单」菜单 `/portal/orders`（menuOrder 23，登录可见）+ 订单详情深链 `/portal/orders/:orderNo`；列表（订单号 / 产品 / 定价 / 状态 / 关联合约 / 时间 / 分页 / 状态过滤）+ 详情（快照 / 关联产品与合约 / 时间线 / 合约工作台链接）+ 空态 / 加载 / 错误态；非本方 / 不存在同形提示。
- **W8 网关与开发期转发**：网关新增 `connector-orders` 路由（`/api/v1/orders/**` → contract 8085）+ 路由测试；vite 新增一条 `/api/v1/orders` → 8085 转发键；**零新服务 / 端口 / 库 / 镜像**。
- **W9 剧本核对修订与证据**：C-7.1 转 **V1.2**（S2-1~7 + 13 界面入口与操作路径；S2-7 界面归 3.7.7、S2-8~12 归 3.7.4；业务判定一字不改，PO 批准）；复用声明 / 规格外实现声明 / 门禁证据 / 业务可读交付说明 / 台账与日志。

### 不做什么（N1~N9）

- **N1 不做产品评价**：B5 归 3.7.4；订单完成后不出现评分 / 评价入口。
- **N2 不做计量 / 计费 / 账单 / 对账**：B7~B12 归 3.7.5~3.7.8；订单不展示账单 / 用量 / 费用预估。
- **N3 不做运营管理界面**：订单治理检索仅后端（B4-2 读面语义）；账单 / 订单管理页面归 3.7.7。
- **N4 不新建服务 / 端口 / 数据库 / 镜像 / 权限点**：订单子域在 `contract-service` / `ctds_contract` 库；权限复用 `contract.deal / read / governance`。
- **N5 不做推送 / 消息 / 轮询 / 站内信**：B6 维持"留痕可查 + 主动查询"。
- **N6 不做资金 / 支付 / 退款 / 发票 / 分账**：V1.0 无资金动作（规格 §4-7；C-7.3 归 P1）。
- **N7 不改 3.7.2 门户首页与详情其他语义**：仅启用订购入口 + 新增订购弹窗；列表 / 检索 / 收藏订阅 / 不可达提示零改动。
- **N8 不改合约端点语义 / 错误码 / 既有状态机**：发起逻辑提取为行为等价重构；订单状态联动挂接不改合约状态转移；不新增合约状态。
- **N9 不夹带**：DB-88 / DB-96 / DB-97 / 3.7.4 评价 / 3.7.5+ 计量计费 / 3.8.x 存证上链均按各自归属，不在本卡处理。

## 3. 主要流程（用户旅程概述）

1. **订购**：需方 A 登录 → 「数据产品门户」→ P1 详情 →「发起订购」→ 弹窗选择模板、填写必填条款与策略 → 提交 → 成功跳转订单详情；订单 `进行中`，关联合约草案 `协商中`，定价快照与产品详情一致。
2. **重复订购（负向）**：A 对 P1 再次发起（进行中未了结）→ 被拒（1011C0001，业务可读）；进行中订单仍一份。
3. **合约衔接**：订单详情显示关联合约号 + 定价快照 +「前往合约工作台」→ 沿 C-4.2 协商 / 双签 → 合约生效 → 返回订单详情：订单 `已完成（已订购）`，时间线新增"合约生效"。
4. **终止关闭（负向腿）**：A 对 P2 发起订购 → B（供方）在合约工作台拒签 / 协商终止 → 订单 `已关闭`，关闭原因业务可读，时间线新增"合约终止"。
5. **订单查询**：A 「我的订单」→ 列表（本方订单、状态过滤、分页）→ 详情（快照 / 关联合约 / 时间线）；供方 B 可在同一读面看到与自己产品相关的订单（`myRole=供方`）。
6. **非本方（负向）**：主体 C 以订单深链访问 A 的订单 → 同形提示"订单不存在或无权查看"，不返回订单数据；拒绝留痕。
7. **运营检索（后端）**：运营方按产品 / 需方 / 状态检索全量订单（B4-2）→ 本卡以接口验证；管理界面归 3.7.7。
8. **运营档**：admin 浏览门户时订购入口保持隐藏（沿用 3.7.2 动作条显隐）；admin 不通过门户代为下单；治理读面独立权限。
9. **关闭后重购**：订单关闭后，A 以新 `requestId` 再次订购同产品同条款 → 生成新订单 + 新合约草案（不复用已终止合约）。

## 4. 决策点（Q1~Q8 + D1，2026-11-01 一次确认）

> 摘要见任务卡 §二；以下为全文与备选业务影响。

- **Q1 订单域落位与权限**：建议 **A** = `contract-service` 内新增订单子域（迁移 V4 三表 + `/api/v1/orders` 端点；同库同事务；复用 `contract.deal/read/governance`，零新权限点）。业务理由：规格把订单定义为"合约发起的业务外壳（登记 + 状态联动）"，订单与合约共用同一状态机与定价快照，放同库同服务可把"订单创建 + 合约草案"和"合约状态转移 + 订单状态"做成原子事务，不产生跨服务漂移；零新服务 / 端口 / 库 / 镜像 / 部署。备选 **B** = 新建 `order-service`（领域隔离更好，但新增服务骨架 / 端口 / 数据库 / 网关 / K8s / 演示启动项 + 跨服务一致性方案，1 会话预算不可行）；**C** = 订单并入合约表（丢失订单独立标识与"订单-合约"关联语义，不满足 B3/B4）。业务影响：A 让订购链一次交付、演示环境零新增组件；B 更"纯"但周期与风险显著上升。
- **Q2 订购交互（模板与条款）**：建议 **A** = 订购弹窗中由需方选择启用模板 + 填写必填条款 + 策略（复用 `ClauseEditor` / `StrategyEditor`），提交即订单 + 合约草案同事务落库。业务理由：C-4.1 明确"需求方选定启用模板对产品发起合约草案"，模板与产品无服务端绑定，自动选模板会替用户做出法律条款选择。备选 **B** = 一键订购自动选模板（无依据，易错配）；**C** = 先登记订单、用户另行去合约工作台发起（违背 B3-3"订单创建后即衔接合约草案"）。业务影响：A 多一步填写，但合约草案真实、可继续签署；B 快但可能产生错误合约；C 无法自动衔接。
- **Q3 订单状态联动通道**：建议 **A** = 同库写链同事务联动（新增轻量事务编排 bean，将"合约状态转移 + 订单状态更新 + 双方留痕"原子提交；失败整体回滚）。业务理由：B3-4 要求"合约生效 → 订单自动转已完成"，订单状态与合约状态不得漂移；同库同服务使原子提交成本最低。备选 **B** = 订单读时对账（零改合约写面，但未读期间订单状态滞后，运营按状态检索可能漏单）；**C** = 事件 / MQ（无既有消息中间件，超范围）。业务影响：A 订单状态始终与合约一致；B 最省事但"自动转"打折；C 引入新基础设施。
- **Q4 订单读面范围**：建议 **A** = 需方 + 供方双角色「我的订单」（B12-1 明文"需方 / 供方可查询本方订单"）+ 运营方治理检索后端（B4-2；界面归 3.7.7）；非本方同形 404 + 拒绝留痕。备选 **B** = 仅需方读面（供方订单查询后移，B12-1 未兑现；3.7.6 计费读面还要再补）。业务影响：A 一次把订单读面语义补齐，前端只展示"与我相关"订单并标注角色；B 省一点后端工作但留下规格缺口。
- **Q5 前端入口与菜单**：建议 **A** = 新增「我的订单」菜单 `/portal/orders`（menuOrder 23，登录可见、无权限点）+ 订单详情深链 `/portal/orders/:orderNo`；菜单计数 9/22 → 10/23。业务理由：C-7.1 S2-13 要求"查看订单列表与详情"，独立菜单最直观，深链可被负向步骤直接访问。备选 **B** = 不新增菜单，在门户头部加"我的订单"入口（省 1 菜单，但订单页无侧边栏归属、深链入口不自然）。业务影响：A 多 1 个菜单，换取清晰的信息架构与可验收深链。
- **Q6 订单幂等与关闭后重购**：建议 **A** = 订单端点 `@Idempotent` 键 = 需方 + 客户端 `requestId`（弹窗打开时生成一次）；订单专用发起通路绕开合约发起的**内容幂等注解**；DB `active_order_key` 唯一索引兜底并发；订单关闭后用新 `requestId` 可生成新订单 / 新合约。业务理由：合约发起的幂等键含条款指纹且 TTL 内返回首次结果——若订单直接复用该注解，关闭后同内容重购会关联到已终止合约；订单需要自己的请求幂等键。备选 **B** = 仅内容键（关闭后重购命中旧缓存，业务错误）；**C** = 不做幂等（双击 / 重试产生重复订单）。业务影响：A 既防双击又不阻断合理重购；B / C 均有业务缺陷。
- **Q7 订单状态边界（规格未明示面显式化）**：建议 **A** = 仅映射 B3-4 已定义的两条联动（生效→已完成 / 生效前终止→已关闭）；**合约生效后的完结 / 强制终止不改订单状态**（订单保持已完成，关联合约可见后续状态），不扩业务判定。备选 **B** = 生效后终止也关闭订单（规格未定义，属业务规则扩展，须走规格变更）。业务影响：A 严格按规格，订单表达"订购是否成立"；B 会让已完成订单因后续履约终止而回退为已关闭，语义混淆且超范围。
- **Q8 剧本修订与本卡验收范围**：建议 **A** = C-7.1 转 **V1.2**——S2-1~6 + 13 本卡界面验收；S2-7 运营检索**后端验证**、界面归 3.7.7；S2-8~12 归 3.7.4；业务判定一字不改，提示 PO 批准。备选 **B** = 本卡实现运营检索界面使 S2-7 可界面执行（侵入 3.7.7 范围，菜单与治理界面提前落地）。业务影响：A 保持 3.7.3 / 3.7.7 / 3.7.4 的清晰边界，S2-7 在 3.7.7 交付后补走查；B 让剧本当场全绿但超范围。
- **D1 体量 / 是否拆分**：建议**不拆分**——预估 **2200~3000 行**有效变更（任务卡 §五分解），**1 个编码会话**（WBS 行 315 = 1 人日）。理由：订单 + 合约联动 + 门户订购/订单界面 + C-7.1 S2 核对是同一走查链，拆分则 S2 断裂且产生"有订单无界面 / 有界面无后端"中间态；沿 3.3.6 / 3.4.7 / 3.5.6 / 3.6.7 / 3.7.2 界面包先例豁免 400 行上限（登记制）。
