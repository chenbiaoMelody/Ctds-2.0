## 2. 结构组成（业务视角）

```
业务系统（3.8.3 埋点后）──存证请求──▶ [存证服务 8090]
                                        │
                                        ├─ 存证台账（记录 + 状态流转留痕 + 取号）
                                        │
                                        └─ 存证网关（可插拔）
                                              ├─ 本地不可变账本（本卡默认，账本表 append-only）
                                              └─ 真实链适配器（见 Q1：本卡条件项）
运营方治理档 ──读清单 / 核验 / 重试 / 异常概览──▶ [存证服务] ──经统一网关对外──
```

- **一个服务**：`services/evidence-service`（端口 8090 / 库 `ctds_evidence`）；
- **三张表**：存证记录 / 状态流转留痕 / 账本（本地链实现用；append-only）；
- **一个抽象**：`EvidenceGateway`（上链 / 按交易标识取账本条目），换链只换适配器；
- **一段权限**：运营方治理档可读可核验可重试；业务系统只持有"内部写入"服务身份。

## 3. 主要流程

**3.1 写入（一条业务动作 → 一条存证）**

1. 业务侧提交：环节类型 / 业务单据号 / 操作类型 / 主体 DID / 事件时点 / 操作人；
2. 服务算 DID 摘要与内容摘要 → 取号 → 落库（状态 = 待上链）；
3. 调存证网关写入账本（五项）；
4. 成功 → 状态 = 已上链 + 链上交易标识；失败 → 状态 = 上链失败 + 原因摘要（**业务侧请求仍返回成功，存证失败对业务无回滚**）；
5. 同一三元组重复提交 → 返回原记录（`duplicate=true`），不新增行、不新增留痕。

**3.2 核验**

1. 按存证编号定位记录；
2. 未上链（待上链 / 上链失败）→ 结论 = **未上链** + 当前状态；
3. 已上链 → 从账本取该笔的摘要，与"按记录字段重算的摘要"及"记录里存的摘要"三方比对；
4. 全等 → **通过**；任一不等 → **不一致**，同时给出期望摘要 / 账本摘要 / 本地摘要与核验时点；
5. 无论结论如何，写一条核验留痕；记录本身一字不改。

**3.3 失败重试**

1. 运营方对"上链失败"记录发起重试；
2. 网关成功 → 状态推进为已上链；失败 → 保持失败、重试次数 +1、更新原因摘要；
3. 每次重试都追加留痕（前一条失败留痕保留）。

**3.4 演示期构造（仅演示库，剧本附录 A 口径）**

- "链不可达" = 以环境变量关闭存证网关后重启服务（无运行期后门）；
- "摘要不一致" = 受控 SQL 改动账本中一条记录的摘要值，核验后按原值还原并复验通过；
- "待上链" = 只能出现在写入途中崩溃的窗口，正常演示构造不出 → 剧本记"该态不可构造"说明（S2-5 允许）。

## 4. 决策点（待编排师一次确认）

| 编号 | 问题（业务语言） | 建议口径 A | 备选与业务影响 |
| --- | --- | --- | --- |
| **Q1** | **"真的区块链"在本卡做到什么程度？** 本机没有现成的链节点，拉镜像与接入官方 SDK 都需要先过依赖审批 | **A**：本卡交付可切换的"存证网关"抽象 + **本地不可变账本**实现（默认，零新依赖，写入 / 核验 / 失败 / 重试全链可演示）+ 真实链接入契约与部署说明；真实链 SDK 接入作为**条件项**：开工前若演示机 Docker、镜像与依赖审批都就绪则同批接入，否则登记跟踪项（不虚报"真链已对接"） | B：本卡必须真链落地 → 需要先完成镜像验证 + 依赖审批，未完成则本卡无法开工（工期不可控）；C：明确裁剪真链、全部转部署期 → 与 WBS 行 327"对接选型链"有差距，需登记变更 |
| **Q2** | 存证服务放在哪里？ | **A**：新建独立服务（8090 / 独立库）——存证是证据层，与业务库解耦，符合 ADR-004 网关抽象 | B：并入合约服务（省一个部署单元，但证据层与业务库耦合、后续四环节埋点会跨库写）；C：并入网关服务（网关职责膨胀） |
| **Q3** | 上链是"立刻做"还是"排队做"？ | **A**：**同步**写入后立刻上链，失败即置失败态、由运营方手动重试；无消息队列、无定时任务（最小实现、演示确定性最强） | B：异步队列（业务响应更快，但引入队列组件与"存证丢失窗口"，超出最小实现）；C：定时批量上链（演示不可控、失败发现滞后） |
| **Q4** | 存证编号怎么保证"终身不复用"？ | **A**：`EV` + 日期 + 6 位当日序列（如 `EV20261105000001`），取号表原子自增、**不回收不重用**；再加"环节 + 单据号 + 操作类型"唯一键防重（闭掉 3.8.1 遗留的 B1-AC2 弱闭环） | B：随机 UUID（不可读、无法人工核对顺序）；C：数据库自增主键直接当编号（跨库迁移/重建会复用，违背终身唯一） |
| **Q5** | 上链的摘要怎么算？要不要加盐？ | **A**：固定顺序串（版本头 + 环节 + 单据号 + 操作类型 + 事件时点 + DID 摘要）经 SM3；上链只放五项（摘要 + 单据号 + 时点 + 操作类型 + DID 摘要）；**不加盐**——加盐会让第三方无法独立复算，反而削弱"可核验"，且需引入密钥依赖 | B：加盐（防枚举更强，但核验方必须拿到盐，外部无法独立验证；盐泄漏即失效）；C：直接哈希原文（违反 ADR-004 白名单，S0） |
| **Q6** | 谁能看、谁能核验、谁能重试？ | **A**：新增 1 个权限点 `evidence.governance`（仅运营方治理档）承担清单 / 详情 / 核验 / 重试 / 概览；另 1 个 `evidence.internal.write` 只发给业务系统服务身份（3.8.3 用）；**不加 `evidence.read`**（参与方读面归 3.8.4 评估） | B：核验与重试拆成两个权限点（V1.0 仅治理档使用，多一个空转点）；C：复用 `contract.governance`（跨域语义错位） |
| **Q7** | 演示时怎么制造"链坏了"和"摘要被改"？ | **A**：链不可达 = 环境变量关闭网关后重启（无运行期开关、无后门）；摘要不一致 = 仅演示库受控 SQL 改账本一行 + 还原复验（剧本附录 A 口径）；"待上链"态如实登记为不可构造 | B：加一个运行期"模拟故障"端点（等于给系统开后门，违反 B4-4）；C：不做负向演示（B3-2 / B4-1 无法验收） |
| **Q8** | 验收剧本要不要改？ | **A**：C-8.1 转 **V1.2**——只补"逐步接口路径 + 演示构造口径 + 待上链不可构造说明"；**业务判定与步骤编号一字不改**，提示 PO 批准 | B：不改剧本（剧本维护说明要求核对修订，操作形态与交付不一致）；C：重写剧本（超范围） |
| **Q9** | 3.8.1 留下的两笔跟踪项怎么处置？ | **A**：① "终身不复用"由 Q4 的取号 + 唯一键**本卡闭合**（B1-AC2 转强闭环）；② `*_action_log` 段值守卫（清理脚本删除条件收敛）**不在本卡消化**，仍归 4.2.x 真链执行前；③ 若 Q1 采 A 且真链条件未就绪，新登记跟踪项（FISCO BCOS SDK 接入与真链实测） | B：本卡一并改写清理脚本（未经真链验证的破坏性语句改写，风险高于收益） |
| **D1** | 体量 / 是否拆分 | **不拆分**（预估 **2200~2800 行**，1 个编码会话；WBS 行 327 = 1 会话）。写入 / 核验 / 失败重试是同一验收链，拆则产生"有写入无核验"中间态；超出 400 行按服务包先例登记制豁免 | 拆分：两个 PR，中间态不可验收 |
