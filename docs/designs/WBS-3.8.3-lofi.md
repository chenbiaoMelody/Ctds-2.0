## 2. 结构组成（业务视角）

```
业务动作（空间准入 / 策略生效 / 合约生效 / 交付创建 / 使用放行）
        │  同一业务事务
        ▼
   业务落库成功 ──提交后（afterCommit）──▶ [存证提交客户端 common-evidence-client]
                                                │  只发六个业务字段
                                                ▼
                                  POST /api/v1/evidence/internal/records
                                                │
                                                ▼
                                  [存证服务 8090]（3.8.2 已交付）
                                     ├─ 存证记录（编号 / 状态 / 摘要）
                                     └─ 存证账本（本地不可变哈希链）
```

- **一个客户端**：`common/evidence-client`（新增平台自有模块，三服务复用）；
- **五个业务提交点**：空间 2 处、合约 2 处（含授权双写）、交付 1 处、使用 1 处；
- **零新增表 / 零迁移**：只读或回传既有留痕行的自增 id；
- **DID 三路取源**：合约存证事件（合约 / 使用）、合约内部摘要（交付）、DID 服务内部端点（空间）；
- **一段配置**：`ctds.evidence.client.*`（开关 / 地址 / 身份 / 超时），部署清单注入地址。

## 3. 主要流程

**3.1 通用提交（客户端）**

1. 业务动作在事务内完成落库；
2. 调用客户端 `record(事件)`：若当前有事务，注册"提交后"回调；无事务则立即发送；
3. 事务提交 → 组装六字段 JSON → 同步 HTTP 调存证服务（服务身份头 `evidence-internal`）；
4. 存证服务返回成功（`code=0`）→ 结束；返回失败 / 超时 / 不可达 → **只记 WARN 日志**（环节 / 单号 / 操作类型），业务响应不受影响；
5. 事务回滚 → 回调不执行，**不产生存证**。

**3.2 各环节触发点**

| 环节 | 业务动作 | 触发条件 | 业务单据号 |
| --- | --- | --- | --- |
| 授权 | 空间成员准入 | 审批通过 / 邀请确认，成员行与准入单同事务成功 | `SPACE{空间id}:ADMISSION{准入单id}` |
| 授权 | 空间策略生效 | 覆盖提交成功（`POLICY_OVERRIDE`），同值无操作不触发 | `SPACE{空间id}:POLICY-AL{留痕行id}` |
| 授权 | 公共数据授权类合约生效 | 合约双签生效 + 模板类型 = 公共数据授权 | `contract_no`（逐字一致） |
| 合约 | 合约生效 | 合约双签生效（`contract_attestation` 落库） | `contract_no`（逐字一致） |
| 交付 | 交付记录创建 | 交付行落库成功（幂等重放不触发） | `delivery_no`（逐字一致） |
| 使用 | 使用控制放行 | `contract_usage_log` 放行行落库成功 | `USG{12 位放行留痕 id}` |

**3.3 拒绝 / 无操作 / 回滚（零事件）**

- 空间：红线放宽拒绝、同值幂等、权限拒绝、状态门槛 → 零事件；
- 合约：首签未生效、重复签署、状态冲突 → 零事件；只有 `EFFECTED` 才发；
- 交付：参数 / 形态 / 准入 / 判定失败、幂等重放 → 零事件；只有真实新建成功才发；
- 使用：状态失效、越界、配额耗尽 → 零事件（拒绝留痕仍在 `contract_usage_log` DENIED 行）。

**3.4 主体标识取不到时（诚实降级）**

- 空间：DID 服务未配置 / 不可达 / 主体无 ACTIVE DID → 跳过该条 + WARN；业务成功不受影响；
- 交付：合约内部摘要未回 `requesterDid` → 跳过该条 + WARN；
- 合约 / 使用：合约存证事件缺双方 DID（理论不应发生）→ 跳过该条 + WARN；
- 跳过属"存证缺失"，不在本卡补造；登记为可见缺口，审计视图（3.8.4）可据日志核对。

**3.5 演示期口径**

- 演示前先启动 evidence-service（8090）与 did-service（8082）；空间成员准入 / 策略生效 / 合约双签 / 交付 / 放行各做一次，存证总览对应环节各 +1；
- 存证服务停止时做业务动作：业务仍成功，日志出现 WARN，存证总览无新增——用于演示"存证与业务解耦 + 失败可见"（对应剧本 S2-4 的调用侧版本）；
- 不提供运行期"模拟失败"开关；不使用假 DID / 假单号构造。

## 4. 决策点（待编排师一次确认）

| 编号 | 问题（业务语言） | 建议口径 A | 备选与业务影响 |
| --- | --- | --- | --- |
| **Q1** | 三个服务都要"提交存证"，代码放哪？ | **A**：新增平台自有 `common/evidence-client` 模块，一处实现三处复用（根 pom 20→21，零新第三方依赖） | B：塞进 `common-logging`（少一个模块，但"存证"与"日志"混在一起，且空间 / 合约要新增对日志模块的依赖）；C：三服务各写一份（违反横切收敛，后续改口径要改三处） |
| **Q2** | 授权环节上游没有业务单号，存证单号怎么定？ | **A**：用上游留痕行主键派生可读键：`SPACE{空间id}:ADMISSION{准入单id}`、`SPACE{空间id}:POLICY-AL{留痕行id}`；合约用 `contract_no`。零迁移、可反查 | B：给上游表加"业务单号"列并取号（3 张迁移 + 第二套编号体系，违反"不新增第二套业务口径"）；C：UUID（人工无法从单号看出是哪笔业务，审计定位困难） |
| **Q3** | 使用环节的单号：剧本写"计量流水源单号"，但放行时点拿不到 | **A**：用"放行留痕单号"`USG{12 位}`，剧本 V1.3 把该括号说明改为"使用放行留痕单号"（判定"逐字一致"不变） | B：改用计量流水源单号（要把埋点挪到网关 + 计量采集 + 合同三处，异步且有演示端点缺口）；C：两处都埋（一次使用两条存证，重复） |
| **Q4** | "空间策略继承"在代码里没有批量写动作，怎么落？ | **A**：以"策略覆盖提交成功"承载（空间策略相对平台策略生效，一次一条；同值不触发） | B：新增"空间启用时批量继承平台条目"（新业务行为 + 批量留痕，超本卡，需规格变更）；C：不埋（授权环节少一类覆盖，剧本只能验成员准入） |
| **Q5** | 公共数据授权类合约生效，算一条还是两条存证？ | **A**：两条——授权环节"授权类合约生效" + 合约环节"合约生效"，同编号不同环节（结构不冲突） | B：只落合约（授权环节对这类合约缺覆盖）；C：只落授权（合约环节缺覆盖） |
| **Q6** | 空间 / 交付没有 DID，主体标识从哪来？ | **A**：合约 / 使用用本域合约存证事件；交付用合约内部摘要新增需方 DID；空间调 DID 服务内部端点（仅新增一个只读角色映射）；取不到跳过 + 告警 | B：空间 / 交付都调 DID 服务（交付多一处权限与客户端）；C：拿主体编号冒充 DID（格式与语义都不对，不可采） |
| **Q7** | 存证调用放事务里还是提交后？失败怎么办？ | **A**：提交后调用；失败不回滚业务、只告警；无队列无补偿（登记跟踪项） | B：每服务加 outbox + 定时补偿（强一致，但 4 个库改造 + 调度，建议另立卡）；C：事务内调用 / 失败回滚业务（可能给回滚的业务留下假证据 / 违反解耦） |
| **Q8** | 开关与默认地址怎么定？ | **A**：默认开启；地址默认空 = 跳过 + 告警，部署清单显式注入；测试默认不打网络 | B：默认本机 8090（漏配也能用，但所有既有集成测试会真实打网络、拖慢门禁）；C：不设开关 |
| **Q9** | 验收剧本要不要改？ | **A**：C-8.1 转 V1.3（S1 真实业务触发 + 单据号口径对齐；业务判定与步骤编号不变） | B：不改（S1-5 无法执行）；C：重写（超范围） |
| **Q10** | 3.8.2 的跟踪项怎么办？ | **A**：顺带闭合 DB-113 P3-4（补六类操作类型正向测试）；真链 DB-115 与 DB-114 不动；新登记"调用侧不可达窗口" | B：把 DB-113 / DB-114 全部消化（超范围）；C：不处置（继续挂账） |
| **D1** | 体量 / 是否拆分 | **不拆分**（预估 1400~1800 行，1 个编码会话；四环节是同一验收链，拆则中间态不可验收） | 拆分：两个 PR，中间态"授权有存证、交付无存证"不可验收 |
