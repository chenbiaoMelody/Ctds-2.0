## 一、一句话方向

> 把"三个管理员各管各的、不能互相越界"从**规格和剧本里的纸面约定**变成**平台真正执行的权限映射**：三员角色真实生效、权限授予/收回可追溯、`admin` 不再同时握着审计读面与授权权，而整套判定仍走原来**唯一的那一个内核**。

**为什么必须做**（立卡实测事实，均附证据）：

1. **三员只存在于文档**：`platform.sysadmin` / `platform.secadmin` / `platform.audadmin` 在代码与配置中零命中（仅规格:203/:208、台账:155、卡 3.9.1:41 文字）；B2 分立目前只靠 C-10.1 S1 人工验收保证。
2. **`admin` 与 Q2-A 相反**：实测 9 服务 `application.yml` 中 `admin` 同时持 `evidence.governance`（evidence:35，审计读面）、`connector.review`（connector:29，授权/核验写面）、`kms.admin`（kms:45）及各域 governance 写面 → B2-4「三类关键点两两不重叠」与 B8-R3 不成立；C-8.2 剧本监管档亦为 `admin`（:45）。
3. **映射只有配置、没有库表留痕**：`ConfigRolePermissionMapper` 解析 `ctds.auth.permissions.<角色>`；规格:47-48 明写 3.9.2 覆盖 `RolePermissionMapper` Bean 换库表、落库后由库表留痕承载，当前均无实现。
4. **两个权限点未分离**：健康总览与核验写面共用 `connector.review`、`connector.health.read` 零实现（DB-120 ⑤，B6-R3）；`kms.admin` 与授权类审批同持（DB-120 ⑥，规格:195）。
5. **DB-120 六项无承接包**：台账:155 明写 ①⑤⑥ 归 3.9.2、② 归 3.9.2 / 收口批、③④ 归部署期 / V1.5；卡 3.9.1:76-77 记"默认随 3.9.2 承接"。

## 二、三个交付面（业务可读）

| 面 | 交付什么 | 谁能验、怎么验 |
| --- | --- | --- |
| **面 1：三员真正生效** | 三个平台角色的权限点映射落库；`RolePermissionMapper` 换库表来源（判定内核零改动）；`admin` 按 Q2-A 撤除审计读面 / 授权类 / 运维写面 | 用三枚演示身份分别调用配置 / 授权 / 审计读面端点：本职成功、另两职被拒；C-10.1 S1 十三步可逐步走查 |
| **面 2：授权可追溯** | 权限授予 / 收回端点 + 变更留痕（变更人 / 时点 / 角色 / 权限点 / 前后值）；权限清单只读读面 | 授予后同一角色访问面变化、收回后恢复被拒；每次变更能查到一条留痕（B1-3 / B1-4） |
| **面 3：分离与收尾** | 拆出只读 `connector.health.read`；`kms.admin` 与授权类审批分离；DB-120 六项逐条处置或登记；ADR-005 / ADR-011 正文回写（走变更流程）；C-8.2 演示身份切换 + C-10.1 操作路径落定（**待 PO 批准**） | 结构断言：三类关键点两两不重叠、健康总览只读点与核验写面不同持、平台角色不同持 `kms.admin` 与授权权；台账债务行状态变化逐条可核 |

**"三员分立"到底怎么算过关**（本包最核心的一句业务判定）：

> 任一平台角色不得同时持有「业务配置」「权限授予」「审计读面」三类关键权限点中的两类以上；`kms.admin` 不得与「权限授予」同持；`admin` 不再持审计读面 / 授权类权限点 / 运维写面。且以上全部由**同一个** `DefaultAccessControl` 判定内核执行——**只换映射，不写第二套校验**（规格边界 2）。

只验"三员能登录/能调用"不算过关——那无法排除越权与两套权限体系。

## 四、不做什么（边界，写死）

1. **不做账号体系、登录、会话与令牌签发**（Q3-A；账号表 / 登录端点 / JWT 签发归部署期 / V1.5；G-09 顺延）。
2. **不做库内多租户**：不新增 `tenant_id` 列与租户表（Q1-A）；租户生命周期归 3.9.3。
3. **不改权限判定内核**：`DefaultAccessControl` / `PermissionInterceptor` / `@RequirePermission` 语义零改动，只覆盖 `RolePermissionMapper` Bean（规格边界 2 / ADR-005 行 37）。
4. **不新增规格外权限点**：新增权限点**仅限** `connector.health.read`（规格边界 8），且须在连接器域任务卡登记；角色值域封闭，新增角色走变更流程。
5. **不做角色管理界面**（归 3.9.5）、**不做指标接入 / 告警外发**（归 3.9.4 / 生产扩展点）、**不做 C-10.3 / C-10.4 / C-8.3**（P1/P2，章程:75）。
6. **零新第三方依赖、零门禁配置改动、零迁移超出本包映射留痕所需最小集、零演示库既有数据改动**；**不改他域剧本业务判定**（C-8.2 仅演示身份与操作路径，须 PO 批准）。
