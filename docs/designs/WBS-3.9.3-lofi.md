## 一、业务目标（一句话）

把"这套平台是谁、什么版本、开着还是停了"变成**平台自己能声明、能校验、能执行**的能力：系统管理员读"部署域信息"读到唯一事实；配置与实际不符时平台明确报错不装正常；退役态业务请求被明确拒绝而数据与审计分毫不动、可恢复；每次开通/升级/退役三证可查。

## 二、三个交付面（方向）

### 面 1：部署域信息只读读面（B9-R1/R2 → S3-1/S3-2）

- **给谁用**：系统管理员（`platform.sysadmin`，只读权限点 `platform.domain.read`）；业务角色一律被拒（403 + `1000C0005`，B3-2 同码同文）。
- **给什么**：部署域标识 / 名称 / 平台版本 / 生命周期状态（`ACTIVE`/`RETIRED`）/ 库 schema 清单 / 服务清单 + 配置校验结论；另明示"V1.0 = 单实例单部署域"口径行（S3-2）。
- **放哪**：evidence-service（平台管理读面既有落点，Q1-A）；端点与响应契约见 hifi §2。
- **不做什么**：不做任何写面、不做在线生命周期 API（Q11-A）、不做界面（归 3.9.5）。

### 面 2：配置校验 fail-closed 与退役拦截（B9-R4/R6 → S3-4/S3-5/S3-7）

- **配置从哪来**：声明式 Spring 配置 `ctds.domain.*`，部署清单 env / 配置文件注入（Q3-A）；**缺省 `ACTIVE`**——不配置 = 现状零变化（既有演示链零影响）。
- **校验怎么做**：evidence 启动时校验自身数据源 schema ∈ 清单，不一致 → **启动失败**（fail-closed，S3-4 演示路径）；全量 schema/服务清单一致性 = 部署脚本扩展 + runbook（B9-R4 原文口径，Q6-A）。
- **退役怎么拦**：`common/auth` 横切组件双适配（Q2-A）——11 业务服务 servlet 过滤器 + gateway WebFilter（统一入口，CHG §3 防绕过）；`RETIRED` 时业务请求 503 + `1013C0004`；豁免面 = 配置化路径模式（健康读数 `/actuator/**` + evidence 审计读面 + 部署域读面自身）；恢复 `ACTIVE`（配置翻回 + 滚动更新）后业务自动恢复（S3-7）。
- **不做什么**：不改判定内核（`DefaultAccessControl`/`PermissionInterceptor` 零改动）；不删任何数据/审计记录（B9-R6 禁令）。

### 面 3：生命周期留痕与部署承载（B9-R3/R5 → S3-3/S3-6/S3-8）

- **动作怎么执行**：开通 = 首次部署基线（当前演示域即为已开通，剧本口径诚实声明）；升级/退役/恢复 = 配置变更 + 滚动更新，按 runbook 执行；**每次动作登记变更单编号与操作人**（配 `ctds.domain.change-order`/`operator`）。
- **留痕三证**（Q5-A，不新增表）：变更单（人工登记）+ 部署记录（runbook 操作段 + 脚本输出，含前后版本与状态）+ **启动审计事件 `domain.lifecycle`**（经既有 `AuditRecorder`，仅当变更单编号+操作人齐备时触发）。
- **部署脚本扩展**（D2 100~200 行）：全量 schema/服务清单一致性校验 + runbook 部署域操作段（升级/退役/恢复三动作步骤）。
- **不做什么**：不新增配置变更记录表（B9-R5 为"若新增"条件句）；不承诺多实例自动开通（非目标 4）。

## 四、边界（不做什么，汇总）

1. 不新建租户表、不新增 `tenant_id` 列、不做库内租户维度（Q1-A/Q10-A）；
2. 不提供在线生命周期 API，不做多实例自动开通（Q11-A / 非目标 4）；
3. 不新增第三方依赖、不新增前端改动（界面归 3.9.5，DB-128 不承接）、不改门禁配置、不改判定内核；
4. 不新增写权限点（生命周期无在线写面，Q13-A）；错误码仅 1013 段顺延两值（Q4-A）；
5. 不删数据、不以退役为名删审计记录（B9-R6 禁令）；
6. 不改 C-10.2 剧本与其它域文档；剧本只做端点回填与陈旧勘正（业务判定零变更，PO 批准）。
