## 一、业务目标（一句话）

把"平台跑得怎么样、连接器在不在线、出了什么告警、告警谁处置了"变成**平台自己能读、能标注、能处置、能留痕**的能力：系统管理员在一处读到四区块读数（未接入的服务如实标注"未接入"，绝不显示为 0 或绿）、读到要素齐备的告警列表（触发与恢复双向可辨），并经由唯一鉴权 + 留痕入口处置告警；连接器健康度三态在后端显式，"从未上报"不再以空值冒充。

## 二、三个交付面（方向）

### 面 1：指标接入（B5-R1 → S1-2）

- **给谁用**：Prometheus（监控栈自动发现）与读面抽查载体；**给什么**：12 个平台服务（11 业务 + gateway，范围随 Q2 裁决）全部具备 actuator + micrometer-registry-prometheus 依赖、exposure 收敛 `health,prometheus`、（集群内）Pod 三注解抓取。
- **怎么做**：ADR-014 :36 原文口径"新服务接入 = 2 依赖 + 3 注解，零 Prometheus 配置改动"——依赖已登记（dependencies.md :24-25，PO 预授权），批量机械接入；example 零改动（样样板）；did/kms/subject 半接入补齐。
- **诚实口径**：接入（代码与配置在库）≠ 采集（部署形态）——subject/connector/did/kms 无 k8s 清单（runbook §3.1 本机演示启动），集群外部署不纳入集群内抓取，读数如实呈现"未接入"；暴露面核对（S1-2）以配置为准，采集状态以读面实测为准。
- **不做什么**：不动 Prometheus/Alertmanager/Grafana 配置与部署（k8s-monitoring 清单零改动）；不扩告警规则（封闭两条）；不加集群层指标（node-exporter 等归 ADR-014 :16 后续增强点）。

### 面 2：监控读数与告警列表读面（B5/B7 → S1-1/S1-3/S2-1/S2-3~S2-5）

- **给谁用**：系统管理员（新只读权限点 `platform.monitor.read`，Q3-A 仅授 `platform.sysadmin`；无权限 403 + `1000C0005` 同码同文）。
- **给什么**：`GET /api/v1/platform/metrics` = 逐服务四区块读数（服务存活 / JVM 堆内存与 GC / HTTP 速率 / 5xx 错误率与 P95——ADR-014 :54 四区块**原文口径**），未接入服务显式"未接入"标注（B5-4），读数与 `/actuator/prometheus` 同源（都来自 Prometheus，B5-2 抽查一致由构造保证）；`GET /api/v1/platform/alerts` = 两规则渲染为固定告警项，要素七项齐备（告警名/级别/对象/触发时点/当前值/阈值/状态），状态映射 = firing→已触发、pending/inactive→已恢复（B7-R1 本卡落定，Q4-A）。
- **放哪**：evidence-service（Q1-A，平台管理读面既有落点）；数据源 = Prometheus HTTP API（JDK HttpClient 先例，BASEURL env 注入默认空 fail-closed → 503 + `1013S0003`）。
- **不做什么**：读数只读（无指标写入/篡改/伪造入口，B5-3）；不做告警外发（G-04 待生效）；不做数据持久化与留存（ADR-014 v1 边界 + G-07 待生效）。

### 面 3：运维处置与健康度三态（B8/B6 → S2-6/S2-7/S2-8 + S1-4）

- **处置怎么落**：`POST /api/v1/platform/alerts/actions`（权限点 `platform.alert.handle`，Q3-A 仅授 sysadmin）= **唯一鉴权 + 留痕入口**（B8-R1 处置通道唯一性）——静默 = 转发 Alertmanager `POST /api/v2/silences`（silenceId 入留痕）；确认/升级 = 平台留痕型动作（不改变告警引擎状态，v1 路由空 + 外发未接诚实标注"待生效"）；三动作均留痕四要素（处置人/时点/对象/结论），载体 = `AuditRecorder` 事件 `alert.dispose`（零新表，Q7-A）；处置对象 = 封闭两规则名，未知名 400 + `1013C0005`（Q8-A）。
- **健康度三态怎么落**：connector-service 治理读面**加性字段** `healthStatus`（ONLINE/OFFLINE/NEVER_REPORTED，读时派生沿 B6-R2 既有逻辑）——既有 `online` 布尔零破坏（前端既有页零影响），"从未上报"后端显式化（B6-R1），前端展示归 3.9.5。
- **不做什么**：无删除入口（B8-R2 零 DELETE）；不做处置外发与升级通知（G-04）；不新增处置记录表（Q7-A）；不改健康度判定内核与 `offline-after` 语义。

## 四、边界（不做什么，汇总）

1. 不扩/不改告警规则（封闭两条，B7-R2 + ADR-014 :46/:90；容量类阈值取值设计落定登记不实现规则，Q5-A）；
2. 不动监控栈部署面（monitoring.ps1 / deploy/k8s-monitoring 清单零改动；ADR-014 :36"零 Prometheus 配置改动"承诺兑现）；
3. 不新增第三方依赖（actuator/micrometer 已登记 PO 预授权；客户端走 JDK HttpClient）；不新增前端改动（界面归 3.9.5，DB-128 不承接）；
4. 不做告警外发通道（G-04）/ 集中日志与留存（G-07）/ 数据持久化 / 集群层指标 / AIOps（C-10.4）——全部"待生效"诚实标注；
5. 不新增处置记录表与登录令牌（Q7-A / 规格 Q3-A）；错误码仅 1013 段顺延两值（Q8-A）；
6. 不删任何监控/告警/审计数据（B8-R2）；不改健康度判定内核、`offline-after` 语义与既有 `online` 字段（加性原则）；
7. 不改门禁配置；剧本只做操作路径回填与陈旧事实勘正（业务判定零变更，PO 批准）；发现规格缺口走变更流程。
