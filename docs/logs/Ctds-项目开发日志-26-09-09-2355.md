## 附录：业务可读交付说明（WBS 2.4.7，供 PO 业务验收）

**完成了什么**：平台新增"幂等"与"分布式锁"两个公共组件（common-idempotency），业务代码一行注解即可获得能力——`@Idempotent`（同一订单号/业务键重复提交只处理一次、第二次直接返回首次结果）与 `@Locked`（同一商品的并发操作排队执行、不超卖）。默认基于 Redis（生产），另配内存模式（演示/单测/单机部署零中间件）。配套 example-service 两个演示端点 + ADR-007 契约 + 4 视角评审处置。

**如何演示（5 项）**：
1. 启动：`cd services/example-service && mvn spring-boot:run`（内存模式，无需 Redis）；
2. **幂等演示**：连续两次 POST `/api/v1/demo/orders` 提交同一订单号（如 {"orderNo":"ORD-001"}）——两次返回结果完全一致（订单号/状态/创建时间），第二次不重复创建（组件保证）；
3. **互不影响**：提交不同订单号（ORD-A / ORD-B）→ 各自独立返回，两条订单都创建成功；
4. **锁演示**：并发 20 次 POST `/api/v1/demo/stock/deduct` 扣同一商品（{"productId":"P001","quantity":1}）——全部成功且库存恰好扣 20（初始 100，剩 80），不超卖（无锁时非原子读改写会超卖）；
5. **拒绝面**：扣 1000 件 → 400"库存不足"（1000C0001）。

**注意事项**：① 演示走内存模式（application.yml 已配 mode=memory），多实例生产部署必须 mode=redis（组件默认，需引入 redisson 依赖并配置 Redis 连接）；② 幂等结果缓存默认 10 分钟 TTL，过期后同键可重新执行；③ 幂等/锁键由业务指定，建议含租户/业务命名空间且不可枚举（ADR-007 §4-④）；④ 集成测试 4+4 条与组件 63 条单测已全绿，门禁 GREEN（密钥扫描 0 命中）。
