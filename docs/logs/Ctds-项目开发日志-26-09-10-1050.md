## 当前续点（新会话从这里继续；续接会话承接本块另建新日志）

- **已完成（排查结论）**：
  1. Watt Toolkit（进程 Steam++.Accelerator）用 hosts 把 github 域名改写为 127.0.0.1，本地监听 **0.0.0.0:80/443** 转发（Windows hosts 含 github.com 等 20+ 域名条目）；
  2. WSL2 有独立网络命名空间：WSL 的 /etc/hosts 每次实例启动自动重建（追加行不持久），且 WSL DNS 转发应用 Windows hosts → github.com 解析 127.0.0.1（WSL 自身 loopback，无服务）→ git 直连超时；
  3. 打通路径：WSL 经 **Windows 宿主 IP（默认网关 10.155.113.254）:443** 访问加速器 → 单实例内追加 /etc/hosts（github 域名 → 10.155.113.254）+ git config http.sslVerify false（加速器自签证书）+ safe.directory（root 运行 git）→ **git 能连上 github.com**（网络/TLS 通）；
  4. **最终阻塞**：github.com 深层路径全部 404——curl 对照测试：`/octocat/Hello-World`（已知公开仓库）与 `/login` 页面均 404、`/chenbiaoMelody/Ctds-2.0.git/info/refs?service=git-upload-pack` 与 octocat 同路径均 404（响应体 size=9，中间层简单 404）→ **加速器对 github.com 的转发只响应根路径 301，深层路径（git 协议必需的 info/refs）不可达**；git push 报 `repository not found` 即此 404 所致，不能据此判定仓库不存在。
