### 业务可读交付说明

- **完成了什么功能**：给平台的集成测试装上"自动化真实验证"能力——以前验证"程序+真实数据库"协作要靠人工起容器、手工跑流程，现在测试运行时自动拉起一次性真实 MySQL 8 容器（随机端口随机口令，测完自动销毁），原来的条件测试（环境变量门控）升级为全自动；原来人工演练的两个安全护栏场景——"乱版本的脚本会被拒绝""已执行的脚本被人偷偷改过会报警拒绝启动"——从此每次跑测试都自动回归。写法规范固化为 ADR-010，后续所有业务服务的集成测试照此办理。本机没开 Docker 时这些测试自动跳过、门禁照常全绿，自动化程度只升不降。
- **如何演示**：确认 Docker Desktop 运行中 → `cd services/example-service && mvn -B -ntp test` → 输出末行 `Tests run: 46, Failures: 0, Errors: 0, Skipped: 0` + `BUILD SUCCESS`（其中 FlywayGuardrailTest/FlywayMigrationTest 4 用例为真实容器执行，各约 24-48 秒；测试结束后 `docker ps` 无残留容器）。对照演示：停掉 Docker Desktop 再跑同命令 → 容器化 4 用例标记 skipped、其余照常全绿。
- **注意事项**：① 有 Docker 态下全量测试耗时增加约 75 秒（3 个容器先后起停），Windows 下收尾出现 "Surefire is going to kill self fork JVM" 警告属 JVM 退出时序噪音，BUILD SUCCESS 不受影响——未来 2.5.x CI 配超时阈值需计入此开销（评审④留痕）；② 护栏测试会在系统临时目录残留 ctds-flyway-* 目录（无敏感内容，评审②④一致判定留观察项，不阻塞）；③ 验收剧本建议：无集成测试节点，无需更新；如 PO 认可可增补"容器化集成测试演示"节点；④ 2.4.10 演练容器 ctds-mysql-demo 与本任务无关，仍待您验收后处置。
