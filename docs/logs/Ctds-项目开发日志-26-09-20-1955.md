### 问题与教训

1. **第一次门禁调用是"假执行"**：Git Bash 下 `-File scripts\\gates\\run-gates.ps1` 的双反斜杠被吞成 `scriptsgatesrun-gates.ps1`，PowerShell 报"参数不存在"而管道 `| tail` 让退出码变成 **0**——若不看输出，会得到一个"GREEN"的假结论。**教训：门禁类命令一律核对报告文件是否真的新增（`ls -t scripts/gates/reports/`），退出码不等于结论**（与既有"PowerShell 5.1 编排脚本坑/假 PASS"记忆同族）。
2. **既有 KMS 的默认配置启动疑点被定位为实施前置项**：默认 profile 排除了数据库自动配置，但密钥仓储构造器硬依赖数据库客户端，全仓无该 profile 的启动测试——不在本包设计里顺手猜，改为"实施第一步实测 + 如实登记"，避免把非本包缺陷混进交付。
3. **端口共存是设计约束而非偏好**：三个既有服务全部默认 8080，本包若不做端口分派，S1 演示（一次业务流需三服务同时在线）在物理上无法执行——该事实写进 lofi 待确认问题 Q2 的业务影响栏，供编排师裁决。
4. **台账插入行时以"上一行前缀"为替换锚点会吞掉原行**：本次追加变更记录时误把 00:4x 行的行首当作锚点替换，导致两行并成一行、原行日期丢失——靠 `tail`+逐行复核当场发现并按原行全文重建（最终行序与内容已复核正确）。**教训：追加表格行只能以"唯一末段文本"或整行为锚点，替换后必须回读目标区域核对行数与日期**；另注意 Bash 终端中文显示为乱码属代码页假象，核验一律用 Read 工具读 UTF-8 原文。
