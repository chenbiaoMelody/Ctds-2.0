### 做了什么（业务可读）

把"每天本地凌晨 0~8 点之间跑必红的测试"修好了。根因是测试造数用**数据库的钟**（容器按世界时走）、而服务判定"今天"用**应用自己的钟**（按本地时区走），两者差 8 小时——那 2 个失败用例只是"没等到对的时间窗口"才不红，本质一直在。修复只动了测试代码：造数改由应用时钟算时间再传进去，和产品代码写库用的是同一口钟。没动任何产品代码。

**怎么证明修好了**：用"把本机时钟拨到世界时 +12 区"的方式，在任意时刻人为制造出和凌晨窗口一模一样的两钟错位——修复前确实复现出那 2 个失败（和台账记录的失败一模一样），修复后同条件下全绿；再按登记的验收口径连跑 3 次全绿，最后把整个主体服务的 134 个测试全量跑一遍也全绿。

### 问题与教训

1. **`MSYS2_ARG_CONV_EXCL='*'` 会让 mvn 崩**（`ClassNotFoundException: plexus.classworlds.launcher.Launcher`）——Git Bash 下别设它；时区参数选无斜杠的 `GMT+12` 避开 MSYS 路径改写。
2. **surefire 3.x 的属性名是 `-Dsurefire.failIfNoSpecifiedTests=false`**（老 `-DfailIfNoTests` 已被忽略，`-Dtest=...` 配合 `-am` 多模块会因"无匹配用例"直接 BUILD FAILURE）。
3. **新 fix 分支务必从 main 起**（`git checkout -b fix/... origin/main`），本次误从 feat 分支起被 `rebase --onto origin/main` 纠正——教训：创建分支前先确认 `git branch --show-current` 与目标基线。
4. **窗口缺陷用"时区偏移"做确定性复现**，比"等真实凌晨"可重复、可入回归；该方法已写入 DB-22 卡"验证设计"供后续同族缺陷复用。
