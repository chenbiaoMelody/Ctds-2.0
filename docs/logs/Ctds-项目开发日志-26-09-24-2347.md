### 问题与教训

1. **中文分支名要"创建后回显核对"**：分支名含中文（沿先例命名），命令行传参存在编码风险 → 创建后立即 `git branch --show-current` 回显，与预期逐字一致才继续（同族：`-2256`"关键动作不与其他命令混在复合命令里"）。
2. **"最新日志在分支上"必须写进交接提醒**：确认留痕落分支（沿先例）后，main 上仍是立卡态文档——若新会话在 main 冷启动会读到过期状态。已在日志首部加醒目提示并要求 `git checkout` 分支后再读（这是"分支即工作区"带来的**已知代价**，用提示而非流程变更来化解）。
3. **一次确认的收益可落为"零返工"指标**：Q1~Q7 在设计阶段把落位、协议口径、样例真实性、三查、留痕、鉴权、双向实现七件事全部定死，编码会话只需"照契约实现 + 前置实测"，避免 3.1.8 那样在实施中才发现契约解释分歧（本会话把 `LocalDidStatusPort`、错误码零新增等易分歧点写进 hifi）。
