### 问题与教训

1. **"用例总数"必须写清统计口径，且口径要跨模块一致**：本次必修项的根因不是算错，而是**同一次统计里对三个模块用了两种口径**（did 剔陈旧、example/subject 未剔）。教训：计数类留痕应附"口径 + 剔除清单"，并在每次重构时对**所有模块**执行同一规则（可在台账行内固定写法）。
2. **删除测试类后要清理构建目录**：三个已删除类（`DiagEndpointTest` / `InternalAdmissionIntegrationTest` / `DidResolutionVerificationIntegrationTest`）的 surefire 报告长期残留在 `target/`，是本次账实偏差的物证。教训：删除测试类后建议 `mvn clean`（或至少删除对应报告）再统计；长期可考虑在门禁/统计脚本里按"报告对应的源文件是否存在"过滤。
3. **评审会话零代码变更**：本次评审发现 8 条建议，一律只登记不改动——避免"评审"与"改进"混在一个会话，保持评审对象可复现（评审对象 = 明确快照/工作树 + 报告号）。
4. **陈旧证据也可能"看起来新鲜"**：评审中不能只信台账数字，要回到文件级实测（逐份报告 + 源文件存在性）才能定性。
