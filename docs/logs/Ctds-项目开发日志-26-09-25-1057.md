您回复"继续任务"后，我先按规矩冷启动（读上一份日志、任务卡与编码契约），复述了续点，您回"**确认**"，于是我按图纸把 **DID 管理界面** 这一包做完了。

**这一包解决了什么问题**：主体入驻后系统会自动发一张"数字身份（DID）"，但此前**运营管理员在界面上看不到、也管不了它**；验收剧本里有 17 个步骤都写着"打开 DID 管理页"。现在这条运营通道打通了。

**界面上多了什么**：
1. 左侧菜单新增一项"**DID 管理**"（仅管理员权限可见，普通演示角色看不到、也进不去，会被引导回工作台）；
2. 页面里可以**按主体编号、按状态（有效 / 已吊销 / 待签发）筛选并翻页**查看所有 DID 记录；点"查看详情"能看到记录要素、DID 文档的公开要素（公钥、控制者、创建时间）与**操作留痕**（谁在什么时候、因为什么、把哪张身份从什么状态改成了什么状态）；
3. **吊销**做成"两段式"，防误操作：先填理由（**留空会被当场拦下**）→ 弹出二次确认，明确写着"**吊销不可逆**"→ 点"取消"什么都不会发生（不发请求、不留痕）；点"确认"才真正吊销并立刻出现在留痕里；
4. **重签**（给已吊销的主体换一张全新身份，旧记录永久保留、旧标识永不复用）与**重试**（对"待签发"的失败记录重试签发）；
5. 右上角"**演示与验证**"进入第二页：可以**生成演示签名**（仅演示/调试期，生产默认关闭）→ 自动填入验证区 → 显示"通过 / 不通过 / 不可用（系统态）"及原因；还能**解析**任一 DID（未登记会以黄色提示条说"未登记该 DID"，不是报错样式）并查看**验证留痕**（只有时间/DID/结果/原因，**不留业务数据原文**）。

**这一包不会碰的东西（已做实并验证）**：没有新增任何错误码、状态值、数据库表或第三方组件；界面上**绝不出现任何私钥**（只显示 KMS 密钥引用）；演示签名入口**出厂就是关闭的**（需要显式开启，生产禁用）；没有改动任何已有接口的行为；没有动门禁配置。
