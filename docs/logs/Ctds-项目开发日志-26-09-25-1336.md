### 问题与教训

1. **文档表格行的精确匹配（踩坑）**：首次替换台账/任务卡的行时漏掉了表格行首的 `| 评审与验收 | ` 前缀 → 替换失败一次。**教训**：Markdown 表格行的 `old_str` 必须包含行首单元格前缀，且优先用"唯一短片段 + 周边锚点"而非整行长文本（长行易与既有内容不同步）。
2. **超长行（数千字符）不宜整行替换**：台账"进行中/待编排师"行单行逾 2000 字符，整行匹配风险高 → 采用**只改行首片段**的方式（把长内容保留为"历史明细"），既避免失配又保留证据链。**教训**：对超长行做"前缀式改写"，不要重写整行。
3. **PowerShell 控制台中文输出乱码**：`Get-Content`/`Select-String` 输出中文为乱码（编码问题），但**不影响仓库文件本身**（`read_file` 与 git 均为正常 UTF-8）。**教训**：核验中文文档内容一律用 `read_file`（编辑器读取），不要以 PowerShell 控制台输出为准。
4. **推送/合并需人工授权**：本会话的推送与 `--no-ff` 合并均走工具授权通道（编排师指示 + 授权通过），**未绕过**权限流程。
5. **走查结论不得代笔**：编排师只在会话中告知"走查验收通过"，因此仓库留痕只写"通过 + 无新增缺陷/无修复轮"这一事实与走查输入，**不虚构逐步现象与截图**；细节留在 gitignored 步骤卡由编排师回填。**教训**：验收类留痕以"可核验事实"为界，未取得的证据如实标注来源与存放位置。
