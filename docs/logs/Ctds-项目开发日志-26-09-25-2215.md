### 问题与教训

1. **合并类收口必须做"树一致性"核验**：只看"用例数/门禁报告对得上"仍是间接推断；`git diff <评审态梢> main` 为空才是"合并后跑的就是评审过的那份代码"的**直接证据**——本次据此免去重复跑一次门禁（约 6 分钟），同时结论不失真。建议固化为合并收口的固定动作（本会话新沉淀）。
2. **演示数据盘点必须覆盖 KMS**：清单最初按"业务表"盘点（主体/DID/留痕），实测发现联调同时新建了 **2 组 SM2 密钥对**（`did-S20260925000002-2`、`did-S20260925000005-1`）+ 2 条密钥审计行——只删业务行会留下**孤儿密钥**。教训：数据清理清单三面齐备 = 业务表 + KMS + 仓库外残留。
3. **Windows 控制台中文显示乱码 ≠ 数据错**：`docker exec mysql` 与 PowerShell 输出中文为 `???`（控制台编码问题），库内存的是正常 UTF-8；核验中文内容一律用编辑器读取仓库文件（沿用 `-1336` 第 3 条教训）。
4. **超长表格行继续"前缀式改写"**：台账"进行中/待编排师"行单行逾 2000 字符，本次仍只改行首片段、把原内容标注为"**历史明细、保留追溯**"，避免整行匹配失配（沿用 `-1336` 第 2 条经验）。
5. **`git rev-parse --short A B C` 在本机环境报 `Needed a single revision`**：改用逐个 `git rev-parse <ref>` 与 `git log -1 <ref>` 取值即正常（浅坑，记录备查）。
