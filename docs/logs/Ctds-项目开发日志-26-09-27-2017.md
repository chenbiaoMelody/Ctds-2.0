## 任务记录 ｜ 2026-09-27 20:1x ｜ 编排师：项目主导者（兼任） ｜ AI/模型：ZCode ｜ 卡号：WBS-3.2.6（立卡段）

### 做了什么（业务可读）

1. **把"空间管理界面"这件事说清楚了**：三份验收剧本（创建准入 / 成员与权限 / 隔离与策略继承）过去只能靠技术人员在后台发请求来验，现在第一次有了"人点得动"的界面方案——**一个菜单进空间列表与创建，进空间后分三栏办事（基本情况 / 成员与准入 / 策略），平台侧的"策略条目治理"单独一个菜单**；
2. **解决了"一个人演出多个角色"的难题**：剧本需要在同一场演示里分别以"申请人""被邀成员""非成员""平台运营方"的身份操作，此前界面做不到 → 新方案在顶栏加了"演示身份"（填主体编号 + 选身份档）；**并且明确：普通身份档绝不能带"平台运营"权限**，否则剧本里"越权被拒"的步骤会被系统放行，等于把不合格当合格；
3. **补上了一个"看不见的记录"缺口**：剧本要求"打开空间详情能看到操作留痕（谁、何时、做了什么）"，但目前后端没有读取留痕的通道 → 方案建议**只增加一个"看留痕"的只读接口**（不新增错误码、不改数据库、不动已有功能）——这属于新增能力，已单列为待你拍板的问题（Q6）；
4. **把风险与边界写成清单**：非成员看别人空间一律用同一条提示（防止"猜空间是否存在"）；危险动作（解散 / 移除成员 / 转移所有权）必须二次确认且"取消就不发请求"；界面不自己算策略宽严（防止两处标准打架）；
5. **一共列出 8 个待你拍板的问题 + 1 个体量问题**（详见任务卡 §二，每个问题都给了建议答案与"不这么做会怎样"），另附**可离线打开的线框图**（11 个画面），你可以照着图核对"这个界面是不是你要的样子"。

### 问题与教训

1. **"界面入口占位"是文档里的定时炸弹**：三剧本自 2026-09-26 起一直写"待 3.2.6 交付后核对修订"，若本包不交付，三份剧本都无法人工验收 → 本包把"核对修订"写成**交付物之一**（W12）并要求提示 PO 批准，避免把"改名"漏成"改判定"；
2. **越权类剧本步骤与演示角色头天然冲突**（本会话最重要的设计发现）：过去 3.2.3~3.2.5 走查都是"技术侧代执行"，改用界面走查后，若前端统一带平台角色头，剧本里"成员越权被拒"会全被放行——**这类"让绿灯失真"的风险必须在设计期用测试锚点钉死，不能留到走查才发现**（已落 T27）；
3. **新增只读端点要主动暴露、不能悄悄加**："看留痕"这个能力不在 WBS 行 256 的字面里，但剧本需要它 → 一律列成 Q6 让人拍板，并写明"零新码、零迁移、零改动既有语义"，避免"顺手加接口"变成规格外实现；
4. **分支建立时机**：立卡即建分支（沿 3.1.11 先例），使"文档入库"与"确认留痕"两次提交都落在同一分支，后续编码不换分支、评审对象连续。
