### 问题与教训

1. **工具把 vitest 判成"watch 服务"会在 10 秒后中断命令**：`npx vitest run …` 输出只留 `RUN` 头 → 改用 `npm test -- <路径/目录>` 口径即可完整跑完并回显结果（已固化，供后续会话直接复用）；
2. **`el-dialog` 测试中给 VTU 加 `stubs: { teleport: true }` 会引发 ElSelect "Maximum recursive updates exceeded"**：去掉该 stub 即正常（ElDialog 默认不 append-to-body，内容留在组件树内可直接断言）；教训 = 弹窗类测试先行验证"不加 stub 能否断言"，不要盲目 stub teleport；
3. **源集守卫的扫描面比"本包新增文件"更宽**：`layouts/*.vue` 被纳入扫描，MainLayout 既有的演示角色下拉命中"裸角色中文字面量"→ 处理方式 = **把标签收口到 store 常量**（不扫描 store），UI 文案零变化；这类"守卫命中既有代码"的处置口径值得写进后续界面卡的前置清单；
4. **jsdom 下 el-select 的 popper DOM 不可依赖**：断言"值域来自目录常量"改为断言"切换键 → 取值落该键值域首项"，既稳定又直接对应契约语义；
5. **断言要按"契约允许的全部合法输入"写**：T13 首跑失败源于断言只允许 `intro` 一个键，而生效期非空时按白名单提交三个键才是正确行为 → 拆成"空字段不提交"与"有值按白名单提交"两个用例，口径更清楚。
