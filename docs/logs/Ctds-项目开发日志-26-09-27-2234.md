- **D1 缺陷（本段新发现，P1，待裁定；本包无改动面）**：
  - **现象（业务可读）**：空间被解散后，用**同一个名称**在界面上再创建 → 界面告诉你"创建成功"，但实际**没有新建空间**，返回的是**那个已解散的旧空间**；剧本要求此时应**被拒绝**（防止同名不同空间造成历史混淆）。
  - **证据链**：① 界面：成功提示 + 弹窗关闭（截图 `c21-S3-6` 前后 + 报告 `c21-report-3.txt` 第 87 行）；② 库内：走查后 `space` 最大 id 仍为 10（无新行）、`space_action_log` 无该次 CREATE 行、`space_name_lock` 中 `医疗验证空间-3 → 9` **确实已写入**（22:32:13）；③ 直连 8083 探针：`POST /api/v1/data-spaces {name:"医疗验证空间-3"…}` → `http=200 {"code":"0","data":{"id":9,…,"status":"DISSOLVED"}}`。
  - **根因（代码级）**：`services/space-service/src/main/java/com/ctds/space/application/SpaceCreationService.java:43` 的 `@Idempotent(key = "#cmd.ownerSubjectNo + ':' + #cmd.normalizedName")` 在**方法体之前**直接返回首次结果 → 绕过方法体内 :46-49 的 `existsInNameLock`（名称锁）与 :50-53 的（同主同名）判定。幂等键只含"主体 + 归一化名"，**不含空间状态/终态维度**，因此解散后再提交同名创建被判为"重复提交"。
  - **影响面**：无数据损坏（未真正复用名称、未新建空间）；但（a）**剧本 S3-6 判定不成立**；（b）**界面误导**——提示"已创建（未启用）"，实际返回已解散空间（PO 演示时会看到"创建成功但列表里没有"）；（c）幂等窗口内"解散后重建"无法被拒。
  - **归属**：上游 WBS-3.2.3 创建链路（本包 3.2.6 前端仅**原样展示**后端响应；任务卡已声明"不改既有端点语义"）。**未做任何修复**（红线：不擅自修复、规格外不实现）。

### 问题与教训

1. **断言要贴"契约口径"，不能凭直觉**：首跑把"统一文案（不区分不存在/未入驻）"误写成"文案中不得出现'不存在'"，实际统一文案**本身就含**"未入驻或不存在"——改为**正向证明**（不存在主体探针与未入驻主体**同码同文案**）后才真正验证了"防枚举"；
2. **界面特性先查契约再判缺陷**：普通档列表不含 PRIVATE 空间一度看起来像"自己创建的空间看不见"，查上游端点 7/T12 后确认是**已确认口径**——若直接记缺陷，就会制造假红灯；
3. **前置限制要用探针穿透**：名称输入框有 `maxlength=128`，界面层根本提交不了超长名称；此时"超长被拒"只能由**服务端探针**承载，否则会把"输入被截断"误判为"校验通过"；
4. **幂等边界是独立风险面**：S1-7（同名重放返回首次结果、空间数不增）**合理**，而 S3-6（解散后同名重放返回已解散空间）**不合理**——同一机制两个方向，说明"幂等键选择"必须单列边界用例（剧本原先未覆盖，本段补上实证）；
5. **环境交互的坑要沉淀给下一幕**：`el-select` 下拉残留会让"点选项"变得不稳定（须先 `Escape` 并等下拉归零）；Playwright 启动会尝试清空 `test-results`（本机安全删除拦截会致启动失败）→ **必须给 `--output` 独立目录**；
