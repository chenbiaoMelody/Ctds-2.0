### 问题与教训

1. **"合并"指示要拆成"先提交分支文档、再合并"**：工作树不干净时合并会把留痕落下；而"日志与代码同库提交"要求留痕入库 → 顺序必须是"分支提交并推送 → 合并 main"（沿 3.2.3 先例）；
2. **树一致性对照"验收态分支梢"**（`baf109f`）而非合并前基线 `56e02fd`：前者为空才说明"合并后 main = 被验收的那版内容"，这才支撑"免复跑门禁"；**不得把"合并成功"当门禁结论**；
3. **合并不等于把遗留项转绿**：C-2.1 S3-6 属上游缺陷（已转 DB-28），合并后**仍显式登记为"非通过项"**——否则就是"用合并动作抹掉红灯"，与"绿灯不得失真"相违；
4. **显式 `--no-ff` 保留合并痕迹**：便于日后追溯"这批验收结论对应哪两条线"，也符合项目既有惯例；
5. **收口留痕要"三处齐"**：合并提交号、台账快照/进行中/待编排师/下一包、日志——缺任一处，下一个会话就得靠猜（会话记忆不可信）。
