- **关键决策**（本段生效）：
  1. **R5 时点基准以解析器纯函数参数注入**：hifi §4.1 契约 API 为 `parse(JsonNode)`，但 hifi §1 明确"解析器为纯函数式静态组件（无状态、无 I/O）"且 R5 需"起始日 ≥ 提交日"基准——故实现为 `parse(JsonNode)`（= `parse(document, LocalDate.now())`，契约三方法齐备）+ **重载 `parse(JsonNode, LocalDate)`**（纯函数主体，时点判定的可测单点），既守契约又不引入系统时钟脆性（3.3.7"脆性用例"教训）；域单测夹具以固定提交日 `2026-01-01` 保持断言语义零变更；
  2. **`UsageControlPolicy.fromJson` 收敛删除**（hifi §4.3 允许"保留为解析器内部实现细节或收敛删除"）：容忍读语义整体迁入 `parseTolerant`（含未知版本 fail-closed），"解析单点"零分叉；既有回环测试改经 `parseTolerant`（断言零变更）；
  3. **trim 规范化只在写路径（`parse`）生效，读路径 `parseTolerant` 不改写存量字节**：避免 3.4.3 存量（可能含首尾空白文本）在回读时与既有内容哈希/规范化口径漂移（对外行为零变更）；判定值一致性由新写入面保证（R6 = 提交规范化）；
  4. **目录 `fields()` 承载"文档要素字段名封闭集"**（= `quota`/`term`/`purpose`/`territory`/`noRedistribution`），解析器未知要素拒绝以 `PolicyElementCatalog.fields()` 为据（hifi §3"封闭性由目录承载、校验规则由解析器承载"分工兑现）；`UsagePolicyDsl` 只承载版本与字段名常量，**不另立要素清单常量**（避免两处并行定义——评审③视角锚）；
  5. **拒绝态不落半解析模型**：`ParseResult.policy` 在存在违规时 = `UsageControlPolicy.empty()`（违规以清单为准，调用方落 C0015），与 3.4.3 `ClauseValues` 既有行为一致；
  6. **门禁命令口径**：`checkstyle:check` 必须自仓库根执行（`-pl services/contract-service`）——配置路径取 `${maven.multiModuleProjectDirectory}/config/checkstyle/checkstyle.xml`，模块目录内直接调用必报 "Unable to find configuration file"（本段实测教训，非缺陷）；
