### 二、业务可读总结（给项目主导者）

**这一包要做的**：给平台建"**大门口的门卫**"——所有数据产品的 API 交付调用统一从网关进（不再各服务各端口各自为政），门口依次做四件事：**验身份**（假身份头一律作废）、**挡频率**（同一主体对同一接口调用太频就拦）、**先查合约再放行**（越界调用在"转发给数据源之前"就被拒，请求根本到不了数据源）、**放行才记账**（放行 1 次记 1 条计量，被拒的 0 条）。这四件正是 WBS 行 289 写明的产出。

**本包明确不做**（已登记由后面包接）：交付记录页面/查询（归交付域后续包）、把现有前端与部署统一切到单入口（建议后续统一做，避免扰动既有演示剧本）、真实数据源接入（连接器）、真实用户令牌（3.9.1）、计量账单与上链存证（3.7.5 / 3.8.3）。

**两个好消息（减少风险与工作量）**：① 网关的"验身份 + 身份头剥离/注入"组件**早就写好并测过**（当初就为 3.5.2 预留），本包不用重写鉴权，只负责把它"装上并打开开关"——顺带兑现了台账里那条"身份信任边界"债务的**一半**解除条件（另一半是真实令牌）；② 限流按"内存令牌桶"做（沿用本项目幂等/锁组件的既有做法），**不新增 Redis 等中间件**，演示环境可以直接跑。

**需要您拍板的是 9 个口径 + 1 个体量问题**（建议口径都是 A、体量不拆分），最关键的三条：① 是否按 ADR-005 引入 Spring Cloud Gateway（这是当初已批准的选型，本包只是落地 + 登记依赖）；② 越界拒绝**沿用合约域原有错误码**（不另造一套）；③ 网关自身错误用**预留的 1009 段新码**（实测该段当前零占用）。全文与备选影响见 `docs/designs/WBS-3.5.2-lofi.md` §3。
