- **关键决策**（本段生效）：
  1. **`common-auth` 的 `spring-boot-starter-web` 在网关模块以 `<exclusions>` 移除**：Spring Cloud Gateway 不支持 Servlet 容器；若类路径同时含 `spring-webmvc`，Boot 会判定 `WebApplicationType=SERVLET` → 反应式安全链与网关整体不激活（**静默失效 = 鉴权旁路**）。同批在 `application.yml` 显式声明 `spring.main.web-application-type: reactive` 作第二道防线。**common-auth 一行未改**（hifi §9 补登记第 1 条）。
  2. **网关自建 401 出口**：common-auth 的 `GatewayAuthEntryPoint` 固定 `traceId="-"`，与 Q8-A"未认证响应亦带追踪号"冲突 → 以 `@ConditionalOnMissingBean` 语义（`GatewayUnauthorizedEntryPoint`）覆盖缺省出口，**复用码值 1000C0002 + `AuthAdvice` 常量文案 + `auth.verify` FAILURE 审计动作与原因枚举口径**；**不改 common**（hifi §9 补登记第 3 条）。
  3. **判定响应非合约域业务码一律 fail-closed**：`§7` 明文透传集 = 越界类 **C 型**码（C0020/C0013/C0012/C0008），`§2` 明文"判定不可达 → 不放行"；故 `1008S` 型 / 未知形态 / 非 2xx 无码体 → 503 + `1009S0001`（不透传），避免把"未能判定"透传成业务结论（hifi §9 补登记第 7 条）。
  4. **凭据格式具体化**：合约编号头 = 非空且仅 `[A-Za-z0-9._-]`、≤64（与 common-api traceId 净化同族字符集）；空值与格式非法同码同文 400 + `1009C0001`（hifi §9 补登记第 8 条）。

### 二、业务可读总结（给项目主导者）

网关这一包做完了，**"交付必须过网关"这条链路在本卡范围内已经能跑通并且测过**：调用方必须带有效身份令牌才能进门（伪造的身份头会被网关无条件剥掉）；**限流**按"谁 + 调哪个接口"保护（超频返回"频率超限"）；请求转给数据源之前，网关会先向合约系统问一句"这次使用合不合法"——**不合法就当场拒绝，请求根本不会碰到数据源**，且拒绝说法沿用合约系统的原话（不换词、不换码）；**只有放行的调用才记 1 条计量**（拒绝不记账，但会留痕）。另加两道默认安全：不在"允许交付的路径清单"里 → 直接 404 拒绝；合约系统联系不上 → **宁可拒绝也不放行**。

同时给合约系统加了一个"内部判定窗口"（只允许网关这个服务身份调，普通业务角色调不了），判定逻辑**一个字都没重写**，是直接复用原有判定引擎——避免出现两套口径。
