### 二、业务可读总结（给项目主导者）

**这次真实试跑证明了什么**：CI 确实会自动触发、会自动跑全量门禁、会把结论写回 PR 页面并如实判红——"自动验票机"的骨架是通的，而且它没有粉饰失败。

**它同时暴露了三类问题**：
1. **我们自己的疏漏**（本卡内可修）：CI 机器上没有安装前端依赖包，所以三个前端检查项都报"命令找不到"；CI 上也缺少"失败时把详细日志带回来"的步骤，导致这次只能看到摘要、看不到具体哪几条断言失败。
2. **老工具在 CI 环境下的两处脆弱点**（需您批准扩面后才修）：① 扫描项（sast）用 Docker 跑，而 GitHub 免费 Windows 跑机**没有 Docker 服务**——工具一探测就抛异常，把整个门禁"撞停"，连报告都没写出来（本应是"扫描项报错、其它项照常跑完"）；② 门禁在"报告目录不存在"时兜底写入失败，报告文件丢失。
3. **三类还没定性的失败**：自检 5 条断言失败、覆盖率项退出 1、变异测试类路径生成失败——这三项的具体原因在跑机临时目录里，跑完即销毁，必须先补"失败取证上传"才能看到。

**需要您做一个选择（扫描项怎么办）**：GitHub 免费 Windows 跑机没有 Docker。A = 自备一台常开 Windows 机器做跑机（脚本零改动，但要维护机器）；B = 换一个不需要 Docker 的扫描工具（能继续用免费跑机，但要按变更流程引入新工具）；C = 让扫描项一直报错（CI 永久红灯，等于关闭条件永远达不成，不建议）。
