- **关键决策**（本段生效）：
  1. **凭据头编码器按网关真实解码器勘正**：网关 `DeliveryCredentialGlobalFilter` 用 `UriUtils.decode`（RFC 3986 百分号），**不解 `+`**；修复批原用 `URLEncoder`（表单语义，空格 → `+`）会导致含空格要素在网关侧变成 `+` 字面值——改用 `UriUtils.encode(UTF-8)` 配对（行为 4/5 判定输入正确性）。
  2. **`contractNo` 凭据头不编码**：网关对该头**不解码**且设 `^[A-Za-z0-9._-]{1,64}$` 正则（不匹配即 400）——SDK 改**原值发送 + 本地同规则 fail-fast**（CONFIG），既与网关一致又避免"看似编码、网关拒绝"的哑错。
  3. **幂等键不编码 + 必填**：平台交付域按原值 `[A-Za-z0-9._-]{1,128}` 校验（`DeliveryCommandService`），编码会改变键值语义（跨工具重试对不上）；SDK 本地同规则校验后**原值**入 `X-Idempotency-Key`。
  4. **文件型交付请求体补 `deliveryType`**：平台 `DeliveryRequest(contractNo, deliveryType, fileId, purpose, territory)`，修复批原实现漏 `deliveryType`（必填）→ 必然 400；SDK 内部私有 record 固定 `FILE`（不让调用方误传）。
  5. **交付门面拆三腿（实现偏差留痕）**：API 型（网关交付面 GET data-products）/ 文件型（POST deliveries）/ 详情——平台两条腿的**请求体与判定链不同**，合并为单一 `requestDelivery` 必错；hifi §3 勘正注 + ADR-026 §2-4 登记。
  6. **`ContractView` 采并集扩展而非新增 record**：平台 `Initiated` / `Detail` / `Mine` 三形态字段集不同；并集 + `@JsonIgnoreProperties` 宽松映射（未出现字段为 null）在骨架期最小且够用，字段级运行期核验归 3.6.8（跟踪项 T2）。
  7. **分页参数用必填 int + 本地校验**（`Pages`）：与平台 `PageQuery` 默认值 / 上限（1~10000 / 1~100）对齐，非法值 CONFIG fail-fast 不打到平台。
  8. **业务判定语义零变更**：六门面 / fail-closed 三态 / 凭据引用制 / 零 1010 码值 / 零加解密面全部保持——本段只改技术契约层。
  9. **验证口径以最新复跑为准**：39 例 / 94.22% / 0 违规；全仓门禁仍由 PR gate check 承载（本段未本地全量复跑，登记）。
