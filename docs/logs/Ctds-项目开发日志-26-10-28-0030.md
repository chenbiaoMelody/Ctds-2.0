- **关键决策**（本段生效）：
  1. **`reason_code` 由 16 放宽到 32（V3 内 ALTER）**：自检失败原因枚举名最长 22 字符（`INSUFFICIENT_PERMISSION`），首轮测试暴露 `Data too long` 被留痕单点吞掉（业务不报错但审计缺行）。处置 = 加性放宽既有列宽（沿 V2 `ALTER` 先例），**不改枚举、不新增列、不建第二事实源**。
  2. **`ConnectorUnavailableException` 在适配器调用边界必须放行**：首轮把"密钥不可用"误收成 502（适配器非预期），破坏了 fail-closed 语义；修正为 catch 顺序 `ConnectorUnavailableException` 先行上抛、其余 RuntimeException 才转 502。教训 = **异常收敛点要按语义分层，不能一把 catch**。
  3. **自检结论不建表、按 `detail` 首段 `sourceNo=` 派生**：`connector_action_log` 无 source 列，hifi §2"详情 1 次查询"以 `detail LIKE 'sourceNo=SRxxxxxx;%'` + `ORDER BY id DESC LIMIT 1` 实现；失败原因同时入 `reason_code`（机读）与 `detail`（可读）。
  4. **模拟源观测面 3 个 public 方法**（`mockExchangeCount` / `mockDataVersion` / `mockResetCounters`）：hifi §9 T4/T8 的"零变更 / 零触达"断言必须可证伪（不能只断言 `passed=true`）；方法限定在适配器类上并注释"真实对接时随客户端替换移除"，非测试后门。

### 三、业务可读总结（给项目主导者）

**这一包把"给政务共享交换平台等四类数据源登记接入"的功能做完了。** 现在四种源（政务共享交换平台、数据库、对象存储、API 网关）都能登记、都能拿到 `SR` 开头的源编号；登记时填的访问凭据会**加密保存**，界面上只能看到 `****abcd` 这样的掩码，任何地方都查不到明文；万一加密组件不可用，系统宁可拒绝登记也不明文凑合。政务源可以"试连"，试连失败会明确告诉您是**网络不通、凭据不对、还是没权限**，并留下记录；试连不会改动源端数据。数据库 / 对象存储 / API 网关三类目前只能登记，试连和取数会明确回"该类型的适配还没开放"（留给下一包）。另外，内部取数接口已经就位（等交付链在"判定放行"后调用），每次取数只返回摘要、不留数据本体，并留五个要点（谁、哪个连接器、哪个源、哪份合约、结果）；被拒绝的四种情况都**不会去碰源端**，这一点有自动化断言逐项证明。连接器注销后，它的源不能再取数，但档案和记录都还能查。
