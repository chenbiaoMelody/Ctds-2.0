- **关键决策（本段）**：
  1. **E3 依赖形态修正**：common-logging 与网关直引 `spring-jdbc`（非 hifi §5.3 的 starter-jdbc）——HikariCP 上类路径使 Boot 在无数据源配置的服务（网关ApplicationContextRunner 实证）激活主数据源装配失败；落库实现单后台写线程逐条 upsert 本无需连接池；行为面与 hifi §5.1 契约零偏差。
  2. **E4 幂等 SQL 等价替换**：metering 仓储 `INSERT IGNORE` 替代 `ON DUPLICATE KEY UPDATE id=id`——CLIENT_FOUND_ROWS 默认语义实证下后者空转 affected=1 与新增不可判别；`INSERT IGNORE` 语义等价（uk 兜底重复零写入）且计数判别可靠；**ADR-007 幂等语义不变**（uk + 幂等写入）。
  3. **异常处理器精确映射**：metering 域 `@RestControllerAdvice` 对 1011C0008→404 / 1000C0005→403 / 1000C0002→401 精确出站（ADR-005 §3-7"精确映射由组件完成"的本地兑现），其余沿 C/B→400、S→500 全局口径。
  4. **通道 1/2 测试边界维持 hifi §8 声明**：metering 集成以事件行造数隔离（不起网关全链）；网关→落库链由 common-logging 单测（mock JdbcTemplate）+ 演示走查承载——评审可议项，如实申报。
  5. **采集测试清场策略**：事件源替身表与 metering_flow 逐用例清理——采集为全量重扫语义，不清场则跨用例计数污染（第一轮实证）；替身表只含采集/勾稽所需列（hifi §2 查询契约列面），完整表结构由上游迁移权威。
