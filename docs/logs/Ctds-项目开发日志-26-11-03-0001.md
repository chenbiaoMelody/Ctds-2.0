  2. **教训 2：Windows 下 `Get-NetTCPConnection` 杀进程不彻底**——`Stop-Process` 按监听 PID 击杀后 jar 仍被占用（repackage 报 "Unable to rename"）；实际需 `Get-Process java` 全量核对并杀干净。另：`Start-Process` 返回的 PID 与 jar 实际 JVM PID 可能不同，**不要只依赖 pid 文件**。
  3. **教训 3：静态纪律扫描会命中注释文本**——`PortalSourceGuard.spec.ts` 的 `'admin'` 断言按**原文**扫描（不剥注释），文档注释里写"零 `admin` 字面量"即自我命中。处置 = 注释改写为"角色名零出现"。**后续写守卫 spec 时，被扫描文件内的注释也不得出现被禁字面量**。
  4. **工具坑：`npx vitest run … > file` 被运行器判为 watch 命令**——命令返回时用例尚未完成（输出仅 `RUN` 头），需 `Start-Sleep` 后再读日志；`Get-Content` 读取不影响判定（日志完整）。后续长任务一律"写日志 + 轮询读取"，不以即时空输出判失败（沿 3.3.7 教训）。
