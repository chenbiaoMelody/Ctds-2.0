## 一、业务可读交付说明（编码段）

**做了什么**：按已确认的设计，把资源**变更**和资源**注销**两个写操作的拒绝提示统一——"不是你的资源 / 别的空间的资源 / 不存在的资源"三种情况现在都回复"400 + 错误码 `1000C0003` + 资源不存在"，与资源**查询**接口的口径一字不差。试探者无法再靠"403 与 404 的差别"猜出哪些资源编号真实存在（上一卡关闭了查询面，本卡关闭了写面——资源域读+写出站从此单一字典）。内部"谁试探了谁"的留痕保留：非本人操作仍记录一条拒绝痕迹（记号从 `C0006` 改为 `C0003`，与查询面口径一致），历史记录不动；查询不存在的资源不留任何痕迹。

**如何演示**：① 启动 catalog 服务后，用主体 A 登记一个资源；② 用同空间的主体 B（或另一空间的主体）调用"变更该资源"与"注销该资源"，看到的错误码、提示文字与"资源根本不存在"时完全一样；③ 管理界面留痕清单里能看到 B 的拒绝记录各 1 条（记号 `C0003`）。自动化证据：新增 6 个测试用例 + 2 个旧用例反转，红相（改造前）7 个用例如预期失败、实现后 26 个全绿；catalog 服务全量 205 个测试全绿；全仓质量门禁单发绿灯（15 项通过 0 项失败，配置指纹与基线逐字一致）。

**注意事项**：① 对外行为变化仅限"变更/注销"两操作的"不存在/非本人"拒绝（404/403 → 400、码值统一 `1000C0003`、文案统一"资源不存在"）——前端不按码值分支（零改动），外部联调/测评若有固定旧预期的用例需复核（测评面影响评估在下一段落盘）；② 入驻资格提示、治理面查询、产品封装检查的旧提示口径**全部未动**；③ 覆盖率 92.50% 与上一卡基线 92.52% 差 0.02 个百分点，逐行归因证明与本卡无关（catalog 模块实际 +1 行且改动行全覆盖；差异来自其它模块测试运行时的非确定性波动），已如实登记供评审裁定。
