## 剧本 S1：三员分立与权限边界幕（行为 B1、B2、B3，正向 + 双向负向 + 留痕）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 系统管理员 | 打开角色与权限清单，**逐角色记录权限点集合作为基线**（系统管理员 / 安全管理员 / 审计管理员 / 一个业务角色各记一份） | 四份清单均可读出；权限点命名均为 `<域>.<动作>` 形式，无空值、无重复（B1-1 / B1-2） |
| 2 | 系统管理员 | 执行一次平台业务配置动作（如阈值参数登记 / 平台参数配置；3.9.4 落定承载面） | 动作成功，并产生一条管理动作留痕（B2-1 正向） |
| 3 | 系统管理员 | 尝试访问审计查询（存证记录 / 审计报告） | 被拒：**400 + `1000C0003` + "记录不存在"**（审计读面反枚举口径，沿 C-8.2 S1-7 / `EvidenceAuditAccessGuard`；本步不适用 403 口径）（B2-1 / B3-2，负向） |
| 4 | 系统管理员 | 尝试为某业务角色授予一个权限点 | 被拒：403 + `1000C0005`（B2-1，负向——管理权与授权权分离） |
| 5 | 安全管理员 | 为某业务角色**授予**一个权限点（V1.0 = 变更单 + 配置变更 + 重启生效；3.9.2 落库后 = 授予面操作），记录授予前后的可见面 | 授予成功并留痕（变更单编号 / 变更人 / 时点 / 角色 / 权限点 / 前后值）；该业务角色重启后获得对应能力（B1-3 / B1-4，正向 + 双向） |
| 6 | 安全管理员 | 将步骤 5 的权限点**收回**（同上路径：变更单 + 配置还原 + 重启；3.9.2 后 = 收回面操作），随后由该业务角色重试步骤 5 的能力 | 收回成功并留痕；业务角色对应能力恢复为被拒（B1-3，双向） |
| 7 | 安全管理员 | 尝试访问审计查询；另尝试修改业务配置 | 审计查询被拒 **400 + `1000C0003` + "记录不存在"**（反枚举口径）；修改业务配置被拒 403 + `1000C0005`（B2-2，负向） |
| 8 | 审计管理员 | 查询一笔业务的审计记录并导出一份审计报告 | 查询与导出均成功，产生调阅 / 导出留痕（调阅人 / 时点 / 条件 / 报告编号）（B2-3 正向） |
| 9 | 审计管理员 | 尝试修改业务数据；另尝试授予权限点 | 两项均被拒 403 + `1000C0005`（B2-3，负向） |
| 10 | 普通业务角色 | 访问角色与权限清单页、运维处置入口 | 两项均被拒 403 + `1000C0005`，文案"无权限执行该操作"（B3-2，负向） |
| 11 | 普通业务角色（无 `evidence.governance`） | ① 访问审计读面（任一审计端点）；② 由审计管理员以同一端点查询**不存在**的单号，记录两项提示并逐字比对 | 两项均为 400 + `1000C0003` + "记录不存在"，**逐字同文**（反枚举面越权同文；归属不匹配类同文参照由 S2-3 / S2-4 承载）（B3-2，负向 + 双向参照） |
| 12 | 审计管理员 | 读取拒绝留痕（`rbac.check` DENIED 审计事件），检索 S1-3 / S1-4 / S1-7 / S1-9 / S1-10 的拒绝记录 | 每条可读出 actor（谁被拒）/ 权限点（被拒的动作）/ 时点（B3-3）；无独立读面时由陪验工程师只读**审计事件载体**核对（默认 = `ctds.audit.file-dir` 下 JSONL，检索 `action=rbac.check` + `outcome=DENIED`；若部署期切 `metering-db` 则查对应审计表），系统管理员不可读该读面 |
| 13 | 编排师（判定人） | 将 S1-1 的四份权限点清单**两两比对**，并核对平台管理面端点清单 | ① "业务配置 / 权限授予 / 审计读面"三类关键权限点，**无任一角色同时持有两类的关键点**；`admin` 档（若保留）不持有审计读面与授权类关键点（B2-4 结构性判定）；② 清单中的权限点**均在各域规格中登记过**（无未登记权限点），平台管理面端点**无未挂权限点者**（B1-1 / B3-4，观察点） |

## 剧本 S2：部署域与空间隔离幕（行为 B4，双向 + 参照比对）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 系统管理员 | 打开部署域信息（实例标识 / 库 schema 清单） | 可读出当前部署域标识与 schema 清单，且与运行实例一致（B4-1）；页面明示"V1.0 = 单实例单部署域，业务隔离由逻辑空间承载"（规格 §6-3 口径） |
| 2 | 供方（空间 A 成员） | 在空间 A 内检索资源 / 产品 | 仅命中属于空间 A 的对象；记录其中一条资源标识（资源 X）（B4-2 正向） |
| 3 | 需方（空间 B 成员） | 以空间 B 的身份访问资源 X 的详情与交付入口 | 被拒；提示与"对象不存在"同形（同码同文，B4-2 负向） |

| 6 | 系统管理员 | 打开运维读数（服务存活 / 告警列表 / 连接器健康总览） | 读数**不按空间切分**，为部署域全量；与 S2-2~S2-5 的业务数据空间过滤形成对照（B4-3，观察点） |
| 7 | 编排师（判定人） | 核对部署域与"跨租户"场景 | 确认 V1.0 无跨部署域数据互通场景（跨空间由官方互联互通 C-9.x 承载，非本规格）；记录"跨租户场景不适用"说明，不以单实例环境冒充已实现多租户（B4-1 / 规格 §6-3 观察点） |

## 剧本 S3：部署域配置与生命周期幕（行为 B9，V1.3 草案）

> **口径诚实声明**：V1.0 = 单实例单部署域。本幕的"开通"以**当前演示部署域为已开通基线**（首次部署已由部署 runbook 完成），**不在演示环境再开通第二部署域**；"升级"与"退役"以配置版本 / 状态变更演示，业务判定与数据口径不变。生命周期动作**由部署变更执行，不提供在线业务 API**（规格 B9-R3 / Q11）。

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 系统管理员 | 打开部署域信息（标识 / 名称 / 平台版本 / 生命周期状态 / 库 schema 清单 / 服务清单） | 读面返回 `ACTIVE` + 与部署配置一致的完整信息；业务角色访问同一读面被拒 403 + `1000C0005`（B9-1 / B3-2） |
| 2 | 编排师（判定人） | 将读面返回的 schema 清单 / 服务清单与部署清单、runbook 逐项核对 | 逐项一致；页面明示"V1.0 = 单实例单部署域，生命周期 = 配置版本与状态管理，不做多实例自动开通"（B9-1 / 规格 §6-3） |
| 3 | 系统管理员 | 执行一次**升级**：登记变更单 → 将平台版本号递增（如 1.0.0 → 1.0.1）→ 按部署 runbook 滚动更新 | 升级成功；读面版本号递增；旧版本配置与变更记录可查（B9-2 正向 / B9-4） |
| 4 | 系统管理员 | **受控构造**：登记变更单 + 还原计划后，把 schema 清单改为一个不存在的 schema；重启或查询读面；随后还原 | 启动失败或读面明确返回"配置不一致"且业务端点不可用；还原后复验恢复正常（B9-3，负向 + 双向） |
| 5 | 系统管理员 | 执行**退役**：登记变更单 → 状态置 `RETIRED` → 按部署 runbook 停止对外业务入口 | 读面状态 = `RETIRED`；除审计读面与健康读数外的业务请求被拒 **503 + 1013 段码值**（语义"部署域已退役"）（B9-2 正向 / B9-6） |
| 6 | 审计管理员 | 在 `RETIRED` 状态下查询审计记录并导出报告 | 审计读面仍可用；数据与审计记录保留可查，未被删除（B9-2 / B9-6） |
| 7 | 系统管理员 | 恢复 `ACTIVE`（登记变更单 → 状态置 `ACTIVE` → 按部署 runbook 恢复业务入口），业务角色重试 S3-5 被拒的业务动作 | 业务恢复成功；读面状态 = `ACTIVE`（B9-2，双向） |
| 8 | 编排师（判定人） | 核对 S3 生命周期动作的留痕与结构口径 | 每次开通 / 升级 / 退役均有变更单编号 / 操作人 / 时点 / 动作 / 前后值（B9-4）；全仓无 `tenant_id` / 租户表 / 在线租户生命周期 API（B9-5，观察点） |

### 操作路径说明（V1.3 草案；界面入口仍待 3.9.5）

> **V1.2 落定（2026-11-12 WBS-3.9.2 编码段）**：下表 5 处承载行（含 S1-12 变更留痕 R2）按已确认设计（hifi §2 / §9 E5）回填实际端点（沿 C-8.1 剧本 V1.2 先例）。**运行期前提**：各服务启动须注入 `CTDS_AUTH_RBAC_SOURCE=jdbc` + `CTDS_AUTH_RBAC_SCHEMA=ctds_evidence`（E6-A），角色→权限点以库表 `ctds_evidence.role_permission` 为唯一来源；未注入则仍走配置文件兜底，本表三员身份不成立。业务判定与步骤编号不因路径变化而改变。**V1.3 草案（2026-11-13 WBS-3.9.3 规格补充）**：S3 幕的部署域读面 / 退役拦截端点由 3.9.3 实施卡回填；S1/S2 路径不变。
