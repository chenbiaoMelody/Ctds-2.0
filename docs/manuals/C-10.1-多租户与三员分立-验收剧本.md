## 剧本 S1：三员分立与权限边界幕（行为 B1、B2、B3，正向 + 双向负向 + 留痕）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 系统管理员 | 打开角色与权限清单，**逐角色记录权限点集合作为基线**（系统管理员 / 安全管理员 / 审计管理员 / 一个业务角色各记一份） | 四份清单均可读出；权限点命名均为 `<域>.<动作>` 形式，无空值、无重复（B1-1 / B1-2） |
| 2 | 系统管理员 | 执行一次平台侧管理动作（如平台配置项 / 账号归属信息登记） | 动作成功，并产生一条管理动作留痕（B2-1 正向） |
| 3 | 系统管理员 | 尝试访问审计查询（存证记录 / 审计报告） | 被拒：403 + `1000C0005`，文案"无权限执行该操作"（B2-1 / B3-2，负向） |
| 4 | 系统管理员 | 尝试为某业务角色授予一个权限点 | 被拒：403 + `1000C0005`（B2-1，负向——管理权与授权权分离） |
| 5 | 安全管理员 | 为某业务角色**授予**一个权限点，记录授予前后的可见面 | 授予成功并留痕（变更人 / 时点 / 角色 / 权限点 / 前后值）；该业务角色随即获得对应能力（B1-3 / B1-4，正向 + 双向） |
| 6 | 安全管理员 | 将步骤 5 的权限点**收回**，随后由该业务角色重试步骤 5 的能力 | 收回成功并留痕；业务角色对应能力恢复为被拒（B1-3，双向） |
| 7 | 安全管理员 | 尝试访问审计查询；另尝试修改业务配置 | 两项均被拒 403 + `1000C0005`（B2-2，负向） |
| 8 | 审计管理员 | 查询一笔业务的审计记录并导出一份审计报告 | 查询与导出均成功，产生调阅 / 导出留痕（调阅人 / 时点 / 条件 / 报告编号）（B2-3 正向） |
| 9 | 审计管理员 | 尝试修改业务数据；另尝试授予权限点 | 两项均被拒 403 + `1000C0005`（B2-3，负向） |
| 10 | 普通业务角色 | 访问角色与权限清单页、运维处置入口 | 均被拒（与"对象不存在"同码同文的前置：见 S1-11）（B3-2，负向） |
| 11 | 普通业务角色 | 以 S1-10 的同一入口访问一个**不存在**的对象标识，记录其提示；再比对 S1-3 / S1-9 的拒绝提示 | 归属不匹配类拒绝 = 400 + `1000C0003`，与"对象不存在"**逐字同文**（B3-2，负向 + 双向参照） |
| 12 | 系统管理员 | 打开拒绝留痕读面，检索 S1-3 / S1-4 / S1-7 / S1-9 / S1-10 的拒绝记录 | 每条可读出 actor（谁被拒）/ 权限点（被拒的动作）/ 时点（B3-3） |
| 13 | 编排师（判定人） | 将 S1-1 的四份权限点清单**两两比对**，并核对平台管理面端点清单 | ① "业务配置 / 权限授予 / 审计读面"三类关键权限点，**无任一角色同时持有两类的关键点**；`admin` 档（若保留）不持有审计读面与授权类关键点（B2-4 结构性判定）；② 清单中的权限点**均在各域规格中登记过**（无未登记权限点），平台管理面端点**无未挂权限点者**（B1-4 / B3-4，观察点） |

## 剧本 S2：部署域与空间隔离幕（行为 B4，双向 + 参照比对）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 系统管理员 | 打开部署域信息（实例标识 / 库 schema 清单） | 可读出当前部署域标识与 schema 清单，且与运行实例一致（B4-1）；页面明示"V1.0 = 单实例单部署域，业务隔离由逻辑空间承载"（规格 §6-3 口径） |
| 2 | 供方（空间 A 成员） | 在空间 A 内检索资源 / 产品 | 仅命中属于空间 A 的对象；记录其中一条资源标识（资源 X）（B4-2 正向） |
| 3 | 需方（空间 B 成员） | 以空间 B 的身份访问资源 X 的详情与交付入口 | 被拒；提示与"对象不存在"同形（同码同文，B4-2 负向） |
| 4 | 需方（空间 B 成员） | 直接访问空间 B 内**不存在**的资源标识，记录提示；与 S2-3 逐字比对 | 提示逐字一致（400 + `1000C0003`，B4-2 双向参照） |
| 5 | 需方（空间 B 成员） | 访问一笔属于空间 A 的合约 / 交付记录 | 被拒，理由同 S2-3（B4-2） |
| 6 | 系统管理员 | 打开运维读数（服务存活 / 告警列表 / 连接器健康总览） | 读数**不按空间切分**，为部署域全量；与 S2-2~S2-5 的业务数据空间过滤形成对照（B4-3，观察点） |
| 7 | 编排师（判定人） | 核对部署域与"跨租户"场景 | 确认 V1.0 无跨部署域数据互通场景（跨空间由官方互联互通 C-9.x 承载，非本规格）；记录"跨租户场景不适用"说明，不以单实例环境冒充已实现多租户（B4-1 / 规格 §6-3 观察点） |

## 剧本维护说明

- **V0.9 立卡草案（2026-11-10）**：随规格 V0.9 同批提交；待编排师一次确认后转 V1.0（仅版本行改写）。**步骤与业务判定自本版起锁定**，后续修订须留痕并说明理由。
- **执行前提联动**：本剧本可执行前提 = **3.9.2（RBAC 与三员分立实现）+ 3.9.5（系统管理界面）** 交付；3.9.3 仅影响 S2-1 的读面形态，不阻断判定。3.9.2 编码段落地后须回填"操作路径说明"表（沿 C-8.1 V1.2 / C-8.2 V1.2 先例）。
- **剧本间执行顺序（推荐）**：C-1.1（主体）→ C-2.1（空间）→ C-4.2（合约签署）→ C-5.1（交付调用）→ C-8.2（审计查询）→ **本剧本（S1 → S2）** → C-10.2 监控运维（S1 → S2）。
- **不可承诺项**：本剧本不验证真实登录、账号密码策略、会话与令牌签发（**V1.0 不做，规格 §7 Q3**）；不验证同一自然人兼任两员的账号级强制（归 3.9.2 / 部署期，规格 §7 Q4）；不验证库内多租户维度（**V1.0 不做，规格 §7 Q1**）；不验证短信 / 邮件通知与告警外发（G-04）。
