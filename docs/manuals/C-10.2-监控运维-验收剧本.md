## 剧本 S1：监控读数与连接器健康度幕（行为 B5、B6，正向 + 诚实标注 + 三态）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 系统管理员 | 打开基线看板，逐区块记录当前读数作为基线；并抽查一项读数与指标端点对照 | 四区块齐备且可读：**服务存活** / **JVM 堆内存与 GC** / **HTTP 速率** / **5xx 错误率与 P95 时延**；抽查项（如 HTTP 速率或 P95）与对应服务 `/actuator/prometheus` 同指标取值一致（B5-2） |
| 2 | 系统管理员 | 核对指标端点暴露面（各服务配置） | 暴露面收敛为 `health,prometheus`，无其他 actuator 端点开放（B5-1） |
| 3 | 系统管理员 | 在读数面查找**未接入指标**的服务 | 明确的"未接入"标注可见（**不显示为 0、不显示为绿**）；与监控读面"未接入"标注一致（未接入项不以 0 或绿呈现）（B5-4，负向 + 观察点） |
| 4 | 系统管理员（持健康总览只读权限点；3.9.2 落地前由既有治理档 `admin` 演示） | 打开连接器健康总览，逐连接器记录状态与最近心跳时点 | 每个连接器给出**三态之一**：在线 / 离线 / 从未上报；"在线"项的最近心跳时点新鲜，"离线"项超过阈值（B6-1） |
| 5 | 系统管理员（同上权限口径） | 按附录 A 将 `offline-after` 阈值调小并重启 connector-service，复看健康总览 | 同一心跳数据下，原"在线"连接器派生结论变为"离线"（阈值生效，读时派生）（B6-2，受控构造） |
| 6 | 系统管理员（同上权限口径） | 按附录 A 还原阈值并重启，复看健康总览 | 结论恢复原状；还原前后均留痕（B6-2 / 附录 A） |
| 7 | 系统管理员（同上权限口径） | 核对一个"离线"连接器的注册状态 | 该连接器**仍在册**（注册状态独立于在线状态）；注销的连接器即便有心跳历史也不在册（B6-4，双向） |
| 8 | 普通业务角色 | 尝试读取他人连接器的健康明细 | 被拒（403 + `1000C0005`，文案"无权限执行该操作"）；本步不适用同码同文口径（后者仅指归属不匹配 ∥ 对象不存在，均 400 + `1000C0003`）（B6-3，负向） |
| 9 | 系统管理员 | 尝试写入 / 修改指标读数 | 系统**无**手工写入或修改读数的入口（B5-3，负向） |

## 剧本 S2：容量告警与处置幕（行为 B7、B8，双向 + 留痕 + 边界）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 系统管理员 | 打开告警列表，记录当前状态作为基线 | 列表可读，每条告警要素齐备：告警名 / 级别 / 对象 / 触发时点 / 当前值 / 阈值 / 状态（firing · resolved）（B7-1） |
| 2 | 系统管理员（演示执行人） | 按附录 A 构造一次服务下线（后端副本置 0） | 构造动作前后留痕（操作人 / 时点 / 动作）；此为演示期专用动作 |
| 3 | 系统管理员 | 等待规则窗口（1 分钟）后查看告警列表 | `CtdsBackendDown` 进入 **firing**（critical），对象与实际下线服务一致；要素齐备（B7-2 正向） |
| 4 | 系统管理员（演示执行人） | 按附录 A 恢复副本（置 1），再等待一个窗口 | 告警转为 **resolved**；恢复动作留痕（B7-2 双向） |
| 5 | 系统管理员 | 查看 `CtdsBackendHighErrorRate`（5xx 占比 > 5%）的触发条件与当前读数；无法构造流量时执行**演算** | 规则与阈值可读出；**触发或演算二者之一必须完成**——演算 = 以 Prometheus 查询表达式在 5m 窗口内演算 5xx 占比 > 5% 并留档算式与取值（示例：`sum(rate(http_server_requests_seconds_count{status=~"5.."}[5m])) / sum(rate(http_server_requests_seconds_count[5m]))`）；"未触发且无演算记录"= 该条挂账不判定（不得记为通过）（B7-2） |
| 6 | 系统管理员 | 对一条告警执行处置动作（确认 / 静默 / 升级任一可行者） | 处置成功，产生处置留痕：处置人 / 时点 / 对象 / 结论（B8-1） |
| 7 | 安全管理员 / 审计管理员 / 普通业务角色 | 分别尝试执行运维处置动作（确认 / 静默） | 三类角色**均被拒**（403 + `1000C0005`）；仅系统管理员可执行（B8-3，双向） |
| 8 | 系统管理员 | 查找删除监控 / 告警数据的入口 | 系统**无**删除入口（B8-2，负向 + 观察点） |
| 9 | 编排师（判定人） | 核对规格与本剧本的能力边界表述 | 明示"告警外发通道未接（**G-04 待生效**）""集中日志与留存未建（**G-07 待生效**）""监控数据不持久化（Pod 重建清零）""单副本无高可用""不含集群层指标"（ADR-014 §4）；**无**"已实现邮件/短信/webhook 通知""长期留痕已满足"类承诺（B7-3 / B8-4，观察点） |

## 附录 A：演示期专用构造与留痕（禁生产）

| 项 | 口径 |
| --- | --- |
| 适用范围 | S1-5 / S1-6（阈值调整与还原）与 S2-2 / S2-4（服务下线与恢复）仅限演示环境；生产 / 演示外环境一律禁止 |
| 构造方式 | ① **阈值调整** = 修改 connector-service 配置 `ctds.connector.health.offline-after`（**重启生效**，无运行期开关；**仅系统管理员执行，须以变更单 / 部署记录留痕**）→ 复看派生结论 → 按原值还原并再次重启；② **服务下线** = `kubectl -n default scale deployment ctds-backend --replicas=0`（等价"服务不可达"），恢复 = 置回 1；③ 不得以直接改库、改 Prometheus 内部数据或伪造告警的方式构造判定 |
| 留痕要求 | 构造前记录原值（副本数 / 阈值），构造后记录新值与操作人 / 时点；S2 恢复后须确认告警转 resolved 方视为处置完毕 |
| 还原核验 | 还原后必须复看一次基线（副本 = 1、阈值 = 原值、健康总览结论恢复），避免遗留污染后续演示（沿"停 → 验证 → 重启 → 复验"收工惯例） |
