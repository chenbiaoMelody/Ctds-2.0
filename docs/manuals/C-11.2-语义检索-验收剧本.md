## 步骤

### S1 向量化与相似度数学（B1：本地确定性、离线、零外呼）

- **做什么**：运行公共组件测试，验证①同一文本在任何实例得到同一 384 维向量；②向量 L2 归一化；③纯标点/空文本为零向量；④余弦相似度/Top-K 排序与维度边界。
- **命令**：`mvn -B -ntp -pl common/vector-store test checkstyle:check`
- **预期**：`Tests run: 10, Failures: 0, Errors: 0`，checkstyle 0 违规，BUILD SUCCESS。
- **业务含义**：平台具备可复现的本地向量化与排序底座，不依赖外部模型、不产生费用。

### S2 语义检索范围、排序与刷新（B2/B3）

- **做什么**：运行 catalog 集成测试（真实 MySQL 8 容器，Flyway V1~V5），验证——
  1. 结果恒仅 LISTED（DRAFT/DELISTED/CANCELLED 不出现）；响应字段与 R6 完全一致（无 score/status）；
  2. 相关产品按相似度排在未匹配产品之前；
  3. 来源资源语义标签参与命中；简介变更后源指纹触发重算、排名上升；下架后立即不可见且缓存行保留；
  4. 分类父类目含子树过滤；分页 `total/totalPages` 稳定；
  5. `q` 空/超长/类目不存在 → `1007C0013`；纯标点 → 200 空页；未认证 401；无 `catalog.read` 403；未入驻 `1007C0006`；分页越界 `1000C0001`。
- **命令**：`mvn -B -ntp -pl services/catalog-service -am -Dtest=CatalogSemanticSearchIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false test`
- **预期/实测**：`Tests run: 5, Failures: 0, Errors: 0`，BUILD SUCCESS。
- **业务含义**：需求方可用"金融风控"这类词找到相关数据；下架零泄漏；资格与目录检索同口径。

### S3 V5 向量缓存表迁移（B2/B4）

- **做什么**：在全新 MySQL 8 库上跑 Flyway V1~V5，核对 `product_embedding` 表结构/注释/主键，并核对 V1~V4 既有表（含 `data_product`）列零扰动。
- **命令**：`mvn -B -ntp -pl services/catalog-service -am -Dtest=CatalogProductVectorMigrationIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false test`
- **预期/实测**：`Tests run: 1, Failures: 0, Errors: 0`，BUILD SUCCESS。
- **业务含义**：新增向量缓存不动既有数据结构，升级可回放、可复核。

### S4 演示规模性能基准（B5）

- **做什么**：复用 `scripts/benchmark/catalog-seed.sql` 造 1k/10k 已上架产品；记录首查（惰性向量计算/回写）耗时与预热后稳态 P50/P95/max；10k 稳态 P95 目标 ≤500ms（容器内单机口径）。
- **命令**：`mvn -B -ntp -pl services/catalog-service -am -Dtest=CatalogSemanticSearchBenchmarkIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false test`
- **实测**（2026-11-17，容器内单机、串行、Mock 资格门、无并发加压）：1k 冷启动 **1637ms** / P50 **17ms** / P95 **24ms**；10k 冷启动 **8754ms** / P50 **93ms** / P95 **106ms**；10k P95 ≤500ms **PASS**。结果 JSON：`services/catalog-service/target/benchmark/w3102-semantic-bench-*.json`。
- **业务含义**：演示规模（万级产品）检索可用；首查需建缓存（冷启动秒级），稳态毫秒级；**不宣称生产并发性能**。

### S5 零外呼、零密钥与既有面回归（B4）

- **做什么**：核对五项证据——
  1. **E1 零外呼/零新增外部构件**：`common-vector-store` 仅 test starter 依赖；主源零 `java.net/HttpClient/okhttp/openai` 引用；全部测试离线可跑（除 Testcontainers 本地 Docker）；
  2. **E2 零真实密钥**：本卡零密钥配置/字段；门禁 secretsScan 应为 GREEN（门禁单发时核验）；
  3. **E3 既有面零改动**：既有 21 个 catalog 测试文件零改动；R6 关键词检索测试 11/11 绿；代码 diff 仅新模块 + 根 pom/模块 pom 登记 + catalog 语义检索链 + V5 + 测试/文档；
  4. **E4 全量回归**：catalog 全量测试 **195/195** 绿（含既有 R6 与既有基准）；checkstyle 0 违规；全仓门禁单发 GREEN、ConfigSha256 逐字一致、coverage overall 不劣于 **92.36%**（**门禁单发待评审/验收前补跑**）；
  5. **既有面行为**：R6 检索路径/参数/响应零变化；前端/网关零改动；V1~V4 零改动。
- **业务含义**：本卡只新增"按意思找数据"的读端点与内部向量缓存；不改既有检索、不动网关/前端、不引入新中间件、不产生模型费用。

## 通过判定

S1~S4 全绿 + S5 五项证据齐备（E4 门禁单发在评审/验收前补齐）= 验收通过。

**诚实边界**（lofi §6 / hifi §3/§9）：
1. 本地确定性向量不是真实语义模型——同义词/深层语义能力有限，**不承诺** PRD :263"目录语义检索 Top5 命中率 ≥90%"上线指标；真实 embedding 归 V1.5；
2. MySQL 8 + Java 余弦为演示规模实现（O(n) 扫描），**不是生产级向量数据库**；未来数据/性能触顶时按 ADR-003 §5 新增 pgvector/Milvus 适配器（可覆写 `VectorStore.search`）；
3. 基准为容器内单机、串行、Mock 资格门、无并发加压；首查冷启动秒级（1k ≈1.6s / 10k ≈8.8s），生产并发/容量归 WBS-4.2.1 / V1.5；
4. 进程内 L1 向量缓存为实现优化（持久层仍为 MySQL）；多实例各自缓存，源指纹校验保证变更可感知；
5. 语义检索端点当前直连 catalog 8084 验收；`/api/v1/catalog/**` 网关路由为存量缺口，不属本卡。
