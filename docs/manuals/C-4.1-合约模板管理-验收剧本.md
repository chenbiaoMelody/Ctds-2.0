## 剧本 S1：模板浏览（三类预置、启用可见、资格门槛）

**验证规格行为**：行为 1 规则 2 / 5（预置三类、浏览边界与防枚举）

| 步骤 | 操作人 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 已入驻主体（**A 主体**） | 打开模板浏览入口，查看模板列表 | 列表可见**三类预置模板**：公共数据授权 / API 调用 / 隐私计算（均为"启用中"） |
| 2 | 已入驻主体（A 主体） | 打开"API 调用"类模板详情 | 可见**条款框架**（必填条款项与可选项；具体槽位名称以交付实物为准）；页面**不含**任何数据本体与敏感原文 |
| 3 | 未入驻主体（**C 主体**，待审核） | 以 C 主体身份尝试浏览模板 | **被拒绝**，提示为**统一业务文案**（不提示"主体不存在"，防枚举） |

## 剧本 S2：版本与维护（版本化、版本快照、启停）

**验证规格行为**：行为 1 规则 1 / 3 / 4（维护权唯一、版本化与快照、启停）

| 步骤 | 操作人 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 平台运营管理员 | 修订"API 调用"类模板的条款框架（如新增一个可选条款项）并发布 | 产生**新版本号**（如 V1 → V2）；**旧版本保留可查**；维护留痕四要素齐备（谁 / 何时 / 哪个模板 / 什么动作与版本号） |
| 2 | 已入驻主体（**B 主体**） | 在模板列表查看该模板 | 显示**最新版本 V2** |
| 3 | 运维 / 演示员（技术侧配合项） | 核对一份基于该模板 **V1** 发起、仍处"协商中"的既有合约草案（由 C-4.2 剧本 S1 步骤 1 产出） | 草案**仍按 V1 版本快照显示条款**，**不受 V2 修订影响**（版本快照） |
| 4 | 平台运营管理员 | **停用**"隐私计算"类模板 | 停用成功且留痕；模板列表中该模板不再呈现为"启用中"（浏览者不可见 / 不可用于新发起，二选一以 3.4.2 交付口径为准，业务判定 = 不可用） |
| 5 | 运维 / 演示员（技术侧配合项） | 尝试以该已停用模板新发起一份合约草案 | **被拒绝**（停用模板不可新发起） |
| 6 | 平台运营管理员 | 重新**启用**该模板 | 启用成功且留痕；恢复可浏览、可发起 |

## 剧本 S3：边界与留痕（越权拒绝、留痕可查）

**验证规格行为**：行为 1 规则 1 / 6 / 7 与行为 7 规则 3（维护权唯一、服务端强制、留痕）

| 步骤 | 操作人 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 已入驻主体（**B 主体**） | 以 B 主体身份尝试新增 / 修订 / 停用模板（含**直接调用接口**绕过界面的技术侧配合变体） | **均被拒绝**且记录拒绝留痕（服务端强制；模板维护仅限平台运营方） |
| 2 | 未入驻主体（**C 主体**） | 以 C 主体身份尝试维护模板 | **被拒绝**，提示为统一业务文案（防枚举） |
| 3 | 平台运营管理员 | 查看模板维护留痕（新增 / 修订 / 启停） | 每条留痕含"谁 / 何时 / 哪个模板 / 什么动作与版本号"，**不含敏感原文** |

## 剧本维护说明

1. **界面名称核对修订（3.4.7 交付后一次完成）**：本剧本界面入口当前为占位；待 WBS-3.4.7 交付后按 C-1.2 / C-3.1 剧本同款机制一次性核对修订（只改名称 / 路径 / 承载说明，业务判定不变，修订经 PO 批准留痕）。
2. **剧本间执行顺序**：本剧本独立可执行；若与 C-4.2 剧本串演，推荐顺序 = **本剧本（S1 / S2——S2 步骤 3 依赖 C-4.2 剧本 S1 步骤 1 的协商中草案）→ C-4.2（全幕）→ C-4.3（全幕）**；单独执行时 S2 步骤 3 的"既有草案"可由技术侧代造（判定面相同）。
3. **规格变更联动**：规格 C-4.1~4.3 若变更（含决策点口径调整），本剧本须同批同步并提示 PO 审批（章程 §7 剧本同步）。
4. **执行记录**：执行时在验收会话记录中回填"逐步现象 + 结论"；剧本不承载技术细节，技术证据由对应任务卡的测试与门禁报告承载。
