## 剧本 S1：计量采集与流水幕（行为 B7、B8）

> **V1.1 操作形态注记**：本幕操作路径自 3.7.5 交付起以计量采集服务接口承载；S1-3 / S1-4 新增"运营触发采集"操作步（V1.1 新增，业务判定不变）。各步 curl 示例见幕末《S1 操作路径表》；各步"预期结果"（业务判定）与 V1.0 一字未改。

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 需方 A | 查询本方 P1 合约的计量流水 | 放行 N 次 → 计量可勾稽事件数 = N（**放行 1 次 ≡ 计量事件 1 条**），每条含事件时点、动作、合约编号（B7-1） |
| 2 | 需方 A | 对 P1 合约发起一次越界调用（沿 C-4.3 越界场景构造） | 调用被拒；计量事件数仍 = N 不变；拒绝留痕独立存在且**不进入**任何计量聚合（B7-2，负向：拒绝零计量） |
| 3 | 运营方 | 对同一交付动作做三方勾稽：**先运营触发计量采集（V1.1 新增操作步，见操作路径表）**，随后核对交付记录 / 合约策略计数 / 计量流水 | 三方各恰好 1 条且相互一致——**不双计**（交付记录与策略计数分工沿 ADR-023，计量侧无第二份流水）（B7-3） |
| 4 | 运营方 | 查沙箱作业与导出的计量记录（**V1.1：先运营触发采集，见操作路径表**）；随后执行一次策略模拟器 / 测试台自检 | 沙箱作业与导出各计一次使用且不互相叠加（单一事件源不双轨）；自检执行后计量流水**零新增**（B7-4） |
| 5 | 需方 A | 查 P0（免费档）合约的计量与计费情况 | 计费金额 = 0、无计费明细行；但其调用事件留痕完整可查（B8-2） |
| 6 | 运营方 | 核对 P1 合约"第 1~N 次放行 + 第 N+1 次越界被拒"序列的计数与计量 | 计数表 = N、计量聚合 = N——拒绝未触碰任何计数与计量（B8-3，负向核对） |
| 7 | 主体 C | 以主体 C 身份查询需方 A 合约的计量记录 | 被拒绝，错误信息业务可读（B8-4，负向——C 与该合约无任何当事关系） |

### S1 操作路径表（V1.1：接口承载 + curl 示例）

> 调用一律**直连计量采集服务回环端口** `http://127.0.0.1:8089`：平台身份头信任边界 = 服务回环直连（ADR-016 §2.7），演示期以身份头注入调用（`X-Ctds-Subject` 主体号 / `X-Ctds-Roles` 角色）。**身份头不可经网关注入**——网关对入站身份头一律剥离重建（防伪造），经网关调用须持 JWT 令牌：正式链路 `http://127.0.0.1:8086/api/v1/metering/**` 同路径代理可用（JWT 鉴权；3.7.7 界面交付后切换承载时启用）。`<合约号>` 形如 CO + 6 位。接口统一响应封套中 `code = "0"` 为成功；错误码与业务文案在各步预期中标注。

| 步骤 | 角色与接口调用（curl 示例） | 读数与判定承载 |
| --- | --- | --- |
| S1-1 | 需方 A：`curl -H "X-Ctds-Subject: <需方A主体号>" -H "X-Ctds-Roles: requester" http://127.0.0.1:8089/api/v1/metering/contracts/<P1合约号>/flows` | 流水逐条可溯（时点/动作/合约/主体），事件数 = N |
| S1-2 | 越界调用后重跑 S1-1；拒绝留痕查看：网关审计文件 `logs/audit-<日期>.jsonl` 中 `gateway.delivery.denied` 行 | 流水仍 = N；拒绝留痕独立存在（文件面存证），不入计量聚合 |
| S1-3 | 运营方两步——① 触发采集：`curl -X POST -H "X-Ctds-Subject: <运营主体号>" -H "X-Ctds-Roles: admin" http://127.0.0.1:8089/api/v1/metering/collect`；② 四方读数：`curl -H "X-Ctds-Subject: <运营主体号>" -H "X-Ctds-Roles: admin" http://127.0.0.1:8089/api/v1/metering/contracts/<P1合约号>/reconcile` | ② 返回中 `deliveryFileCount` / `usageLogAllowedCount` / `meteringFlowCount` 各 = 1（`usageCounterUsedCount` 同步 = 1）——三方各恰好 1 条不双计 |
| S1-4 | 同 S1-3 两步（换沙箱合约号）；模拟器自检执行后重跑①触发采集，响应 `collected = 0` | 沙箱作业与导出各计 1 条；自检后采集零新增 |
| S1-5 | 需方 A：flows 与 summary（免费档 P0 合约号）——`curl ... /api/v1/metering/contracts/<P0合约号>/flows`（summary 同路径换 `/summary`）；**V1.2 补验**：运营方对 P0 触发出账（S2-1 同款调用换 P0 合约号） | 事件留痕完整可查；**免费档无账单**——出账被拒 HTTP 409 `code = 1011C0015`、账单零新增（B8-2 字面口径） |
| S1-6 | 运营方：reconcile（P1 合约号）+ 需方 A：summary（P1 合约号） | `usageCounterUsedCount = meteringFlowCount = N`；summary 分期聚合合计 = N |
| S1-7 | 主体 C：`curl -i -H "X-Ctds-Subject: <主体C主体号>" -H "X-Ctds-Roles: requester" http://127.0.0.1:8089/api/v1/metering/contracts/<P1合约号>/flows` | HTTP 404 + 响应 `code = 1011C0008`、文案"计量数据不存在或不可读"（业务可读，不暴露内部实现） |

> 非本方读数错误为**同码同文**（合约不存在与非本方同形，防枚举）；触发采集可重复执行（重复触发 `collected = 0` 幂等，零重计）。

## 剧本 S2：出账幕（行为 B9、B10、B12）

> **V1.2 操作形态注记**：本幕操作路径自 3.7.6 交付起以计费接口承载（前缀 `/api/v1/billing/**`）；各步 curl 示例见幕末《S2 操作路径表》。**各步"预期结果"（业务判定）与 V1.1 一字未改**。

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 运营方 | 对 P1 合约手动触发即时出账 | 账单生成：金额 = N × 次单价，明细逐条可溯至计量流水；账单字段最小集齐备（编号 / 合约与双方 / 周期 / 金额构成 / 状态 / 生成时点）（B9-1、B10-1） |
| 2 | 运营方 | 对 P1 合约同周期再次触发出账 | 被拒绝（幂等），理由业务可读（B10-1，负向） |
| 3 | 运营方 | 对 P2（包月）合约触发本周期出账 | 账单金额 = 订单周期费，与调用次数无关（调用次数变化不影响包月金额）（B9-2） |
| 4 | 运营方 | 对 P3（交易额分成）合约触发出账 | 账单金额 = 约定交易额 × 分成费率，基数与费率均可追溯至合约 / 订单定价快照（B9-3） |
| 5 | 需方 A | 按账单明细 + 定价快照独立复算 P1 账单金额 | 复算结果 = 账单金额（同输入同输出，计费可复算）（B9-4） |
| 6 | 供方 B | 变更在售产品定价（走目录域既有流程），随后核对已出账单 | 定价变更留痕、只向后生效；**已生成账单金额逐字不变**（B9-4，负向：不得追溯改账） |
| 7 | 运营方 | 尝试直接修改已生成账单的金额字段；随后演示更正路径（另出更正单 / 红字冲正） | 直接修改被系统拒绝；更正单生成后原账单内容逐字未变且全程留痕（B10-3，负向 + 留痕） |
| 8 | 运营方 | 抽查全部账单编号 | 编号全库唯一、终身不复用（含已关闭 / 冲正账单）（B10-2，观察点） |
| 9 | 需方 A / 供方 B | 分别按合约、周期、产品过滤查询本方计量与账单 | 各自结果完整且仅含本方数据（B12-1） |
| 10 | 主体 C | 查询需方 A 与供方 B 之间的账单（非本方） | 被拒绝，错误信息业务可读、无内部实现细节（B12-3，负向——C 与该账单合约无任何当事关系） |
| 11 | （说明步） | 编排师核对出账触发口径 | 本剧本以手动即时出账承载演示；**自然月周期自动出账（B10-1 周期腿）已由 3.7.6 实现**（每月 1 日 00:10 出上月账，cron / 开关可配），其实现验证由自动化用例承载（固定周期批量出账 + 重复运行零新增 + 免费档 / 无计量 / 分成无基数跳过），**不等待真实时钟**；本剧本只验手动腿（业务判定不变） |

### S2 操作路径表（V1.2：接口承载 + curl 示例）

> 调用一律**直连服务回环端口** `http://127.0.0.1:8089`（身份头信任边界 = 服务回环直连，ADR-016 §2.7；经网关正式链路 `http://127.0.0.1:8086/api/v1/billing/**` 同路径代理、JWT 鉴权）。`<合约号>` 形如 CO + 6 位，`<账单号>` 形如 BL + 6 位，`<周期>` 形如 2026-10。响应封套 `code = "0"` 为成功。

| 步骤 | 角色与接口调用（curl 示例） | 读数与判定承载 |
| --- | --- | --- |
| S2-1 | 运营方：`curl -X POST -H "Content-Type: application/json" -H "X-Ctds-Subject: <运营主体号>" -H "X-Ctds-Roles: admin" -d "{\"contractNo\":\"<P1合约号>\",\"period\":\"<周期>\"}" http://127.0.0.1:8089/api/v1/billing/bills` | HTTP 201；`data.amount` = N × 次单价、`data.quantity` = N、`data.details` 逐条含 `meteringFlowId`；账单号 / 双方 / 周期 / 金额构成 / 状态 `ISSUED` / 生成时点齐备 |
| S2-2 | 同 S2-1 再发一次 | HTTP 409，`code = 1011C0010`、文案"该合约该周期账单已存在，请勿重复出账" |
| S2-3 | 同 S2-1（换 P2 包月合约号） | `data.amount` = 周期费、`data.quantity` 为空；调用次数变化不影响该金额 |
| S2-4 | 同 S2-1（换 P3 分成合约号，并携带基数）：`-d "{\"contractNo\":\"<P3合约号>\",\"period\":\"<周期>\",\"agreedTransactionAmount\":10000}"` | `data.amount` = 约定交易额 × 费率；`data.baseAmount` / `data.shareRate` 双快照可读（缺基数 → HTTP 400 `code = 1011C0013`） |
| S2-5 | 需方 A：`curl -H "X-Ctds-Subject: <需方A主体号>" -H "X-Ctds-Roles: requester" http://127.0.0.1:8089/api/v1/billing/bills/<账单号>` | 按 `details` 逐行金额 + 账单头快照独立复算 = `data.amount`（同输入同输出） |
| S2-6 | 供方 B 走目录域变更定价后，重跑 S2-5 | `data.amount` 与 `data.details` 逐字不变（既有账单不追溯）；新周期出账方按新快照 |
| S2-7 | 直接修改：对账单路径发 `PUT` / `PATCH`（同 URL）→ 404 / 405，无金额修改端点；更正路径：`curl -X POST -H "Content-Type: application/json" -H "X-Ctds-Subject: <运营主体号>" -H "X-Ctds-Roles: admin" -d "{\"amount\":-3.00,\"reason\":\"红字冲正：计量口径修正\"}" http://127.0.0.1:8089/api/v1/billing/bills/<账单号>/corrections` | 直接修改被拒；更正单 HTTP 201（`billType = CORRECTION`、`correctionOfBillNo` = 原单号）；重跑 S2-5 原单金额与明细逐字未变，`correctionBillNos` 可见更正单（双向可溯） |
| S2-8 | 运营方：`curl -H "X-Ctds-Subject: <运营主体号>" -H "X-Ctds-Roles: admin" "http://127.0.0.1:8089/api/v1/billing/bills/governance?pageSize=100"` | 编号全库唯一、终身不复用（含更正单编号） |
| S2-9 | 需方 A / 供方 B：`curl ... "http://127.0.0.1:8089/api/v1/billing/bills/mine?contractNo=<合约号>&period=<周期>&productId=<产品id>"` | 各自结果仅含本方数据，`myRole` 标注 `REQUESTER` / `PROVIDER` |
| S2-10 | 主体 C：`curl -i -H "X-Ctds-Subject: <主体C主体号>" -H "X-Ctds-Roles: requester" http://127.0.0.1:8089/api/v1/billing/bills/<账单号>` | HTTP 404 + `code = 1011C0009`、文案"账单或对账数据不存在或不可读"（与"账单不存在"同码同文，防枚举） |

> 非本方读数一律**同码同文**（账单不存在与非本方同形）；同合约同周期重复出账由唯一键兜底（并发同样恰一成功）。
