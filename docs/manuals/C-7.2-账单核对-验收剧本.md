## 剧本 S1：对账通过幕（行为 B11-1，正向）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 运营方 | 对 P1 合约本周期账单发起对账 | 对账执行，四方比对齐备：合约计数表（余额口径）/ 合约执行流水（流水口径）/ 计量流水聚合 / 账单合计（B11-1） |
| 2 | 运营方 | 查看对账结论与留痕 | 结论 = "通过"；四方数值逐项一致可读；对账时点、比对数值、结论、执行人留痕完整（B11-1、B11-4） |
| 3 | 需方 A | 查看本合约对账结论 | 需方 / 供方可读本方合约的对账结论（B12-1，读面观察点） |

## 剧本 S2：差异处置幕（行为 B11-2 / B11-3 / B11-4，负向 + fail-closed 处置）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | （演示期专用） | 按附录 A 方式构造账实差异：使计量流水聚合与账单合计不一致（如少计一条放行明细） | 构造前后均留痕（操作人 / 时点 / 改动内容）；此为**对账断言负向验证的演示期专用动作**，业务系统本身无"改流水"入口（B11-2 前置） |
| 2 | 运营方 | 再次对同一账单发起对账 | 结论 = "差异"（**账实不符必被报**，不允许静默通过）；差异明细可定位（缺失 / 多出 / 不一致的条目可读）（B11-2，负向，双向断言） |
| 3 | 运营方 | 尝试确认 / 继续流转该账单 | 被拒绝：相关账单处于冻结态，确认与后续动作被拒且理由业务可读（B11-3，负向 fail-closed） |
| 4 | 运营方 | 执行复核：查看差异明细，登记复核结论与处置决定（演示路径 = 还原附录 A 构造 + 登记更正说明） | 复核全程留痕（复核人 / 时点 / 结论 / 处置）；**除显式人工留痕动作外，系统未自动修改任何数据**（B11-4，观察点） |
| 5 | 运营方 | 差异澄清后再次发起对账 | 结论恢复 = "通过"；账单冻结解除，后续流转恢复可用（B11-3 正向腿收尾） |

## 附录 A：演示数据与差异构造（演示期专用，禁生产）

| 项 | 口径 |
| --- | --- |
| 适用范围 | 本剧本 S2 步骤 1 的差异构造为**全平台对账演示的唯一显式直改库动作**，仅限演示库；生产 / 演示外的库一律禁止（DB-64 累计口径同源纪律：演示库人工处置、构造动作留痕） |
| 构造方式 | 将 P1 合约本周期计量流水中一条放行明细的计费数量或金额改为不一致值（推荐改值不删行：保留勾稽线索、构造后可完整还原） |
| 留痕要求 | 构造前记录原值，构造后记录新值与操作人 / 时点；S2 步骤 4 处置时按原值还原并登记更正说明——构造 → 报警 → 冻结 → 复核 → 还原 → 解冻全链留痕闭合 |
| 还原核验 | 还原后以 S1 口径复跑一次对账，结论 = "通过"方视为构造数据清理完毕（避免遗留账实差异污染后续演示——沿"停 → 验证 → 重启 → 复验"收工惯例） |
