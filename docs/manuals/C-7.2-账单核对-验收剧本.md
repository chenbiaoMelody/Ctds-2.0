### S1 操作路径表（V1.1：接口承载 + curl 示例）

> 调用一律**直连服务回环端口** `http://127.0.0.1:8089`（身份头信任边界 = 服务回环直连，ADR-016 §2.7）。`<合约号>` 形如 CO + 6 位，`<周期>` = 被对账账单的自然月（如 2026-10）。响应封套 `code = "0"` 为成功。

| 步骤 | 角色与接口调用（curl 示例） | 读数与判定承载 |
| --- | --- | --- |
| S1-1 | 运营方：`curl -X POST -H "X-Ctds-Subject: <运营主体号>" -H "X-Ctds-Roles: admin" "http://127.0.0.1:8089/api/v1/billing/contracts/<P1合约号>/reconciliations?period=<周期>"` | HTTP 200；`data` 含四方数值（`counterUsedCount` / `usageLogAllowedCount` / `usageLogAllowedAllTime` / `meteringFlowCount` / `meteringFlowAllTime`）、`billQuantity`、`billTotalAmount`、`recomputedAmount` |
| S1-2 | 同上响应体 + 治理读面复核：`curl ... "http://127.0.0.1:8089/api/v1/billing/bills/governance?contractNo=<P1合约号>&period=<周期>"` | `conclusion = "PASS"`、`differences` 为空、四方数值逐项一致；`createdBy` / `createdAt` / 数值全部落库可查（B11-4 留痕） |
| S1-3 | 需方 A：`curl -H "X-Ctds-Subject: <需方A主体号>" -H "X-Ctds-Roles: requester" "http://127.0.0.1:8089/api/v1/billing/contracts/<P1合约号>/reconciliations?period=<周期>"` | HTTP 200；本方合约对账结论与差异明细可读（B12-1）；主体 C 同调用 → HTTP 404 `code = 1011C0009`（同码同文） |

## 剧本 S2：差异处置幕（行为 B11-2 / B11-3 / B11-4，负向 + fail-closed 处置）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | （演示期专用） | 按附录 A 方式构造账实差异：使计量流水聚合与账单合计不一致（如少计一条放行明细） | 构造前后均留痕（操作人 / 时点 / 改动内容）；此为**对账断言负向验证的演示期专用动作**，业务系统本身无"改流水"入口（B11-2 前置） |
| 2 | 运营方 | 再次对同一账单发起对账 | 结论 = "差异"（**账实不符必被报**，不允许静默通过）；差异明细可定位（缺失 / 多出 / 不一致的条目可读）（B11-2，负向，双向断言） |
| 3 | 运营方 | 尝试确认 / 继续流转该账单 | 被拒绝：相关账单处于冻结态，确认与后续动作被拒且理由业务可读（B11-3，负向 fail-closed） |
| 4 | 运营方 | 执行复核：查看差异明细，登记复核结论与处置决定（演示路径 = 还原附录 A 构造 + 登记更正说明） | 复核全程留痕（复核人 / 时点 / 结论 / 处置）；**除显式人工留痕动作外，系统未自动修改任何数据**（B11-4，观察点） |
| 5 | 运营方 | 差异澄清后再次发起对账 | 结论恢复 = "通过"；账单冻结解除，后续流转恢复可用（B11-3 正向腿收尾） |

### S2 操作路径表（V1.1：接口承载 + curl 示例）

| 步骤 | 角色与接口调用（curl 示例） | 读数与判定承载 |
| --- | --- | --- |
| S2-1 | 演示期专用构造（见附录 A）：`UPDATE metering_flow SET occurred_at = '<移出本期的时点>' WHERE source_no = '<源单号>'`（改值不删行；先记录原值），并按附录 A 留痕 | 构造前后留痕：原值 / 新值 / 操作人 / 时点（业务系统本身无"改流水"入口） |
| S2-2 | 运营方重跑 S1-1 同款调用 | `conclusion = "DIFFERENCE"`；`differences` 非空且可定位（`type` 含 `BILL_QUANTITY_VS_METERING` / `USAGE_LOG_VS_METERING_PERIOD` 等，`expected` / `actual` / `detail` 可读）（B11-2 负向） |
| S2-3 | 运营方尝试确认：`curl -X POST -H "X-Ctds-Subject: <运营主体号>" -H "X-Ctds-Roles: admin" http://127.0.0.1:8089/api/v1/billing/bills/<账单号>/confirm` | HTTP 409，`code = 1011C0011`、文案"账单已冻结，当前操作不可执行"；治理读面该账单 `status = FROZEN`（B11-3 fail-closed） |
| S2-4 | 运营方复核并还原附录 A 构造（改回原值时点）+ 登记复核结论与处置说明（演示以台账 / 日志留痕） | 复核全程留痕（复核人 / 时点 / 结论 / 处置）；**除显式人工动作外系统未自动修改任何数据**（B11-4 观察点；对账前后账单金额与明细逐字一致） |
| S2-5 | 运营方还原后重跑 S1-1 同款调用，再确认账单 | `conclusion = "PASS"`；账单 `status` 恢复冻结前状态；随后 confirm 返回 HTTP 200（B11-3 正向腿收尾） |

## 附录 A：演示数据与差异构造（演示期专用，禁生产）

| 项 | 口径 |
| --- | --- |
| 适用范围 | 本剧本 S2 步骤 1 的差异构造为**全平台对账演示的唯一显式直改库动作**，仅限演示库；生产 / 演示外的库一律禁止（DB-64 累计口径同源纪律：演示库人工处置、构造动作留痕） |
| 构造方式 | **V1.1 适配实现列面**：计量流水表 `metering_flow` 无"计费数量 / 金额"列（列面 = 合约 / 主体 / 源单号 / 动作 / 资源 / 事件时点），故构造方式改为**改一条放行明细的事件时点（`occurred_at`）移出本期**——`UPDATE metering_flow SET occurred_at = '<上月或更早时点>' WHERE source_no = '<源单号>'`（**改值不删行**：保留勾稽线索、构造后可完整还原）；效果等价于"本期少计一条放行明细"，业务判定（差异必报 + 冻结 + 还原解冻）不变 |
| 留痕要求 | 构造前记录原值，构造后记录新值与操作人 / 时点；S2 步骤 4 处置时按原值还原并登记更正说明——构造 → 报警 → 冻结 → 复核 → 还原 → 解冻全链留痕闭合 |
| 还原核验 | 还原后以 S1 口径复跑一次对账，结论 = "通过"方视为构造数据清理完毕（避免遗留账实差异污染后续演示——沿"停 → 验证 → 重启 → 复验"收工惯例） |
