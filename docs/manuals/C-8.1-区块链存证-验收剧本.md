## 剧本 S1：四环节存证写入幕（行为 B1、B2，正向 + 幂等负向）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 监管方（运营方治理档） | 打开存证总览，**逐环节记录当前存证条数作为基线**（授权 / 合约 / 交付 / 使用各记一值） | 总览按"授权 / 合约 / 交付 / 使用"四类分列；基线四值可读并记录在案，步骤 2~5 每步在基线对应环节上**恰 +1**（B1-2） |
| 2 | 需方 / 供方 | 在空间内完成一次成员准入（**由业务系统自动触发**：空间成员申请审批通过或邀请确认），或完成一份公共数据授权类合约生效（二选一，按演示可用路径） | 授权环节新增 1 条存证事件：环节=授权、业务单据号 = 空间准入键 `SPACE{空间id}:ADMISSION{准入单id}`（可反查 `space_action_log`）或授权类合约编号（与上游留痕**逐字一致**）、主体标识为 DID 摘要（B1-1 / B1-3 / B1-4） |
| 3 | 需方 / 供方 | 发起并完成一份合约双签（合约生效）（**由业务系统自动触发**：合约双方依次签署） | 合约环节新增 1 条存证事件，其业务单据号与合约域存证事件（`contract_attestation`.`contract_no`）**逐字一致**（B1-3 / B1-4）；若该合约为公共数据授权类，授权环节同时新增 1 条（同单号同时点，Q5 双写——授权环节基线亦 +1） |
| 4 | 需方 | 完成一次交付调用（**由业务系统自动触发**：发起 API / FILE 交付） | 交付环节新增 1 条存证事件，业务单据号 = 交付记录单号（**逐字一致**）（B1-1 / B1-3 / B1-4） |
| 5 | 需方 | 完成一次使用控制放行；另发起一次会被拒绝的越界调用（**由业务系统自动触发**：交付判定 / 网关调用） | 放行新增 1 条存证事件，业务单据号 = 使用放行留痕单号 `USG{12 位}`（与 `contract_usage_log` 放行行**逐字一致**）；**拒绝调用不产生存证事件**（拒绝零计量沿 ADR-020 §2.4，证据层同理），拒绝留痕可在审计调阅中读到（B1-1 / B1-3） |
| 6 | 运营方 | 对同一步骤 4 的同一笔交付重复触发存证（模拟重试） | 存证事件条数**不增加**（同一环节 + 同一单据号 + 同一操作类型唯一）；无第二条重复记录（B2-2，负向 + 幂等） |
| 7 | 监管方 | 抽查上述任一条存证事件的存证内容 | 仅含内容摘要 + 元数据四项（业务单据号 / 时间戳 / 操作类型 / 主体 DID 摘要）；**不出现数据原文、个人信息、商业密文、密钥材料**（B1-4，负向） |
| 8 | 监管方 | 读出**至少 2 条**存证事件的编号与六要素 | 两条编号互不相同且格式可读；六要素齐备（字段有值、非空串）；状态为"已上链"或"待上链"；无同号复用痕迹（B1-1 / B1-2） |

## 剧本 S2：核验与失败处置幕（行为 B3、B4，双向 + fail-visible）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 监管方 | 对 S1 任一条"已上链"存证事件发起核验 | 结论显式 = **"通过"**；核验人、时点、对象、结论留痕可查（B3-1 / B3-3） |
| 2 | 运营方（演示执行人） | 按附录 A 构造一次"摘要不一致"（受控替身或测试链改造，仅演示环境） | 构造前后均留痕（操作人 / 时点 / 改动内容）；此为**核验负向验证的演示期专用动作**，业务系统本身无"改存证"入口（B3-2 前置） |
| 3 | 监管方 | 对步骤 2 的存证事件再次核验 | 结论显式 = **"不一致"**（不允许默认通过）；可定位差异（存证编号 / 业务单据号 / 期望摘要 / 实际摘要 / 核验时点）（B3-2，负向 + 双向断言） |
| 4 | 运营方（演示执行人） | 按附录 A 还原步骤 2 的构造；随后制造一次"链不可达"（停止链节点或断开适配器） | 还原后核验恢复"通过"；链不可达期间新产生的存证事件状态 = **"上链失败"**，原因摘要可读（B4-1） |
| 5 | 监管方 | 对步骤 4 产生的"上链失败"存证事件发起核验；若存在"待上链"态事件，同样各核验一次 | 结论显式 = **"未上链"**（不默认通过、不报"不一致"）；同时提示当前存证状态（上链失败 / 待上链）；若演示中构造不出"待上链"态，须记录"该态不可构造"说明（B3-3，负向） |
| 6 | 运营方 | 打开存证总览查看异常项 | 待上链数与失败数与实际状态一致；失败项含最近失败时点（B4-2） |
| 7 | 运营方 | 恢复链可用后对失败存证事件执行重试 | 重试成功 → 状态推进为"已上链"；失败记录与重试记录**两条都保留**，且状态流转记录可读出**每步时点与结果、无空窗**（B2-4 / B4-3） |
| 8 | 监管方 | 核验前先记录业务数据快照，执行一次核验后**逐字比对** | 核验不改变存证事件内容，也不改变业务数据（核验前后逐字一致，B3-4，观察点） |
| 9 | 非运营方账号 | 尝试调用"修改存证""删除存证""手工填写链上交易标识"入口 | 界面层**无对应入口**，接口层直调**均被拒绝**（越权一律被拒）；无伪造通道（B2-3 / B4-4，负向） |

### 操作路径说明（V1.3 按 3.8.3 实测落定；界面入口归 3.8.5）

> 服务 = `evidence-service`（本机 `http://127.0.0.1:8090`；治理读面经统一网关 `http://127.0.0.1:8086/api/v1/evidence/**`）。以下路径为**接口承载**，界面交付前以接口工具（如 `curl` / Postman）执行；业务判定与步骤编号不变。

| 剧本步骤 | 接口与身份 |
| --- | --- |
| S1-1 / S2-6（总览） | `GET /api/v1/evidence/overview`（`admin` 角色）→ `onChainCount` / `pendingCount` / `failedCount` / `lastFailedAt` |
| S1-2~S1-5（四环节写入） | **由四环节业务自动触发（V1.3 起不再手工调写面）**：空间成员审批通过 / 邀请确认 → `AUTHORIZATION/SPACE_MEMBER_ADMITTED`（`SPACE{id}:ADMISSION{id}`）；空间策略覆盖 → `AUTHORIZATION/SPACE_POLICY_INHERITED`（`SPACE{id}:POLICY-AL{留痕id}`）；合约双签生效 → `CONTRACT/CONTRACT_EFFECTIVE`（公共数据授权类另加 `AUTHORIZATION/DATA_AUTH_CONTRACT_EFFECTIVE`，同单号同时点）；交付创建 → `DELIVERY/DELIVERY_CREATED`（`delivery_no`）；使用放行 → `USAGE/USAGE_ALLOWED`（`USG{12 位}`）。服务身份头由 `common-evidence-client` 自动携带（`X-Ctds-Subject` = 服务名 / `X-Ctds-Roles: evidence-internal`）；地址由部署注入 `CTDS_EVIDENCE_BASEURL`，未注入 = 跳过 + WARN（业务仍成功）。写面接口与判定不变（3.8.2 冻结） |
| S1-6（重复触发） | 同三元组（环节 + 单据号 + 操作类型）再调一次写面 → 响应 `duplicate=true`、`evidenceNo` 与首次相同 |
| S1-7 / S1-8（抽查 / 编号） | `GET /api/v1/evidence/records?stageType=DELIVERY&pageNum=1&pageSize=10`（至少一个过滤条件）；单笔：`GET /api/v1/evidence/records/{evidenceNo}`（含 `contentDigest`、六要素与留痕） |
| S2-1·3·5（核验） | `POST /api/v1/evidence/records/{evidenceNo}/verify` → `conclusion` = `PASS` / `MISMATCH` / `NOT_ON_CHAIN`（HTTP 恒 200） |
| S2-7（重试） | `POST /api/v1/evidence/records/{evidenceNo}/retry` → 成功 200 `status=ON_CHAIN`；仍不可达 503 `1012S0001`（记录保持 `FAILED`）；已上链 409 `1012C0003` |
| S2-9（越权） | 非 `admin` 角色调上述治理端点 → 403；不存在的编号 → 404 `1012C0001`（同码同文）；接口层无 PUT / PATCH / DELETE 端点（无修改 / 删除 / 手工填交易标识入口） |

## 附录 A：演示期专用构造与留痕（禁生产）

| 项 | 口径 |
| --- | --- |
| 适用范围 | S2 步骤 2（摘要不一致构造）与步骤 4（链不可达构造）仅限演示库与演示链环境；生产 / 演示外环境一律禁止（DB-64 口径同源：演示数据人工处置、构造动作留痕） |
| 构造方式 | ① 摘要不一致 = 在**演示库受控 SQL** 改动一条账本记录的 `payload_digest`（记录原值后再改，如改为 64 个 `a`），不改存证记录本身；正向核验（S2 步骤 1 与步骤 4 还原后复验）必须走**真实适配器**（本卡 = 本地不可变账本）；② 链不可达 = 以环境变量 `CTDS_EVIDENCE_CHAIN_ENABLED=false` **重启**存证服务（等价"断开适配器"/停链；无运行期开关、无后门），恢复 = 改回 `true` 重启；③ "待上链"态 = 只在"账本已写、状态未更"的崩溃窗口出现，**正常演示不可构造** → S2-5 按剧本允许口径记录"该态不可构造"说明，不得用造假方式构造 |
| 留痕要求 | 构造前记录原值，构造后记录新值与操作人 / 时点；S2 步骤 4 按原值还原，还原后复跑核验确认"通过"方视为清理完毕 |
| 还原核验 | 还原后必须复验一次"通过"，避免遗留污染后续演示（沿"停 → 验证 → 重启 → 复验"收工惯例） |

## 剧本维护说明

- **V1.0 定稿（2026-11-05 一次确认）**：随规格 `C-8.1-8.2-存证与审计` V1.0 同批批准；步骤与业务判定以本文件为准，界面入口与操作路径为占位。
- **V1.1 评审修复（2026-11-05 4 视角评审循环 1）**：补"未上链"核验（S2-5）、越权被拒（S2-9）、状态流转时点（S2-7）、编号唯一性对照（S1-8）、单据号逐字一致（S1-2/3/5）、核验前后快照（S2-8）；授权环节改 Q1-A 口径；角色栏改实名。**业务判定与 Q 裁决结论未改。**
- **V1.2 编码段落定（2026-11-05 WBS-3.8.2）**：补"操作路径说明"表（内部写面 + 治理五端点 + 越权口径）、演示构造口径（环境变量关链 + 重启 / 受控 SQL 改账本一行 + 还原）与"待上链态不可构造"说明。**步骤编号与业务判定与 V1.1 逐字一致**；界面入口仍归 3.8.5；本版待 PO 批准后生效。
- **V1.3 编码段落定（2026-11-06 WBS-3.8.3）**：S1-2~S1-5 改为"四环节业务自动触发"（补业务入口）；S1-2 补空间准入键派生规则（`SPACE{id}:ADMISSION{id}`）；S1-3 补公共数据授权类合约 Q5 双写说明（授权环节基线亦 +1）；S1-5 单据号改为"使用放行留痕单号 `USG{12 位}`"；演示前提补 `did-service` 启动与"未启动仅缺该条存证"兜底；操作路径表 S1-2~S1-5 行按实测重写。**步骤编号与业务判定一字未改**；待 PO 批准随验收生效。
- **演示前提联动**：本剧本的可执行前提 = 3.8.2（存证服务与链对接）+ 3.8.3（四环节埋点）交付；3.8.4 / 3.8.5 交付后一次性核对界面入口与自动化覆盖（沿 C-7.2 剧本 V1.1~V1.3 维护先例）。
- **剧本间执行顺序（推荐）**：C-1.1（主体）→ C-2.1（空间）→ C-4.2（合约签署）→ C-4.3（策略生效与使用放行）→ C-5.1（交付调用）→ **本剧本（S1 → S2）** → C-8.2 合规审计（S1 → S2，承接本剧本存证数据）。
- **不可承诺项**：本剧本不验证"司法采信""对外出证"能力（ADR-004 §4 公信力边界，V1.5 评估）；不验证真实链性能（归 3.8.6 / 4.2.x）。
