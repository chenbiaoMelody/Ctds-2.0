## 剧本 S1：四环节存证写入幕（行为 B1、B2，正向 + 幂等负向）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 监管方（运营方治理档） | 打开存证总览，记录当前四环节存证条数 | 总览按"授权 / 合约 / 交付 / 使用"四类分列，条数与当前业务量相符（B1-2） |
| 2 | 需方 / 供方 | 在空间内完成一次成员准入（或空间数据使用授权生效） | 授权环节新增 1 条存证事件：环节=授权、业务单据号可读、主体标识为 DID 摘要（B1-1 / B1-3） |
| 3 | 需方 / 供方 | 发起并完成一份合约双签（合约生效） | 合约环节新增 1 条存证事件，其业务单据号与合约域存证事件（`contract_attestation`）指向同一份合约（B1-3） |
| 4 | 需方 | 完成一次交付调用 | 交付环节新增 1 条存证事件，业务单据号 = 交付记录单号（B1-1 / B1-3） |
| 5 | 需方 | 完成一次使用控制放行 | 使用环节新增 1 条存证事件，业务单据号 = 计量流水源单号；拒绝调用不产生存证（拒绝零计量沿 ADR-020 §2.4） |
| 6 | 运营方 | 对同一步骤 4 的同一笔交付重复触发存证（模拟重试） | 存证事件条数**不增加**（同一环节 + 同一单据号 + 同一操作类型唯一）；无第二条重复记录（B2-2，负向 + 幂等） |
| 7 | 监管方 | 抽查上述任一条存证事件的存证内容 | 仅含内容摘要 + 元数据四项（业务单据号 / 时间戳 / 操作类型 / 主体 DID 摘要）；**不出现数据原文、个人信息、商业密文、密钥材料**（B1-4，负向） |
| 8 | 监管方 | 读出该存证事件的编号与六要素 | 存证编号全局唯一、可读；六要素齐备；状态为"已上链"或"待上链"（B1-1 / B1-2） |

## 剧本 S2：核验与失败处置幕（行为 B3、B4，双向 + fail-visible）

| 序号 | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 监管方 | 对 S1 任一条"已上链"存证事件发起核验 | 结论显式 = **"通过"**；核验人、时点、对象、结论留痕可查（B3-1 / B3-3） |
| 2 | （演示期专用） | 按附录 A 构造一次"摘要不一致"（受控替身或测试链改造，仅演示环境） | 构造前后均留痕（操作人 / 时点 / 改动内容）；此为**核验负向验证的演示期专用动作**，业务系统本身无"改存证"入口（B3-2 前置） |
| 3 | 监管方 | 对步骤 2 的存证事件再次核验 | 结论显式 = **"不一致"**（不允许默认通过）；可定位差异（存证编号 / 业务单据号 / 期望摘要 / 实际摘要 / 核验时点）（B3-2，负向 + 双向断言） |
| 4 | （演示期专用） | 按附录 A 还原步骤 2 的构造；随后制造一次"链不可达"（停止链节点或断开适配器） | 还原后核验恢复"通过"；链不可达期间新产生的存证事件状态 = **"上链失败"**，原因摘要可读（B4-1） |
| 5 | 运营方 | 打开存证总览查看异常项 | 待上链数与失败数与实际状态一致；失败项含最近失败时点（B4-2） |
| 6 | 运营方 | 恢复链可用后对失败存证事件执行重试 | 重试成功 → 状态推进为"已上链"；失败记录与重试记录**两条都保留**（B4-3） |
| 7 | 监管方 | 对照核验前后业务数据 | 核验不改变存证事件内容，也不改变业务数据（B3-4，观察点）；系统无"手工填写链上交易标识""修改 / 删除存证"入口（B4-4，负向 + 观察点） |

### 操作路径说明（V0.9 占位）

> 存证服务端点（`EvidenceGateway` 的存证 / 核验 / 查询）由 3.8.2 落定，本剧本立卡期不预设端点与端口；3.8.2 / 3.8.3 交付后按实测补"逐步接口与界面路径"，**业务判定不变**（沿 C-7.2 V1.1 修订先例）。

## 附录 A：演示期专用构造与留痕（禁生产）

| 项 | 口径 |
| --- | --- |
| 适用范围 | S2 步骤 2（摘要不一致构造）与步骤 4（链不可达构造）仅限演示库与演示链环境；生产 / 演示外环境一律禁止（DB-64 口径同源：演示数据人工处置、构造动作留痕） |
| 构造方式 | ① 摘要不一致 = 在**受控替身**（演示用核验替身）或测试链上改动一条记录的摘要值，不改业务库、不改存证事件原记录；② 链不可达 = 停止演示链容器 / 断开适配器连接（不改代码、不改配置默认值） |
| 留痕要求 | 构造前记录原值，构造后记录新值与操作人 / 时点；S2 步骤 4 按原值还原，还原后复跑核验确认"通过"方视为清理完毕 |
| 还原核验 | 还原后必须复验一次"通过"，避免遗留污染后续演示（沿"停 → 验证 → 重启 → 复验"收工惯例） |

## 剧本维护说明

- **V0.9 草案（2026-11-05 立卡段）**：随规格 `C-8.1-8.2-存证与审计` V0.9 同批派生；步骤与业务判定以本文件为准，界面入口与操作路径为占位。
- **演示前提联动**：本剧本的可执行前提 = 3.8.2（存证服务与链对接）+ 3.8.3（四环节埋点）交付；3.8.4 / 3.8.5 交付后一次性核对界面入口与自动化覆盖（沿 C-7.2 剧本 V1.1~V1.3 维护先例）。
- **剧本间执行顺序（推荐）**：C-1.1（主体）→ C-2.1（空间）→ C-4.2（合约签署）→ C-5.1（交付调用）→ **本剧本（S1 → S2）** → C-8.2 合规审计（S1 → S2，承接本剧本存证数据）。
- **不可承诺项**：本剧本不验证"司法采信""对外出证"能力（ADR-004 §4 公信力边界，V1.5 评估）；不验证真实链性能（归 3.8.6 / 4.2.x）。
