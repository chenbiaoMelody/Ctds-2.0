| 2 | 监管方 | 按业务单据号检索任一笔交付单 | 唯一定位到该笔存证事件，并展开"存证事件 + 业务留痕"时间线（B5-2） |
| 3 | 监管方 | 按主体 + 时间窗过滤 | 返回该主体在窗口内的全部四环节存证事件；换用另一主体，结果集随之切换（B5-2） |
| 4 | 监管方 | 对步骤 2 的业务单据号发起日志调阅 | 时间线连续：存证事件（含核验结论）→ 上游业务留痕逐条可读，无断点（B6-1） |
| 5 | 监管方 | ① 尝试不设任何条件的全量调阅 / 全量导出；② 仅给一个最宽条件（如十年时间窗）发起调阅 / 导出 | ① **被拒绝**，提示需给出条件（业务单据号 / 主体 / 时间窗 / 环节至少一项）；② 被拒绝，或按上限分页 / 截断并明确提示上限（**不返回全量**）（B6-2，负向 + 上限） |

| 7 | 监管方 → 普通主体（非监管） | ① 先用监管方账号检索一个**不存在的单据号**并记录提示（参照）；② 普通主体直接访问审计视图与调阅入口 | ① 取得"对象不存在"参照提示（含状态码与文案全文）；② 被拒绝，提示与参照**同码同文**（逐字一致，不泄露对象是否存在）（B5-4，负向 + 双向参照） |
| 8 | 监管方 | 抽查调阅结果内容 | 不出现数据原文与个人信息；敏感字段按截断标记展示（B6-4，负向 + 观察点）；视图内无修改 / 删除 / 补录按钮（B5-3，观察点） |

### 操作路径说明（V1.3 补界面路；V1.2 落定 E1~E5 实测端点表）

> **界面路径（V1.3 落定；V1.5 状态更新）**：浏览器 `5173` 登录（运营档）→ 左侧菜单**「监管审计」**五标签页（S1 幕全部步骤 + S2 幕报告生成与下载）；报告按号补取 = 审计报告 tab 底部"按报告编号补取文件"区；界面为只读呈现（无写按钮），业务判定以服务接口为唯一事实源（下表）。**V1.5 运行期切换后**：界面运营档仍发送 `admin` 头，而库表 seed 已按 E3 裁定 A 撤除 `admin` 的 `evidence.governance` → **界面路在本版暂不可用**（前端演示身份切换归 3.9.5，登记 DB-128）；本版验收走下方服务接口路，S1/S2 业务判定与步骤编号不变。

**演示通道与身份口径**（沿 C-7.2 V1.1 修订先例）：直连 evidence 服务回环端口 `http://127.0.0.1:8090` + 身份头两枚（`X-Ctds-Subject: <主体编号>`、`X-Ctds-Roles: <角色>`）；**监管档 = 持 `evidence.governance` 的治理角色身份**（V1.5 演示值示例 `X-Ctds-Subject: S-admin-evidence` + `X-Ctds-Roles: platform.audadmin`；`admin` 已按 E3 裁定 A 撤除该点，**不得再作监管档**）；**普通主体 = 无治理角色身份**（如 `X-Ctds-Roles: requester`）。服务启动须注入 `CTDS_AUTH_RBAC_SOURCE=jdbc` + `CTDS_AUTH_RBAC_SCHEMA=ctds_evidence`（E6-A；未注入则仍走配置文件兜底、本表身份不成立）。经统一网关访问走 `/api/v1/evidence/audit/**` 同前缀（网关零改动自动覆盖），身份以网关登录态为准，不可手工注入身份头。
