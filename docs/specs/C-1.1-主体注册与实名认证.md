## 1. 用户故事

作为**拟接入城市可信数据空间的企业/机构**，我希望在线提交注册信息、上传营业执照完成 OCR 识别、由法定代表人完成实人核验，全程无需线下跑腿，审核通过后即成为空间正式主体——以满足"谁在用空间必须真实可溯"的准入底线。

作为**平台运营审核人员**，我希望看到每个申请主体的注册信息、证照识别结果与核验结论的完整档案，能一键通过或驳回（附理由），驳回后申请人可修改重报——以保证入驻主体真实、过程可审计。

作为**政府部门接入单位**，我希望不适用企业版 OCR+法人核验流程，而是凭本单位政务 CA 数字证书直接建立主体身份——以符合政务侧既有信任体系、避免重复认证。

## 2. 术语与角色

| 术语/角色 | 含义 |
| --- | --- |
| 主体 | 接入空间的组织单位：企业、机构、政府部门（个人主体授权归 C-1.4，不在本规格） |
| 申请人 | 代表主体执行注册操作的用户账号 |
| 法人核验 | 验证"该主体的法定代表人"真实身份的核验（要素与方式由认证渠道决定） |
| 认证渠道 | 外部实名认证服务的统一抽象：营业执照 OCR、法人核验、政务 CA 证书验证（实现收口 std-adapter） |
| 审核员 | 平台侧对入驻申请做人工审核的运营角色 |
| 认证档案 | 一次注册产生的全部材料：注册信息、证照影像与 OCR 结果、核验记录、状态流转记录 |

## 3. 行为清单（业务语言）

### 行为 1：主体注册（企业/机构）

**业务规则**

1. 申请人填写并提交注册信息：主体名称、统一社会信用代码、主体类型（企业/机构/政府部门）、注册地址、联系人及联系方式、管理员账号；标记**必填**字段缺一不可，格式校验不通过即时提示；
2. **统一社会信用代码全平台唯一**：重复提交时明确提示"该主体已注册"，不泄露已有账号任何信息；
3. **防重复提交**：同一申请的重复点击/重放不产生多份申请（幂等，复用 common-幂等组件，ADR-007）。**V1.0 已知口径（2026-09-13 变更留痕，ADR-016 §2.5）**：无客户端请求令牌时，幂等结果窗口内（默认 600 秒，可调 `ctds.idempotency.default-expire-seconds`）再次提交同信用代码的注册（含撤销后的重报）**返回首次结果、重报不真正执行**；窗口过后提交才按"该主体已注册"拒绝或按撤销重报口径真正执行。窗口内复用与"重复注册拒绝"无法按无令牌请求区分，V1.0 取"窗口内复用、窗口外拒绝"口径；演示/试运行期为受控小范围开放，如需精确区分走客户端请求令牌演进（须规格变更）。
4. 注册成功后主体进入 **"待认证"** 状态，向申请人返回申请编号，后续认证、审核均以此编号跟踪；
5. 主体名称、统一社会信用代码等关键信息在**认证通过前不可变更**；确需修改 = 撤销当前申请重新注册（V1.0 口径，避免认证材料与注册信息不一致）。

**验收标准（Given/When/Then）**

- Given 必填信息完整且信用代码未注册，When 申请人提交注册，Then 注册成功、主体状态为"待认证"、返回申请编号；
- Given 该信用代码已存在任一非驳回终态主体，When 再次以同一信用代码注册，Then 被拒绝并提示"该主体已注册"；
- Given 同一注册请求因网络重试到达两次，When 平台处理，Then 只产生一份申请（第二请求返回首次结果，不报错不重复建档）；
- Given 必填字段缺失或格式不合法，When 提交，Then 逐字段提示原因，不产生任何半成品档案。

### 行为 2：营业执照 OCR 识别

**业务规则**

1. 申请人在认证环节上传营业执照影像（图片文件，大小/格式限制随设计细化）；
2. 系统调用认证渠道的 OCR 能力识别证照要素（主体名称、统一社会信用代码、法定代表人、注册地址等），**识别结果回填表单供申请人核对确认**——OCR 是辅助录入手段，不直接生效；
3. 申请人核对时修改过的字段以人工确认为准；识别置信度过低或影像不可读时提示重传，不静默放行；
4. OCR 识别的统一社会信用代码与注册信息填写值不一致时，**阻断提交并明确提示差异**，申请人修正后才能进入下一步；
5. **证照影像与 OCR 原始结果按 L4 管控**：国密 SM4 加密存储（唯一入口 `common-crypto`，ADR-006）、页面展示对无关字段脱敏、任何查看留审计记录。

**验收标准（Given/When/Then）**

- Given 一张清晰营业执照影像，When 上传并触发 OCR，Then 返回识别要素并回填表单，申请人确认后生效；
- Given OCR 识别的信用代码与注册填写值不一致，When 申请人提交确认，Then 被阻断并提示差异字段；
- Given 影像模糊不可识别，When 上传，Then 提示"无法识别请重传"，不产生部分识别结果；
- Given 证照影像已存储，When 检查数据库存储内容，Then 影像数据为密文形态；审核员查看该影像时产生一条"谁在何时查看"的审计记录。

### 行为 3：法人实人核验

**业务规则**

1. 核验对象为注册主体登记的**法定代表人**：提交法人姓名、身份证号及认证渠道要求的核验要素，由认证渠道返回"通过/不通过"结论；
2. 核验结论与提交要素、渠道流水号**全程留痕**（时间、发起人、结论），构成认证档案一部分；
3. 核验**不通过可重试**，但受重试次数限制：**当日 5 次，超限当日锁定、次日自动恢复**（Q3 已裁决 2026-09-13；数值为业务可调参数，实现时随参数表确认）；
4. 法人姓名/身份证号与 OCR 识别的营业执照法人信息**不一致时阻断发起核验**，提示先修正注册信息或证照要素（政务 CA 通道除外，见行为 6）；
5. **认证渠道不可用时 fail-fast**：返回明确业务错误"认证服务暂不可用，请稍后重试"，**不静默降级**为人工免验、不留半完成状态（沿 ADR-006 fail-fast 语义）。

**验收标准（Given/When/Then）**

- Given 法人要素真实且与营业执照一致，When 发起核验，Then 渠道返回通过，认证档案记录本次核验流水；
- Given 法人核验不通过，When 查看认证档案，Then 存在带时间与结论的失败记录，主体可重新发起；
- Given 当日核验失败已达上限，When 再次发起，Then 被拒绝并提示"今日核验次数已用完，请次日再试"；
- Given 认证渠道服务不可用，When 发起核验，Then 返回"认证服务暂不可用"明确错误，主体状态不变、无脏数据残留。

### 行为 4：认证结果与主体状态流转

**业务规则**

1. 主体状态机（V1.0 最小集）：**待认证 → 待审核**（OCR 确认 + 法人核验通过后自动流转）／**待认证 → 认证失败**（核验不通过且申请人主动结束或超限，可修改后重新发起）；**待审核 → 已入驻**（审核通过）／**待审核 → 已驳回**（审核驳回，附理由，可修改后重新申请）；**已入驻**为稳定态（冻结/注销等运营态归 C-1.3/运营机制，不在本规格）；
2. 每次状态流转**留痕**：流转前后状态、触发方（申请人/系统/审核员）、时间、备注；
3. 认证通过后自动进入待审核，**不自动入驻**——入驻必须经人工审核（等保与准入底线，政务 CA 通道见行为 6 的差异口径）。

**验收标准（Given/When/Then）**

- Given 申请人已完成证照确认与法人核验（均通过），When 系统处理，Then 主体状态自动流转为"待审核"并留痕；
- Given 审核驳回并附理由，When 申请人查看，Then 可见驳回理由且主体可修改后重新提交；
- Given 任一状态流转，When 查询流转记录，Then 存在前状态、后状态、触发方、时间四要素。

### 行为 5：平台人工审核

**业务规则**

1. 审核员在审核工作台看到"待审核"主体清单及认证档案（注册信息、证照影像、OCR 结果、核验记录），可放大查看原始影像；
2. 审核动作二选一：**通过**（主体状态流转为"已入驻"）/ **驳回**（必填驳回理由）；
3. **审核操作仅授权角色可执行**（复用 common 鉴权 RBAC，2.4.5），非授权调用拒绝并留拒绝记录；
4. 审核结论与操作者、时间留痕，构成认证档案闭环；
5. 演示期审核工作台界面随 3.1.5 交付；本规格只约束审核业务行为与权限边界，界面设计走 3.1.5 两级设计门禁。

**验收标准（Given/When/Then）**

- Given 一个待审核主体，When 授权审核员执行"通过"，Then 主体状态流转为"已入驻"，档案记录审核人与时间；
- Given 审核驳回时未填写理由，When 提交，Then 被拒绝并提示理由必填；
- Given 未授权角色调用审核接口，When 请求到达，Then 被拒绝且留拒绝审计记录。

### 行为 6：政府部门政务 CA 接入

**业务规则**

1. 主体类型为"政府部门"时，**不适用**营业执照 OCR 与法人核验流程；注册时提交单位信息并上传/登记**政务 CA 数字证书**；
2. 系统调用认证渠道的证书验证能力校验政务 CA 证书真实性（有效期、证书链、单位身份要素）；验证通过 → 认证视为通过，主体直接进入**待审核**；验证失败 → 明确提示失败原因，可重新提交；
3. 政务主体仍须经过**平台人工审核**后入驻（Q2 已裁决 2026-09-13：信任源不同但审核底线统一，不免人工审核）；
4. 政务 CA 证书接入通道实现**收口 std-adapter**（3.1.4 交付，ADR-008），不得散落业务代码；
5. 证书材料按 L4 管控（同行为 2 第 5 条）。

**验收标准（Given/When/Then）**

- Given 一份有效的政务 CA 证书，When 政府主体提交注册，Then 证书验证通过、主体状态直接进入"待审核"，认证档案记录证书验证流水；
- Given 一份过期/无效证书，When 提交，Then 被拒绝并提示明确原因，主体停留待认证状态；
- Given 政府主体，When 查看其认证流程，Then 全程不出现营业执照 OCR 与法人核验步骤。

### 行为 7：认证渠道统一适配（收口与降级口径）

**业务规则**

1. 营业执照 OCR、法人核验、政务 CA 验证三类外部能力统一抽象为**认证渠道接口**，实现收敛于 std-adapter（ADR-008）；业务代码只见接口不见具体渠道；
2. **演示期口径（Q1 已裁决 2026-09-13）**：不采购真实第三方认证服务，由 std-adapter 提供**模拟认证渠道**——可按预置规则返回通过/不通过（支撑验收剧本 S1/S2 可重复执行）；后续接入真实渠道时业务代码零改动（接口已抽象）；
3. 渠道调用全程留痕：渠道标识、请求流水号、结论、耗时；
4. 渠道异常与业务不通过严格区分：渠道异常 = "服务暂不可用"（可重试，不计入核验失败次数）；业务不通过 = 核验失败（计入重试限制）。

**验收标准（Given/When/Then）**

- Given 模拟认证渠道按预置规则运行，When 执行验收剧本 S1/S2，Then 结果可重复、可预期；
- Given 渠道抛出技术异常，When 业务处理，Then 返回"认证服务暂不可用"且不计入核验失败次数；
- Given 任一次渠道调用，When 查询留痕，Then 存在渠道标识、流水号、结论三要素。

## 4. 非目标（本任务卡不做，边界划清）

1. **DID 签发与身份互认**（入驻流程的后续环节，归 C-1.2 / WBS 3.1.7~3.1.12；本规格止步于"已入驻"，已入驻主体进入 DID 签发的衔接契约随 3.1.7 规格定义）；
2. **资质档案、信用评级、黑名单**（C-1.3）；
3. **个人主体注册与授权**（C-1.4）；
4. **AI 辅助核验与风险画像**（C-1.5，P1）；
5. **连接器接入**（入驻流程后续环节，归 C-6.x）；
6. **真实第三方认证服务采购与对接**（演示期零外部采购，沿 2.4.6 lofi Q3 裁决口径；模拟渠道见行为 7）；
7. **主体冻结/注销/退出**（运营机制，登记后续工作包）；
8. **传输加密 TLS**（等保清单 G-01 缺口，独立裁决，本规格仅在 L4 管控矩阵中登记"待生效"事实，不虚报）。

## 6. 边界声明

1. **与实施包的分工**：本规格 = 业务行为契约；数据模型与注册服务（3.1.2）、实名认证集成（3.1.3）、政务 CA 接入（3.1.4）、审核后台界面（3.1.5）各自走两级设计门禁，实现与本规格逐条一致；
2. **主体状态机**以本规格行为 4 为准，实施包不得私自增删状态；
3. **注册页面**（申请人侧）界面原型归 3.1.2/3.1.3 设计交付；**审核工作台**界面归 3.1.5；
