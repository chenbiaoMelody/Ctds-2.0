## 1. 用户故事

作为**已入驻空间的主体（企业/机构/政府部门）**，我希望审核通过后平台自动为我签发一个属于我主体的数字身份（DID），后续凭它即可证明"我是我"而无需每次重复出示证照——以满足空间内"身份真实、可信可溯"的准入底线。

作为**平台运营管理员**，我希望看到每个主体的 DID 签发记录与状态，能在必要时（如私钥疑似泄露）吊销某个 DID 并留下完整操作痕迹——以保证身份可管可控、责任可追溯。

作为**对端可信数据空间或外部验证方**，我希望凭主体出示的 DID 与签名验证其身份真伪（含是否已被吊销），验证通过后再与该主体开展业务——以实现跨空间身份互认、免重复认证。

## 2. 术语与角色

| 术语/角色 | 含义 |
| --- | --- |
| DID | 分布式数字身份标识：主体在空间内及跨空间的数字身份凭证，与主体一一绑定（V1.0 PRD 术语：分布式数字身份标识） |
| DID 文档 | 与 DID 配套的**公开**身份说明：公钥、状态、服务端点等公开要素（具体字段结构归 3.1.8 设计）；不含任何 L4 敏感信息 |
| 签发 | 主体入驻后生成 DID、DID 文档与配套密钥并登记注册表的动作 |
| 解析 | 按 DID 查询其文档与当前状态（互认与验证的前提） |
| 验证 | 核验"某 DID 对某数据的签名"是否成立：签名、状态、主体绑定三查 |
| 吊销 | 使某个 DID 永久失效的管理动作 |
| 互认 | 两个可信数据空间互相认可对方签发的 DID：经统一互认接口完成解析与验证 |
| 对端空间 | 与本空间建立互认关系的另一个可信数据空间（演示期为模拟对端，§7 Q3） |
| 主体 | 已入驻空间的组织单位（口径同 C-1.1：企业/机构/政府部门；个人归 C-1.4） |
| 运营管理员 | 平台侧管理 DID（查看签发记录/状态/吊销）的运营角色 |

## 3. 行为清单（业务语言）

### 行为 1：DID 自动签发与主体绑定（入驻联动）

**业务规则**

1. 触发时点（§7 Q1，建议口径 A）：主体审核通过、状态变为"**已入驻**"时，系统**自动**签发该主体的 DID——无需申请人发起任何申请；处于待认证/待审核/已驳回/认证失败状态的主体不产生 DID。（沿 ADR-016 §6 衔接入口，本行为即其衔接契约：subject-service 主体状态到达 ADMITTED → 触发 DID 签发；触发实现形态归 3.1.8 设计。）
2. 一主体同一时期只有一个**有效** DID；吊销后重新签发产生**新** DID，旧 DID 标识永不复用、记录不删除（全程可追溯）。
3. DID 密钥对采用国密算法（经 common-crypto 唯一入口），**私钥一律 KMS 托管**（ADR-015）；任何库表、接口响应、日志不得出现明文私钥——DID 相关记录与文档只含公开要素与密钥引用（分级规范：DID 私钥/主体凭证 = L4）。
4. 签发留痕四要素：签发时间、关联主体（主体标识/申请编号）、DID 标识、密钥引用（KMS 引用，非明文）。
5. 签发失败不改变主体"已入驻"状态（入驻是审核结论）；该主体 DID 记录停留"待签发"，可由运营重试，重试成功后补齐留痕。
6. 同一主体的签发触发防重（幂等）：重复触发不产生第二个有效 DID。
7. 主体类型（企业/机构/政府部门）不影响签发口径——政务 CA 通道入驻的主体同规则。

**验收标准（Given/When/Then）**

- Given 一主体经人工审核通过变为"已入驻"，When 系统处理完成，Then 该主体名下存在一条"有效"DID 记录，含留痕四要素；
- Given 签发联动被重复触发，When 签发处理，Then 该主体有效 DID 仍只有一个，不产生第二份有效记录；
- Given 全部 DID 相关库表与日志，When 检索私钥明文样式，Then 零命中（私钥仅以 KMS 引用呈现）；
- Given 处于"待认证/待审核/已驳回/认证失败"任一状态的主体，When 查询其 DID，Then 不存在有效 DID；
- Given 签发过程失败（如密钥服务不可用），When 查看该主体与 DID 记录，Then 主体状态仍为"已入驻"，DID 记录为"待签发"且可重试。

### 行为 2：DID 解析（文档与状态查询）

**业务规则**

1. 解析输入 = DID 标识；输出 = DID 文档（公开要素）+ 当前状态。DID 状态集锁定两值：**有效 / 已吊销**（实施包不得增删；"待签发"是签发记录的中间态，不是 DID 状态）。
2. 解析结果**不含任何 L4 敏感信息**（法人身份证号、证照影像等一律不出现——分级规范 §4.4）。
3. 未登记的 DID → 返回明确"未登记"业务答复，不以系统异常样式呈现。
4. 已吊销 DID → 照常返回文档但状态为"已吊销"——验证方必须能看到吊销状态（行为 3 依赖此口径）。

**验收标准（Given/When/Then）**

- Given 空间内有效 DID，When 解析，Then 返回其 DID 文档与状态"有效"，且内容不含 L4 敏感字段；
- Given 已吊销 DID，When 解析，Then 返回文档与状态"已吊销"；
- Given 未登记的 DID，When 解析，Then 返回"未登记"明确答复；
- Given 任一解析结果全文，When 核对，Then 不出现敏感个人信息明文。

### 行为 3：DID 身份验证（签名 + 状态 + 绑定三查）

**业务规则**

1. 验证的业务含义：某方主张"我是这个 DID 的持有者，这是我对该数据作出的签名"，平台据此判定该身份主张成立与否。
2. 验证三查，**任一不满足即验证失败并返回明确失败原因**：① **签名核验**——用该 DID 文档中的公钥验签（国密算法，经 common-crypto 唯一入口）；② **状态核验**——DID 状态为"有效"（已吊销即失败）；③ **主体绑定核验**——DID 关联主体在空间内为有效主体（已入驻）。
3. 每次验证留痕：时间、DID、验证结果，失败另含失败原因；留痕不保存业务数据原文（验证通道不得变成数据存储通道）。
4. **验证只证明身份，不等于授权**：验证通过仅意味着"身份主张成立"，该身份能做哪些业务由使用控制策略（C-4.3）与各业务模块权限另行管辖。

**验收标准（Given/When/Then）**

- Given 有效 DID 对数据作出的真实签名，When 验证，Then 三查全部通过，结果"验证通过"并留痕；
- Given 签名与数据不匹配（数据被篡改或签名伪造），When 验证，Then 结果"验证不通过"，原因为签名核验失败；
- Given 已吊销 DID 作出的（密码学上真实的）签名，When 验证，Then 结果"验证不通过"，原因为状态已吊销；
- Given 任一次验证，When 查询留痕，Then 存在时间/DID/结果三要素（失败另含原因），且无业务数据原文；
- Given 验证通过结论，When 后续业务引用，Then 该结论仅代表身份主张成立，不附带任何业务授权（授权判定在各业务模块，本验证不含）。

### 行为 4：DID 吊销

**业务规则**

1. 吊销操作人 = 平台运营管理员（管理界面归 3.1.11 实施包）；主体注销/冻结的**联动吊销**为 C-1.3 预留触发点（本规格只登记预留，不定义行为）。
2. 吊销必须填写理由；留痕五要素：操作人、时间、理由、DID、状态变更（有效 → 已吊销）。
3. 吊销即时生效：生效后解析可见"已吊销"（行为 2 规则 4），验证一律失败（行为 3 三查②）。
4. 吊销不可逆（§7 Q4，建议口径 A）：不提供"恢复"操作；需要继续使用身份 = 重新签发新 DID（行为 1 规则 2，旧 DID 永不复用、记录保留可追溯）。

**验收标准（Given/When/Then）**

- Given 运营管理员对某有效 DID 执行吊销并填写理由，When 确认，Then 状态变为"已吊销"，留痕五要素齐备；
- Given 吊销理由留空提交，When 提交，Then 被拒绝，提示"吊销理由必填"；
- Given 已吊销 DID，When 分别执行解析与验证，Then 解析状态"已吊销"、验证不通过（双向口径）；
- Given 已吊销 DID，When 查找"恢复"操作，Then 不存在该操作（不可逆；旧 DID 记录永久保留可追溯）。

### 行为 5：跨空间身份互认

**业务规则**

1. 互认 = 认可对端空间签发的 DID：本空间可验证"对端主体凭其对端 DID + 签名"的身份主张；对端亦可同样验证本空间 DID（**双向**）。
2. 互认的验证口径 = 行为 3 三查（对端 DID 的文档解析经互认通道获取）；来访身份主张验证通过后留痕：对端空间标识、DID、时间、验证结果——作为后续业务（目录检索、合约签订等）引用其身份的依据。
3. 互认协议实现**收口 std-adapter `did` 域**（ADR-008）：业务服务不得绕过本模块直接对接互认协议；协议文本未入库前不冻结协议签名；能力未开放时接口明确返回"该标准互联功能尚未开放"（1003 段占位契约——不存在"配置即用"假象）。
4. 演示期对端空间 = 模拟对端（§7 Q3，建议口径 A——沿 C-1.1 规格 Q1"模拟认证渠道"先例）：由 std-adapter 提供预置规则，保证验收剧本可重复执行。

**验收标准（Given/When/Then）**

- Given 对端主体凭其对端 DID 与有效签名来访，When 本空间验证，Then 三查通过，来访记录留痕（对端空间标识/DID/时间/结果）；
- Given 对端主体使用已被其对端空间吊销的 DID，When 本空间验证，Then 验证不通过（状态核验失败）；
- Given 本空间 DID 被对端空间验证（双向口径），When 对端验证执行，Then 结果与本空间该 DID 当前状态一致（有效→通过/已吊销→不通过）；
- Given 互认能力未开放（协议实现交付前），When 调用互认接口，Then 返回"该标准互联功能尚未开放"，不返回任何伪结果。

## 4. 非目标（本任务卡不做，边界划清）

1. **Agent DID / 智能体身份**：智能体注册、Agent DID 签发与委托授权链归 C-12.1/12.2（V1.5）；跨空间智能体互认归 C-9.3（P2）；
2. **真实区域枢纽对接**：与区域枢纽的对接归 C-9.1（P1）；本规格互认口径不预设枢纽协议细节；
3. **链上/分布式账本 DID 注册表**：注册表承载口径见 §7 Q2（建议库表承载）；链上演进如采需另走技术栈变更流程；
4. **主体注销/冻结联动**：主体运营态归 C-1.3，其与 DID 吊销的联动触发点仅登记预留（行为 4 规则 1）；
5. **连接器 DID 绑定**：连接器注册与核验服务（WBS 3.6.3）绑用 DID，属下游消费方，本规格不定义连接器行为；
6. **DID 管理界面**：签发记录/状态/吊销管理页归 3.1.11 实施包（本规格只定义业务行为）；
7. **个人主体 DID**：个人主体授权归 C-1.4；本规格主体口径同 C-1.1（组织单位）。

## 6. 边界声明

1. **与实施包的分工**：本规格 = 业务行为契约；DID 密钥管理与签发服务（3.1.8）、DID 解析与验证服务（3.1.9）、跨空间身份互认接口（3.1.10，收口 std-adapter）、DID 管理界面（3.1.11）、测试补全与集成（3.1.12，含与连接器注册联调）各自走两级设计门禁，实现与本规格逐条一致；
2. **DID 状态集**以本规格行为 2 规则 1 为准（有效/已吊销两值；"待签发"为签发记录中间态），实施包不得私自增删；
3. **DID 标识格式、DID 文档字段结构、接口路径与字段**属设计层（3.1.8/3.1.9 高保真）——本规格只锁业务语义（唯一性、公开性、状态可见），不预设技术格式；
4. **互认协议细节**：信通院《互联互通规范》正式文本未入库（ADR-008 特别说明），行为 5 只锁业务口径，协议签名随规范文本取得后按变更流程在 std-adapter 冻结；
5. 本规格发现的外部缺口已如实登记 §5（kms 启用前提），不私自补需求。

| Q1 | DID 签发时点 | **A. 已入驻（ADMITTED）时自动签发**——沿 ADR-016 衔接入口；未入驻者不持可用身份，人工审核准入底线严；演示叙事"审核通过即发身份"顺畅。**B. 认证通过（待审核）即签发**——贴近 V1.0 PRD 行 90 流程图字面顺序（"核验 → DID 签发 → … → 审核通过入驻"）；但未入驻主体先持可用身份，与人工审核准入底线有张力，且驳回后需回收已签发 DID，引入"已签发未入驻"的清理规则 | **A**——身份凭证跟随准入结论，避免"先发身份再审核"的回收复杂度；PRD 流程图顺序按"入驻全流程含 DID 环节"理解，与 ADR-016 不构成冲突（此解读随裁决留痕） |
| Q2 | DID 注册表承载（V1.0） | **A. 平台库表承载**——DID 文档与状态落平台库，解析接口对外提供；零新依赖、演示可控。**B. 分布式账本/链上承载**——更贴"分布式"字面，但 V1.0 无对应 WBS 项、引入新中间件与运维面，违背技术栈冻结（ADR-001） | **A**——"分布式"体现在跨空间互认（WBS 3.1.10）而非本空间注册表形态；链上演进登记为方向，如采需走技术栈变更流程 |
| Q3 | 互认演示口径 | **A. 模拟对端空间**——std-adapter 预置对端 DID 与签名规则，剧本可重复执行、零采购（沿 C-1.1 Q1 先例）。**B. 真实对接对端空间**——C-9.1 为 P1 且 V1.0 无对端条件 | **A**——接口已按 ADR-008 收口抽象，后续接真实对端业务零改动 |
| Q4 | 吊销可逆性 | **A. 不可逆**——吊销即永久失效，重新使用 = 重签新 DID；安全语义清晰、审计链干净。**B. 可恢复**——吊销可撤销恢复原 DID；灵活但"吊销"语义被稀释，私钥疑似泄露场景下恢复窗口本身是风险 | **A**——L4 身份凭证从严（分级规范行 144：身份凭证被冒用=主体被冒名）；确需继续使用的场景走"重签新 DID"，旧 DID 留痕可溯 |
