## 1. 用户故事

- **作为系统管理员（平台管理员）**：我能管理系统侧的配置项与账务归属信息、能看运维读数并处置告警；但我**不能**审批业务、**不能**授予或收回他人权限、**不能**查阅审计明细——我被制度性地限制在"管理"一侧。
- **作为安全管理员**：我能授予与收回权限点、审批安全相关策略；但我**不能**改业务数据、**不能**看审计明细——授权者不受托审计。
- **作为审计管理员**：我能查询审计记录、调阅时间线、导出审计报告并留下自己的调阅痕迹；但我**不能**改业务、**不能**改权限——看账的人不能动账。
- **作为运营方**：我能一眼看到平台服务是否存活、接口速率与错误率、时延是否达标、各连接器是否在线；容量或错误率异常时，告警在我的列表里可见并可处置。
- **作为平台**：三员权责两两不重叠，任何单一角色都做不到"既做业务又审业务"；隔离口径与既有逻辑空间一致，不新增第二套"租户"概念；监控与告警的边界（外发未接、集中日志未建）如实标注，不虚报已满足。

## 2. 术语与角色

| 术语 | 口径 |
| --- | --- |
| **平台角色（RBAC 角色）** | 权限点的命名集合，V1.0 为自由字符串（既有实现事实），由 `ctds.auth.permissions.<角色>` 配置映射到权限点。**本规格定义三员平台角色**：`platform.sysadmin`（系统管理员）/ `platform.secadmin`（安全管理员）/ `platform.audadmin`（审计管理员）（命名与既有 `admin` 的关系见 §7 Q2，已裁决采 A） |
| **权限点** | `<域>.<动作>` 形式的字符串授权单元（既有事实：`evidence.governance` / `catalog.product` / `connector.heartbeat` / `billing.governance` 等）；一域一段，值域封闭，新增须在所属域任务卡登记 |
| **三员分立** | 系统管理员 / 安全管理员 / 审计管理员三个平台角色的**敏感权限面两两不重叠**：业务配置 ∥ 权限授予 ∥ 审计读面三者互斥，任一角色不同时持有另两面的关键权限点（§7 Q4，已裁决采 A） |
| **租户（V1.0 口径）** | **部署单元** = 一个客户一套平台实例（私有化部署为主，PRD §1.3）；库内不引入 `tenant_id` 维度（§7 Q1，已裁决采 A）。业务隔离由**逻辑空间**（C-2.1~2.3）承载。本规格所称"租户管理"在 V1.0 = 部署域配置与空间隔离的验收口径 |
| **部署域** | 一套平台实例所辖的全部服务与数据（含其库 schema 的集合，如 `ctds_subject` / `ctds_contract` / `ctds_evidence`）；跨部署域数据互通需走互联互通（C-9.x，非本规格） |
| **逻辑空间** | 平台内按场景隔离的虚拟数据流通域（C-2.1~2.3 既有口径）；资源 / 合约 / 交付 / 计量均带空间归属，是本规格唯一认可的**业务隔离维度** |
| **监控读数** | 平台服务运行状况的可读呈现：服务存活、JVM 堆内存与 GC、HTTP 速率、5xx 错误率与 P95 时延（ADR-014 §3.5 四区块口径） |
| **连接器健康度** | 连接器与平台连通状况的三态派生结论：**在线**（最近心跳未超阈值）/ **离线**（超阈值）/ **从未上报**（无心跳记录）；读时派生、无调度任务（既有实现事实） |
| **容量告警** | 指标阈值越限产生的通知项，要素 = 告警名 / 级别 / 对象 / 触发时点 / 当前值 / 阈值 / 状态（firing · resolved） |

**角色**：系统管理员（运维与平台配置）、安全管理员（权限与安全策略）、审计管理员（审计查询与报告）、既有业务角色（申请人 / 供方 / 需方 / 审核员 / 空间运营方，口径沿各域规格不变）、普通用户。

## 3. 行为清单（业务语言）

> 编号 B1~B8；每条行为含规则（R）与验收标准（AC）。B1~B4 归 C-10.1（多租户与权限），B5~B8 归 C-10.2（监控运维）。

### C-10.1 多租户与权限

#### 行为 1（B1）角色与权限点模型（RBAC）

**规则**
1. 角色 = 权限点的命名集合；权限点命名固定 `<域>.<动作>`，一域一段，值域封闭，新增权限点须在所属域任务卡登记（不得在实现里"顺手"新增未登记权限点）；
2. 平台角色值域封闭：三员（`platform.sysadmin` / `platform.secadmin` / `platform.audadmin`）+ 既有业务角色（`applicant` / `provider` / `requester` / `reviewer` / `platform.operator` / 治理档 `admin`，§7 Q2，已裁决采 A）；新增角色须走变更流程；
3. 角色 → 权限点映射可配置：V1.0 沿用配置文件来源（`ctds.auth.permissions.<角色>`，ADR-005 行 37 / 既有 `ConfigRolePermissionMapper`），3.9.2 以覆盖 `RolePermissionMapper` Bean 换库表，**权限判定内核不改**；
4. 映射变更（授予 / 收回）必须可追溯：变更人、时点、角色、权限点、变更前后值留痕（V1.0 承载 = 配置变更记录 + 审计事件，§7 Q4，已裁决采 A）。

**验收标准**
1. 三角色与既有业务角色的权限点清单可从配置/读面完整读出，权限点命名符合 `<域>.<动作>` 且无重复（B1-1 / B1-2）；
2. 同一角色被授予某权限点后，其可访问面随之变化；收回后恢复被拒（B1-3，双向）；
3. 授权映射变更产生一条可查的变更留痕（变更人 / 时点 / 前后值）（B1-4）；
4. 系统内不存在"未登记权限点"（逐一比对域规格登记清单，观察点）（B1-1）。

#### 行为 2（B2）三员分立与职责互斥

**规则**
1. **系统管理员** = 平台业务配置与账号归属管理、运维读数与告警处置；**不含**业务审批、**不含**权限授予/收回、**不含**审计明细读面；
2. **安全管理员** = 权限点授予/收回、安全策略与密钥授权类审批；**不含**业务配置、**不含**审计明细读面；
3. **审计管理员** = 审计查询 / 时间线调阅 / 审计报告导出；**不含**业务配置、**不含**权限授予、**不含**业务数据写；
4. 三员敏感面**两两不重叠**：任一平台角色不得同时持有"业务配置"与"权限授予"与"审计读面"三类关键权限点中的两类以上；"同一自然人不得兼任两员"的技术强制（账号唯一性）归 3.9.2 / 部署期（§7 Q4，已裁决采 A）。

**验收标准**
1. 系统管理员执行平台配置动作成功、访问审计读面被拒、执行授权动作被拒（B2-1，正向 + 双向负向）；
2. 安全管理员执行授权动作成功（含收回），访问审计读面被拒、修改业务配置被拒（B2-2）；
3. 审计管理员查询与导出成功并留痕，修改业务 / 授权被拒（B2-3）；
4. 三角色的权限点清单两两比对，"业务配置 / 权限授予 / 审计读面"三类关键权限点无任一角色跨两面持有（B2-4，观察点 + 结构性断言）。

#### 行为 3（B3）权限校验与越权处置

**规则**
1. 功能级权限校验统一走 `common/auth`（`@RequirePermission` 注解或显式 `AccessControl` 调用），服务内不得另立第二套判定；
2. 出站口径统一（ADR-005 行 37 / ADR-016 §2.6）：未认证 = 401 + `1000C0002`；无功能权限 = 403 + `1000C0005`；**归属不匹配** = 400 + `1000C0003`，与"对象不存在"**同码同文**（防存在性枚举）；
3. 拒绝必须留痕：`rbac.check` DENIED 审计事件含 actor / 权限点 / 对象 / 时点（既有 `DefaultAccessControl` 行为，本规格只要求不得绕过）；
4. 平台管理面（三员相关端点、运维写面）**必须显式挂权限点**，不得依赖"无注解默认放行"（V1.0 按接口控制的既有口径，仅限业务读面）。

**验收标准**
1. 三角色对各自无权端点调用一律 403 + `1000C0005`，文案统一"无权限执行该操作"（B3-2，负向）；
2. 归属不匹配访问返回 400 + `1000C0003`，且与对象不存在**逐字同文**（剧本须先取一个不存在对象的参照提示再比对）（B3-2，负向 + 双向参照）；
3. 每次拒绝在留痕中可读出 actor / 权限点 / 时点（B3-3）；
4. 平台管理面无"未挂权限点"端点（逐个端点核对，观察点）（B3-4）。

#### 行为 4（B4）租户（部署域）隔离与空间边界

**规则**
1. V1.0 租户 = 部署单元（单实例单部署域）；**不在库内引入 `tenant_id` 维度**，与 C-2.1~2.3 "不引入第二套隔离概念"的既有裁决一致（§7 Q1，已裁决采 A）；
2. 业务隔离维度 = 逻辑空间：资源 / 产品 / 合约 / 交付 / 计量数据均带空间归属，跨空间访问一律被拒（同码同文，沿 B3-2 口径）；
3. 平台级运维读数（监控指标、告警、连接器健康总览）按**部署域全量**可见，不按空间切分；业务数据读面按空间归属过滤；
4. 多租户终态（库内租户维度、单实例多租户）不在 V1.0；如确需，走架构变更流程（ADR-001 技术栈冻结 + 数据模型变更），不在本域私自引入。

**验收标准**
1. 部署域标识（实例 / 库 schema 清单）可从部署配置读出，且与运行实例一致（B4-1）；
2. 空间 A 的成员访问空间 B 的资源 / 合约 / 交付对象被拒，且与"对象不存在"同码同文（B4-2，负向 + 双向参照）；
3. 同一业务单据在空间过滤下只在其归属空间可见，跨空间检索不命中（B4-2）；
4. 运维读数（监控 / 告警 / 连接器健康）不按空间切分，与部署域口径一致（B4-3，观察点）。

### C-10.2 监控运维

#### 行为 5（B5）平台性能监控读数

**规则**
1. 指标来源 = Spring Boot Actuator + `micrometer-registry-prometheus`，暴露面收敛为 `health,prometheus`（ADR-014 §3.2），不得新增其他端点暴露；
2. 基线读数四项：**服务存活** / **HTTP 速率** / **5xx 错误率** / **P95 时延**（另含 JVM 堆内存与 GC，ADR-014 §3.5 看板四区块）；
3. 读数**只读**：不提供指标写入、篡改、伪造入口；
4. **诚实边界**：未接入指标的服务必须显式标注"未接入"（不得呈现为 0 或伪造绿值）；V1.0 事实 = 仅 `example-service` 暴露 `/actuator/prometheus`，其余业务服务接入归 3.9.4（§7 Q5，已裁决采 A）。

**验收标准**
1. 监控读数可读出四项基线（存活 / 速率 / 5xx 错误率 / P95 时延），数值与指标端点一致（B5-2）；
2. 未接入指标的服务在读数中显式标注"未接入"，不显示为 0 值（B5-4，负向 + 观察点）；
3. 指标端点暴露面仅为 `health,prometheus`（逐服务核对配置）（B5-1）；
4. 系统无"手工写入指标 / 修改读数"的入口（B5-3，负向）。

#### 行为 6（B6）连接器健康度

**规则**
1. 健康度三态显式：**在线 / 离线 / 从未上报**，不得只给二态或以空值代替三态；
2. 判定 = 最近心跳时点 + 阈值 `ctds.connector.health.offline-after`（默认 5m，启动校验 1m~1440m），**读时派生、无调度任务**（复用既有 `/heartbeats` 与 `last_heartbeat_at`，§7 Q6，已裁决采 A）；
3. 运营方可读全平台连接器健康总览（既有治理列表只读面），普通角色不可读他人连接器明细；
4. 健康度**不改变**连接器业务状态：注册 / 注销状态与在线状态相互独立，"离线"不等于"已注销"。

**验收标准**
1. 连接器健康总览可读出每个连接器的在线状态与最近心跳时点，三态取值之一（B6-1）;
2. 阈值调整后（重启生效），同一心跳数据的派生结论随之变化（受控构造，演示期）（B6-2）；
3. 离线连接器仍在册（注册状态可见），注销连接器不因心跳恢复而在册（B6-4，双向）；
4. 非运营方角色读取他人连接器健康明细被拒（B6-3，负向）。

#### 行为 7（B7）容量告警与阈值

**规则**
1. 告警要素齐备：告警名 / 级别（critical · warning）/ 对象 / 触发时点 / 当前值 / 阈值 / 状态（firing · resolved）；
2. V1.0 告警规则**封闭两条**：`CtdsBackendDown`（critical，1m）/ `CtdsBackendHighErrorRate`（warning，5m，5xx 占比 > 5%）；**新增或修改规则须走任务卡与设计流程**（ADR-014 §3.3 行 46），本规格不得自行扩规则；
3. 通知出口 = 告警列表读数（界面 / API）+ Alertmanager UI·API；**外发通道（邮件 / webhook）V1.0 不承诺**，缺口 **G-04** 标注"待生效"；
4. 容量类阈值口径（连接器规模、调用量、存储水位）本规格只定义**读数与要素**，具体阈值取值归 3.9.4 落定；本规格不预设数字。

**验收标准**
1. 告警列表可读出要素齐备的告警项，状态二值之一（B7-1）；
2. 制造一次服务下线后，`CtdsBackendDown` 在规则窗口后进入 firing，恢复后转 resolved（B7-2，双向）；
3. 错误率越限时 `CtdsBackendHighErrorRate` 触发（演算或演示构造二者之一，须记录口径）（B7-2）；
4. 规格与剧本明示"外发通道未接（G-04 待生效）"，未出现"已实现邮件/短信/webhook 通知"类承诺（B7-3，负向 + 观察点）。

#### 行为 8（B8）运维处置与合规边界

**规则**
1. 告警处置 = 确认 / 静默 / 升级（三类动作之一或组合），处置必须留痕：处置人 / 时点 / 对象 / 结论；
2. 监控与告警数据**不可删除**：无删除入口；数据留存与集中收集 = 缺口 **G-07**（部署期立项），未闭环前标注"待生效"；
3. 运维写面（处置动作、阈值配置）仅系统管理员可执行；业务角色与安全 / 审计管理员对运维写面一律被拒；
4. 诚实边界：v1 监控栈数据不持久化（Pod 重建清零）、单副本无高可用、不含集群层指标（ADR-014 §4 行 66）——相关管控标注"待生效"，不虚报。

**验收标准**
1. 处置动作执行成功且产生处置留痕（处置人 / 时点 / 对象 / 结论）（B8-1）；
2. 系统无删除监控 / 告警数据的入口；越权调用被拒（B8-2，负向）；
3. 安全管理员 / 审计管理员 / 业务角色执行运维写面动作被拒，系统管理员成功（B8-3，双向）；
4. 规格与剧本明示"留存与集中收集未建（G-07 待生效）""监控数据不持久化""不含集群层指标"，无相反承诺（B8-4，观察点）。

## 6. 边界声明

1. **不重复定义上游口径**：身份头、角色映射、错误码、指标暴露、心跳与健康度派生一律以上游规格 / ADR 为准；本规格只定义"三员如何划分""健康度与告警如何验收"；
2. **权限判定内核唯一**：三员分立的实现必须是"同一判定内核 + 不同映射"，不得为三员新写第二套校验逻辑（否则出现"两套权限体系"）；
3. **租户口径诚实**：V1.0 不以库内租户维度冒充多租户；对外表述统一为"单实例单部署域 + 逻辑空间隔离"，多租户演进须走变更流程；
4. **账号体系边界**：本规格不定义登录与会话；"账户"在 V1.0 指请求头声明的主体标识与角色集合，生产账号体系与令牌签发归部署期（§7 Q3，已裁决采 A）；
5. **告警能力边界**：告警"可见可处置"不等于"已通知到人"——外发通道未接（G-04），监控数据不持久化（ADR-014 §4），相关管控标注"待生效"；
6. **监控 ≠ 审计**：监控读数服务于运维（存活 / 性能），审计读面服务于合规追溯（存证 / 留痕），两者受众与数据面不同，本规格不合并二者，也不以监控读数替代审计证据；
7. **角色边界**：V1.0 三员为权限面划分，不等同于组织岗位编制；同一自然人兼任的技术禁止归 3.9.2 / 部署期（§7 Q4，已裁决采 A）；
8. **错误码边界**：本规格只登记业务错误语义，**预留 1013 段**（立卡实测 `1013C` / `1013S` / `1013B` 全仓零命中；1011 已归 3.7 运营域、1012 已归 3.8 存证域），码值随实施包落定；不新增权限点与端点（§7 Q9，已裁决采 A）。
