## 1. 用户故事

作为**平台架构负责人与未来 AI 功能（V1.5 C-11.x）的实施方**，我希望平台有一个统一的"模型插座"：所有模型调用将来都走同一套 OpenAI 兼容接口，国产模型（GLM/DeepSeek/Qwen/Kimi）以适配器形式插拔，**换模型只改配置不改代码**；V1.0 阶段只交付插座本身（接口 + 配置 + 路由与开关/预算判定逻辑），**不通电**——不发起任何真实模型调用、不产生任何费用、不承载任何业务功能，为 V1.5 智能增效与 3.10.2~3.10.4 后续包打底。

## 2. 行为清单（业务语言）

### 行为 1：OpenAI 兼容契约（B1）

**业务规则**

1. 平台定义统一的模型调用契约，请求/响应结构与 **OpenAI Chat Completions 兼容格式**一致（业界事实标准，ADR-003 §2.1）：请求含模型名、消息列表（角色 + 内容）、温度、最大 token 数等字段；响应含标识、模型名、候选结果列表、token 用量；
2. 契约为**纯数据结构 + 统一调用接口**，V1.0 不提供任何真实调用实现；JSON 字段命名与 OpenAI 兼容（snake_case，如 `max_tokens` / `finish_reason` / `prompt_tokens`）；
3. 统一调用接口是未来**所有 AI 调用的唯一入口**（ADR-003 §3 决策 3 审计预留的挂点位置）；V1.0 不实现审计落库（归 3.10.3 / V1.5）。

**验收标准（Given/When/Then）**

- Given 一个符合 OpenAI 兼容格式的请求/响应 JSON，When 经契约结构序列化往返，Then 字段名与字段值逐字一致（含多轮消息、可选字段缺省）；
- Given V1.0 交付物，When 检查统一调用接口，Then 接口存在且签名稳定，但**无任何真实调用实现类**。

### 行为 2：Provider 适配器与配置化路由（B2）

**业务规则**

1. 定义 **Provider 适配器接口**：每个国产模型供应商一个适配器实现位，适配器以供应商编号标识；V1.0 仅交付接口与配置注册机制，**不交付任何真实适配器实现**（零外呼，Q3-A）；
2. 供应商清单按 ADR-003 §2.1：**glm（默认）/ deepseek / qwen / kimi**；供应商连接参数（服务地址、密钥引用、默认模型名）全部走配置，**改配置即换供应商，不改代码**；
3. 路由规则：调用方指定供应商则用指定的；未指定则用配置的默认供应商；指定/默认的供应商**未注册**时给出明确拒绝判定（不静默 fallback，防"以为换了模型其实没换"）；
4. **模型密钥只进配置中心/KMS**（ADR-003 红线）：配置结构含密钥字段位，但仓库、测试、日志中**零真实密钥值**（测试用占位符）。

**验收标准（Given/When/Then）**

- Given 默认配置，When 路由解析未指定供应商的调用，Then 解析到 glm 适配器位；
- Given 修改默认供应商配置为 deepseek/qwen/kimi 之一且该适配器已注册，When 路由解析，Then 解析到对应适配器位（**代码零改动**）；
- Given 指定一个未注册的供应商编号，When 路由解析，Then 返回"供应商未注册"的明确拒绝判定；
- Given 全库检索（门禁 secretsScan + 人工核对），When 检查配置/代码/测试/文档，Then 零真实模型密钥。

### 行为 3：开关与预算控制位（B3）

**业务规则**

1. 网关级**启用开关**：配置级布尔位，**缺省关闭**（V1.0 零消耗的安全默认）；关闭时一切调用判定为拒绝；
2. **token 预算上限**控制位：配置级数值位（缺省 0 = 未设限，预留位）；已用量达到或超过上限时判定为拒绝（上限语义，保守口径）；
3. 控制位为**纯判定逻辑**（可单测的判定接口）：V1.0 不做运行时拦截链、不做计量计费对接、不做用量累计落库（归 V1.5 / 3.10.4 / C-11.6）；
4. 判定顺序固定：先开关、后预算；拒绝原因可区分（关闭 / 超预算 / 供应商未注册）。

**验收标准（Given/When/Then）**

- Given 开关关闭（含缺省态），When 执行调用判定，Then 拒绝且原因为"网关未启用"；
- Given 开关开启且预算上限未设（0），When 执行调用判定，Then 放行；
- Given 开关开启、预算上限 N>0、已用量 ≥N，When 执行调用判定，Then 拒绝且原因为"超出预算"；已用量 <N 则放行；
- Given 上述判定，When 检查实现，Then 无网络调用、无计费写入、无用量落库。

### 行为 4：零消耗与既有面零影响（B4）

**业务规则**

1. V1.0 交付物**不发起任何真实模型外呼**：模块不引入 HTTP 客户端/模型 SDK，测试全部离线可跑（ADR-003 §4"仅预留不产生消耗"）；
2. 抽象层承载于**公共组件区新模块**（Q2-A），不新增服务/端口/网关路由/数据库表/迁移；
3. 既有 21 个模块的主源与测试**零改动**（根 pom 仅新增模块登记与依赖管理条目，沿 common 先例）；门禁配置零改动，新模块自动纳入既有全仓门禁扫描面。

**验收标准（Given/When/Then）**

- Given V1.0 全部测试，When 在断网环境运行，Then 全部通过（零网络依赖）；
- Given 本卡交付 diff，When 核对改动面，Then 除新模块目录与根 pom 登记外零既有文件改动；
- Given 全仓门禁，When 单发运行，Then GREEN 且 ConfigSha256 与基线逐字一致、coverage overall 不劣于基线。

## 3. 非目标（本任务不做）

1. **真实模型外呼 / 私有化接入通道实连**（Q3-A；PRD :291 通道能力归 V1.5，避免预算消耗）；
2. 智能路由/降级/灰度运行时、按 token/次计量计费、模型资产目录（PRD C-11.1 P1 面，V1.5 / C-11.6）；
3. 护栏框架与 AI 调用日志表结构、审计落库（**3.10.3**；本卡仅以统一调用接口签名留挂点）；
4. 向量库与目录语义检索（**3.10.2**）；AI 服务配置管理页（**3.10.4**，消费本规格配置键）；
5. 流式（stream）响应实现（契约保留字段位，实现归 V1.5）；
6. 新错误码/权限点/HTTP 端点（本模块为库，无出站面；错误码映射归未来消费方）；
7. 运行时预算拦截与用量累计（V1.5 / C-11.6）。

## 5. 边界声明

1. **规格-实现边界**：本规格只约束"抽象与配置"层行为；任何真实调用、计费、审计落库、页面均为规格外，实现即打回；
2. **模块边界**：`common/model-gateway` 为纯库模块，无 Spring 容器依赖、无 HTTP 端点、无 DB；配置绑定由未来消费方（3.10.4 / V1.5 服务）承接；
3. **密钥边界**：密钥值只经部署环境/配置中心/KMS 注入；仓库内仅键名与占位符（红线 7）；
4. **口径差裁决留痕**：PRD :291"接入通道" ⊃ WBS :348"仅抽象与配置"，按 WBS 收敛（Q3-A，编排师 2026-11-16 确认）；V1.5 承接时以 PRD 全量口径另行规格化；
5. **下游消费方**：3.10.2（VectorStore 与本模块无直接耦合，仅同属 AI-0）/ 3.10.3（审计挂点 = 统一调用接口）/ 3.10.4（配置页消费本规格配置键）/ V1.5 C-11.x（真实适配器与运行时）。
