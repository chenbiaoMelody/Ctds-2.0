## 1. 用户故事

作为**平台安全负责人与未来 AI 功能（V1.5 C-11.x）的实施方**，我希望所有 AI 调用在统一入口处都经过一道可插拔的"安检门"：调用前可检查输入、调用后可检查输出，不合规的调用被明确拒绝；同时每次调用的元数据都有一条统一的审计记录位置，为 V1.5 的评测护栏中心与 AI 行为审计打底。V1.0 阶段只交付**框架与预留**：不实现任何具体检查规则、不建数据库表、不写库、不发生真实模型调用、不产生费用。

## 2. 行为清单（业务语言）

### 行为 1：护栏框架契约（B1）

**业务规则**

1. 平台定义两类护栏扩展位：**输入护栏**（模型调用前执行）与**输出护栏**（模型调用后执行）；每个护栏对本次内容给出**放行（ALLOW）或拒绝（DENY）**判定，拒绝时携带可读原因码；
2. 护栏按注册顺序执行；**首个拒绝即短路**，后续护栏不再执行；未注册任何护栏时视为放行（直通）；
3. 护栏自身执行异常（抛运行时异常或返回空判定）时，**一律按拒绝处理（fail-closed）**，原因码为 `GUARDRAIL_ERROR`——安全优先，不允许"护栏坏了就当没护栏"；
4. 框架提供一个可包装统一调用入口的**装饰器**：输入护栏拒绝时**不得调用下游模型**；输出护栏拒绝时**不得把响应交给调用方**；下游调用本身抛出的异常**原样抛出**，不改变既有语义；
5. 框架不改动 3.10.1 已交付的统一调用入口契约；装饰器实现该入口接口，未来业务按需使用；
6. V1.0 **不交付任何具体护栏实现**（prompt 注入检测、敏感信息识别、内容合规、幻觉/越权检测、引用溯源均归 V1.5 C-11.5）。

**验收标准（Given/When/Then）**

- Given 输入护栏判定拒绝，When 执行包装后的调用，Then 下游模型不被调用、抛出拒绝异常且原因可读；
- Given 多个输入/输出护栏，When 第一个判定拒绝，Then 后续护栏不再执行（短路）；
- Given 护栏抛运行时异常或返回空判定，When 执行调用，Then 按拒绝处理且原因为 `GUARDRAIL_ERROR`；
- Given 未注册任何护栏，When 执行调用，Then 内容直通（放行）；
- Given 输出护栏判定拒绝，When 下游已返回响应，Then 响应不交给调用方、抛出拒绝异常；
- Given 下游调用抛出异常，When 经过装饰器，Then 原异常原样抛出，且审计记录结果为失败。

### 行为 2：AI 调用审计记录契约（B2）

**业务规则**

1. 每次经过装饰器的调用尝试**恰好产生一次审计记录尝试**，结果三分：成功（SUCCESS）、被拒绝（DENIED）、失败（FAILURE）；
2. 记录内容**仅限元数据**：调用用途、操作主体、供应商、模型、输入/输出 token 数、耗时、结果、错误码（可空）、护栏判定与原因、链路标识、时间；**禁止记录 prompt / 响应原文、密钥、个人信息**（红线 7；数据分级 CAT-01 / L2）；
3. 审计记录器契约：**绝不抛错、绝不阻塞**（沿 ADR-005 §3-6 审计铁律）；记录器自身异常不得改变调用结果；V1.0 默认使用**空记录器（No-op）**，不落库、不写文件；
4. 审计记录失败时仅影响留痕，不影响业务调用结果；
5. V1.0 **不建 AI 调用日志表、不写库、不新增迁移**；真实落库与归属服务留 V1.5。

**验收标准（Given/When/Then）**

- Given 任意一次调用尝试，When 检查审计记录器，Then 恰好收到一条记录，结果与调用结果一致（成功/拒绝/失败）；
- Given 审计记录器抛异常，When 执行调用，Then 调用结果与无记录器时完全一致（成功仍成功、异常仍原样抛出）；
- Given 任意记录，When 检查字段，Then 仅含元数据，零 prompt / 响应原文 / 密钥 / 个人信息；
- Given V1.0 默认装配，When 执行调用，Then 使用空记录器、零数据库写入。

### 行为 3：AI 调用日志表结构预留（B3）

**业务规则**

1. 平台在 `deploy/sql/ai-call-log.sql` 提供 AI 调用日志的**表结构预留定稿**：字段含链路标识、用途、操作主体、供应商、模型、输入/输出 token、耗时、结果、错误码、护栏判定与原因、创建时间；索引覆盖链路标识与创建时间；
2. 表结构**不得包含 prompt / 响应原文等内容列**（与 B2 隐私口径一致）；
3. **V1.0 禁止建表、禁止写入、禁止新增迁移**（沿 2.4.4 占位声明与 ADR-005 §3-6）；归属服务与 Flyway 实施由 V1.5（C-8.4 / C-11.5）承接；
4. 结果值域固定：`SUCCESS / DENIED / FAILURE`；护栏判定值域固定：`ALLOW / DENY`。

**验收标准（Given/When/Then）**

- Given 预留 DDL 文件，When 检查结构，Then 字段/索引/值域注释齐备，且零内容原文列；
- Given 全仓数据库迁移脚本，When 检索 AI 调用日志表，Then 零命中（V1.0 未建表）；
- Given V1.0 运行期，When 执行任何调用，Then 零数据库写入。

### 行为 4：零外呼、零密钥与既有面零变化（B4）

**业务规则**

1. V1.0 交付物**不发起任何真实模型外呼**：不引入 HTTP 客户端 / 模型 SDK / 网络客户端，测试全部离线可跑；
2. 框架承载于**公共组件区新模块**（Q2-A），不新增服务 / 端口 / 网关路由 / 数据库表 / 迁移 / 权限点 / 错误码 / 外部依赖；
3. 3.10.1 `common/model-gateway` 与 3.10.2 `common/vector-store` 的契约、主源与测试**零改动**；根 pom 仅新增模块登记与依赖管理条目；门禁配置零改动。

**验收标准（Given/When/Then）**

- Given V1.0 全部测试，When 在断网环境运行，Then 全部通过（零网络依赖）；
- Given 本卡交付 diff，When 核对改动面，Then 除新模块、根 pom 登记与预留 DDL 定稿外零既有文件改动；
- Given 全仓门禁，When 单发运行，Then GREEN 且 ConfigSha256 与基线逐字一致、coverage overall 不劣于 92.43%。

## 3. 非目标（本任务不做）

1. **真实护栏算法**：prompt 注入检测、敏感信息识别、内容合规审核、幻觉/越权检测、强制引用溯源（V1.5 C-11.5 P1）；
2. AI 生成内容标识（V1.5 / 合规要求）；
3. 真实模型调用、真实 embedding、任何外部 API 调用（V1.5）；
4. **AI 调用日志建表、落库、迁移与归属服务实施**（V1.5；V1.0 仅结构预留与记录契约）；
5. C-8.4 AI 行为审计上链存证（P1，非本卡）；
6. AI 服务配置管理页 / 前端界面（**3.10.4**）；
7. AI 可观测与成本治理（C-11.6）、计量计费（C-7.x）；
8. 新服务 / 端口 / 网关路由 / 权限点 / 错误码 / HTTP 端点 / 外部依赖 / 门禁配置；
9. 改动 3.10.1 / 3.10.2 已交付契约与测试；承载任何业务功能。

## 5. 边界声明

1. **框架 ≠ 护栏中心**：本规格只约束"接口 + 执行链 + 装饰器 + 审计契约 + 表结构预留"；任何具体检查算法、评测流水线、内容标识均为规格外，实现即打回；
2. **预留 ≠ 已建表**：V1.0 不建表、不写库、不新增迁移；交付说明不得表述为"已实现 AI 审计落库"；
3. **V1.0 装饰器为休眠态**：3.10.1 无真实 `ModelGateway` 实现，装饰器仅供未来实现包装与测试；不得宣称已产生任何 AI 调用/审计数据；
4. **失败语义**：护栏异常 = 拒绝（fail-closed）——这是安全与可用性的明确取舍，未来如要改为放行须走规格变更；
5. **隐私边界**：审计仅元数据，零 prompt / 响应原文 / 密钥 / 个人信息；数据分级 CAT-01 / L2；
6. **下游消费方**：3.10.4（配置页，不消费本规格）/ V1.5 C-11.5（实现护栏算法与评测）/ V1.5 C-8.4（实现审计落库与上链）/ 未来业务 AI 调用（使用装饰器）。
