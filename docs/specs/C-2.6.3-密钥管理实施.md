## 1. 用户故事

作为**平台运维负责人与安全合规负责人**，我希望平台所有数据加密密钥由密钥管理服务（KMS）集中托管，而不是散落在各服务器本地文件里；密钥可以按编号轮换，轮换不中断业务、不使旧密文失效；并有自动门禁拦截任何硬编码密钥——以满足等保三级"密码管理"控制项与数据分级规范对密钥材料（L3，生产 L4）的管控要求。

## 2. 行为清单（业务语言）

### 行为 1：密钥集中托管（KMS 接入）

**业务规则**

1. 平台 SM4 数据密钥全部由密钥管理服务集中托管；业务服务经既有统一加解密入口（`common-crypto`）透明取用密钥，切换对业务代码**零改动**（ADR-006 §5.1 已预留）；
2. 密钥管理服务的密钥库**落库不留明文**：存储的密钥材料须经加密保护，加密密钥库的根密钥来自部署环境注入（环境变量/部署注入），不落盘、不入库、不入代码；
3. 密钥材料不出现在代码、配置文件、日志、异常消息中（章程红线 7，验收时全库检索可核对）。

**验收标准（Given/When/Then）**

- Given 密钥管理服务在线，When 业务服务执行 SM4 加密或解密，Then 密钥由密钥管理服务供给，业务服务本地不再依赖密钥文件（演示核对：业务配置中无本地密钥文件路径）；
- Given 密钥管理服务不可用，When 业务服务执行加解密，Then 返回明确业务错误"密钥服务暂不可用"（`1001S0001`），**不得静默降级**为本地密钥或明文（fail-fast，沿 ADR-006 enabled=false 同款语义）；
- Given 密钥库存储，When 检查数据库中的密钥记录，Then 所有密钥材料字段均为密文形态（信封格式），无明文密钥。

### 行为 2：密钥轮换策略

**业务规则**

1. 密钥按**密钥编号**（业务别名）管理，与既有信封格式与 `KeyProvider.sm4Key(keyRef)` 口径一致；
2. 轮换由**授权管理员显式触发**（V1.0 不做自动定时轮换，见非目标）；
3. 轮换后：**新数据一律用新版本密钥加密**；**旧版本密钥保留用于解密旧密文**，旧密文不失效（依赖 ADR-006 §3.2 信封版本位；解密按密文归属版本取历史密钥）；
4. 轮换动作**必须留痕**：操作者、时间、密钥编号、新旧版本写入审计日志；
5. 轮换接口仅授权管理员可调用，非授权调用拒绝。

**验收标准（Given/When/Then）**

- Given 密钥 K 已产生密文 C1，When 授权管理员轮换 K，Then C1 仍可正常解密，且此后新加密数据使用新版本密钥；
- Given 一次轮换操作，When 查询审计日志，Then 存在操作者、时间、密钥编号、新旧版本四要素记录；
- Given 未授权身份调用轮换接口，When 请求到达，Then 被拒绝且留拒绝记录。

### 行为 3：禁硬编码检查

**业务规则**

1. 提交门禁自动扫描硬编码密钥（在既有 secretsScan 门禁上**增强规则**，不新建第二套扫描），命中即红灯、禁止合入（门禁无特批，章程原则 6）；
2. 扫描范围：代码、配置、文档；规则在既有 7 条正则之上补齐**国密密钥材料样式**（如 Base64 编码的 16/32 字节密钥常量、密钥文件路径硬编码等，具体正则清单由设计细化并在门禁配置留痕）；
3. 门禁规则调整属配置变更，随本任务分支留痕提交（不触碰 CI 门禁配置红线——是增强规则而非放宽）。

**验收标准（Given/When/Then）**

- Given 代码或配置中写入密钥样式内容，When 运行门禁，Then secretsScan 红灯并指明文件位置；
- Given 不含密钥的常规提交，When 运行门禁，Then 绿灯通过（新增规则不得误伤正常开发内容）。

## 3. 非目标（本任务不做）

1. 自动定时轮换（V1.0 仅管理员手动触发；自动轮换作为改进建议登记）；
2. SM2 身份类密钥（主体身份密钥归 3.1.8 DID 体系，ADR-006 §3.3 已划界）；
3. 传输加密 TLS/HTTPS（等保清单 G-01，独立缺口）；
4. 商业/云厂商 KMS 产品采购对接（演示期零外部采购，沿 2.4.6 lofi Q3 裁决口径）；
5. 算法与信封格式变更（ADR-001/ADR-006 冻结）；
6. 多区域/跨集群密钥同步。

## 5. 边界声明

- **允许改动**：`common/crypto`（新增 KMS 侧 KeyProvider 实现，覆盖 Bean 方式接入）；新建密钥管理服务模块（`services/` 下，按 ADR-001 冻结技术栈）；`scripts/gates/gates-config.json`（secretsScan 规则增强）；`docs/`（ADR-006 状态注记、等保清单三行按维护规则刷新）；
- **禁止改动**：既有业务服务代码（零改动接入是验收项）；算法实现与信封格式；CI 门禁的放宽类配置。
