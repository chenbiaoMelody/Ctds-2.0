## 1. 用户故事

作为**数据提供方（已入驻主体、空间成员）**，我希望**在空间内登记数据资源**并完成元数据填报与分类分级申报，让平台生成唯一数据标识、全程留痕可溯——以便后续把资源产品化对外提供，且"登了什么、谁登的"清清楚楚。

作为**需求方（已入驻主体）**，我希望**在统一目录按分类与关键词检索已上架的数据产品，并订阅收藏感兴趣的产品**——以便快速找到合规可订购的数据，不错过产品变更。

作为**提供方与平台运营方**，我希望**产品的上架 / 下架可管可查**：提供方自助上下架、运营方治理兜底（强制下架），目录只呈现可信内容——以便"目录里有什么、谁放的、何时变的"随时可查。

## 2. 术语与角色

| 术语 / 角色 | 说明 |
| --- | --- |
| **数据资源（资源）** | 提供方在空间内登记的数据对象本体描述（数据集 / API / 报告 / 模型四形态，§7 Q4 建议口径）；资源是**登记与元数据载体**，不承载本体数据的存储与传输（交付归 C-5.x） |
| **数据产品（产品）** | 资源的产品化封装（PRD C-3.3）：含形态、定价与目录呈现信息，是统一目录的检索与订购单元 |
| **统一目录（目录）** | 平台级的数据产品目录（PRD C-3.2）：仅呈现**已上架**产品，支持分类检索与订阅收藏 |
| **数据标识** | 平台在资源登记成功时生成的**全平台唯一、不可变更**的编号（§7 Q3 建议口径；编号规则随 3.3.2 落定） |
| **语义标签** | 描述资源内容与用途的标签，从**受控词表**中选取（§7 Q6 建议口径）；词表集合随 3.3.3 落定 |
| **分类分级申报** | 登记时由提供方申报所登记数据的**分类归属与敏感级别（L1~L4）**——分级规范 CAT-07 口径"由提供方在登记时申报，平台复核"；资源元数据本身按 **CAT-03** 落级 |
| **提供方** | 登记资源并封装产品的**已入驻（ADMITTED）主体**；资源的管理动作仅限登记主体本人（§7 Q1 建议口径） |
| **需求方（检索用户）** | 检索目录、订阅收藏产品的**已入驻主体**；不要求与提供方同空间 |
| **平台运营方** | 平台侧治理角色：可查看全部资源与产品治理信息、**强制下架**违规产品（行为 4、7——治理动作唯一例外且留痕） |
| **上架 / 下架** | 产品进入 / 退出统一目录的动作（行为 4）；下架后不可被新检索与新订购，既有权益不受影响（归 C-4.x / C-7.x 承接） |
| **留痕四要素** | "谁 / 何时 / 对象 / 动作"四项业务要素，只记业务要素、不含敏感原文（对齐 C-1.1 / C-1.2 / 空间域同源口径） |

## 3. 行为清单（业务语言）

> **口径说明**：每条行为的"验收标准"即剧本步骤的判定依据；「（§7 Qx，建议 A）」即该条依赖的决策点**建议口径落点**（待编排师确认，确认后改"已裁决采 A"）。

### 行为 1：数据资源登记（C-3.1）

**规则**

1. **资格门槛**：登记主体须为**已入驻（ADMITTED）**主体，且为**目标空间的成员（member 及以上）**（§7 Q1 建议口径——空间是资源归属容器，沿 ADR-005 `/api/v1/data-spaces/{id}/datasets` 先例）；未入驻主体的拒绝口径**不区分**"主体不存在"与"主体未入驻"（防枚举，对齐 C-1.1 出站口径）；非空间成员的拒绝为权限拒绝（留痕）。
2. **空间状态门槛**：仅**已启用（ACTIVE）**空间可登记资源；未启用（已创建未启用）/ 已冻结 / 已解散空间一律拒绝——冻结拒新增资源系空间规格行为 2 规则 3 的显式兑现，未启用与已解散沿"未启用不生效策略 / 解散归档不可变"的同源口径延伸（§7 Q1 建议口径）。
3. **要素**：登记须提供——资源名称、资源类型（数据集 / API / 报告 / 模型四类受控枚举，§7 Q4 建议口径）、简介、语义标签（受控词表选取）、**分类分级申报（必填）**（见规则 4）；可选字段随 3.3.2 数据模型落定。
4. **分类分级申报与重要数据拒收**：申报口径为"提供方申报、平台复核"（分级规范 CAT-07）；**申报为"重要数据"的资源，V1.0 一律拒收登记**（分级规范 §4.5-3）并留痕；疑似重要数据特征在登记环节的落地 = 拒收 + 事件登记 + 上报（分级规范 §4.5-1）。
5. **数据标识**：登记成功由**平台生成全平台唯一、不可变更**的数据标识（§7 Q3 建议口径）；同一空间内资源名称唯一，名称为空或超长一律拒绝，控制字符与首尾空白归一化后判定（复用既有归一化口径）。
6. **幂等**：同一登记请求重复提交（同请求标识）只产生一条资源，重复请求返回首次结果（复用 `common` 幂等组件，ADR-007）。
7. **留痕**：登记动作记录四要素，不含敏感原文与数据本体。

**验收标准**

- **GIVEN** 一个已入驻且为某已启用空间成员的主体；**WHEN** 提交要素齐备（含分类分级申报）的登记请求；**THEN** 登记成功、平台生成唯一数据标识、留痕四要素齐备。
- **GIVEN** 一个未入驻主体；**WHEN** 尝试登记资源；**THEN** 被拒绝，提示为统一业务文案（不暴露该主体是否存在的差异）。
- **GIVEN** 一个非目标空间成员的已入驻主体；**WHEN** 尝试在该空间登记资源；**THEN** 被拒绝且记录拒绝留痕。
- **GIVEN** 一个未启用 / 已冻结 / 已解散的空间；**WHEN** 尝试登记资源；**THEN** 一律被拒绝（业务码表意"空间状态不可登记"）。
- **GIVEN** 一份申报为"重要数据"的登记请求；**WHEN** 提交；**THEN** 被拒收登记且留痕（分级规范 §4.5-3 硬约束）。
- **GIVEN** 同一空间已存在名为"普惠金融数据集"的资源；**WHEN** 以含首尾空白的同名提交登记；**THEN** 归一化后判定同名、被拒绝。
- **GIVEN** 一次已成功的登记请求；**WHEN** 以同一请求标识重复提交；**THEN** 资源数量不变、返回首次结果（幂等）。

### 行为 2：资源变更与注销（C-3.1）

**规则**

1. **变更**：仅**登记主体本人**可变更其资源（简介、语义标签、分类分级申报等，可变字段集随 3.3.2 落定）；**分类分级申报的变更只能收紧不得放宽**（级别只能就高上调，下调/放宽方向的变更一律拒绝——与空间域"红线不得放宽"、分级规范"就高"原则同源）；每次变更留痕含"从何值 → 到何值"。
2. **注销前提与不可逆**：仅登记主体本人可发起注销，**须二次确认防误操作**（沿 C-1.2 吊销、空间解散二次确认先例）；注销为**不可逆终态**，留痕保留可追溯；**存在任何未注销产品引用的资源不得注销**（须先处理产品，行为 3 / 4）。
3. **名称锁定**：注销后资源名称在**同一空间**内不可复用（对齐空间域"解散后名称锁定"的防御口径——避免"同名不同资源"混淆历史）。
4. **状态门槛**：已注销资源的一切变更与"再封装 / 再上架"动作一律拒绝。
5. **越权拒绝**：非登记主体（含空间其他成员、空间管理员）执行变更 / 注销一律拒绝并留痕（资源管理权不随空间角色自动扩展，§7 Q1 建议口径）。

**验收标准**

- **GIVEN** 登记主体本人；**WHEN** 变更资源简介与语义标签；**THEN** 变更成功、留痕含从何值到何值。
- **GIVEN** 登记主体本人；**WHEN** 提交分类级别**下调**方向的申报变更；**THEN** 被拒绝且留痕（只能收紧）。
- **GIVEN** 一份无任何产品引用的资源；**WHEN** 登记主体二次确认注销；**THEN** 注销成功且不可逆，名称在本空间内不可再使用。
- **GIVEN** 一份已被产品引用的资源；**WHEN** 尝试注销；**THEN** 被拒绝（先处理产品）。
- **GIVEN** 一个空间管理员（非登记主体）；**WHEN** 尝试变更或注销他人资源；**THEN** 被拒绝且记录拒绝留痕。

### 行为 3：产品封装与定价（C-3.3）

**规则**

1. **封装前提**：仅**资源登记主体本人**可从其**自有资源**封装产品；资源须处于有效状态（未注销，且资源所在空间未解散——已解散空间的资源不得再封装新产品，沿"解散归档不可变"口径，§7 Q5 建议口径）。
2. **产品形态**：API / 数据集 / 报告 / 模型四类受控枚举（PRD C-3.3）；形态与资源类型的一致性校验规则随 3.3.5 落定，本规格定"形态必填且从枚举选取"。
3. **定价模型**：上架前须明确定价——**免费 / 按次 / 包月 / 交易额分成四档**（对齐 WBS 3.7.6 计费引擎口径，§7 Q4 建议口径）；免费也须显式选择（不得空缺）；价格数值字段随 3.3.5 落定。
4. **一资源多产品**：允许同一资源封装多个产品（不同形态 / 定价，数量上限随 3.3.5 落定，§7 Q4 建议口径）。
5. **产品要素与命名**：产品名称、简介、形态、定价模型、关联资源为必填；产品名称**同一提供方内唯一**（对齐空间域"同一所有者唯一"先例，§7 Q3 建议口径）；产品信息不得含敏感原文与个人信息（CAT-04 落级复核归 3.3.5）。
6. **幂等与留痕**：封装请求幂等（ADR-007）；封装动作留痕四要素。

**验收标准**

- **GIVEN** 登记主体的一份有效资源；**WHEN** 以齐备要素（含定价模型）封装产品；**THEN** 封装成功、产品处于"未上架"初始态、留痕齐备。
- **GIVEN** 一份他人（非本人）登记的资源；**WHEN** 尝试从其封装产品；**THEN** 被拒绝且留痕。
- **GIVEN** 一份已注销资源或已解散空间内的资源；**WHEN** 尝试封装；**THEN** 被拒绝（状态门槛）。
- **GIVEN** 同一提供方已存在名为"XX 数据服务"的产品；**WHEN** 以同名再次封装；**THEN** 被拒绝。
- **GIVEN** 一次已成功的封装请求；**WHEN** 以同一请求标识重复提交；**THEN** 产品数量不变、返回首次结果（幂等）。

### 行为 4：产品上下架管理（C-3.3）

**规则**

1. **状态机**：`未上架 → 已上架 ⇄ 已下架`，另设**已注销**（仅可从"未上架 / 已下架"发起、不可逆、须二次确认；有在架产品须先下架）（§7 Q5 建议口径）；**可重新上架**（留痕）。
2. **上架前提**：产品要素齐备（含定价）+ 关联资源有效（未注销）+ 提供方主体仍为 ADMITTED；上架后产品进入统一目录可被检索（行为 5）。
3. **下架效果**：下架后产品**不再出现在目录检索结果**、不可被新订购（订购入口归 C-7.3）；**既有权益不受影响**（已成立订单 / 合约的效力归 C-4.x / C-7.x 承接，本规格不改变）。
4. **治理兜底**：**平台运营方可强制下架**任意在架产品（含理由，留痕）；被强制下架的产品重新上架**须提供方整改后自助发起**（本规格不设"运营方解锁"额外状态，V1.0 最小口径）。
5. **变更留痕**：上架 / 下架 / 重新上架 / 强制下架 / 产品信息与定价变更均留痕四要素；已上架产品的信息与定价变更允许（留痕），对既有合约的效力归 C-4.x。
6. **越权拒绝**：非提供方执行上下架与变更一律拒绝（服务端强制 + 留痕）。

**验收标准**

- **GIVEN** 一个要素齐备的未上架产品；**WHEN** 提供方上架；**THEN** 进入"已上架"且可被目录检索到（与行为 5 联动）。
- **GIVEN** 一个已上架产品；**WHEN** 提供方下架；**THEN** 目录检索不再呈现该产品；**AND WHEN** 提供方重新上架；**THEN** 恢复可检索（均留痕）。
- **GIVEN** 一个已上架产品；**WHEN** 平台运营方强制下架并填写理由；**THEN** 下架成功、留痕含理由与操作者。
- **GIVEN** 一个已上架产品；**WHEN** 非提供方尝试下架或变更定价；**THEN** 被拒绝且记录拒绝留痕。
- **GIVEN** 一个已下架产品；**WHEN** 尝试注销；**THEN** 允许（二次确认后）且不可逆、留痕保留。

### 行为 5：统一目录检索与分类（C-3.2）

**规则**

1. **呈现范围**：目录仅呈现**已上架**产品；未上架 / 已下架 / 已注销产品对提供方本人与平台运营方之外不可检索（行为 7 细化边界）。
2. **检索者资格**：检索主体须为**已入驻（ADMITTED）**主体（§7 Q6 建议口径）；未入驻主体的拒绝口径不区分"不存在 / 未入驻"（防枚举）。
3. **检索能力**：支持**分类过滤（平台受控类目）+ 关键词匹配（名称 / 简介）+ 分页**（复用 `common-pagination`，ADR-005 分页规范）；类目树与种子类目随 3.3.4 落定；**语义检索为预留接口**（对接 AI-0，归 3.10.2 / 3.3.4，本规格不含）。
4. **检索 ≠ 可访问**：检索结果与产品详情**仅为目录元数据**，不含资源本体、不含敏感原文（对齐空间域"可见性 ≠ 可访问性"同源口径）；资源本体访问须经订购与合约（C-7.3 / C-4.x）。
5. **排序**：默认排序口径随 3.3.4 落定（建议上架时间倒序），本规格不做承诺。

**验收标准**

- **GIVEN** 一个已上架产品；**WHEN** 任一已入驻主体按分类或关键词检索；**THEN** 该产品出现在结果中且仅含目录元数据。
- **GIVEN** 一个未上架（或已下架 / 已注销）产品；**WHEN** 任一主体检索目录；**THEN** 结果不含该产品。
- **GIVEN** 一个未入驻主体；**WHEN** 尝试检索目录；**THEN** 被拒绝且提示为统一业务文案。
- **GIVEN** 一次目录检索；**WHEN** 结果超过单页容量；**THEN** 按分页规范返回（`total` 与分页字段齐备）。

### 行为 6：订阅与收藏（C-3.2）

**规则**

1. **收藏**：已入驻主体可收藏**已上架**产品、取消收藏；重复收藏幂等（不新增行）；仅可操作**本人**的收藏（越权拒绝）。
2. **订阅**：订阅 = 登记对产品的**订阅关系**，产品信息变更 / 重新上架时订阅者**可感知**（§7 Q7 建议口径）；**V1.0 通知形态最小化**——订阅关系与产品变更留痕可查，不承诺实时推送（通知渠道随 3.3.4 / 3.7.2 落定）。
3. **状态联动**：产品下架 / 注销后，既有收藏与订阅条目**保留但标记产品当前状态**（不删除历史）；不可对未上架产品**新发起**订阅与收藏。
4. **留痕**：收藏 / 取消 / 订阅 / 退订均留痕（谁 / 何时 / 对哪个产品）。

**验收标准**

- **GIVEN** 一个已上架产品；**WHEN** 已入驻主体收藏；**THEN** 收藏列表含该产品；**AND WHEN** 重复收藏；**THEN** 收藏数不变（幂等）。
- **GIVEN** 一个已上架产品；**WHEN** 已入驻主体订阅；**THEN** 订阅关系登记成功且留痕可查。
- **GIVEN** 主体 A 的收藏条目；**WHEN** 主体 B 尝试取消 A 的收藏；**THEN** 被拒绝（仅可操作本人条目）。
- **GIVEN** 一个已下架产品；**WHEN** 查看既有收藏条目；**THEN** 条目保留且标记"已下架"；**AND WHEN** 新发起收藏 / 订阅；**THEN** 被拒绝。

### 行为 7：目录访问边界与治理例外（C-3.1~3.3 安全面）

**规则**

1. **默认拒绝与服务端强制**：资源与产品的管理动作（登记 / 变更 / 注销 / 封装 / 上下架）仅限**登记主体本人**；非本人（含同空间其他成员与管理员）一律拒绝——判定在**服务端**，界面隐藏不构成权限（对齐 C-1.1"安全边界在后端"口径）。
2. **未上架对象的读取边界**：非提供方读取未上架 / 已下架 / 已注销产品或资源的详情 → 一律拒绝，且拒绝口径**不区分**"对象不存在"与"对象未上架"（防枚举）。
3. **治理例外唯一**：**平台运营方**可查看全部资源与产品（含未上架）的治理信息——唯一例外且**查看留痕**（沿 DB-29 运营档治理查看留痕已交付先例；机制复用形态随 3.3.2~3.3.5 落定）。
4. **越权探测可取证**：被拒绝的越权访问产生拒绝留痕（谁 / 何时 / 目标 / 结果），供审计与 3.3.7 测试取证。
5. **数据本体零接触**：本域一切端点不返回资源数据本体（本体交付归 C-5.x 交付链路）。

**验收标准**

- **GIVEN** 一个非登记主体；**WHEN** 直接调用接口尝试变更他人资源 / 产品（绕过界面）；**THEN** 服务端拒绝且产生拒绝留痕。
- **GIVEN** 一个未上架产品；**WHEN** 非提供方按标识读取其详情；**THEN** 被拒绝且提示与"不存在"同形（防枚举）。
- **GIVEN** 平台运营方；**WHEN** 查看全部产品治理信息（含未上架）；**THEN** 允许且产生查看留痕。
- **GIVEN** 任一目录端点；**WHEN** 检查响应内容；**THEN** 不含资源数据本体与敏感原文。

## 6. 边界声明

1. **演示期安全边界**：演示态服务仅本机可达（ADR-016 §2.7），目录域端点**不得对外暴露**；网关上线前，访问控制结论仅覆盖**应用层鉴权与查询过滤**（诚实边界）。
2. **权限判定的强制点**：一切管理动作与读取边界以**服务端**判定为准；界面隐藏、前端路由守卫均**不构成**权限。
3. **留痕不含原文**：目录域留痕只记业务要素（谁 / 何时 / 对什么 / 做了什么），**不落**敏感原文、个人信息与数据本体（对齐 C-1.1 / 空间域口径与分级规范）。
4. **资格与成员口径唯一**：目录域不自行判定"主体是否可参与"——主体资格一律以 C-1.1 ADMITTED 为准、空间成员关系一律以空间域（3.2.4 交付）为准（避免第二套口径）。
5. **重要数据拒收是硬约束**："申报重要数据的登记一律拒收"（分级规范 §4.5-3）须**代码强制并有反向探针**；任何"放宽申报、绕过拒收"的实现路径（含界面、接口、数据订正）都不允许（沿"安全断言必须代码强制"教训）。
6. **名称与术语**：目录域统一使用"数据资源 / 数据产品 / 统一目录"；资源命名沿 ADR-005 先例（§7 Q8 建议口径），不在本域引入"商品 / 物品 / listing"等第二套概念。
