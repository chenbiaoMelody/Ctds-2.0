## 1. 用户故事

作为**数据需求方（已入驻主体）**，我希望**从平台预置的合约模板出发，与数据产品的提供方在线协商条款并完成电子签署**——以便与提供方之间"约定了什么、谁签的、何时生效"清清楚楚、有据可查且不可抵赖。

作为**数据提供方（产品属主）**，我希望**在合约中约定使用控制策略（次数、期限、用途、域内使用、禁止再分发），合约生效后策略自动执行、越界使用一律被拒**——以便我的数据"给出去之后怎么被使用"仍有硬约束，而不是一纸空文。

作为**平台运营方**，我希望**统一维护合约模板、并拥有唯一的治理例外（查看全部合约治理信息、必要时强制终止违规合约）**——以便平台上流通的合约"从什么模板来、谁在履约、有没有被治理过"随时可查。

## 2. 术语与角色

| 术语 / 角色 | 说明 |
| --- | --- |
| **数字合约（合约）** | 数据产品供需双方就数据使用达成的电子协议：以**合约模板**为框架、经**在线协商**定稿、经**电子签署**生效、内含**使用控制策略**条款；合约文本与签署记录按 CAT-04 **L3** 管控 |
| **合约模板（模板）** | 平台预置的合约条款框架（公共数据授权 / API 调用 / 隐私计算三类，PRD C-4.1）：含必填条款槽位与可选条款槽位（槽位集合随 3.4.2 落定）；**版本化**管理 |
| **在线协商** | 供需双方就合约条款交替提案 / 反提案的过程，每轮产生新的**条款版本**（全程留痕含"从何值 → 到何值"） |
| **电子签署** | 双方各自以**主体 DID 身份 + 国密 SM2 数字签名**完成的签署动作（复用 did / kms 既有能力；V1.0 平台内口径，§7 Q4） |
| **签署存证** | 签署完成时登记的**存证事件**（合约哈希 + 签署要素）；V1.0 落库留痕，**链上对接归 3.8.x**（3.8.3"合约"环节埋点，§7 Q5） |
| **使用控制策略（策略）** | 合约条款的组成部分：**次数 / 期限 / 用途 / 域内使用 / 禁止再分发**五要素（PRD C-4.3），由提供方提出、随合约双签生效、由策略执行引擎自动执行（§7 Q6） |
| **策略执行引擎** | 在数据交付 / 调用链路上执行策略判定的组件（调用拦截、配额计数、期限控制、用途 / 域校验；归 3.4.5，与网关集成）；本规格只定义**判定口径** |
| **提供方** | 合约对象数据产品的**属主主体**（ADMITTED、产品在架；沿目录域"管理动作仅限本人"口径） |
| **需求方** | 发起合约的**已入驻（ADMITTED）主体**，且**不得与提供方为同一主体**（§7 Q1） |
| **合约双方** | 提供方与需求方合称；合约详情、策略视图与执行记录的**默认可见对象** |
| **平台运营方** | 平台侧治理角色：**唯一**的模板维护者与治理例外持有者（查看全部合约治理信息 + 强制终止，均留痕） |
| **留痕四要素** | "谁 / 何时 / 对象 / 动作"四项业务要素，只记业务要素、不含敏感原文（对齐 C-1.1 / C-1.2 / 空间域 / 目录域同源口径） |

## 3. 行为清单（业务语言）

> **口径说明**：每条行为的"验收标准"即剧本步骤的判定依据；依赖决策点的条目以「（§7 Qx）」标注，裁决后回填"已裁决采 X"。

### 行为 1：合约模板管理（C-4.1）

**规则**

1. **维护权唯一**：模板的新增、修订、启用、停用仅限**平台运营方**；其他任何主体（含提供方与需求方）一律拒绝并留痕（服务端强制）（§7 Q2）。
2. **预置三类模板**：平台预置**公共数据授权 / API 调用 / 隐私计算**三类模板（PRD C-4.1 原文）；预置模板随 3.4.2 交付落库。
3. **版本化**：模板修订产生**新版本**，旧版本保留可查；**合约发起时锁定模板版本快照**——模板后续修订 / 停用不影响已发起的合约与协商中草案（版本快照口径，§7 Q2）。
4. **启用 / 停用**：停用模板不可用于新发起合约；停用不影响既有合约与协商中草案；启停均留痕。
5. **浏览边界**：已入驻主体可浏览**启用中**模板及其条款框架；未入驻主体的拒绝口径不区分"主体不存在 / 未入驻"（防枚举，对齐 C-1.1 出站口径）。
6. **发起必须走模板**：合约草案只能从**启用模板**发起，不允许自由文本起草（条款一致性由模板框架保证，§7 Q2）。
7. **留痕**：模板新增 / 修订 / 启停均留痕四要素（版本号与操作者）。

**验收标准**

- **GIVEN** 平台运营方；**WHEN** 新增或修订模板；**THEN** 产生新版本、旧版本保留、留痕四要素齐备。
- **GIVEN** 一份基于模板 V1 发起并协商中的合约草案；**WHEN** 运营方将该模板修订为 V2；**THEN** 草案仍按 V1 快照继续协商（不受影响）。
- **GIVEN** 一份已停用模板；**WHEN** 任一已入驻主体尝试以其发起合约；**THEN** 被拒绝。
- **GIVEN** 未入驻主体；**WHEN** 尝试浏览模板；**THEN** 被拒绝且提示为统一业务文案（不暴露主体是否存在）。
- **GIVEN** 非运营方主体；**WHEN** 尝试新增 / 修订 / 停用模板；**THEN** 被拒绝且记录拒绝留痕。

### 行为 2：合约发起与在线协商（C-4.2）

**规则**

1. **合约对象锚点**：合约对象 = 目录域**已上架产品**；提供方 = 产品属主（ADMITTED）；**需求方 = 已入驻主体且 ≠ 提供方**；未入驻主体发起被拒且不区分"不存在 / 未入驻"（防枚举）（§7 Q1）。
2. **产品状态门槛**：未上架 / 已下架 / 已注销产品**不可新发起合约**（沿目录域行为 4 规则 3"下架后不可被新订购"口径）；**产品下架 / 注销后既有合约效力不变**（归行为 6 承接）。
3. **发起与快照**：需求方选定启用模板对产品发起合约草案（幂等，ADR-007）；草案锁定模板版本快照、含产品定价口径（沿产品定价四档；**计费与账单归 3.7.x，本规格不做**）。
4. **协商机制**：双方**交替提案 / 反提案**，每轮产生新条款版本并留痕（含"从何值 → 到何值"与提案方）；任一方可**终止协商**（留痕）；**双方先后确认**后条款锁定，合约进入"待签署"（§7 Q3）。
5. **策略条款**：使用控制策略条款由**提供方**提出（行为 4）；需求方可经协商反馈（每轮条款版本承载）。
6. **留痕**：发起 / 每轮提案 / 确认 / 终止均留痕四要素。

**验收标准**

- **GIVEN** 已入驻需求方与一份在架产品；**WHEN** 从启用模板发起合约草案；**THEN** 草案创建成功、锁定模板版本快照、留痕齐备。
- **GIVEN** 一份已下架产品；**WHEN** 需求方尝试发起合约；**THEN** 被拒绝。
- **GIVEN** 未入驻主体；**WHEN** 尝试发起合约；**THEN** 被拒绝且提示为统一业务文案。
- **GIVEN** 提供方本人；**WHEN** 尝试对**自己的**产品以需求方身份发起合约；**THEN** 被拒绝（合约双方须为不同主体）。
- **GIVEN** 协商中的一份合约；**WHEN** 提供方提交反提案；**THEN** 条款版本 +1、留痕含从何值到何值。
- **GIVEN** 一次已成功的发起请求；**WHEN** 以同一请求标识重复提交；**THEN** 合约数量不变、返回首次结果（幂等）。

### 行为 3：电子签署与合约生效（C-4.2）

**规则**

1. **签署方式**：电子签署 = 双方各自以**主体 DID 身份 + 国密 SM2 数字签名**完成签署（复用 did / kms 既有签发与验签能力；**对接第三方电子签服务 = 非目标**，§7 Q4）。
2. **双签生效**：任一方先签后合约处于"部分签署"；**双方均签署后合约生效**，生效时间以**最后一签**为准；签署动作不可撤销（V1.0 口径——撤回路径 = 行为 6 的终止，仅限对方未签署时）。
3. **拒签终止**：在对方未签署前，任一方可**拒签终止**合约（留痕）；对方已签署后不可单方撤回。
4. **验签可核**：合约双方与平台运营方可核验签署有效性（签名、签署方身份、签署时间——不可抵赖）；验签不通过按异常处置留痕。
5. **签署存证**：合约生效时登记**存证事件**（合约哈希 + 双方签署要素），V1.0 落库留痕；**链上存证对接归 3.8.x**（3.8.3"合约"环节埋点；本规格只定存证事件口径，§7 Q5）。
6. **留痕**：每方签署、拒签、存证事件均留痕四要素。

**验收标准**

- **GIVEN** 一份待签署合约；**WHEN** 提供方签署；**THEN** 合约处于"部分签署"、留痕齐备；**AND WHEN** 需求方签署；**THEN** 合约**生效**、生效时间 = 最后一签时间、存证事件登记（含合约哈希）。
- **GIVEN** 一份已生效合约；**WHEN** 任一方核验签署；**THEN** 双方签名与身份核验通过（不可抵赖）。
- **GIVEN** 一份对方未签署的部分签署合约；**WHEN** 任一方拒签终止；**THEN** 合约终止且留痕。
- **GIVEN** 一份双方均已签署的生效合约；**WHEN** 任一方尝试单方撤回签署；**THEN** 被拒绝。

### 行为 4：使用控制策略条款（C-4.3）

**规则**

1. **策略归属**：策略是**合约条款的组成部分**，由**提供方提出**、经协商定稿、随合约双签**同时生效**（§7 Q6）。
2. **策略五要素**：**次数**（使用次数上限）/ **期限**（使用期限）/ **用途**（用途限定）/ **域内使用**（使用地域范围）/ **禁止再分发**（PRD C-4.3 与 WBS 行 278 DSL 规范口径）；五要素可独立启用或组合，**至少启用一项**（无策略的合约须显式声明"无使用限制"并经双方确认）；要素的字段与 DSL 语法归 **3.4.4**（策略即代码）。
3. **策略模型对齐复用**：使用控制策略模型与空间域策略模型**对齐复用**（空间规格行为 7 规则 6：禁止两处各自定义策略模型）——模型形态对齐的落点归 3.4.4 DSL 设计；两类策略的**业务对象不同**（空间策略 = 平台 / 空间级治理配置的继承覆盖；使用控制策略 = 供需双方就数据使用的一对一约定），本规格只定后者的业务语义。
4. **策略视图**：合约双方可查看本合约的策略全文（要素值与组合）；未参与方不可见（行为 7）。
5. **生效后变更**：合约生效后策略**不可单方变更**；变更须双方合意走合约变更流程（留痕含从何值 → 到何值）；V1.0 变更流程的最小形态 = 双方确认的新条款版本（深化归 3.4.3）。
6. **要素校验**：策略要素取值非法（如次数为负 / 期限早于生效日）在发起与协商提交时即拒绝。

**验收标准**

- **GIVEN** 一份含五要素策略的合约；**WHEN** 双签生效；**THEN** 策略同时生效、双方可在策略视图查到要素全文。
- **GIVEN** 一份策略要素取值非法的条款提案；**WHEN** 提交；**THEN** 被拒绝。
- **GIVEN** 已生效合约；**WHEN** 提供方尝试单方变更策略；**THEN** 被拒绝。
- **GIVEN** 一份未声明任何策略要素且未显式声明"无使用限制"的条款定稿；**WHEN** 提交确认；**THEN** 被拒绝（至少一项或显式声明）。

### 行为 5：策略执行与绕过拒绝（C-4.3）

**规则**

1. **执行点**：策略在**数据交付与调用链路**上执行（调用拦截、配额计数、期限控制、用途 / 域校验——归 3.4.5 引擎，与网关 / 交付链集成，WBS 行 279）；本规格定义**判定口径**，不含引擎实现。
2. **五类拦截**：**次数耗尽**（超出合约次数上限）/ **期限届满**（超期使用）/ **用途不符**（约定用途之外的使用）/ **域外使用**（约定地域范围之外的使用）/ **再分发动作**（约定禁止再分发时的转授 / 转售 / 对外提供动作）——一律**服务端拒绝 + 拒绝留痕**。
3. **服务端强制**：策略执行判定在**服务端**；界面提示、前端隐藏、参数篡改均不构成执行（对齐 C-1.1"安全边界在后端"）；**直接调用接口同样被拦截**。
4. **双向用例硬约束**：每一类策略要素必须有"**策略生效（合规使用被放行）+ 绕过被拒（越界使用被拦截）**"的**双向用例**（章程与 AGENTS §4 明文；由 3.4.6 模拟器与测试台、3.4.8 测试与集成承接）。
5. **执行与拒绝记录**：放行产生**使用计数**（双方可查本合约执行记录摘要）；拒绝留痕含"谁 / 何时 / 哪份合约 / 触发的策略要素 / 拒绝结果"。
6. **配额计数口径**：次数配额的计数口径（按调用次数 / 按交付次数）随 3.4.5 设计落定，本规格登记为未定义项。

**验收标准**

- **GIVEN** 一份次数上限 100 的生效策略；**WHEN** 第 1~100 次合规使用；**THEN** 全部放行且使用计数可查；**AND WHEN** 第 101 次；**THEN** 被拒绝且拒绝留痕含触发要素。
- **GIVEN** 一份期限 30 天的生效策略；**WHEN** 期限内使用；**THEN** 放行；**AND WHEN** 期限届满后使用；**THEN** 被拒绝。
- **GIVEN** 一份用途限定"风控建模"的生效策略；**WHEN** 以约定用途使用；**THEN** 放行；**AND WHEN** 以约定外用途使用；**THEN** 被拒绝。
- **GIVEN** 一份域内使用限定的生效策略；**WHEN** 域内使用；**THEN** 放行；**AND WHEN** 域外使用；**THEN** 被拒绝。
- **GIVEN** 一份含禁止再分发的生效策略；**WHEN** 尝试再分发动作；**THEN** 被拒绝且留痕。
- **GIVEN** 任一被拒场景；**WHEN** 绕过界面直接调用接口；**THEN** 同样被拦截（服务端强制）。

### 行为 6：合约状态与生命周期（C-4.2）

**规则**

1. **状态机**：`草案 → 协商中 → 待签署 → 已生效 → 已完结`；终止分支：协商中**协商终止**（任一方）、待签署 / 部分签署**拒签终止**（任一方，对方未签署时）、生效后**双方合意解除**或**运营方强制终止**（含理由）（§7 Q3）。
2. **终态与不可逆**：已完结 / 已终止（各分支）为**终态**，留痕保留可追溯、不可删除。
3. **产品联动**：产品下架 / 注销后**既有合约效力不变**（承接目录域行为 4 规则 3"既有权益不受影响"）；该产品不可再新发起合约（行为 2 规则 2）；既有合约履约完毕后自然完结。
4. **强制终止**：平台运营方可强制终止生效中合约（治理兜底，理由必填、留痕含操作者与理由——沿目录域"强制下架"同款口径）；被强制终止合约下的策略同步失效。
5. **主体资格联动**：合约双方主体状态异常（如主体注销 / 资格撤销）时的合约处置口径，V1.0 登记为未定义项（归 3.4.3 实施时复核，诚实边界）。
6. **留痕**：全部状态转移留痕四要素（含触发方与结果）。

**验收标准**

- **GIVEN** 一份协商中合约；**WHEN** 任一方终止协商；**THEN** 合约终止且留痕。
- **GIVEN** 一份生效合约；**WHEN** 双方合意解除；**THEN** 合约完结且留痕。
- **GIVEN** 一份生效合约；**WHEN** 平台运营方强制终止并填写理由；**THEN** 终止成功、留痕含理由与操作者、合约下策略同步失效。
- **GIVEN** 在架产品 A 的一份生效合约；**WHEN** 提供方将产品 A 下架；**THEN** 该合约**效力不变**（仍可履约至完结）；**AND WHEN** 任何主体尝试对产品 A 新发起合约；**THEN** 被拒绝。

### 行为 7：合约域访问边界与治理例外（C-4.1~4.3 安全面）

**规则**

1. **默认可见对象**：合约与协商详情、策略全文、执行记录摘要仅**合约双方**可见；非合约参与方（含同空间其他成员与管理员、平台其他入驻主体）读取一律拒绝，且拒绝口径**不区分"合约不存在 / 无权限"**（防枚举）。
2. **治理例外唯一**：**平台运营方**可查看全部合约治理信息（含协商中 / 已终止）——唯一例外且**查看留痕**（沿 DB-29 / 目录域治理查看留痕先例；机制复用形态随 3.4.2~3.4.5 落定）。
3. **服务端强制**：一切可见性与管理动作判定在**服务端**；界面隐藏不构成权限；越权探测可取证（拒绝留痕）。
4. **数据本体零接触**：合约域一切端点不返回数据资源本体（本体交付归 C-5.x）；合约文本按 **CAT-04 L3** 管控（存储保密走国密组件，访问沿角色边界）。
5. **留痕不含敏感原文**：合约域留痕只记四要素（谁 / 何时 / 对象 / 动作）与业务要素（版本号、策略要素值、拒绝原因的业务码表意），**不落**敏感原文与数据本体（CAT-04 L3 管控的合约全文仅存于合约载体本体，非留痕字段）。

**验收标准**

- **GIVEN** 一份他人（非本人参与）的合约；**WHEN** 任一非参与方按合约标识读取；**THEN** 被拒绝且提示与"不存在"同形（防枚举）。
- **GIVEN** 平台运营方；**WHEN** 查看全部合约治理信息；**THEN** 允许且产生查看留痕。
- **GIVEN** 任一合约域端点；**WHEN** 检查响应内容；**THEN** 不含数据本体与敏感原文。
- **GIVEN** 一个非运营方主体；**WHEN** 直接调用接口尝试维护模板或终止他人合约；**THEN** 服务端拒绝且产生拒绝留痕。

## 6. 边界声明

1. **演示期安全边界**：演示态服务仅本机可达（ADR-016 §2.7），合约域端点**不得对外暴露**；网关上线前，策略执行结论仅覆盖**应用层拦截判定**（网络级控制归 3.5.2，诚实边界）。
2. **权限判定的强制点**：一切管理动作与可见性判定以**服务端**为准；界面隐藏、前端路由守卫均**不构成**权限（对齐 C-1.1 / 空间域 / 目录域口径）。
3. **电子签署的法律效力边界（诚实声明）**：V1.0 电子签署 = 平台内 DID + 国密 SM2 数字签名，满足"身份可核验、签名不可抵赖、留存可追溯"的技术口径；**不等同**于《电子签名法》意义上的"可靠电子签名"资质（第三方 CA / 合规电子签服务对接归后续，§7 Q4 备选影响已声明）。
4. **策略执行的覆盖边界**：策略拦截覆盖**平台交付与调用链路内**的使用行为；"下载后线下扩散"等链路外行为无法由平台策略引擎拦截（该风险由合约违约条款与履约监测〔C-4.4，P1〕、存证审计〔3.8.x〕承接——诚实边界，不承诺绝对防控）。
5. **资格与状态口径唯一**：合约域不自行判定"主体是否可参与"（一律以 C-1.1 ADMITTED 为准）、不自行判定产品状态（一律以目录域为准）、不另设第二套定价体系（沿产品定价四档）。
6. **名称与术语**：合约域统一使用"数字合约 / 合约模板 / 在线协商 / 电子签署 / 使用控制策略"；资源命名沿 ADR-005 先例（§7 Q8），不在本域引入"合同书 / 协议书 / license"等第二套概念。
