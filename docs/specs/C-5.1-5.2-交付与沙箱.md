## 1. 用户故事

作为**数据需求方（已入驻主体，已与提供方签署生效合约）**，我希望**凭已生效的合约按约定方式取到数据（API 调用 / 加密文件下载），并且每次取用都在合约约定的范围内**——以便"我买了什么、能用多少、怎么用"在链路上就被强制，而不是靠我自己守规矩。

作为**数据提供方（产品属主）**，我希望**我的数据在交付通道里以国密加密传输、交付与调用记录可查，需要把原始数据交给需求方开发时走"沙箱"（数据进得去、出不来，产物必须经审核才能带走）**——以便"数据给出去之后怎么被使用"在交付环节同样有硬约束。

作为**平台运营方**，我希望**在沙箱结果导出这个唯一出口上保留审核权并全程留痕**——以便"原始数据不出域、结果审核后导出"（PRD C-5.2 原文）在业务上真的可执行、可追责。

## 2. 术语与角色

| 术语 / 角色 | 说明 |
| --- | --- |
| **交付（数据交付）** | 把已签合约约定的数据（或其调用能力）按约定形态提供使用方使用的动作；V1.0 两种形态 = **API 交付**（网关调用）与**文件交付**（加密文件）——PRD C-5.1 |
| **API 交付** | 使用方经**网关**（ADR-005 全平台唯一流量入口）按合约调用数据产品接口的交付形态；链路 = 鉴权 → 限流 → **策略执行点** → 转发 → **计量埋点**（形态见 WBS 行 289；本规格只定业务行为与判定口径） |
| **文件交付** | 平台把数据以**国密加密交付包**形式提供使用方下载/领取的交付形态（加密与完整性校验走 `common` 国密组件，ADR-006），区别于"线下拷贝" |
| **交付记录（交付单）** | 每一次交付动作（一次 API 交付会话 / 一份交付包 / 一次沙箱交付）的业务载体：含合约、形态、触发方、时间、结果；是计量与存证的**事件源**（模型与端点归 3.5.2~3.5.5，本规格只定业务口径） |
| **数据沙箱（沙箱）** | 平台提供的**隔离开发环境**（PRD C-5.2）：需求方在其中使用合约约定的数据做开发/分析，**原始数据不出域**（进得去、带不出），**产物经审核后方可导出** |
| **沙箱任务** | 一次沙箱申请的载体：绑定**已生效合约**与可用数据集、含资源配额与生命周期（创建 → 运行 → 到期/关闭）；归 3.5.4 |
| **结果物（沙箱产物）** | 在沙箱内产生的开发/分析成果（模型、脚本、报告、数据集等业务形态）——**导出前必须经平台审核**（PRD C-5.2 原文），归 3.5.5 |
| **审核（结果审核）** | 平台运营方对结果物"是否可带出沙箱"的判定动作（含结论与理由，全程留痕）；**审核通过 ≠ 无策略约束**——导出仍受合约策略校验（行为 6 规则 3） |
| **策略执行点** | 交付 / 调用链路上调用策略执行引擎（3.4.5 `check`）的位置；**判定语义唯一权威在合约域**（ADR-019 / ADR-020），交付域**消费不复制** |
| **计量事件** | 交付 / 调用放行产生的业务事件（供 3.7.5 计量采集与 3.7.6 计费使用）；计量模型与流水表归 3.7.x，本规格只定"应产生"口径 |
| **需求方（使用方）** | 合约的需求方一侧；**交付与沙箱的发起主体**（沿合约域角色口径） |
| **提供方** | 合约对象数据产品的属主主体；交付 / 沙箱的**只读可见方**（不代发起） |
| **平台运营方** | 平台侧治理角色：**沙箱结果导出的审核者**与交付域治理例外持有者（查看与审核均留痕） |
| **留痕四要素** | "谁 / 何时 / 对象 / 动作"四项业务要素，只记业务要素、**不含数据本体与敏感原文**（对齐 C-1.1 / C-1.2 / 空间域 / 目录域 / 合约域同源口径） |

## 3. 行为清单（业务语言）

> **口径说明**：每条行为的"验收标准"即剧本步骤的判定依据；「（§7 Qx，已裁决采 A）」即该条依赖的决策点**裁决口径落点**（2026-10-15 编排师一次确认，沿 C-3.1~2.3 / C-4.1~4.3 规格先例）。

### 行为 1：交付准入与凭据（C-5.1 / C-5.2 共同前提）

**规则**

1. **凭合约交付**：API 交付、文件交付与沙箱任务的**唯一凭据 = 已生效合约**（双方签署生效，C-4.2）；**未生效 / 已终止 / 已完结（COMPLETED，沿合约域 C-4.1~4.3 术语）的合约不可新发起交付或沙箱任务**（沿合约域状态门槛与 `1008C0013` 口径——交付域不另设第二套状态判定）。（§7 Q1，已裁决采 A）
2. **发起主体唯一**：交付 / 沙箱的发起人 = 合约**需求方**；提供方与平台运营方**只读可见**（不代发起）；非合约参与方发起一律拒绝。（§7 Q1，已裁决采 A）
3. **形态与合约一致性**：交付形态须与合约锚定产品的形态（API / 数据集 / 报告 / 模型）及约定条款一致；形态不符的交付请求拒绝（不做"绕过合约形态"的额外通道）。（§7 Q1，已裁决采 A）
4. **防枚举**：非参与方与"合约不存在"**同码同文逐字**（沿 R6~R11 口径）；拒绝留痕可取证（留痕四要素）。
5. **幂等**：交付发起支持幂等键（ADR-007）；同一幂等键重放返回首次结果，不产生第二次交付记录。

**验收标准**

1. 以**已生效合约**发起 API 交付 / 文件交付 / 沙箱申请 → **受理**，产生交付记录（含合约、形态、触发方、时间）。
2. 以**协商中 / 待签署**合约发起 → **拒绝**（合约未生效）。
3. 以**已终止 / 已完结**合约发起 → **拒绝**（状态不允许，口径与合约域 `1008C0013` 同语义域）。
4. **提供方**（非发起方）代发起 → **拒绝**且留痕；**非合约参与方**发起 → **拒绝**且与"合约不存在"**同码同文**。
5. 交付形态与合约约定不符 → **拒绝**，不产生交付记录。
6. 同一幂等键重放发起 → 返回首次结果，**交付记录不增加**。

### 行为 2：API 交付（C-5.1）

**规则**

1. **网关唯一入口**：API 交付一律经**网关**（ADR-005：全平台唯一流量入口）——**不经网关的直连数据源调用不属于合规交付通道**；网关承载鉴权、限流、策略执行点与计量埋点（WBS 行 289）。（§7 Q2，已裁决采 A）
2. **交付链顺序**：请求处理顺序 = **鉴权（身份）→ 限流（主体 + 接口，ADR-005 基线）→ 策略执行点（调用 3.4.5 `check`）→ 转发数据源 → 计量埋点**；**策略判定在转发之前**（越界请求不触达数据源）。（§7 Q2，已裁决采 A）
3. **判定不复制**：策略判定语义**唯一权威在合约域**（ADR-019 / ADR-020）；交付链只**消费**判定结果，**不另设第二套策略口径**；越界拒绝沿用合约域出站码与文案（`1008C0020` / `0013` / `0012`，ADR-020 §2.3）。（§7 Q2，已裁决采 A）
4. **凭据形态**：V1.0 = 调用方以**合约编号 + 主体身份**（沿平台既有身份头口径）发起；**独立 API Key 的签发 / 轮换归后续**（登记为未定义项，§6-5 诚实边界）。（§7 Q2，已裁决采 A）
5. **限流与配额分工**：网关限流 = **网络级 / 频率级**保护（不承担业务配额）；**业务次数配额唯一由策略执行引擎判定与计数**（ADR-020 §2.4）——两者不互相替代。
6. **调用记录**：放行的交付 / 调用产生**计量事件**与可查记录；拒绝一律留痕（含触发要素），**拒绝不产生计量**（对齐"拒绝零计数"）。（§7 Q7，已裁决采 A）

**验收标准**

1. 期限内、次数内、用途与域内合规的 API 调用 → **放行**并返回数据；**计量事件产生 1 条**。
2. 经**网关**发起越界调用（超次数 / 超期 / 用途不符 / 域外 / 再分发动作）→ **拒绝**且**不触达数据源**、无计量事件。
3. **绕过网关直连数据源**属于链路外行为——**不在平台承诺范围内**（§6-4 诚实边界），剧本不作正向承诺。
4. 提供方与平台运营方可查看该合约的交付 / 调用记录（**不含数据本体与原文**）。
5. 合同状态失效（终止/完结）后调用 → 沿用合约域 `1008C0013` 口径拒绝。

### 行为 3：文件交付（C-5.1）

**规则**

1. **国密加密交付**：文件交付包一律以**国密组件**（`common` 国密，ADR-006 / ADR-015）加密后交付，**禁止自行实现密码学**；传输完整性以**国密摘要（SM3）校验**。
2. **本体不进留痕**：交付记录与留痕只记**产物标识、校验值、结果**，**不含文件本体与数据原文**；日志与界面展示同样不含本体。
3. **按合约最小必要**：交付的数据范围以合约约定为准，不做合约外的额外交付；交付形态与产品形态（数据集 / 报告 / 模型）一致。
4. **交付记录与可核性**：每次文件交付产生交付记录（谁 / 何时 / 哪份合约 / 产物标识 / 校验值 / 结果），供双方与治理方只读查看（不含本体）。
5. **幂等与重复交付**：同一幂等键重放不重复生成交付记录与交付包。

**验收标准**

1. 以生效合约发起文件交付 → **生成加密交付包**且校验值可核（SM3）。
2. 交付记录可查（含校验值），**不含文件本体与数据原文**。
3. 非参与方查看他人交付记录 → **拒绝**且与"记录不存在"同码同文（防枚举）。
4. 交付范围超合约约定 → **拒绝**，不生成交付包。
5. 同一幂等键重放 → 返回首次交付包信息，**交付记录不增加**。

### 行为 4：沙箱申请与开通（C-5.2）

**规则**

1. **凭合约申请**：沙箱任务须绑定**已生效合约**（行为 1）；申请人与合约需求方一致。
2. **隔离环境**：沙箱运行于**平台侧隔离环境**（容器隔离，3.5.4），与生产数据链路逻辑隔离；**沙箱内可读可算、不可直接带出数据本体**（PRD C-5.2"原始数据不出域"的平台侧落地口径）。（§7 Q5，已裁决采 A）
3. **资源配额与生命周期**：沙箱任务含资源配额（计算/内存/时长）与明确生命周期（创建 → 运行 → 到期自动关闭 / 主动关闭）；到期后任务不可继续使用。
4. **可查**：沙箱任务的创建、运行、关闭与到期**全程留痕**；提供方与平台运营方可只读查看（不含数据本体）。
5. **不得绕开合约**：沙箱申请不得替代合约（无合约不得进沙箱），也不得在沙箱内引入合约未约定的数据源。

**验收标准**

1. 以生效合约申请沙箱 → **开通成功**，任务状态与配额可查并留痕。
2. 以未生效 / 已终止合约申请 → **拒绝**。
3. 非合约需求方申请 → **拒绝**且留痕（防枚举口径同行为 1 规则 4）。
4. 沙箱任务到期后继续使用 → **拒绝**（生命周期终止生效）。
5. 沙箱任务创建 / 运行 / 关闭全程可查，记录**不含数据本体与数据原文**。

### 行为 5：沙箱内使用与隔离（C-5.2）

**规则**

1. **数据进得去、带不出**：沙箱内的原始数据**不可**通过平台任何端点直接导出、下载或复制出沙箱（**唯一出口 = 行为 6 的审核后导出**）；原始数据本体不得出现在沙箱外的界面、日志与留痕。
2. **环境隔离**：沙箱实例之间、沙箱与生产链路之间相互隔离（默认拒绝）；越界访问（跨沙箱、跨合约数据）一律拒绝。
3. **使用留痕**：沙箱内对数据的使用产生**使用留痕**（谁 / 何时 / 哪个沙箱任务 / 动作），**不含数据本体与数据原文**。
4. **策略仍生效**：沙箱内使用同样受合约策略约束——**用途 / 域 / 再分发等要素在沙箱场景下同样判定**（消费 3.4.5 引擎判定口径，不另设沙箱专用策略口径）。（§7 Q7，已裁决采 A）
5. **配额到顶即止**：沙箱任务超出资源配额后不可继续使用（配额判定在服务端，界面不构成绕过路径）。

**验收标准**

1. 沙箱内正常使用合约数据 → **可用**，且产生使用留痕（不含本体）。
2. 尝试从沙箱**直接导出原始数据**（非结果物 / 未经审核路径）→ **拒绝**（唯一出口规则）。
3. 尝试访问**其他沙箱任务**或其他合约的数据 → **拒绝**且留痕。
4. 在沙箱内以合约约定外**用途 / 域**使用数据 → **拒绝**（策略在沙箱场景同样生效）。
5. 超出资源配额继续使用 → **拒绝**（配额到顶即止）。

### 行为 6：结果审核与导出（C-5.2，本域核心管控点）

**规则**

1. **唯一出口**：沙箱结果物的**唯一合规出口 = 平台审核通过后的导出**（PRD C-5.2 原文"结果审核后导出"）；未经审核或审核未通过的结果物**不可导出**（服务端强制）。
2. **审核留痕**：审核动作产生留痕（谁审 / 何时 / 哪个沙箱任务 / 结论与理由）；审核结论 = 通过 / 驳回（驳回含理由）。
3. **导出仍受策略约束**：审核通过 ≠ 免策略——导出前仍执行**策略校验**（用途 / 域 / 再分发等要素，消费 3.4.5 判定口径）；策略越界 → **拒绝导出**。（§7 Q6，已裁决采 A）
4. **服务端强制**：导出判定在**服务端**；界面隐藏、参数篡改、**绕过界面直调接口**均不构成导出路径（对齐"安全边界在后端"）。
5. **导出记录**：导出产生记录（谁 / 何时 / 哪份合约与沙箱任务 / 结果物标识 / 结果），供双方与治理方只读查看。
6. **双向用例硬约束**：结果导出必须有"**审核通过 → 导出放行**"与"**未审核 / 未通过 / 绕过界面 → 导出被拒**"的**双向用例**（章程与 AGENTS §4 双向思路；由 3.5.5 实现、3.5.7 测试与集成承接）。

**验收标准**

1. 审核**通过**的结果物发起导出 → **放行**，产生导出记录；策略校验通过。
2. **未提交审核**的结果物导出 → **拒绝**。
3. **审核驳回**的结果物导出 → **拒绝**（理由可查）。
4. 审核通过但**策略校验越界**（如约定外用途 / 禁止再分发形式）的结果物导出 → **拒绝**且留痕含触发要素。
5. **绕过界面直调导出接口**（未审核的结果物）→ **同样被拒绝**（服务端强制）。
6. 非参与方查看 / 导出他人沙箱结果物 → **拒绝**，与"不存在"同码同文（防枚举）。

### 行为 7：交付域访问边界与治理例外

**规则**

1. **默认拒绝**：交付记录、沙箱任务、结果物与导出记录的可见范围 = **合约参与方（需求方 + 提供方）**；其余主体一律拒绝（防枚举）。
2. **治理例外唯一**：**平台运营方**可查看交付域治理信息，并对沙箱结果物执行**审核**——唯一例外，且查看与审核**均留痕**（沿 DB-29 / 目录域 / 合约域治理查看留痕先例）。
3. **服务端强制**：一切可见性、审核与导出判定在**服务端**；界面隐藏不构成权限；越权探测可取证（拒绝留痕）。
4. **链路外零接触**：交付链路之外（如目录检索、合约详情、界面展示）**不返回数据本体**（沿目录域 / 合约域"本体零接触"口径；本体仅在交付通道内、按合约最小必要传输）。
5. **留痕不含敏感原文**：交付域留痕只记四要素与业务要素（形态、结果、校验值、触发要素码），**不落**数据本体、数据原文与个人信息（CAT-04 / CAT-07 管控要求）。
6. **资格口径唯一**：交付域不自行判定"主体是否可参与"（一律以 C-1.1 ADMITTED 为准）、不自行判定产品与合约状态（一律以目录域 / 合约域为准）。

**验收标准**

1. 需求方与提供方分别查看同一合约的交付记录与沙箱任务 → **均可查看**（内容不含本体）。
2. 非参与方查看 → **拒绝**，与"对象不存在"同码同文。
3. 平台运营方查看治理信息 → **可查看**且产生**治理查看留痕**。
4. 目录检索 / 合约详情 / 交付列表界面上**不出现数据本体与原文字段**。
5. 越权探测（如以他人身份查看导出记录）→ **拒绝 + 拒绝留痕**（四要素齐备）。

## 4. 非目标（本规格明确不做，归属包见括号）

8. **不做连接器跨机构交付通道**——归 **C-6.x（3.6.x 未开工）**；本规格只定平台侧交付与沙箱口径。
9. **不做网络级 / 网关侧访问控制与限流的深化实现**——归 **3.5.2**（ADR-005 基线）；演示期服务仅本机可达（ADR-016 §2.7）。

## 6. 边界声明

1. **演示期安全边界**：演示态服务仅本机可达（ADR-016 §2.7）；**债务 `DB-03`（身份信任边界）的长期解除条件 = 3.5.2 网关 HeaderStripFilter + 3.9.1 真实令牌**——交付域**网关上线前**的鉴权结论仅覆盖应用层判定，**不承诺网络级强隔离**（ADR-020 §2.9 同源诚实边界）。
2. **权限判定的强制点**：一切可见性、审核与导出判定以**服务端**为准；界面隐藏、前端路由守卫均**不构成**权限（对齐 C-1.1 / 空间域 / 目录域 / 合约域口径）。
3. **"原始数据不出域"的平台侧口径（诚实声明）**：V1.0 沙箱为**平台侧隔离环境**——落地口径是"**沙箱内可读可算、数据本体不可经平台端点带出，唯一出口为审核后导出**"；**跨机构物理"数据不出域"**依赖连接器（3.6.x）与隐私计算（C-5.3，P1），**本规格不作跨机构承诺**。
4. **链路外行为不承诺**：交付与沙箱管控覆盖**平台交付 / 调用链路内**的行为；"已导出结果的线下扩散""绕过网关直连数据源"等链路外行为**不在平台承诺范围内**（该风险由合约违约条款与履约监测〔C-4.4，P1〕、存证审计〔3.8.x〕承接——沿 C-4.3 规格 §6-4 同款口径）。
5. **凭据形态的 V1.0 边界**：API 交付 V1.0 沿用平台既有身份口径（合约编号 + 主体身份），**独立 API Key 的签发 / 轮换 / 吊销不在本规格范围**（登记为未定义项，随 3.5.2 设计或后续真实凭证体系落定）。
6. **资格与状态口径唯一**：交付域不自行判定主体资格（一律以 C-1.1 ADMITTED 为准）、不自行判定产品与合约状态（一律以目录域 / 合约域为准）、不另设第二套策略判定与计量口径（ADR-019 / ADR-020 / 3.7.x）。
7. **名称与术语**：交付域统一使用"数据交付 / API 交付 / 文件交付 / 数据沙箱 / 沙箱任务 / 结果物 / 结果审核与导出"；资源命名沿 ADR-005 先例（§7 Q8，已裁决采 A），不在本域引入"投递 / 包体 / 镜像 / workspace"等第二套概念。

| **Q8** | 资源命名与错误码段位 | **A：资源名 `deliveries`（交付记录）+ `sandboxes`（沙箱任务）+ 导出沿用 ADR-005 动词子资源（`POST /…/actions/export`）；错误码顺延 `1009` 段**（1000~1008 已占用：1000 平台公共 / 1001 国密组件 / 1002 幂等锁组件+KMS / 1003 std-adapter / 1004 主体服务 / 1005 DID 服务 / 1006 空间域 / 1007 目录域 / 1008 合约域〔最新码值 `1008C0020`（评审修复批勘正：原误引 `1008C0021`）〕；**`1009C` 段无任何错误码定义占用**（立卡时实测；本规格自身引用不计）；本规格只预留段位，码值随实施包） | B：复用 1008 段（与"一域一段"惯例冲突）；C：资源名 `shipments` / `workbenches`（与 PRD"数据交付 / 数据沙箱"术语不一致） |
| **Q9** | 剧本界面步骤的落地时点 | **A：两份剧本"业务步骤先行、界面入口占位"，界面名称待 3.5.6 交付后按 C-1.2 / C-3.1 / C-4.1 剧本同款"界面名称核对修订"机制一次性核对**（业务判定不变，修订由 PO 批准留痕） | B：剧本全部走"接口 + 命令行样例"（界面交付后再补剧本——会让剧本长期不含界面步骤） |

> **体量 D1（随本表一并确认）**：建议**不拆分**——本卡是 WBS 行 288 的"单卡单目标"（一份规格 + 两份剧本同源派生），拆分将产生"规格无剧本可验、剧本无规格可溯"的中间态（沿 C-2.1 / C-3.1 / C-4.1 D1 同款理由）。
