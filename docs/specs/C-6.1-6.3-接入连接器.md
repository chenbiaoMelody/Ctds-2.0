## 1. 用户故事

作为**参与方（数据提供方 / 数据使用方 / 数商）**，我希望**把标准化连接器接入平台，让我的业务系统经由它完成身份查验、资源登记、产品上架、合约处理、交付与使用控制**——以便我以统一、可信的方式参与数据流通，而不需要为接入单独造轮子（PRD C-6.1 六项功能）。

作为**平台运营方**，我希望**在平台侧对连接器进行注册核验、升级与注销的全生命周期管理**——以便接入平台的每一台连接器都**可信（核验三查）、可控（升级与注销有闸门）、可追溯（全程留痕）**（PRD C-6.2）。

作为**数据提供方**，我希望**连接器能适配我的真实数据源（政务共享交换平台 / 数据库 / 对象存储 / API 网关），源凭据安全托管、连通可自检**——以便交付链取到的是真实源数据，且源端凭据不泄露（PRD C-6.3）。

## 2. 术语与角色

| 术语 / 角色 | 说明 |
| --- | --- |
| **接入连接器（连接器）** | **部署于参与方侧的标准化数据流通组件**（PRD 行 231 术语原文）；本规格中"部署于参与方侧"为业务归属语义（见 §6-1 诚实边界） |
| **连接器属主主体** | 连接器登记所属的已入驻参与方主体；连接器以该主体 DID 为身份锚、以该主体身份开展业务动作 |
| **连接器注册** | 平台侧对连接器的登记与核验动作（PRD C-6.2）：参与方提交申请 → 平台运营方核验通过后生效 |
| **连接器编号** | 核验通过时平台签发的**全局唯一**实例标识；终身不复用（含注销后）；前缀与号段随 3.6.3 实施落定 |
| **连接器版本与兼容性** | 连接器的版本标识与升级时的**兼容性声明**（兼容 / 不兼容）——不兼容升级须运营方显式确认 |
| **六项功能框架** | C-6.1 要求的**身份管理、资源管理、产品管理、合约管理、交付、使用控制**六项功能（PRD C-6.1 原文）；V1.0 以连接器 SDK 框架承载（3.6.2），业务能力由平台对应域提供（行为 2 映射表） |
| **适配器** | 连接器侧对接具体数据源的组件（政务共享交换平台 / 数据库 / 对象存储 / API 网关四类）；归 3.6.5 / 3.6.6 |
| **源接入（连接配置）** | 一条"连接器 × 数据源"的接入登记：源类型、源地址、访问凭据、所属连接器；凭据国密加密存储 |
| **连通性自检** | 源接入后的只读探测（连通 / 凭据 / 权限三查），不产生源端数据变更 |
| **健康度** | 连接器的在线 / 离线状态语义（在线 = 活跃 / 心跳上报未超时；离线 = 超时未上报）——§7 Q8 最小预留 |
| **DID 绑定** | 连接器与所属主体 DID 的绑定记录；连接器是 DID 的**下游消费方**（C-1.2 规格 V1.1 §4.5 口径） |
| **参与方** | 数据提供方 / 数据使用方 / 数商（沿 PRD 角色口径）；连接器的属主与申请者 |
| **平台运营方** | 平台侧治理角色：连接器注册核验者、不兼容升级显式确认者、注销管控者（动作全程留痕） |
| **留痕四要素** | "谁 / 何时 / 对象 / 动作"四项业务要素，只记业务要素、**不含数据本体、源数据原文与凭据明文**（对齐 C-1.1 / C-1.2 / 交付域同源口径） |

## 3. 行为清单（业务语言）

> **口径说明**：每条行为的"验收标准"即剧本步骤的判定依据；「（§7 Qx）」即该条依赖的决策点落点——**一次确认后回填"已裁决采 A"**（沿 C-5.1~5.2 规格先例）。行为 1~5 归 C-6.1、行为 6~10 归 C-6.2、行为 11~14 归 C-6.3。

### 行为 1：连接器接入前提与身份锚（C-6.1 / C-6.2 共同前提）

**规则**

1. **主体前提**：连接器接入以**所属主体已入驻（C-1.1 ADMITTED）**为前提；未入驻 / 待审核 / 已退出主体发起接入一律拒绝。接入为**入驻后的独立业务动作**，不回改 C-1.1 入驻流程（§7 Q3；PRD 行 90 流程中"连接器接入"环节由本前提检查承载）。
2. **身份锚唯一**：连接器**不另设独立身份**——以**所属主体的 DID** 为身份锚（ADR-017），平台侧以**唯一连接器编号**作实例标识；连接器对平台的业务调用沿用平台既有身份口径（§7 Q2）。
3. **防枚举与留痕**：接入登记全程留痕（谁 / 何时 / 对象 / 动作），拒绝理由业务可读；非入驻主体的接入拒绝沿平台防枚举口径，不泄露主体存在性细节。

**验收标准**

1. 已入驻主体发起连接器接入（提交名称 / 类型 / 版本 / 所属主体）→ **受理**，登记记录生成（状态 = 待核验）。
2. 未入驻 / 待审核主体发起接入 → **拒绝**（主体资格不满足）+ 留痕。
3. 同一主体可登记多台连接器，每台编号唯一；**同主体同名连接器唯一**（防重）。
4. 登记记录含名称 / 类型 / 版本 / 所属主体 / 状态 / 时间，**不出现凭据明文**。

### 行为 2：六项功能框架与平台域映射（C-6.1）

**规则**

1. **六项功能**：连接器提供**身份管理、资源管理、产品管理、合约管理、交付、使用控制**六项功能（PRD C-6.1 原文）；V1.0 六项功能以**连接器 SDK 框架**承载（3.6.2），业务能力由平台对应域提供（下表），连接器**不复制平台数据存储、不建第二套业务口径**：

   | 连接器功能 | 平台侧承载域 | 业务口径来源 |
   | --- | --- | --- |
   | 身份管理 | C-1.1 主体 + C-1.2 DID | 主体资格、DID 状态 |
   | 资源管理 | 目录域（C-2.x / C-3.x） | 资源登记与元数据 |
   | 产品管理 | 目录域（C-3.x） | 产品上架 / 下架 / 四形态 |
   | 合约管理 | 合约域（C-4.x） | 协商 / 签署 / 履约 |
   | 交付 | 交付域（C-5.1） | 网关唯一入口 / 加密文件交付 |
   | 使用控制 | 策略执行引擎（C-4.3，ADR-020） | 判定语义唯一权威 |

2. **路由一致性**：经连接器发起的业务动作与在平台直接操作**业务等效**——同一主体身份、同一校验、同一留痕、同一错误语义；连接器不得提供平台不允许的动作。
3. **框架边界**：V1.0 SDK 骨架只承载六项功能的接入框架（3.6.2），**不含**适配器实现（3.6.5 / 3.6.6）与管理界面（3.6.7）。

**验收标准**

1. 已接入连接器依次发起六类业务动作各一次（查身份 / 登记资源 / 查看产品 / 查看合约 / 发起交付 / 发起使用）→ **均受理成功**，结果与平台直接操作一致。
2. 六类动作在平台对应域产生**留痕**（与直接操作同源同要素）。
3. 经连接器发起平台不允许的动作（如以他人主体身份查询）→ **拒绝**，与平台直接操作的拒绝语义一致。

### 行为 3：身份管理功能（C-6.1）

**规则**

1. **身份查验**：连接器可查验**本所属主体**的身份信息与 DID 状态（经平台主体 / DID 域只读消费）；不可查验其他主体。
2. **DID 下游消费形态**：连接器作为 DID **下游消费方**（C-1.2 规格 V1.1 §4.5 口径），"取 DID → 验身份"为接口级消费形态；接口报文与实现归 3.6.3，**真实联调归 3.6.3 交付后另行立卡**（CHG-C-1.2-V1.1）。

**验收标准**

1. 经连接器查验本主体身份 → 返回本主体身份要素与 DID 状态（可解析、状态有效）。
2. 跨主体身份查验 → **拒绝**。
3. 平台侧可凭连接器绑定完成"取 DID → 验身份"业务查验（业务演示级；真实联调归 3.6.3 后另卡）。

### 行为 4：交付功能（C-6.1）

**规则**

1. **凭据不变**：经连接器发起交付的凭据与平台一致 = **已生效合约**（C-5.1 行为 1 口径；未生效 / 已终止 / 已完结合约不可发起，沿合约域状态门槛语义）。
2. **入口唯一**：V1.0 数据交付唯一合规通道 = **平台网关交付链**（ADR-005 / ADR-022，C-5.1 行为 2 口径）；连接器作为**需求方侧发起端**参与交付；**连接器间点对点直传不在 V1.0 范围**（§4-5）。
3. **源端取数经适配器**：连接器作为**提供方侧源端**时，交付取数经**适配器**（行为 14）完成；**先判定后取数**——策略判定未放行不触达源。

**验收标准**

1. 经连接器以已生效合约发起交付 → **受理**，产生交付记录（事件源口径沿 C-5.1，与直接发起无差别）。
2. 以未生效 / 已终止 / 已完结合约经连接器发起交付 → **拒绝**（沿合约域状态门槛）。
3. 提供方侧源端交付取数经适配器完成且留痕可查（**不含数据本体与原文**）。

### 行为 5：使用控制功能（C-6.1）

**规则**

1. **判定唯一权威在平台**：使用控制策略判定唯一权威在合约域策略引擎（ADR-019 / ADR-020）；连接器**消费判定结果**——不复制策略、不建本地第二判定点（§7 Q6）。
2. **fail-closed**：连接器对平台判定结果**只执行不裁剪**——放行则继续、拒绝即终止动作，**不得本地放行**；判定不可达时不得默认放行（沿平台 fail-closed 基调）。
3. **双向约束**：连接器场景下"策略生效放行"与"越界拒绝"双向必有（沿 AGENTS §4 双向用例硬约束；由 3.6.2 / 3.6.8 实现与测试承接）。

**验收标准**

1. 合约范围内经连接器发起使用 → **放行**（与平台直接操作一致）。
2. 越界使用（超次数 / 超期 / 用途不符 / 域外 / 再分发）经连接器发起 → **拒绝**，连接器终止动作、**无本地放行路径**；拒绝留痕含触发要素。
3. 不存在经连接器绕过平台判定的合规使用路径（服务端强制口径沿 C-5.1 §6-2）。

### 行为 6：连接器注册申请与登记（C-6.2）

**规则**

1. **两步制**（§7 Q4）：注册 = **参与方提交申请**（连接器名称 / 类型 / 版本 / 所属主体）→ **平台运营方核验**后生效（沿 C-1.1 注册-审核两步惯例）。
2. **信息完整**：申请要素（名称 / 类型 / 版本 / 所属主体）不全 → **拒绝受理**，理由业务可读，可补正重提。
3. **防重**：同主体同名连接器唯一——重复申请不重复建档；版本变更走**升级**（行为 9）而非新建。
4. **编号签发**：核验通过时平台签发**全局唯一连接器编号**（前缀与号段随 3.6.3 实施落定，本规格不定码值）；编号**终身不复用**（含注销后）。

**验收标准**

1. 要素齐全的申请 → **受理**，状态 = 待核验，登记可查。
2. 缺要素申请 → **拒绝受理**（可读理由）；补正重提 → 正常受理。
3. 同主体同名重复申请 → **提示重复**，不新建档。
4. 核验通过 → 生成唯一编号；该编号不再签发给任何其他连接器。

### 行为 7：注册核验（C-6.2）

**规则**

1. **核验三查**（§7 Q4）：① **主体资格**——所属主体已入驻（C-1.1 ADMITTED，ADR-016）；② **DID 有效**——所属主体 DID 可解析且状态有效（ADR-017）；③ **信息完整**——申请要素齐备。任一不满足 → **核验拒绝**。
2. **拒绝可读可溯**：核验拒绝给业务可读理由（哪一查不通过）+ 留痕；补正后可重新核验。
3. **核验通过**：状态转**已注册**、签发编号、建立 DID 绑定（行为 8）；核验动作全程留痕（谁核 / 何时 / 对象 / 结论）。

**验收标准**

1. 三查全过的申请核验 → **通过**：状态 = 已注册 + 编号签发 + 绑定建立。
2. 未入驻主体的申请核验 → **拒绝**（主体资格不满足）+ 留痕。
3. 主体 DID 已吊销 / 无效的申请核验 → **拒绝**（DID 校验不通过）+ 留痕。
4. 拒绝后补正重提 → 重新核验；全程留痕链完整。

### 行为 8：DID 绑定与身份核验消费（C-6.2）

**规则**

1. **绑定建立**：注册生效时建立**连接器 ↔ 所属主体 DID** 绑定记录（绑定关系与建立时间可查）；绑定随注销解除（记录保留）。
2. **下游消费**：平台侧可凭绑定完成"取 DID → 验身份"查验（C-1.2 规格 V1.1 §4.5 下游消费方口径）；本规格只定业务语义，**不定义接口报文**（归 3.6.3；真实联调归 3.6.3 交付后另卡——CHG-C-1.2-V1.1）。
3. **状态联动（fail-closed）**：所属主体 DID 状态变化（如吊销）在绑定查验中**如实反映**；DID 失效后连接器的身份类动作不得通过。

**验收标准**

1. 注册生效后绑定记录可查（连接器 ↔ DID ↔ 建立时间）。
2. 凭绑定"取 DID → 验身份"业务查验通过。
3. 所属主体 DID 吊销后，连接器身份类查验 → **不通过**（如实反映 DID 状态）。

### 行为 9：升级与版本兼容（C-6.2）

**规则**

1. **升级 = 登记动作**：连接器版本变更以**升级登记**承载（新版本号 + 兼容性声明）；V1.0 升级为平台侧登记与留痕动作，**不含运行中实例的在线热升级**（部署动作归实施）。
2. **兼容分级**（§7 Q5）：声明**兼容**的版本 → 平台侧**原子替换**版本记录并留痕（旧 / 新版本号入留痕），业务动作不中断；声明**不兼容**的版本 → **不自动替换**，须平台运营方**显式确认**后方替换；确认前旧版本继续有效。
3. **留痕可溯**：版本历史链完整可查（每次变更含旧版本 / 新版本 / 兼容性声明 / 确认人〔如走显式确认〕/ 时间）。

**验收标准**

1. 兼容升级登记 → 版本**原子替换**成功，业务动作不中断，留痕含新旧版本。
2. 不兼容升级登记 → **不自动替换**；运营方显式确认后替换生效（确认留痕齐备）。
3. 不兼容升级未经确认 → 版本保持旧值，连接器按旧版本继续有效。
4. 版本历史全链可查。

### 行为 10：注销（C-6.2）

**规则**

1. **前置检查**：注销前检查该连接器**无进行中交付作业**；存在 → **拒绝注销**并提示先完结或终止（防止"作业中途失源"）。
2. **终态不可逆**：注销后状态 = **已注销（终态）**；连接器**不可发起任何业务动作**（身份查验、交付、使用等一律拒绝）；编号**终身不复用**。
3. **历史保留**：已注销连接器的历史登记、版本、绑定与业务留痕**全部保留可查**（可追溯义务）；绑定关系解除但记录保留。

**验收标准**

1. 存在进行中交付作业的连接器注销 → **拒绝**（前置检查不通过，提示可读）。
2. 无在途作业的连接器注销 → **成功**，状态 = 已注销。
3. 已注销连接器发起任意业务动作 → **拒绝**。
4. 注销后重新注册同名连接器 → 新编号**不复用**旧编号；旧连接器历史记录保留可查。

### 行为 11：源类型范围与适配器承载（C-6.3）

**规则**

1. **四类源**（§7 Q7）：V1.0 多源适配覆盖**政务共享交换平台、数据库、对象存储、API 网关**四类源（PRD C-6.3 原文）；每类源由对应**适配器**承载（政务源归 3.6.5，三类通用源归 3.6.6），适配器随连接器分发（SDK 框架，3.6.2）。
2. **登记制**：源接入须**先登记后使用**——未登记的源不得被适配器读取（默认拒绝）。
3. **政务源 V1.0 承载形态**：政务共享交换平台 V1.0 以**标准报文模拟源**承载对接能力；**真实政务平台生产对接属部署实施期事项**（诚实声明，§6-3 / §7 Q7）。

**验收标准**

1. 四类源各完成一次接入登记 → **均受理**（四类均在适配范围内）。
2. 未登记的源发起读取 → **拒绝**（默认拒绝）。
3. 政务源演示环境为**模拟源**且如实标注（不虚称已对接真实政务平台）。

### 行为 12：源接入登记与凭据保护（C-6.3）

**规则**

1. **配置登记**：源接入登记要素 = 源类型、源地址、访问凭据、所属连接器；登记全程留痕。
2. **凭据国密保护（硬约束）**：访问凭据**不以明文展示或落库**——经 `common` 国密组件加密存储（ADR-006 / ADR-015，**全平台唯一加解密入口，禁止自行实现密码学**）；界面与记录仅显**掩码**；配置变更留痕（新旧要素，凭据仍掩码）。
3. **归属与级别**：源数据属 **CAT-07 接入的第三方数据资源**——分级与管控沿"提供方登记申报、平台复核、随来源数据级别就高"口径；源接入不改变平台既有数据分类分级义务。

**验收标准**

1. 源接入登记成功后，凭据仅以**掩码**可见（界面与记录均无明文）。
2. 配置变更（如换地址）→ **变更留痕**（旧 / 新要素；凭据仍掩码）。
3. 未登记源 / 非本连接器归属的源配置 → **不可被读取或查看**（默认拒绝，沿平台防枚举口径）。

### 行为 13：连通性自检（C-6.3）

**规则**

1. **只读探测**：源接入登记后可发起**连通性自检**——只读探测（连通 / 凭据 / 权限三查），**不产生源端数据变更**。
2. **失败原因可读**：自检失败给业务可读原因，最低覆盖三类：**网络不可达 / 凭据无效 / 权限不足**；失败留痕。
3. **自检不等于授权**：自检通过只证明"连得上"，**不构成对该源的业务授权**——实际读取仍受行为 14"先判定后取数"约束。

**验收标准**

1. 配置正确的源自检 → **通过**（只读，源端零变更）。
2. 凭据错误的源自检 → **失败**且原因 = 凭据无效（可读）。
3. 地址不可达的源自检 → **失败**且原因 = 网络不可达。
4. 权限不足的源自检 → **失败**且原因 = 权限不足。

### 行为 14：源数据读取与交付链衔接（C-6.3）

**规则**

1. **先判定后取数**：适配器读取服务于平台交付链——**使用控制判定放行后方可取数**（沿 C-5.1 行为 2"策略判定在转发之前"同构口径）；拒绝不触达源。
2. **真实源演进路径（承接登记）**：平台既有交付链取数为演示探针（3.5.2 Q4-A 登记"**真实数据源接入归连接器 3.6.x**"）——自本规格起真实源接入具备业务依据，随 3.6.5 / 3.6.6 落地、3.6.8 端到端接入演练验证；落地前交付链以 C-5.1 已交付口径为准。
3. **留痕与计量不变**：经适配器取数的交付，其交付记录 / 留痕 / 计量事件口径与 C-5.1 完全一致（统一事件源；**拒绝零计量**）。

**验收标准**

1. 合规交付经适配器自真实源取数 → **成功**，交付记录与留痕照常（不含本体与原文）。
2. 越界交付（约定外用途等）→ 判定**拒绝**且**不触达源**（先判定后取数）。
3. 适配器读取链路全程留痕可查（谁 / 何时 / 哪个源 / 哪份合约 / 结果）。

## 4. 非目标（本规格明确不做，归属包见括号）

1. **不做连接器 SDK 与服务的模型与接口实现**（表结构、端点、迁移、错误码码值、编号前缀与号段）——归 **3.6.2~3.6.4**；本规格只定义业务行为与验收标准（错误码只**预留 1010 段位**，§7 Q9）。
2. **不做适配器实现**（政务共享交换平台 / 数据库 / 对象存储 / API 网关四类适配器本体）——归 **3.6.5 / 3.6.6**；本规格只定源接入、自检与读取的业务口径。
3. **不做管理控制台界面**（连接器列表 / 健康度 / 版本管理页面）——归 **3.6.7**；剧本界面入口按"占位 + 交付后核对修订"机制处理（沿 C-5.1 剧本 Q9 先例）。
4. **不做轻量化连接器**（PRD 行 148 **C-6.4 = P1**）与**智能连接器**（V2.0 行 199 **C-6.5 = P2**，含源端元数据自动抽取、敏感数据识别与脱敏建议、接入质量自检报告）——归 V1.5 / V2.0。
5. **不做连接器间点对点直传**——V1.0 数据交付唯一合规通道 = 平台网关交付链（C-5.1 行为 2 口径）；点对点为未来演进方向，**登记不设计**。
6. **不做策略本地执行与策略下发**——使用控制判定唯一权威在合约域（ADR-019 / ADR-020），连接器只消费判定结果（§7 Q6）。
7. **不做真实政务共享交换平台的生产对接与联调**——V1.0 以标准报文模拟源承载（§7 Q7-A 诚实口径）；真实对接属部署实施期事项。
8. **不做跨机构物理"数据不出域"承诺**——该承诺依赖隐私计算（PRD C-5.3 = P1）与连接器侧部署形态演进，与 C-5.2 规格 §6-3 口径一致（3.5.1 承接划界）；本规格只定业务归属语义（§6-1）。
9. **不回改 C-1.1 入驻流程剧本与主体域实现**——连接器注册以主体已入驻为前提、独立动作（§7 Q3）；如需显式嵌入入驻流程走规格变更流程。
10. **不做计量模型、计费账单与区块链存证对接**（归 3.7.x / 3.8.x）——连接器环节只定"应产生事件"口径，事件源沿 C-5.1 交付记录，不另设第二套口径。

## 6. 边界声明

1. **"部署于参与方侧"的业务语义（诚实声明）**：PRD 术语"接入连接器部署于参与方侧"——V1.0 落地为"**连接器属主主体 + 适配源归属**"的业务归属语义与 SDK 分发形态；演示期连接器与平台同机部署（ADR-016 §2.7 仅本机可达），**本规格不承诺物理分布与网络隔离**；跨机构物理"数据不出域"承诺**不作**（见 §4-8，与 C-5.2 §6-3 划界一致——3.5.1 Q5-A 承接）。
2. **身份锚边界**：连接器不设独立 DID（§7 Q2）——设备级 / 实例级凭证体系（API Key、证书、独立 DID 文档）不在 V1.0 范围，随 3.9.1 真实令牌体系统一演进；演示期沿用平台既有身份头口径（**DB-03 信任边界沿承**，长期解除条件不变）。
3. **政务源承载形态（诚实声明）**：政务共享交换平台 V1.0 以**标准报文模拟源**承载对接能力（§7 Q7-A）；**真实政务平台生产对接属部署实施期事项**，不在 V1.0 承诺范围。
4. **真实数据源演进路径（3.5.2 承接）**：平台既有交付链取数为演示探针（3.5.2 Q4-A 登记"真实数据源接入归连接器 3.6.x"）——自本规格起真实源接入具备业务依据（行为 14），随 3.6.5 / 3.6.6 落地、3.6.8 集成演练验证；**落地前交付链行为以 C-5.1 已交付口径为准，本规格不回改交付域剧本**。
5. **三卡纪律承接汇总**：3.5.3 / 3.5.4 / 3.5.5 三卡纪律声明"不夹带连接器（3.6.x）"——本规格即为该承接的落点，连接器域行为一律在本域定义；本规格交付后 C-5.2 规格 §6-3"跨机构归 3.6.x"的指向即落在本规格 §6-1 划界上。
6. **CHG-C-1.2-V1.1 衔接**：C-1.2 规格 V1.1 §4.5 明文"连接器注册与核验服务（WBS 3.6.3）**绑用 DID，属下游消费方**，本规格不定义连接器行为"——本规格行为 3 / 8 按该口径定义绑定业务语义，**不定义接口报文**；"与连接器注册的真实联调"归 3.6.3 交付后另行立卡。变更单"3.6.3 当前未开工、无 C-6.x 规格"的前提随本规格消除（变更单历史只读不回改，销项留痕于本节与任务卡）。
7. **信通院 / 互联互通收敛义务**：连接器域涉及信通院测评 / 互联互通的实现面一律收敛 `std-adapter`（AGENTS 技术约定、ADR-008 能力域契约）；本规格只定业务行为，模块边界随实施包设计落定。
8. **资格与状态口径唯一**：连接器域不自行判定主体资格（一律以 C-1.1 ADMITTED 为准）、不自行判定产品与合约状态（一律以目录域 / 合约域为准）、不另设策略 / 计量 / 存证第二口径（ADR-019 / ADR-020 / 3.7.x / 3.8.x）。

| **Q1** | 剧本份数与四幕分布（WBS 行 300"剧本〔接入 / 注册 / 适配 / 升级注销〕"） | **A：三份剧本按规格条目各一份**——C-6.1 剧本承载"接入"幕、C-6.2 剧本承载"注册核验"+"升级注销"（S1~S3）、C-6.3 剧本承载"适配"幕；与"一条（组）规格一份剧本"惯例一致（C-1.1 / C-3.1 / C-4.1 / C-5.1 同款） | B：四份剧本按幕名一幕一份——"注册"与"升级注销"同属 C-6.2，拆成两份薄册维护面翻倍、交叉引用断链 |
| **Q2** | 连接器身份形态 | **A：连接器不另设独立身份**——以所属主体 DID 为身份锚（ADR-017），平台侧唯一连接器编号作实例标识；业务调用沿用平台既有身份口径；DID 服务对象模型零扩展 | B：每台连接器签发独立 DID——连接器成为 DID 服务新对象类型（ADR-017 变更 + 3.6.3 体量膨胀）；设备级身份的真实凭证体系归 3.9.1 统一演进，V1.0 抢跑产生第二套凭证口径 |
| **Q3** | 与主体入驻流程的关系（PRD 行 90"连接器接入"环节） | **A：连接器注册以主体已入驻为前提、作为入驻后的独立业务动作**；不回改 C-1.1 已验收入驻流程与剧本（PRD 行 90 的"连接器接入"环节由本前提检查承载）；如需显式嵌入入驻流程走规格变更流程另议 | B：回改 C-1.1 入驻流程加入连接器步骤——改动已验收剧本与审核操作面（涉变更流程），业务收益低且阻塞本卡 |
| **Q4** | 注册与核验流程 | **A：两步制**（参与方申请 → 运营方核验，沿 C-1.1 注册-审核惯例）+ **核验三查**（主体资格 ADMITTED / 主体 DID 有效 / 信息完整）；拒绝给可读理由 + 留痕 + 补正重提 | B：参与方自助注册即生效——"平台侧核验"（PRD C-6.2 原文）缺项，不可信连接器可接入；C：运营方代录入——参与方无申请入口，与"连接器部署于参与方侧"的组件归属不符 |
| **Q5** | 生命周期状态机与升级 / 注销口径 | **A：三主态 = 待核验 → 已注册 → 已注销（终态不可逆）**；升级 = 已注册态下的版本变更登记（兼容 = 原子替换留痕；不兼容 = 运营方显式确认后替换，确认前旧版本有效）；注销前置 = 无进行中交付作业；注销后编号终身不复用、历史留痕保留 | B：增设"停用 / 恢复"中间管控态——超出 PRD C-6.2 明文四动作（注册 / 核验 / 升级 / 注销）的新增管控能力，运营上确需"暂停不注销"时走规格变更补入；C：引入"升级中 / 注销中"过程态——状态机复杂化，V1.0 演示与实现面膨胀 |
| **Q6** | 使用控制与交付的执行点（连接器与平台链路关系） | **A：平台侧唯一执行**——交付统一经平台网关唯一入口（ADR-005 / ADR-022 / C-5.1 口径），策略判定唯一权威在合约域引擎（ADR-019 / ADR-020）；连接器"使用控制功能"= 携带凭据发起 + 接受并执行平台判定结果，**拒绝即终止、不得本地放行（fail-closed）** | B：连接器本地执行策略副本——需策略下发 / 同步机制，打破"判定语义唯一权威"，合规口径失真且 V1.0 体量膨胀 |
| **Q7** | 多源适配的 V1.0 承载形态 | **A：四类源全量**（政务共享交换平台 / 数据库 / 对象存储 / API 网关 = 3.6.5 + 3.6.6）；凭据经 `common` 国密组件加密存储（ADR-006 / ADR-015，禁明文）；政务源 V1.0 以**标准报文模拟源**承载（诚实声明：真实政务平台生产对接属部署实施期事项）；先判定后取数 | B：V1.0 只做三类通用源、政务源顺延——PRD C-6.3 明文列政务共享交换平台，缺项；C：本卡即要求真实政务平台直连联调——演示期不可达不可控，阻塞交付且超纯文档包边界 |
| **Q8** | 连接器健康度语义（3.6.7 健康度页 / 3.9.4 健康度监控的上游） | **A：本规格预留最小健康度语义**——在线 = 活跃 / 心跳上报未超时、离线 = 超时未上报；承载归 3.6.3（上报口径）、展示归 3.6.7、监控对接归 3.9.4；本规格只定语义不定实现 | B：本规格不提健康度——3.6.7"健康度"页面与 3.9.4"连接器健康度监控"届时无规格依据，需补规格或返工 |
| **Q9** | 错误码段位与资源命名 | **A：错误码顺延预留 `1010` 段**（1000~1009 已占用：1000 平台公共 / 1001 国密组件 / 1002 幂等锁组件+KMS / 1003 std-adapter / 1004 主体服务 / 1005 DID 服务 / 1006 空间域 / 1007 目录域 / 1008 合约域 / 1009 交付域〔3.5.1 Q8 预留〕；**`1010C` / `1010S` 全库零占用**——立卡时实测：Java 源码 + docs 全文检索，docs 侧命中仅日期字面量撞字符）；资源命名沿 ADR-005 先例随 3.6.3 设计落定；**本规格只登记业务错误语义，不占码值** | B：复用 1009 交付段（与"一域一段"惯例冲突）；C：本卡即定编号前缀与码值——属实施细节，越纯文档包边界 |
