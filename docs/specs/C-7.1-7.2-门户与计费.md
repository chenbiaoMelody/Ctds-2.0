## 1. 用户故事

- **作为需方（数据使用方）**：我在门户像网购一样浏览已上架的数据产品、看详情和价格；选中后一键订购，订单自动衔接合约签署；合约生效后我完成交付调用，月底能查到自己的计量明细和账单，账单与我的实际使用对得上。
- **作为供方（数据提供方）**：我上架的产品在门户被浏览和订购；我能查到本方产品的订购情况、计量流水与应收账单，账单金额可以逐笔追溯回每一次调用。
- **作为运营方**：我掌握全量订单、计量流水与账单；账单出账前后都能执行对账，账实不符时对账必须报警、相关账单冻结待人工澄清——资损风险被结构性拦住。
- **作为平台**：计量只消费既有事件源（网关放行事件、合约计数、交付记录），不新增第二套计数口径；免费产品不产生计费流水；一切计费语义可复算、可追溯。

## 2. 术语与角色

| 术语 | 口径 |
| --- | --- |
| **门户** | 面向平台注册主体的"网购式"产品浏览面：产品列表 / 详情 / 检索 / 订购入口（C-7.1）。V1.0 承载 = 登录后浏览（§7 Q2，已裁决采 A）；页面实现归 3.7.2 |
| **订购 / 订单** | 需方对目标产品发起的订购业务登记载体：记录需方、产品、定价快照、时点与状态；订单状态与合约状态联动（§7 Q3，已裁决采 A）。订单流程实现归 3.7.3 |
| **评价** | 已完成有效交付的需方对产品的 1~5 分评分与可选文字评价；详情页只读展示均分与评价数（§7 Q4，已裁决采 A）。评价系统实现归 3.7.4 |
| **计量 / 计量流水** | 对既有事件源（网关放行事件、合约计数表、交付记录、沙箱作业）按"合约 × 周期"聚合形成的计量记录；**事件产生口径唯一权威 = ADR-020 §2.4 / §2.8 与 ADR-022 §2.6**，本规格只消费不复制 |
| **出账 / 账单** | 出账 = 按"合约 × 出账周期"聚合计费结果生成账单的动作；账单 = 含明细可溯构成的账单记录（编号唯一、生成后不可篡改，§7 Q6，已裁决采 A）。账单生成实现归 3.7.6 |
| **对账（账单核对）** | 账单合计、计费明细合计、计量流水聚合、合约计数表口径的**交叉验证**；数据源 = ADR-020 V3 两表（counter = 余额口径 / log = 流水口径）+ 计量流水 + 账单（§7 Q7，已裁决采 A）。对账断言为本规格硬约束（AGENTS §4 / 章程行 412） |

**角色**：需方（平台注册主体，发起订购/评价、查本方订单流水账单）；供方（平台注册主体，查本方产品订购/流水/应收账单）；运营方（全量订单、计量、账单读面 + 对账复核与差异处置）。

## 3. 行为清单（业务语言）

> 编号 B1~B12；每条行为含规则（R）与验收标准（AC）。规则标注"（§7 Qx，已裁决采 A）"处为已经编排师裁决的口径落点（2026-10-31 一次确认，Q1~Q9 均采建议口径 A）。

### C-7.1 数据产品门户

#### 行为 1（B1）门户浏览准入与受众

**规则**
1. 浏览受众 = **平台全体注册主体**：登录后即可浏览全部已上架产品，浏览本身不设运营方审批环节（§7 Q2，已裁决采 A）；
2. **公开匿名浏览（未登录的互联网访问）不属于 V1.0 承诺**：V1.0 全站保持登录制；未登录访问门户页面一律引导至登录（§7 Q2，已裁决采 A）；
3. 浏览是只读动作：门户不修改目录域任何数据（上架 / 变更 / 下架仍走目录域既有流程）；
4. 浏览不产生业务资格：浏览 ≠ 入驻、≠ 订购资格、≠ 交付权（资格语义仍归 C-1.1 / C-4.x）。

**验收标准**
1. 已登录的平台注册主体（任意角色）可浏览全部"已上架"产品列表与详情，无需运营方审批；
2. 未登录状态访问门户浏览面，被引导至登录，不返回任何产品数据（负向）；
3. 门户内任意操作不改变产品目录数据（浏览前后产品列表与详情一致）；
4. 浏览记录不产生资格变化（主体状态、合约资格在浏览前后不变）。

#### 行为 2（B2）产品浏览与检索（复用目录服务）

**规则**
1. 门户的产品列表 / 详情 / 检索 = **目录服务（C-3.x）同一数据面**：门户不自建第二套目录口径、不缓存出第二事实源（§6-1）；
2. 仅展示"已上架"状态的产品：待上架 / 已下架 / 审核中产品不在门户出现；
3. 检索与筛选沿用目录域既有检索能力与口径，门户不新增检索语义；
4. 产品详情页展示产品元数据与**定价四档**（免费 / 按次 / 包月 / 交易额分成——消费 `C-3.1-2.3` 规格 §3-3 定价模型口径；免费档显式展示"免费"）。

**验收标准**
1. 门户展示的产品集合 = 目录服务同一时点"已上架"产品集合（无多出、无遗漏）；
2. 构造"待上架 / 已下架"产品各一，门户列表与检索均不可见（负向）；
3. 详情页定价展示与产品上架时登记的四档定价一致（免费档显式为"免费"，不得空缺）；
4. 门户检索结果与目录服务同一检索条件的直接查询结果一致。

#### 行为 3（B3）订购发起与订单登记

**规则**
1. 需方在门户对目标产品发起订购 → 平台生成**订单**：登记需方、产品、**定价四档快照**（沿 C-4.1 行为 2 规则 3"发起与快照"口径）、发起时点与订单状态（§7 Q3，已裁决采 A）；
2. **订购幂等**（ADR-007）：同需方对同产品存在进行中订单时，重复发起被拒绝并给出可读理由，不产生第二份进行中订单；
3. 订单创建后即衔接**合约草案发起**（消费 C-4.2 签署流程：草案锁定模板版本快照与定价口径——本规格不重复定义合约语义）；
4. **订单状态与合约状态联动，不另设独立资金流**（§7 Q3，已裁决采 A）：合约生效 → 订单"已完成（已订购）"；合约被拒绝 / 撤回 / 草案关闭 → 订单"已关闭"；订单状态变更全程留痕。

**验收标准**
1. 发起订购后生成唯一订单，订单四要素（需方 / 产品 / 定价快照 / 时点）登记完整可查；
2. 同需方同产品重复发起订购被拒，返回业务可读理由，进行中订单仍只有一份（负向 + 幂等）；
3. 订单创建后合约草案同步发起，草案中的定价口径 = 订单定价快照；
4. 合约生效后订单转为"已完成"、合约拒绝 / 撤回后订单转为"已关闭"，状态与合约一致且变更留痕可查。

#### 行为 4（B4）订单查询与留痕

**规则**
1. 需方可查询**本方**订单列表与详情（状态、关联产品与合约、关键时点）；
2. 运营方可查询全量订单（管理读面；管理界面承载归 3.7.7，本规格只定读面语义）；
3. 订单全生命周期留痕：创建、状态变更、关闭原因均可追溯；
4. **非本方订单不可读**（服务端强制归属校验，沿 C-5.1 §6-2 先例）。

**验收标准**
1. 需方订单列表仅含本方订单，详情字段完整（状态 / 关联合约 / 时点）；
2. 运营方可按产品 / 需方 / 状态检索全量订单；
3. 抽查任一订单，其状态变更均有留痕记录且时间线连续可读；
4. 以需方 A 身份查询需方 B 的订单明细被拒绝，错误信息业务可读且不暴露内部实现（负向）。

#### 行为 5（B5）产品评价

**规则**
1. **评价人资格 = 对该产品已完成有效交付的需方**：无有效交付记录的主体不可对该产品评分或评价（防刷评，负向必有）（§7 Q4，已裁决采 A）；
2. 评价内容最小口径 = **总分（1~5）+ 可选文字评价**；一人一产品一期一评（重复提交 = 更新本人既有评价，不叠加计数）；
3. 展示 = 产品详情页只读展示**均分与评价数**；文字评价展示沿最小实现（不作排序 / 精选等运营语义——归 3.7.4 设计）；
4. 评价留痕可溯（评价人 / 产品 / 评分 / 时点）；运营方可隐藏违规评价（隐藏留痕，不物理删除）。

**验收标准**
1. 已完成有效交付的需方可成功提交评价，评分 1~5 合法值校验生效（0、6 等非法值被拒，负向）；
2. 无有效交付记录的主体对该产品提交评价被拒，理由业务可读（负向）；
3. 同一需方重复提交评价，评价总数不变、本人既有评价被更新；
4. 详情页展示的均分与评价数 = 该产品全部有效评价的统计值；运营方隐藏后该评价不再计入展示且隐藏留痕可查。

#### 行为 6（B6）状态感知划界（留痕可查，不做实时推送）

**规则**
1. 订单 / 合约 / 评价相关状态变化的用户感知方式，V1.0 = **留痕可查 + 用户主动查询**（沿 3.3.4 Q6-A 口径），**不做实时推送 / 消息通道**（3.3.4 已定归 3.7.2 评估；如需改判一律走规格变更流程，本规格不私自扩）（§4-6）；
2. 订单列表 / 详情页展示的状态即为权威状态，无需用户另行核对多面数据。

**验收标准**
1. 需方通过订单列表与详情即可获知订单当前权威状态（与合约状态联动一致）；
2. 平台不产生任何站外推送承诺（规格与剧本中无推送类验收步骤——评审核对项）。

### C-7.2 计量计费中心

#### 行为 7（B7）计量事件消费与不双计

**规则**
1. **计量事件源唯一且既有**，本规格不新增事件产生点，只消费：① 交付 / 调用放行事件（ADR-022 §2.6：**放行 1 次 ≡ 计量事件 1 条**，动作名 `gateway.delivery.metering`；**拒绝 0 条**，拒绝留痕以 `gateway.delivery.denied` 独立承载不与计量混算）；② 合约使用计数与执行流水（ADR-020 V3 两表）；③ 文件交付记录（ADR-023：`delivery` 记录 = 事件源、`usage_log` = 策略计数，**两者分工不双计**）；④ 沙箱作业（ADR-024：`sandbox_job` 一行 = 一次数据使用）与沙箱导出（ADR-025：复用 `deliveries`，**单一事件源不双轨**）；
2. **模拟器与测试台不产生计量**（ADR-021：自检报告零落库，不污染使用流水对账口径）；
3. 计量消费侧**不改上游**：采集与落库不得修改网关、合约、交付任何端点 / 表结构 / 错误码（`common-logging` `AuditRecorder` 为唯一依赖点，3.7.5 落库实现替换不改网关调用点——ADR-022 口径）；
4. 计量侧不另造第三份流水：计量流水 = 对上述既有事件源的消费聚合，与合约域 V3 两表保持可勾稽（不复制、不改写其语义）。

**验收标准**
1. 对同一合约发起 N 次放行调用，计量侧可勾稽出的事件数 = N（放行 1 次 ≡ 事件 1 条）；
2. 构造越界调用被拒：计量事件数不变、拒绝留痕独立存在且不进入任何计量聚合（负向：拒绝零计量）；
3. 同一交付动作在计量流水中有且只有一条记录（交付记录、策略计数、计量流水三方勾稽不双计）；
4. 沙箱作业与导出各产生一次使用计量且不互相叠加；策略模拟器 / 测试台执行后计量流水零新增。

#### 行为 8（B8）计量模型与免费档

**规则**
1. 计量模型 = 按"**合约 × 计量周期**"把计量事件聚合为计量记录（合约维度归属清晰、周期可闭账）；
2. **免费档产品不产生计费流水**（沿 WBS-3.3.1 卡评审核勘先例），但其调用事件照常留痕进入事件源（保证对账数据源完整性）；
3. **拒绝零计量为结构性保证**（计数口径唯一权威 = ADR-020 §2.4"按调用计数：放行才 +1、拒绝零计数"；计量引用节号以 §2.4 / §2.8 为准——DB-51 勘正义务落点，禁止引用日志 `-1658` 误引的节号版本）；
4. 计量记录归属校验：非本方合约的计量记录，需方 / 供方均不可读（服务端强制，沿 C-5.1 §6-2 先例）。

**验收标准**
1. 任一计量记录可追溯至其聚合的事件明细（事件时点、动作、合约编号完整）；
2. 免费档产品的合约在出账周期内计量流水聚合的计费金额 = 0 且不生成计费明细行（但其调用事件留痕完整可查）；
3. 构造"第 1~N 次放行 + 第 N+1 次越界被拒"序列：计数表 = N、计量聚合 = N（拒绝未触碰任何计量与计数，负向）；
4. 以需方 A 身份查询需方 B 合约的计量记录被拒，错误信息业务可读（负向）。

#### 行为 9（B9）计费引擎三模式

**规则**
1. **计费依据 = 已生效合约条款 + 订购时定价四档快照**（消费 C-4.1 行为 2 规则 3 / C-3.1 §3-3 口径，本规格不重定义定价模型）；
2. 三计费模式（对齐定价四档，免费档见 B8-2）：**按次** = 计量事件数 × 次单价；**包月** = 订单周期费（订阅制，按订单周期计，非事件级）；**交易额分成** = 以合约 / 订单登记的**约定交易额 × 分成费率**计（§7 Q5，已裁决采 A：V1.0 不采集真实支付金额，支付通道对接归 C-7.3 收益分账——诚实边界）；
3. **计费可复算**：同一账单的计费结果 = 由其计量明细与定价快照重新计算的结果（同输入同输出）；定价快照变更不影响已生成账单（变更留痕只向后生效）；
4. **资金语义红线**：计费错误 = 资损 S0 场景（章程行 441）；费率 / 模式 / 快照的任何变更全程留痕；本规格不引入任何现金收支动作（无支付、无退款、无结算划拨）。

**验收标准**
1. 按次产品：账单金额 = 放行事件数 × 次单价，逐笔可溯至计量明细；
2. 包月产品：账单金额 = 订单周期费，与调用次数无关（构造调用次数差异不影响包月金额）；
3. 交易额分成产品：账单金额 = 约定交易额 × 分成费率，基数与费率均可追溯至合约快照；
4. 同一账单由任意第三方按明细 + 快照复算，结果与账单一致；定价快照变更后已出账单金额不变（负向：不得追溯改账）。

#### 行为 10（B10）账单生成

**规则**
1. **账单 = 按"合约 × 出账周期"聚合计费结果生成**：明细 = 计量流水逐条可溯；一份账单归属恰好一份生效合约（含其供需双方）；
2. **出账触发双轨**（§7 Q6，已裁决采 A）：按出账周期自动出账（默认自然月）+ 运营方手动即时出账（演示与运营处置用）；同合约同周期重复出账被拒（幂等，ADR-007）；
3. 账单字段最小集：账单编号（唯一且终身不复用）/ 关联合约与双方 / 周期 / 金额构成（分模式列示）/ 账单状态 / 生成时点；
4. **账单生成后不可篡改**：金额与明细不可修改；更正 = 另出更正单 / 红字冲正并全程留痕（原账单保持原样可查）（§7 Q6，已裁决采 A）；账单读面：需方 / 供方查本方，运营方全量（管理界面归 3.7.7）。

**验收标准**
1. 手动触发与周期触发各出账一次，两份账单的明细均可逐条追溯至计量流水，且同合约同周期第二次出账被拒（幂等负向）；
2. 账单编号全库唯一、终身不复用（含已关闭 / 冲正账单的编号）；
3. 尝试修改已生成账单的金额或明细被系统拒绝；冲正 / 更正单生成后原账单内容逐字未变（负向 + 留痕）；
4. 需方 / 供方各查本方账单完整可读；以需方 A 身份查询需方 B 账单被拒（负向，沿 B4-4 同款归属校验）。

#### 行为 11（B11）对账（账单核对）——硬约束

**规则**
1. **对账数据源 = 四方交叉验证**（ADR-020 V3 两表 + 本域两簿）：① 合约计数表（余额口径）/ ② 合约执行流水（流水口径）/ ③ 计量流水聚合 / ④ 账单合计——正常态下四方一致（ADR-020 §6："计费/对账（3.7.x）以计数表与流水表交叉验证"）；
2. **对账断言双向必有**（AGENTS §4"计费必须有对账断言"硬约束，沿 C-4.3 / C-6.1 双向用例先例）：正向 = 正常出账后对账通过；负向 = 构造账实差异后**对账必须报差异**（"账实不符必被报"，不允许静默通过）；
3. **差异处置 = fail-closed**（§7 Q7，已裁决采 A）：对账报差异 → 相关账单冻结（不得确认 / 不得进入后续确认流程）→ 运营方复核留痕 → 差异澄清前账单保持冻结；对账**不自动修数**——修数 = 人工显式处置并全程留痕；
4. 对账执行与结果全程留痕（对账时点、比对四方数值、结论、差异明细与处置人）。

**验收标准**
1. 正常出账后执行对账：四方数值一致、结论"通过"、留痕完整（正向）；
2. 构造计量流水与账单差异（演示期专用方式见对账剧本附录）：对账结论 = "差异"，差异明细可读（缺失 / 多出 / 不一致的条目可定位）（负向，双向断言）；
3. 差异未澄清期间：相关账单状态为冻结，确认与后续动作被拒且理由业务可读（负向）；
4. 全程无自动改数：差异处置前后，除显式人工留痕动作外任何数据未被修改；复核与处置全程留痕可溯。

#### 行为 12（B12）计费读面与查询

**规则**
1. 需方 / 供方可查询**本方**计量流水、账单与订单（按合约 / 周期 / 产品过滤），并可读本方合约的**对账结论与差异明细**（非本方不可读；剧本承载 = 账单核对剧本 S1）；
2. 运营方可查询全量计量流水、账单与订单，并可发起手动出账与对账（操作权限面细化归 3.7.7 设计）；
3. 读面归属校验 = 服务端强制（非本方数据不可读，沿 C-5.1 §6-2 先例）；对外错误信息业务可读、不暴露内部实现；
4. 本规格新增业务动作（手动出账、对账、评价隐藏等）的全部错误语义预留 **1011 段**错误码（§7 Q8，已裁决采 A：实测全库零占用；编号前缀与码值随实施包落定，本规格只登记业务语义不占码值——沿 1010 段先例）。

**验收标准**
1. 需方 / 供方按合约、周期、产品过滤查询本方计量与账单（含本方合约对账结论），结果完整且仅含本方数据；
2. 运营方可检索全量数据并发起手动出账与对账，操作留痕；
3. 非本方计量 / 账单 / 订单的读取一律被拒（三类各一负向抽查），错误信息无内部实现细节；
4. 本规格登记的业务错误语义清单完整（1011 段预留声明），全库实测无 1011 开头错误码占用（立卡时实测留痕）。
