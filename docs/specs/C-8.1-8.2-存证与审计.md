## 1. 用户故事

- **作为监管方（平台审计视角）**：我能看到授权、合约、交付、使用四个环节的存证是否齐备、是否上链、核验结论是什么；任一笔业务单据我都能从存证记录追溯到业务留痕，形成完整时间线；我能按条件导出一份审计报告交给检查人员。
- **作为运营方**：链上存证自动发生，我不需要手工操作；上链失败不会丢失、不会被静默吞掉，失败项与待上链项在我这里一眼可见并可重试处置；我没有任何"补录/修改/删除存证"的入口。
- **作为需方 / 供方**：我的合约签署与每一次交付、使用都留下可核验的证据；证据里不包含数据原文与个人信息。
- **作为平台**：存证只消费上游既有事件源（合约存证事件、交付记录、计量流水、空间授权留痕），不新增第二套业务口径；链实现可替换，换链只改适配器。

## 3. 行为清单（业务语言）

> 编号 B1~B8；每条行为含规则（R）与验收标准（AC）。B1~B4 归 C-8.1（存证），B5~B8 归 C-8.2（审计）。

### C-8.1 区块链存证

#### 行为 1（B1）存证事件模型与四环节覆盖

**规则**
1. 一条业务动作对应一条存证事件（不遗漏、不重复）；存证事件六要素齐备：存证编号 / 环节类型 / 业务单据号 / 主体标识（DID 摘要）/ 操作类型 / 事件时点，另含内容摘要与存证状态（§7 Q3，已裁决采 A）；
2. **环节类型值域封闭** = 授权 / 合约 / 交付 / 使用四类，不设第五类；
3. 四环节事件源**只消费**上游既有口径，不新建第二套业务事实：授权 = 空间成员准入与空间数据使用授权留痕（C-2.x）；合约 = `contract_attestation` 存证事件（C-4.1 行为 3 规则 5）；交付 = 交付记录（C-5.1 行为 2 规则 6 / §7 Q4·Q7，已裁决采 A）；使用 = 使用控制放行/拒绝留痕与计量流水（C-4.3 / C-7.2，拒绝零计量沿 ADR-020 §2.4）；
4. **上链范围白名单**（ADR-004 §3-3）：只允许内容摘要 + 最小元数据（业务单据号、时间戳、操作类型、主体 DID 摘要）；原文 / 个人信息 / 商业密文 / 密钥材料一律禁止上链，白名单外上链按 **S0 事件**处置（ADR-004 §4 风险③）。

**验收标准**
1. 四个环节各发生一次业务动作后，各可查到 1 条对应存证事件，环节类型与业务单据号可读（B1-1）；
2. 任一存证事件可读出六要素 + 内容摘要 + 存证状态；存证编号全局唯一、终身不复用（B1-1）；
3. 抽查任一存证事件的存证内容，**不含**数据原文、个人信息、商业密文与密钥材料；元数据只含白名单四项（B1-4，负向）；
4. 存证事件不新增业务判定：同一业务事实的存证记录与上游留痕（合约存证事件 / 交付记录 / 计量流水）单据号逐字一致（B1-3，观察点）。

#### 行为 2（B2）存证写入与幂等

**规则**
1. 业务动作成功后应产生存证事件；**存证与业务解耦**：上链失败不回滚业务动作，但失败必须以"待上链 / 上链失败"状态显式可见，不得静默丢失（§7 Q4，已裁决采 A；fail-visible）；
2. **幂等**：同一环节类型 + 同一业务单据号 + 同一操作类型只产生一条存证事件；重复触发 / 重试不产生重复事件（沿 ADR-007 幂等口径）；
3. 存证状态机 = 待上链 → 已上链 / 上链失败；失败可重试，状态流转全程留痕（时点 / 结果 / 操作人）；
4. 已生成的存证事件**不可修改、不可删除**：只允许状态推进与重试追加留痕（§7 Q5，已裁决采 A）。

**验收标准**
1. 同一业务单据重复触发存证，存证事件条数不增加（B2-2，负向 + 幂等）；
2. 上链失败后，该存证事件状态 = 上链失败且可查、可重试；重试成功后状态推进为已上链并留下两次状态记录（B2-1 / B2-3）；
3. 系统不存在"删除存证""修改存证内容"的业务入口；越权调用一律被拒（B2-4，负向）；
4. 存证状态流转记录可读出每步时点与结果，无空窗（B2-3）。

#### 行为 3（B3）链上核验

**规则**
1. 核验 = 按存证编号或业务单据号定位存证事件，重算内容摘要并与链上记录比对；结论三态 = **通过 / 不一致 / 未上链**，必须显式给出，**不允许默认通过**（§7 Q5，已裁决采 A）；
2. 结论为"不一致"时必须显式报告并可定位（存证编号 / 业务单据号 / 期望摘要 / 实际摘要 / 核验时点），不得降级为"通过"；
3. 核验动作留痕：核验人 / 时点 / 对象 / 结论；
4. 链上核验的技术承载 = `EvidenceGateway.verify`（3.8.2）；本规格只定业务口径，不定实现。

**验收标准**
1. 正常存证事件核验结论 = "通过"，核验人与时点落库可查（B3-1 / B3-3）；
2. 摘要被改动后再核验，结论 = "不一致"且差异项可读（B3-2，负向，双向断言）；
3. 未上链（待上链 / 上链失败）的存证事件核验结论 = "未上链"，并提示当前存证状态（B3-1，负向）；
4. 核验不改变存证事件内容与业务数据（观察点：核验前后业务数据逐字一致）。

#### 行为 4（B4）存证异常与失败处置

**规则**
1. 上链失败 / 超时 / 链不可达：状态置"上链失败"，保留未上链事实与原因摘要，**禁止吞异常**（章程"禁止吞异常"）；
2. 待上链与失败数量、失败原因、最近失败时点在审计视图可见（消费 B5）；
3. 失败处置 = 重试或人工登记处置结论；处置全程留痕；
4. **不提供"补录假存证 / 伪造链上交易标识"的通道**；链上事实只能由真实上链产生（诚实边界）。

**验收标准**
1. 制造一次链不可达，存证事件状态 = 上链失败且原因摘要可读（B4-1）；
2. 审计视图可读出待上链数与失败数，且与存证事件实际状态一致（B4-2）；
3. 重试成功后状态推进，失败与重试两条记录均保留（B4-3）；
4. 系统无"手工填写链上交易标识"入口（B4-4，负向）。

### C-8.2 合规审计

#### 行为 5（B5）监管审计视图

**规则**
1. 受众 = 监管视角角色（V1.0 由运营方治理档承载，§7 Q6，已裁决采 A）；三员分立与外部监管账号归 3.9.2；
2. 视图内容：① 四环节存证总览（按环节 / 时间窗 / 主体 / 业务单据号过滤）；② 异常项（待上链 / 上链失败 / 核验不一致）；③ 单笔业务全链时间线（存证事件 + 业务留痕）；
3. 视图**只读**：不提供修改 / 删除 / 补录 / 重放存证入口；
4. 越权访问一律拒绝，且错误口径防枚举（同码同文，沿 ADR-016 §2.6 / C-7.2 B12-3 先例）。

**验收标准**
1. 监管视角角色可读四环节存证总览与异常项（B5-2）；
2. 按业务单据号可定位到唯一存证事件并展开全链时间线（B5-2）；
3. 视图无任何写动作入口（B5-3，负向 + 观察点）；
4. 非监管视角角色访问被拒，且与"对象不存在"同码同文（B5-4，负向）。

#### 行为 6（B6）日志调阅

**规则**
1. 调阅对象 = 既有留痕（存证事件 + 各域业务留痕 + `common` 结构化审计事件），**只读、不复制入库、不建第二事实源**（§7 Q7，已裁决采 A）；
2. 调阅条件：业务单据号 / 主体标识 / 时间窗 / 环节类型，至少一种；无条件全量导出不提供；
3. **调阅动作本身留痕**：调阅人 / 时点 / 条件 / 返回条数 / 结论用途；
4. 调阅结果不含敏感原文与个人信息（脱敏口径沿 `common/logging` 审计契约：键 ≤20 字符、值 ≤512 字符并标记截断）。

**验收标准**
1. 以业务单据号调阅：可读出该笔业务的存证事件与各环节留痕，时间线连续（B6-1）；
2. 无条件全量调阅请求被拒（B6-2，负向）；
3. 每次调阅生成一条调阅留痕，含调阅人 / 时点 / 条件（B6-3）；
4. 调阅结果中不出现数据原文与个人信息（B6-4，负向 + 观察点）。

#### 行为 7（B7）审计报告导出

**规则**
1. 报告要素：报告编号（唯一）、生成人、生成时点、统计范围与口径（时间窗 / 环节 / 主体 / 产品 / 合约）、存证清单、核验结论汇总、异常项清单；
2. 报告**生成后不可篡改**：报告内容摘要随报告登记，可后续核验；更正要走"重新生成新编号报告 + 更正说明留痕"，不得覆盖原报告；
3. 导出动作留痕（导出人 / 时点 / 范围 / 报告编号）；导出内容不含原文与个人信息；
4. 形态 = **CSV / JSON**（零新依赖，§7 Q8，已裁决采 A）；PDF / 报表模板归 3.8.4 评估。

**验收标准**
1. 指定范围生成报告成功，报告要素齐备且编号唯一（B7-1）；
2. 报告内容与同条件审计视图读数一致（存证清单条数 / 核验结论分布逐项一致，B7-1）；
3. 重复生成不覆盖既有报告，每次生成新编号并留痕（B7-2 / B7-3）；
4. 非监管视角角色导出被拒（B7-4，负向）；导出文件不出现原文与个人信息（负向）。

#### 行为 8（B8）审计读面归属、留存与合规边界

**规则**
1. **归属校验**：监管视角角色可读全量；需方 / 供方的本方证据读面若开放，归 3.8.4 评估；跨方一律拒（同码同文）；
2. **留存**：审计数据（存证事件 + 调阅与导出留痕）留存目标 ≥6 个月（等保惯例）；V1.0 承载 = 本地库 + 按天滚动文件；集中日志平台与留存期限配置 = 缺口 **G-07**（部署期立项），未闭环前对应管控标注"待生效"，不虚报已满足；
3. **不可删除**：业务侧与运营侧均无删除 / 归档清除审计数据的入口；数据清理只允许部署期运维按留存策略执行并留痕；
4. **诚实边界**：自建链公信力弱，V1.0 不以存证单独承担对外出证责任（ADR-004 §4 风险①）；出证增强（司法鉴定 / 公证）归 V1.5。

**验收标准**
1. 归属校验双向：监管角色全量可读、跨方访问被拒且同码同文（B8-1）；
2. 系统无删除审计数据入口（B8-3，负向 + 观察点）；
3. 规格与剧本明示留存与公信力边界，未出现"多长期限已满足""可对外出证"类承诺（B8-2 / B8-4，观察点）。

## 6. 边界声明

1. **不重复定义上游口径**：合约存证事件、交付记录、计量流水、空间准入留痕的字段与语义一律以上游规格为准；本规格只定义"存证事件如何引用它们"；
2. **存证 ≠ 业务事实源**：存证是证据层，业务事实仍以上游域数据为准；存证缺失不得反向修改业务数据；
3. **存证与业务解耦**：上链失败不回滚业务，但失败必须可见（fail-visible），不得出现"业务成功且存证静默丢失"；
4. **链不可删除特性**：上链数据不可删除（ADR-004 §4 风险③），因此白名单是唯一防线；白名单外上链按 S0 处置；
5. **公信力诚实边界**：自建链单独存证不足以对外出证，V1.0 不承诺司法采信（V1.5 增强）；
6. **留存边界**：≥6 个月为等保惯例目标；V1.0 未配置集中日志与留存期限（G-07），对应管控标注"待生效"；
7. **角色边界**：V1.0 监管视角由运营方治理档承载；外部监管机构账号、三员分立归 3.9.2；
8. **错误码边界**：本规格只登记业务错误语义，**预留 1012 段**（立卡实测 Java + docs 双查零占用；码值随实施包落定），不新增权限点与端点。
