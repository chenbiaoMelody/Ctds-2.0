## 1. 动机（为什么要改）

hifi §5-2 定义了三个交付请求头（`X-Ctds-Contract-No` / `X-Ctds-Purpose` / `X-Ctds-Territory`），但**未定义非 ASCII 取值（中文策略要素）的传递编码**。真链走查暴露出该缺口的两个实测事实：

1. **真机不可传递**：非 ASCII 头值被安全防火墙拒绝（实测 500，异常 `ServerExchangeRejectedException`，非受控 4xx/拒绝语义）→ 演示口径下中文策略要素（如"风控建模"/"本市域"）**无法经交付链送达判定**；
2. **测试侧哑绿**：T5 用例以中文头构造请求时，被测试内嵌 Netty **编码为 ASCII `?`** → stub 判定不比对要素 → 用例"通过"但未真实覆盖（假绿）。

即：**契约缺口**导致"中文要素传递"既无约定、也无真实覆盖。按红线 4 精神走查段零夹带修复，本单为缺口补全的正式变更流程入口。

## 2. 变更项清单

| # | 变更项 | 落点 | 代码影响面 |
| --- | --- | --- | --- |
| 1 | **要素头取值约定 = URL 百分号编码（RFC 3986）**：`X-Ctds-Purpose` / `X-Ctds-Territory` 的取值由调用方按百分号编码（UTF-8）后发送；纯 ASCII 且不含 `%` 的值可不编码（编码后等价）；**空值/缺失 = 未声明**（口径不变） | hifi §5-2 表下新增约定条目 | 网关 `DeliveryCredentialGlobalFilter`（接收侧**解码**） |
| 2 | **接收侧解码口径**：网关在凭据解析过滤器内对两要素头执行百分号解码（UTF-8）；**解码失败**（非法百分号序列 / 非法 UTF-8）→ **400 + `1000C0001`**（平台公共段"参数非法"，common 既有码；不扩张 `1009C0001` 语义、不新增码位）；解码后送往判定的值 = 业务原值（判定语义零变更） | hifi §5-2 + §7 复用表补注 | 同上（错误码常量引用 `common-errorcode`） |
| 3 | **测试口径补注（T5 哑绿修复）**：测试构造非 ASCII 要素头时必须**显式百分号编码**（不得依赖内嵌容器自动编码）；断言 stub 判定**收到解码后原值**；新增"注入非法编码 → 400 + `1000C0001`"负向用例 | hifi §9 T5 行补注 | 网关集成测试（T5 及新增负向 1 例） |
| 4 | **边界登记**：解码后要素值长度上限 **≤256 字符**（超限 → 400 + `1000C0001`；防超长头注入）；理由 = 要素值域为封闭目录短词，256 足够且对齐 header 安全实践 | hifi §5-2 | 同上 |
| 5 | **版本与留痕**：hifi V1.0 → **V1.1**（版本头 + 末节变更记录）；本变更单存档 `docs/tasks/` | hifi 头部 | 无 |

## 3. 技术影响评估（章程 §7.4 第 3 条三项核查）

| 核查项 | 结论 |
| --- | --- |
| 是否影响已通过测评的接口 | **否**——无端点/字段/错误码码值/状态枚举变化；**改变的是"头取值的编码约定"**（此前未定义）；纯 ASCII 调用方（含既有走查脚本）行为不变 |
| 是否影响合约/计费等资金语义 | **否**——判定输入值 = 解码后原值，`1008C0020` 等判定结论与计量口径零变更 |
| 是否需要数据迁移 | **否**——零库表/零迁移 |
| 安全影响 | **正向**——① 消除"非 ASCII 头被防火墙 500"的非受控形态；② 解码失败为受控 400；③ 长度上限收敛超长头 |

## 6. 分级判定论证（为何是 B 级而非 A 级）

| 章程 §7.1 判据 | 本次情形 | 结论 |
| --- | --- | --- |
| **A 级** = 需求变更（**改变验收标准 / 接口 / 数据模型**） | 行为 2 规则 4/5 与验收标准一字未改；无端点/字段/数据模型变化；**头名、头语义、判定面全部保持** | **不成立** |
