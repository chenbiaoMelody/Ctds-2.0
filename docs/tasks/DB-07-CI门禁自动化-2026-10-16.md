## 一、范围与设计

- **做什么 / 不做什**：做 = 把 README 预留给 CI 的"切换接口"接通（流水线执行 `run-gates.ps1` + 按退出码判定）+ 结论三形态回写 + gateSelfTest 随接入启用（配置注记的既定条件）；不做 = 门禁脚本改造 / 阶段拆分并行 / Linux 迁移 / E2E 与 dependencyScan 接入 / 分支保护设置 / 新依赖 / 任何阈值与阶段范围变化。

**立卡前素材盘点（只读，本会话实测）**：

| 项 | 结论 |
| --- | --- |
| ① CI 现状 | `.github/` 不存在（Test-Path False + `git ls-files .github` = 0 条）——DB-07 现象复验成立 |
| ② 门禁运行器契约 | README §"这是什么"明文 D-3 切换接口预留（流水线执行脚本 + 检查退出码）；实测脚本：报告目录不存在则自动创建（L758-760，CI 新鲜克隆可用）、JAVA_HOME 环境变量优先（L301-302，setup-java 可注入）、mvn 经 `cmd.exe` 定位（Windows 专用） |
| ③ Windows 依赖面 | `$env:TEMP`（L87/L668）、`taskkill /T`（L111）、`cmd.exe`（L335）、config `toolchain.javaHome = C:\Program Files\Java\jdk-17`、sast 段 `%TEMP%` 源集副本（L668）——**runner 必须 Windows**（否则 = 门禁脚本变更，红线 3） |
| ④ 阶段与预算 | 19 阶段（14 enabled / 5 PENDING）；单 job 全量 CI 侧预估 ~60~100 分钟（unitTest 本地 850~900s + coverage 1800s 预算 + mutationTest 1800s + 前端 ~120s + sast 900s），GitHub 单 job 6h 上限内；**CI 硬件慢于本机的超时风险如实预登记**（首跑观测；若触预算 → 走门禁变更流程调预算，不私自放宽） |
| ⑤ gateSelfTest 启用条件 | config 该段注记明文"未接入 CI 前固定 PENDING…WBS-2.2.9 接入 CI 后改 enabled=true"——**本卡即该条件的达成时点**；**（2026-10-16 勘误）** 立卡段原写"启用后每轮门禁多跑 selftest.ps1"系**未验证假设**——运行器无 gateSelfTest 执行器（冲突证据链见开发日志 `-2022`）；经编排师裁定 C，本卡内含执行器落地（hifi §3-bis）；selftest 全量实测 **32 秒**（15 场景 94 断言，只写 `%TEMP%`） |
| ⑥ 依赖解析 | 本地走用户级 `%USERPROFILE%\.m2\settings.xml`（阿里云镜像）；CI runner 无该文件 → 直连 Maven Central（境外基础设施可达；镜像是国内网络优化，不为 CI 新增 settings 文件） |
| ⑦ 前端工具链 | `frontend/package.json` **无 engines 声明**（Node 版本未钉）；workflow 以 setup-node 显式钉版本（建议 20 LTS）；本地/CI 版本漂移风险登记观察项（不在本卡改 package.json） |
| ⑧ 秘密面 | 门禁全程零秘密需求（演示密钥仅走查期用、不入门禁）；workflow 仅用自动注入的 GITHUB_TOKEN——**零 repository secret**；workflow 文件自身受 secretsScan 扫描（入库即扫，零秘密设计自证） |
| ⑨ WBS 锚点 | 行 178 = 2.2.2 CI 流水线（预算 1 会话）；门禁文档引用的 2.2.7/2.2.9 行号在 WBS 不存在（2.2 段仅 6 行）——呈报编排师裁定是否补行，本卡不擅自改 WBS |
| ⑩ 先例 | DB-43（门禁可观测性）：门禁变更流程四件套（ADR-018 修订记录 + changeLog + ConfigSha256 基线 + 编排师确认）；DB-48（前端测试参数）：免设计小卡先例——本卡规模介于两者之间，取两级设计 |

**设计要点摘要（供快速表决）**：

1. **单 job 全量**：一个 job 跑 `run-gates.ps1` 全阶段（零门禁改动、结论单一、退出码即 PR check 结论）；concurrency 同 ref 取消在跑旧任务；
2. **触发**：`pull_request`（opened/synchronize/reopened，全分支）+ `push`（仅 main）+ `workflow_dispatch`（手动）；
3. **runner**：`windows-latest` + `setup-java`（temurin 17）+ `setup-node`（20）+ runner 自带 Docker（sast 与 Testcontainers 需要——**首跑实证可用性**；不可用则环境性 ERROR 如实定性，不伪造绿灯）；
4. **结论三形态**：job 摘要（`$GITHUB_STEP_SUMMARY`）+ PR 评论（`actions/github-script`：退出码语义 + 五态计数 + RunLabel + ConfigSha256）+ artifact 上传报告目录（CI 上 `scripts/gates/reports/` 为临时产物，取回供第三方复核）；
5. **gateSelfTest 随接入启用**（配置一位 + 变更流程四件套——config 注记的既定条件，非新增决策）；
6. **分支保护建议**（编排师在 GitHub 设置开启 require status checks）——呈报不代设。
