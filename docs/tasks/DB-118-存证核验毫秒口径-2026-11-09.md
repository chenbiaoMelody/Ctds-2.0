# DB-118 缺陷卡：存证核验毫秒口径不一致导致误报"不一致"（2026-11-09）

| 项 | 内容 |
| --- | --- |
| 来源 | **WBS-3.8.5 验收走查发现**（编排师 2026-11-09 提交界面截图：存证核验 `EV20261107000005` 返回"核验结论：不一致"）；取证 `build-output/w385-verify-precision-2026-11-09.txt`；日志 `docs/logs/Ctds-项目开发日志-26-11-09-2151.md`；台账行（本卡登记 = DB-118） |
| 级别与性质 | **S2 缺陷修复**（功能正确性 / 数据口径一致性；无越权、无数据泄漏、无数据破坏）。**免两级设计声明**（AGENTS §4：S2 缺陷修复可免设计）：本卡以"业务可读行为清单 + 边界值 + 验收标准"替代两级设计，理由 = 修复面为单一入口规范化，不改摘要契约、不改接口出参、不改界面；如编码中发现需触碰摘要契约或存储列类型，**停止并回到变更流程** |
| 缺陷现象 | 对**从未被篡改**的存证记录执行核验，返回 `conclusion = MISMATCH`：`expectedDigest` 与 `actualDigest = localDigest` 不等（实测 `EV20261107000005`：expected `0e2cbe80…d2ed` / actual=local `003561eb…02c8`，链上载荷与库中摘要一致）；同批 `EV20261107000003` / `EV20261107000004` 核验 = PASS |
| 根因（已复算确认） | ① 上游事件时点携带**亚毫秒（微秒）**精度（如 `15:02:42.8665xxZ`）；② `EvidenceDigests.occurredAtIso` 用 `yyyy-MM-dd'T'HH:mm:ss.SSS'Z'` 对亚毫秒**截断** → 摘要输入取 `.866`；③ `JdbcEvidenceRepository.toLocal`（`LocalDateTime.ofInstant(instant, UTC)`）保留微秒，列 `datetime(3)` 对小数秒**四舍五入** → 落库 `.867`；④ `EvidenceVerifyService` 以读回的 `.867` 复算 → 与写入期 `.866` 的摘要不等 → 误报。**凡亚毫秒 ≥ .0005 的记录将永久误报**（演示数据 6 条中 1 条命中：全毫秒窗口扫描仅 `.866` 复算得库中摘要） |
| 影响面 | 审计核验对未篡改数据给出"不一致"红结论，并推高审计总览 `mismatchCount`；影响审计可信口径。前端（WBS-3.8.5）为原样渲染，**非本缺陷来源** |
| 范围（做 / 不做） | **做**：`services/evidence-service` 入参时点规范化（截断到毫秒），使「摘要输入 = 落库值 = 出参」同一口径；补红相单测与边界用例；既有用例零回归。**不做**：不改摘要规范字符串、不改接口出参结构、不改前端、不升级 `datetime` 列精度、不在本卡自动改历史数据（见"历史数据处置"） |
| 修复方案 | **采纳 A（最小）**：`EvidenceRules.occurredAt(...)` 返回前 `truncateTo(ChronoUnit.MILLIS)`——摘要（`.SSS` 截断语义）、落库（`datetime(3)` 四舍五入）、出参三处统一为毫秒。**不采纳 B**：列升 `datetime(6)` + 摘要改微秒格式——改动摘要契约（第三方复算口径）与迁移面，风险 > 收益 |
| 行为清单（验收可读） | 1) 上游送 `…42.8665xxZ` → 存证入库时间显示 `…42.866Z`，核验 = **通过**；2) 送 `…42.866000Z`（整毫秒）→ 行为不变；3) 送 `…42.9999xxZ` → 截断 `…42.999Z`（不四舍五入到下一秒）；4) 送 `…42.000499Z` → 截断 `…42.000Z`；5) 事件时点未来/过早校验与错误码**不变**（仍 1012C0002）；6) 摘要规范字符串、接口出参字段与前端展示**不变** |
| 验收标准 | ① 复现用例先红后绿（构造微秒输入 → 摘要与落库一致、`verify` = PASS）；② 边界用例覆盖行为清单 1~6；③ evidence-service 既有 42 例 + 全仓相关用例零回归；④ 行覆盖 ≥70%（evidence 域 ≥80%）、checkstyle 0 违规、全仓门禁单发 GREEN（ConfigSha256 与基线一致，本卡不改配置）；⑤ 4 视角评审循环 ≤3 轮，零未处置 P1/P2；⑥ 编排师验收；⑦ 剧本是否需更新须回答（预期：C-8.1 / C-8.2 **无需更新**，无界面与判定变化） |
| 历史数据处置（**需显式授权，默认不动**） | 修复只防新增；已写入的历史行（如 `EV20261107000005`）其摘要按旧 `.866` 计算、落库 `.867`，修复后仍会 MISMATCH。三选项待编排师裁定：**①** 保留为历史差异并在交付说明/剧本说明中明示（零数据改动，推荐先做）；**②** 授权一次性把该行 `occurred_at` 改为 `.866`（或按新口径重算 `content_digest`）——**改演示数据须显式授权**，不得由 AI 自行执行；**③** 演示库清理重建（随 4.2.1 真链前统一处理） |
| 可观测证据 | 修复前：`POST /api/v1/evidence/records/EV20261107000005/verify` = MISMATCH（expected ≠ actual=local）；修复后新建一条带微秒的事件 → 核验 PASS 且库中时间为截断毫秒 |
| 关闭条件 | ① 上述验收标准 ①~⑥ 全达成；② 台账 DB-118 转"已关闭"并注明历史数据处置选项；③ 交付说明含"业务可读总结（缺陷是什么 / 已怎么修 / 历史数据如何处理）"；④ 合并须编排师显式指示（验收通过 ≠ 合并授权） |
| 分支（建议） | `fix/DB-118-存证核验毫秒口径`（自本地 `main` 梢开立；不推 `main`） |
| 关联 | 规格 `docs/specs/C-8.1-8.2-存证与审计.md` **B3-1**（核验三态）/ **B3-2**（不一致可定位）；实现 `services/evidence-service/src/main/java/com/ctds/evidence/domain/EvidenceDigests.java`（`.SSS` 截断）、`domain/EvidenceRules.java`（时点入口）、`infrastructure/JdbcEvidenceRepository.java:225-231`（`toLocal`）、`application/EvidenceWriteService.java:85-91`、`application/EvidenceVerifyService.java:58-72`；迁移列 `datetime(3)` |
