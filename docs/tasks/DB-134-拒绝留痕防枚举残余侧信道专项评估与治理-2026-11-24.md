**现有可复用能力**：

- `common/logging` 的 `AsyncFileAuditRecorder`：有界队列、后台线程、不阻塞、不抛错，但队列满或文件失败会丢弃并告警；`JdbcMeteringAuditRecorder` 仅处理计量白名单，不能直接承载目录拒绝留痕。
- `common-auth` 已传递依赖 `common/logging`，目录服务运行期已有 `AuditRecorder` 通道；但 `catalog-service` 生产主源当前没有调用它做对象拒绝留痕。
- 网关已有主体 + 接口级进程内令牌桶；无对象级、动作级限流，且多实例各自计数。
- `common/idempotency` 面向请求结果幂等，缓存失败会 fail-closed，不能直接当作拒绝审计去重组件。

**测试现状**：现有用例锁定“非属主恰 1 行、不存在 0 行、封套一致”，未覆盖耗时分布、审计写失败、重复探测窗口与限流。

## 三、业务方案与决策点

| 编号 | 方案 | 业务收益 | 业务代价 / 残余风险 | 规格影响 |
| --- | --- | --- | --- | --- |
| Q1-A | **等强同步审计**：存在与非存在均经过同一审计入口；按主体 + 对象 + 动作去重；超限统一 429；审计故障两态同形 | 审计完整性最高；关闭故障出站差；重复探测写放大受控 | 猜测不存在的 id 也会留痕；需迁移 / 新表设计；查询本身仍有极小耗时差 | 复核后预计无需改规格，但需 PO 确认“猜测也留痕”的业务语义 |
| Q1-B | **异步优先**：复用公共非阻塞审计，后台异步落审计表 | 请求不等数据库；审计故障不再改变响应 | 队列满 / 停机可能延迟或丢失；页面留痕变最终一致；仍需审计猜测 id 才能对齐入口 | 需先评估并批准规格 / ADR 补充 |
| Q1-C | **最小缓解**：保留同步数据库留痕，仅加去重与对象级限流 | 改动较小；降低写放大与高频探测 | 审计写入故障仍可能出现 500 / 400 差异；DB-134 只能部分关闭 | 预计无需改规格 |
| Q1-D | **显式接受残余风险**：不改生产代码，仅补风险说明与监控建议 | 零业务回归面 | 时序、写放大、故障差异继续存在 | 无需改规格；需 PO 显式接受并限定适用范围 |

### 7.5 高风险点自查

- **并发**：应用层同 key 计数同步；数据库唯一键跨实例兜底；并发用例验证恰一条审计。
- **事务**：成功路径事务不变；拒绝审计沿用仓储写入口，审计异常仅捕获用于回滚限流预留，随后原样上抛、不吞并不降级。
