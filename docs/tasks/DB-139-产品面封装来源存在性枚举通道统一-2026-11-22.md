## 一、范围与设计要点（立卡段）

- **业务目标一句话**：把产品封装（W8）对"这不是你的资源 / 不存在的资源"两种情况的提示统一为单一口径（建议与资源域 DB-132/DB-135 同一字典：**400 + `1000C0003` + 资源不存在**），消除"持产品创建权限者用 404/403 差异探测资源 id 是否存在"的同型枚举通道——DB-135 在资源域写面关闭的通道，本卡在产品封装面关闭。
- **与 DB-135 的两点性质差异（如实标注，不影响手法同型）**：① DB-135 是"规格 B3-R2 已规定统一口径、实现残余偏差"的**符合性修复**；本卡规格只要求"被拒绝且留痕"、未规定出站码——属**规格内设计自由度向反枚举方向的收敛**（规格零改动）。② DB-135 改造的是资源本身的属主操作（update/cancel）；本卡改造的是**产品域动作引用资源域对象**的来源检查——留痕落点（资源域 `dataset_action_log` + DENIED_CREATE）与"封装前提=本人"业务规则（行为 3 规则 1）保留，仅出站口径统一。
- **改造面极小、但边界重要**：真正的改造分支只有 `create` 来源检查段两处（`:104-107` 不存在 / `:108-119` 非属主），但 `1007C0006` 同时服务**入驻资格门槛、资源登记门槛、产品面其他消费点**（另一语义/待划界），`1007C0005` 同时服务**治理读面**——设计必须先画清"仅封装来源检查改、其余零变化"的隔离线（DB-135 同款隔离手法）。
- **不新增错误码**：Q1-A1 情形复用平台公共码 `1000C0003`（`ErrorCodes.RESOURCE_NOT_FOUND`）与资源域文案常量；HTTP 400 由全局处理器按 `ErrorType.CLIENT` 落定；文案为服务端常量（禁止拼接用户输入，章程 4.3）。
- **验收基准已固定**：规格行为 3 AC（:96-97）字面 + Q1 裁决口径即本卡验收基准；规格与剧本正文均不改。
- **首动作（设计段）**：读本卡 → 复读规格行为 3（:82-99）+ 行为 6 规则 1（:157）+ 台账 DB-139 行 → 复读 `ProductCommandService.create` 全链 + `CatalogExceptionHandler` 映射 + 既有测试两态断言锚点 → 产出 lofi/hifi V0.9 → 提请一次确认。
