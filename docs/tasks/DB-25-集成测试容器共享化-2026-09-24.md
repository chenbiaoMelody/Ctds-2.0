## 一、技术方案（编码契约）

### 1.1 支撑类（每模块一份，不进 main 源集）

```java
package com.ctds.<service>.support;   // 测试源集内；ArchUnit LayerRulesTest 已 DoNotIncludeTests，不受分层规则约束

/** DB-25 共享容器：模块内 JVM 级单例，首次访问启动，进程退出由 Ryuk 回收（Testcontainers 官方单例容器模式）。 */
public final class SharedMySqlContainer {

    private static final MySQLContainer<?> CONTAINER = new MySQLContainer<>("mysql:8.0")   // 显式标签，ADR-010 §3.2
            .withDatabaseName("ctds_bootstrap");

    private SharedMySqlContainer() {
    }

    /** 共享容器（首次调用启动；后续调用返回同一实例）。 */
    public static synchronized MySQLContainer<?> container() { ... }

    /** 把共享容器连接参数（指定库名）注入测试上下文；库不存在则创建——库名隔离 = ADR-010 §3.6。 */
    public static void register(final DynamicPropertyRegistry registry, final String database) { ... }

    /** 指定库名的 JDBC URL（库不存在则创建）；纯 JUnit 用例（无 Spring 上下文）直接使用。 */
    public static String jdbcUrlFor(final String database) { ... }
}
```

**关键点**：
- `disabledWithoutDocker` 语义**保持不变**：各测试类保留 `@Testcontainers(disabledWithoutDocker = true)` 类注解，Testcontainers JUnit 扩展的 `ExecutionCondition` 在**任何容器被触碰之前**判定——无 Docker 时整类跳过（门禁不红），有 Docker 时 `@DynamicPropertySource` 首次求值触发容器启动；
- 连接参数经 `@DynamicPropertySource`（最高优先级属性源）注入 `spring.datasource.url/username/password`，替换原 `@ServiceConnection` 的自动注入（库名逐类不同，故不可继续用 `@ServiceConnection`）；
- **did 模块特有的 UTC 连接参数**（`connectionTimeZone=UTC` / `forceConnectionTimeZoneToSession=true` / `TZ=UTC`，DB-22"两把钟"族遗留口径）**逐字保留**；
- 现有容器配置（镜像标签 `mysql:8.0`、库名语义）不变，仅"每类一容器"改"每模块一容器 + 每类一库"。

### 1.2 每测试类改造（示例）

```java
-@Container
-@ServiceConnection
-static final MySQLContainer<?> MYSQL = new MySQLContainer<>("mysql:8.0")
-        .withDatabaseName("ctds_subject");
+@DynamicPropertySource
+static void datasource(final DynamicPropertyRegistry registry) {
+    SharedMySqlContainer.register(registry, "ctds_subject_review");   // 每类独立库名
+}
```

- 各类库名 = `ctds_subject_<用例域>` / `ctds_did_<用例域>` / `ctds_demo` / `ctds_guardrail_<序号>`；
- `FlywayGuardrailTest`（纯 JUnit + Flyway API，无 Spring）：保持**方法级全新库**语义——共享容器 + **每用例独立库名**（ADR-010 §3.6 明文允许的等价替代），原先的"方法级容器"（每方法一次容器启动）随之取消。

### 1.3 防回归守卫（固化，防"回退为自起容器"静默变慢）

每个模块新增 1 个 `SharedContainerGuardTest`（纯源码形态扫描，**零新增依赖**；不采用 ArchUnit——ArchUnit 面向字节码与分层规则，本守卫的锚点是"源集写法形态"，文本扫描更直接且报错点可读）。四条机器锚点：
① 不得声明容器字段注解（`@Container`——简写/通配导入/全限定三种写法一律命中；本模块统一采用形态 B，比 ADR-010 §8 字面"禁类级"更严：共享容器 + 独立库名已覆盖方法级容器场景）；
② 不得直接实例化容器（`new MySQLContainer(...)` 等；唯一合法实例化点 = 支撑类自身）；
③ **库名字面量全模块去重**——把"独立库名 = 隔离载体"从一次性手工探针固化为可回归断言；
④ 使用共享容器的测试类**必须带** `@Testcontainers(disabledWithoutDocker = true)`。
另设"扫描面必须覆盖到使用共享容器的测试类"断言，防扫描路径失效导致的空跑假绿。
理由：DB-23 教训同族——修复若无自动化锚点，将来有人加回自起容器，时长增长只在"贴线"时暴露（无感回归）。**守卫自身的可证伪性由四类注入反向探针实测**（见 §5.4）。

## 三、ADR-010 补记草案（待签署；签署后写入 `docs/adr/ADR-010-集成测试规范.md` §8）

> **§8 补记（2026-09-24，DB-25）：容器共享化与声明形态扩展**
>
> **背景**：§3.7 沉淀条件已满足（containerized 集成测试消费者 ≥2：example-service / kms / did / subject-service）。全仓 `mvn test` 实测 595s 贴 §门禁 `unitTest` 600s 上限（DB-25），主要开销为"每测试类一次 MySQL 容器启动"（13 次 ≈ 200s）。
>
> **补记结论（扩展 §3.2 的容器声明形态，非替代）**：
> 1. **形态 A（原 §3.2，默认）**：`@Testcontainers(disabledWithoutDocker = true)` + `@Container` 字段 + `@ServiceConnection`；适用单类或容器使用类少的模块。
> 2. **形态 B（本补记新增，用于同一模块 ≥2 个容器化测试类）**：**JVM 级单例共享容器**——模块测试源集内 `SharedMySqlContainer`（`MySQLContainer` 静态单例，首次访问启动，进程退出由 Ryuk 回收）+ 各测试类经 `@DynamicPropertySource` 注入连接参数 + **每测试类（或每用例）独立库名**。约束：
>    - **必须保留** `@Testcontainers(disabledWithoutDocker = true)`（无 Docker 跳过语义不得弱化，§3.4）；
>    - **必须**逐类/逐用例独立库名（§3.6 明文允许"各用例独立 schema/库名"作为方法级容器的等价隔离手段）；
>    - **不得**跨模块共享容器实例（模块 = 独立 JVM 与独立生命周期）；
>    - 镜像显式标签纪律（§3.2）与凭据零入库纪律（§3.5）不变；
>    - **必须**有防回归守卫（禁止在采用形态 B 的模块内回退为类级 `@Container`），避免时长增长无感回归。
> 3. **基座落位**：形态 B 的支撑类**暂按模块各自实现**（不新建跨模块测试基座模块，避免依赖面变更）；若后续消费者继续增加，按 §3.7 另行评估提取 `common/test-support`（登记沉淀建议，见本卡"沉淀建议"）。
> 4. **§3.7 关联**：本次处置即 §3.7 所述"≥2 消费者后评估共享测试基类"的落地实现，随本补记留痕。
>

### 5.6 业务可读交付说明

**完成了什么**：把"每次跑测试都要重新开一台数据库"改成"每个服务只开一台数据库、各测试各自用独立库"。原先全仓跑一遍测试要 **9 分 25 秒**，而系统允许的上限是 **10 分钟**——只剩 35 秒余量，机器稍慢就会"红灯"，而且这种红灯长得像"代码写错了"。现在降到 **4 分 10 秒**，余量约 6 分钟；测试项一条没少（反而多了 3 条"防回退"守卫）。

**如何演示**：① 在项目根目录执行 `mvn -B -ntp test`，观察结尾 `Total time` 由 9:25 降为 4 分 10 秒左右且 `BUILD SUCCESS`；② 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\gates\run-gates.ps1`，结尾 ExitCode 0（全绿）。

**注意事项**：① 本改动**只动测试代码**，对三个正在运行的演示服务与数据库无任何影响（演示环境保持运行，未关停）；② 门禁报告本次出现 `SKIP=2`：一条是 `secretsScan.binary`（DB-18 既有的二进制可见行，正常），另一条是**演示环境运行中被占用的未入库日志文件**（`services/*/logs/*.log`，已被逐条列名待人工复核）；两条均与本次改动无关；③ 门禁 `unitTest` 的 600 秒上限**未改动**（阈值变更属独立架构变更流程，本卡不夹带）；④ 后续新增服务做容器化集成测试时，按 ADR-010 §8 形态 B 复用同一写法（每模块一个共享容器 + 逐类独立库名）。
