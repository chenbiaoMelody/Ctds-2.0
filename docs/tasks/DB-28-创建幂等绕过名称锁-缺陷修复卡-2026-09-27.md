## 一、修复口径对比（**Q1 已选定 = 方案 A（2026-09-28）；编码归独立会话**）

| 方案 | 做法 | 业务影响 | 对既有剧本判定的影响 |
| --- | --- | --- | --- |
| **A（最小改动，建议）** | 幂等命中后**补一次终态/名称锁判定**：若命中结果已 `DISSOLVED`（或该归一化名已进 `space_name_lock`）→ 按名称锁口径拒绝（`1006C0003` + 「空间名称已被锁定，不可复用」） | 语义收敛：解散前的重放仍返回首次结果（"防重复提交"本意不变）；**解散后重放被拒**（名称不可复用） | **S1-7 保持 PASS**；**S3-6 转 PASS** |
| B | 幂等键**纳入状态/终态维度**（键追加活动态标识） | 键语义复杂化（需解释"同名不同键"）；实现与测试面更大 | S1-7 / S3-6 均可 PASS，但键语义须在 `ADR-007` 补记 |
| C | 幂等改为**在途请求去重**（仅防并发重复提交，不再缓存结果） | 语义最正确（幂等 = 防重复提交，而非结果缓存），但改动面最大、影响所有创建调用方 | **S1-7 判定将变化**（同名重放返回 `1006C0003` 而非首次结果）→ 须走**规格/剧本变更流程**并 PO 批准 |

> **Q1 选定留痕（2026-09-28 20:0x，编排师会话回复"都按建议"；由 WBS-3.2.6 C-2.3 走查收口段代录）**：**Q1 = 方案 A**（最小改动：幂等命中后补一次终态/名称锁判定——命中结果已 `DISSOLVED` 或归一化名已进 `space_name_lock` → 按名称锁口径拒绝 `1006C0003` + 「空间名称已被锁定，不可复用」）；**Q2 = 需要**（修复后重走 C-2.1 S3-6 界面复验，作为关闭条件②）；**Q3 = 并行关系确认**（3.2.6 三幕走查已完成，C-2.1 收口待本卡修复后复验 S3-6）。**本卡编码归独立会话/任务**（单会话单任务口径），本节由此转"可开工"。

## 二、测试与验收要求（测试先行）

- **先写失败测试（RED）后实现**，至少覆盖：① 解散后同名重放 → 期望 `1006C0003` + 名称锁文案，且**空间数不变、无新 CREATE 留痕**；② 未解散同名重放 → **仍返回首次结果**（S1-7 语义保持，回归锚）；③ 名称锁命中且**不同主体**同名创建 → 维持既有拒绝（回归锚）；④ 同键并发创建行为不劣化（沿 ADR-007 既有口径）；
- 本地门禁：`mvn -B -ntp -pl services/space-service test`、`mvn -B -ntp -pl services/space-service checkstyle:check`（仓库根）；交付态门禁沿 3.2.6 口径（`mvn -B -ntp -pl services/space-service package` 通过 + 前端 `npm run build` 不受影响）；
- **关闭条件（可核对）**：① 上述用例全绿（含 RED→GREEN 证据）；② **C-2.1 走查 S3-6 复验转 PASS**（界面提示为"名称已被锁定"，且空间数/留痕正确）；**S1-7 保持 PASS**；③ 4 视角评审（循环 ≤3 轮）通过；④ 合并须编排师显式指示（"验收通过"≠合并授权）；
- 回归风险面：同名重放、跨主体同名、名称锁与 DB 唯一键兜底（`uk_owner_norm_name`）、在 `common` 幂等组件零改动前提下所选方案是否可落地。
