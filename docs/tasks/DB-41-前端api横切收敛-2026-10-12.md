## 一、范围与设计（本卡设计见两级设计文件，正文不重复）

- **做什么 / 不做什么**：见 `docs/designs/DB-41-lofi.md` §1、§2；
- **待确认问题**：lofi §3（**Q1~Q3**）；**体量**：lofi §4（Q2-A 口径预估 ±300 行有效变更，机械转换为主）；
- **编码契约**（现状盘点 / 目标形态 / 收敛明细 / 边界与异常 / 测试计划 / 前置检查 / 交付门禁）：见 `docs/designs/DB-41-hifi.md` §1~§7。

**设计要点摘要（供快速表决）**：

1. **本卡零功能、零行为变更**，四件事（对应台账四族）：路径段编码全仓统一（①）+ `pageQuery`/空主体拦截沉淀 `client.ts` 公用层（②）+ 三域 rolesHeader 体内收敛私有工厂、导出面不变（③）+ 分页签名统一单对象（④，视 Q2）；
2. **公用层落点 = 扩展现有 `client.ts`**（零新文件）：域请求工厂收编"空主体前置拦截（`1000C0002` 零请求）+ 页面级角色头合并"三域逐字副本，各域文件收缩为一行工厂调用；
3. **零变更实证口径**：现行全部路径标识（`CT000003`/`CO000013`/`1001C0002`/`TV001` 等与 DID 串）经编码后 URL 逐位不变（did 域本就编码、subject 进度查询本就编码）→ 三域 spec 的 URL 断言零改动即天然回归锚；
4. **有意不收敛点（留痕）**：did/subject 两域维持"无空主体前置拦截"现状（补拦截 = 行为变更，超出本卡零变更锚）；`spaceRolesHeader` 与 catalog/contract 角色值不同——工厂带参数收敛，不做值合并。
