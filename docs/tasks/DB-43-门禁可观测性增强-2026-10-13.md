**设计要点摘要（供快速表决）**：

1. **本卡零业务影响**：三件事都是"给机器把关系统补随身记录"——① mvn 三段（编译/风格/单测）**成功/失败/超时三态都落完整原始输出 + 机器可核摘要行**（`stage / command / exitCode / elapsed / time`），根治 WBS-3.4.7"0 字节日志分不清成功还是没跑"的教训；② 前端提示文案与后端真源的**双源守卫升级**（前端守卫真读后端 `ContractErrorCodes.java` 逐条比对 8 对文案，真源在后端；前端方案为编码自决——备选后端 JUnit / 门禁新阶段见 hifi 论证，选前端理由 = 副本侧守卫 + 沿既有 SourceGuard 家族 + 零门禁配置改动）；③ npm 检查与覆盖率/变异/安全扫描**失败或超时时完整原始输出落盘** + 报告失败行附完整路径；
2. **落盘位置 = `%TEMP%\ctds-gate-<阶段>-out.log`**（Q2-A 建议；沿用 maven 段既有命名，零新惯例）；
3. **Q1 增量发现**：盘点中确认"门禁增强独立卡"沿续族——**跟踪-15**（门禁运行器证据缺口）与 ① 语义高度重叠，建议视为 ① 的兑现对象；**跟踪-23 剩余子项**（阶段超时后清理进程树加固）建议随卡（同一脚本/同一次变更流程/同类危害）；**跟踪-16 / 25 维持沿续**（不随卡）；
4. **实证勘正（台账表述）**：台账 DB-43 行"报告面缺机器可核退出码"与本卡盘点不符——报告面 PASS/FAIL 行自 `b93aefbf`（2026-09-06）起**已含** exit 码；真实缺口在"**原始输出（日志）面**：成功不落盘、失败日志无摘要行、超时零证据"。本卡按实证执行并在 §四 留痕勘正。
