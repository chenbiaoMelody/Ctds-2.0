## 一、范围与设计（本卡设计见两级设计文件，正文不重复）

- **做什么 W1~W9 / 不做什么 N1~N7**：见 `docs/designs/WBS-3.1.11-lofi.md` §1；
- **结构组成**：lofi §2；**主要流程**：lofi §3；**待确认问题**：lofi §3 末（Q1~Q8）；
- **编码契约**（接口契约表 / 库表与复用 / 错误码 / 配置与装配 / 前端设计 = 界面说明书 / 边界值与异常 / 测试锚点 / 演示口径 / 变更登记 / 实施前置检查项）：见 `docs/designs/WBS-3.1.11-hifi.md` §1~§10。

**设计要点摘要（供快速表决）**：

1. **落位**：读数端点与演示签名端点落 `services/did`（DID 能力归属服务，单一事实源）；界面落 `frontend`（Vue 3 + Element Plus，1 个菜单项「DID 管理」+ 2 个视图）；
2. **后端只加"读"与"演示"两类端点**：写操作（吊销/重签/重试）**全部复用 3.1.8 既有端点**，本包不新增写端点、不改其语义；
3. **记录状态展示口径**：列表 = 签发记录视角，显示既有 `DidStatus` 三值（`ACTIVE` 有效 / `REVOKED` 已吊销 / `PENDING_ISSUE` **记录中间态**），解析端口径仍锁两值（规格行为 2 规则 1）——**不新增状态枚举**；
4. **吊销交互（界面强制项）**：**理由必填**（前置校验 + 后端 `1005C0002` 兜底）→ **二次确认弹窗明示"吊销不可逆"** → 取消 = 状态不变且不产生留痕（不发起请求）→ 确认 = 调既有吊销端点 → 留痕五要素在"操作留痕"区可见；
5. **重签入口（规格行为 4 规则 4 点名界面）**：列表行操作，成功后新 DID 行出现、旧行保留（旧标识永不复用）；另提供"待签发"记录的**运营重试**（行为 1 规则 5）；
6. **演示与验证区**：仅演示/调试期——**代签**（规格 §6.6 平台侧代签边界，默认关闭的代码门槛）→ **验证三查结果**、**解析结果（含"未登记"业务答复非报错样式）**、**验证留痕列表**（含失败原因，**不含任何数据原文**）；
7. **零新增依赖面**：分页复用 `common/pagination`（`PageQuery`/`PageResult`，ADR-005 §3.2；`did-service` 新增平台内部模块依赖）；签名复用 `DidKmsClient` 扩展 `sign` → KMS 既有签名面（ADR-017 §2.6）；前端复用 `apiJson` 封装与既有 `ElMessageBox` 二次确认范式。
