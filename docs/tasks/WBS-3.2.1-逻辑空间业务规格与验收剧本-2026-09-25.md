## 一、范围与设计

- **做什么 / 不做什么**：见规格 `docs/specs/C-2.1-2.3-逻辑空间管理.md` §3（**7 条行为**）与 §4（非目标 8 项）；本卡不做设计类文件（免设计，理由见下表）。
- **免设计声明（章程 2.6.2 免设计类）**：本卡为**纯文档类**任务——交付物即"规格 + 剧本"本身，**没有可设计的产品形态**（无界面、无服务、无数据模型）；空间域的模型 / 服务 / 界面设计分别在 **3.2.2 / 3.2.3 / 3.2.4 / 3.2.5 / 3.2.6** 实施包内走两级设计门禁。故本卡**不产出 lofi/hifi**，以规格 §7 决策点清单（Q1~Q8）承接"方向确认"，以规格全文承接"编码契约的上游输入"（沿 WBS-3.1.7 同款免设计先例）。

**设计要点摘要（供快速表决）**

1. **一份规格覆盖三条 P0**（C-2.1 创建 / C-2.2 成员与权限 / C-2.3 隔离与策略继承），拆为 **7 条业务行为**，每条带 4~5 条可判定的验收标准（评审循环 1 勘误：原稿多处误计"8 条"，实为 7 条——行为 1~7）；
2. **资格门槛唯一**：一切空间能力以 C-1.1 的 **ADMITTED** 为前置，空间域不新建第二套资格口径；
3. **隔离的诚实边界**：隔离 = **服务端强制 + 默认拒绝**（应用层）；网络级隔离明确不在本规格（网关 3.5.2 与部署层承接）；
4. **策略不降级是硬约束**："红线条目不得放宽 + 冲突取严"（与数据分类分级"就高"同源），且要求**代码强制 + 反向探针**（沿"安全断言必须代码强制"教训）；
5. **术语与命名收敛**：统一"逻辑空间 / 空间"、资源名 `data-spaces`（沿 ADR-005 先例）、错误码**预留 1006 段**——避免空间域出现"tenant"等第二套概念；
6. **剧本界面步骤占位**：三份剧本先写业务步骤，界面入口待 **3.2.6** 交付后按 C-1.2 剧本同款"界面名称核对修订"机制一次性核对（业务判定不变，修订经 PO 批准留痕）。
