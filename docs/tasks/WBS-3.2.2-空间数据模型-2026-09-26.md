## 一、范围与设计

- **做什么 / 不做什么**：见 lofi「做什么 / 不做什么」两节与 hifi 交付物清单；表清单 6 张、约束探针 6 组，均映射规格行为（§三）。
- **两级设计一并提交**（章程 2.6.3 ≤1 天卡）：lofi = 方向（服务落点 / 表清单 / 关系 / Q 清单），hifi = 编码契约（库表设计 / 硬约束方案 / 测试计划 / 分级落级）。

**设计要点摘要（供快速表决）**

1. **新建独立服务模块 `space-service`**（微服务架构 + 每服务独立库惯例；空间域为 WBS 已规划独立域，3.2.3/3.2.4 的宿主）；
2. **6 张表承载 7 条行为**：space（空间主表+状态机）/ space_name_lock（解散名全平台锁定）/ space_member（成员关系+角色）/ space_admission（准入单：申请/邀请载体）/ space_policy（策略条目载体，平台级+空间级）/ space_action_log（统一留痕，含拒绝留痕）；
3. **三条唯一性硬约束 DB 兜底**（"安全断言必须代码强制"教训的数据库版）：同 owner 归一化名唯一（UNIQUE 索引）/ 解散名全平台锁定（锁定表 PK）/ 同空间同主体唯一活跃成员关系 + 唯一活跃所有者（MySQL 生成列 + UNIQUE 索引）——均有反向探针测试；
4. **策略表只建载体**（scope/entry_key/entry_value/is_redline/status），条目语言与可配置项集合归 3.2.5（防两处各自定义策略模型）；
5. **分级落级复核**（本卡指派义务）：space/space_policy=CAT-01 L2、成员与权限映射=CAT-02 L2、留痕=CAT-06 L3（对齐审计明细先例），回写分级规范 §6.1。
