## 一、范围与设计

- **做什么 / 不做什么**：见 lofi「做什么/不做什么」与 hifi 端点表/引擎契约/错误码表；规格行为 7 六条规则逐条落地 + §6.5 红线硬约束反向探针。
- **两级设计一并提交**（章程 2.6.3 ≤1 天卡）：lofi = 方向（目录定稿/判定语义/Q 清单），hifi = 编码契约（端点契约表/引擎解析与写门事务/错误码表/测试计划）。

**设计要点摘要（供快速表决）**

1. **目录定稿（规则 6 授权"随 3.2.5 定稿"）**：封闭目录 3 键（`data.visibility` 数据可见范围 / `data.retention` 数据留存期限 / `member.data_export` 成员数据导出），每键封闭值域 + **严格度单射**（数值越大越严，同键值域内无并列）；红线标记沿用 `is_redline`（仅平台级可标）；目录 = 代码注册表 `PolicyCatalog`（测试封闭性锚）；
2. **判定与生效语义（规则 2/3）**：覆盖写入门 = 值域校验（0012）→ 红线放宽拒（严格度下降 + is_redline=1 → 0013 + POLICY_OVERRIDE_REJECTED 留痕）→ 其余落库（覆盖行已存在则 UPDATE 值，同键至多一条 ACTIVE 由 scope_uniq 兜底）+ POLICY_OVERRIDE 留痕；同值重复覆盖 = 幂等无操作无留痕（沿 3.2.4 E7 先例）；**有效策略解析 = 每键取两侧更严者**（规则 3 取严），来源标注三态（继承自平台 / 空间覆盖生效 / 空间覆盖存在但平台更严未生效——取严可解释）；非红线放宽覆盖允许落库但被取严兜底不生效（规格只拒红线放宽——Q2 语义请确认）；
3. **5 端点最小完整面**：平台面 3（创建/值与红线变更/列表，`/api/v1/platform-policies`，门 = 新权限点 `platform.policy`）+ 空间面 2（覆盖提交 = `space.admin` 沿承接项③；有效策略视图 = `space.member`），ADR-005 命名先例；
4. **生命周期联动（规则 5）**：冻结/解散空间的策略写动作一律拒（复用 1006C0002 空间状态门槛，文案区分）；归档条目不可变（3.2.3 解散三写已置 ARCHIVED，本包写门 + 测试固化）；已配置覆盖在冻结期间保留、恢复后仍生效（剧本 S3-3 口径）；归档空间策略可查看（沿 3.2.3 解散后可见口径）；
5. **V3 迁移（Q6）**：`space_action_log.action` 注释登记新动作码 POLICY_DEFINE（平台条目创建/值与红线变更，沿 V2 先例）+ 平台级基线种子 3 条（演示可复现；种子=平台基线配置非演示残留，清理口径登记"保留"）；
6. **C-4.x 对齐义务登记（规则 6）**：本包目录注册表 = 空间域策略条目语言的权威定义；C-4.x 使用控制策略设计时须引用/对齐本模型（禁止两处各自定义）——登记为移交项随台账与任务卡 §四。
