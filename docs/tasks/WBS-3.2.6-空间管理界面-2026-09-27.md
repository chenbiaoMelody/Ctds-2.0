## 一、范围与设计（本卡设计见两级设计文件，正文不重复）

- **做什么 W1~W12 / 不做什么 N1~N8**：见 `docs/designs/WBS-3.2.6-lofi.md` §1；
- **结构组成**：lofi §2；**主要流程**：lofi §3；**待确认问题**：lofi §3 末（Q1~Q8 + D1）；
- **编码契约**（接口契约表 / 前端模块与类型 / 路由与菜单 / 演示身份 / 后端新增读端点 / 界面说明书 / 测试锚点 / 边界值与异常 / 剧本步骤→界面入口映射 / 变更登记 / 实施前置检查项 / 勘误）：见 `docs/designs/WBS-3.2.6-hifi.md` §1~§12。

**设计要点摘要（供快速表决）**：

1. **落位**：界面全部落 `frontend`（Vue 3 + Element Plus，2 个菜单项「逻辑空间」「平台策略治理」+ 4 个路由 + 4 个视图）；后端**仅 Q6-A 新增 1 个只读留痕端点**（`services/space-service`），其余 24 个端点只读复用；
2. **三面界面的组织**：空间管理 / 成员管理 / 策略配置**统一在"空间详情"的三个区内**（概览 / 成员与准入 / 策略），平台侧策略条目治理独立成页——与 WBS 行 256 三块一一对应，且成员与策略天然带空间上下文；
3. **演示身份是关键使能项**（Q2）：顶栏提供"主体编号 + 身份档（普通主体 / 平台运营方）"；**普通档请求头 = `applicant`、运营档 = `applicant,platform.operator`**——剧本中"以 C 主体被拒""以 E 主体越权被拒"与"以运营方治理"两类步骤靠它区分；若恒带平台角色，越权步骤会被放行（硬约束，测试锚点 T27 钉死）；
4. **权限一律在服务端**：前端按钮显隐只做体验层；演示期 admin 角色能看到菜单，但以某主体身份执行越权动作会被后端拒（正是剧本要求）——界面**原样展示后端业务文案**，不改写、不吞掉；
5. **非成员同形口径**：非公开空间对非成员按"不存在"口径返回（`1006C0004`），界面两条分支用**同一条**提示文案与样式（防存在性探测），由反向探针 T30 钉死；
6. **留痕读面（Q6）**：C-2.1 剧本 S1-3 的"打开空间详情查看留痕 + 四要素"判定目前**无端点可承载** → 建议新增 1 个只读端点 `GET /api/v1/data-spaces/{id}/action-logs`（零新码、零迁移、零改动既有语义）；
7. **零依赖面**：前端零新增依赖；后端零新增模块依赖（分页组件 3.2.3/3.2.5 已引入）；`vite.config.ts` 仅新增开发期转发两条前缀 → 8083；分页复用 `common-pagination`（`PageData<T>` 复用 `api/types.ts`）、二次确认复用 `ElMessageBox.confirm` 既有范式、错误展示复用 `apiJson` + `ApiError`。
