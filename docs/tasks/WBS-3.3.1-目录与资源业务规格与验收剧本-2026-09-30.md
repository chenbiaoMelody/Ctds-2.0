## 一、范围与设计

- **做什么 / 不做什么**：见规格 `docs/specs/C-3.1-2.3-数据目录与资源.md` §3（**7 条行为**）与 §4（非目标 8 项）；本卡不做设计类文件（免设计，理由见下表）。
- **免设计声明（章程 2.6.2 免设计类）**：本卡为**纯文档类**任务——交付物即"规格 + 剧本"本身，**没有可设计的产品形态**（无界面、无服务、无数据模型）；目录域的模型 / 服务 / 界面设计分别在 **3.3.2 / 3.3.3 / 3.3.4 / 3.3.5 / 3.3.6** 实施包内走两级设计门禁。故本卡**不产出 lofi/hifi**，以规格 §7 决策点清单（Q1~Q9）承接"方向确认"，以规格全文承接"编码契约的上游输入"（沿 WBS-3.1.7 / WBS-3.2.1 同款免设计先例）。

**设计要点摘要（供快速表决）**

1. **一份规格覆盖三条 P0**（C-3.1 登记 / C-3.2 目录 / C-3.3 封装上架），拆为 **7 条业务行为**（登记 / 变更注销 / 封装定价 / 上下架 / 检索分类 / 订阅收藏 / 访问边界与治理例外），每条带 4~7 条可判定的验收标准；
2. **资源挂在空间下**：提供方 = 已入驻且为空间成员的主体，资源沿 ADR-005 `/data-spaces/{id}/datasets` 先例归属空间；**产品 = 资源的产品化封装**，上架后进入**平台统一目录**（平台级、跨空间可检索）——"空间内隔离 + 目录公开检索"两级口径分开；
3. **检索 ≠ 可访问**：目录结果与详情仅为元数据，资源本体访问须经订购 / 合约（C-7.3 / C-4.x）——与空间域"可见性 ≠ 可访问性"同源；
4. **合规硬约束前置**：分类分级申报必填（提供方申报、平台复核口径——分级规范 CAT-07）+ **申报"重要数据"一律拒收登记**（分级规范 §4.5-3，须代码强制 + 反向探针）；
5. **定价与计费对齐**：定价四档（免费 / 按次 / 包月 / 交易额分成）与 WBS 3.7.6 计费引擎口径一致，避免目录域另起一套定价体系；
6. **治理例外唯一且留痕**：平台运营方可查看全部对象治理信息 + 强制下架（沿 DB-29 治理查看留痕已交付先例）；
7. **剧本界面步骤占位**：三份剧本先写业务步骤，界面入口待 **3.3.6** 交付后按 C-1.2 剧本同款"界面名称核对修订"机制一次性核对（业务判定不变，修订经 PO 批准留痕）。
