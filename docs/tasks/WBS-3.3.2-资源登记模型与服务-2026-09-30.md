## 一、范围与设计

- **做什么 / 不做什么**：见 lofi「做什么 / 不做什么」两节与 hifi 端点表/错误码表/表设计；规格行为 1/2 全部规则逐条落地，行为 7 的资源侧（服务端强制 / 防枚举同形 / 越权留痕）随本卡承载。
- **两级设计一并提交**（章程 2.6.3 ≤1 天卡）：lofi = 方向（服务落点 / 表清单 / 资格与成员判定通道 / Q 清单），hifi = 编码契约（端点契约表 / 错误码表 / 表结构与约束 / 状态机与事务 / 测试计划 / 分级落级）。

**设计要点摘要（供快速表决）**

1. **新建域级服务 `catalog-service`**（目录与资源域 3.3.2~3.3.5 共用宿主，沿 space-service 域级服务先例；端口 8084、库 `ctds_catalog` 顺延）；资源命名沿 ADR-005 裁决 `datasets`，服务内资源 = dataset 表/实体（术语"数据资源"映射 `Dataset`，规格 §6 边界声明 6 统一术语，不引入第二套概念）；
2. **3 表承载行为 1/2**：dataset（主表+数据标识 data_no 业务编号+申报字段+状态）/ dataset_name_lock（注销名同空间锁定，沿 space_name_lock 先例）/ dataset_action_log（统一留痕含 from→to 值）；同空间归一化名唯一 = DB 唯一索引兜底（`uk_space_norm_name`，沿 3.2.2 uk_owner_norm_name 先例），探针含全角空格绕过尝试；
3. **两道跨域判定走内部端点**（不直连对方库）：主体 ADMITTED → subject 内部端点（先例现成）；**空间状态+成员关系 → space 新增 1 个 internal 端点**（最小暴露两字段语义，沿 InternalAdmissionController 先例）——既有服务唯一改动 = space 1 端点 + yml 1 行授权（ADR-016 §6 补记）；不可达/失败 = UNAVAILABLE 统一文案，不冒充"无权限/不存在"（防枚举同形）；
4. **重要数据拒收代码强制 + 反向探针**（边界声明 5 硬约束）：申报 important=true 一律拒收 + DENIED 留痕；探针含"放宽申报绕过拒收"尝试必被拒；
5. **注销 = 两写事务**（status=DELETED + name_lock 写入，沿空间解散三写事务先例收缩）+ `confirmCancellation=true` 二次确认 API 强表达（沿 confirmDissolve 先例）；**引用保护检查留接口**（ProductReferenceGuard），产品表落地（3.3.5）前恒放行——该规则实体兑现与补测登记为 3.3.5 义务，理由 = 产品表不存在时无从查起（规格验收标准 GWT 验证依赖产品引用存在，属 3.3.5 验收面）；
6. **数据标识编号规则落定**（规格未定义项，§7 Q3 授权 3.3.2 定）：`DS + yyyyMMdd + 6 位当日序号`（沿 subject nextDailySeq 先例：序号表原子自增、当日重置；全平台唯一、不可变）；
7. **分级落级复核**（本卡指派义务，沿 3.2.2 Q9 先例）：dataset 主表+申报字段=CAT-03 L2、留痕=CAT-06 L3，回写分级规范 §6.1 同步行。
