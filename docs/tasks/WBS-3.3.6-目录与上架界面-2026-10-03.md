## 一、范围与设计（本卡设计见两级设计文件，正文不重复）

- **做什么 W1~W11 / 不做什么 N1~N8**：见 `docs/designs/WBS-3.3.6-lofi.md` §1；
- **结构组成**：lofi §2；**主要流程**：lofi §3；**待确认问题**：lofi §3 末（Q1~Q7 + D1）；
- **编码契约**（接口契约表〔复用 24 + 新增 R14/R15/R16〕/ 前端模块与类型 / 路由与菜单 / 演示身份 / 后端新增读端点 / 界面说明书 / 测试锚点 / 边界值与异常 / 剧本步骤→界面入口映射 / 变更登记 / 实施前置检查项 / 勘误）：见 `docs/designs/WBS-3.3.6-hifi.md` §1~§12。

**设计要点摘要（供快速表决）**：

1. **落位**：界面全部落 `frontend`（Vue 3 + Element Plus）——「数据目录」菜单内容替换（检索门户 + 我的收藏/订阅/互动留痕页签）+ 新增「资源登记」「产品上架」「目录治理」三菜单项 + 产品详情深链路由；后端**仅 Q2-A 新增 3 个只读留痕端点**（catalog-service 模块内），其余 26 端点只读复用；
2. **留痕屏幕可核对是本卡的硬需**（Q2）：三剧本多步判定面含"留痕四要素 / from→to / 拒绝留痕 / 订阅留痕"，剧本是给人"只看屏幕"执行的 → 建议按 3.2.6 Q6-A 先例新增 3 个只读端点（资源留痕 / 产品留痕 / 我的互动留痕），零新表零新码零迁移；
3. **演示身份扩展是关键使能项**（Q4）：目录域页面级角色头 = 普通档 `provider`、运营档 `admin`（沿 3.3.5 走查实测口径）；**普通档不得携带 `admin`**（硬约束，测试锚点 T17 钉死）；顶栏控件零新增（3.2.6 已交付）；
4. **同形拒绝与错误展示纪律**：`1007C0005` / `1007C0011` / `1007C0012` 三类拒绝在界面各用**同一条**提示常量与样式；所有拒绝文案**原样展示**（不吞、不改写）；写动作不做乐观更新；
5. **越权类步骤的界面承载**（W10）：他人对象在界面上无入口（安全面正确行为）→ 剧本核对修订时按"技术侧配合 + 留痕区核对"逐条标注承载说明（沿 C-3.2 S3-2 先例），业务判定一字不改；
6. **资源登记空间选择 = 编号直填 + 下拉快捷**：剧本含"非成员空间""未启用空间"等对照步骤，下拉只列可见空间会让步骤字面不可执行 → 空间编号可直填（服务端判定为准，界面不拦截提交）；
7. **零依赖面**：前端零新增依赖（`package.json` 零改动）；后端零新增模块依赖；`vite.config.ts` 开发期新增 5 条转发键 → 8084（含 `^/api/v1/data-spaces/[^/]+/datasets` 正则键，须在空间域前缀之前——Vite 8 `doesProxyContextMatchUrl` 实测支持 `^` 正则且键序先行命中）；
8. **债务定稿**：DB-36 = 维持双轨 + 登记有意分叉（界面统一中文，Q5-A）；DB-39 = common 沉淀不采 + 孪生 DTO 维持现状（Q6-A）——均以"明确结论 + 理由 + 触发条件"关闭留痕。
