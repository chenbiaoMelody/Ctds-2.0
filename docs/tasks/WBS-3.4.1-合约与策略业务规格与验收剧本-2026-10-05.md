## 一、范围与设计

- **做什么 / 不做什么**：见规格 `docs/specs/C-4.1-4.3-数字合约与使用控制.md` §3（**7 条行为**）与 §4（非目标 8 项）；本卡不做设计类文件（免设计，理由见下表）。
- **免设计声明（章程 2.6.2 免设计类）**：本卡为**纯文档类**任务——交付物即"规格 + 剧本"本身，**没有可设计的产品形态**（无界面、无服务、无数据模型、无 DSL）；合约域的模型 / 服务 / DSL / 引擎 / 界面设计分别在 **3.4.2 / 3.4.3 / 3.4.4 / 3.4.5 / 3.4.6 / 3.4.7** 实施包内走两级设计门禁。故本卡**不产出 lofi/hifi**，以规格 §7 决策点清单（Q1~Q9）承接"方向确认"，以规格全文承接"实施包的上游输入"（沿 WBS-3.1.7 / 3.2.1 / 3.3.1 同款免设计先例）。

**设计要点摘要（供快速表决）**

1. **一份规格覆盖三条 P0**（C-4.1 模板 / C-4.2 协商签署 / C-4.3 策略引擎），拆为 **7 条业务行为**（模板管理 / 发起与协商 / 电子签署与生效 / 策略条款 / 策略执行与绕过拒绝 / 状态与生命周期 / 访问边界与治理例外），每条带 4~6 条可判定的验收标准；
2. **合约锚定在架产品**：合约对象 = 已上架产品（承接目录域"下架不可新订购、既有权益不变"口径）；需求方 ≠ 提供方；资格与防枚举沿 C-1.1 出站口径；
3. **模板是治理抓手**：模板仅平台运营方维护（预置三类：公共数据授权 / API / 隐私计算）、版本化 + **版本快照**（模板修订不影响既有合约）、合约必须从启用模板发起；
4. **电子签署用既有底座**：V1.0 = 平台内 DID 身份 + 国密 SM2 数字签名（复用 did / kms，零新增依赖；双签生效、最后一签为准、验签不可抵赖）；**法律效力边界诚实声明**（§6-3：不等同"可靠电子签名"资质）；签署存证 = 存证事件落库 + 预留 3.8.3 埋点（上链归 3.8.x 未开工）；
5. **策略是合约条款**：五要素（次数 / 期限 / 用途 / 域内使用 / 禁止再分发）由提供方提出、随双签生效、生效后不可单方变更；与空间策略模型**对齐复用**（空间规格行为 7 规则 6 约束）；
6. **双向用例是硬约束**：每类策略要素必须"策略生效（放行）+ 绕过被拒（拦截）"双向验证（AGENTS §4 明文；写入规格行为 5 规则 4 + C-4.3 剧本 S2/S3 两幕 + 3.4.6 / 3.4.8 承接）；
7. **剧本界面步骤占位**：三份剧本先写业务步骤，界面入口待 **3.4.7** 交付后按 C-1.2 / C-3.1 剧本同款"界面名称核对修订"机制一次性核对（业务判定不变，修订经 PO 批准留痕）。
