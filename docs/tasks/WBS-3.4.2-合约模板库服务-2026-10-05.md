## 一、范围与设计

- **做什么 / 不做什么**：见 lofi「做什么 / 不做什么」两节与 hifi 端点表/错误码表/表设计；规格行为 1 全部 7 规则逐条落地，5 条验收标准全部有测试锚；**模板条款槽位集合与模板数据模型**（规格 §未定义项授权 3.4.2 落定）随两级设计定稿——槽位集合以**业务可读条款清单**呈现（lofi §三），供编排师按业务语义确认。
- **两级设计一并提交**（章程 2.6.3 ≤1 天卡）：lofi = 方向（服务落点 / 表清单 / 判定通道 / 槽位业务清单 / Q 清单），hifi = 编码契约（端点契约表 / 错误码表 / 表结构与约束 / 状态机与事务 / 测试计划 / 分级落级）。

**设计要点摘要（供快速表决）**

1. **新建域级服务 `contract-service`**（合约域 3.4.2~3.4.8 七个实施包共用宿主，沿 catalog-service 域级先例；端口 8085、库 `ctds_contract` 顺延）；资源命名沿 ADR-005 裁决 `contract-templates`；
2. **3 表承载行为 1**：contract_template（主表：模板编号/名称/类型/当前版本号/状态）/ contract_template_version（版本表：版本号 + 条款框架 JSON 载体，**行级版本化——修订 = 新增版本行，版本行不可变**，旧版本天然保留可查；版本行即"版本快照"载体）/ contract_template_action_log（统一留痕四要素含版本号与 from→to）；预置三类模板 = 迁移种子（各 1 条模板记录 + V1 版本行，状态启用中）；
3. **两道判定通道均走既有内部端点，不新建对端改动**：已入驻判定 → subject 内部端点（先例现成，仅 yml 加 1 行 client 授权）；平台运营方判定 → 沿 3.3.6 目录域 admin 角色头先例（写面与运营读面要求 admin 档，普通档/无头一律拒绝并留痕）；不可达/失败 = UNAVAILABLE 统一文案不冒充（防枚举同形，沿 3.3.2 client 三态先例）；
4. **浏览边界**：已入驻读面仅呈现**启用中**模板（运营方维护视图可查停用模板以支持重新启用——剧本 S2-4"二选一"口径的裁决点，见 Q6）；
5. **版本快照机制**：版本行不可变由设计保证（无更新路径 + 反向探针）；"合约发起时锁定快照"的写入动作归 3.4.3 发起流程（本卡交付版本有效性校验查询）；
6. **错误码 1008 段**：`ContractErrorCodes` 常量类定稿（C 客户端错误 / S 服务端错误两型，沿 1007 段先例）；
7. **分级落级复核**（本卡指派义务，沿 3.3.2 Q8 先例）：模板与版本（业务配置数据）+ 留痕（含操作者）落级随 hifi 落级表定稿，回写分级规范 §6.1 同步行。
