## 一、范围与设计

- **做什么 / 不做什么**：见 lofi「做什么 / 不做什么」两节与 hifi 端点表/错误码表/表设计；规格行为 2/3/6/7 逐规则落地、行为 4 本卡承载面（规则 1/2/4/5/6）落地，验收标准逐条有测试锚；**§未定义项四项**（合约数据模型、协商轮次上限、合约变更流程深化、主体资格异常处置）随两级设计定稿（lofi §八 Q 清单，编排师确认即生效）。
- **两级设计一并提交**（章程 2.6.3 ≤1 天卡）：lofi = 方向（服务落点 / 业务链路与状态机 / 表清单 / 判定通道 / 签署机制 / 可见性与治理 / Q 清单），hifi = 编码契约（端点契约表 / 错误码表 / 表结构与约束 / 状态机与事务 / 加密与存证口径 / 测试计划 / 分级落级）。

**设计要点摘要（供快速表决）**

1. **落点**：`contract-service` 既有宿主（3.4.2~3.4.8 共用，无新骨架/端口/库），迁移 **V2 六表**；合约编号 `CO` + 6 位全局序号（沿模板 `CT` 先例）；端点编号续 3.4.2：**写面 W5~W12（参与方 7 + 治理 1）/ 读面 R6~R11（参与方 4 + 治理 2）**；
2. **协商机制**：发起即"协商中"（首版条款 V1，需求方填写）；双方**交替提案/反提案**，每轮新增条款版本行（行级版本化、版本行不可变，变更明细"从何值→到何值"落版本行）；**每方对当前版本各确认一次，双方齐 → 待签署**；新提案自动重置确认（新版本行）；**不设轮次上限**（协商终止随时可用，Q3）；
3. **状态机**：协商中 → 待签署 → 部分签署 → 已生效 → 已完结；终止分支（终态）= 协商终止 / 拒签终止 / 运营方强制终止；**发起即协商中**（"草案"为瞬态不单独落地，兑现剧本 S1-1 口径，Q2）；
4. **签署**：双方各以主体 DID + 国密 SM2 签署**条款快照哈希**（SM3）；复用 did 既有三能力（解析校验 DID 归属与状态 / 演示签名入口代签 / 验证端点验签）；**双签生效、生效时间 = 最后一签**；生效即登记**存证事件**（合约哈希 + 双方签署要素），链上对接预留 3.8.3 埋点（Q5）；
5. **目录衔接**：catalog 新增**内部只读端点**（最小暴露：产品名/状态/属主/定价两列）供发起门槛与定价快照——公开读面无法鉴别非在架、治理读面过宽，均不适配（Q6）；
6. **策略条款**：作为条款值的独立结构化字段承载（五要素 + 显式"无使用限制"声明）；门槛校验 = 至少一项启用或显式声明 + 基础取值合法（次数正整数 / 期限起止有序）；**完整 DSL 语法与空间策略模型形态对齐归 3.4.4**（Q7）；
7. **可见性与治理**：合约与协商详情仅合约双方可见（非参与方读写一律"不存在"同形 404 + 拒绝留痕，防枚举）；平台运营方治理面可查全部（含协商过程）+ **每次治理查看写查看留痕**；强制终止理由必填（沿目录域强制下架先例）；
8. **L3 加密承载**：合约文本（条款值 / 变更明细 / 快照规范化原文）与签署记录（签名值）按 CAT-04 **L3 存储保密走国密组件**（SM4 密文列，`common-crypto` 唯一入口，密钥源配置沿 subject 先例）；哈希为不可逆摘要明文落库（登记口径）；留痕表不含敏感原文（沿全仓同源口径）。
