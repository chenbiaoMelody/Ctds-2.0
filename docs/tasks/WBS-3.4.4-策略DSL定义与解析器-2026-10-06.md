## 一、范围与设计

- **做什么 / 不做什么**：见 lofi「做什么 / 不做什么」两节与 hifi 要素目录表/解析器契约/校验规则表；规格行为 4 规则 2/3/6 逐条落地（规则 1/4/5 由 3.4.3 承载已闭环——本卡零触碰），验收标准逐条有测试锚；**规格未定义项三项**（DSL 语法、字段与解析器、空间模型形态对齐）随两级设计定稿（lofi §八 Q 清单，编排师确认即生效）。
- **两级设计一并提交**（章程 2.6.3 ≤1 天卡）：lofi = 方向（DSL 形态 / 对齐模式 / 解析器与收敛 / 校验增强面 / Q 清单），hifi = 编码契约（要素目录表 / DSL v1.0 文档规范 / 解析器 API 与校验规则表 / 调用点收敛清单 / 兼容映射矩阵 / 测试计划 / ADR-019 大纲）。

**设计要点摘要（供快速表决）**

1. **落点**：`contract-service` 既有宿主 `com.ctds.contract.domain.policy` 新包（包名踏勘空闲）；**零表结构变更**（dslVersion 进策略 JSON 文档内——策略文档随条款值已在 SM4 密文列，L3 承载零改动）；
2. **DSL 形态**：**结构化声明式策略文档**（JSON 规范文档 + `dslVersion` 版本字段 + 封闭要素目录）——"策略即代码" = 机器可读、可校验、可版本化、可判定执行的结构化文档，随条款版本行行级版本化；**不做文本语法**（消费方盘点：3.4.5 引擎直读模型 / 3.4.6 模拟器跑结构化用例 / 3.4.7 界面结构化表单 / C-4.6 AI 生成输出 JSON 最稳——无一需要文本语法；Q1）；
3. **对齐复用**：与空间 `PolicyCatalog` **模式同构**（单点权威注册表 + 键命名规范"域.名词小写点分" + 封闭约束）——两个权威点各自服务本域、ADR-019 登记同构契约与互不漂移评审锚；**空间域零改动**；目录键（对齐空间命名规范）与文档字段名（沿 3.4.3 固定字段序兼容）两层分离、映射表留痕（Q2）；
4. **解析器与收敛**：解析器 = 校验规则单点（3.4.3 三件校验〔结构 / 取值 / 确认门槛〕迁出值对象，调用点委托——hifi §10-7 兑现）；3.4.5 引擎同宿主消费（沿 QC1 先例）；引擎独立部署的迁移触发条件登记 ADR-019（Q3）；
5. **完整校验增强**（移交-4"完整策略校验增强"具体化，Q4）：版本门槛（缺省容忍 = 1.0、未知版本值 fail-closed 拒绝）+ 互斥校验（"无使用限制"声明与任一要素启用不得并存——规格行为 4 规则 2 语义推论）+ 文本要素 trim 规范化（判定一致性前提）+ 期限起始不早于提交日（规格"期限早于生效日"在提交时点的可判定化）；
6. **判定语义标注**：目录注册表每要素标注判定语义（次数上限 / 期限内 / 用途等值 / 域内等值 / 再分发禁止——供 3.4.5 引擎直接消费的契约面；**本卡只标注不实现**）；
7. **兼容映射**：3.4.3 存量（无 version 字段）读容忍缺省 1.0；既有载荷与测试夹具零破坏（Q4-A 口径下）；演示库存量零迁移；
8. **ADR-019**：随编码批落稿——形态决策 / 字段定稿 / 同构契约 / 落点与迁移触发条件 / 版本演进规则，决策内容 = 本卡 §二 确认口径。
