## 一、范围与设计

- **做什么 / 不做什么**：见 lofi「这卡做什么 / 不做什么」两节与 hifi 三端点契约表、场景集表、测试计划；规格行为 5 规则 2/3/4/5 逐条落地，规则 4 双向用例硬约束由测试台场景集与测试矩阵承载；**规格未定义项一项**（"双向用例的模拟器形态"——规格尾注明示归 3.4.6）随两级设计定稿（lofi §九 Q 清单；**编排师已于 2026-10-08 一次确认——Q1~Q7 均采建议口径 A + D1 不拆分**）。
- **两级设计一并提交**（章程 2.6.3；本卡预估 1 会话且设计面单卡闭合、无合理拆分切面——D1 论证见 lofi §八）：lofi = 方向（形态与落点 / 模拟通道口径 / 测试台场景集 / 受控执行与可见性 / Q 清单），hifi = 编码契约（三端点请求响应契约 / 场景集与预期表 / 配额纯判定与两腿同源 / 可见性守卫抽取 / 错误码与 HTTP 语义表 / 零副作用与事务口径 / 测试计划 / ADR-021 大纲）。
- **非界面类**（服务端能力）→ 设计形态 = **业务可读行为清单 + 接口契约表 + 边界值与异常行为**（免静态 HTML 原型；界面归 3.4.7）。

**设计要点摘要（供快速表决）**

1. **形态与落点**（Q1-A）：contract-service **同宿主**，三组端点全在 `interfaces`，编排在新增 `application.PolicySimulationService`；**零新模块、零新表、零新迁移**；
2. **模拟与执行是两条通道**（Q2-A）：**模拟通道**（试算：假想上下文 + 零副作用 + 结论以数据返回）/ **执行通道**（受控执行：真实计数与留痕、异常形态返回）——两通道判定语义同源（同一 `PolicyJudge` + 目录 + 配额判据），差异只在副作用与错误表达，ADR-021 登记；
3. **配额纯判定补齐**（Q3-A）：3.4.5 的配额只存在于"判检一体原子递增"（数据库条件 UPDATE），**无纯函数入口**——模拟通道需要它；方案 = `PolicyJudge` **新增** `judgeQuota(policy, assumedUsedCount)`（与四要素判定同址，判定不散落）+ 对照一致性锚（模拟 ≡ 真实执行）；
4. **测试台 = 目录驱动的双向场景集**（Q4-A，兑现 3.4.4 移交-2）：五要素 × 双向 10 场景 + 空策略 1 场景，**一键执行 → 结构化报告**（`PASS/FAIL/SKIPPED` + 期望/实际/触发要素），**零落库**；要素目录扩增而场景集未同步 → 结构锚测试红；
5. **受控执行端点 = 剧本演示入口**（Q5-A，兑现 3.4.5 移交-2）：把引擎的应用层判定入口产品化为"受控调用"端点，替代 3.4.5 走查期的临时 Java harness（不入库、每次走查重建）；**不是交付链本体**（C-5.x 上线后由 3.4.8 复核同判定面并评估退役）；
6. **可见性守卫抽取**（Q6-A，跟踪-17 触发条件成立）：第三消费方出现（模拟 / 测试台 / 受控执行）→ 抽取应用层共享守卫供 R12 与新端点共用；R12 行为零变更由既有矩阵锚回归保护；
7. **错误码与 ADR**（Q7-A）：**零新码位**（全复用），**新建 ADR-021**（跨包契约，供 3.4.7 / 3.4.8 消费）；
8. **诚实边界三写**（规格 §6-1 / ADR-020 §2.9 沿续）：模拟结论不是放行承诺（正式放行只经执行通道）；受控执行端点为演示期形态；网关未上线前不承诺网络级。
