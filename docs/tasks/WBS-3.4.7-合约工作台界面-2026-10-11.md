## 一、范围与设计（本卡设计见两级设计文件，正文不重复）

- **做什么 W1~W12 / 不做什么 N1~N8**：见 `docs/designs/WBS-3.4.7-lofi.md` §1；
- **结构组成**：lofi §2；**主要流程**：lofi §3；**待确认问题**：lofi §3 末（Q1~Q7 + D1）；
- **编码契约**（接口契约表〔复用 27 + 新增 R13 + 跨域 1〕/ 前端模块与类型 / 路由与菜单 / 演示身份 / 后端新增读端点 / 界面说明书 / 测试锚点 / 边界值与异常 / 剧本步骤→界面入口映射 / 变更登记 / 实施前置检查项 / 勘误）：见 `docs/designs/WBS-3.4.7-hifi.md` §1~§12。

**设计要点摘要（供快速表决）**：

1. **落位**：界面全部落 `frontend`（Vue 3 + Element Plus）——新增「合约模板」「合约工作台」「合约治理」三菜单（`menuOrder 14/15/16`）+ 合约详情深链路由；后端**仅 Q2-A 新增 1 个只读留痕端点**（contract-service 模块内），其余 27 端点只读复用；
2. **"留痕判定面屏幕可核对"是本卡的硬需**（Q2）：三剧本多步判定面含"发起/提案/签署/拒签/终止/强制终止/越权拒绝留痕四要素齐备"——而**合约统一留痕表 `contract_action_log` 当前无任何读面**（实测：仅写路径 `repository.insertLog`，无分页查询）→ 建议按 3.3.6 Q2-A 先例新增 **R13**（零新表零新码零迁移，读面 = 参与方 + 治理例外，沿 R6~R12 防枚举与共享守卫口径）；
3. **演示身份扩展是关键使能项**（Q4）：合约域页面级角色头 = 普通档 `provider`（持 `contract.template.read` / `contract.read` / `contract.deal`）、运营档 `admin`（另持 `contract.template.manage` / `contract.governance`）；**普通档不得携带 `admin`**（硬约束，测试锚点 T18 钉死）；顶栏控件零新增（3.2.6 已交付）；
4. **3.4.6 三端点的界面承载 = 本卡的"策略与使用"面**（Q5）：策略视图（R7 条款值内策略全文渲染）+「模拟试算」弹窗（假想上下文 + 可选策略草稿；**拒绝以数据展示、不弹错误**）+「测试台」一键报告（PASS/FAIL/SKIPPED 三态）+「发起使用（受控执行）」弹窗（参与方；放行显示计数、越界原样展示 C0020）+ 使用摘要区（R12——quota/放行/拒绝/记录分页）；
5. **条款编辑形态**（Q6）：发起 = 按 R5 框架渲染槽位表单（必填标记 + 填写说明）+ 策略编辑器（五要素 + 无使用限制声明）；提案 = 按当前条款值渲染（键只读 + 值可改 + 增删槽位行）；**非法取值不前端硬拦**（如次数负数可提交，由服务端 1008C0015 判定——剧本步骤"要素取值非法被拒"屏幕可执行）；
6. **发起弹窗的产品选择 = 编号直填 + 检索回填**（跨域复用 `api/catalog.ts` 的检索）：剧本含"已下架产品发起被拒"对照步骤，产品下拉只列在架会让步骤字面不可执行 → 编号可直填（服务端判定为准，界面不拦截提交）；
7. **零依赖面**：前端零新增依赖（`package.json` 零改动）；后端零新增模块依赖；`vite.config.ts` 开发期新增 2 条转发键（`/api/v1/contracts`、`/api/v1/contract-templates` → 8085）；
8. **同形拒绝与错误展示纪律**：`1008C0001`（模板不可用）/ `1008C0002`（模板维护越权）/ `1008C0003`（未入驻统一文案）/ `1008C0010`（产品不可用）/ `1008C0012`（合约不可见）/ `1008C0013`（状态不允许）/ `1008C0015`（策略条款非法）/ `1008C0017`（模板不可发起）/ `1008C0020`（越界使用）在界面各用**同一条**提示常量与样式；所有文案**原样展示**（不吞、不改写）。
