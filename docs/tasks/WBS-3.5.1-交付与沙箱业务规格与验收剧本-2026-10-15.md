## 一、范围与设计

- **做什么 / 不做什么**：见规格 `docs/specs/C-5.1-5.2-交付与沙箱.md` §3（**7 条行为**）与 §4（非目标 9 项）；本卡不做设计类文件（免设计，理由见下）。
- **免设计声明（章程 2.6.2 免设计类）**：本卡为**纯文档类**任务——交付物即"规格 + 剧本"本身，**没有可设计的产品形态**（无界面、无服务、无数据模型）；交付域的网关交付链 / 加密文件传输 / 沙箱环境 / 审核导出 / 界面设计分别在 **3.5.2 / 3.5.3 / 3.5.4 / 3.5.5 / 3.5.6** 实施包内走两级设计门禁。故本卡**不产出 lofi/hifi**，以规格 §7 决策点清单（Q1~Q9）承接"方向确认"，以规格全文承接"实施包的上游输入"（沿 WBS-3.1.7 / 3.2.1 / 3.3.1 / 3.4.1 同款免设计先例）。

**设计要点摘要（供快速表决）**

1. **一份规格覆盖两条 P0**（C-5.1 API/文件交付、C-5.2 数据沙箱），拆为 **7 条业务行为**，每条带 5~6 条可判定的验收标准（共 37 条）；
2. **凭据唯一 = 已生效合约**：未生效 / 终止 / 完结合约不可新发起交付或沙箱；发起人 = 合约需求方，提供方与运营方只读；**不引入"订单"作为第二凭据**（C-7.3 未开工，避免双轨）；
3. **API 交付 = 网关唯一入口**：链路 = 鉴权 → 限流 → **策略执行点（消费 3.4.5 `check`）** → 转发 → **计量埋点**，**策略判定在转发之前**（越界不触达数据源）；**判定语义唯一权威在合约域，交付域消费不复制**（ADR-019 / ADR-020）；
4. **文件交付 = 国密加密交付包**（SM4 加密 + SM3 完整性校验，`common` 唯一入口）；**交付记录只记产物标识与校验值，本体与原文不进留痕与日志**；
5. **沙箱 = 平台侧隔离环境**：绑定已生效合约 + 资源配额 + 生命周期；**原始数据"进得去、带不出"，唯一出口 = 审核后导出**（PRD C-5.2 原文）；**诚实声明**：跨机构物理"数据不出域"依赖连接器（3.6.x）与隐私计算（C-5.3，P1），本规格不作跨机构承诺；
6. **结果导出是唯一管控出口且双向必有**：审核通过 ≠ 免策略——导出前**仍执行策略校验**；服务端强制（**绕过界面直调同拒**）；**双向用例硬约束**写入规格行为 6 规则 6 + C-5.2 剧本 S2/S3 两幕（沿 AGENTS §4 使用控制策略双向用例的同款要求）；
7. **横切三件事只消费不新造**：策略判定（3.4.5）、计量事件（3.7.5）、存证事件（3.8.3）——本规格只定"应产生"的业务口径与对账数据源约定；
8. **剧本界面步骤占位**：两份剧本先写业务步骤，界面入口待 **3.5.6** 交付后按 C-1.2 / C-3.1 / C-4.1 剧本同款"界面名称核对修订"机制一次性核对（业务判定不变，修订经 PO 批准留痕）；
9. **跨域剧本衔接已登记**：C-4.3 剧本 S2/S3 的"使用动作"演示承载（此前为技术侧受控调用模拟）在交付链交付后**由本域交付调用链承接**——C-5.1 剧本维护说明第 3 条已登记建议；**他剧本不擅自改动**，同步修订须 PO 批准（3.5.7 复核后处理）。
