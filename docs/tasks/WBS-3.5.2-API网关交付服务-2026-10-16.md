**设计要点摘要（供快速表决）**：

1. **网关 = 新模块 `services/gateway-service`（端口 **8086**，Reactive，无库无迁移）**——落实 ADR-005「Spring Cloud Gateway，全平台唯一流量入口」；**该 ADR 已于 2026-09-06 批准方案 A**，本卡是其实施包，不是新选型（依赖引入仍按 `dependencies.md` 四步登记 + 变更流程留痕）；
2. **鉴权零新研发**：`common-auth` 网关侧链（剥离 -200 → JWT 校验 → 注入 -90）已实现且已测，本卡只做"起 REACTIVE 应用 + 置 `ctds.auth.gateway.enabled=true` + 配 JWT 密钥来源"（**DB-03 解除条件之一兑现**；FR2 完整信任边界仍需 3.9.1 真实令牌）；
3. **交付调用链顺序固定**（规格行为 2 规则 2）：**鉴权 → 限流 → 策略执行点（转发前判定）→ 转发 → 计量埋点**；越界**不触达数据源**（规格验收标准 2）；
4. **策略执行点只消费不复制**：网关经**合约域新增内部判定端点**调用既有 `check`（ADR-020 §2.8 明文"端点形态由消费方设计定"），越界原码透传（`1008C0020`→403 / `1008C0013`→409 / `1008C0012`→404）；**不复用** 3.4.6 演示期 `usage-executions` 端点（其归 ADR-021 演示形态、权限面向参与方，复用会把演示端点变成生产链路）；
5. **限流与配额分工**：网关 = 网络级/频率级保护（主体 + 接口令牌桶，阈值配置化）；业务次数配额唯一由策略执行引擎判定与计数（规格行为 2 规则 5）——两者不互相替代；
6. **凭据形态 = 合约编号 + 主体身份**（3.5.1 Q2-A 已裁决；独立 API Key 登记未定义项归后续）；
7. **计量埋点 = 放行 1 次产生 1 条计量事件，拒绝不产生**（规格行为 2 规则 6）——事件字段口径本卡定义，**流水模型与采集归 3.7.5**；
8. **交付记录（`deliveries`）面不在本卡**（建议 Q5-A）：本卡只做网关链路四件；交付记录模型/端点/读面归交付域宿主包（登记衔接），避免 1 会话预算内混入 DB 面与读面；
9. **前端代理与部署清单不在本卡切换**（建议 Q4-A）：本卡建网关并让"交付调用面"生效，其余端点仍按现状直连（诚实边界 + 登记切换动作，归 3.5.6/3.5.7 前统一）；
10. **错误码**：网关自身错占用 **1009 段**（3.5.1 Q8-A 已预留交付与沙箱域，实测零占用）；未认证复用 `1000C0002`、无权限复用 `1000C0005`；**越界一律透传合约域原码**；
11. **契约沉淀**：新建 `ADR-022 网关交付链契约`（建议 Q9-A），固化链路顺序 / 判定唯一 / 限流与配额分工 / 信任边界与头处置 / 交付面与凭据 / 计量事件口径 / 未收敛面与诚实边界 / 演进触发；
12. **剧本回答 = 无需更新**：`C-5.1` S1/S3 已承载本卡判定面；界面入口待 3.5.6 按既有"界面名称核对修订"机制一次性核对（登记，不擅自改剧本）。
