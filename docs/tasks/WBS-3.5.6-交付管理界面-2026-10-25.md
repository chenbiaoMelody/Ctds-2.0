**设计要点摘要（供快速表决）**：

1. **3 菜单 4 视图 + 1 深链**（Q1-A）：「交付记录」（`/deliveries`，menuOrder 17，登录可见）= 列表 + 详情**抽屉**（简单读面）；「沙箱任务」（`/sandboxes`，menuOrder 18，登录可见）= 列表 + **详情深链页**（多区块：配额生命周期 / 工作台 / 结果物 / 导出记录）；「交付治理」（`/delivery-governance`，menuOrder 19，admin）= 双 Tab（**导出审批**〔沙箱治理 + 审核写面 + 审核留痕〕+ 交付记录治理）；沿剧本占位口径命名（「交付管理」分组菜单 → 现有平铺一级菜单结构下的三个菜单项，核对修订时说明映射）。
2. **演示身份双头映射**（Q2-A）：`deliveryRolesHeader()` = 普通档 **`requester,provider` 双头** + 运营档 `admin`；主体编号决定视角（业务层按合约参与方判定），一个普通档即可演示需求方全操作 + 提供方只读对照（S1-4）+ 提供方代发起被业务层拒（准确文案，规避 DB-63/66"权限层先拦"同型问题）；硬约束普通档不带 `admin`。
3. **幂等键 = 弹窗实例级 UUID**（Q3-A）：写弹窗打开时 `crypto.randomUUID()` 生成，随 `X-Idempotency-Key` 头提交（`apiJson` 扩展自定义头入参）；同弹窗重复提交 = 同键重放返回首次结果（剧本 S1-5 / S2-3 演示口径）；弹窗关闭重开 = 换新键；**不做全局自动生成**（每请求新键 = 幂等失效）。
4. **跨域合约检索回填**（Q4-A）：发起交付 / 申请沙箱弹窗的合约选择 = 编号**直填** + **检索回填**（只读复用 `api/contract.ts` 我的合约列表，各带各的域角色头，沿 3.4.7 产品选择跨域先例）；要素（用途 / 地域）与文件标识可填**任意值**（服务端判定，剧本"约定外被拒"步骤可执行）；必填留空 = 前置拦截零请求。
5. **留痕读面缺口补 1 端点**（Q5-A）：新增 `GET /api/v1/deliveries/{contractNo}/action-logs`（或同级路径，编码段按 3.4.7 R13 形态定稿）——参与方 + 治理例外、防枚举同码同文、读即留痕、零新表零新码零迁移；承载 C-5.1 S3-7"查看被拒的越权探测记录"屏幕可核对。
6. **状态机显隐唯一依据 = 后端字段**（沿 ADR-025）：结果物"提交审核"按 `status`（仅未登记 / 已驳回可提交，已通过不可）、「导出」仅 `APPROVED`（待审核 / 已驳回禁用并提示原因）、「关闭任务」仅 RUNNING；治理页审核操作**只对治理详情内结果物**；结论一经作出不可修改（界面提示走重新提交流程）。
7. **零本体纪律**（行为 7 规则 4）：列表 / 详情 / 治理 / 留痕全链只展示业务要素（编号 / 状态 / 字节数 / SM3 / 结论 / 理由 / 结果码）；唯一内容出口 = 加密包下载端点（密文 + `X-Ctds-Sm3` 提示校验）；SourceGuard 守卫测试锚定。
8. **同形拒绝与错误展示纪律**：`1009C0005`（缺幂等键）/ `1009C0007` / `1009C0010`（同码同文防枚举）/ `1009C0011`（生命周期）/ `1009C0012`（数据面零出口）/ `1009C0015` / `1009C0016`（结果物状态）/ `1008C0013`（合约状态）/ `1008C0020`（策略越界）/ `1000C0002`（未登录）各用同一条提示常量，文案**原样展示**（不吞、不改写）。
