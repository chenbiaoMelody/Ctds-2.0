## 一、范围与设计

- **做什么 / 不做什么**：见 lofi §1（业务可读行为清单 9 条）与 §2（边界划清 10 条）；技术契约见 hifi（迁移 / 类清单 / 端点契约 / 错误码 / 状态机与事务 / 测试清单）。
- **设计组织**：非界面类两级设计——lofi（方向确认：行为清单 + 决策点 Q1~Q7 + 边界值）→ hifi（定稿确认：表结构 + 端点契约 + 错误码表 + 测试清单 = 编码契约）；≤1 天一并提交，请编排师**一次确认**。

**设计要点摘要（供快速表决）**

1. **在既有 `connector-service` 增量**（Q1-A）：无新服务 / 无新端口 / 无新库；迁移 `V2` = 3 表（版本变更 / 作业占用 / 升级取号）+ 1 列（`connector_registration.cancelled_at`）；
2. **升级 = 登记动作**：兼容 → **同事务原子替换**（改当前版本 + 变更行 `APPLIED` + 留痕含新旧）；不兼容 → 变更行 `PENDING_CONFIRM`（**当前版本不动**），运营方显式确认后同事务替换；同连接器**至多 1 条待确认**（生成列 + 唯一索引）；
3. **在途作业判定口径**（Q2-A，本卡关键裁决）：连接器域建**占用台账** + 2 个内部写端点（登记 / 释放），注销时按连接器数在途占用；**接入方 = 交付链 / SDK 归 3.6.8**，本卡以内部端点代登记即完成剧本 S3-1 演示（剧本原文已标"技术侧配合项构造在途作业"）；
4. **注销口径**：`PENDING_REVIEW`（= 撤回申请）与 `REGISTERED` 两态可注销；同事务 = 状态 `CANCELLED` + `cancelled_at` + 绑定 `ACTIVE→RELEASED` + `released_at` + 留痕；**已注销后业务动作拒绝、历史读面保留**（后者由 3.6.3 既有代码天然满足）；
5. **零跨域出站调用**：本卡不新增任何服务间调用，故**无新 `1010S` 码**（`1010S0003` 维持段位预留）；新增 2 个 C 型码（见 Q6）；
6. **零 3.6.3 语义改动**：注销后绑定查验 → `1010C0003`、内部面 → `1010C0003`、心跳 → `1010C0004`，均为 3.6.3 既有读面/门槛逻辑的既有结果（立卡实测 `ConnectorQueryService` 行 101~161 / 128~146 已确认），**不改这 12 个端点**。
