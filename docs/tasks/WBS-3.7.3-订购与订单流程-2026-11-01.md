**设计要点摘要（供快速表决）**：

1. **订单域落位（Q1-A）**：`contract-service` 内新增订单子域（迁移 V4 三表 + `/api/v1/orders` 端点）——订单 = 合约业务外壳（规格 Q3-A），同库同事务保证订单与合约状态一致；**零新服务/端口/库/镜像**；复用 `contract.deal/read/governance` 权限点。
2. **订购交互（Q2-A）**：门户详情「发起订购」启用 → 订购弹窗（选择启用模板 + 填写必填条款 + 策略）→ 提交即 **订单 + 合约草案同事务落库**；复用既有 `ClauseEditor` / `StrategyEditor`，不新建第二套条款语义。
3. **状态联动（Q3-A）**：合约生效 / 生效前终止与订单状态**同事务原子提交**（新增轻量事务编排挂接 `sign/terminate`）；订单状态 = 进行中 / 已完成 / 已关闭三态；不另设独立状态机。
4. **幂等与重购（Q6-A）**：订单端点 `@Idempotent` 键 = 需方 + 客户端 `requestId`；订单专用发起通路**绕开合约内容幂等注解**，确保订单关闭后同内容重购生成新合约；DB `active_order_key` 唯一索引兜底并发。
5. **读面（Q4-A）**：需方 + 供方双角色读（B12-1）+ 运营方治理检索后端（界面归 3.7.7）；非本方一律同形 404（1011C0002）+ 拒绝留痕；零新权限点。
6. **前端入口（Q5-A）**：新增「我的订单」菜单 `/portal/orders`（menuOrder 23，登录可见）+ 订单详情深链 `/portal/orders/:orderNo`；菜单计数 9/22 → 10/23。
7. **状态边界（Q7-A）**：仅映射 B3-4 已定义的两条联动；合约生效后的完结 / 强制终止**不改订单状态**（订单保持已完成，合约状态经关联合约可见）；不扩业务判定。
8. **剧本与验收（Q8-A）**：C-7.1 转 V1.2——S2-1~6 + 13 本卡界面验收；S2-7 后端验证、界面归 3.7.7；S2-8~12 归 3.7.4；业务判定一字不改，PO 批准。
