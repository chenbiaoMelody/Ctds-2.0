## 一、范围与设计

- **做什么 / 不做什么**：见规格 `docs/specs/C-8.1-8.2-存证与审计.md` §3（**8 条行为**）与 §4（非目标 12 项）；本卡不做设计类文件（免设计，理由见下）。
- **免设计声明（章程 2.6.2 免设计类）**：本卡为**纯文档类**任务——交付物即"规格 + 剧本"本身，**没有可设计的产品形态**（无界面、无服务、无数据模型）；存证服务与链对接 / 四环节埋点 / 监管审计视图 / 审计界面设计分别在 **3.8.2 / 3.8.3 / 3.8.4 / 3.8.5** 实施包内走两级设计门禁。故本卡**不产出 lofi/hifi**，以规格 §7 决策点清单（Q1~Q9）承接"方向确认"，以规格全文承接"实施包的上游输入"（沿 WBS-3.1.7 / 3.2.1 / 3.3.1 / 3.4.1 / 3.5.1 / 3.6.1 / 3.7.1 同款免设计先例）。

**设计要点摘要（供快速表决）**

1. **一份规格覆盖两条 P0**（C-8.1 区块链存证 / C-8.2 合规审计），拆为 **8 条业务行为**（4+4），每条带 3~4 条可判定验收标准（共 **29 条**）；
2. **四环节事件源只消费不复制**（B1）：授权 = 空间成员准入与授权留痕（C-2.x）/ 合约 = `contract_attestation`（C-4.1 已交付）/ 交付 = 交付记录（C-5.1）/ 使用 = 使用控制留痕与计量流水（C-4.3 / C-7.2）；环节类型值域封闭四类；
3. **上链白名单是唯一防线**（B1-4 / §6-4）：只上摘要 + 四项元数据；原文 / 个人信息 / 商业密文 / 密钥材料禁上链，白名单外上链按 S0 处置（ADR-004）；
4. **存证与业务解耦 + fail-visible**（B2 / Q4）：上链失败不回滚业务，但失败/待上链状态必须可见、可重试、不静默——拒绝"用存证链可用性反向卡死全部业务"；
5. **幂等与不可变**（B2 / Q5）：同一环节 + 单据号 + 操作类型唯一；存证生成后不可改删，只允许状态推进与重试留痕；
6. **核验三态显式**（B3）：通过 / 不一致 / 未上链，不默认通过；不一致必报可定位；
7. **监管视角 V1.0 承载**（B5 / Q6）：以运营方治理档承载，外部监管账号与三员分立归 3.9.2；视图只读、无补录入口；
8. **日志调阅不建第二事实源**（B6 / Q7）：只读既有留痕（存证事件 + 各域 action_log + 结构化审计事件），调阅本身留痕；
9. **报告不可篡改**（B7）：编号唯一、内容摘要可后续核验、更正走新编号报告；形态 CSV / JSON（零新依赖）；
10. **诚实边界三写**（§6-5 / §6-6 / B8）：自建链不单独承诺对外出证（V1.5 增强）、留存 ≥6 个月为 G-07 部署期目标且当前标"待生效"、明确不做 C-8.3/C-8.4/C-8.5。
