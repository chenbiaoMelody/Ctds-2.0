### 设计要点摘要（供快速表决）

1. **加性读面，不动存量**：审计读面全部落 `/api/v1/evidence/audit/` 新前缀，3.8.2 既有 5 端点、内部写面、网关、k8s、前端零改动；
2. **时间线以 evidence 为唯一检索面**：五类 businessNo 前缀反解 → 按需调 4 个新增域内 audit-trail 只读端点 → 聚合层统一脱敏（DID/主体号 SM3 摘要化）出站；跨域不可达 = 显式 `UNAVAILABLE` 标记降级 + WARN（不伪装连续）；
3. **调阅条件与上限全沿 3.8.2 硬约束**：至少一条件（拒 = 1012C0002）、时间窗 ≤90 天、分页 ≤100；报告清单上限 10000 条；
4. **越权与"不存在"同码同文**：审计读面族统一 400 + 1000C0003 + 同文案（ADR-016 §2.6 先例同型，服务内守卫实现，满足剧本 S1-7 逐字判定）；
5. **报告不可篡改三件套**：生成即登记快照（内容 JSON + SM3 摘要 + 唯一编号）→ 下载时重算摘要核验（不一致 = 1012S0003 显式报错）→ 只插不改（重复生成新编号）；
6. **调阅/导出动作留痕落库**：`evidence_access_log`（调阅人/时点/条件/返回条数/用途），剧本 S1-6 / S2-4 可核对；
7. **只读铁律**：全部新端点 GET/POST 查询语义，仓储端口无删除/更新方法，ArchUnit 沿例扩展；
8. **诚实边界**：JSONL 审计事件不在调阅面（G-07 待生效）、留存 ≥6 个月标"待生效"、自建链不承诺对外出证、参与方读面不开放——四项在剧本 S2-8 与交付说明中逐字可摘录。
