### 设计要点摘要（供快速表决）

1. **两菜单一底座，零后端改动**：监管审计（menuOrder 26，5 tab）+ 存证核验（menuOrder 27，单页），均挂 `evidence.governance`；后端 10 端点原样消费，网关同前缀零改动；
2. **菜单计数三处断言同步是硬门禁**：26 / 27 追加不重排，MainLayout.spec（11 不变 / 25→27）+ router.spec（max 25→27）；
3. **界面不制造第二口径**：治理面出参（主体编号原文）与审计面出参（DID / 操作人摘要化）各自原样渲染，零二次脱敏、零还原；
4. **核验工具单卡流**：输入存证编号 → verify → 三态结论卡（PASS 绿 / MISMATCH 红 + 期望·实际·本地三方摘要与编号·单号·时点定位 / NOT_ON_CHAIN 橙 + 当前存证状态提示）+ 核验留痕表（detail 端点 actions）；
5. **E5 文件下载双形态分流**：成功 = Blob + a[download]（Content-Disposition 文件名解析）；失败 = ApiResult JSON 解析（1012S0003 原文弹出）——沿 downloadDeliveryPackage 范式，SourceGuard 裸 fetch 第二处豁免登记；
6. **时间线诚实呈现**：TRAIL 单笔模式 el-timeline（存证事件 + 业务留痕逐节点，sourceStatus = UNAVAILABLE 显式降级标记不伪装连续）+ LIST 清单模式 trailHint 展开；
7. **硬约束体验引导、后端唯一裁决**：日期选择器限 90 天可选（UI 便利），零条件 / 超限错误由后端返回并原文展示，前端不复制业务规则；
8. **报告页无清单端点**：生成表单（≥1 条件 + remark）→ 结果卡（编号 / 范围 / 条数 / 结论分布 / 异常数 / 内容摘要）→ CSV / JSON 双格式下载 + 按号补下载区（S2-7 界面路）。
