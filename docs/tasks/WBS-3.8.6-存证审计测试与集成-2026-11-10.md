## 一、范围与设计

- **做什么 / 不做什么**：见 lofi §二（三个交付面）与 §四（六条边界）；测试面与探针面的完整清单见 hifi §1 / §2。
- **业务目标一句话**：把"存证审计域已经建好"从**各服务自证**升级为**一条链上可复现的证明**——四个真实业务动作在真实四服务同时在链时，各产生且仅产生一条对应环节存证，单号与上游留痕逐字一致。
- **立卡实测的四个缺口**（本包存在理由，均有证据）：
  1. 现有 70 例 evidence 测试**全部单服务 + 桩对端**（被调方 = `services/evidence-service/src/test/java/com/ctds/evidence/support/AuditStubServer.java`），**无真实四服务串链用例**；四环节完整性只由剧本 C-8.1 S1 人工验收保证（`docs/manuals/C-8.1-区块链存证-验收剧本.md:19-26`）。
  2. 网关 `connector-evidence` 路由（`services/gateway-service/src/main/resources/application.yml:126-132`）既有 `GatewayConnectorRoutesIntegrationTest` 已断言转发 / 判定链零调用 / 零计量，**真增量 = 响应体逐字透传（含中文）未断言**（立卡原写"零自动化断言"失实，hifi §9 E11 校正）。
  3. evidence **不在** `coreModules`（`scripts/gates/gates-config.json:12`），变异只对 did（`:39`）——P0 域的质量刻度尺只按整体 70% 卡（本包**只如实登记建议，不改配置**）。
  4. **DB-115 明确写着承接 = "3.8.6 测试与集成 / 部署期"**，DB-109 / DB-110 等 evidence 测试硬化项无承接包（台账 `:143~:152`）。

**设计要点摘要（供快速表决）**

1. **完整性判定口径写死**：每环节"overview 计数**恰 +1** + 单号**逐字一致**"，只验存在性不算过关（Q3-A）；
2. **两条腿分工明确**：能进 CI 的进 CI（T1~T10），必须真机串链的用**探针脚本**（六链 18 条判定，带 PASS 计数下限 `exit 1`），沿 3.7.8 探针先例；
3. **不碰门禁配置**：evidence 实测 90.70% 已超 core 线 80%，改 `coreModules` / 扩变异属门禁配置变更，走独立流程（Q4/Q5-A）——本包只留建议；
4. **债务收口有明确边界**：能关的关（DB-109；DB-110 复核不关闭，hifi §9 E9）、该转的转（DB-115 → 部署期）、其余按可自动化边界逐条处置，不虚报全清；
5. **剧本只加对照不加判定**：C-8.1 / C-8.2 各升一版，仅追加《自动化覆盖对照》一节。
