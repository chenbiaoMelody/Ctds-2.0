## 一、范围与设计

- **做什么 / 不做什么**：见 lofi §二（三个交付面）与 §四（边界）；行为清单 / 接口契约表 / 边界值与异常行为见 hifi §1~§4。
- **业务目标一句话**：把"平台跑得怎么样、连接器在不在线、出了什么告警、告警谁处置了"从**散落在监控栈 UI 里的运维私有信息**变成**平台自己能读、能标注、能处置、能留痕的能力**——系统管理员在一处读到四区块读数（未接入的服务如实标注"未接入"，绝不显示为 0 或绿），读到要素齐备的告警列表（触发与恢复双向可辨），并经由唯一鉴权 + 留痕入口处置告警（确认/静默/升级）；连接器健康度三态在后端显式，"从未上报"不再以空值冒充。
- **立卡实测的四个缺口**（本包存在理由，均有证据）：
  1. **指标接入面与 ADR-014 口径落差**：12 个平台服务中仅 `example-service` 全量接入（2 依赖 + exposure `health,prometheus`）；did/kms/subject 半接入（actuator 有、micrometer 无、exposure=`health`）；其余 8 服务无 actuator/micrometer/management 段；`deploy/k8s` 9 组清单仅 backend 带三注解——B5-1"暴露面收敛逐服务核对"现状不成立。
  2. **监控读数无读面**：全仓无任何监控读数端点（四区块读数、未接入标注零承载）；剧本 S1-1 抽查载体与 S1-3 判定标"读数服务（3.9.4 落定）"（剧本 `:50`）。
  3. **告警列表与处置通道零承载**：无告警列表读面（要素七项）、无处置留痕入口（B7-1/B8-1 零实现）；剧本 S2-1/S2-6 标"读数与处置服务（3.9.4 落定）"（剧本 `:53`）；B8-R1 处置通道唯一性 = 平台处置服务（3.9.4）是规格点名本卡交付的义务。
  4. **健康度三态后端未显式**：connector-service 后端仅布尔 `online`（`ConnectorView.summary(registration, online)`），"从未上报"与"离线"同为 false、前端以「—」空值呈现——B6-R1"三态显式、不得以空值代替"后端口径不成立（加性字段修复，前端展示归 3.9.5）。

**设计要点摘要（供快速表决）**

1. **读面落 evidence-service**（Q1-A）：平台管理读面既有落点（3.9.2/3.9.3 先例），`/api/v1/platform/**` 网关路由已有（零路由改动），RBAC seed 与 1013 段同源；端点 `GET /api/v1/platform/metrics` + `GET /api/v1/platform/alerts` + `POST /api/v1/platform/alerts/actions`，`@RequirePermission` 显式挂点（B3-R4）。
2. **指标接入 = 2 依赖 + exposure 配置 + 3 注解**（ADR-014 :36 原文口径）：12 服务批量机械接入（example 零改动），Prometheus 抓取零配置改动（Pod 注解 kubernetes_sd 自动发现）；集群外本机部署服务（subject/connector/did/kms）不纳入集群抓取、读数如实"未接入"——接入（代码与配置在库）与采集（部署形态）两口径分离，诚实呈现。
3. **告警列表 = Prometheus rules 权威渲染"规则即告警项"**（Q4-A）：状态映射 B7-R1 本卡落定 = firing→已触发、pending/inactive→已恢复（未触发）；当前值 = 表达式实时查询；阈值 = 封闭两规则登记映射；Alertmanager 仅处置（静默）链路依赖——列表读面不依赖 Alertmanager 存活。
4. **处置三动作唯一入口**（Q6-A）：静默 = 平台处置服务转 Alertmanager `POST /api/v2/silences`（matcher=alertname）；确认/升级 = 平台留痕型动作（不改变告警引擎状态；v1 路由空 + 外发未接 G-04，升级的实际通知效果"待生效"诚实标注）；三动作均留痕。
5. **处置留痕零新表**（Q7-A）：复用 `AuditRecorder`（沿 3.9.3 `DomainLifecycleAuditEmitter` 先例，事件 `alert.dispose`，detail = 动作/结论/静默时长/silenceId，处置人 = subject 头、时点 = 审计载体自带）；"监控与告警数据不可删除"由审计载体结构性满足。
6. **权限点与码值登记齐**（Q3-A/Q8-A/边界 8）：`platform.monitor.read`（读面）+ `platform.alert.handle`（处置写面）仅授 `platform.sysadmin` 走 **V5 迁移**（V4 已应用不可改，checksum 红线）+ change_log 留痕；`1013C0005`（告警对象未定义）/`1013S0003`（监控数据源不可用→503）顺延落定登记；`PermissionPointRegistryTest` 扩展纳入 V5；治理档 admin/secadmin/audadmin/业务角色不持新点 → B8-3 双向天然成立。
7. **容量类阈值取值设计落定登记、不扩规则**（Q5-A）：连接器规模 / 调用量 / 存储水位建议取值与口径在本卡设计文件落定，B7-R2"V1.0 规则封闭两条"不破，容量类告警规则未建如实标注"待生效"。
8. **数据源不可用 fail-closed**：Prometheus/Alertmanager BASEURL 默认空或不可达 → 读面 503 + `1013S0003`（沿 `1013S0001` MAPPING_UNAVAILABLE 先例），不伪造空数据/零值（B5-4 同精神）。
